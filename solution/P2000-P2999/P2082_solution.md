# P2082 区间覆盖（加强版） — 题解

## 一、解题过程：人类思考叙事

拿到题目第一反应：区间合并。这不是 P1955 那道"区间并"吗，把区间排序然后合并就行。

但先别急，看数据范围：$1 \le s_i < t_i \le 10^{17}$，$N \le 10^5$。这里有两个要命的点：

第一个点是 **坐标大到 $10^{17}$**。区间合并本身是 $O(N\log N)$，跟坐标大小无关，这一半没问题。但"总长"怎么算？如果按照连续实数区间的长度算，$[1,3]$ 和 $[3,5]$ 的并长是 $4$ 而不是 $6$，因为端点 $3$ 被算了两遍。题目里给的是 $s_i < t_i$ 的**整数**区间，且提示"区间覆盖后的总长"，配套的官方样例是：

```
3
1 100000
200001 1000000
100000000 100000001
```
输出 `900002`。

用 $r-l+1$ 算：$100000 + 800000 + 2 = 900002$。用 $r-l$ 算：$99999+799999+1 = 899999$。所以本题统计的是**被覆盖的整数点个数**，也就是每段合并后的 $[L,R]$ 贡献 $R-L+1$。这一点必须先钉死，否则整个答案会差个位数。

第二个点是 **答案会爆 int**。$10^{17}$ 级别的坐标差直接放进 `int` 会溢出成负数，必须 `long long`。

第二个点里还藏着第三个点：**合并的判定条件要用 $l \le R+1$ 而不是 $l \le R$**。虽然对于"整数点个数"这个统计口径，$l = R+1$ 时合不合并答案都一样（$[1,100]$ 与 $[101,200]$ 分开算 $100+100=200$，合并算 $200-1+1=200$），但用 $l \le R+1$ 判定可以让"当前已经覆盖到的最右端 + 1"这个不变量更干净，而且更贴近"整数点被连续覆盖"的直观含义。

于是整体思路落地：

1. 把所有区间按左端点升序排序（左端点相同时按右端点升序，这个 tie-break 不影响正确性，但能让代码更稳）。
2. 从左到右扫描，维护当前连续块 `[cl, cr]`。
3. 若下一个区间的左端点 `l <= cr + 1`，说明它和当前块在整数意义下相邻或重叠，直接把 `cr` 扩到 `max(cr, r)`。
4. 否则当前块已经封口，把 `cr - cl + 1` 累加到答案，然后用新区间开新块。
5. 扫完后别忘了把最后一个块也加进去。

就这么简单，一个 `sort` 解决。

## 二、思维链：完整证明

**引理 1**：合并后的每个连续块 $[L,R]$ 对答案的贡献是 $R-L+1$，即块内被覆盖的整数点个数。

*证明*：题目中所有区间端点都是整数，且统计口径为"被覆盖的整数点个数"（由官方样例 `1 100000 / 200001 1000000 / 100000000 100000001` 输出 `900002` 反推：$100000+800000+2=900002$，而连续长度口径会得到 $899999$，两者不同，故本题采用整数点口径）。

对一个合并块 $[L,R]$，其中每个整数点 $x\in[L,R]$ 都至少被原始某个区间覆盖（合并的定义保证了块内无空隙），因此这些点全部计入答案，共 $R-L+1$ 个。证毕。

**引理 2**：按左端点升序排序后，扫描一遍得到的连续块，两两之间不存在交集。

*证明*：设算法在处理区间 $i$ 时判定 `a[i].l > cr + 1`，于是封口当前块 $[cl,cr]$ 并以 $a[i]$ 开新块。此时新块的左端点 $a[i].l \ge cr+2 > cr$，严格大于旧块右端点。之后新块的右端点只会单调增大，因此后续所有块的左端点也都大于 $cr$。故所有块两两不交。证毕。

**引理 3**：每个原始区间 $[s_i,t_i]$ 都被完整地包含在某个合并块中。

*证明*：考察排序后任意一个区间 $a[i]$。处理它时，当前块为 $[cl,cr]$，其中 $cl \le a[i].l$（因为按左端点升序排列，所有之前的块的左端点都 $\le a[i].l$，且 $cl$ 是最近一次开块的左端点）。若 $a[i].l \le cr+1$，则 $a[i]$ 被并入当前块，且并入后块的右端点 $\ge a[i].r$，故 $a[i]\subseteq[cl,cr]$。若 $a[i].l > cr+1$，则算法封口旧块并以 $a[i].l, a[i].r$ 开新块，此时 $a[i]$ 就是新块本身，同样被完整包含。证毕。

**引理 4**：算法统计的答案等于被覆盖的整数点总数。

*证明*：由引理 2，各合并块两两不交；由引理 3，每个原始区间被完整包含在某块中，故被覆盖的整数点集合恰为各块的整数点集合之并（不会有遗漏，也不会有重复计数）。

再证明**无遗漏**：任取一个被覆盖的整数点 $x$，它属于某个原始区间 $a[i]$，由引理 3，$a[i]\subseteq$ 某块 $[L,R]$，故 $x\in[L,R]$，被计入。

再证明**无重复**：任取两个不同的块 $[L_1,R_1]$、$[L_2,R_2]$，由引理 2 它们不相交，故两块的整数点集合不相交，不会被重复计数。

最后由引理 1，每块贡献 $R-L+1$ 个点，累加即为答案。证毕。

**引理 5**：排序时以右端点作为第二关键字不影响答案。

*证明*：排序只用于保证左端点非降。引理 3 的证明只用到"处理 $a[i]$ 时 $cl \le a[i].l$"，这由左端点非降保证；同一左端点的两个区间先后顺序不同，只会改变"先开哪个块"，而由引理 4，最终统计结果与块的具体划分无关，只与被覆盖点集有关。因此第二关键字的取法不影响结果。证毕。

**定理**：算法输出的即为题目要求的区间覆盖总长。

*证明*：由引理 4，累加各块的 $R-L+1$ 恰为被覆盖整数点数；由引理 1，这与题目统计口径一致。故输出正确。证毕。

## 三、模式总结（按实际思考顺序）

1. **先钉死统计口径** — 是"连续长度 $R-L$"还是"整数点数 $R-L+1$"？用官方样例反推，锁定为后者。
2. **识别题型：区间合并** — 排序 + 一趟扫描，把交叠的区间压成互不相交的连续块。
3. **合并判定用 $l \le R+1$** — 整数语义下"相邻即连续"，让"最右覆盖点 + 1"成为自然的不变量。
4. **注意整数溢出** — 坐标与答案都到 $10^{17}$，`int` 不够，必须 `long long`。
5. **收尾别忘加最后一块** — 扫描型合并的经典漏点。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $N$ | 区间个数 | `int`，$\le 10^5$ |
| $s_i,t_i$ | 第 $i$ 个区间的左右端点 | `i64`，$[1,10^{17}]$ |
| `a[i]` | 排序后的第 $i$ 个区间 | `seg`，`{i64 l, r}` |
| `cl` | 当前连续块的左端点 | `i64` |
| `cr` | 当前连续块的右端点 | `i64` |
| `ans` | 累计答案（已覆盖整数点数） | `i64`，$\le 10^{17}$ |

### 算法步骤

1. 读入 $N$ 与所有区间到 `a[]`。
2. 按 `(l 升序, r 升序)` 排序 `a[]`。
3. 初始化 `ans = 0`，`cl = a[0].l`，`cr = a[0].r`。
4. 对 $i = 1 \dots N-1$：
   - 若 `a[i].l <= cr + 1`：两块在整数意义下相邻或重叠，`cr = max(cr, a[i].r)`；
   - 否则：当前块封口，`ans += cr - cl + 1`，然后 `cl = a[i].l`，`cr = a[i].r`。
5. 累加最后一块：`ans += cr - cl + 1`。
6. 输出 `ans`。

### 复杂度

- 时间复杂度：$O(N\log N)$，排序占主导，扫描为 $O(N)$。
- 空间复杂度：$O(N)$，存储所有区间。

### 验证状态

- 标程 `P2082.cpp` 用 `g++ -O2 -std=c++17` 编译通过。
- 题面官方样例 `3 / 1 100000 / 200001 1000000 / 100000000 100000001` 输出 `900002`，与官方一致。
- 编写暴力 `P2082_brute.cpp`（逐整数点打标记再统计，坐标受限于 $10^5$ 以内）与对拍脚本 `P2082_check.py`，在 $N\le 30$、坐标 $\le 10^5$ 的随机数据及"完全包含 / 首尾相接 / 互不相交"等极端构造上对拍 **3004 组全部通过**。
- 由于暴力按坐标开数组，$10^{17}$ 级坐标的大数据无法暴力覆盖，该部分改由官方样例与上述极端构造验证。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2082 区间覆盖（加强版）
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{100005};

struct seg
{
	i64 l,r;
};

int n;
seg a[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
		cin>>a[i].l>>a[i].r;
	sort(a,a+n,[](seg x,seg y){
		if(x.l!=y.l)
			return x.l<y.l;
		return x.r<y.r;
	});

	// 整数点口径：合并块 [cl,cr] 贡献 cr-cl+1；坐标与答案都要 long long
	i64 ans=0,cl=a[0].l,cr=a[0].r;
	for(int i=1;i<n;++i)
	{
		if(a[i].l<=cr+1)
		{
			cr=max(cr,a[i].r);
		}
		else
		{
			ans+=cr-cl+1;
			cl=a[i].l;
			cr=a[i].r;
		}
	}
	ans+=cr-cl+1;
	cout<<ans<<'\n';
	return 0;
}
```

### 代码说明

- `seg` 结构体只有 `l`、`r` 两个字段，纯聚合体，成员用花括号初始化风格。
- 排序比较器按 `(l, r)` 双关键字，左端点相同时按右端点升序，保证扫描时块的单调性直观。
- `ans`、`cl`、`cr` 一律为 `i64`：坐标 $10^{17}$ 与答案 $10^{17}$ 都超出 `int` 范围。
- 合并判定用 `a[i].l<=cr+1` 而非 `a[i].l<=cr`，对应"整数点连续"的语义。
- 全程使用 `'\n'` 而非 `endl`；`main` 以 `return 0;` 正常结束。
