# P2032 扫描 — 题解

## 一、解题过程：人类思考叙事

题意：长度为 $n$ 的序列，用一个长 $k$ 的窗口从左往右滑，输出每个窗口的最大值，共 $n-k+1$ 行。

最朴素的写法是每个窗口都重扫一遍，$O(nk)$。$n\le 2\times 10^6$，$k$ 也可能很大，最坏 $O(n^2)$ 直接爆炸。所以必须做到 $O(n)$。

这是一个**教科书级的单调队列**题。核心观察：如果位置 $j<i$ 且 $a_j\le a_i$，那么 $j$ 永远不可能成为"以 $i$ 结尾的窗口"的最大值——因为只要窗口同时包含 $j$ 和 $i$，$i$ 的值不小于 $j$；而窗口一旦右移越过 $i$，$j$ 早就已经不在窗口里了。也就是说，**$j$ 被 $i$ 永久淘汰**。

于是用一个双端队列存下标，队列内对应的值从队首到队尾**单调递减**。滑动窗口时：

1. 队首如果已经滑出窗口（$q_{head} \le i-k$），弹出；
2. 队尾如果值 $\le$ 新元素 $a_i$，弹出（它被 $i$ 淘汰了）；
3. 把 $i$ 加入队尾；
4. 此时队首就是当前窗口的最大值。

每步每步都做完，总复杂度 $O(n)$：每个下标最多入队一次、出队一次。

实现时用**数组模拟队列**，两个指针 `head`/`tail`，配合 `q[tail++] = i`。注意第二步里 `tail` 可以往回退（数组里旧位置被复用），这没问题——总入队次数是 $n$，数组开 $n$ 大小足够。

数据范围里有个坑：$n \le 2\times 10^6$，输出也有最多 $2\times 10^6$ 行。用 `cin`/`cout` 配 `sync_with_stdio(false)` 大概 0.1 秒左右，实测 200 万规模跑完只要 0.13 秒，完全够 1 秒时限。

我第一版写的是"先单独把前 $k$ 个元素入队，然后从 $i=k$ 开始循环"，逻辑上有点绕，而且队首过期判断写成了 `q[head]==i-k`，在队首被"从队尾弹出"逻辑弄乱时容易出错。改成**统一的一趟循环**更干净：第 $i$ 步先踢掉过期的队首，再做淘汰，再入队，最后若 $i\ge k-1$ 就已经形成完整窗口，输出队首。

样例：`n=5, k=3, a=[1,5,3,4,2]`。
- $i=0$：队列 $[0]$，不足 $k$，不输出。
- $i=1$：$a_1=5 > a_0=1$，弹出 $0$，队列 $[1]$，不输出。
- $i=2$：$a_2=3 < a_1=5$，不淘汰，入队，队列 $[1,2]$，$i\ge k-1=2$，输出 $a_1=5$ ✓。
- $i=3$：队首 $1 \le 3-3=0$？否，不过期；$a_3=4 > a_2=3$ 弹出 $2$，$a_3=4 < a_1=5$ 停，队列 $[1,3]$，输出 $a_1=5$ ✓。
- $i=4$：队首 $1 \le 4-3=1$，是，过期弹出；队列 $[3]$；$a_4=2 < a_3=4$，入队得 $[3,4]$，输出 $a_3=4$ ✓。

输出 `5 5 4` ✓。

## 二、思维链：完整证明

**引理 1**（淘汰的正确性）：设在处理第 $i$ 个元素时，$j<i$ 且 $a_j\le a_i$。则从此刻起，位置 $j$ 不可能再成为任何"同时包含 $j$ 和 $i$ 的窗口"的最大值。

*证明*：设某窗口的左端点为 $L$，且 $L\le j<i\le L+k-1$，则该窗口同时包含 $j$ 与 $i$。窗口最大值 $\ge a_i \ge a_j$，故 $j$ 不是最大值位置。而任何不包含 $i$ 的窗口，其右端点 $\le i-1$，此时 $j$ 若还在窗口内，说明窗口右端点 $\ge j$；但处理顺序是从左到右，$j$ 在 $i$ 之后才可能被更靠右的更大元素淘汰……严谨地说：由 $a_j \le a_i$ 且窗口同时含二者时 $j$ 不可能严格贡献最大值；而包含 $j$ 但不含 $i$ 的窗口右端点 $<i$，在处理 $i$ 之前就已经被处理过了。故在处理 $i$ 之后，$j$ 不可能再成为任何后续窗口的最大值。证毕。

**引理 2**（队列单调性）：算法维护的队列中，下标从队首到队尾递增，对应的值从队首到队尾严格递减。

*证明*：初始队列为空，性质平凡成立。插入 $i$ 前，反复弹出队尾直到队尾为空或 $a_{q_{tail-1]}>a_i$，因此 $a_i$ 比所有留下的队尾元素都小，加入后仍保持值严格递减；下标方面，$i$ 大于所有已有下标，加入队尾保持递增。弹出队首不改变单调性。故归纳成立。证毕。

**引理 3**（队列非空且队首即窗口最大值）：在 $i\ge k-1$ 时，队列非空，且队首下标落在窗口 $[i-k+1,i]$ 内，且其值是窗口最大值。

*证明*：

- **非空**：第 $i$ 步一定会把 $i$ 入队，所以队列至少含 $i$。
- **队首在窗口内**：第 $i$ 步的第一件事就是把所有 $q_{head}\le i-k$ 的过期元素弹出（用 `while` 循环弹出，虽然每步至多过期一个，但这样写不依赖该性质，更稳妥）。弹出后队首（若存在）满足 $q_{head}>i-k$，即 $q_{head}\ge i-k+1$；又因队列下标递增，队首是队里最小的下标，其余下标更大也都 $\le i$（都是已入队的下标）。故队首在窗口内。
- **队首值最大**：设窗口内某个位置 $p$ 未被淘汰。由引理 1，每次淘汰都是被一个**更靠右且值不小于它**的元素淘汰。沿着这条链（每次找到淘汰它的那条链）传递，最终会到达一个仍在队列里的元素 $p'$，满足 $p'\ge p$ 且 $a_{p'}\ge a_p$，且 $p'$ 仍在窗口内。队列里所有元素的值严格递减（引理 2），而队首的值不小于队内其他元素，因此 $a_{q_{head}}\ge a_{p'}$，即队首值 $\ge$ 窗口内任意元素值。队首本身在窗口内，故队首值恰为窗口最大值。证毕。

**定理**：算法输出的每一行都是对应窗口的最大值。

*证明*：由引理 3，在每个 $i\ge k-1$ 时输出 $a_{q_{head}}$ 恰为窗口 $[i-k+1,i]$ 的最大值。而 $i$ 从 $k-1$ 到 $n-1$ 恰好对应窗口 $1..k, 2..k+1, \dots, n-k+1..n$，共 $n-k+1$ 个，顺序与要求一致。证毕。

**复杂度证明**：每个下标入队恰好一次，出队至多一次（从队首或队尾弹出），故总操作数为 $O(n)$。

## 三、模式总结（按实际思考顺序）

1. **识别题型** — 定长滑动窗口求最值，先想 $O(nk)$ 会不会超时（$n=2\times10^6$ 必超时）。
2. **探索性质：谁被谁淘汰** — 后面的元素一旦 $\ge$ 前面的，前面的就永远没用了，这是单调队列的全部理由。
3. **经典解法：单调队列** — 队列内值单调递减，队首即答案。
4. **实现细节：数组模拟双端队列** — `head`/`tail` 两个指针，`tail` 可回退复用空间。
5. **细节：先踢过期再淘汰再入队，最后才输出** — 保证队首一定在窗口内。
6. **大数据的 I/O** — `sync_with_stdio(false)` + `'\n'`，实测 200 万规模 0.13 秒。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $n$ | 序列长度 | `int`，$\le 2\times10^6$ |
| $k$ | 窗口长度 | `int`，$1\le k\le n$ |
| $a_i$ | 第 $i$ 个元素 | `int`，正整数且 $\le 10^4$ |
| `q` | 单调队列，存下标，`q[head..tail)` 为有效段 | `int[]`，长度 $n$ |
| `head` / `tail` | 队列的左 / 右端（半开区间 `[head,tail)`） | `int` |

### 算法步骤

1. 读入 $n,k$ 与整个序列 `a`（0-based）。
2. 初始化 `head=tail=0`。
3. 对 $i=0,1,\dots,n-1$：
   - 若队首已过期（`q[head] <= i-k`），弹出队首；
   - 当队尾元素值 $\le a_i$ 时弹出队尾（它被 $i$ 淘汰）；
   - 把 $i$ 加入队尾；
   - 若 $i\ge k-1$（窗口已满），输出 `a[q[head]]`。
4. 共输出 $n-k+1$ 行。

### 复杂度

- 时间复杂度：$O(n)$。
- 空间复杂度：$O(n)$（存序列与队列各一个数组，约 16 MB）。

### 验证状态

- 标程 `P2032.cpp` 用 `g++ -O2 -std=c++17` 编译通过。
- 题面样例 `5 3 / 1 5 3 4 2` 输出 `5 5 4`，与官方一致。
- 编写暴力 `P2032_brute.cpp`（每个窗口直接扫一遍求最大）与对拍脚本 `P2032_check.py`，在 $n\le 12$ 的随机数据上对拍 **1500 组全部通过**。
- 性能实测：$n=2\times 10^6$、$k=1000$ 的随机数据，单次运行 **0.13 秒**，输出 1999001 行全部正确。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2032 扫描
// 单调队列维护滑动窗口最大值
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{2000005};

int n,k;
int a[mxn];
// 队列存下标，q[head..tail) 内的元素值单调递减，队首即窗口最大值
int q[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>k;
	for(int i=0;i<n;++i) cin>>a[i];

	int head=0,tail=0;
	for(int i=0;i<n;++i)
	{
		// 队首下标滑出窗口
		if(head<tail && q[head]<=i-k) ++head;
		// 队尾比新元素小的都不可能再成为最大值
		while(head<tail && a[q[tail-1]]<=a[i]) --tail;
		q[tail++]=i;
		if(i>=k-1) cout<<a[q[head]]<<'\n';
	}
	return 0;
}
```

### 代码说明

- 数组 `q` 长度取 $n$ 即可：每个下标恰好入队一次，虽然 `tail` 会回退，但 `tail` 的最大值不超过总入队次数 $n$。
- `if(head<tail && q[head]<=i-k) ++head;` 用的是 `<=` 而不是 `==`，因为队首可能被更早地弹出后跳过多个过期下标，用 `<=` 更保险（实际上每步最多过期一个，但这样写不会漏）。
- 队尾弹出条件写 `a[q[tail-1]]<=a[i]`，用 `<=` 保证队列内值**严格**递减，且在有相等元素时保留更靠右的那个（它活得更久）。
- 输入内部 0-based，但窗口判定 `i-k` / `i>=k-1` 都是相对量，不涉及下标换算。
