# P2955 [USACO09OCT] Even? Odd? G — 题解

## 一、解题过程：人类思考叙事

**题意重述（剥离背景）。** 读入 $N$（$1\le N\le 100$）个正整数 $l_j$（$1\le l_j\le 10^{60}$），对每个数输出一行：偶数输出 `even`，奇数输出 `odd`。

**第一反应与第一个坑。** "判断奇偶"本身是 `x%2` 一行的事。但看到数据范围 $l_j\le 10^{60}$，第一反应必须是：**这个数装得下吗？** 算一遍各整型的上限：

| 类型 | 上限 | 与 $10^{60}$ 比较 |
|---|---|---|
| `int` | $\approx2.1\times10^9$ | 差 $51$ 个数量级 |
| `long long` | $\approx9.2\times10^{18}$ | 差 $41$ 个数量级 |
| `unsigned long long` | $\approx1.8\times10^{19}$ | 差 $41$ 个数量级 |
| `__int128` | $\approx1.7\times10^{38}$ | 仍差 $22$ 个数量级 |

连 `__int128` 都装不下。用 `cin>>long long` 读 $10^{60}$ 会读取失败（流置 fail 位、值被截成边界值），后面所有数全部读错——这是本题唯一的、也是致命的陷阱。题目 difficulty 标"入门"，但通过率只有约三分之一，坑就埋在这里。

**第二步：我需要整个数吗？** 退一步问：判断奇偶到底需要多少信息？十进制数 $N=\overline{d_kd_{k-1}\dots d_1d_0}$ 可以写成

$$N=d_0+10\cdot\overline{d_k\dots d_1}.$$

$10$ 是偶数，所以 $10\cdot(\text{任何整数})$ 是偶数，于是 **$N$ 与它的末位 $d_0$ 同奇偶**。前面 $59$ 位是什么完全无所谓。

**第三步：把两个观察拼起来。** 既然只需要末位，那就**把数当字符串读入**，取最后一个字符 `s.back()`，看它是不是 `0/2/4/6/8`。字符串长度最多 $61$（$10^{60}$ 是 $61$ 位数），`cin>>string` 毫无压力。整道题变成：

```
读 n；循环 n 次：读字符串 s；末位数字 &1 ? "odd" : "even"。
```

不需要高精度除法、不需要逐位取模、不需要 `__int128`——**信息量分析把高精度问题降级成了单字符判断**。

**边界核对。** $l_j\ge1$ 保证字符串非空，`s.back()` 合法；正整数无符号位，末字符必是数字；即使数据带前导零（题面未禁止），末位仍然是真正的个位，结论不受影响。$N=1$、$l_j=1$（最小奇数）、$l_j=10^{60}$（最大允许值，末位 $0$，偶）都要能处理。

**手造数据核对。** 题面样例解释给了两个数 $1024$ 与 $5931$，用作第一组：

```
输入：      输出：
2           even
1024        odd
5931
```

$1024$ 末位 $4$ 偶 ✓，$5931$ 末位 $1$ 奇 ✓，与解释"1024 可被 2 整除，5931 不能"一致。

第二组专打范围边界：$N=4$，四个数为 $1$、$10^{60}$（$1$ 后跟 $60$ 个 $0$）、$10^{60}-1$（$60$ 个 $9$）、$2$。期望输出 `odd / even / odd / even`。这一组里 $10^{60}$ 与 $10^{60}-1$ 任何整型读法都会翻车，字符串读法必须全对。实测输出与期望逐行一致。

## 二、思维链：完整证明

**记号。** 第 $j$ 个输入数的十进制串为 $s$（长度 $L\le61$），其数值 $N=\sum_{i=0}^{L-1}d_i\cdot10^i$，其中 $d_i$ 是从右往左第 $i$ 位数字，$d_0$ 为末位（即 `s.back()-'0'`）。

---

### 引理 1（整型读入必然失败）

对 $l_j\le10^{60}$ 的输入，任何 C++ 内置整型（含 `unsigned long long` 与 `__int128`）都无法表示所有合法输入，故 `cin>>整型` 的读法不正确。

*证明*：$10^{60}$ 本身是合法输入（范围含等号）。各类型最大值：`int` $\le2^{31}-1=2147483647<10^{10}$；`long long` $\le2^{63}-1=9223372036854775807<10^{19}$；`unsigned long long` $\le2^{64}-1=18446744073709551615<2\times10^{19}$；`__int128` $\le2^{127}-1<2^{128}=3.4\times10^{38}<10^{39}$。全部 $<10^{60}$。当输入超出类型可表示范围时，`istream` 的数值提取会置 `failbit` 并把值存为类型最大值（C++ 标准 [facet.num.get] 的溢出行为），此后流处于失败态，**后续所有读入都不再执行**——不仅当前数错，后面 $N-j$ 个数也全错。故整型读法在合法数据上必然产生错误输出。证毕。

### 引理 2（奇偶性只由末位决定）

对任意十进制正整数 $N=\sum_{i=0}^{L-1}d_i10^i$，有 $N\equiv d_0\pmod 2$。从而 $N$ 为偶 $\iff d_0\in\{0,2,4,6,8\}$。

*证明*：把求和拆出末位：$N=d_0+\sum_{i=1}^{L-1}d_i10^i=d_0+10\cdot M$，其中 $M=\sum_{i=1}^{L-1}d_i10^{i-1}$ 是整数（去掉个位后的数）。因 $2\mid10$，有 $2\mid10M$，即 $10M\equiv0\pmod2$。两边加 $d_0$ 得 $N\equiv d_0\pmod2$。

$d_0\in\{0,1,\dots,9\}$，其中模 $2$ 余 $0$ 的恰为 $\{0,2,4,6,8\}$，余 $1$ 的恰为 $\{1,3,5,7,9\}$。故 $N$ 偶 $\iff d_0$ 偶 $\iff d_0\in\{0,2,4,6,8\}$。证毕。

**推论（程序判据正确）**：`(s.back()-'0')&1` 计算的是 $d_0\bmod2$：字符 `'0'..'9'` 的 ASCII 码连续（$48..57$），减 `'0'` 恰得数字值；`&1` 取最低二进制位，对 $0..9$ 等于模 $2$。结果为 $1$ 输出 `odd`、为 $0$ 输出 `even`，与引理 2 的判据一致。

### 引理 3（字符串读入的合法性）

`cin>>s` 能完整、正确地读入每个 $l_j$，且 `s.back()` 是该数的个位数字。

*证明*：输入格式保证每个数独占一行（或至少以空白分隔）、由数字字符组成、无符号（正整数）。`cin>>string` 按空白切分并读入全部连续非空白字符，故 $s$ 恰为该数的十进制串，长度 $L\le61$（$10^{60}$ 是 $61$ 位，其余 $\le60$ 位），无长度限制问题。串非空（$l_j\ge1$ 至少一位），`s.back()` 合法且是最后一个字符 = 十进制表示的最低位 $d_0$。即使存在前导零，前导零只影响高位，末字符仍是个位，引理 2 不受影响。证毕。

### 引理 4（输出格式与顺序）

程序输出恰 $N$ 行，第 $j$ 行对应第 $j$ 个输入数的奇偶性。

*证明*：循环 `for(i=0;i<n;++i)` 按读入顺序逐个处理，每轮恰输出一个字符串加 `'\n'`（三目运算的两个分支都自带换行），共 $N$ 行。第 $j$ 轮读入的是第 $j$ 个数（引理 3），由引理 2 推论输出其正确奇偶性。单词拼写 `even`/`odd` 全小写，与题面逐字一致。证毕。

### 引理 5（复杂度）

时间 $O(\sum L_j)=O(61N)$，空间 $O(\max L_j)=O(61)$。

*证明*：每个数被 `cin>>s` 线性扫描一次（$O(L_j)$），其余操作（取末字符、减、位与、输出常数长单词）均 $O(1)$。总时间 $O(\sum L_j)\le61\times100=6100$ 字符级操作。空间只有一个复用字符串 $s$（$\le61$ 字节，SSO 或一次堆分配）加常数变量。证毕。

### 定理

程序对每个合法输入数输出正确的 `even`/`odd`，共 $N$ 行，时间 $O(61N)$。

*证明*：引理 1 说明必须放弃整型读入；引理 3 保证字符串读入完整正确；引理 2 及其推论保证"末位 &1"判据与真实奇偶性等价；引理 4 保证行数、顺序、拼写正确；引理 5 给出复杂度。证毕。

## 三、模式总结（按实际思考顺序）

1. **explore its property** — 先看数据范围：$10^{60}$ 超过一切内置整型（连 `__int128` 都不够），整型读入必然失败且会污染后续读入。
2. **consider easier version** — 问"判断奇偶最少需要多少信息"：$N=d_0+10M$，高位全部被因子 $10$ 吸收，只需末位。
3. **reduce to easier problem** — 高精度数降级为字符串：`cin>>s` 读入，`s.back()-'0'` 取个位，高精度问题塌缩成单字符判断。
4. **classic problem solution** — 十进制整除判据的通用形态：模 $2$（或 $5$）只看末位，模 $4$（或 $25$）看末两位，模 $3$（或 $9$）看数位和——本题是其中最简的一档。
5. **discuss by category** — 边界逐类核对：$l_j=1$、$l_j=10^{60}$（$61$ 位）、$10^{60}-1$（$60$ 个 $9$）、可能的前导零，均不影响末位判据。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 | 初值 / 记忆点 |
|------|------|------|---------------|
| `n` | 数的个数 $N\le100$ | `int` | 读入 |
| `s` | 当前数的十进制串（复用） | `string` | 每轮 `cin>>s` 覆盖；长度 $\le61$ |
| `s.back()-'0'` | 个位数字 $d_0\in[0,9]$ | `int`（表达式） | ASCII 连续保证减法即数值 |
| `&1` | $d_0\bmod2$ | 表达式 | $1$ 奇 `odd`，$0$ 偶 `even` |

### 算法步骤

1. I/O 加速三行；读 $N$。
2. 循环 $N$ 次：`cin>>s` 读入整个数（字符串）。
3. 取末位 `(s.back()-'0')&1`：为 $1$ 输出 `odd\n`，否则输出 `even\n`。

### 复杂度

- 时间：$O(61N)\le6100$ 字符级操作。
- 空间：$O(61)$，一个复用字符串。
- 验证状态：`g++ -std=c++20 -O2` 编译通过；题面解释的 $1024/5931$ 输出 `even/odd` 吻合；另造 $1$、$10^{60}$、$10^{60}-1$、$2$ 四数边界组输出 `odd/even/odd/even` 全对。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2955 [USACO09OCT] Even? Odd? G
// l_j 可达 1e60，任何内置整型都装不下 ⇒ 按字符串读入
// 十进制数 mod 2 只由末位决定：N = d0 + 10*M ⇒ N ≡ d0 (mod 2)
#include<bits/stdc++.h>
using namespace std;

int n;
string s;

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
	{
		cin>>s;
		cout<<(((s.back()-'0')&1)?"odd\n":"even\n");
	}
	return 0;
}
```

### 代码说明

- **绝不能写 `cin>>long long`**：$10^{60}$ 触发溢出，流置 `failbit` 后后续读入全部失效（引理 1），这是本题通过率低的根源。
- `s.back()` 要求串非空，由 $l_j\ge1$ 保证；若担心极端脏数据可改 `s[s.size()-1]`，语义相同。
- `&1` 优先级低于 `-`，但这里 `(s.back()-'0')` 已显式加括号，`&1` 作用于数字值而非字符码——其实字符码 `&1` 与数字值 `&1` 奇偶相同（`'0'`=48 为偶），但显式减 `'0'` 更不易误读。
- 三目输出两个分支都带 `'\n'`，每数恰一行；全小写 `even`/`odd` 照抄题面。
- 字符串 `s` 全局复用，$N$ 轮读入自动覆盖，无需清空。
