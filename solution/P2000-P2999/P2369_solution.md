# P2369 EXCEEDED WARNING A — 题解

## 一、解题过程：人类思考叙事

题意：给出 $n$ 个小于 $10^9$ 的非负整数，输出其中**最小的 $m$ 个**，按从小到大排列。$m<10^5$，$n<10^6$，**内存限制 4000 KiB**。

这个内存限制是题目的灵魂，先算一笔账。

**第一反应：全部读进来排序。**

$n<10^6$，一个 `int` 数组要 $4n<4\times10^6$ 字节，约 $3906$ KiB。而限制是 $4000$ KiB $=4096000$ 字节。看起来"刚好塞得下"，实际上：

- 程序本身（代码段、数据段、运行库）要占几百 KB；
- `std::sort` 是原地排序，但要递归栈（$\log n$ 层，微不足道）；
- 如果再用 `cin` / `printf`，stdio 缓冲还要几 KB；
- 最要命的是评测机的内存统计口径通常把整个进程的常驻内存算进去。

也就是说 $4n$ 的数组**几乎必然超**。而题目特意用"Danger Warning"的题名和"小心溢出，注意 Memory Limit = 4000KiB"的提示，就是在说：**不要存下所有数**。

顺便，"小心溢出"这句对 $n<10^6$、值 $<10^9$ 的数据其实有点迷惑——单个数值不会溢出 int，$n\cdot\max a$ 会溢出但也不需要算。合理的理解是：别用"把答案累加"之类的操作，也别用 `long long` 把内存翻倍（$8n=7812$ KiB，必死）。

**第二反应：只保留"可能成为答案"的数。**

答案只要最小的 $m$ 个。$m<10^5$，也就是最多保留 $10^5$ 个数 = $400$ KB，这才是本题该有的内存量级。

顺着这个想法：我需要一个"容量为 $m$ 的容器 $H$"，扫过所有数之后，$H$ 里恰好是最小的 $m$ 个。处理到新数 $x$ 时：

- 如果 $H$ 还没装满，把 $x$ 放进去；
- 如果装满了，问自己："$x$ 有资格挤掉 $H$ 里的某个数吗？"——有资格当且仅当 $x$ **小于 $H$ 中最大的那个**。这时就踢掉最大值，换上 $x$；否则 $x$ 比 $H$ 里 $m$ 个数都不小，不可能是最小的 $m$ 个之一，直接丢弃。

**第三反应：容器要能 $O(1)$ 取最大、$O(\log m)$ 删除最大——大根堆。**

上面那段话的关键动作是"取出 $H$ 的最大值"。如果用小根堆，取出来的是最小值，而最小值恰恰是**最该保留**的；想删最大值还得遍历整堆，退化成 $O(m)$。所以必须用**大根堆**：堆顶就是当前保留集合里的最大值，正好是"该被淘汰的候选"。

这一步的直觉可以总结成一句话：**我要维护"最小的 $m$ 个"，于是我要随时知道"这 $m$ 个里最大的那个"，所以用大根堆。**（很多人第一反应是小根堆，因为"要最小"，这是把"查询对象"和"淘汰对象"搞混了。）

**第四反应：最后怎么输出？**

堆里是 $m$ 个无序的数，而题目要求从小到大输出。两种做法：

1. 不断弹出堆顶，得到的是从大到小的序列，先存进数组再倒着输出；
2. 更简单：直接对堆数组 `sort` 一遍（$O(m\log m)$，$m<10^5$ 完全不用在乎），然后顺序输出。

选 2，代码最短。

**坑点整理：**

- **内存**：堆数组只开 $m+2$（约 $400$ KB），读入缓冲 $64$ KB，合计不到 $0.5$ MB，安全。
- **重复元素**：题目要的是"最小的 $m$ 个数"，是**多重集**语义，重复值要保留。大根堆方案天然支持：遇到等于堆顶的 $x$ 时，换与不换得到的多重集相同（见引理 4 的注），实现上选择"严格小于才换"。
- **$m>n$**：题面只说 $m<10^5,\ n<10^6$，没有断言 $m\le n$（虽然"输出其中最小的 $m$ 个数"隐含了）。防御式写法：装满就停，最后输出 $\min(m,\text{堆大小})$ 个。
- **$m=0$**：什么都不输出。
- **读入量**：$n\approx10^6$ 个数，用 `fread` 自己读更稳（也顺便避免 `cin` 的内部缓冲挤占内存）。

自造小例子（题面无样例）：

```
5 3
9
1
7
3
5
```

$H$ 容量 3：读 9 → `[9]`；读 1 → `[9,1]`；读 7 → `[9,1,7]`；堆顶 9；读 3 → $3<9$，换掉 9 → `[3,1,7]`；读 5 → $5<7$，换掉 7 → `[3,1,5]`。排序输出 `1 3 5` ✓（全部数排序是 1,3,5,7,9，前三个正是 1,3,5）。

## 二、思维链：完整证明

记号：输入序列 $x_1,\dots,x_n$；$S_k=\{x_1,\dots,x_k\}$（多重集）；$H_k$ 表示处理完前 $k$ 个数后堆中的多重集；$h_1\le h_2\le\dots$ 表示升序排列。

**引理 1（最大值的淘汰判据）**：设 $H$ 是 $m$ 个元素的多重集，$M=\max H$，$x$ 是任意数。则
$$\text{$H\cup\{x\}$ 的 $m$ 个最小元素}=\begin{cases}H,&x\ge M,\\ H-\{M\}+\{x\},&x<M.\end{cases}$$

*证明*：用到一个统一的事实：**大小为 $m+1$ 的多重集里取 $m$ 个最小元素，等价于把该多重集删掉一个最大元素。**（因为升序排列 $y_1\le\dots\le y_{m+1}$ 后，最小的 $m$ 个就是 $y_1,\dots,y_m$，而删掉的正是 $y_{m+1}$。）

现在看 $H\cup\{x\}$ 的最大元素：

- 若 $x>M$：最大元素是 $x$，删掉它剩下 $H$。
- 若 $x<M$：最大元素是 $M$（$x$ 小于 $M$，故 $x$ 不是最大），删掉它剩下 $H-\{M\}+\{x\}$。
- 若 $x=M$：最大元素的值是 $M$，无论删掉的是"$x$ 那一份"还是"$H$ 里的那一份"，剩下的多重集都是同一个（因为两者值相等，都是 $M$）：$H-\{M\}+\{x\}=H$。故结果可写成 $H$。

把前两种与第三种合并即得引理结论（$x\ge M$ 时结果为 $H$，$x<M$ 时结果为 $H-\{M\}+\{x\}$）。证毕。

**引理 2（堆不变式）**：处理完前 $k$ 个数后，$H_k$ 恰是 $S_k$ 中最小的 $\min(m,k)$ 个元素构成的多重集。

*证明*：对 $k$ 归纳。

- $k=0$：$H_0=\varnothing$，是 $S_0$ 中最小的 $0$ 个。成立。
- 设对 $k-1$ 成立，$H=H_{k-1}$，$s=\min(m,k-1)$，$H$ 是 $S_{k-1}$ 最小的 $s$ 个。
  - **情形 A：$s<m$**（即 $k-1<m$，堆未满）。此时 $H=S_{k-1}$ 全体。插入 $x_k$ 得 $H\cup\{x_k\}=S_k$ 全体，而 $\min(m,k)=k$（因为 $k\le m$），所以"$S_k$ 最小的 $k$ 个"就是 $S_k$ 全体。成立。
  - **情形 B：$s=m$**（堆已满）。此时 $\min(m,k)=m$。由引理 1，把 $x_k$ 与 $H$ 合并后取 $m$ 个最小，得到的就是算法要的结果；算法正是这么做的（$x_k\ge\max H$ 时不动，$x_k<\max H$ 时替换堆顶）。而"$H$ 是 $S_{k-1}$ 最小的 $m$ 个"加上引理 1 的组合就给出 "$H_k$ 是 $S_k$ 最小的 $m$ 个"。成立。

归纳完成。证毕。

注意这个不变式的**关键前提**是"$H$ 保留的是 $S_{k-1}$ 最小的 $m$ 个"——即被淘汰的元素永远不会再被需要。引理 1 的情形 $x\ge M$ 说明：当新元素不小于当前最大值时，$m$ 小集合**完全不变**，被淘汰的旧元素也没有机会"回归"。这正是"在线只保留一部分"可行的原因。

**引理 3（大根堆的两条操作维护了堆序）**：

1. `up(i)`：把下标 $i$ 的元素与父 $(i-1)/2$ 比较，若更大则交换并上移，直到不再更大或到根。操作结束后数组满足"父 $\ge$ 子"。
2. `down(i)`：把下标 $i$ 的元素与两个子 $2i+1,2i+2$（在堆内）比较，若某子更大则与**最大者**交换并下移，直到不再需要。

*证明*：这两条是标准的堆调整，此处把"为什么交换最大者"说清楚。对 `down`：设交换前除位置 $i$ 与它子树的关系外，其余各处都满足"父 $\ge$ 子"；设 $\max$ 的三个候选是 $h_i,h_l,h_r$，令 $b$ 为其中最大的下标。若 $b=i$ 则已满足，停。否则交换 $h_i,h_b$：交换后新位置 $i$ 的值是三者最大，故对两个子都满足"父 $\ge$ 子"；新位置 $b$ 的值是旧 $h_i$，它可能小于 $b$ 的子树里的元素，故需要继续在 $b$ 下沉。由于每步都向下走一层，最多走树高 $O(\log m)$ 步后终止，终止时全树满足堆序（每层向下时，被"越过"的子树不受影响，未被访问的部分原本就满足堆序）。`up` 同理：每步向上，父链之外不受影响，$O(\log m)$ 步终止。证毕。

由于只交换元素、不增删，这两个操作保持堆的多重集不变——这一点在引理 2 中使用（$H$ 的多重集被正确维护）。

**引理 4（最终输出即正确答案）**：算法最后对堆数组 `sort` 后输出前 $\min(m,sz)$ 个，得到的恰是 $S_n$ 中最小的 $m$ 个数按升序排列。

*证明*：由引理 2（取 $k=n$），堆内多重集是 $S_n$ 最小的 $\min(m,n)$ 个元素。对这个多重集排序后顺序输出，就是从小到大排列的这 $\min(m,n)$ 个元素；题面要求输出最小的 $m$ 个（隐含 $m\le n$），此时 $\min(m,n)=m$，正是答案。若数据违反 $m\le n$，输出的也是"能给出的全部"（$S_n$ 的所有元素升序），是题面语义下最合理的回应。证毕。

关于重复元素：引理 1 的证明已包含并列情形，算法用"严格小于才替换"（`x<h[0]`）实现，与引理 1 的情形 $x\ge M$ 对应（$x=M$ 时不动）。不动与替换都给出同一多重集（都是 $m$ 个最小值），故"$=$ 时怎么选"不影响正确性。

**引理 5（空间）**：堆数组 $4(m+2)$ 字节 $<400$ KB，读入缓冲 $64$ KB，合计 $<0.5$ MB $\ll4000$ KiB。

*证明*：$m<10^5$ ⇒ $m+2<100002$ ⇒ $4(m+2)<400008$ 字节 $\approx390.6$ KiB；加 $65536$ 字节的 `buf` 与常数级局部变量，总计 $<465$ KB，远小于 $4000$ KiB $=4096000$ 字节。相对于"存下全部 $n$ 个数"需要 $\approx3906$ KiB（几乎顶格），堆方案的安全余量是数量级的差别。证毕。

**引理 6（时间）**：总时间复杂度 $O(n\log m)$。

*证明*：每个数要么被插入（`up`，$O(\log m)$），要么与堆顶比较后被丢弃（$O(1)$）或被替换（`down`，$O(\log m)$）。$n$ 个数合计 $O(n\log m)$。最后排序 $O(m\log m)$ 被 $O(n\log m)$ 吸收（$m<10^5<n$）。取 $n=10^6,m=10^5$，约 $1.7\times10^7$ 次比较量级，非常宽裕。证毕。

**定理**：算法输出正确，且时间 $O(n\log m)$、空间 $O(m)$，在 $4000$ KiB 限制下安全。

*证明*：正确性由引理 2（不变式）、引理 3（堆操作合法）、引理 4（输出即答案）组合而得；复杂度与空间由引理 5、6。证毕。

## 三、模式总结（按实际思考顺序）

1. **explore the real constraint** — 先算内存账：$4n\approx3906$ KiB 贴着 $4000$ KiB 的线，全存必炸 ⇒ 这才是本题真正的约束。
2. **reduce to easier problem** — 不存全部，只维护"候选集"，大小是 $m$ 而不是 $n$。
3. **explore its property** — 新数有资格留下 ⟺ 它小于当前候选集的最大值（引理 1：$m$ 小集合的淘汰判据）。
4. **classic problem solution** — 需要 $O(1)$ 取最大、$O(\log m)$ 删最大 ⇒ **大根堆**（不是小根堆：要淘汰的是最大值，不是最小值）。
5. **碰壁与修正** — 直觉想用小根堆（"求最小"），但小根堆取出的是最该保留的元素 ⇒ 方向纠正。
6. **defer reconstruction** — 堆里是无序的，最后 `sort` 一次再输出，不为"有序"额外付代价。
7. **boundary check** — 多重集语义（重复值保留）、$m>n$ 时输出全部、$m=0$ 时不输出、$10^6$ 输入量用 `fread`。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 | 初值 / 记忆点 |
|------|------|------|----------------|
| `n` | 数据个数，$<10^6$ | `int` | 由 `rd()` 读入 |
| `m` | 要输出的最小个数，$<10^5$ | `int` | 由 `rd()` 读入 |
| `h[0..sz)` | 大根堆数组，保存"当前候选集"，`h[0]` 是其中最大值 | `int[100005]` | 全局数组，`sz` 从 0 开始 |
| `sz` | 堆中元素个数，$\le m$ | `int` | 0 |
| `up(i)` | 下标 $i$ 处元素上浮，恢复堆序 | 函数 | 插入新元素后调用 |
| `down(i)` | 下标 $i$ 处元素下沉，恢复堆序 | 函数 | 替换堆顶后调用 |
| `buf,len,pos` | `fread` 输入缓冲及游标 | `char[]/int` | 64 KB |
| `gc(), rd()` | 取一字符 / 读一个非负整数 | 函数 | `rd` 跳过非数字字符 |

### 算法步骤

1. `rd()` 读入 `n, m`，`sz=0`。
2. 循环 $n$ 次读入一个 $x$：
   - 若 `sz<m`：`h[sz]=x; up(sz); ++sz;`（堆未满，直接加入）；
   - 否则若 `x<h[0]`：`h[0]=x; down(0);`（比当前最大值小，替换它）；
   - 否则什么都不做。
3. `sort(h,h+sz)` 把候选集升序排列。
4. 输出 `h[0..min(sz,m))`，每行一个。

### 复杂度

- 时间：$O(n\log m)$（$10^6\times17$ 级别），加最后的 $O(m\log m)$ 排序。
- 空间：$O(m)$，堆 $<400$ KB + 缓冲 $64$ KB，远小于 $4000$ KiB。

### 验证状态

编译通过（`g++ -std=c++20 -O2`）；与"全部读入 + 全排序"的暴力在 300 组随机数据（$n\le80$、$m\le n$、值域 $\le30$ 以制造大量重复）上完全一致；极限数据 $n=999999,\ m=99999$（值域 $10^9$）输出与全排序的暴力逐行一致，耗时约 $0.2$ s。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2369 EXCEEDED WARNING A
// 思路：只要最小的 m 个 => 用一个大小为 m 的「大根堆」当候选集
//       堆顶是候选集里的最大值：新数比它小就顶替它，否则直接丢弃
//       最后把堆数组排序输出。只用 O(m) 内存（Memory Limit = 4000KiB）
#include<bits/stdc++.h>
using namespace std;

constexpr int mxm{100005};        // m<1e5，堆里只放 m 个数

int n,m,sz;
int h[mxm];                       // 大根堆：h[0] 是堆中最大的那个

char buf[1<<16];
int len=0,pos=0;

int gc()
{
	if(pos==len)
	{
		len=(int)fread(buf,1,sizeof(buf),stdin);
		pos=0;
		if(len<=0)
			return -1;
	}
	return buf[pos++];
}
int rd()
{
	int c=gc();
	while(c<'0'||c>'9')
		c=gc();
	int x=0;
	while(c>='0'&&c<='9')
	{
		x=x*10+(c-'0');
		c=gc();
	}
	return x;
}

void up(int i)                    // 新元素上浮
{
	while(i>0)
	{
		int f=(i-1)>>1;
		if(h[f]>=h[i])
			break;
		swap(h[f],h[i]);
		i=f;
	}
}
void down(int i)                  // 堆顶下沉
{
	for(;;)
	{
		int l=i*2+1,r=l+1,b=i;
		if(l<sz&&h[l]>h[b])b=l;
		if(r<sz&&h[r]>h[b])b=r;
		if(b==i)
			break;
		swap(h[i],h[b]);
		i=b;
	}
}

int main()
{
	n=rd();m=rd();
	for(int i=0,x;i<n;++i)
	{
		x=rd();
		if(sz<m)                  // 堆还没装满，直接塞
		{
			h[sz]=x;
			up(sz);
			++sz;
		}
		else if(x<h[0])           // 比堆中最大还小，替换掉它
		{
			h[0]=x;
			down(0);
		}
	}
	sort(h,h+sz);
	for(int i=0;i<sz&&i<m;++i)
		printf("%d\n",h[i]);
	return 0;
}
```

### 代码说明

- 堆用**全局数组手写**而不是 `priority_queue`：`priority_queue` 默认容器是 `vector<int>`，会在堆上另分配 $m$ 个 int（多一份 $400$ KB），而本题的内存限制只允许一份。手写数组同时省掉了 `push/pop` 的函数调用开销。
- `up` 在建堆阶段逐个插入：总代价 $O(m\log m)$，可以忽略；若想更严谨地 $O(m)$ 建堆也无必要。
- `x<h[0]` 用严格小于：等于堆顶时不替换。由引理 1 的并列讨论，两种选择得到同一多重集，故不影响答案。
- `down` 里 `b` 记录"三者中最大的下标"，先比左子再比右子，最后 `b==i` 则停——这是把"与最大者交换"写成了三段比较。
- `sort(h,h+sz)` 是对堆数组直接排序，堆序被破坏无所谓，因为之后不再需要堆。
- 输出条件 `i<sz&&i<m` 同时处理了 $m>n$（此时 `sz==n`）与 $m=0$（不输出）。
- 输入用 `fread` 缓冲（$64$ KB）：$10^6$ 个数用 `cin` 会有明显的常数，而且 `cin` 的内部缓冲也要占内存。
