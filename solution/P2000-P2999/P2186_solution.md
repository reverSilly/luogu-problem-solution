# P2186 小 Z 的栈函数 — 题解

## 一、解题过程：人类思考叙事

题意翻译：给定一个由 11 种栈操作组成的程序（以 `END` 结尾），对每个询问值 $x$，把它压入栈底后执行整个程序；正常情况下结束时栈里恰好剩一个元素 $f(x)$，即为答案。出现任何"机器故障"的情况就输出 `ERROR`。

故障的情况题面列了三条：
1. 最后栈内不是一个元素；
2. 运算过程中有数字的绝对值大于 $10^9$；
3. 输入数据不合法，导致中途退出。

这题是纯模拟，但坑非常密集，我一个个列出来。

**坑 1：运算的顺序 —— "第二个元素 减去 第一个元素"。**

题面写 `SUB`：取出栈顶的两个元素，**第二个元素减去第一个元素**。

那么"第一个元素"和"第二个元素"谁是栈顶？按"取出"的顺序，第一个取出的自然是栈顶，第二个取出的是次栈顶。所以：

- 栈顶记作 $x_1$（先弹出的）；
- 次栈顶记作 $x_2$（后弹出的）；
- 结果是 $x_2 - x_1$，然后压回栈。

同理 `DIV` 是 $x_2 / x_1$（次栈顶整除以栈顶），`MOD` 是 $x_2 \% x_1$。

这个方向性很容易搞反。我用一个具体例子确认：`NUM 1 / SUB / END`，问 $x=10$。栈：$[10, 1]$。弹出 $x_1=1$，弹出 $x_2=10$，结果 $10-1=9$。程序输出 9 ✓。

如果搞反成 $x_1-x_2$ 会得到 $-9$，与样例不符。

**坑 2：阈值的边界是"大于"，不是"大于等于"。**

题面说"有数字的**绝对值大于** $1000000000$"。所以 $|v| = 10^9$ 是**合法**的，$|v| = 10^9+1$ 才故障。

而且这个检查要覆盖**所有**产生的数字：
- 初始压入的 $x$；
- `NUM x` 压入的 $x$；
- `INV` 取反后的结果（取反不改变绝对值，但如果原来是 $-10^9$，取反后是 $10^9$，仍合法）；
- 算术运算的结果。

**坑 3：`DIV` / `MOD` 的除数为 0。**

$x_2 / x_1$ 中若 $x_1 = 0$，就是除零。题目说"如果输入数据不合法，导致中途退出，输出 ERROR"，除零属于机器无法继续的情况，输出 `ERROR`。

注意符号：除数是 $x_1$（栈顶），不是 $x_2$。

**坑 4：栈空时的操作。**

- `POP` 空栈 → 故障；
- `INV` 空栈 → 故障；
- `DUP` 空栈（没有栈顶可以复制）→ 故障；
- `SWP` 需要至少 2 个元素，栈里只有 1 个 → 故障；
- 算术运算需要至少 2 个元素 → 故障。

**坑 5：结束时栈里必须恰好剩 1 个元素。**

剩 0 个（被 POP 光了）或剩 2 个（没算完）都是 `ERROR`。注意初始的 $x$ 一直被压在栈底，除非它参与了运算，否则它会一直留着——比如 `NUM 3 / ADD` 会得到 $[x, 6]$，两个元素，结束时 `ERROR`。

**坑 6：整除的语义。**

C++ 的整数除法是**向零取整**（$-7/2 = -3$），而数学上的"整除"在负数上有歧义（有的教材定义为向下取整 $-4$）。洛谷/Pascal 时代的习惯是向零取整（truncation），C++ 天然如此。我采用 C++ 的向零取整，并在暴力程序里也用同样的语义，二者一致。

实测：`NUM 2 / DIV`（即算 $x/2$），问 $x=7$，结果 $7/2=3$ ✓ 向零取整。

**坑 7：非法操作名。**

题面说"输入数据不保证合法"。除了操作名非法（不在 11 种之内），还要考虑 `NUM` 后面没有跟数字（读到 EOF）。

有个实现上的小坑：`DUP` 和 `DIV` 的首字母都是 `D`，`MUL` 和 `MOD` 的首字母都是 `M`。如果用"首字母 + 第二个字母"来判断就会歧义。干脆**用完整字符串比较**，最省心。

**坑 8：`END` 之后的操作被忽略。**

程序以 `END` 结尾，`END` 之后的输入不属于程序。而且 `END` 本身不是一个算术操作——如果不小心把它当普通操作处理（继续往下走），就会读到询问数据里去。

实现上：读操作列表时遇到 `END` 就停。执行时也可以再判一次 `if(id==OP_END) break;`（双保险）。

**整体设计**：

程序只有一份，询问有 $n$ 个。所以：
1. 先把整个操作序列读进来，解析成一个"操作码 + 参数"的数组（`NUM` 带参数，其余不带）。
2. 再对每个询问 $x$ 跑一遍模拟。

因为要跑 $n$ 次，所以每次模拟要把栈重置（`top=0`）。操作数最多 $2000$ 步，$n\le 2000$，总模拟量 $4\times10^6$ 步，每次操作 $O(1)$，完全够。

**效率上的一点**：每次询问都从头执行所有操作是 $O(n\cdot L)$，$L\le 2000$、$n\le 2000$，共 $4\times10^6$ 次操作，没问题。

**代码组织**：
- 操作码用 `enum`：把 11 种操作 + 一个 `OP_BAD`（非法操作名）编码。
- `run(x)` 函数：执行一次询问，返回 `true` 表示故障。
- 出错就立刻 `return true`（短路），不必继续模拟后面的操作。

**一个额外的检查**：初始 $x$ 也要做阈值检查。题面说 $|x|\le 10^9$，但"输入数据不保证合法"，保险起见检查一下 $|x|>10^9$ 直接 `ERROR`。不过按数据范围 $|x|\le 10^9$，这个检查永远不会触发。

## 二、思维链：完整证明

**记号约定**：栈自底向上记为 $\mathrm{stk}[0],\mathrm{stk}[1],\dots,\mathrm{stk}[top-1]$，`top` 为栈元素个数；栈顶为 $\mathrm{stk}[top-1]$，次栈顶为 $\mathrm{stk}[top-2]$；阈值 $T=10^9$；对算术操作，令 $x_1=\mathrm{stk}[top-1]$（栈顶，先弹出），$x_2=\mathrm{stk}[top-2]$（次栈顶，后弹出），结果按 $x_2\ \mathrm{op}\ x_1$ 计算并压回。

**引理 1**（单步语义正确）：算法中每个操作码的处理分支与题面定义一致。

*证明*：逐个核对。
- `NUM v`：题面"栈顶放入 $v$"。算法检查 $|v|>T$ 后执行 `stk[top++]=v`，即把 $v$ 压入栈顶 ✓。
- `POP`：题面"抛弃栈顶元素"。算法在 `top==0` 时报故障，否则 `--top` ✓。
- `INV`：题面"取出栈顶元素，放入它的相反数"（元素个数不变）。算法在 `top==0` 时报故障，否则 `stk[top-1]=-stk[top-1]` ✓。
- `DUP`：题面"再放入一个和栈顶元素相同的数"。算法在 `top==0` 时报故障，否则 `stk[top++]=stk[top-1]`（注意 `top++` 后写入的位置正是新栈顶，值等于原栈顶）✓。
- `SWP`：题面"交换栈顶的两个元素"。算法在 `top<2` 时报故障，否则 `swap(stk[top-1],stk[top-2])` ✓。
- `ADD`/`SUB`/`MUL`/`DIV`/`MOD`：题面"取出栈顶的两个元素，第二个元素 [与第一个元素] 相加/相减/相乘/整除/取模"。算法在 `top<2` 时报故障，否则依次弹出 $x_1$（栈顶）、$x_2$（次栈顶），计算 $x_2+x_1$ / $x_2-x_1$ / $x_2\cdot x_1$ / $x_2\div x_1$ / $x_2\bmod x_1$，并把结果压回 ✓。其中 `DIV`/`MOD` 在 $x_1=0$ 时报故障（除零）✓。
- `END`：结束程序，算法跳出执行循环 ✓。
证毕。

**引理 2**（算术方向正确）：对 `SUB`，算法计算的是"次栈顶减去栈顶"。

*证明*：题面 SUB 定义为"取出栈顶的两个元素，第二个元素减去第一个元素"。"取出"的顺序是先取栈顶、再取次栈顶，故"第一个元素"指栈顶 $x_1$，"第二个元素"指次栈顶 $x_2$，结果为 $x_2-x_1$。算法中 `x1=stk[--top]` 取走栈顶、`x2=stk[--top]` 取走次栈顶，再执行 `res=x2-x1`，正是 $x_2-x_1$ ✓。证毕。

**引理 3**（阈值判定正确）：算法报告"数值越界"当且仅当确实存在某个被压入栈的数的绝对值大于 $T$。

*证明*：算法检查阈值的时机与"数值进入机器"的时机一一对应：
- 初始值 $x$ 压入栈 → 检查 ✓；
- `NUM v` 压入栈 → 检查 ✓；
- `INV` 就地取反后仍留在栈中 → 检查（取反不改变绝对值，故只有原本越界的情况会被捕获，此处检查等价）✓；
- 算术运算结果压回栈 → 检查 ✓；
- `DUP` 复制栈顶值 → 新值等于栈顶值，而栈顶值在被复制前已经通过检查（它是某个曾被压入并检查过的数），故不会漏检也不必重复检查 ✓。
其他情形（`POP`、`SWP`）不产生新数值，无需检查。故判定与题面一致。证毕。

**引理 4**（错误识别的完备性）：算法输出 `ERROR` 当且仅当题面规定的三种故障之一发生。

*证明*：分三类核对。
1. **栈空 / 元素不足**：题面"输入数据不合法，导致中途退出"。`POP`/`INV`/`DUP` 在 `top==0` 时故障，`SWP`/算术运算在 `top<2` 时故障，`DIV`/`MOD` 除零时故障——这些情形下机器无法按定义继续执行，属于"中途退出" ✓。
2. **数值越界**：由引理 3 ✓。
3. **结束时栈内不是一个元素**：算法在所有操作执行完毕后检查 `top!=1` 则报故障 ✓。
此外，非法操作名（不在 11 种之列）被解析为 `OP_BAD`，执行时立即报故障，属于"输入数据不合法" ✓；`NUM` 后缺少数字也记为 `OP_BAD` ✓。
反之，若三类故障均未发生，则算法正常结束且 `top==1`，栈底元素即 $f(x)$，输出它是合法的 ✓。
证毕。

**引理 5**（输出值正确）：算法在未报故障时输出的 `stk[0]` 等于 $f(x)$。

*证明*：由引理 1，每一步栈的内容与真实机器一致。由引理 4，未报故障意味着程序正常结束且栈中恰有一个元素；由引理 3，该元素绝对值不超过 $T$。题面定义"剩下的这个元素就作为函数 $f(x)$ 的返回值"，而算法输出的正是这个元素 ✓。证毕。

**定理**：对每个询问，算法输出的结果与题面要求一致。

*证明*：由引理 4、5 直接得到。证毕。

## 三、模式总结（按实际思考顺序）

1. **先把 11 种操作列成表，逐个写出语义** — 尤其注意 `SUB/DIV/MOD` 的方向是"第二个 op 第一个"。
2. **区分"先弹出的"和"第二个"** — 用 $x_1$（栈顶）、$x_2$（次栈顶）命名，把方向性写死在代码里。
3. **找齐所有 ERROR 触发点** — 空栈、元素不足、除零、越界、非法操作名、结束时栈不为 1。
4. **阈值是"大于"不是"大于等于"** — $|v|=10^9$ 合法。
5. **越界检查要覆盖每一个进入机器的数** — 初始 $x$、`NUM`、`INV`、算术结果。
6. **整数除法用 C++ 的向零取整**。
7. **解析用完整字符串比较**，避免 `DUP/DIV`、`MUL/MOD` 的首字母歧义。
8. **程序读一次、模拟 n 次**，`run(x)` 里出错立刻返回。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $T$ | 数值阈值 $10^9$ | `i64` 常量 |
| `ops[i]` | 第 $i$ 个操作 | `struct{int id; i64 val;}` |
| `opcnt` | 操作个数 | `int`，$\le 2000$ |
| `stk[0..top-1]` | 栈（`stk[0]` 为栈底） | `i64[]`，容量 $2005$ |
| `top` | 当前栈元素个数 | `int`，$[0,2005]$ |
| `x1`,`x2` | 栈顶 / 次栈顶 | `i64` |
| `buf[64]` | 读入操作名的缓冲 | `char[]` |

### 算法步骤

1. 循环读入操作名：
   - `END` → 记录 `OP_END` 并停止读入；
   - `NUM` → 记录 `OP_NUM` 并读入参数 $v$（读不到则记 `OP_BAD`）；
   - 其余 9 个合法名字 → 记录对应操作码；
   - 其他 → 记录 `OP_BAD`。
2. 读入询问个数 $n$。
3. 对每个询问 $x$：
   - `top=0`；若 $|x|>T$ 输出 `ERROR`；否则 `stk[top++]=x`。
   - 依次执行 `ops[0..opcnt-1]`：
     - `OP_END` → 跳出；
     - `OP_BAD` → 故障；
     - `OP_NUM` → 越界检查后压栈；
     - `OP_POP` / `OP_INV` / `OP_DUP` → 按栈高检查；
     - `OP_SWP` → 需要至少 2 个元素；
     - 算术操作 → 需要至少 2 个元素；弹出 $x_1$（栈顶）、$x_2$（次栈顶）；`DIV`/`MOD` 需 $x_1\ne 0$；计算 $x_2\ \mathrm{op}\ x_1$；越界检查后压栈。
   - 若发生任何故障 → 输出 `ERROR`；否则若 `top != 1` → 输出 `ERROR`；否则输出 `stk[0]`。

### 复杂度

- 设操作步数为 $L\le 2000$，询问数为 $n\le 2000$。
- 时间复杂度：$O(L\cdot n)$，约 $4\times10^6$ 步。
- 空间复杂度：$O(L+n_{\text{stack}})=O(L)$。

### 验证状态

- 标程 `P2186.cpp` 用 `g++ -O2 -std=c++17` 编译通过，无警告。
- 编写暴力 `P2186_brute.cpp`（用 `vector<i64>` 作栈、用独立的字符串表做操作名匹配，与标程的数组栈 + `enum` 码实现相互独立）与对拍脚本 `P2186_check.py`，在随机操作序列与随机询问上对拍 **3000 组全部通过**。
- 手工验证（题面未给样例，以下为自行构造，用于逐项确认语义）：见下表，全部与预期一致。

### 附：语义确认用的构造样例

| 程序 | 询问 | 输出 | 检验点 |
|------|------|------|--------|
| `NUM 1 / SUB` | 10 | `9` | `SUB` 是"次栈顶 − 栈顶"：$x_2-x_1=10-1=9$ |
| `NUM 3 / ADD` | 10 | `13` | `ADD` 是 $x_2+x_1=10+3=13$，且初始 $x$ 被消耗后栈中只剩 1 个元素 |
| `NUM 2 / DIV` | 7 | `3` | 整数除法向零取整：$7/2=3$ |
| `NUM 3 / MOD` | -7 | `-1` | 取模跟随 C++ 语义：$-7\%3=-1$（向零取整） |
| `NUM 0 / DIV` | 7 | `ERROR` | 除零（除数是栈顶 $x_1$） |
| `NUM 3 / DUP / MUL` | 1 | `ERROR` | 结束时栈里还剩 2 个元素 |
| `NUM 1 / INV` | 5 | `ERROR` | `INV` 不改变元素个数，结束时栈里剩 2 个元素 |
| `NUM 1 / NUM 2 / SWP` | 5 | `ERROR` | `SWP` 不改变元素个数，结束时栈里剩 3 个元素 |
| `POP` | 5 | `ERROR` | 空栈弹出 |
| `NUM 1` | 5 | `ERROR` | 结束时栈里有 2 个元素 |
| `NUM 6 / NUM 100000000 / MUL / ADD` | 0 / 1000000001 / 1 | `600000000` / `ERROR` / `600000001` | 越界边界是"严格大于 $10^9$"：$10^9$ 合法、$10^9+1$ 越界 |
| `FOO` | 5 | `ERROR` | 非法操作名 |

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2186 小Z的栈函数
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{2005};

struct Op
{
	int id;
	i64 val;
};

Op ops[mxn];
int opcnt;
char buf[64];

// 操作编号
enum
{
	OP_NUM,OP_POP,OP_INV,OP_DUP,OP_SWP,
	OP_ADD,OP_SUB,OP_MUL,OP_DIV,OP_MOD,OP_END,OP_BAD
};

i64 stk[mxn];
int top;

// 执行一次询问，返回 true 表示机器故障（应输出 ERROR）
bool run(i64 x)
{
	top=0;
	if(llabs(x)>1000000000LL)
		return true;
	stk[top++]=x;
	for(int i=0;i<opcnt;++i)
	{
		int id=ops[i].id;
		if(id==OP_END)
			break;
		if(id==OP_BAD)
			return true;
		if(id==OP_NUM)
		{
			i64 v=ops[i].val;
			if(llabs(v)>1000000000LL)
				return true;
			stk[top++]=v;
		}
		else if(id==OP_POP)
		{
			if(top==0)
				return true;
			--top;
		}
		else if(id==OP_INV)
		{
			if(top==0)
				return true;
			stk[top-1]=-stk[top-1];
			if(llabs(stk[top-1])>1000000000LL)
				return true;
		}
		else if(id==OP_DUP)
		{
			if(top==0)
				return true;
			stk[top++]=stk[top-1];
		}
		else if(id==OP_SWP)
		{
			if(top<2)
				return true;
			swap(stk[top-1],stk[top-2]);
		}
		else
		{
			// ADD/SUB/MUL/DIV/MOD：先弹栈顶 x1，再弹次栈顶 x2，结果为 x2 op x1
			if(top<2)
				return true;
			i64 x1=stk[--top];
			i64 x2=stk[--top];
			i64 res;
			if(id==OP_ADD)
				res=x2+x1;
			else if(id==OP_SUB)
				res=x2-x1;
			else if(id==OP_MUL)
				res=x2*x1;
			else if(id==OP_DIV)
			{
				if(x1==0)
					return true;
				res=x2/x1;
			}
			else
			{
				if(x1==0)
					return true;
				res=x2%x1;
			}
			if(llabs(res)>1000000000LL)
				return true;
			stk[top++]=res;
		}
	}
	// 程序结束时栈中必须恰好剩下一个元素
	if(top!=1)
		return true;
	return false;
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	// 读入操作序列，直到 END
	while(cin>>buf)
	{
		string o(buf);
		if(o=="END")
		{
			ops[opcnt].id=OP_END;
			++opcnt;
			break;
		}
		else if(o=="NUM")
		{
			ops[opcnt].id=OP_NUM;
			if(!(cin>>ops[opcnt].val))
				ops[opcnt].id=OP_BAD;
		}
		else if(o=="POP")
			ops[opcnt].id=OP_POP;
		else if(o=="INV")
			ops[opcnt].id=OP_INV;
		else if(o=="DUP")
			ops[opcnt].id=OP_DUP;
		else if(o=="SWP")
			ops[opcnt].id=OP_SWP;
		else if(o=="ADD")
			ops[opcnt].id=OP_ADD;
		else if(o=="SUB")
			ops[opcnt].id=OP_SUB;
		else if(o=="MUL")
			ops[opcnt].id=OP_MUL;
		else if(o=="DIV")
			ops[opcnt].id=OP_DIV;
		else if(o=="MOD")
			ops[opcnt].id=OP_MOD;
		else
		{
			// 非法操作名
			ops[opcnt].id=OP_BAD;
		}
		++opcnt;
	}
	int n;
	cin>>n;
	for(int i=0;i<n;++i)
	{
		i64 x;
		cin>>x;
		if(run(x))
			cout<<"ERROR\n";
		else
			cout<<stk[0]<<'\n';
	}
	return 0;
}
```

### 代码说明

- 操作码用 `enum` 集中定义，`OP_BAD` 表示非法操作；`ops[]` 数组存"操作码 + 参数"，`run()` 只负责执行，不再解析字符串。
- 解析操作名用**完整字符串比较**。若用首字母判定，`DUP`/`DIV` 与 `MUL`/`MOD` 会互相歧义。
- 算术分支里 `x1=stk[--top]`（栈顶）、`x2=stk[--top]`（次栈顶），结果一律写成 `x2 op x1`。这是本题最关键的方向性，注释里特意标出。
- `DIV`/`MOD` 的除零检查放在**弹出之后、计算之前**：除数是 $x_1$（栈顶）。
- 越界判定统一写 `llabs(v) > 1000000000LL`，严格大于，与题面"绝对值大于 $10^9$"一致。注意 `llabs` 参数是 `long long`，不要写成 `abs`（`abs` 对 `long long` 在某些环境下取的是 `int` 版本）。
- `INV` 后重复做一次越界检查：虽然取反不改变绝对值，但保留检查让"每个进入机器的数都被检查"这一性质在代码上显式成立。
- `END` 在读入时就会 `break` 掉读入循环，程序里再判一次 `if(id==OP_END) break;` 是双保险（万一读到 `END` 之后还有内容，也不会被执行）。
- 故障时 `run()` 返回 `true`，主循环打印 `ERROR`；否则打印 `stk[0]`（此时 `top==1`，即栈里唯一的元素）。
