# P2788 数学1（math1）- 加减算式 — 题解

## 一、解题过程：人类思考叙事

**题意重述。** 一行字符串（长度 $\le 60000$），是一个加减法多项式，每项数字在 $0\sim32767$ 之间，求值。结果保证在长整型范围内。没有括号、没有乘除，就是纯粹的"数 $\pm$ 数 $\pm$ 数 $\cdots$"。

**第一反应：这题到底难在哪？** 算式没有优先级问题（加减同级、从左到右），所以**不需要栈、不需要表达式树**，一遍扫描就能算完。真正的活儿只有两件：把数字从字符流里"攒"出来，把符号正确地挂到每一项上。

**第二步：设计扫描状态。** 任何时刻，扫描器只需要记住三个量：

- `num`：当前这一项已经读到的数字（还没读完整）；
- `sgn`：当前这一项的符号（$+1$ 或 $-1$）；
- `ans`：前面所有**已经完整**的项的带符号和。

规则只有两条：遇到数字字符，`num=num*10+(c-'0')`（Horner 攒数）；遇到 `+` 或 `-`，说明当前项读完了，`ans+=sgn*num` 结算，`num` 清零，`sgn` 换成新符号。扫描结束后**最后一项没有后继运算符来触发结算**，要补一句 `ans+=sgn*num`。

**第三步：两个容易翻车的边界，用状态机自然填平。**

1. **首项带符号**（如 `-5+3`）：`sgn` 初始为 $+1$、`num` 初始为 $0$。读到开头的 `-` 时先结算 `ans+=1*0`（加了个零，无害），再把 `sgn` 置 $-1$——于是首项 `5` 自动带上了负号。**不需要任何特判**，"先结算后翻号"的顺序天然处理了前导符号。反过来若先翻号后结算，首项符号就会挂错。
2. **空白字符**：题面说"一行字符串"，稳妥起见把非数字非运算符的字符（空格、`\r`、换行）一律跳过，不参与任何状态变化。

顺带一提一个有趣的小技巧：因为 `%d` 本身会吞掉前导 `+`/`-`，`while(scanf("%d",&x)==1)ans+=x;` 对无空格的合法算式也能工作（`1+2-3` 被读成 `1`、`+2`、`-3`）。但它依赖输入严格无空白、无多余字符，鲁棒性不如显式状态机，这里不采用。

**第四步：范围估算。** 长度 $\le60000$，每项至少占 $1$ 个数字字符，非首项还带 $1$ 个运算符，故项数 $m\le30001$。任何前缀部分和的绝对值 $\le m\times32767<10^9$，其实连 `int` 都装得下；题目说"长整型"，用 `i64` 更是绰绰有余。`num` 单项 $\le32767$，Horner 中间量也不会超。

**手造数据核对**（题面无样例）：

| 输入 | 手算 | 程序输出 |
|---|---|---|
| `1+2-3` | $0$ | `0` ✓ |
| `32767-32767+1` | $1$ | `1` ✓ |
| `-5+3` | $-2$ | `-2` ✓（前导负号） |
| `10` | $10$ | `10` ✓（单项、无运算符） |
| `0-32767-32767` | $-65534$ | `-65534` ✓ |
| `1+2+...+10` | $55$ | `55` ✓ |

## 二、思维链：完整证明

**记号。** 输入字符流为 $c_1c_2\cdots c_L$（$L\le60000$），合法算式形如
$$[\texttt{+}|\texttt{-}]\;t_1\;\mathrm{op}_2\;t_2\;\cdots\;\mathrm{op}_m\;t_m,$$
其中 $t_j$ 是十进制数字串（值 $v_j\in[0,32767]$），$\mathrm{op}_j\in\{+,-\}$，允许夹杂空白。首项符号 $s_1$ 由前导符号决定（无前导则 $+1$），其余 $s_j$ 由 $\mathrm{op}_j$ 决定。算式的值定义为 $W=\sum_{j=1}^m s_jv_j$。

---

### 引理 1（Horner 攒数正确）

若某项的数字字符依次为 $d_1,d_2,\dots,d_k$（$d_i\in\{0..9\}$），则执行 $k$ 次 `num=num*10+(c-'0')`（`num` 从 $0$ 开始）后，`num` $=\sum_{i=1}^k d_i\cdot10^{k-i}=v_j$。

*证明*：对 $k$ 归纳。$k=0$ 时 `num`$=0$，空数字串值为 $0$，成立。设 $k-1$ 位后 `num`$=\sum_{i=1}^{k-1}d_i10^{k-1-i}$。第 $k$ 步后
$$\texttt{num}'=10\sum_{i=1}^{k-1}d_i10^{k-1-i}+d_k=\sum_{i=1}^{k-1}d_i10^{k-i}+d_k\cdot10^0=\sum_{i=1}^kd_i10^{k-i}.$$
这正是十进制表示的定义。中间量单调递增且终值 $\le32767$，无溢出。证毕。

### 引理 2（扫描不变量）

把字符流按"项"划分：第 $j$ 项的**数字段**是 $t_j$ 的那 $k_j$ 个数字字符，其**定界符**是紧随其后的运算符（末项的定界符是 EOF）。定义扫描到任意位置时的状态：`ans`、`num`、`sgn`。则不变量为：

> 设当前正处于第 $j$ 项的数字段中（已读入其中前 $r$ 个数字，$0\le r\le k_j$），且此前所有完整项已结算。则
> `ans` $=\sum_{l<j}s_lv_l$，`num` $=\sum_{i=1}^r d_i10^{r-i}$（当前项已读前缀的值），`sgn` $=s_j$。

*证明*：对已读字符数归纳。

**初始**：未读任何字符，处于第 $1$ 项数字段之前（$r=0$），`ans`$=0$（空和）、`num`$=0$、`sgn`$=1$。若无前导符号则 $s_1=1$ ✓；若有前导符号，它属于"第 $1$ 项之前的定界符"，见下条运算符规则（结算空项 $0$ 后置号），同样到达 `sgn`$=s_1$、`num`$=0$ ✓。

**读到数字字符**：它必属于当前项的数字段（合法算式中数字只出现在项内）。由引理 1 的归纳步，`num` 更新为已读前缀的值；`ans`、`sgn` 不变 ✓。

**读到运算符 $o\in\{+,-\}$**：合法算式中，运算符出现当且仅当前一项的数字段刚结束（$r=k_j$）。由归纳假设 `num`$=v_j$、`sgn`$=s_j$，执行 `ans+=sgn*num` 后 `ans`$=\sum_{l\le j}s_lv_l$，即"前 $j$ 项完整结算"；`num=0`、`sgn`$=\mathrm{sign}(o)=s_{j+1}$，恰好是第 $j+1$ 项数字段开始前（$r=0$）的不变量 ✓。**前导符号**是 $j=0$ 的退化情形：`num`$=0$，结算加 $0$ 无害，`sgn` 置为 $s_1$ ✓。

**读到空白**：三个量都不变，而空白不属于任何项的数字段，不变量中"已读前缀"不受影响 ✓。

**EOF**：末项数字段读完（$r=k_m$）但没有运算符触发结算。循环外补 `ans+=sgn*num`，由不变量即 $\sum_{l<m}s_lv_l+s_mv_m=W$ ✓。证毕。

### 引理 3（项数与数值范围）

项数 $m\le(L+1)/2\le30001$；任意时刻 $|\texttt{ans}|\le m\cdot32767<10^9$，$0\le\texttt{num}\le32767$。故 `i64` 全程无溢出（事实上 `int` 也够，但按题面"长整型"用 `i64`）。

*证明*：每项至少 $1$ 个数字字符；除首项外每项前还有 $1$ 个运算符，故 $L\ge m+(m-1)=2m-1$，即 $m\le(L+1)/2$。`ans` 是若干完整项的带符号和，项数 $\le m$、每项 $\le32767$，三角不等式给出界。`num` 是单项前缀值，$\le v_j\le32767$。$30001\times32767\approx9.83\times10^8<2^{31}$，更远小于 $2^{63}$。证毕。

### 引理 4（对非法/宽松输入的鲁棒性）

代码对"非数字且非 $+/-$"的字符一律跳过。因此在合法算式允许夹杂任意空白（空格、`\r`、`\n`）时结果不变；对题面保证的合法输入，行为与引理 2 完全一致。

*证明*：空白字符不改变 `ans/num/sgn`（引理 2 第三条），也不参与项的划分——删掉所有空白后得到的纯算式与原式有相同的项序列与符号序列，故值相同。代码等价于"先删空白再扫描"。证毕。

### 定理

程序输出算式的值 $W=\sum_j s_jv_j$，时间 $O(L)$，额外空间 $O(1)$。

*证明*：引理 1 保证每项数值解析正确；引理 2 保证符号挂载与结算时机正确（含前导符号与末项 EOF 结算）；引理 4 保证空白不影响；引理 3 保证无溢出。每个字符恰被 `cin.get` 读一次并做 $O(1)$ 处理，故时间 $O(L)$；状态只有三个标量，空间 $O(1)$。证毕。

## 三、模式总结（按实际思考顺序）

- explore its property — 只有加减、无括号无优先级 ⇒ 不需要栈/表达式树，一遍扫描即可。
- classic problem solution — 三状态状态机（`sgn/num/ans`）：数字 Horner 攒数，遇运算符"先结算后翻号"。
- discuss by category — 前导符号（结算空项 $0$ 自然处理）、末项无后继运算符（EOF 补结算）、空白跳过。
- explore its property — 范围估算：项数 $\le30001$，部分和 $<10^9$，`i64` 绰绰有余。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 初值 | 记忆点 |
|---|---|---|---|
| `num` | 当前项已读数字前缀的值 | `i64`，$0$ | 遇运算符清零 |
| `sgn` | 当前项符号 $\pm1$ | `int`，$1$ | 遇运算符**结算后**再置新号 |
| `ans` | 已完整结算项的带符号和 | `i64`，$0$ | EOF 后还要加最后一项 |

### 算法步骤

1. I/O 加速三行。
2. `cin.get(c)` 逐字符读到 EOF：数字则 `num=num*10+(c-'0')`；`+`/`-` 则 `ans+=sgn*num; num=0; sgn=±1`；其余跳过。
3. 循环外 `ans+=sgn*num` 结算末项。
4. 输出 `ans`。

### 复杂度

- 时间：$O(L)$，$L\le60000$。
- 空间：$O(1)$（三个标量）。
- 验证状态：`g++ -std=c++20 -O2` 编译通过；六组手造数据（含前导负号、单项、极值项、连续减法）全部与手算一致。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2788 数学1（math1）- 加减算式
// 一遍扫描：数字用 Horner 攒进 num，遇到 +/- 就把 sgn*num 结进 ans 并翻转符号。
// 开头的符号作用在 num=0 上，天然正确；空白字符直接跳过。
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

i64 ans,num;
int sgn=1;

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	for(char c;cin.get(c);)
	{
		if(c>='0'&&c<='9')
			num=num*10+(c-'0');
		else if(c=='+'||c=='-')
		{
			ans+=sgn*num;	// 结算上一项
			num=0;
			sgn=c=='+'?1:-1;
		}
	}
	ans+=sgn*num;	// 最后一项没有后继运算符，单独结算
	cout<<ans<<'\n';
	return 0;
}
```

### 代码说明

- **先结算后翻号**的顺序是前导符号正确性的全部来源：开头的 `-` 结算的是 `num=0`，加零无害，随后 `sgn=-1` 恰好挂到首项上。
- 循环外那句 `ans+=sgn*num` 不可省：末项后面没有运算符。
- 用 `cin.get` 而不是 `cin>>`：算式是无空格的连续串，`>>` 会把整串当一个 token；逐字符读同时兼容夹杂空白的情形。
- 全局 `i64` 默认 $0$、`sgn` 显式置 $1$，与引理 2 的初始状态一一对应。
