# P2908 [USACO08OPEN] Word Power S — 题解

## 一、解题过程：人类思考叙事

**题意重述（剥离背景）。** 有 $N$ 个名字（$1\le N\le 1000$，每个长度 $\le 1000$，非空）和 $M$ 个能量串（$1\le M\le 100$，每个长度 $\le 30$，非空）。对每个名字，统计有多少个能量串是它的**子序列**——能量串的字符要按顺序出现在名字里，但**不必连续**；大小写等价（`Bessie` 蕴含 `EE`：两个 `e` 分别在第 $2$、$6$ 位）。每个名字输出一行答案。

口径说明：题面强调"所有的大写字母和小写字母都是等价的"，隐含字符集就是字母（原题保证字符串仅含字母）。因此把两边都**折成小写**后按普通字符相等匹配即可；代码用 `c-'a'` 索引也依赖这一点。

**第一步：认出问题——子序列判定，不是子串。** "按顺序出现、不一定紧挨"就是子序列（subsequence）的定义。样例解释里 `Bessie` 蕴含 `si`（`s` 在第 $3$ 位、`i` 在第 $5$ 位，中间隔着别的字符）而不蕴含 `eB`（顺序反了），把"保序、可跳、不可重排"三个要点都演示了。单个判定的经典做法是**双指针贪心**：扫名字，依次匹配能量串的每个字符，每次取最靠左的可行位置。

**第二步：估复杂度，发现要优化。** 对每对（名字，能量串）跑一次双指针，最坏 $O(N\cdot M\cdot L)=1000\times100\times1000=10^8$ 次字符比较——能过但很悬，而且做了大量重复工作：**同一个名字被 $M$ 个能量串各扫一遍**。名字的信息完全可以预处理一次、共享给所有能量串。

**第三步：next 自动机。** 对每个名字预处理 `nxt[p][c]` = 名字中位置 $\ge p$ 的第一个字母 `c` 的下标（不存在则记 $L$=名字长度）。倒序递推一遍，$O(26L)$。之后判定一个能量串只需逐字符跳：`cur=nxt[cur][c]`，跳到 $L$ 就失败，否则 `++cur` 继续——每个字符 $O(1)$，一个能量串 $O(|pat|)$。总复杂度降到 $O(N(26L+M\cdot P))\approx 1000\times(26000+3000)=2.9\times10^7$，而且与能量串内容无关地快。

**第四步：贪心为什么对？** 这是必须证的核心：每次取**最靠左**的匹配位，会不会"贪心吃亏"、错过后面才能成立的匹配？不会——归纳可证贪心的第 $i$ 个匹配位 $\le$ 任何合法匹配方案的第 $i$ 个匹配位（引理 2）。贪心把"剩余可选空间"留得最大，所以任何方案能匹配成功，贪心必然也成功。`nxt` 查询只是把这个贪心用查表加速，正确性原封不动。

**手造数据核对。** 题面 Hint 给了完整的 $5\times3$ 蕴含表，直接当第一组；另造三组打"重复字符""长度与顺序""大小写"：

第一组（Hint 原例）：

```
输入：
5 3
Bessie
Jonathan
Montgomery
Alicia
Angola

nGo
Ont
```

逐格手核：`Bessie`（b,e,s,s,i,e）含 `se`（s@2,e@5）✓、无 `n` ✗、无 `o` ✗ → $1$；`Jonathan`（j,o,n,a,t,h,a,n）无 `s` ✗、无 `g` ✗、`Ont`（o@1,n@2,t@4）✓ → $1$；`Montgomery`（m,o,n,t,g,o,m,e,r,y）无 `s` ✗、`nGo`（n@2,g@4,o@5）✓、`Ont`（o@1,n@2,t@3）✓ → $2$；`Alicia` 三个全 ✗ → $0$；`Angola`（a,n,g,o,l,a）无 `s` ✗、`nGo`（n@1,g@2,o@3）✓、`Ont`（o@3 之后再无 n）✗ → $1$。期望输出 `1 1 2 0 1`，程序逐行吻合 ✓。

第二组（重复字符 + 超长模式）：`1 2 / aaa / aa / aaaa`。`aa` 是 `aaa` 的子序列 ✓；`aaaa` 比名字长，鸽笼原理必失败 ✗。输出 `1` ✓。

另造极限数据：$1000$ 个长度 $1000$ 的名字、$100$ 个长度 $30$ 的能量串（名字字母充足，每个能量串都蕴含），$1000$ 行输出全为 `100`，瞬间跑完。

## 二、思维链：完整证明

**记号。** 名字 $s$（长度 $L\le1000$），能量串 $p$（长度 $P\le30$），均已折成小写。$\mathrm{fold}$ 把大写字母映为对应小写、其余不变。$s$ 的下标 $0..L-1$。"$p$ 是 $s$ 的子序列"指存在严格递增下标列 $t_1<t_2<\cdots<t_P$ 使 $s[t_i]=p[i]$（称这样的下标列为一个**嵌入**）。

---

### 引理 1（大小写折叠保持子序列关系）

设原始串 $S,P$ 仅含字母。则"$P$ 的字符按顺序出现在 $S$ 中、大小写等价"当且仅当 $\mathrm{fold}(P)$ 是 $\mathrm{fold}(S)$ 的（普通）子序列。

*证明*：定义字母等价 $c\sim d\iff\mathrm{fold}(c)=\mathrm{fold}(d)$。题意的"蕴含"是：存在严格递增下标列 $t_1<\cdots<t_P$ 使 $S[t_i]\sim P[i]$ 对所有 $i$。由 $\sim$ 的定义，$S[t_i]\sim P[i]\iff\mathrm{fold}(S[t_i])=\mathrm{fold}(P[i])$。又 $\mathrm{fold}$ 逐字符作用不改变长度与下标，$\mathrm{fold}(S)[t_i]=\mathrm{fold}(S[t_i])$、$\mathrm{fold}(P)[i]=\mathrm{fold}(P[i])$。故条件等价于 $\mathrm{fold}(S)[t_i]=\mathrm{fold}(P)[i]$，即 $\mathrm{fold}(P)$ 是 $\mathrm{fold}(S)$ 的子序列。两个方向逐字互推。证毕。

（$\mathrm{fold}$ 把 $52$ 个字母的 $26$ 个等价类一一映到 `a..z`，所以折叠后"字符相等"就是"大小写等价"，不会把不同字母混同。）

---

### 引理 2（贪心最左匹配的正确性与支配性）

定义贪心过程：$g_1$ = $s$ 中第一个等于 $p[1]$ 的位置；$g_i$ = $s$ 中位置 $>g_{i-1}$ 的第一个等于 $p[i]$ 的位置；某步不存在则贪心失败。则：

(a) **支配性**：若存在任一嵌入 $t_1<\cdots<t_P$，则贪心成功且 $g_i\le t_i$ 对所有 $i$；
(b) $p$ 是 $s$ 的子序列 $\iff$ 贪心成功。

*证明*：(a) 对 $i$ 归纳。$i=1$：$g_1$ 是 $p[1]$ 在 $s$ 中的**最小**出现位置，而 $t_1$ 是一个出现位置，故 $g_1\le t_1$。设 $g_{i-1}\le t_{i-1}$。$t_i>t_{i-1}\ge g_{i-1}$ 且 $s[t_i]=p[i]$，说明"位置 $>g_{i-1}$ 的 $p[i]$ 出现位置"集合非空（含 $t_i$），故 $g_i$ 存在（贪心不会在此步失败），且 $g_i$ 是该集合的最小元 $\le t_i$。归纳完成，贪心走完全部 $P$ 步，成功。

(b) "$\Leftarrow$"：贪心成功时 $g_1<\cdots<g_P$（每步要求位置 $>g_{i-1}$）且 $s[g_i]=p[i]$，本身就是一个嵌入。"$\Rightarrow$"：即 (a)。证毕。

**直觉**：贪心每一步都把匹配位压到最左，给后续字符留下**最长**的剩余后缀；任何别的嵌入的剩余空间都是它的子集，所以别的方案能走通，贪心必能走通。这就是"贪心不吃亏"的严格版本。

---

### 引理 3（`nxt` 表的正确性）

对名字 $s$（长 $L$）定义
$$\texttt{nxt}[p][c]=\min\{q\ge p:\ s[q]=c\}\quad(\text{集合为空时记 }L).$$
代码的倒序递推——`nxt[L][c]=L`；对 $p=L-1..0$：先整行复制 `nxt[p][c]=nxt[p+1][c]`，再令 `nxt[p][s[p]-'a']=p`——恰好算出上式。

*证明*：对 $p$ 从 $L$ 递减归纳。$p=L$：$\{q\ge L\}$ 为空，定义值 $L$，代码置 $L$ ✓。

设 $p+1$ 行正确。考察集合 $A=\{q\ge p:s[q]=c\}$ 与 $B=\{q\ge p+1:s[q]=c\}$，则 $A=B\cup(\{p\}\ \text{若}\ s[p]=c)$。
- 若 $s[p]=c$：$\min A=p$。代码先复制再覆盖 `nxt[p][c]=p` ✓。
- 若 $s[p]\ne c$：$A=B$，$\min A=\min B$（空时同为 $L$）。代码复制 `nxt[p+1][c]` 且不覆盖字母 $c$ ✓。

覆盖只影响 $c=s[p]$ 那一列，其余 $25$ 列保持复制值，两分支穷尽。证毕。

---

### 引理 4（查表查询 = 贪心，$O(P)$ 判定）

查询过程：`cur=0`；对 $p$ 的每个字符 $c$：`cur=nxt[cur][c]`，若 `cur==L` 判失败，否则 `++cur`。则查询成功当且仅当贪心成功（从而当且仅当 $p$ 是 $s$ 的子序列），且第 $i$ 步赋值后的 `cur` 恰为 $g_i+1$。单次查询 $O(P)$。

*证明*：归纳不变量：处理完第 $i$ 个字符后 `cur`$=g_i+1$（$g_i$ 为引理 2 的贪心匹配位）。初始 `cur=0`，相当于 $g_0=-1$（"上一个匹配位"为空）。第 $i$ 步：`nxt[cur][c]`$=\min\{q\ge g_{i-1}+1:s[q]=p[i]\}$，正是贪心定义的 $g_i$（不存在时为 $L$）。若为 $L$：贪心在第 $i$ 步失败，查询判失败 ✓；否则 `++cur` 得 $g_i+1$ ✓。走完 $P$ 步即贪心成功。由引理 2(b)，等价于子序列关系。每步一次数组访问 + 一次比较，$O(P)$。

**附带边界**：$P>L$ 时查询必失败——嵌入要求 $P$ 个严格递增下标落在 $[0,L)$，鸽笼原理不可能；查表过程也必然在某步跳到 $L$（每步 `cur` 至少 $+1$，至多 $L$ 步耗尽），无需特判。证毕。

---

### 引理 5（复杂度：从 $10^8$ 到 $2.9\times10^7$）

朴素双指针：每对（名字，能量串）最坏扫整个名字，$O(NML)=10^8$。`nxt` 方案：每个名字建表 $O(26L)$、回答 $M$ 个查询 $O(MP)$，总时间 $O(N(26L+MP))$；代入上界 $1000\times(26\times1000+100\times30)=2.9\times10^7$。空间 $O(NL+MP+26L)$（名字与能量串存储 + 一张复用表）。

*证明*：建表：$L$ 行 $\times26$ 列复制 + 每行一次覆盖，$O(26L)$；查询由引理 4 为 $O(P)$，$M$ 个共 $O(MP)$；$N$ 个名字求和即得。朴素法每对独立扫名字，最坏 $O(L)$，共 $NM$ 对。空间：`s` 共 $\le NL=10^6$ 字符，`t` 共 $\le MP=3000$ 字符，`nxt` 为 $1005\times26$ 个 `int` $\approx104$ KB，逐名字复用不累积。证毕。

**为什么值得优化**：$10^8$ 在 $1$ 秒时限边缘，且重复扫描同一名字 $M$ 遍是纯浪费；建表把"名字的字母分布信息"一次性固化，$M$ 个查询共享，复杂度对 $M$ 的依赖从 $O(NML)$ 降为 $O(NMP)$（$P\le30\ll L$）。

---

### 定理

程序对每个名字输出蕴含它的能量串个数（大小写等价、子序列意义），总时间 $O(N(26L+MP))$。

*证明*：引理 1 保证折小写后判定与题意等价；引理 3 保证 `nxt` 表正确；引理 4 保证查表查询与贪心逐步一致、失败判据正确；引理 2 保证贪心成功当且仅当子序列存在；引理 5 给出复杂度。对每个名字把 $M$ 个查询的成功数累加即答案。证毕。

## 三、模式总结（按实际思考顺序）

1. **explore its property** — "蕴含"= 子序列（保序、可跳、不可重排），不是子串；大小写等价 ⇒ 两边 fold 成小写再普通匹配。
2. **classic problem solution** — 子序列判定的经典双指针贪心：依次取最靠左的可行匹配位。
3. **explore its property** — 贪心支配性：归纳证 $g_i\le t_i$（任何嵌入），最左匹配给后续留最大空间，故贪心必不吃亏。
4. **consider easier version** — 估朴素复杂度 $NML=10^8$ 悬；同一名字被 $M$ 个模式重复扫 ⇒ 预处理一次、共享给所有模式。
5. **classic problem solution** — next 出现位置自动机 `nxt[p][26]`：倒序递推 $O(26L)$ 建表，每模式 $O(|pat|)$ 跳转判定，总量降到 $2.9\times10^7$。
6. **discuss by category** — 哨兵 $L$ 兼作失败标记；模式比名字长自动失败（鸽笼）；重复字母靠 `++cur` 跳过已用位；大小写折叠在建表前完成。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 | 初值 / 记忆点 |
|------|------|------|---------------|
| `n,m` | 名字数 $N$、能量串数 $M$ | `int` | 读入 |
| `s[i]` | 第 $i$ 个名字（处理时折小写） | `string[mxn]` | 读入，0-based |
| `t[j]` | 第 $j$ 个能量串（读入后立即折小写） | `string[mxm]` | 只折一次，所有名字共用 |
| `L` | 当前名字长度 | `int` | 每个名字现算；兼作"不存在"哨兵 |
| `nxt[p][c]` | 当前名字中位置 $\ge p$ 的第一个字母 `c` 的下标，不存在 $=L$ | `int[mxl][26]` | 每个名字重建：`nxt[L][*]=L`，倒序复制 + 覆盖 |
| `cur` | 贪心搜索起点 = 上一个匹配位 $+1$ | `int` | 每个模式从 $0$ 开始；跳到 $L$ 即失败 |
| `ok` | 当前模式是否匹配成功 | `bool` | 每模式重置 `true` |
| `ans` | 当前名字的能量值 | `int` | 每名字重置 $0$，`ans+=ok` |
| `mxn,mxm,mxl` | $1000+5$ / $100+5$ / $1000+5$ | `constexpr int` | 数组尺寸 |

### 算法步骤

1. I/O 加速三行；读 $N,M$；读 $N$ 个名字；读 $M$ 个能量串并折小写。
2. 对每个名字：折小写；建 `nxt` 表（末行置 $L$，$p=L-1..0$ 复制下一行再覆盖 `nxt[p][s[p]]=p`）。
3. 对每个能量串：`cur=0` 逐字符 `cur=nxt[cur][c]`，遇 $L$ 失败，否则 `++cur`；成功则 `++ans`。
4. 输出该名字的 `ans`。

### 复杂度

- 时间：$O(N(26L+MP))\approx2.9\times10^7$（$L\le1000,P\le30$）。
- 空间：$O(NL+MP+26L)$，`nxt` 表约 $104$ KB。
- 验证状态：`g++ -std=c++20 -O2` 编译通过；Hint 原例输出 `1 1 2 0 1` 与蕴含表逐格吻合；另造"重复字母 + 超长模式""顺序反转""纯大小写"三组小数据输出 `1 / 1 / 1` 全对；$1000$ 名字 $\times1000$ 字符、$100$ 模式 $\times30$ 字符的极限数据 $1000$ 行全为 `100`，瞬间完成。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2908 [USACO08OPEN] Word Power S
// 能量=名字中作为子序列出现的能量串个数（忽略大小写）
// 每个名字建 nxt[p][c]=位置≥p 的第一个字母 c（不存在=L），贪心最左匹配每个模式 O(|pat|)
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{1005},mxm{105},mxl{1005};

int n,m,nxt[mxl][26];
string s[mxn],t[mxm];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>m;
	for(int i=0;i<n;++i)
		cin>>s[i];
	for(int j=0;j<m;++j)
	{
		cin>>t[j];
		for(char&c:t[j])
			if(c>='A'&&c<='Z')
				c+=32;	// 大小写等价：统一折成小写
	}
	for(int i=0;i<n;++i)
	{
		int L=s[i].size();
		for(char&c:s[i])
			if(c>='A'&&c<='Z')
				c+=32;
		for(int c=0;c<26;++c)
			nxt[L][c]=L;	// 哨兵 L：后面再也没有字母 c
		for(int p=L-1;p>=0;--p)
		{
			for(int c=0;c<26;++c)
				nxt[p][c]=nxt[p+1][c];
			nxt[p][s[i][p]-'a']=p;
		}
		int ans=0;
		for(int j=0;j<m;++j)
		{
			int cur=0;
			bool ok=true;
			for(char c:t[j])
			{
				cur=nxt[cur][c-'a'];	// 贪心：取最靠左的可行匹配位
				if(cur==L){ok=false;break;}
				++cur;
			}
			ans+=ok;
		}
		cout<<ans<<'\n';
	}
	return 0;
}
```

### 代码说明

- **哨兵是 $L$ 不是 INF**：`nxt` 存的是"位置"，$L$（名字长度）天然表示"越界 = 不存在"，且查询里 `cur==L` 恰好统一了失败判据——下一步若从 $L$ 出发，`nxt[L][c]=L` 仍会失败，不会读到脏数据。每个名字重建表时末行必须重置为当前的 $L$（名字长度不同）。
- **先判 `cur==L` 再 `++cur`**：匹配位是 `cur` 本身，成功后搜索起点才是 `cur+1`；顺序反了会跳过刚匹配的字符或漏判失败。
- **折叠时机**：能量串读入时折一次即可（所有名字共用）；名字在**建表前**折，保证 `s[i][p]-'a'` 落在 $[0,26)$。
- **重复字母**：`++cur` 保证同一位置不会被两个模式字符复用（`aaa` 匹配 `aa` 用位 $0,1$，匹配 `aaaa` 在第四步跳到 $L$ 失败）。
- `nxt` 全局复用、逐名字覆盖，无需清空：倒序递推把 $0..L$ 行全部写满，旧名字的残留行（$>L$）不会被访问。
- 模式比名字长无需特判：`cur` 每步至少 $+1$，必然在 $P$ 步内跳到 $L$（引理 4 附带边界）。
