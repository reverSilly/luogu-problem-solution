# P2278 [HNOI2003] 操作系统 — 题解

## 一、解题过程：人类思考叙事

先把调度规则用自己的话讲一遍。单 CPU，每个进程有三个已知量：到达时间、执行时间、优先级（数字越大优先级越高）。规则可以拆成五条：

1. 同一时刻只有一个进程在运行。
2. 进程到达时如果 CPU 空闲，它立即开始运行。
3. 进程运行期间，如果来了一个**优先级严格更高**的新进程，新进程立即抢占 CPU，原来的进程让出。
4. 进程到达时如果 CPU 正在运行一个优先级**不低于**它的进程，它只能等待（同优先级也不抢占）。
5. 每当 CPU 空闲（当前进程结束），从等待进程里选优先级最高的运行；优先级相同则选到达时间最早的。

输入按到达时间从小到大给出，一行四个自然数：进程号、到达时间、执行时间、优先级；读到文件结束。要求按**结束时间**输出每个进程的进程号和结束时间。

第一反应是逐单位时间模拟：每个时刻先处理到达，再决定谁跑，跑一秒，时间加一。但到达时间和执行时间都能到 $10^8$，进程数也不少，总时间可以到 $10^{13}$ 量级，逐秒模拟必然超时。

必须找到"时间可以跳跃"的理由。盯着规则看：能改变"谁在运行"的事件只有两类——有新进程到达（可能触发抢占），或者当前进程执行完毕（CPU 重新选人）。如果在两个相邻的到达时刻之间没有任何进程到达，那么等待集合不变，正在跑的进程优先级也不变，没有谁能触发抢占；于是它只会一直跑到结束。也就是说，**两次到达之间，CPU 的行为是完全确定的**，我们不需要一秒一秒地走，只需要一次把这段时间跨过去。

于是自然想到事件驱动：维护当前时间 $t$ 和等待集合，每次让当前最优的进程一直跑到"它结束"或"下一个进程到达"这两个时刻中较早的那个。等待集合需要支持"插入"和"取优先级最高（同优先级取到达最早）"，用优先队列即可。

这里有一个很漂亮的观点：可以把"正在运行的进程"也放回优先队列里，不必单独维护。理由如下。若进程 $r$ 正在运行，那么等待中的所有进程优先级都不高于 $r$——否则上一轮就会选那个更高的；同优先级的等待者到达时间都比 $r$ 晚，否则上一轮会选它。所以 $r$ 恰好是"按优先级降序、到达时间升序"排序后的堆顶。新进程到达时，只有它的优先级**严格大于** $r$ 才会改变堆顶，这正好就是"严格更高才抢占"；优先级相同的新进程到达更晚，排在 $r$ 后面，$r$ 继续运行，正好就是"同优先级不抢占"。CPU 空闲时选堆顶，也正好符合规则 5。一个优先队列就把三条规则统一了。

具体循环：

- 若堆为空，把时间跳到下一个进程的到达时刻（CPU 空闲期间什么都不会发生）。
- 把所有到达时间 $\le t$ 的进程压入堆（它们都已经到达）。
- 弹出堆顶 $u$，它就是当前应该运行的进程。
- 设 $nxt$ 为下一个尚未入堆的进程的到达时间；若没有则为无穷大。
- 若 $t+u.rem\le nxt$，$u$ 会在下一进程到达之前（或恰好同时）结束：令 $t\mathrel{+}=u.rem$，输出 $u$ 的进程号与 $t$。
- 否则 $u$ 只能运行到 $nxt$：令 $u.rem\mathrel{-}=nxt-t$，$t=nxt$，把 $u$ 压回堆。下一轮先插入到达时刻为 $nxt$ 的新进程，再重新取堆顶；如果新进程优先级更高，$u$ 就被抢占了，否则 $u$ 继续当堆顶。

手工跑几个例子确认语义。第一组：

```
1 0 10 1
2 3 1 2
```

$t=0$ 时压入 1，堆顶是 1，下一到达是 $3$，$0+10>3$，所以 1 只跑到 $3$，剩余 $7$，时间跳到 $3$。压入 2（优先级 $2>1$），堆顶变成 2，$3+1\le\infty$，2 在 $4$ 结束，输出 `2 4`。之后 1 以剩余 $7$ 继续，在 $11$ 结束，输出 `1 11`。

第二组（同一时刻到达）：

```
1 0 5 1
2 0 3 2
3 0 2 2
```

三者在 $t=0$ 一起入堆。优先级最高的有 2 和 3，同优先级取到达早的，而它们到达时间相同，按输入顺序取 2（保证不会有同优先级同时到达，所以这个平局实际不会出现）。2 在 $3$ 结束；然后 3 在 $5$ 结束；最后 1 在 $10$ 结束。

第三组（同优先级不抢占）：

```
1 0 5 1
2 2 1 1
```

2 到达时优先级与 1 相同，1 继续运行，$5$ 结束；2 在 $6$ 结束。

第四组（空闲空档）：

```
1 0 2 3
2 10 1 1
```

1 在 $2$ 结束，堆空，时间直接跳到 $10$，2 在 $11$ 结束。

实现上踩过一个实打实的坑：一开始把"无穷大"写成 `1145141919`（约 $1.1\times10^9$），小数据全对，但造了一组 $20000$ 个进程、每个执行 $10^8$ 的数据后程序卡死了。原因是所有进程都到达后 $nxt$ 取这个"无穷大"，而真实时间已经超过 $10^{12}$，`t+rem<=nxt` 恒假，代码走进"只跑到 $nxt$"的分支，用负数去减剩余时间，时间还会倒退，循环永远结束不了。换成 $1.145\times10^{18}$ 之后一切正常。结论：**事件驱动模拟里的 INF 必须大于最大可能的总时间**，不能随手拿一个"看起来很大"的 $10^9$ 或 $10^{12}$。

## 二、思维链：完整证明

**形式化规则**：设时刻 $t$ 的**就绪集合** $R(t)$ 为所有满足"到达时间 $\le t$ 且尚未结束"的进程。规则为：

- R1：任意时刻至多一个进程在运行。
- R2：若某进程到达时 CPU 空闲，它立即运行。
- R3：若运行中的进程 $r$ 遇到到达进程 $p$ 且 $pr(p)>pr(r)$，则 $p$ 立即抢占，$r$ 转为等待。
- R4：若 $pr(p)\le pr(r)$，$p$ 等待，$r$ 继续。
- R5：CPU 空闲且有等待进程时，运行其中优先级最高者；若并列，运行到达时间最早者。

题面保证不会有"相同优先级且同时到达"的两个进程；下文的比较器额外用进程号打破剩余平局，只是为了给优先队列一个严格全序。

**引理 1（无到达则不换人）**：设区间 $(t,t')$ 内没有任何进程到达。若时刻 $t$ 有一个进程 $r$ 在运行，则在 $r$ 结束之前，CPU 一直运行 $r$，不会切换到其他进程。

*证明*：按规则，运行中的进程只在两种情况下被换下：一是 R3 的抢占，二是它自己结束（R5 重新选人）。区间内没有到达，R3 的前提"有进程到达"不成立，故不会发生抢占。$r$ 未结束时 CPU 不空闲，R5 也不会触发。等待集合与 $r$ 的优先级在区间内都不变，没有任何机制能换下 $r$。因此 $r$ 一直运行到剩余时间归零。证毕。

**引理 2（堆顶就是规则的选择）**：设在决策时刻 $t$ 已把所有到达时间 $\le t$ 的进程插入堆中，堆按"优先级降序、到达时间升序、进程号升序"排序。则规则在这一时刻选择运行的进程恰好是堆顶。

*证明*：分两种情形。

**情形 A：时刻 $t$ 之前 CPU 空闲。** 此时等待集合必为空：若还有等待进程，按 R5，CPU 在更早的时刻就会开始运行其中一个，不可能保持空闲。因此 $t$ 时刻的就绪集合恰好是"到达时间等于 $t$ 的新进程"（更早到达的进程要么已结束，要么在等待，而等待为空说明都已结束）。规则 R2 让新到达的进程运行；若有多个同时到达，R5 规定取优先级最高、并列取到达最早，这正是堆顶的定义。

**情形 B：时刻 $t$ 之前 CPU 正在运行进程 $r$。** 先证明两条性质：

1. 所有等待进程的优先级都不高于 $pr(r)$。理由：$r$ 是在上一次决策时被选中的；若当时某个等待进程优先级更高，按 R5 就不会选 $r$；从上次决策到 $t$ 之间由引理 1 没有发生到达，等待集合只可能因进程结束而变小，不会凭空出现更高优先级的等待者。
2. 若有等待进程与 $r$ 优先级相同，则它的到达时间晚于 $r$。理由：若它到达更早，按 R5 的并列规则，上次决策会选它而不是 $r$。

现在把时刻 $t$ 到达的新进程加入就绪集合。对任意新进程 $p$：

- 若 $pr(p)>pr(r)$，由 R3，$p$ 抢占，运行 $p$；此时 $p$ 是就绪集合中优先级最高者（等待者不高于 $r$，其余新进程即使更高也只是另一个候选，堆顶取其中最高），正是堆顶。
- 若 $pr(p)\le pr(r)$：若严格小于，由 R4，$p$ 等待，$r$ 继续；若等于，$p$ 的到达时间晚于 $r$，按并列规则仍应让 $r$ 继续，这也符合 R4。此时 $r$ 仍是就绪集合的最大元素：等待者优先级不高于它，新进程优先级不高于它，等于它时到达更晚。堆顶正是 $r$。

多个新进程同时到达时，上述论证逐对比较即可：就绪集合的最大元素要么是 $r$，要么是某个严格更高优先级的新进程；堆顶的定义与规则的选择一致。证毕。

**引理 3（一次事件步的状态正确性）**：设循环开始时不变式成立，$u$ 为堆顶，$nxt$ 为下一个未入堆进程的到达时间（没有则为 $\infty$），且 $nxt>t$。执行下述一步后，模拟状态与真实系统在时刻 $\min(t+rem_u,nxt)$ 的状态一致：

- 若 $t+rem_u\le nxt$：$t\gets t+rem_u$，$u$ 结束并从堆中删除，输出 $u$；
- 否则：$u$ 的剩余时间减去 $nxt-t$，$t\gets nxt$，$u$ 放回堆中。

*证明*：由引理 2，$u$ 是时刻 $t$ 真实系统应运行的进程。由引理 1，在 $nxt$ 之前没有到达，$u$ 不会被打断。

- 若 $rem_u\le nxt-t$：$u$ 连续运行 $rem_u$ 个单位后在 $t+rem_u$ 结束，结束时刻不晚于 $nxt$。这段时间内没有新进程到达（$t+rem_u\le nxt$），真实系统在 $t+rem_u$ 移除 $u$，其余进程原样等待。模拟做同样的事，并把 $t$ 更新为 $t+rem_u$，状态一致；若之后还有等待进程，循环的下一轮会按 R5 继续选人，直到时间到达 $nxt$，每一步都可重复本论证。
- 若 $rem_u>nxt-t$：$u$ 从 $t$ 连续运行到 $nxt$，消耗 $nxt-t$ 个单位，剩余 $rem_u-(nxt-t)>0$，仍处于运行/就绪状态；等待集合在这段时间内不变（没有到达、没有结束），$t$ 时刻新到达的进程要等到 $nxt$ 才进入就绪集合。模拟把剩余时间减去 $nxt-t$、把 $t$ 置为 $nxt$、把 $u$ 放回堆，正好对应"$u$ 还没结束、等待集合不变"这一状态。下一轮先插入 $nxt$ 时刻到达的新进程，再取堆顶，就完成了 $nxt$ 时刻的决策。
- 若 $rem_u=nxt-t$：归入第一种情况，$u$ 恰在 $nxt$ 结束；下一轮在 $t=nxt$ 插入新到达的进程再选人，与真实系统"$u$ 结束、新进程到达、重新调度"一致。

三种情况覆盖了所有可能，状态转移正确。证毕。

**引理 4（循环不变式）**：在每轮循环的开头（尚未执行空闲跳转与入堆），下列命题同时成立：

1. $t$ 是已经忠实模拟到的时刻；
2. 每个到达时间 $\le t$ 的进程，要么已结束并输出，要么在堆中且剩余时间正确；
3. 堆中不存在到达时间 $>t$ 的进程；
4. 若真实系统在时刻 $t$ 应有一个进程运行，则它就是堆顶。

*证明*：对循环轮数归纳。

- 初始时 $t=0$，堆空，还没有任何进程到达（若最早到达时间为 $0$，本轮会立即入堆），四条成立。
- 若堆空且还有未入堆进程：真实系统在 $t$ 到下一到达时刻之间空闲，不做任何事；模拟把 $t$ 跳到该到达时刻，进程状态完全不变，第 2、3 条仍成立，第 4 条在跳转后的时刻由下一轮的入堆与选人建立。
- 非空时：先把所有到达时间 $\le t$ 的进程入堆，由输入按到达时间排序，这一步恰好补齐了就绪集合，第 2、3 条成立；由引理 2，堆顶就是规则的选择；由引理 3，弹出堆顶并按两种情况推进后，状态与真实系统在更新后的时刻一致，第 1、2 条成立；被放回堆的 $u$ 剩余时间正确，未入堆的进程到达时间都大于新的 $t$（因为 $nxt$ 是最近的未来到达），第 3 条成立；第 4 条在下一轮由引理 2 重新建立。

由归纳原理，不变式在每一轮都成立。证毕。

**引理 5（终止与复杂度）**：设进程数为 $n$，则循环至多执行 $2n+1$ 轮，总时间复杂度 $O(n\log n)$，空间复杂度 $O(n)$。

*证明*：每轮循环分两类：

- "结束"分支：堆顶进程被永久删除，这样的轮次至多 $n$ 次。
- "被抢占/跑到下一到达"分支：时间被推进到 $nxt$，而 $nxt$ 是某个尚未入堆进程的到达时间，因此 $idx<n$。下一轮开始时 $t=nxt$，入堆循环至少会把该进程插入并使 $idx$ 增加 $1$。这样的轮次夹在入堆轮之间，至多 $n$ 次推进，加上至多 $n$ 次入堆推进，总轮数为 $O(n)$。

每轮至多做一次入堆（均摊到每个进程一次）、一次弹出、一次压回，优先队列单次操作 $O(\log n)$，故总时间 $O(n\log n)$。存储所有进程与堆，空间 $O(n)$。证毕。

**引理 6（输出正确）**：程序对每个进程恰好输出一行，输出的结束时间等于该进程在真实调度中的结束时间，且各行按结束时间非降序排列。

*证明*：进程只会在两种情况下离开堆：剩余时间在执行中减到 $0$（结束分支），或者初始剩余时间就是 $0$（第一个分支中 $t+0\le nxt$，立即输出）。由引理 4 的不变式，离开时 $t$ 正是真实系统中该进程运行完剩余时间的时刻，即结束时间。每个进程的总执行时间有限，循环不会漏掉它；由引理 5 循环终止，故每个进程恰好输出一次。$t$ 在每轮中只增不减（结束分支增加 $rem\ge0$，抢占分支增加到 $nxt>t$，空闲分支跳到不早于当前时刻的到达时间），而输出发生在 $t$ 更新之后，因此输出行的结束时间随输出顺序非降。题面要求"按照进程结束的时间输出"，非降序满足这一要求；若出现执行时间为 $0$ 的进程导致同一时刻多个结束，这些行之间的先后不影响结束时间本身。证毕。

**引理 7（比较器合法性）**：`operator<` 定义的关系是严格弱序（实际上是全序），因此 `priority_queue` 的行为良定义。

*证明*：该比较器等价于按三元组 $(-pr,\ at,\ id)$ 的字典序比较。三个坐标都取全序（整数的大小、进程号互不相同），字典序在全序坐标上仍是全序：任意两个不同元素必有一个坐标首次不同，比较结果唯一且满足非自反、传递、可比。故它是严格弱序。证毕。

**定理**：程序输出的每一行都是正确的"进程号 + 结束时间"，且按结束时间排列。

*证明*：由引理 4，模拟的每一步都与真实调度一致；由引理 6，输出时刻与结束时间一致且顺序合法；由引理 7，优先队列的排序可靠。因此输出正确。证毕。

## 三、模式总结（按实际思考顺序）

- **explore its property** — 只有"进程到达"和"当前进程结束"会改变调度决策，两次到达之间跑谁完全确定。
- **hit the wall** — 逐单位时间模拟，总时间可达 $10^{13}$ 以上，必然超时。
- **reduce to easier problem** — 事件驱动：把连续时间压成一次"运行 $\min(rem,nxt-t)$"的跳跃。
- **classic problem solution** — 优先队列维护等待集合，键为（优先级降序，到达时间升序）。
- **discuss by category** — 队首在下一到达前跑完 / 跑不完只能跑到下一到达，两种情况分别更新状态。
- **unify the rules** — 把"正在运行"也看成堆顶：严格更高才换顶，同优先级因到达更早而留任。
- **boundary** — 堆空时时间跳到下一到达；总时间与 INF 必须使用足够大的 64 位值（$10^9$、$10^{12}$ 都不够）。
- **verify tie rule** — "同优先级不抢占"由比较器的"到达早者优先"自动实现，不需要额外判断。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 | 初始化 / 记忆点 |
|------|------|------|----------------|
| $n$ | 进程总数（读到 EOF） | `int` | $0$，每读一行加一 |
| $P_i$ | 第 $i$ 个进程 `{id,at,rem,pr}` | `proc[]` | 按输入顺序存放（输入已按到达时间非降序） |
| $id$ | 进程号 | `int` | 输入 |
| $at$ | 到达时间 | `i64` | 输入 |
| $rem$ | 剩余执行时间 | `i64` | 初值等于输入的执行时间，运行中递减 |
| $pr$ | 优先级（越大越高） | `int` | 输入 |
| $Q$ | 等待/就绪进程的大根堆 | `priority_queue<proc>` | 空；比较器为优先级降序、到达升序、进程号升序 |
| $idx$ | 下一个尚未入堆的进程下标 | `int` | $0$ |
| $t$ | 当前模拟时刻（已完成工作的右端点） | `i64` | $0$ |
| $nxt$ | 下一个未入堆进程的到达时间，没有则为 $\infty$ | `i64` | 每轮计算，$\infty=1145141919810114514$ |

### 算法步骤

1. 循环 `cin>>id>>at>>du>>pr` 直到 EOF，把 `{id,at,du,pr}` 存入 $P$（`du` 作为剩余时间 `rem` 的初值）。
2. 初始化堆 $Q$ 为空、$idx=0$、$t=0$。
3. 当 $idx<n$ 或堆非空时循环：
   1. 若堆为空，令 $t=\max(t,P_{idx}.at)$（CPU 空闲，直接把时间跳到下一进程到达）。
   2. 当 $idx<n$ 且 $P_{idx}.at\le t$ 时，把 $P_{idx}$ 压入堆并令 $idx$ 加一。
   3. 弹出堆顶 $u$。
   4. 令 $nxt=P_{idx}.at$（若 $idx<n$），否则 $nxt=\infty$。
   5. 若 $t+u.rem\le nxt$：令 $t\mathrel{+}=u.rem$，输出 `u.id t`。
   6. 否则：令 $u.rem\mathrel{-}=nxt-t$，$t=nxt$，把 $u$ 压回堆。
4. 输出顺序即为按结束时间排列的顺序，程序结束。

### 复杂度

- 时间复杂度：$O(n\log n)$，循环 $O(n)$ 轮，每轮优先队列操作 $O(\log n)$。
- 空间复杂度：$O(n)$，存储全部进程与当前等待集合（题面保证等待队列不超过 $15000$）。

### 验证状态

编译通过（`g++ -std=c++20 -O2`）；用四组手造数据分别验证了抢占、同一时刻到达、同优先级不抢占、空闲空档，结果均符合规则；与逐单位时间模拟的暴力在 $300$ 组小数据与 $100$ 组 $15\sim30$ 进程数据上对拍全部一致；另用 $20000$ 个进程、每个执行 $10^8$ 的极限数据验证总时间 $2\times10^{12}$ 时输出仍单调且末行恰为 `20000 2000000000001`。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2278 [HNOI2003] 操作系统
// 事件驱动模拟：两次到达之间没人能抢占，直接让堆顶跑到"结束"或"下一到达"
// 堆顶 = 优先级最高、同优先级到达最早；严格更高才抢占，同优先级自然留任
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{1000005};
constexpr i64 inf{1145141919810114514LL};   // 必须大于最大可能总时间

struct proc
{
	int id;
	i64 at,rem;
	int pr;
	friend bool operator<(const proc&a,const proc&b)
	{
		if(a.pr!=b.pr)
			return a.pr<b.pr;          // 优先级大的先
		if(a.at!=b.at)
			return a.at>b.at;          // 同优先级到达早的先
		return a.id>b.id;
	}
}P[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	int n=0,id,pr;
	i64 at,du;
	while(cin>>id>>at>>du>>pr)
		P[n++]={id,at,du,pr};

	priority_queue<proc>Q;
	int idx=0;
	i64 t=0;
	while(idx<n||!Q.empty())
	{
		if(Q.empty())                  // CPU 空闲，时间跳到下一到达
			t=max(t,P[idx].at);
		while(idx<n&&P[idx].at<=t)     // 所有已到达的进程入堆
			Q.push(P[idx++]);
		proc u=Q.top();
		Q.pop();
		i64 nxt=(idx<n?P[idx].at:inf);
		if(t+u.rem<=nxt)               // 在下一到达前（或恰好同时）跑完
		{
			t+=u.rem;
			cout<<u.id<<' '<<t<<'\n';
		}
		else                           // 只跑到下一到达，被抢占或继续竞争
		{
			u.rem-=nxt-t;
			t=nxt;
			Q.push(u);
		}
	}
	return 0;
}
```
