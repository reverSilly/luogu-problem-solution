# P2038 [NOIP 2014 提高组] 无线网络发射器选址 — 题解

## 一、解题过程：人类思考叙事

题意：城市是 $129\times 129$ 的网格（东西向、南北向街道各 129 条，编号 $0\sim 128$）。有 $n$ 个路口存在公共场所，第 $i$ 个在 $(x_i,y_i)$，有 $k_i$ 个。只能装一个发射器，传播参数 $d$，覆盖范围是以安装点为中心、边长 $2d$ 的正方形（含边界）。求：能覆盖最多公共场所的安装点有**多少个**，以及最多能覆盖**多少个**公共场所。

第一反应：这题就是枚举。枚举所有可能的安装点 $129\times 129 = 16641$ 个，每个点再扫一遍 $n\le 20$ 个公共场所看看有没有被覆盖，$16641\times 20 \approx 3.3\times 10^5$，秒过。

但先想清楚"覆盖"的判定。安装点在 $(x,y)$，覆盖范围是 $[x-d,x+d]\times[y-d,y+d]$（闭区间，因为题面说"传播范围包括正方形边界"）。公共场所 $(x_i,y_i)$ 被覆盖当且仅当

$$|x-x_i|\le d \quad\text{且}\quad |y-y_i|\le d$$

注意"包含边界"，所以是 $\le$ 而不是 $<$。这个细节如果写成 `<`，样例就过不了（样例里 $d=1$，两个点 $(4,4)$ 和 $(6,6)$，要同时覆盖需要 $x\in[5,5]$、$y\in[5,5]$，即只有 $(5,5)$ 一个点，如果用严格小于就一个都覆盖不到）。

枚举时维护两个量：
- `best`：目前找到的最大覆盖数，初值设成 $-1$（这样第一个点一定会触发"更新"分支）；
- `cnt`：达到 `best` 的点个数。

对每个点算出 `sum`：
- 若 `sum > best`：说明找到了更好的，记录 `best = sum`，`cnt = 1`；
- 若 `sum == best`：又找到一个同样好的，`cnt++`；
- 否则不管。

最后输出 `cnt` 和 `best`。

样例验证：$d=1$，两个点 $(4,4,10)$ 和 $(6,6,20)$。
- 能覆盖 $(4,4)$ 的安装点：$x\in[3,5],y\in[3,5]$，共 9 个；
- 能覆盖 $(6,6)$ 的安装点：$x\in[5,7],y\in[5,7]$，共 9 个；
- 交集是 $x=5,y=5$ 一个点，此处覆盖 $10+20=30$；
- 其余点最多只覆盖一个，最多是 20（9 个点）。

所以最大值是 30，只有 1 个方案，输出 `1 30` ✓。

这里有个容易搞混的地方：题目问的是"安装地点**方案数**"和"能覆盖的**最多公共场所数量**"。注意 `cnt` 是**安装点的个数**，不是覆盖方案的个数；`best` 是公共场所的数量，不是方案数。输出顺序是"方案数 最多数量"，即 `1 30`。

**边界情况**：安装点可以在城市的任何一个路口，包括那些没有公共场所的路口（比如 $(0,0)$），也包括边角。所以必须枚举全部 $129\times 129$，不能只枚举有公共场所的路口附近。

**枚举范围**：题目说街道编号 $0\sim 128$，共 129 条，所以安装点坐标也应该是 $0\sim 128$。注意**不能**枚举 $-d\sim 128+d$，因为安装地点必须在"城市内"的路口上。

## 二、思维链：完整证明

**引理 1**（覆盖判定）：安装点 $(x,y)$ 覆盖公共场所 $i$ 当且仅当 $|x-x_i|\le d$ 且 $|y-y_i|\le d$。

*证明*：以 $(x,y)$ 为中心、边长 $2d$ 的正方形，其横坐标范围为 $[x-d,x+d]$，纵坐标范围为 $[y-d,y+d]$（含边界）。点 $(x_i,y_i)$ 落在该正方形内当且仅当 $x-d\le x_i\le x+d$ 且 $y-d\le y_i\le y+d$，即 $|x-x_i|\le d$ 且 $|y-y_i|\le d$。证毕。

**引理 2**（枚举的完备性）：算法枚举了所有合法安装地点。

*证明*：城市由 129 条东西向街道与 129 条南北向街道构成，编号均为 $0\sim 128$，其交点（路口）恰为所有满足 $0\le x\le 128$、$0\le y\le 128$ 的整数点，共 $129^2=16641$ 个。算法用两重循环 `for(x=0..128) for(y=0..128)` 恰好遍历这 $16641$ 个点，每个点一次，不重不漏。证毕。

**引理 3**（`sum` 的正确性）：算法在安装点 $(x,y)$ 处计算出的 `sum` 等于该点能覆盖的公共场所总数。

*证明*：算法对每个公共场所 $i$，由引理 1 判定其是否在覆盖范围内，若在则把 $k_i$ 加入 `sum`。所有公共场所恰好被检查一次，故 `sum` 恰为被覆盖公共场所的数量之和。证毕。

**引理 4**（`best` 与 `cnt` 的不变式）：在枚举过程中的任意时刻，`best` 等于已枚举点中最大的 `sum`，`cnt` 等于已枚举点中 `sum == best` 的点数。

*证明*：对枚举点数归纳。初始时 `best=-1`、`cnt=0`，此时"已枚举点"为空集，其最大 `sum` 无定义，取 `best=-1`、`cnt=0` 与不变式相容（约定空集的最大值小于任何合法 `sum`，因为 `sum\ge 0$）。

设处理新点得到 `sum` 后：

- 若 `sum > best`：新点成为唯一已知的最优（此前 `cnt` 个点都等于旧的 `best` < 新 `sum`，不再是最优），故令 `best=sum`、`cnt=1` 正确。
- 若 `sum == best`：新点与旧的 `cnt` 个最优点并列，`cnt` 加一正确。
- 若 `sum < best`：新点不是最优点，两个量都不变正确。

故不变式始终成立。证毕。

**定理**：算法输出正确。

*证明*：由引理 2，枚举覆盖了所有合法安装点；由引理 3，每个点的覆盖数计算正确；由引理 4，枚举结束后 `best` 是所有安装点中的最大覆盖公共场所数，`cnt` 是达到该最大值的安装点个数。二者正是题目所求。证毕。

## 三、模式总结（按实际思考顺序）

1. **识别题型** — 网格上的"枚举安装点 + 统计覆盖"，范围小，直接暴力。
2. **明确枚举范围** — 街道编号 $0\sim 128$，安装点必须是**路口**，共 $129^2$ 个。
3. **覆盖判定的数学化** — $|x-x_i|\le d$ 且 $|y-y_i|\le d$，注意是 $\le$（含边界）。
4. **一次遍历同时求两个答案** — 维护 `best` 与 `cnt`，`sum>best` 时重置计数，`sum==best` 时计数加一。
5. **别漏掉"没有公共场所的路口"** — 候选安装点不能只取有公共场所的地方。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $d$ | 发射器传播参数 | `int`，$1\le d\le 20$ |
| $n$ | 有公共场所的路口数 | `int`，$\le 20$ |
| $x_i,y_i$ | 第 $i$ 个公共场所的坐标 | `int[]`，$0\sim 128$ |
| $k_i$ | 第 $i$ 个路口的公共场所数量 | `i64`，$\le 10^6$ |
| `sum` | 当前安装点能覆盖的公共场所总数 | `i64` |
| `best` | 所有安装点中最大的 `sum` | `i64`，初值 $-1$ |
| `cnt` | 达到 `best` 的安装点个数 | `int` |

### 算法步骤

1. 读入 $d$、$n$，以及每个公共场所的 $(x_i,y_i,k_i)$。
2. 初始化 `best=-1`、`cnt=0`。
3. 枚举安装点 $(x,y)$，$x=0..128$，$y=0..128$：
   - 令 `sum=0`；
   - 对每个公共场所 $i$，若 `abs(px[i]-x)<=d && abs(py[i]-y)<=d`，则 `sum += pk[i]`；
   - 若 `sum > best`，则 `best=sum`、`cnt=1`；否则若 `sum == best`，则 `cnt++`。
4. 输出 `cnt << ' ' << best`。

### 复杂度

- 时间复杂度：$O(129^2\cdot n)$，最多约 $3.3\times 10^5$ 次判定。
- 空间复杂度：$O(n)$。

### 验证状态

- 标程 `P2038.cpp` 用 `g++ -O2 -std=c++17` 编译通过。
- 题面样例 `1 / 2 / (4,4,10) (6,6,20)` 输出 `1 30`，与官方一致。
- 编写暴力 `P2038_brute.cpp`（**不同算法**：把每个公共场所的 $k_i$ 直接铺到它能覆盖的所有路口上，累加出一张 $129\times 129$ 的权值表，再扫表求最大与计数）与对拍脚本 `P2038_check.py`，在 $d\in[1,20]$、$n\in[1,20]$、坐标随机的数据上对拍 **1500 组全部通过**。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2038 [NOIP 2014 提高组] 无线网络发射器选址
// 枚举城市内所有 129*129 个路口作为安装点，统计被覆盖的公共场所数
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{25};

int d,n;
int px[mxn],py[mxn];
i64 pk[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>d;
	cin>>n;
	for(int i=0;i<n;++i) cin>>px[i]>>py[i]>>pk[i];

	i64 best=-1;
	int cnt=0;
	for(int x=0;x<=128;++x)
		for(int y=0;y<=128;++y)
		{
			i64 sum=0;
			for(int i=0;i<n;++i)
				if(abs(px[i]-x)<=d && abs(py[i]-y)<=d)
					sum+=pk[i];
			if(sum>best) best=sum,cnt=1;
			else if(sum==best) ++cnt;
		}
	cout<<cnt<<' '<<best<<'\n';
	return 0;
}
```

### 代码说明

- `best` 初值必须是 `-1` 而不是 `0`：因为存在某个安装点完全不覆盖任何公共场所时 `sum` 可能为 $0$，若初值取 $0$，第一轮会走 `sum==best` 分支把 `cnt` 加一，虽然最终结果不一定错，但 `cnt` 的语义会变得混乱（"最大值为 0 的点数"这一情形被 `cnt=1` 起始也覆盖了，结论仍对，但推理不清）。取 `-1` 保证第一个点走"重置"分支，语义最干净。
- 覆盖判定写 `<=d` 而非 `<d`：题面明确"传播范围包括正方形边界"。用严格小于会在 $d=1$ 这类小参数下漏掉边界点。
- 枚举范围写死 `0..128`：安装地点必须是城市内的路口，不能枚举到 `-d` 或 `129+d`。
- 公共场所数量 $k_i\le 10^6$、$n\le 20$，总和 $\le 2\times 10^7$，`int` 也够，但统一用 `i64` 更稳妥。
- 输出顺序是"方案数 最多公共场所数"，注意不要写反。
