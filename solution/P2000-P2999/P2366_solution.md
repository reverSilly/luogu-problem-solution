# P2366 yyy2015c01 的 IDE 之 Watches — 题解

## 一、解题过程：人类思考叙事

题面很短，但要读细。要造一个"变量观察器"，支持三种语句：

- `n=1;` —— 常量赋给变量，常量的**位数不超过 9**（注意不是数值不超过 9）；
- `a=b;` —— 变量之间赋值，**若右边的变量此前没被赋值过，认为它初值为 0**；
- `m=1+2;` —— 只有一个 `+` 的加法赋值，两个操作数各自是常量或变量，两个操作数都介于 $1$ 与 $10^6$ 之间。

输入第一行是语句条数 $n$，后面 $n$ 行每行一条语句，**不会有多余字符**（所以没有空格）。输出：把所有**被赋值过**的变量按标识符的**字典序**输出，每行"变量名 值"。题面保证所有变量的值不大于 int 的最大值；Hint 还特意提醒"别想着变量标识符只有一位哟"。

这不是一个算法题，是一个**字符串解析 + 模拟**题。所以思考的重点在于：怎么切串、状态怎么存、以及哪里有坑。

**第一步：怎么把一条语句读进来？**

最自然的想法是 `cin >> 名字` 把变量名读出来。但语句是 `a=b;` 这种"没有空格分隔"的连续串，`cin >> string` 会一口气读到空白为止，把 `a=b;` 整行读成一个 token。所以必须**整行读**（`getline`），再自己切。

**第二步：怎么切？**

一条语句的骨架是 `左值=右值;`。右值里可能有 `+`，但左值和右值里都**不可能**出现 `=` 和 `;`（标识符由字母/数字/下划线组成，常量由数字组成）。所以：

1. 找第一个（也是唯一一个）`=`，左边是变量名，右边是表达式；
2. 把右边末尾的 `;` 去掉；
3. 把右边按 `+` 切开，得到 1 个或 2 个操作数。

这里有个顺序问题：必须先切 `=` 再切 `+`。如果反过来先按 `+` 切，`a=b+c;` 的第一个 token 会是 `a=b`，里面还夹着等号和左值，反而更麻烦。

**第三步：每个操作数是常量还是变量？**

看起来可以"看首字符是不是数字"来判断。但更稳的做法是**整串判断是否全为数字**：标识符不可能全是数字（否则和常量没法区分），所以"全数字 ⇒ 常量，否则 ⇒ 变量名"。这一条同时解决了 Hint 提醒的坑：`a1`、`var10` 这种**带数字的标识符**绝不是常量。

**第四步：状态怎么存？**

变量名不止一位、数量未知，显然不能开数组下标，用 `map<string, long long>`。读一个变量时若表里没有，`map::operator[]` 会自动插入 $0$ —— 这恰好实现了"未赋值变量读作 $0$"。

**第五步（这里差点翻车）：输出哪些变量？**

题面说"输出共 $n$ 行"，但紧接着又说"每行是一个**被赋值过的变量**"。这两句只有在"每个变量恰好被赋值一次"时才等价，而题目并没有保证这一点（同一个变量可以被反复赋值）。于是要做一个判断：`x=1; x=2;` 应当输出什么？显然是**一行** `x 2`——因为观察器观察的是"所有语句运行完后"每个变量的值，一个变量就是一个值。所以正确的理解是：**输出行数 = 被赋值过的不同变量个数**，每个变量输出它的最终值。"共 $n$ 行"是题面的宽松措辞。

更要紧的是：**不能用 `map` 的键集作为输出集合**。因为第 3 步里 `val[tk]` 读未赋值变量时会往 `map` 里插一个值为 0 的条目，于是"只被读过、从没被赋值"的变量也会混进 map。反例：

```
2
x=y+z;
w=x;
```

`y`、`z` 从没被赋值，但 `val[y]`、`val[z]` 被插进了 map，值为 0。如果遍历 map 输出，就会多出 `y 0`、`z 0` 两行。所以必须**另外用 `set<string>` 记下所有出现在左值的名字**，只输出这个集合里的变量。

**第六步：顺序**

语句之间是有依赖的（后面的语句读前面的结果），必须**严格按顺序执行**。不能用"每个变量取最后一次赋值的右边"这种"离线"想法去优化。反例：

```
3
x=1;
y=x;
x=2;
```

若只看 x 的最后一次赋值，会认为 x=2 且 y 也等于 2；但顺序执行时 `y=x` 发生在 `x=2` 之前，实际 y=1。所以老老实实一行一行模拟。

**第七步：值的范围**

- 常量位数 ≤ 9 ⇒ 常量 < $10^9$，int 装得下；
- `A+B` 里 A、B ∈ $[1,10^6]$ ⇒ 和 ≤ $2\times 10^6$；
- 题面保证所有变量值不超过 int 最大值。

所以 `int` 就够，用 `long long` 更保险（多写一个 `using i64=long long;` 而已）。位数 ≤ 9 这一条还有个隐含作用：不能用 `char` 级别的"逐位"处理，必须整串转数字（`stoll`）。

小例子（自己造的，题面没给样例）：

```
3
a=b;
b=7;
c=1+2;
```

逐行执行：`a=b` 时 b 未赋值 ⇒ a=0；`b=7` ⇒ b=7；`c=1+2` ⇒ c=3。被赋值过的变量是 `{a,b,c}`，字典序输出：

```
a 0
b 7
c 3
```

注意 `a` 的值是 $0$ 但**照样要输出**——"被赋过值"和"值非零"是两回事。

## 二、思维链：完整证明

下面把上面每一步的"为什么成立"补齐。

**引理 1（语句的唯一分解）**：每条语句必然恰好形如 `L=R;`，其中 $L$ 是不含 `=`、`+`、`;` 的非空串，$R$ 不含 `;`。因此"找行中唯一一个 `=`、再剥掉末尾的 `;`"能正确切出左值和右值。

*证明*：三种语法形式 `n=1;`、`a=b;`、`m=1+2;` 中都恰有一个 `=`，且都以 `;` 结尾。标识符由字母、数字、下划线组成，常量由数字组成，都不含 `=`、`+`、`;`，所以 `=` 与 `;` 只可能出现在语法规定的分界处：`=` 恰好一个（在左值与右值之间），`;` 恰好一个（在行尾）。又题面保证"不会有多余的其他字符"（无空格、无注释），故行首到第一个 `=` 之间就是 $L$，第一个 `=` 到最后一个字符之间去掉尾部 `;` 就是 $R$。唯一性保证 `find('=')` 找到的一定是那个分界符。证毕。

**引理 2（操作数切分）**：把 $R$ 按 `+` 切开得到 1 个或 2 个非空 token，它们恰好是语句中的所有操作数，且顺序与原式一致。

*证明*：$R$ 中若不含 `+`，则 $R$ 本身是一个操作数（形式 `n=1;` 或 `a=b;`）；若含一个 `+`，因为 `+` 不可能是任何一个操作数（常量或标识符）的组成部分，它一定是唯一的运算符，故按它切开恰好得到两个非空串，分别对应 $A$ 和 $B$（形式 `m=1+2;`）。题面限定"只有 `+` 且只有两个数或者变量"，故 `+` 至多一个。证毕。

**引理 3（常量的判别）**：一个 token 是常量当且仅当它的所有字符都是数字。

*证明*：($\Leftarrow$) 全为数字的串按十进制解释就是一个合法常量，`stoll` 得到它的值。(⇒) 若 token 是常量，它由数字组成。还需要说明反向不冲突：标识符若全为数字，就会与常量无法区分，而题面三种语句的语义要求二者可区分（`m=1+2` 中 `1` 是值、`x=1+2` 中 `x` 是名字），常规标识符也不以数字开头，故不存在"全数字的变量名"。于是判别无歧义。证毕。

**引理 4（顺序执行的不可省略性）**：语句的语义是对当前变量值逐条更新，故最终每个变量的值必须按输入顺序逐条模拟得到；任何"只保留每个变量最后一次赋值"的离线算法都是错的。

*证明*：给出反例即可（要证明"某算法错误"只需一个反例）。输入 `x=1; y=x; x=2;` 三条语句。顺序执行：`x=1` 后 x=1；`y=x` 读当前 x=1，得 y=1；`x=2` 后 x=2。最终 (x,y)=(2,1)。而离线算法对 y 只看到它的唯一赋值 `y=x`，若用"x 的最终值 2"去代，得到 y=2 ≠ 1。故离线算法错误，必须顺序执行。证毕。

另外还要说明"顺序执行"本身是可实现的：读入第 $i$ 行后立刻执行，无需保存全部语句。这正是本文实现的形态。

**引理 5（未赋值读作 0 的实现）**：用 `map<string,i64>` 且不预先插入任何键时，对未出现过的名字执行 `val[name]` 会插入并返回 $0$，与题面"未被赋值则认为其初始值为 $0$"一致。

*证明*：`std::map::operator[]` 的语义是"若键不存在则值初始化并插入"。`i64`（即 `long long`）的值初始化为 $0$。所以第一次读未赋值变量得到 $0$，正是题面要求的初始值；此后该条目虽然存在，但它的值 $0$ 依然等于"初始值"，不影响任何计算。证毕。

**引理 6（输出集合）**：设 $S$ 为所有出现在某条语句左值的变量名集合，则正确答案恰好是对 $S$ 中每个名字输出一行"名字 最终值"，按字典序排列。

*证明*：分两方面。
- **$S$ 内的变量都要输出**：题面"对所有被赋值过的变量……输出它们"，出现在左值即被赋值，故必须输出。且每个变量只输出一次（"变量"是一个名字，不是一次赋值），必须输出它的**最终**值（最后一次赋值后的值），因为 Watches 观察的是语句全部运行完后的状态。
- **$S$ 外的变量都不能输出**：不在左值出现过的变量只可能出现在右值（被读），它从未被赋值，按题面不属于"被赋值过的变量"。这里要特别注意：`map` 的键集可能比 $S$ 大（引理 5 中读操作会插键），故实现中必须用独立的 `set<string> asg` 维护 $S$，而不能遍历 `map`。若用 `map` 的键集代替 $S$，反例 `x=y+z; w=x;` 会多输出 `y 0`、`z 0`，答案错误。

顺序：`std::set<string>` 按 `<(string)` 升序保存。`string` 的 `operator<` 定义为字典序（逐字符比较，前缀关系时短者更小），与题面"字典序"一致；`set` 的中序遍历即是升序。证毕。

**引理 7（值域安全）**：本题所有中间量都可用 `long long`（乃至 `int`）安全表示。

*证明*：分三种语句看右值。
- 常量：位数 ≤ 9 ⇒ 值 ≤ $999999999<2^{31}-1$。
- `a=b`：结果就是 $b$ 的值，而题面保证"变量的值不大于 int 的最大值"，故 $\le 2^{31}-1$。
- `m=A+B`：A、B 各 $\le 10^6$（若某个操作数是变量，题面同样限定它的值属于 $[1,10^6]$），故和 $\le 2\times10^6$。

三种情形都不超过 $2^{31}-1$，故 `int` 不会溢出，用 `long long` 更无风险。证毕。（顺带说明：常量必须整串转换，不能只取一位——这正是"位数 ≤ 9"这条约束提醒的地方。）

**引理 8（复杂度）**：设语句条数 $n$，每行长度 $L$，不同变量名个数 $V$。总时间复杂度 $O(n\cdot L\log V)$，空间复杂度 $O(V\cdot L)$。

*证明*：每条语句做一次 `find('=')`（$O(L)$）、至多两次 `substr` 与按 `+` 切分（合计 $O(L)$）、至多两次 `map`/`set` 操作（每次 $O(\log V)$ 次字符串比较，每次比较 $O(L)$）。$n$ 条语句合计 $O(nL\log V)$。空间上 `map` 与 `set` 各存至多 $V$ 个长度 $\le L$ 的串。证毕。题面明确"数据很弱"，这个量级远超需要。

## 三、模式总结（按实际思考顺序）

1. **explore its property** — 语句是「无空格」的字符串，`>>` 读不出结构，必须整行读 + 自己切分。
2. **explore its property** — 先用 `=` 分出左右值，再在右值里按 `+` 切；切分顺序不能颠倒。
3. **classic problem solution** — 解释器模式：`map<string,值>` 做符号表，"查不到就用默认值"天然实现「未赋值按 0」。
4. **explore its property** — 「全数字 ⇒ 常量，否则 ⇒ 变量名」这一判别规则成立的前提是标识符不能全为数字，据此顺手解决多字符/带数字标识符。
5. **碰壁与修正** — 输出集合不能用 `map` 的键集：读操作会插键，会把「只读未写」的变量误输出 ⇒ 另开 `set` 记左值。
6. **碰壁与修正** — 不能离线化（只取每个变量最后一次赋值）：反例 `x=1;y=x;x=2;` 说明必须逐条顺序模拟。
7. **explore its property** — 题面「输出共 n 行」与「被赋值过的变量」冲突，以语义为准：行数 = 不同被赋值变量个数。
8. **boundary check** — 常量位数 ≤ 9 ⇒ 整串转数；值域 ≤ int，用 long long 兜底。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 | 初值 / 记忆点 |
|------|------|------|----------------|
| `n` | 语句条数 | `int` | 输入 |
| `line` | 当前读入的一整行语句 | `string` | 每轮 `getline` |
| `lhs` | 等号左边的变量名 | `string` | 由 `line.substr(0,eq)` 得到 |
| `rhs` | 等号右边去掉了尾部 `;` 的表达式 | `string` | 由 `line.substr(eq+1)` 去尾 `;` |
| `eq` | 等号在行中的下标 | `size_t` | `line.find('=')` |
| `val` | 变量名 → 当前值（符号表） | `map<string,i64>` | 空表；查不到即 0 |
| `asg` | 被赋值过的变量名集合 | `set<string>` | 空集；只输出它里面的名字 |
| `s` | 当前语句右值求出的和 | `i64` | 每次语句置 0 |
| `tk` | 当前切出的一个操作数 token | `string` | 常量或变量名 |
| `st, pl` | 当前 token 的起点 / 下一个 `+` 的位置 | `size_t` | `pl==npos` 表示这是最后一个 token |
| `cnt` | 已成功处理（非空）的语句条数 | `int` | 0；与 `n` 同时作为循环条件 |

### 算法步骤

1. 关闭流同步（`cin.tie(nullptr); cout.tie(nullptr); ios::sync_with_stdio(false);`），读入 `n`，再用一次 `getline` 吃掉第一行残留的换行。
2. 循环直到 `cnt == n` 或读不到行：`getline` 一行；去掉结尾可能存在的 `\r`（防 Windows 换行）；跳过空行；`++cnt`。
3. 在 `line` 中找 `=`，切出 `lhs` 与 `rhs`；若 `rhs` 末尾是 `;` 则删掉。
4. 从 `st=0` 开始反复找 `+`：切出 `tk=rhs[st, pl)`；若 `tk` 全为数字则 `s += stoll(tk)`，否则 `s += val[tk]`（未赋值即 0）；`pl==npos` 时结束，否则 `st=pl+1`。
5. `val[lhs]=s`；`asg.insert(lhs)`。
6. 按 `asg` 的升序遍历，输出 `名字 值`，每行一个，换行用 `'\n'`。

### 复杂度

- 时间：$O(n\cdot L\log V)$（$L$ 为单行长度，$V$ 为不同变量个数）。
- 空间：$O(V\cdot L)$，即符号表与输出集合。

### 验证状态

编译通过（`g++ -std=c++20 -O2`），与独立实现（`istringstream` 切分 + `vector` 排序）在 300 组随机小数据上完全一致，另针对多字符/带数字标识符、9 位常量、只读未写变量、混合大小写字典序 4 类边界手造数据单独核对通过。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2366 yyy2015c01 的 IDE 之 Watches
// 思路：整行读入 -> 按 '=' 切出左右值 -> 右值按 '+' 切成操作数
//       全数字的是常量，否则查符号表（没赋过值就是 0）
//       输出集合必须单独记录：查表时会往 map 里插入 0，不能拿 map 的键集当答案集
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

int n;
map<string,i64>val;      // 变量名 -> 当前值；从没出现过的名字查出来就是 0
set<string>asg;          // 被赋值过的变量名，只有这些要输出

bool isNum(const string&s)
{
	if(s.empty())
		return false;
	for(char c:s)
		if(c<'0'||c>'9')
			return false;
	return true;
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	string line;
	getline(cin,line);        // 吃掉第一行末尾的换行符
	for(int cnt=0;cnt<n;)
	{
		if(!getline(cin,line))
			break;
		if(!line.empty()&&line.back()=='\r')
			line.pop_back();   // 防御 Windows 换行
		if(line.empty())
			continue;
		++cnt;
		size_t eq=line.find('=');
		string lhs=line.substr(0,eq);
		string rhs=line.substr(eq+1);
		if(!rhs.empty()&&rhs.back()==';')
			rhs.pop_back();
		i64 s=0;
		for(size_t st=0;;)
		{
			size_t pl=rhs.find('+',st);
			string tk=rhs.substr(st,pl==string::npos?string::npos:pl-st);
			s+=isNum(tk)?stoll(tk):val[tk];   // val[tk] 顺手把未赋值变量置 0
			if(pl==string::npos)
				break;
			st=pl+1;
		}
		val[lhs]=s;
		asg.insert(lhs);
	}
	for(const string&s:asg)
		cout<<s<<' '<<val[s]<<'\n';
	return 0;
}
```

### 代码说明

- `getline(cin,line)` 紧跟 `cin>>n` 的那一次调用是必须的：`>>` 读完 `n` 后停在换行符之前，不"吃掉"它，第一次 `getline` 会读到空串。这一行就是专门消化它的。
- 循环写成 `for(int cnt=0;cnt<n;)` 并在空行处 `continue`：空行不算一条语句，`cnt` 也不增，既容忍了多余空行，也不会因为空行而漏读语句。
- `line.back()=='\r'` 的判断是防御性的：若测试数据是 CRLF，`getline` 会把 `\r` 留在串尾，导致 `rhs` 变成 `1+2;\r`，剥 `;` 就失败（`back()` 是 `\r`）。在 Linux 评测机上这段不会被触发，属于零成本保险。
- `rhs.find('+',st)` 循环是"手工 split"：`pl==npos` 时 `substr(st,npos)` 取到行尾，正好是最后一个 token，随后 `break`。
- `val[tk]` 用 `operator[]` 而不是 `find`：既省一次查找，又天然实现"未赋值读作 0"（引理 5）。副作用是会插键，所以输出只走 `asg`（引理 6）。
- `isNum` 判整串而不是只看首字符：这样 `a1`、`x_2`、`var10` 这类带数字的名字不会被误当成常量。
- 常量用 `stoll` 整串转换，支持最多 9 位（约值 ≤ $999999999$）。
- 输出遍历 `set<string>` 就是字典序；`'\n'` 不用 `endl`。
