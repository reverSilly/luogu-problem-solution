# P2141 [NOIP 2014 普及组] 珠心算测验 — 题解

## 一、解题过程：人类思考叙事

题目说：给一个正整数集合（元素互不相同），问**其中有多少个数**，恰好等于集合中另外两个（不同的）数之和。

注意问的是"有多少个数"，不是"有多少组加法算式"。所以只要一个元素能表示成另外两个元素之和，它就贡献 $1$；至于它有多种表示方式，只算一次。

数据范围 $3\le n\le 100$，元素不超过 $10000$，互不相同。

$n=100$ 的话，枚举所有数对是 $\binom{100}{2}=4950$ 对，完全可以暴力。那关键就是：**怎么把"能被表示"这个信息存下来？**

想到最直接的做法：开一个布尔数组 `mark`，`mark[x]` 表示"$x$ 能被表示成两个不同元素之和"。然后枚举所有数对 $(i,j)$，把 `mark[a[i]+a[j]]` 置真；最后扫一遍数组，统计有多少个 `a[i]` 满足 `mark[a[i]]` 为真。

这个思路非常直接，几乎不需要"想"。但有几个细节必须抠清楚，否则会 WA。

### 细节一：加数必须互不相同

题目要求"两个不同的数"。如果枚举时允许 $i=j$，就会出现 $2a[i]=a[k]$ 这种用同一个数加自己的情况，是非法的。所以枚举必须是 $i<j$。

### 细节二：被加数不能等于加数 —— 需要额外排除吗？

题目样例说明里特别强调"加数和被加数必须是集合中的两个不同的数"。

那么，如果 $a[i]=a[j]+a[k]$，会不会出现 $a[i]=a[j]$ 的情况？即被加数恰好等于某个加数？

由于集合元素是**正整数**且 $a[k]>0$，有 $a[i]=a[j]+a[k]>a[j]$，同理 $a[i]>a[k]$。所以被加数严格大于两个加数，**自动就不可能和加数相等**。

更一般地说：正数性保证了 $a[i]-\min>0$，$a[i]-\max>0$，其中 $\min,\max$ 是两个加数。所以"加数与被加数不同"是自动满足的，不需要写额外判断。

这是本题唯一一个值得想一想的点。

### 细节三：和的范围

$a[i]\le 10000$，所以 $a[i]+a[j]\le 20000$。`mark` 数组要开到 $20000$ 以上。标程取 `mxv{20005}`，并且还加了 `if(s<=mxv-5)` 的保护——虽然在这个数据范围下越界不会发生（$20000\le20000$），但保留一个上界判断是好习惯。

### 细节四：统计的对象

最后统计的是 `if(mark[a[i]]) ++ans;`，即**数集合中元素**，而不是数所有被标记的下标之和。因为元素互不相同，标记数组里的每个真值最多对应一个集合元素，所以直接扫元素数组统计是对的。

同时，标记的重复是无害的：$1+2=3$ 和 $1+3=4$ 都标记了 `mark[3]`……不对，$1+2$ 标记 `mark[3]`，`1+3` 标记 `mark[4]`。总之即使同一个和被多对数对算出来，`mark` 是布尔数组，置真多少次都只算 $1$ 次，这正好符合"有多少个数"的要求。

整题 $O(n^2)$，20 行代码搞定。

## 二、思维链：完整证明

**引理 1**：若 $a_i=a_j+a_k$ 且 $a_k>0$，则 $a_i>a_j$。

*证明*：由 $a_j=a_i-a_k$ 且 $a_k>0$，得 $a_j<a_i$。证毕。

**引理 2（自动满足"加数与被加数不同"）**：若正整数 $a_i$ 等于集合中某两个不同元素 $a_j,a_k$ 之和，则 $a_i$ 与 $a_j,a_k$ 均不同。

*证明*：由引理 1，$a_i>a_j$ 且 $a_i>a_k$（对 $a_k$ 同理，用 $a_j>0$）。既然 $a_i$ 严格大于 $a_j,a_k$，自然三者两两不同。证毕。

**引理 3（标记的正确性）**：算法结束后，`mark[x]` 为真当且仅当 $x$ 等于集合中两个不同元素之和。

*证明*：
（$\Rightarrow$）`mark[x]` 只在枚举数对 $(i,j)$（$i<j$）且 $x=a_i+a_j$ 时被置真。此时 $a_i,a_j$ 是集合中两个不同的元素（$i\ne j$），且由引理 2，$x$ 与它们也不同，故 $x$ 确实等于两个不同元素之和。
（$\Leftarrow$）设 $x=a_p+a_q$，其中 $p\ne q$。不妨设 $p<q$，则枚举数对时会枚举到 $(p,q)$，从而 `mark[x]` 被置真。
两个方向合起来即得等价。证毕。

**引理 4（计数的正确性）**：算法统计出的 `ans` 等于集合中能被表示成另外两个不同元素之和的元素个数。

*证明*：由引理 3，`mark[a[i]]` 为真当且仅当 $a_i$ 能被表示成两个不同元素之和。算法对每个 $i$ 判断一次并计数。又因集合元素互不相同，不同的 $i$ 对应不同的 $a_i$，故被计数的元素恰为所有满足条件的元素，且每个只被计一次。证毕。

**定理**：算法输出的即题目要求的答案。

*证明*：由引理 4 直接得出。证毕。

**补充（重复标记无害）**：设某个元素 $a_i$ 有多种表示 $a_i=a_j+a_k=a_p+a_q$，算法会多次把 `mark[a[i]]` 置真，但 `mark` 是布尔数组且统计时只按元素计一次，故重复表示不会重复计数，与题目"有多少个数"的问法一致。

## 三、模式总结（按实际思考顺序）

1. 题目问"有多少个数能被表示成两数之和" ⇒ 用一个布尔数组 `mark` 记住"哪些数可以"，这是**打标记 + 统计**的标准套路
2. 枚举数对时必须 $i<j$ ⇒ 保证"两个不同的数"
3. 正整数 ⇒ 被加数严格大于加数 ⇒ "被加数 ≠ 加数"自动成立，**不需要额外排除**（这是本题唯一的思维点）
4. 和最大 $20000$ ⇒ `mark` 数组开到 $20000$ 以上
5. 统计时扫**元素数组**而不是标记数组 ⇒ 天然按"元素个数"计，不会因多重表示重复计数

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 |
|------|------|------|
| $n$ | 集合中元素个数 | `int` |
| `a[i]` | 集合中第 $i$ 个元素（内部 0-based） | `int[mxn]` |
| `mark[x]` | $x$ 是否等于集合中两个不同元素之和 | `bool[mxv]` |
| $s$ | 当前枚举出的和 $a[i]+a[j]$ | `int` |
| `ans` | 答案：满足条件的元素个数 | `int` |

### 算法步骤

1. 读入 $n$ 与数组 `a`。
2. 枚举所有数对 $(i,j)$，$0\le i<j<n$：计算 $s=a[i]+a[j]$，若 $s\le mxv-5$ 则置 `mark[s]=true`。
3. 扫一遍 `a`，统计 `mark[a[i]]` 为真的元素个数 `ans`。
4. 输出 `ans`。

### 复杂度

- 枚举数对 $O(n^2)$，统计 $O(n)$，总时间复杂度 $O(n^2)$；$n=100$ 时仅 $4950$ 对数对。
- 空间复杂度 $O(n+V)$，$V=20005$ 为 `mark` 数组大小，约 20 KB。

### 验证状态

- 标程 `g++ -O2 -std=c++17` 编译通过；题面样例说明中的集合 $\{1,2,3,4\}$ 答案为 $2$（由 $1+2=3$、$1+3=4$），与程序输出一致。
- **对拍**：以 Python 三重循环暴力为基准，随机 $500$ 组 + $4$ 组手选边界（`[1,2,3]`、`[1,2,4]`、`[5,6,100]`、`[2,4,6]`），共 $504$ 组随机数据与标程输出全部一致（`all 504 cases match`）。
- 边界自查：`[2,4,6]` 中 $6=2+4$，答案为 $1$，验证了"被加数可以是另两个的和且三者互异"；`[5,6,100]` 答案 $0$，验证了超范围的和不会误标。

## 五、示例代码（C++，Louis Li 风格）

```cpp
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{105};
constexpr int mxv{20005};

int a[mxn];
bool mark[mxv];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	int n;
	cin>>n;
	for(int i=0;i<n;++i)
		cin>>a[i];
	for(int i=0;i<n;++i)
		for(int j=i+1;j<n;++j)
		{
			int s=a[i]+a[j];
			//加数与被加数必须是集合中两个不同的数
			if(s<=mxv-5)
				mark[s]=true;
		}
	int ans=0;
	for(int i=0;i<n;++i)
		if(mark[a[i]])
			++ans;
	cout<<ans<<'\n';
	return 0;
}
```

### 代码说明

- `mxn{105}` = 约束上界 $100$ + 5；`mxv{20005}` = $2\times10000+5$，覆盖所有可能的和。
- `mark` 是全局静态的 `bool` 数组，全局数组自动初始化为 $0$（即"未被标记"），不需要额外 `fill`。
- 双层循环写成 `for(int j=i+1;j<n;++j)`，靠 $j>i$ 保证两数不同，且每个数对只枚举一次。
- `if(s<=mxv-5)` 是防御性上界判断，防止 `mark` 越界写。
- 最后统计的是"集合元素"而非"标记个数"，与题面"有多少个数"严格对应。
- 换行用 `'\n'`。

---

*本题真正的考点不是算法，而是那句"加数和被加数必须是集合中的两个不同的数"：加数互不相同靠 $i<j$ 保证，而被加数与加数不同则由"正整数"自动保证。*
