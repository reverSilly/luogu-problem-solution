# P2027 BrainFuck — 题解

## 一、解题过程：人类思考叙事

题目要我们实现一个 **BrainFuck 解释器**。这题看着吓人，其实就是照着指令表逐条模拟。

先把规格抄清楚：

- 内存：$30000$ 个**有符号 8 位**整数，取值 $[-128,127]$；指针初始指向**第 0 格**。
- 指令集只有 8 个字符：`+ - , . > < [ ]`。
- 输入格式：若干行代码（**有注释**），直到 `$` 结束代码；`$` 后紧跟一个空格（**不属于输入缓冲区**），空格后是缓冲区内容，以"空格 + `$`"结束。

几个必须抠清楚的细节：

**细节一：非指令字符怎么办？** 题面说"代码有注释"，而 BrainFuck 的注释就是"任何不属于指令集的字符"。所以处理方式是：**先把代码里所有非指令字符删掉**，剩下的就是纯指令序列。这样注释里出现的 `[`、`]` 也不会破坏括号配对。

**细节二：8 位有符号会回绕。** `$127 + 1 = -128$`，`$-128 - 1 = 127$`。这是 8 位有符号整数的补码溢出行为。题目特意强调"有符号 8 位整数"，就是为了考这个。用 `int` 存储并手动回绕即可（不能直接 `char`，因为 `char` 的 `+`/`-` 在 `signed char` 上其实已经是回绕的，但可读性差且 `unsigned char` 上会出问题；显式处理最稳）。

**细节三：`,` 读到的是字节，且缓冲区为空时存入 $-1$。** 题面 Hint 说"字符在内存中的数值为字符所对应的 ASCII 码"。所以 `,` 把输入缓冲区的下一个字节（ASCII 码）写进当前格。如果缓冲区已经读空，则存入 $-1$（不是 0！）。

**细节四：`[` / `]` 的跳转语义。**

- `[`：若当前格**不为 0**，则执行循环体；**若当前格为 0，跳过整个循环体**（跳到匹配的 `]` 之后）。
- `]`：若当前格不为 0，跳回匹配的 `[` 重新判断；若为 0，继续往下执行。

标准做法是：预处理出每个 `[` 对应的 `]`、每个 `]` 对应的 `[`（用栈），执行时：
- `[` 且 `mem[ptr]==0` → `pc = cl[pc]`（跳到 `]`，然后统一 `++pc` 就到了 `]` 之后）；
- `]` → `pc = op[pc] - 1`（跳回 `[` 的前一个位置，然后统一 `++pc` 就回到 `[`）。

用"统一 `++pc`"的写法时，`[` 的跳转量要多算一格，正好 `pc = cl[pc]` 让 `++pc` 后落在 `]` 的后一格（`]` 本身会被跳过，因为当前格为 0，执行 `]` 也就是继续往下，符合语义）。

**细节五：输入的解析。** 整份输入形如：

```
write whatever u c ,.,.,.,. $ asdf $
```

代码部分是 `write whatever u c ,.,.,.,. `，第一个 `$` 之后是 ` asdf $`。注意 `$` 后面紧跟一个空格，**这个空格不属于缓冲区**；缓冲区以"空格 + `$`"结尾，所以末尾那个空格也不属于缓冲区。缓冲区内容是 `asdf`。

于是解析步骤：
1. 找第一个 `$`，之前是代码。
2. 剩下的部分找**最后一个** `$`，则缓冲区是「去掉开头的那个空格」到「末尾的空格 `$` 之前」之间的内容。

用 `rfind('$')` 而不是 `find('$')` 是因为缓冲区内容理论上可能含有 `$`……不过更稳妥地说，缓冲区内容一般不会含 `$`（题面没说），用 `rfind` 更保险。

代码部分可能是**多行**的，所以要 `getline` 循环读入直到 EOF。

**细节六：步数保护。** 题面保证"输入的程序能够在 $10^6$ 步内运行结束"，所以加一个 `step` 计数器上限 `1000000` 兜底，防止万一有死循环导致程序卡死（虽然理论上不会）。

样例验证：代码 `write whatever u c ,.,.,.,. ` 去掉注释后是 `,.,.,.,.`，缓冲区 `asdf`。执行：`,` 读 'a'(97)，`.` 输出；`,` 读 's'(115)，`.` 输出；`,` 读 'd'(100)，`.` 输出；`,` 读 'f'(102)，`.` 输出；再一个 `,` 读到缓冲区末尾，存入 -1（但不再输出）。输出 `asdf`。✓

## 二、思维链：完整证明

**引理 1**：删去代码中所有不属于指令集 $\{+,-,,,.,>,<,[,]\}$ 的字符，不改变程序的执行结果。

*证明*：BrainFuck 的语义只由指令序列决定，非指令字符没有任何语义（它们是注释）。执行过程只会按 `pc` 依次取出指令字符并执行，注释字符从不被取出执行，因此删除它们不影响任何一条指令的执行时机与效果，输出结果不变。证毕。

**引理 2**：预处理得到的 `cl` 与 `op` 数组正确表示了括号的匹配关系。

*证明*：用栈自左向右扫描指令序列，遇到 `[` 压栈，遇到 `]` 弹栈并配对。BrainFuck 语言的括号必须正确嵌套（否则程序没有定义），嵌套结构与栈的后进先出配对方式一一对应：每个 `]` 匹配的是最近一个尚未匹配的 `[`。因此 `cl[j]=i`（`[` 位置 $j$ 匹配 `]` 位置 $i$）、`op[i]=j` 记录的都是真正的匹配对。证毕。

**引理 3**：算法对 `+`、`-` 指令的处理与题面"有符号 8 位整数"的规定一致。

*证明*：题面规定内存值域为 $[-128,127]$，即 8 位二进制补码。算法在 `+` 后检查是否等于 128，若是则置为 $-128$（$127+1$ 溢出为 $-128$）；在 `-` 后检查是否等于 $-129$，若是则置为 $127$（$-128-1$ 溢出为 $127$）。除这两种越界情况外数值加/减 1 均在 $[-128,127]$ 内，保持不变。算法维护的 `mem[ptr]` 因此始终等于真实 8 位有符号寄存器的值。证毕。

**引理 4**：算法对 `[` 与 `]` 的跳转实现了题面规定的循环语义。

*证明*：设 `[` 的位置为 $p$，其匹配的 `]` 位置为 $q$（引理 2）。

- 执行 `[` 时若 `mem[ptr] != 0`，算法不跳转，`pc` 前进到 $p+1$，即开始执行循环体，与题面"数值不为 0 时重复执行与匹配的 `]` 之间的语句"一致。
- 执行 `[` 时若 `mem[ptr] == 0`，算法令 `pc = cl[p] = q`，随后统一 `++pc` 使 `pc = q+1`，即跳过了从 `[` 到 `]` 的整个循环体，符合"为 0 时不执行循环体"。
- 执行 `]` 时算法令 `pc = op[q] = p`，随后统一 `++pc` 使 `pc = p+1`，即重新回到循环体开头；下一次遇到 `[` 时会再次检查条件——若此时值已变为 0，则按上一条跳到 $q+1$，退出循环；若不为 0，则继续执行循环体。这恰好实现了"重复执行直到回到 `[` 时数值为 0"。

因此循环语义完全正确。证毕。

**引理 5**：算法对 `,` 与 `.` 的处理符合题面规定。

*证明*：`,` 的语义是"将读入缓冲区中的一个字节送入当前指针指向的内存里面，如果读入缓冲区为空则送入 $-1$"。算法维护输入指针 `ip`，当 `ip < buf.size()` 时取 `buf[ip++]`（即缓冲区下一个字节的 ASCII 码），否则取 $-1$；并把大于 127 的字节值减去 256，使其作为 8 位有符号数存放（例如字节 0xFF 存为 $-1$），与引理 3 的值域一致。

`.` 的语义是"输出当前指针所指向的内存里面的数值（以字符形式输出）"。算法用 `cout.put((char)mem[ptr])` 按字节输出，与题面"字符在内存中的数值为字符所对应的 ASCII 码"配合，使得 `,` 读入的字节能被 `.` 原样还原输出。证毕。

**引理 6**：算法正确地从原始输入中分离出代码与输入缓冲区。

*证明*：输入格式为「若干行代码 + `$` + 一个空格 + 缓冲区内容 + 一个空格 + `$`」。算法读完全部输入得到 `raw`，取 `raw.find('$')` 得到第一个 `$` 的位置 $p$，`raw[0,p)$ 即为代码部分（含换行，但换行属于非指令字符，会被引理 1 的删除步骤滤除）。

设 `rest = raw[p+1, )`，则 `rest` 的第一个字符是题面规定"不属于缓冲区"的那个空格；`rest` 的末尾形如「空格 `$`」。令 `q = rest.rfind('$')`，则 `rest[q-1]` 是末尾的空格，`rest[q+2, )` 无内容。缓冲区即为 `rest[1, q-1)`，即 `rest.substr(1, q-2)`，长度 $q-2$。当缓冲区为空（形如「空格 `$`」）时 $q=2$，长度为 0，`substr` 返回空串，正确。证毕。

**定理**：算法输出的正是给定 BrainFuck 程序在给定输入缓冲区上的执行结果。

*证明*：由引理 6，输入被正确解析为代码与缓冲区；由引理 1，删除注释不改变语义；由引理 2、4，循环控制流正确；由引理 3，内存值的 8 位有符号回绕正确；由引理 5，输入输出指令正确。算法按 `pc` 顺序执行指令直到越过程序末尾，与真实解释器的执行过程完全一致，故输出正确。证毕。

## 三、模式总结（按实际思考顺序）

1. **把题目翻译成数据结构** — 30000 格 8 位有符号内存 + 一个指针 + 一个程序计数器。
2. **先剥注释再执行** — 非指令字符全是注释，直接过滤（引理 1）；这样括号配对也不会被注释里的方括号破坏。
3. **预处理括号匹配** — 用栈一次性求出 `[`↔`]` 对应表（引理 2），避免运行期反复扫描。
4. **统一 `++pc` 的跳转写法** — `[` 置 0 时 `pc=cl[pc]`；`]` 时 `pc=op[pc]-1`，都靠末尾统一的 `++pc` 归位。
5. **8 位有符号回绕** — $127+1\to -128$，$-128-1\to 127$（引理 3）。
6. **`,` 的两个坑** — 缓冲区空时存 $-1$ 而非 0；字节按 8 位有符号存放。
7. **输入解析的空格细节** — `$` 后的第一个空格不属于缓冲区，末尾「空格 `$`」中的空格也不属于缓冲区（引理 6）。
8. **加步数上限兜底** — 题面保证 $10^6$ 步内结束，但仍加上限防止意外卡死。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| `code[]` | 过滤后的纯指令序列 | `char[]`，长度 $\le 30000$ |
| `mem[i]` | 第 $i$ 格内存的值 | `int`，$[-128,127]$ |
| `ptr` | 指针位置 | `int`，$[0,29999]$ |
| `pc` | 程序计数器（下一条待执行指令的位置） | `int` |
| `ip` | 输入缓冲区的读入位置 | `int` |
| `cl[i]` | 指令位置 $i$ 若为 `[`，则为其匹配的 `]` 位置 | `int[]` |
| `op[i]` | 指令位置 $i$ 若为 `]`，则为其匹配的 `[` 位置 | `int[]` |
| `stk[]` | 括号匹配用的栈 | `int[]` |
| `raw` | 读入的全部原始文本 | `string` |
| `part` | 代码部分 | `string` |
| `buf` | 输入缓冲区内容 | `string` |
| `memsz` | 内存格数，$30000$ | `constexpr int` |
| `maxstep` | 最大执行步数，$10^6$ | `constexpr int` |

### 算法步骤

1. 用 `getline` 循环读入全部文本，拼成 `raw`（每行后补 `\n`）。
2. 找 `p = raw.find('$')`，`part = raw.substr(0,p)`；`rest = raw.substr(p+1)`。
3. 找 `q = rest.rfind('$')`，缓冲区长度 `blen = (q>=2) ? (q-2) : 0`，`buf = rest.substr(1, blen)`。
4. 扫描 `part`，只保留 8 个指令字符，得到 `code[0..len-1]`。
5. 用栈预处理括号匹配，写入 `cl` 与 `op`。
6. 清空全部内存，初始化 `ptr=0, pc=0, ip=0, step=0`。
7. 主循环（当 `pc < len && step < maxstep`）：
   1. `step++`，取 `c = code[pc]`。
   2. `+`：`mem[ptr]++`，若等于 128 则置 $-128$。
   3. `-`：`mem[ptr]--`，若等于 $-129$ 则置 $127$。
   4. `>`：`ptr++`；`<`：`ptr--`。
   5. `,`：取缓冲区下一字节（空则 $-1$），大于 127 则减 256，存入 `mem[ptr]`。
   6. `.`：`cout.put((char)mem[ptr])`。
   7. `[`：若 `mem[ptr]==0`，`pc = cl[pc]`。
   8. `]`：`pc = op[pc]-1`。
   9. `pc++`。
8. 输出换行。

### 复杂度

- 时间复杂度：$O(L + T)$，$L$ 为代码长度，$T$ 为实际执行步数（题面保证 $T \le 10^6$）。
- 空间复杂度：$O(L + 30000)$，即指令数组、括号匹配数组与内存数组。

### 验证状态

- 标程 `P2027.cpp` 用 `g++ -O2 -std=c++17` 编译通过。
- 题面样例 `write whatever u c ,.,.,.,. $ asdf $` 输出 `asdf`，与官方一致。
- 编写对拍脚本 `P2027_check.py`，内含一份独立实现的 Python 参考解释器（含 8 位有符号回绕与括号跳转），随机生成含嵌套/非嵌套循环、注释、输入输出的 BF 程序，在 **300 组**随机程序上对拍 **300 组全部通过**。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2027 BrainFuck
// 解释器：30000 个 8 位有符号内存槽；指令集外的字符一律当作注释忽略
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{30005};
constexpr int memsz{30000};
constexpr int maxstep{1000000};

char code[mxn];
int mem[memsz];
int cl[mxn],op[mxn];//cl:'[' 匹配的 ']',op:']' 匹配的 '['
int stk[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	//读入全部内容
	string raw,line;
	while(getline(cin,line))
	{
		raw+=line;
		raw+='\n';
	}
	//格式：代码$ 输入流 $，'$' 后的空格不属于输入缓冲区
	size_t p=raw.find('$');
	string part=raw.substr(0,p);
	string rest=raw.substr(p+1);
	size_t q=rest.rfind('$');
	size_t blen=(q>=2)?(q-2):0;//去掉结尾的「空格 $」
	string buf=rest.substr(1,blen);

	//抽出指令字符，其余全部是注释
	int len=0;
	for(char c:part)
	{
		if(c=='+'||c=='-'||c==','||c=='.'||c=='>'||c=='<'||c=='['||c==']')
			code[len++]=c;
	}
	code[len]='\0';
	//预处理括号匹配
	int top=0;
	for(int i=0;i<len;++i)
	{
		if(code[i]=='[')
			stk[top++]=i;
		else if(code[i]==']')
		{
			int j=stk[--top];
			cl[j]=i;
			op[i]=j;
		}
	}
	for(int i=0;i<memsz;++i)
		mem[i]=0;
	int ptr=0,pc=0,ip=0,step=0;
	while(pc<len&&step<maxstep)
	{
		++step;
		char c=code[pc];
		if(c=='+')
		{
			//8 位有符号：127+1 回绕成 -128
			if(++mem[ptr]==128)
				mem[ptr]=-128;
		}
		else if(c=='-')
		{
			//-128-1 回绕成 127
			if(--mem[ptr]==-129)
				mem[ptr]=127;
		}
		else if(c=='>')
		{
			++ptr;
		}
		else if(c=='<')
		{
			--ptr;
		}
		else if(c==',')
		{
			int v=(ip<(int)buf.size())?(unsigned char)buf[ip++]:-1;
			if(v>127)
				v-=256;//按 8 位有符号存放
			mem[ptr]=v;
		}
		else if(c=='.')
		{
			cout.put((char)mem[ptr]);
		}
		else if(c=='[')
		{
			if(mem[ptr]==0)
				pc=cl[pc];//跳过整个循环体
		}
		else if(c==']')
		{
			pc=op[pc]-1;//跳回 '['，重新判断条件
		}
		++pc;
	}
	cout<<'\n';
	return 0;
}
```

### 代码说明

- 过滤指令字符的那一步同时解决了「注释」与「注释里的方括号破坏配对」两个问题。
- `cl` / `op` 用栈预处理，把运行期的括号查找从 $O(\text{代码长})$ 降到 $O(1)$。
- `if(++mem[ptr]==128)` 利用了 C++ 前置自增先改值再比较的语义；`-` 分支同理用 `if(--mem[ptr]==-129)`。这两种情况分别就是 $127+1$ 与 $-128-1$ 的回绕。
- `,` 的取值用 `(unsigned char)buf[ip++]` 取出字节的无符号值，再对大于 127 的减 256，得到 8 位有符号表示；缓冲区为空时直接取 $-1$。
- `,` 的三目运算符中两个分支类型不同（`unsigned char` 与 `int`），会提升为 `int`，取字节值时需显式转 `unsigned char` 以避免负值被符号扩展。
- `blen` 用 `q>=2` 保护，避免缓冲区为空（格式为「空格 `$`」）时出现负长度。
- `maxstep` 兜底防止意外死循环；题面保证 $10^6$ 步内结束，正常数据不会触发。
- 全程使用 `'\n'` 而非 `endl`；`main` 以 `return 0;` 正常结束。
