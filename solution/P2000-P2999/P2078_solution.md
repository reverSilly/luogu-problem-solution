# P2078 朋友 — 题解

## 一、解题过程：人类思考叙事

题目：A 公司有 $N$ 名员工（全为男性，编号 $1\sim N$），$P$ 对朋友关系；B 公司有 $M$ 名员工（全为女性，编号 $-1\sim -M$），$Q$ 对朋友关系。"朋友的朋友一定还是朋友"。小明编号 $1$，小红编号 $-1$。求"通过小明和小红认识的人"最多能配成多少对情侣（包括他们自己）。

$N,M\le10^4$，$P,Q\le2\times10^4$。

**第一步：读懂"朋友的朋友还是朋友"意味着什么。**

这是一个**传递性**关系。在 A 公司内部，如果 $u$ 和 $v$ 是朋友，$v$ 和 $w$ 是朋友，那么 $u$ 和 $w$ 也是朋友（只要他们同属一个"朋友圈"）。所以 A 公司内部的朋友关系形成了若干个**连通块**，块内任意两人互为朋友。

"通过小明和小红认识的人"就是：小明所在连通块里的人（他们都是小明的朋友），小红所在连通块里的人。

**第二步：情侣怎么配？**

小明是男的（$1$），小红是女的（$-1$）。一个互为朋友的异性组可以配成情侣——注意这里只考虑"通过小明和小红认识"的这批人。

小明所在块里有 $a$ 个人（全是男的），小红所在块里有 $b$ 个人（全是女的）。这两块之间的人互为朋友吗？

题目说"大家都知道，小明和小红是朋友"。小明在 A 公司，小红在 B 公司。题目说"两个公司的员工有一个特点：一个公司的员工都是同性"——所以朋友关系不会跨公司！朋友关系只在公司内部存在。

那么"小明和小红是朋友"这只是个设定，用来把他们俩联系起来。而 A 公司里小明的朋友 = 小明所在连通块，B 公司里小红的朋友 = 小红所在连通块。

这两块的人"通过小明和小红认识"，可以互相配对：$a$ 个男的和 $b$ 个女的，一对一最多配 $\min(a,b)$ 对。

而且题目说"包括他们自己"——小明在 A 块里，小红在 B 块里，都被计入，所以答案就是 $\min(a,b)$，不需要额外 +1。

**第三步：怎么求连通块？**

并查集。$N+M\le2\times10^4$ 个点，$P+Q\le4\times10^4$ 条边，$O(\alpha)$ 时间。

**第四步：编号映射，这是本题唯一的坑。**

输入的编号是：男性 $1\sim N$ 为正，女性 $-1\sim -M$ 为负。

女性编号 $-i$（$1\le i\le M$）对应 B 公司的第 $i$ 号员工。我把它映射到 $N+i$，这样总点数是 $N+M$，编号连续，可以直接开并查集数组。

映射函数：
```cpp
int mp(int x){ return x>0 ? x : N-x; }
```
注意女性 $-i$ 映射到 $N-i$？还是 $N+i$？这里要小心。$i$ 从 $1$ 开始，$-1$ 是小红。$N-x$ 当 $x=-1$ 时得 $N+1$；$N-i$ 当 $x=-i$ 得 $N-i$，但这样 $-1\mapsto N-1$，与男性编号 $N-1$ 冲突了！

所以正确映射是 $N+i = N - x$（因为 $x=-i$）。即 `mp(x) = x>0 ? x : n-x`。$-1\mapsto N+1$，$-M\mapsto N+M$。共 $N+M$ 个点，编号 $1\sim N+M$，无冲突 ✓。

我第一次写成了 `n-x` 的另一版本 `$n-x$`... 让我确认：我最初写的版本是 `n - x`（对女性 $x=-i$，得 $N+i$）——对的。而最初的 bug 是在别处：`sz` 重复计数。

**第五步：并查集实现。**

标准写法：
```cpp
f[i]=i; sz[i]=1;
```
合并时 `sz[root1] += sz[root2]`。

我第一次写的版本是把 `sz[i]` 初始化为 1 后又在 `uni()` 里 `++sz[getrt(i)]`——重复计数了。这就是"全局 int 数组默认 0"的坑的反面：这里 `sz` 不是默认 0 的问题，而是初始化 + 累加两处都做了。

最终答案：`min(sz[getrt(1)], sz[getrt(N+1)])`，其中 $1$ 是小明、$N+1$ 是小红。

**第六步：递归会不会爆栈？** 并查集的 `getrt` 是递归的，$N+M\le2\times10^4$，路径压缩后递归深度极浅（实际上最多 $\log$ 级别），不会爆栈。

样例验证：`4 3 4 2 / 1 1 / 1 2 / 2 3 / 1 3 / -1 -2 / -3 -3`

A 公司 $N=4$，$P=4$ 对朋友：$(1,1),(1,2),(2,3),(1,3)$。B 公司 $M=3$，$Q=2$ 对：$(-1,-2),(-3,-3)$。

- A 公司：$(1,1)$ 自环；$(1,2)$ 把 1、2 连一起；$(2,3)$ 把 3 也连进来；$(1,3)$ 冗余。所以 A 的连通块：$\{1,2,3\}$ 共 3 人，$\{4\}$ 单独（1 人）。小明（1）所在块 = 3 人。
- B 公司：$(-1,-2)$ 把小红和 2 号连一起 → $\{1,2\}$ 共 2 人；$(-3,-3)$ 自环 → $\{3\}$。小红所在块 = 2 人。
- 答案 $\min(3,2)=2$ ✓ 与样例一致。

## 二、思维链：完整证明

**引理 1**：把每个公司的朋友关系看成无向图，则"互为朋友"等价于"同属一个连通块"。

*证明*：朋友关系是对称的（$u$ 是 $v$ 的朋友则 $v$ 是 $u$ 的朋友），故可用无向图建模。题面规定"朋友的朋友一定还是朋友"，意味着朋友关系沿路径传递：若存在路径 $u=v_0,v_1,\ldots,v_k=v$，则 $u$ 与 $v$ 互为朋友。反之，若 $u,v$ 互为朋友，则它们之间存在一条边构成的路径。故"互为朋友"⟺"连通"。证毕。

**引理 2**：通过小明和小红认识的人，恰好是小明所在连通块与小红所在连通块中的人。

*证明*：由引理 1，小明的朋友恰为小明所在连通块全体，同理小红的朋友恰为其所在连通块全体。能通过小明和小红认识的人，必须是小明的朋友或小红的朋友，即属于这两个块之一；反之两个块中的人分别是小明或小红的朋友，自然属于"通过他们认识的人"。证毕。

**引理 3**：小明所在块人数为 $a$、小红所在块人数为 $b$ 时，最多能配 $\min(a,b)$ 对情侣。

*证明*：A 公司员工全为男性，B 公司员工全为女性，而朋友关系只在公司内部（题目"一个公司的员工都是同性"配合两段独立的输入，说明朋友关系不跨公司），故小明块中的人全为男性、小红块中的人全为女性，块内任意异性两人都是朋友，满足"一组互为朋友的异性可以配成情侣"的定义。每对情侣消耗一个男一个女，故对数 $\le\min(a,b)$；另一方面任选 $\min(a,b)$ 名男性与同样多的女性一一配对，因为小明与小红互为朋友（题目保证），这 $\min(a,b)$ 对彼此都"通过小明和小红认识"，且都是互为朋友的异性，故可实现。上下界相同，最大值为 $\min(a,b)$。证毕。

**引理 4**：`mp(x)=x>0?x:N-x` 把所有编号映射到互不相同的 $1\sim N+M$。

*证明*：男性编号 $x\in[1,N]$ 映射为 $x\in[1,N]$。女性编号 $x=-i$（$1\le i\le M$）映射为 $N+i\in[N+1,N+M]$。男性与女性的映射值分处不相交的两个区间，且各自内部一一对应（$i\mapsto N+i$ 是双射）。故所有 $N+M$ 个编号映射后互不相同，恰好覆盖 $1\sim N+M$。证毕。

**定理**：算法输出的 $\min(sz[getrt(1)],sz[getrt(N+1)])$ 即题目所求。

*证明*：由引理 4，编号映射后并查集在 $N+M$ 个点上正确建图；并查集维护的连通块与原图连通块一一对应，故 `sz[getrt(1)]` 是小明所在块人数、`sz[getrt(N+1)]` 是小红所在块人数（由引理 4，$-1$ 映射为 $N+1$）。由引理 2、3，答案即两者的较小值。证毕。

## 三、模式总结（按实际思考顺序）

1. **看到"朋友的朋友还是朋友"立刻想到连通块** — 传递性关系 = 连通分量，并查集是标准解。
2. **先分清两个公司** — 朋友关系不跨公司（全同性），所以"通过小明和小红认识"= 两个块。
3. **"互为朋友的异性配对"→ 人数取 min** — 男块人数与女块人数的较小值，因为每对消耗一男一女。
4. **正负编号映射** — 男 $1\sim N$、女 $-1\sim -M$，用 $N+i$ 把女编号平移到 $N+1\sim N+M$，注意是 $N+i$ 而不是 $N-i$（否则与男性编号冲突）。
5. **并查集的 `sz` 只在一处初始化** — 要么 `sz[i]=1` 初始化、要么合并时 `+=`，不能两处都做（重复计数）。
6. **小明/小红的实际编号** — 小明映射后是 $1$，小红映射后是 $N+1$，别写错成 $N-1$。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $N$ | A 公司（男性）员工数 | `int`，$\le10^4$ |
| $M$ | B 公司（女性）员工数 | `int`，$\le10^4$ |
| $P$ | A 公司朋友关系数 | `int`，$\le2\times10^4$ |
| $Q$ | B 公司朋友关系数 | `int`，$\le2\times10^4$ |
| `f[i]` | 并查集父节点 | `int`，$1\sim N+M$ |
| `sz[i]` | 以 $i$ 为根的连通块人数 | `int`，$1\sim N+M$ |
| `mp(x)` | 编号映射：男 $x\to x$，女 $x\to N-x$ | `int` |
| $a,b$ | 小明块、小红块人数 | `int` |

**初始化约定**：`f[]`、`sz[]` 为全局数组，默认全 0；使用前在循环中显式赋 `f[i]=i; sz[i]=1;`，**不可依赖默认 0**（`sz` 若默认 0 会漏算自己）。

### 算法步骤

1. 读入 $N,M,P,Q$。
2. 初始化并查集：对 $i=1\ldots N+M$，`f[i]=i`、`sz[i]=1`。
3. 读入 $P$ 对朋友关系，每对 $(u,v)$ 调用 `uni(mp(u),mp(v))`。
4. 读入 $Q$ 对朋友关系，同样 `uni(mp(u),mp(v))`。
5. 计算 `a=sz[getrt(1)]`（小明所在块）、`b=sz[getrt(N+1)]`（小红所在块，$-1\mapsto N+1$）。
6. 输出 `min(a,b)`。

### 复杂度

- 时间复杂度：$O((N+M+P+Q)\,\alpha(N+M))$，并查集单次操作均摊 $O(\alpha)$，实际可视为线性。
- 空间复杂度：$O(N+M)$，存储父节点与块大小。

### 验证状态

- 标程 `P2078.cpp` 用 `g++ -O2 -std=c++17` 编译通过。
- 题面官方样例 `4 3 4 2 / 1 1 / 1 2 / 2 3 / 1 3 / -1 -2 / -3 -3` 输出 `2`，与官方一致。
- 编写独立暴力 `P2078_brute.cpp`（用**邻接表 + BFS** 求连通块大小，与并查集是完全不同的实现）与对拍脚本 `P2078_check.py`：随机生成 $1\le N,M\le8$、$0\le P\le N$、$0\le Q\le M$ 的数据（允许自环与重复边），并附加"完全没有朋友关系 / 两边各自连通 / 官方样例"等极端构造，**对拍 2004 组全部通过**。

## 五、示例代码（C++，Louis Li 风格）

```cpp
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{20005};

int n,m,p,q;
//f[i]：并查集父节点
int f[mxn];
//sz[i]：以 i 为根的连通块人数
int sz[mxn];

int getrt(int x)
{
	if(f[x]==x)
		return x;
	return f[x]=getrt(f[x]);
}

//男编号 i -> i，女编号 -i -> n+i
int mp(int x)
{
	return x>0?x:n-x;
}

void uni(int u,int v)
{
	u=getrt(u);
	v=getrt(v);
	if(u==v)
		return;
	f[v]=u;
	sz[u]+=sz[v];
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>m>>p>>q;
	for(int i=1;i<=n+m;++i)
	{
		f[i]=i;
		sz[i]=1;
	}
	for(int i=1,u,v;i<=p;++i)
	{
		cin>>u>>v;
		uni(mp(u),mp(v));
	}
	for(int i=1,u,v;i<=q;++i)
	{
		cin>>u>>v;
		uni(mp(u),mp(v));
	}
	//小明所在块（男）与小红所在块（女）互相都是朋友，配对数取较小者
	int a=sz[getrt(1)];
	int b=sz[getrt(n+1)];
	cout<<min(a,b)<<'\n';
	return 0;
}
```

### 代码说明

- `f[]`、`sz[]` 为全局数组，默认全 0；在初始化循环里显式写 `f[i]=i; sz[i]=1;`，块大小只在初始化时给 1，之后由 `uni()` 累加，不会重复计数。
- `mp(x)` 对女性 $-i$ 返回 `n-x = n+i`，与男性编号区间 $[1,n]$ 不冲突；小红的 `-1` 因此映射为 `n+1`。
- `uni()` 先取根再判重根，重复关系（自环、重复边）直接跳过，块大小不会被多算。
- `getrt` 用递归 + 路径压缩（`f[x]=getrt(f[x])`），$2\times10^4$ 的规模下递归深度很浅。
- 全程使用 `'\n'` 而非 `endl`；`main` 以 `return 0;` 正常结束。
