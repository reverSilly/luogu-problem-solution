# P2550 [AHOI2001] 彩票摇奖 — 题解

## 一、解题过程：人类思考叙事

**题意重述。** 中奖号码是 $7$ 个互不相同的数（取值 $1\sim33$）。小明买了 $n$ 张彩票（$1\le n<1000$），每张也是 $7$ 个互不相同的数。一张彩票中了几个号码，就看它的 $7$ 个数里有几个出现在中奖号码中（**只看个数，不看位置**）。命中 $7$ 个是特等奖，$6$ 个一等奖，$5$ 个二等奖，$4$ 个三等奖，$3$ 个四等奖，$2$ 个五等奖，$1$ 个六等奖；命中 $0$ 个不中奖。要按"特等奖、一等奖、…、六等奖"的顺序输出各奖项的中奖张数。

**第一步：把"中了几等奖"翻译成"命中几个数"。** 题面那张奖项表看起来有七档，其实它只是命中数 $k$ 的一个单调映射：

$$k=7\to\text{特等奖},\quad k=6\to\text{一等奖},\quad\dots,\quad k=1\to\text{六等奖}.$$

也就是说，**奖项完全由命中数 $k$ 决定**，跟具体命中了哪些号码、号码长什么样都无关。这一步把问题从"七种奖项分别判断"塌缩成"对每张彩票算一个整数 $k$，再往对应的桶里丢一张"。我只要维护一个计数数组 `cnt[k]`，最后按 $k=7,6,\dots,1$ 的顺序输出 `cnt[k]` 即可。

**第二步：怎么算一张彩票的命中数 $k$？** 最朴素的想法是拿彩票的每个数去中奖号码里逐个比对，$7\times7=49$ 次比较，$n<1000$ 张也就 $4.9\times10^4$ 次，完全能过。但号码范围只有 $1\sim33$，这让我想到一个更干净的办法：**开一个布尔数组 `win[34]`，把中奖号码对应的位置标记为真**。这样判断"某个数 $x$ 是否中奖"就是 $O(1)$ 的 `win[x]`，一张彩票扫 $7$ 个数累加 `win[x]` 就得到 $k$。

这里有个必须确认的前提：**彩票上的 $7$ 个数互不相同，中奖号码也互不相同**。正因为互不相同，"命中数"就等于"彩票号码集合与中奖号码集合的交集大小"，用 `win[x]` 累加不会把同一个号码重复计数，也不会漏。如果号码可能重复，布尔标记法就会出错（得改用计数），但题面保证了互异，所以这条路是安全的。

**第三步：边界——命中 $0$ 个怎么办？** 题面只设了 $1\sim7$ 个命中的奖项，命中 $0$ 个**不中奖**，不属于任何一档。所以 `cnt[0]` 虽然会被累加，但**绝不输出**。输出只取 `cnt[7]` 到 `cnt[1]` 这七个数。我特意用一张"一个号都没中"的彩票验证：它让 `cnt[0]` 加一，但输出的七个数字不受影响。

**第四步：输出顺序别搞反。** 题目要求"首先输出特等奖，然后依次一等奖至六等奖"，对应的是 $k=7,6,5,4,3,2,1$。所以循环要**从 $7$ 递减到 $1$**，而不是从 $1$ 到 $7$。这是本题最容易写反的地方：奖项等级（特等最高）和命中数（$7$ 最多）是同向的，但和"第几等奖"的序号是反向的。我按命中数 $k$ 递减输出，正好对应奖项从高到低。

**手造数据核对**（题面给了一个兑奖例子，我把它当第一组测试，再另造一组覆盖全部七档）：

第一组，用题面的例子：中奖号码 `23 31 1 14 19 17 18`，一张彩票 `12 8 9 23 1 16 7`。命中 $\{23,1\}$ 共 $2$ 个 → 五等奖。输出应为 `0 0 0 0 0 1 0`（只有五等奖那一档是 $1$）。程序输出一致。

第二组，中奖号码取 `1 2 3 4 5 6 7`，构造 $8$ 张彩票分别命中 $7,6,5,4,3,2,1,0$ 个：

```
1 2 3 4 5 6 7   → 7 个（特等）
1 2 3 4 5 6 8   → 6 个（一等）
1 2 3 4 5 8 9   → 5 个（二等）
1 2 3 4 8 9 10  → 4 个（三等）
1 2 3 8 9 10 11 → 3 个（四等）
1 2 8 9 10 11 12→ 2 个（五等）
1 8 9 10 11 12 13→1 个（六等）
8 9 10 11 12 13 14→0 个（不中奖）
```

期望输出 `1 1 1 1 1 1 1`，程序输出一致。这两组把"命中数→奖项映射""$0$ 命中不输出""输出顺序"三个点全覆盖了。

## 二、思维链：完整证明

**记号。** 中奖号码集合 $W\subseteq\{1,\dots,33\}$，$|W|=7$，元素互异。第 $i$ 张彩票的号码集合 $T_i\subseteq\{1,\dots,33\}$，$|T_i|=7$，元素互异。命中数 $k_i=|T_i\cap W|$。奖项计数 $C_k=\#\{i:k_i=k\}$（$k=0,\dots,7$）。程序输出 $(C_7,C_6,\dots,C_1)$。

---

### 引理 1（布尔标记法精确计算交集大小）

设 `win[x]` 当且仅当 $x\in W$ 时为真。对一张彩票，令 $\text{hit}=\sum_{x\in T_i}\texttt{win}[x]$（按读入的 $7$ 个数逐个累加）。则 $\text{hit}=|T_i\cap W|=k_i$。

*证明*：因为 $T_i$ 的 $7$ 个元素**互不相同**，读入的 $7$ 个数恰好是 $T_i$ 的 $7$ 个元素各一次，没有重复也没有遗漏。于是
$$\text{hit}=\sum_{x\in T_i}\texttt{win}[x]=\sum_{x\in T_i}[\,x\in W\,]=\#\{x\in T_i:x\in W\}=|T_i\cap W|.$$
第一个等号是"互异 ⇒ 每个元素恰被加一次"；第二个等号是 `win` 的定义（$\texttt{win}[x]=[x\in W]$）；第三个等号是交集大小的定义。故 $\text{hit}=k_i$。

**反证补充（为什么"互异"是必要条件）**：若 $T_i$ 含重复元素，比如某个 $x\in W$ 出现两次，则 $\sum_{x\in T_i}\texttt{win}[x]$ 会把 $x$ 计两次，得到 $\text{hit}>|T_i\cap W|$，等式断裂。题面"每张彩票上印有 $7$ 个各不相同的号码"正好排除了这种情形，所以布尔累加与交集大小严格相等。证毕。

---

### 引理 2（奖项与命中数是一一对应，且映射方向正确）

定义奖项函数 $\text{tier}(k)$：$k=7\mapsto$ 特等奖，$k=6\mapsto$ 一等奖，$k=5\mapsto$ 二等奖，$k=4\mapsto$ 三等奖，$k=3\mapsto$ 四等奖，$k=2\mapsto$ 五等奖，$k=1\mapsto$ 六等奖。则 $\text{tier}$ 是 $\{1,\dots,7\}$ 到七个奖项的双射，且"特等奖、一等奖、…、六等奖"的输出顺序恰对应 $k=7,6,\dots,1$。

*证明*：题面兑奖规则逐条给出"$k$ 个号码命中 $\to$ 某奖项"，$k$ 取遍 $1..7$ 时七个奖项各被命中恰好一次，故 $\text{tier}$ 是双射（每个 $k$ 唯一确定一个奖项，每个奖项唯一对应一个 $k$）。

输出顺序：题面要求"首先特等奖，然后依次一等奖至六等奖"。由映射，特等奖 $=k7$、一等奖 $=k6$、二等奖 $=k5$、三等奖 $=k4$、四等奖 $=k3$、五等奖 $=k2$、六等奖 $=k1$。故输出序列为 $(C_7,C_6,C_5,C_4,C_3,C_2,C_1)$，即按 $k$ **递减**遍历。程序 `for(k=7;k>=1;--k)cout<<cnt[k]` 正是这个顺序。证毕。

---

### 引理 3（命中 $0$ 个不计入任何输出）

$k_i=0$ 的彩票不属于任何奖项，故不影响输出的七个计数。

*证明*：题面奖项只覆盖命中 $1\sim7$ 个的情形，没有"命中 $0$ 个"的奖项。因此 $C_0$ 虽然被程序累加（`++cnt[0]`），但输出循环只取 $k=7..1$，从不读取 `cnt[0]`。形式上，输出向量 $(C_7,\dots,C_1)$ 的每个分量都只统计 $k\ge1$ 的彩票，$k=0$ 的彩票对每个分量的贡献均为 $0$。故命中 $0$ 个的彩票被正确忽略。证毕。

---

### 引理 4（计数桶的累加正确）

程序对每张彩票执行 `++cnt[hit]`，最终 `cnt[k]`$=C_k$。

*证明*：对彩票张数归纳。初始 `cnt` 全 $0$（全局数组默认值），对应"还没有任何彩票"，$C_k=0$。处理第 $i$ 张时，由引理 1 算得 $\text{hit}=k_i$，执行 `++cnt[k_i]`，恰好把 $C_{k_i}$ 加 $1$，与"第 $i$ 张彩票命中 $k_i$ 个"的定义一致。$n$ 张处理完后，`cnt[k]` 累计了所有命中数为 $k$ 的彩票张数，即 $C_k$。证毕。

---

### 引理 5（复杂度）

时间 $O(n)$，空间 $O(1)$（常数大小数组）。

*证明*：读入中奖号码 $7$ 次标记 $O(7)$。每张彩票读 $7$ 个数、累加 $7$ 次 `win`、一次 `++cnt`，共 $O(7)=O(1)$，$n$ 张合计 $O(7n)=O(n)$。输出 $7$ 个数 $O(7)$。总时间 $O(n)$，$n<1000$ 时不足 $10^4$ 次基本操作。空间：`win[34]`、`cnt[8]` 都是常数大小，$O(1)$。证毕。

---

### 定理

程序输出的七个整数依次是特等奖、一等奖、…、六等奖的中奖张数。

*证明*：引理 1 保证每张彩票的命中数 $k_i$ 被精确算出；引理 4 保证 `cnt[k]` 恰为命中 $k$ 个的彩票张数 $C_k$；引理 2 保证按 $k=7..1$ 递减输出正好对应"特等奖→六等奖"的顺序；引理 3 保证命中 $0$ 个的彩票不污染输出；引理 5 给出复杂度。故输出正确。证毕。

## 三、模式总结（按实际思考顺序）

- **explore its property** — "中几等奖"只由命中数 $k=|T_i\cap W|$ 决定，与具体号码无关；七档奖项是 $k$ 的单调映射。
- **reduce to easier problem** — 把"七种奖项分别判断"塌缩成"算一个整数 $k$，往桶 `cnt[k]` 里丢一张"，最后按桶输出。
- **classic problem solution** — 号码范围仅 $1\sim33$ ⇒ 布尔标记数组 `win[34]`，$O(1)$ 判命中；号码互异保证累加 = 交集大小。
- **discuss by category** — 命中 $0$ 个不中奖、不输出；输出顺序按 $k=7\to1$ 递减（特等→六等），别写反。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 初值 | 记忆点 |
|------|------|-------------|--------|
| `n` | 彩票张数（$1\le n<1000$） | `int`，读入 | 逐张处理 |
| `win[x]` | 号码 $x$ 是否在中奖号码中 | `bool[34]`，默认 `false` | 下标即号码，$1\sim33$ |
| `cnt[k]` | 命中 $k$ 个号码的彩票张数 | `int[8]`，默认 $0$ | $k=0..7$；只输出 $k=7..1$ |
| `hit` | 当前彩票的命中数 | `int`，每张重置 $0$ | `hit+=win[x]` 累加 $7$ 次 |
| `x` | 读入的单个号码 | `int` | 中奖号码与彩票号码复用 |

### 算法步骤

1. I/O 加速三行。
2. 读 `n`；读 $7$ 个中奖号码，逐个 `win[x]=true`。
3. 对每张彩票：`hit=0`，读 $7$ 个号码逐个 `hit+=win[x]`；`++cnt[hit]`。
4. 按 `k=7,6,...,1` 输出 `cnt[k]`，空格分隔，末尾换行。

### 复杂度

- 时间：$O(n)$（每张 $O(7)$），$n<1000$ 时约 $7\times10^3$ 次操作。
- 空间：$O(1)$（`win[34]`+`cnt[8]`）。
- 验证状态：`g++ -std=c++20 -O2` 编译通过；题面兑奖例子（命中 $2$ 个→五等奖）输出 `0 0 0 0 0 1 0` 吻合；另造覆盖全部七档 + 一张零命中的 $8$ 张彩票数据，输出 `1 1 1 1 1 1 1` 与手算一致。入门级直接模拟，无需对拍。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2550 [AHOI2001] 彩票摇奖
// 每张彩票统计有几个号码命中中奖号码，按命中数 k 累加到 cnt[k]
// 特等奖=k7，一等奖=k6，…，六等奖=k1；依次输出 cnt[7..1]
#include<bits/stdc++.h>
using namespace std;

int n,cnt[8];
bool win[34];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0,x;i<7;++i)
	{
		cin>>x;
		win[x]=true;			// 中奖号码打标记，1..33
	}
	for(int i=0;i<n;++i)
	{
		int hit=0;
		for(int j=0,x;j<7;++j)
		{
			cin>>x;
			hit+=win[x];		// 号码互不相同，直接数命中个数
		}
		++cnt[hit];
	}
	for(int k=7;k>=1;--k)
		cout<<cnt[k]<<(k==1?'\n':' ');
	return 0;
}
```

### 代码说明

- **`win[34]` 而非 `win[33]`**：号码取值 $1\sim33$，用号码本身当下标，需要下标 $33$ 合法，故开 $34$（$0$ 号位闲置）。这是"内部直接用原始编号作下标"的常见 +1 松弛。
- **`hit+=win[x]`**：`bool` 隐式转 `int`（真 $1$ 假 $0$），累加 $7$ 次即命中数。依赖题面"号码互异"，否则重复号码会多计（引理 1 的反证）。
- **`cnt[8]`**：命中数 $k\in[0,7]$，开 $8$ 个桶。`cnt[0]` 会被累加但从不输出（引理 3）。
- **输出 `for(k=7;k>=1;--k)`**：递减遍历对应"特等奖→六等奖"，写反成递增就把奖项顺序颠倒了（引理 2）。
- 全局 `int`/`bool` 数组默认 $0$/`false`，本题无需显式初始化；`cnt` 的零初值恰好是"还没统计任何彩票"。
