# P2814 家谱 — 题解

## 一、解题过程：人类思考叙事

**题意重述。** 输入是一串命令流，以单独一行 `$` 结束：

- `#name`：声明接下来的一组父子关系里的**父亲**是 `name`；
- `+name`：声明 `name` 是**当前父亲**的一个儿子（一个父亲下可以有若干 `+`）；
- `?name`：询问 `name` 的**最早祖先**，按输入顺序输出 `name 祖先名`。

名字恒为 $6$ 个字符、首字母大写、互不相同；最多 $10^3$ 组父子关系，总人数 $\le 5\times10^4$，家谱不超过 $30$ 代。

**第一步：把"家谱"翻译成图。** 每个人至多有一个父亲（家谱的基本常识，题目也保证记载合法），于是"儿子 $\to$ 父亲"这是一张**每个点出度至多为 $1$** 的有向图。又因为父亲总比儿子高一辈，沿着父亲走世代严格递增，不可能走回自己——**无环**。出度 $\le1$ 且无环，这正是**内向森林**（每棵树的所有边指向根）。一个人的"最早祖先"就是他那棵树的**根**。

所以问题塌缩成一句话：**给定一片森林，多次询问某个点所在树的根。**

**第二步：先想最朴素的办法。** 如果名字是 $1..n$ 的整数，记 `fa[x]` 为 $x$ 的父亲，那么询问就是不停 `x=fa[x]` 直到 `fa[x]==x`。题目说"不超过 $30$ 代"，意味着树高 $\le30$，每次询问最多爬 $30$ 步——**这个暴力其实就能过**。但既然标签写着"并查集"，而且爬链的写法在退化数据下不够稳健，我更愿意用**路径压缩**把"爬链" amortize 成近乎 $O(1)$。

**第三步：这里有一个真正的陷阱——不能套"按秩合并"。** 我一开始条件反射地想写标准并查集模板：`f[getrt(son)]=getrt(father)`，再配个按大小/按秩合并。停下来一想：**错了**。标准并查集的"根"只是集合的代表元，按秩合并会**故意把矮树挂到高树下**，根是谁完全由秩决定，跟"辈分"毫无关系。

举个最小反例：父亲 `Aaa`（一棵已经很大的树的根），儿子 `Bbb`（一棵更大的树的根）。若按秩合并把 `Aaa` 挂到 `Bbb` 下，那么询问 `Aaa` 的祖先会得到 `Bbb`——**儿子成了父亲的祖先**，荒谬。

问题的根源：本题的森林结构是**题目直接给定的**（每条 `+name` 明确告诉你"谁是谁的父亲"），我们**不需要也不允许**自由决定合并方向。正确做法是老老实实令

```
f[son] = father;   // 直接认父亲，不做任何按秩交换
```

这样 `f` 就是真实的父亲指针，`getrt` 顺着它爬到的根就是真实的最早祖先。路径压缩只是把"爬过的链"压平，**不改变根是谁**，所以安全。

**第四步：名字是字符串，先映射成整数。** 并查集数组下标必须是整数。用一个 `map<string,int>` 给每个**第一次出现**的名字分配编号 $0,1,2,\dots$，同时把编号对应的原名存进 `nam[]`（输出祖先名时要用）。`#`、`+`、`?` 三种命令都先 `getid(name)` 拿到编号再操作。询问时输出 `nam[getrt(u)]` 就是祖先的原名。

**第五步：几个边界。**

1. **`?name` 的人可能从没在关系里出现过**（题目没保证询问对象一定有家谱）。`getid` 会给它新建一个编号、`f[u]=u`，于是 `getrt(u)=u`，输出"自己 自己"——一个没有记载祖先的人，最早祖先就是自己，合理。
2. **一个人先当父亲、后当儿子**：`#Bbb` 之后 `Bbb` 有了孩子，再后来 `+Bbb` 把 `Bbb` 挂到某父亲下。此时 `f[Bbb]=father`，`Bbb` 的孩子们顺着 `f` 爬会经过 `Bbb` 再到新父亲，完全正确。
3. **路径压缩会不会破坏"认父亲"？** 不会。一个点在**被认父亲之前**没有父亲，`f[x]=x`，它就是自己子树的根，`getrt(x)=x`，压缩是空操作；认父亲时 `f[x]=father` 是干净赋值。认完父亲之后题目不会再给它第二个父亲（家谱合法），所以不存在"压缩后又改父亲"的冲突。
4. **`$` 结束**：读入用 `while(cin>>s&&s!="$")`，`$` 是单独一个 token，`s[0]` 不是 `#/+/?`，靠 `s!="$"` 提前退出。

**手造数据核对**（题面无样例，按规则自造）：

输入：
```
#Aaaaaa
+Bbbbbb
+Cccccc
#Bbbbbb
+Dddddd
?Dddddd
?Cccccc
?Aaaaaa
$
```
关系：`Aaaaaa` 是 `Bbbbbb`、`Cccccc` 的父亲；`Bbbbbb` 是 `Dddddd` 的父亲。
- `?Dddddd`：`Dddddd→Bbbbbb→Aaaaaa`，输出 `Dddddd Aaaaaa`；
- `?Cccccc`：`Cccccc→Aaaaaa`，输出 `Cccccc Aaaaaa`；
- `?Aaaaaa`：根本身，输出 `Aaaaaa Aaaaaa`。

再造一组专打"先当父亲后当儿子"与"未出现的人"：
```
#Xxxxxx
+Yyyyyy
#Zzzzzz
+Xxxxxx
?Yyyyyy
?Wwwwww
$
```
`Xxxxxx` 先是 `Yyyyyy` 的父亲，后被 `+Xxxxxx` 挂到 `Zzzzzz` 下。`?Yyyyyy`：`Yyyyyy→Xxxxxx→Zzzzzz`，输出 `Yyyyyy Zzzzzz`；`?Wwwwww` 从未出现，输出 `Wwwwww Wwwwww`。两组都符合预期。

## 二、思维链：完整证明

**记号。** 人集合 $V$，$|V|\le 5\times10^4$。命令流依次处理。`f[x]` 为点 $x$ 的父亲指针（无父亲时 `f[x]=x`）。`getrt(x)` 为沿 `f` 爬到的根。`nam[i]` 为编号 $i$ 的原名，`id` 为名字到编号的映射。

---

### 引理 1（家谱是内向森林，最早祖先 = 树根）

把"儿子 $\to$ 父亲"看作有向边。合法家谱中每人至多一个父亲，且父亲辈分严格高于儿子。则所得有向图 $G$ 满足：每点出度 $\le1$、无有向环，从而是若干棵**内向树**（边指向根）的不交并；点 $v$ 的最早祖先恰为其所在树的根。

*证明*：出度 $\le1$ 由"每人至多一个父亲"直接得到。无环：若存在环 $v_1\to v_2\to\cdots\to v_t\to v_1$，则辈分沿边严格递增，得 $\text{gen}(v_1)<\text{gen}(v_2)<\cdots<\text{gen}(v_1)$，矛盾。故 $G$ 无环。

一个每点出度 $\le1$ 的无环有向图，从任一点 $v$ 出发沿唯一出边走，因无环且点数有限，必在有限步后停在某个出度为 $0$ 的点 $r$（即 `f[r]=r`，无父亲）。把这条路径上的边反向看，所有点都"汇入" $r$；不同起点若汇入同一 $r$ 则属同一棵树。于是 $G$ 是内向森林，$r$ 是 $v$ 所在树的根。

"最早祖先"即沿父亲链能追溯到的最远的人，正是出度为 $0$ 的根 $r$（再往上无父亲）。证毕。

---

### 引理 2（直接认父亲维持真实父亲指针）

处理命令时：`#name` 令 `cur=id(name)`；`+name` 令 `f[id(name)]=cur`。则在任意时刻，对每个已认父亲的点 $x$，`f[x]` 等于其真实父亲；未认父亲的点 `f[x]=x`。

*证明*：对命令数归纳。初始所有点 `f[x]=x`（`getid` 新建时置），无人有父亲，成立。

`#name` 只改 `cur`，不改 `f`，不变量保持。

`+name`：设当前父亲为 $c$（`cur`），儿子为 $s$。由家谱合法性，$s$ 在此刻**尚未被认过父亲**（否则一人两父，矛盾），故此前 `f[s]=s`。赋值 `f[s]=c` 后，`f[s]` 恰为真实父亲 $c$。其余点的 `f` 不变。不变量保持。

`?name` 只读不写 `f`（路径压缩的写见引理 3，不改变根）。证毕。

**注**：这里**不能**用按秩合并 `f[getrt(s)]=getrt(c)` 之外的方向交换。反例：若 $s$ 的子树比 $c$ 的子树大，按秩合并会把 `getrt(c)` 挂到 `getrt(s)` 下，使 $c$ 的根变成 $s$ 子树里的某点，违背"父亲是祖先"。直接 `f[s]=c` 固定了方向，根永远是辈分最高者。

---

### 引理 3（getrt 返回真实根，路径压缩不改变根）

`getrt(x)`：若 `f[x]==x` 返回 $x$；否则返回 `f[x]=getrt(f[x])`。则返回值是 $x$ 沿真实父亲链的根，且调用后 $x$ 到根路径上所有点的 `f` 都被直接指向根，**各点的根不变**。

*证明*：先证返回值正确。对路径长度归纳。若 `f[x]==x`，$x$ 无父亲，是根，返回 $x$ ✓。否则设 $x$ 的真实父亲为 $p=$`f[x]`（引理 2），$x$ 的根 $=$ $p$ 的根。递归 `getrt(f[x])` 由归纳假设返回 $p$ 的根，即 $x$ 的根 ✓。

再证压缩不改变根。递归返回时执行 `f[x]=r`（$r$ 为根）。这把 $x$ 的父亲指针从 $p$ 改成 $r$。但 $r$ 本就是 $x$ 的祖先（根），把 $x$ 直接挂到 $r$ 下，$x$ 的根仍是 $r$；路径上每个被改的点同理，根都不变。压缩只是缩短链，不改变"谁是谁的祖先"这一事实（根唯一）。证毕。

**推论**：压缩后再次 `getrt` 仍返回同一根；且因为认父亲只发生在"该点尚为根"时（引理 2），压缩与认父亲两种写操作不会互相干扰。

---

### 引理 4（询问输出正确）

`?name` 输出 `name` 与 `nam[getrt(id(name))]`。后者是 `name` 的最早祖先原名。

*证明*：由引理 1，最早祖先 $=$ 树根。由引理 2，`f` 是真实父亲指针。由引理 3，`getrt(id(name))` 返回该树根的编号 $r$。`nam[r]` 是编号 $r$ 的原名（`getid` 建立编号时同步存入），即祖先原名。输出格式 `name 祖先名` 与题面一致。

若 `name` 从未出现：`getid` 新建编号 $u$、`f[u]=u`，`getrt(u)=u`，输出 `name name`，符合"无记载祖先者为自身"。证毕。

---

### 引理 5（复杂度）

设总人数 $N\le5\times10^4$，命令数 $Q$（与 $N$ 同阶）。时间 $O(Q\log N + Q\,\alpha(N))$，空间 $O(N)$。

*证明*：每条命令一次 `map` 查找/插入，$O(\log N)$（红黑树）。`getrt` 带路径压缩，$Q$ 次操作总 amortized $O(Q\,\alpha(N))$（$\alpha$ 为反阿克曼函数，可视作常数）。名字长 $6$ 为常数，字符串比较 $O(1)$。故时间 $O(Q\log N)$。空间：`f`、`nam` 各 $O(N)$，`map` $O(N)$。代入 $N=5\times10^4$ 远低于时限。证毕。

---

### 定理

程序对每个 `?name` 按输入顺序输出其最早祖先原名，总复杂度 $O(Q\log N)$。

*证明*：引理 1 把问题化为森林求根；引理 2 保证 `f` 是真实父亲指针（且方向不可按秩交换）；引理 3 保证 `getrt` 正确且压缩安全；引理 4 保证输出；引理 5 给出复杂度。证毕。

## 三、模式总结（按实际思考顺序）

1. **explore its property** — "每人至多一个父亲 + 辈分递增" ⇒ 儿子→父亲是内向森林，最早祖先 = 树根。
2. **consider easier version** — 名字换成整数后就是"森林求根"，树高 $\le30$ 时朴素爬链即可，但用路径压缩更稳。
3. **classic problem solution** — 并查集（父亲指针 + 路径压缩）维护森林求根，amortized 近 $O(1)$。
4. **explore its property** — 本题森林结构由输入给定，**禁止按秩合并交换方向**，必须 `f[son]=father` 直接认父亲，否则根可能变成后代。
5. **reduce to easier problem** — 字符串名字用 `map<string,int>` 映射成编号，`nam[]` 存原名供输出。
6. **discuss by category** — `#`/`+`/`?`/`$` 四类 token 分别处理；未出现的人自成一树；先当父亲后当儿子靠指针自然衔接。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 | 初值 / 记忆点 |
|------|------|------|---------------|
| `mxn` | 人数上界 $5\times10^4+5$ | `constexpr int{50005}` | 数组尺寸 |
| `f[x]` | 点 $x$ 的父亲指针，无父亲时为 $x$ | `int[mxn]` | `getid` 新建时置 `f[cnt]=cnt` |
| `nam[i]` | 编号 $i$ 对应的原名（输出用） | `string[mxn]` | `getid` 新建时存入 |
| `id` | 名字 $\to$ 编号 | `map<string,int>` | 空，首次出现时插入 |
| `cnt` | 已分配编号数（下一个新编号） | `int` | 全局默认 $0$ |
| `cur` | 当前父亲编号（最近一个 `#`） | `int` | 全局默认 $0$，`#` 时更新 |
| `getrt(x)` | 沿 `f` 爬到的根，带路径压缩 | `int(int)` | `f[x]==x` 返回 $x$ |
| `getid(s)` | 名字 $s$ 的编号，不存在则新建 | `int(const string&)` | 新建时 `f[cnt]=cnt`、`nam[cnt]=s` |
| `s,t` | 当前 token / 去掉首字符的名字 | `string` | 每轮读入 |

### 算法步骤

1. I/O 加速三行。
2. `while(cin>>s&&s!="$")` 读 token；令 `t=s.substr(1)`。
3. 若 `s[0]=='#'`：`cur=getid(t)`。
4. 若 `s[0]=='+'`：`f[getid(t)]=cur`（直接认父亲，**不**按秩合并）。
5. 若 `s[0]=='?'`：`u=getid(t)`，输出 `t<<' '<<nam[getrt(u)]<<'\n'`。

### 复杂度

- 时间：$O(Q\log N)$，$Q$ 为命令数，$N\le5\times10^4$；路径压缩 amortized 近常数。
- 空间：$O(N)$（`f`、`nam`、`map`）。
- 验证状态：`g++ -std=c++20 -O2` 编译通过；两组手造数据（含"先父后子""未出现的人"）逐条吻合。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2814 家谱
// 儿子→父亲是内向森林，最早祖先=树根。用并查集父亲指针+路径压缩求根。
// 关键：森林结构由输入给定，必须 f[son]=father 直接认父亲，禁止按秩合并交换方向。
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{50005};

int f[mxn],cur,cnt;
string nam[mxn];
map<string,int>id;

int getrt(int x)
{
	if(f[x]==x)
		return x;
	return f[x]=getrt(f[x]);	// 路径压缩：不改变根
}
int getid(const string&s)
{
	auto it=id.find(s);
	if(it!=id.end())
		return it->second;
	nam[cnt]=s;
	f[cnt]=cnt;			// 新人自成一树
	return id[s]=cnt++;
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	string s;
	while(cin>>s&&s!="$")
	{
		string t=s.substr(1);
		if(s[0]=='#')
			cur=getid(t);
		else if(s[0]=='+')
			f[getid(t)]=cur;	// 直接认父亲，根永远是辈分最高者
		else
		{
			int u=getid(t);
			cout<<t<<' '<<nam[getrt(u)]<<'\n';
		}
	}
	return 0;
}
```

### 代码说明

- `f[getid(t)]=cur` 是全文核心：它把儿子的父亲指针**固定**指向当前父亲，绝不交换方向。换成按秩合并会让"根"脱离辈分语义（引理 2 的反例）。
- `getrt` 的路径压缩 `f[x]=getrt(f[x])` 只缩短链、不改根（引理 3），因此与"认父亲"兼容。
- `getid` 对首次出现的名字置 `f[cnt]=cnt`，保证未记载祖先的人 `getrt` 返回自身。
- `nam[]` 与 `id` 同步维护：编号是内部 0-based 表示，输出祖先时取 `nam[根编号]` 还原原名。
- `cur` 全局默认 $0$，但输入保证第一个关系命令是 `#`，故 `+` 出现前 `cur` 必已被正确赋值。
