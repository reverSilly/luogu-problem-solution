# P2049 魔术棋子 — 题解

## 一、解题过程：人类思考叙事

题目给一个 $M\times N$ 的方阵，每个格子里有一个整数。棋子从左上角出发，只能向右或向下走，每进入一个格子就把棋子上的数乘以该格子的数。问走到右下角时，棋子上的数模 $K$ 可能是哪些值。

$1\le M,N,K\le 100$。

第一反应是"路径 DP"：设 $f[i][j]$ 是"走到 $(i,j)$ 时的乘积"。但问题是——走到同一个格子，乘积**不唯一**。不同的路径乘出来的数不一样。所以 $f[i][j]$ 不是一个数，而是一个**集合**。

于是自然的定义变成：$f[i][j]$ = 所有能走到 $(i,j)$ 的路径对应的乘积模 $K$ 的余数集合。

转移就很好写了：到达 $(i,j)$ 的路径最后一步必然来自上方 $(i-1,j)$ 或左方 $(i,j-1)$。所以

$$f[i][j]=\{\,r\cdot a_{i,j}\bmod K \;\mid\; r\in f[i-1][j]\cup f[i][j-1]\,\}$$

初值：$f[1][1]=\{a_{1,1}\bmod K\}$（棋子初始为 $1$，进入起点后乘上 $a_{1,1}$）。

答案就是 $f[M][N]$ 里有多少个元素，按升序输出。

这里有个细节要注意：**乘法要取模后再乘**。$K\le 100$，而格子里的整数题面没给上限。如果直接用原始值相乘，$100$ 步乘下来早就溢出了。安全的做法是**读入时就把每个格子对 $K$ 取模**，之后所有乘法都在 $[0,K)$ 的数之间做，乘积最多 $(K-1)^2\le 9801$，`int` 完全够。

另一个细节：**$K$ 可能不保证格子值非负**，所以取模要用 `(x%k+k)%k` 的写法把负数归一化到 $[0,K)$。

集合怎么存？$K\le 100$，每个集合最多 $K$ 个元素，用 `bitset<101>` 存最省事：一个位 $r$ 表示余数 $r$ 可达。转移时枚举 $r=0..K-1$，若某个前驱的第 $r$ 位为 $1$，就把 $r\cdot a_{i,j}\bmod K$ 这一位置 $1$。

复杂度：格子数 $MN$ 个，每个格子枚举 $K$ 个余数，$O(MNK)\le 10^6$，轻松通过。

样例：$2\times3$ 棋盘
```
3 4 4
5 6 6
```
$K=5$。三条路径的乘积分别是 $3\cdot4\cdot4\cdot6=288$、$3\cdot4\cdot6\cdot6=432$、$3\cdot5\cdot6\cdot6=540$，模 $5$ 分别是 $3,2,0$。所以答案是 $3$ 个，结果 `0 2 3`，与题面一致。

## 二、思维链：完整证明

**引理 1**（取模的同余不变性）：对任意整数 $x,y,K\ge1$，有 $xy\equiv (x\bmod K)(y\bmod K)\pmod K$。

*证明*：由带余除法，存在整数 $q_1,q_2$ 使 $x=q_1K+x'$、$y=q_2K+y'$，其中 $x'=x\bmod K$、$y'=y\bmod K$。于是
$$xy=(q_1K+x')(q_2K+y')=q_1q_2K^2+(q_1y'+q_2x')K+x'y',$$
前两项都是 $K$ 的倍数，故 $xy\equiv x'y'\pmod K$。证毕。

**引理 2**（$f[i][j]$ 的定义正确）：算法计算出的 $f[i][j]$ 恰好是所有从起点走到 $(i,j)$ 的合法路径的乘积模 $K$ 所能取到的余数集合。

*证明*：对 $(i+j)$ 归纳（$i+j$ 随路径长度增长）。

**基例**：$i=j=1$ 时唯一路径是停在起点，乘积为 $1\cdot a_{1,1}$，模 $K$ 为 $a_{1,1}\bmod K$。算法令 `f[0][0].set(a[0][0])`，恰为该集合。

**归纳步**：设所有 $i+j$ 更小的格子结论成立。考虑任意一条到达 $(i,j)$ 的路径。它的最后一步或从 $(i-1,j)$ 走来（$i>1$），或从 $(i,j-1)$ 走来（$j>1$）。设最后一步进入前的乘积余数为 $r$，则由归纳步 $r\in f[i-1][j]$ 或 $r\in f[i][j-1]$；进入本格后乘上 $a_{i,j}$，由引理 1，新余数为 $r\cdot(a_{i,j}\bmod K)\bmod K$，这正是算法加入 $f[i][j]$ 的元素。故算法输出的每个元素都对应某条真实路径。

反之，算法加入的任何元素都形如 $r\cdot a_{i,j}\bmod K$，其中 $r$ 属于某个前驱的可达集合；由归纳步存在一条到该前驱的路径，其乘积余数为 $r$，在其后接一步向右或向下进入 $(i,j)$，即得一条到 $(i,j)$ 的路径，其乘积余数恰为算法加入的值。故算法没有多算任何元素。

两个方向合起来，$f[i][j]$ 恰为所求集合。证毕。

**定理**：算法输出的个数与余数列表恰为题目所求。

*证明*：由引理 2，$f[M][N]$ 恰为所有到达右下角的路径的乘积余数集合。算法用 `bitset` 存储该集合，因此置 $1$ 的位数就是"可能的结果个数"；按 $r=0,1,\dots,K-1$ 扫描置 $1$ 的位输出，天然是升序且不重不漏。证毕。

## 三、模式总结（按实际思考顺序）

1. **识别"一个格子有多个答案"的本质** — 同一格子的乘积不唯一，所以状态是集合而非数值。
2. **用位集存集合** — 余数只有 $K\le100$ 种，`bitset` 天然去重且支持集合运算。
3. **转移是"乘完再取模"** — 枚举前驱余数 $r$，转移 $r\cdot a\bmod K$。
4. **先取模再相乘** — 避免乘法溢出；负数用 `(x%k+k)%k` 归一化。
5. **边界** — 起点初值不能写成 $\{1\}$（漏乘起点格子）；$K=1$ 时所有余数都是 $0$，集合只有 $\{0\}$。
6. **验证方式** — 题面 $2\times3$ 样例可手算三条路径核对；另写 DFS 枚举全部路径的暴力做对拍。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $M,N$ | 棋盘的行数、列数 | `int`，$1\le M,N\le 100$ |
| $K$ | 模数 | `int`，$1\le K\le 100$ |
| $a_{i,j}$ | 格子 $(i,j)$ 的数（代码中已对 $K$ 取模归一化） | `i64[105][105]` |
| $f_{i,j}$ | 走到 $(i,j)$ 时乘积可能取的余数集合 | `bitset<101>` |
| $r$ | 某个前驱格子的可达余数 | `int`，$0\le r<K$ |

### 算法步骤

1. 读入 $M,N,K$ 与整个方阵，每个数用 `(x%k+k)%k` 归一化到 $[0,K)$。
2. 按行优先遍历格子：
   - 若为起点 $(0,0)$，令 $f[0][0]$ 只含 $a_{0,0}$；
   - 否则枚举 $r=0..K-1$：若 $i>0$ 且 $f[i-1][j]$ 含 $r$，则把 $(r\cdot a_{i,j})\bmod K$ 加入 $f[i][j]$；若 $j>0$ 且 $f[i][j-1]$ 含 $r$，同理加入。
3. 统计 $f[M-1][N-1]$ 中置 $1$ 的位数并输出。
4. 按 $r=0..K-1$ 升序输出所有置 $1$ 的余数。

### 复杂度

- 时间复杂度：$O(MNK)$，最大 $10^6$。
- 空间复杂度：$O(MNK)$ 比特，即 $O(MN\cdot K/8)$ 字节，$\le 100\cdot100\cdot16\approx160\text{KB}$。

### 验证状态

- 标程 `P2049.cpp` 用 `g++ -O2 -std=c++17` 编译通过，无警告。
- 题面样例 $M=2,N=3,K=5$，方阵 `3 4 4 / 5 6 6`，输出
  ```
  3
  0 2 3
  ```
  与题面"可求得最后的结果为：$0,2,3$"一致。
- 另写暴力 `P2049_brute.cpp`：DFS 枚举全部向右/向下路径，累乘并对 $K$ 取模，用 `vis[]` 标记可达余数。
- 对拍脚本 `P2049_check.py`：**304 组**用例（300 组随机小网格 $M,N\le4,K\le12$ + 4 组极端：$K=1$、全 $0$、含 $0$、$1\times5$），标程与暴力输出 **0 处不一致**。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2049 魔术棋子
// 思路：DP，每个格子维护「走到这里可能的所有乘积 mod K 的余数集合」
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{105};

int m,n,k;
i64 a[mxn][mxn];
bitset<101> f[mxn][mxn];		// f[i][j]: 走到 (i,j) 后可能的所有余数

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>m>>n>>k;
	for(int i=0;i<m;++i)
		for(int j=0;j<n;++j)
		{
			cin>>a[i][j];
			a[i][j]=(a[i][j]%k+k)%k;		// 先取模，避免乘法溢出
		}
	for(int i=0;i<m;++i)
		for(int j=0;j<n;++j)
		{
			if(i==0&&j==0)
			{
				f[i][j].set((int)a[i][j]);
				continue;
			}
			// 从上方或左方走进来，乘上本格数字
			for(int r=0;r<k;++r)
			{
				if(i>0&&f[i-1][j].test(r)) f[i][j].set((int)(r*a[i][j]%k));
				if(j>0&&f[i][j-1].test(r)) f[i][j].set((int)(r*a[i][j]%k));
			}
		}
	bitset<101> res=f[m-1][n-1];
	int cnt=0;
	for(int r=0;r<k;++r) if(res.test(r)) ++cnt;
	cout<<cnt<<'\n';
	bool first=true;
	for(int r=0;r<k;++r)
		if(res.test(r))
		{
			if(!first) cout<<' ';
			first=false;
			cout<<r;
		}
	cout<<'\n';
	return 0;
}
```

### 代码说明

- 读入后立刻 `(a%k+k)%k` 归一化：既防溢出（后续乘法的两个因子都 $<K\le100$），又处理可能的负数。
- `bitset<101>` 的第 $r$ 位表示余数 $r$ 可达；`test(r)` 查询、`set(r)` 置位，天然完成去重。
- 起点的初值是 $a_{0,0}\bmod K$ 而不是 $1$：棋子初始数为 $1$，进入起点时已经乘上了起点的数。
- 转移里 `i>0` / `j>0` 的判断不能省，否则会读越界或把第 $0$ 行第 $0$ 列的默认值混进来。
- 输出时用 `first` 标志控制空格，避免行首出现多余空格。
