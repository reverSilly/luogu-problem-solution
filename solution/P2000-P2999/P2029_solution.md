# P2029 跳舞 — 题解

## 一、解题过程：人类思考叙事

拿到题目第一反应：这不就是"每个箭头选或不选"嘛，那不就是 $2^N$ 枚举？可是 $N \le 5000$，$2^{5000}$ 显然不可能。

先老老实实读题。题目说"如果踏准次数**累计**达到 $T$，并且是在踏中第 $i$ 个箭头达到的，则将得到 $B_i$ 的奖励分数，累计也将清零，重新开始"。

这里有个容易被样例解释带偏的点。题面【样例解释】写的是"跳过第一个，扣 $1$ 分，**连踩** $3$ 个，得 $9$ 分"，"连踩"两个字很容易让人理解成"必须连续踏中"才算一次累计。但题目正文用的是"**累计**"——累计的是"踏中的总次数"，中间漏掉一个箭头并不会清零，只有真的凑满 $T$ 次才清零。**样例解释是题面作者随手写的口语，不足为据**（这一点在本题的题解区里也是被反复强调的）。

第二个要点：这个 $B_i$ 奖励**不是**"每凑满 $T$ 次就发一次固定的 $B$"，而是"在**第 $i$ 个**箭头上凑满的，那就发**$B_i$**"。也就是说奖励是**依赖位置的**。这解释了题面那句"踏中所有的箭头不一定能得最高分"——因为发奖励的位置会随着你漏掉哪些箭头而改变。

那么状态里必须记两样东西：
1. 已经处理到第几个箭头；
2. 距离上次清零以来，已经累计踏中了多少次。

第 2 样东西取值范围是 $0 \sim T-1$（凑满 $T$ 的瞬间就清零了，所以状态里永远存不到 $T$）。状态数 $N \times T = 5000 \times 5000 = 2.5\times 10^7$，可以做。

转移非常直接。第 $i$ 个箭头只有两种选择：

- **不踏中**：扣 $S_i$，累计次数不变；
- **踏中**：加 $S_i$，累计次数 $+1$；如果这一下正好凑满 $T$，额外加 $B_i$，并且累计次数清零（回到 $0$）。

定义 $f[i][c]$ 表示"处理完前 $i$ 个箭头，当前累计次数为 $c$ 时的最高得分"，则

$$f[i][c]=\max\Big(f[i-1][c]-S_i,\quad f[i-1][c-1]+S_i+[c=0]\cdot B_i\Big)$$

第二个式子里的 $f[i-1][c-1]$ 里 $c-1$ 要循环取值：$c\ge 1$ 时来源是 $c-1$；$c=0$ 时来源是 $T-1$（凑满 $T$ 后清零），并且额外拿 $B_i$。

写完发现 $f$ 是二维的，$5001\times 5001$ 个 `int` 要 100 MB。虽然本题内存限制 125 MB 勉强塞得下，但既然第 $i$ 层只依赖第 $i-1$ 层，**滚动成两个一维数组**就只要 $O(T)$ 空间，性价比极高。

最终答案不要求累计次数归零，所以答案是 $\max_{0\le c<T} f[N][c]$。

至于样例：`N=6, T=3, S=1..6, B=1 1 1 20 1 1`。跳过第 1 个（$-1$），踏中 $2,3,4$（$+9$），踏中第 4 个时累计正好凑满 $3$，拿 $B_4=20$ 并清零；再踏中 $5,6$（$+11$）。合计 $-1+9+20+11=39$，与样例输出一致。

## 二、思维链：完整证明

**引理 1**：踏中与不踏中的选择，与"当前累计次数"一起，构成完整的状态描述。

*证明*：设某个方案处理完前 $i$ 个箭头后，累计次数为 $c$（$0\le c\le T-1$）。考虑第 $i+1$ 个箭头：

- 若不踏中，得分变化为 $-S_{i+1}$，累计次数仍为 $c$；
- 若踏中，得分变化为 $+S_{i+1}$，累计次数先 $+1$；若 $c+1=T$ 则额外 $+B_{i+1}$ 并把计数清零，否则计数变为 $c+1$。

两种转移的得分变化只依赖于 $i$、$c$ 和当前的选择，与之前具体怎么走的完全无关。于是"处理到第几个箭头 + 当前累计次数"是一个 Markov 状态（状态里不需要额外记"上一次拿奖励的时刻"，因为奖励是**当场**发的，不累积）。证毕。

**引理 2**：累计次数在状态中永远只取 $0 \sim T-1$。

*证明*：初始时累计次数为 $0$。按引理 1 的转移，累计次数要么保持不变，要么 $+1$；只有在 $+1$ 的结果等于 $T$ 时，才会立刻被清零为 $0$。因此在任何一个"处理完第 $i$ 个箭头"的时刻观察累计次数，它要么是 $0$，要么是 $1 \sim T-1$ 中的某个值，绝不会是 $T$ 或更大。证毕。

**引理 3**：状态转移方程
$$f[i][c]=\max\Big(f[i-1][c]-S_i,\; f[i-1][(c-1+T)\bmod T]+S_i+[c=0]\cdot B_i\Big)$$
正确，其中当 $c=0$ 时来源状态为 $T-1$ 且需要加 $B_i$，当 $c\ge 1$ 时来源状态为 $c-1$ 且不加 $B_i$。

*证明*：设最优方案在第 $i$ 个箭头上不踏中，则前 $i-1$ 个箭头的累计次数必然也是 $c$，前 $i-1$ 步得分不超过 $f[i-1][c]$，故此类方案最优为 $f[i-1][c]-S_i$。反之若踏中第 $i$ 个箭头：踏中后累计次数变为 $c$，若 $c\ge 1$，说明这次踏中只是把计数从 $c-1$ 变成 $c$，未凑满 $T$（因为凑满会清零成 $0$，见引理 2），故前 $i-1$ 步计数为 $c-1$，得分不超过 $f[i-1][c-1]$，此类最优为 $f[i-1][c-1]+S_i$；若 $c=0$，则前 $i-1$ 步计数必为 $T-1$（本次踏中凑满 $T$ 后清零），且必须加上 $B_i$，此类最优为 $f[i-1][T-1]+S_i+B_i$。

这两类穷尽了第 $i$ 个箭头的全部选择（只有"踏"与"不踏"两种），取较大者即为最优。证毕。

**引理 4**：不踏中某个箭头不会清零累计次数。

*证明*：题目原文中"累计也将清零"的触发条件写得很明确——"如果踏准次数累计达到 $T$……则将得到 $B_i$ 的奖励分数，累计也将清零"。清零的**唯一**触发条件是"累计次数达到 $T$"，而这个条件只在**踏中**某个箭头时才可能被满足（不踏中时累计次数不增）。因此漏掉箭头只会扣分，不会影响累计计数。样例解释中的"连踩"属于口语化的随口一说，与"累计"的正文表述不一致，应以正文为准。证毕。

**引理 5**：答案等于 $\max_{0\le c<T} f[N][c]$。

*证明*：题目不要求游戏结束时累计次数恰好为 $0$，只要求"可得到的最高分数"。任何一个完整方案在处理完 $N$ 个箭头后都会落在某个具体状态 $c$ 上，其得分不超过 $f[N][c]$；而 $f[N][c]$ 本身由合法转移构造出来，是一个可达的合法方案的得分。因此对所有 $c$ 取最大值即为答案。证毕。

**引理 6**：滚动数组实现与二维 DP 等价。

*证明*：第 $i$ 层的每个状态只读取第 $i-1$ 层的状态（引理 3 的转移式中所有来源下标都是 $i-1$ 层）。因此用两个长度为 $T$ 的数组交替存放两层即可，无需保留更早的层。实现时按 $c$ 从大到小更新会读到被覆盖的旧值，故实现采用"读旧层、写新层，再交换指针"的方式，保证每一层内部所有转移都读到同一层的旧值。证毕。

**定理**：算法输出的是可得到的最高分数。

*证明*：由引理 1、2、3，DP 状态完备且转移正确，按归纳法 $f[i][c]$ 恰为对应状态的最优得分；由引理 5，最终取最大即为全局最优；由引理 6，滚动实现与二维 DP 等价。证毕。

## 三、模式总结（按实际思考顺序）

1. **读题先抠字眼** — "累计"不是"连踩"，奖励 $B_i$ 依赖达成位置，两处都在样例解释里被写歪了。
2. **状态设计：把"计数器"写进状态** — $f[i][c]$，$c$ 为距上次清零的累计次数，范围 $0..T-1$。
3. **转移：每步二分（踏/不踏）** — 不踏扣分计数不变；踏加分计数进位，恰好凑满 $T$ 时额外加 $B_i$ 并清零。
4. **循环下标绕圈** — 目标状态 $c=0$ 的来源是 $T-1$，这是"凑满清零"在转移式里的体现。
5. **滚动数组降空间** — 层间只依赖上一层，$O(NT)$ 时间换 $O(T)$ 空间。
6. **答案在状态集合上取最大** — 结束时不要求计数器归零。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 范围 |
|------|------|------|
| $N$ | 箭头总数 | `int`，$\le 5000$ |
| $T$ | 触发一次奖励所需的累计踏中次数 | `int`，$\le 5000$ |
| $S_i$ | 踏中第 $i$ 个箭头得分 $S_i$，不踏中扣 $S_i$ | `int`，$[0,10000]$ |
| $B_i$ | 在第 $i$ 个箭头上凑满 $T$ 次时额外获得的奖励 | `int`，$[0,10000]$ |
| $c$ | 距上次清零以来已累计踏中的次数 | `int`，$0\le c<T$ |
| $f[i][c]$ | 处理完前 $i$ 个箭头、累计次数为 $c$ 的最高得分 | `i64` |
| `cur` / `nxt` | 滚动数组，分别存上一层与当前层 | `i64[]`，长度 $T$ |
| `inf` | 不可达状态的哨兵值 | `i64`，$-1145141919$ |

### 算法步骤

1. 读入 $N, T$、数组 $S$、数组 $B$。
2. 若 $T=0$：累计奖励永不触发（计数加一后不可能等于 $0$），且 $S_i\ge 0$，最优为踏中所有箭头，答案 $=\sum S_i$，直接输出。
3. 初始化滚动数组：`cur[0]=0`，`cur[1..T-1]=inf`（不可达）。
4. 对 $i=1,2,\dots,N$：
   - 对每个 $c\in[0,T-1]$ 计算 `nxt[c]`：
     - **不踏**：若 `cur[c]` 可达，则 `nxt[c] = cur[c] - S[i]`；
     - **踏**：来源 `pc = (c==0 ? T-1 : c-1)`，若 `cur[pc]` 可达，则 `nxt[c] = cur[pc] + S[i]`，且当 $c=0$（即由 $T-1$ 凑满清零）时再加上 `B[i]`；
     - 两者取较大值。
   - 交换 `cur` 与 `nxt`。
5. 在 `cur[0..T-1]` 中取最大值并输出。

### 复杂度

- 时间复杂度：$O(N\cdot T)$，最多 $2.5\times 10^7$ 次常数转移。
- 空间复杂度：$O(T)$（外加读入的 $S,B$ 两个数组，共 $O(N+T)$）。

### 验证状态

- 标程 `P2029.cpp` 用 `g++ -O2 -std=c++17` 编译通过。
- 题面样例 `6 3 / 1 2 3 4 5 6 / 1 1 1 20 1 1` 输出 `39`，与官方一致。
- 编写暴力 `P2029_brute.cpp`（DFS 枚举全部 $2^N$ 种踏/不踏方案，独立实现计数与清零逻辑）与对拍脚本 `P2029_check.py`，在 $N\le 12$、$T\in[0,6]$、$S,B\in[0,10000]$ 的随机数据上对拍 **3000 组全部通过**。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2029 跳舞
// 累计计数模型：计数 c 表示"距上次清零以来已踏中的次数"，取值 0..T-1
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{5005};
constexpr i64 inf{-1145141919};

int n,T,s[mxn],b[mxn];
i64 f[2][mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>T;
	for(int i=1;i<=n;++i) cin>>s[i];
	for(int i=1;i<=n;++i) cin>>b[i];

	if(T<=0)	// T=0 时累计奖励永不触发，把所有箭头都踏中即可
	{
		i64 ans=0;
		for(int i=1;i<=n;++i) ans+=s[i];
		cout<<ans<<'\n';
		return 0;
	}

	// f[cur][c]: 已处理完前若干箭头、累计计数为 c 时的最大得分
	i64*cur=f[0],*nxt=f[1];
	fill(cur,cur+T,inf);
	cur[0]=0;
	for(int i=1;i<=n;++i)
	{
		for(int c=0;c<T;++c)
		{
			i64 best=inf;
			if(cur[c]!=inf) best=cur[c]-s[i];		// 不踏中：扣分，计数不变
			int pc=(c==0?T-1:c-1);				// 踏中转移的来源计数
			if(cur[pc]!=inf)
			{
				i64 v=cur[pc]+s[i];
				if(c==0) v+=b[i];				// 由 T-1 触顶 -> 计数清零并给 B_i
				best=max(best,v);
			}
			nxt[c]=best;
		}
		swap(cur,nxt);
	}
	i64 ans=inf;
	for(int c=0;c<T;++c) ans=max(ans,cur[c]);
	cout<<ans<<'\n';
	return 0;
}
```

### 代码说明

- `f[2][mxn]` 是滚动的两层，`i64*cur` / `i64*nxt` 两个指针在每层结束后 `swap`，避免每层 `memcpy`。
- 哨兵 `inf` 取负值 $-1145141919$，与"得分上界 $\le 5000\times 10000 + 5000\times 10000$"相比足够小，可安全用 `cur[c]!=inf` 判断可达。
- 注意 `if(c==0) v+=b[i];` 这一行的含义：当来源计数是 $T-1$ 时，这次踏中恰好凑满 $T$，触发奖励并清零。
- 全程使用 `'\n'` 而非 `endl`；`main` 以 `return 0;` 正常结束。
