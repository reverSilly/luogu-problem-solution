# P2256 一中校运会之百米跑 — 题解

## 一、解题过程：人类思考叙事

题意：有 $N\le 2\times 10^4$ 个选手，名字长度不超过 $20$。给出 $M\le 10^6$ 句话，每句说“学生 A 与学生 B 在同一组”；又给出 $K\le 10^6$ 次询问，问学生 X 与学生 Y 是否在同一组。同一组的关系满足：A 与 B 同组、B 与 C 同组，则 A 与 C 同组。输出 `Yes.` 或 `No.`。

第一反应是把它看成图：每个选手是一个点，每句“A 与 B 同组”是一条无向边，那么“在同一组”就是**连通**。因为题目明确给了传递性（A-B、B-C 推出 A-C），而“同组”也是自反的（自己与自己同组）、对称的（语句中的 A、B 无序）——它正是这些边生成的等价关系，也就是连通关系。

最暴力的做法：每次询问从 X 出发做一次 BFS/DFS，看能否到 Y。单次 $O(N+M)$，$K$ 次就是 $O(K(N+M))$，最坏 $10^6\times 10^6=10^{12}$，完全不可行。

退一步：所有边在询问之前就全部给出了，可以先把图建出来，做一次 BFS/DFS 给每个点标连通块编号，之后每次询问 $O(1)$。这个方案是可行的：$N=2\times 10^4$，$M=10^6$，邻接表存 $2M$ 条有向边，约 $8$ MB，时间 $O(N+M+K)$ 也能过。但它需要把 $10^6$ 条边全部存下来，而且“连通块编号”是一次性批处理，无法处理边逐步加入的情形。

再想一层：我们其实**不需要知道路径，只需要知道两个点是否被合并**。每读到一句“A 与 B 同组”，就是把 A 所在集合与 B 所在集合合并。这正是并查集（DSU）的拿手场景：支持合并两个集合、查询两个元素是否在同一集合，均摊代价极小，空间只要 $O(N)$，还不需要存边。于是选择并查集，边读边合并，询问时比较两个根即可。

接下来是字符串问题：并查集的下标必须是整数，而输入是名字。用一个哈希表把每个名字映射到 $0,\dots,N-1$ 的编号。题目保证所有出现在语句和询问中的名字都在前 $N$ 行里，所以映射一定存在。$M+K$ 可达 $2\times 10^6$，每次查询要做两次字符串哈希查找，必须用较快的 `unordered_map` 并预留桶数。

实现上的坑：

1. **输入量极大**：$M,K\le 10^6$，共约 $4\times 10^6$ 个字符串，必须关闭流同步。
2. **输出格式**：是 `Yes.` 和 `No.`，注意末尾的英文句号，每行一个。
3. **自环与重边**：可能出现 `A A` 或重复的 `A B`，并查集合并同一集合时直接返回即可，不影响正确性。
4. **单组数据**：本题只有一组，不需要多测清空；初始化时把每个 $f[i]$ 设为自己、$sz[i]$ 设为 $1$。
5. **名字可能重复吗**：题面说“$N$ 个选手的名字”，通常保证互不相同；若真有重名，用名字映射会把它们视为同一个学生，这与“名字代表学生”的语义一致。
6. **递归深度**：只做路径压缩、不做按大小合并时树高可能到 $N$；代码同时用了按大小合并，树高 $O(\log N)$，递归 `getrt` 深度不超过约 $15$，绝对安全。

本地题面没有样例，我手造了三组（见第五节），覆盖传递闭包、对称询问和自环。

## 二、思维链：完整证明

### 约定

把 $N$ 个选手看成顶点集 $V=\{0,\dots,N-1\}$，$M$ 句“A 与 B 同组”看成无向边集 $E$。两个顶点**连通**指存在一条由 $E$ 中边组成的路径把它们连起来（允许长度为 $0$ 的路径，即自己到自己）。

**引理 1（同组 = 连通）**：两名选手在同一组，当且仅当他们在图 $(V,E)$ 中连通。

*证明*：两个方向。

- **连通 ⇒ 同组**：设 $x=v_0,v_1,\dots,v_\ell=y$ 是一条路径，每条边 $(v_{i-1},v_i)\in E$ 都对应一句“$v_{i-1}$ 与 $v_i$ 同组”。对路径长度 $\ell$ 归纳：$\ell=0$ 时 $x=y$，自己与自己同组；设 $\ell-1$ 时 $v_0$ 与 $v_{\ell-1}$ 同组，又 $v_{\ell-1}$ 与 $v_\ell$ 同组，由题面给出的传递性，$v_0$ 与 $v_\ell$ 同组。
- **同组 ⇒ 连通**：定义关系 $\sim$ 为“图中连通”。它是等价关系：自己到自己有长度为 $0$ 的路径（自反）；一条路径反向走仍是路径（对称）；两条首尾相接的路径拼接仍是路径（传递）。并且每条边 $(u,v)\in E$ 都满足 $u\sim v$（长度为 $1$ 的路径）。题目中的“同组”是满足“每条边两端同组”的**最小**等价关系：题面规则只允许从这些边出发反复使用自反、对称、传递，因此任何由规则推出的“同组”结论，在任何包含全部边的等价关系中都成立；而 $\sim$ 正是这样一个等价关系，所以由规则推出的每一对都满足 $\sim$。即“同组”包含于 $\sim$，同组 ⇒ 连通。

两个方向合起来即得。证毕。

**引理 2（路径压缩不改变划分）**：`getrt(x)` 返回 $x$ 所在树的根，并把 $x$ 到根路径上的每个结点的父指针直接改成根；这一操作不改变任何结点所在树的根，因此不改变“根相同”这一等价关系。

*证明*：对 `getrt` 的递归结构归纳。若 `f[x]==x`，$x$ 就是根，返回 $x$，无修改。否则递归得到 `r=getrt(f[x])`，它是 $x$ 的父结点所在树的根，也就是 $x$ 所在树的根；随后令 `f[x]=r`。路径上其余结点由递归同理被指向同一个根 $r$。所有被修改的结点原本就以 $r$ 为根，修改后仍以 $r$ 为根；其他结点不受影响。故每个结点的根不变，“根相同”关系不变。证毕。

**引理 3（并查集不变量）**：在处理完前 $t$ 条边后，对任意 $x,y$，`getrt(x)==getrt(y)` 当且仅当 $x,y$ 在前 $t$ 条边构成的图中连通。

*证明*：对 $t$ 归纳。

**基始 $t=0$**：没有边，每个结点初始 `f[i]=i`，各自成树。$x,y$ 连通当且仅当 $x=y$，而此时根相同也当且仅当 $x=y$，成立。

**归纳步**：设前 $t-1$ 条边满足不变量，加入第 $t$ 条边 $(u,v)$，令 $r_u=\text{getrt}(u)$、$r_v=\text{getrt}(v)$。

- 若 $r_u=r_v$：由归纳假设 $u,v$ 已连通，新边在同一个连通块内部，连通关系不变；代码直接返回，并查集也不变，不变量继续成立。
- 若 $r_u\ne r_v$：记两个旧连通块为 $A$（根 $r_u$）与 $B$（根 $r_v$）。代码按大小合并，把其中一个根的父亲设为另一个根。合并后，$A\cup B$ 中所有结点的根都等于合并后的新根；$A\cup B$ 之外结点的根不变。于是对任意 $x,y$：
  - 若 $x,y$ 都在 $A$ 内或都在 $B$ 内：合并前根相同，合并后它们的根一起变成新根，仍相同；在新图中它们当然仍连通。
  - 若 $x,y$ 一个在 $A$、一个在 $B$：合并后根相同；在新图中，$x$ 沿旧路径走到 $u$，经新边到 $v$，再沿旧路径走到 $y$，确实连通。
  - 若 $x,y$ 中至少一个不在 $A\cup B$：设 $x\notin A\cup B$，则 $x$ 的根在合并前后不变，且不等于新根；若 $y\in A\cup B$，则 $y$ 的根是新根，与 $x$ 不同，新图中 $x$ 与 $y$ 也不连通（新边只在 $A\cup B$ 内部连接）；若 $y\notin A\cup B$，则两者的根是否相同与合并前完全一致，而新边只连接 $A,B$，不会产生通向外部的新路径，连通性也不变。

  三种情况合起来，合并后的“根相同”恰好等于新图的连通关系。

由归纳，不变量对所有 $t$ 成立。证毕。

**引理 4（查询正确）**：处理完所有 $M$ 条边后，对每个询问 $(X,Y)$，输出 `Yes.` 当且仅当 $X,Y$ 同组。

*证明*：由引理 3（$t=M$），`getrt(X)==getrt(Y)` 当且仅当 $X,Y$ 在完整图中连通；由引理 1，连通当且仅当同组。代码正是比较两个根，故输出正确。证毕。

**引理 5（树高与复杂度）**：采用按大小合并时，任意时刻树高不超过 $\lfloor\log_2 N\rfloor$；路径压缩不会增加树高。因此单次 `getrt` 为 $O(\log N)$，总时间 $O\bigl((N+M+K)\log N\bigr)$（不计哈希表），空间 $O(N)$。

*证明*：先证按大小合并的树高界。对每个结点 $x$，记其所在子树大小为 $s(x)$。初始每个结点是大小为 $1$ 的根。只有当 $x$ 所在树的根被挂到另一个根下时，$x$ 的深度才增加 $1$；按大小合并保证新父亲所在树的大小不小于 $x$ 所在树的大小，故合并后 $x$ 所在树大小至少翻倍。树大小不超过 $N$，所以 $x$ 的深度最多增加 $\lfloor\log_2 N\rfloor$ 次，树高不超过 $\lfloor\log_2 N\rfloor$。路径压缩只把结点向上提，不会让任何结点的深度增加，故树高界保持。每次 `getrt` 沿树向上走，最多 $O(\log N)$ 步；每次合并两次 `getrt`；$K$ 次询问各两次 `getrt`。字符串哈希查找期望 $O(1)$，共 $N+M+K$ 次左右。故总时间 $O((N+M+K)\log N)$，空间为并查集数组与名字表 $O(N)$。证毕。

**定理**：算法对所有询问输出正确答案，复杂度如上。

*证明*：由引理 4 查询正确；由引理 5 复杂度成立。证毕。

## 三、模式总结（按实际思考顺序）

- **explore its property** — “同组”是自反、对称、传递的等价关系，由 $M$ 句pairwise 语句生成。
- **reduce to easier problem** — 把选手看成点、语句看成无向边，“同组”化为“连通”。
- **consider easier version** — 先想每次询问 BFS（太慢），再想离线建图一次 BFS 标连通块（可行但要存 $10^6$ 条边）。
- **classic problem solution** — 并查集维护增量连通性：边读边合并，查询比较根。
- **prove the data structure** — 对合并次数归纳证明“根相同 = 连通”，并用按大小合并证明树高 $O(\log N)$。
- **engineering** — 名字用 `unordered_map` 映射为整数；$10^6$ 级 I/O 关闭流同步。
- **boundary discipline** — 自环/重边直接合并；输出带英文句号的 `Yes.` / `No.`；单组数据无需清空。

## 四、解法说明

### 符号表

| 符号 | 含义 | 类型 / 初值 |
|------|------|-------------|
| $N$ | 选手数 | `int`，输入 |
| $M$ | “同组”语句数 | `int`，输入 |
| $K$ | 询问数 | `int`，输入 |
| `f[i]` | 并查集中 $i$ 的父结点 | `int[mxn]`，初值 `f[i]=i` |
| `sz[i]` | 以 $i$ 为根的集合大小（仅根有意义） | `int[mxn]`，初值 $1$ |
| `id` | 名字到 $0..N-1$ 编号的哈希表 | `unordered_map<string,int>` |
| `getrt(x)` | 返回 $x$ 的根，路径压缩 | 递归函数 |
| `unite(u,v)` | 合并 $u,v$ 所在集合（按大小） | 函数 |

### 算法步骤

1. 关闭流同步，读入 $N,M$。
2. 读入 $N$ 个名字，建立 `id[name]=i`，并初始化 `f[i]=i, sz[i]=1`。
3. 读入 $M$ 条语句，每条形如 `A B`：
   1. 用 `id` 取得编号 $u,v$；
   2. `unite(u,v)`：求两个根，若相同则返回；否则把较小的树挂到较大的树下，并更新大小。
4. 读入 $K$，对每个询问 `X Y`：
   1. 取得编号 $u,v$；
   2. 若 `getrt(u)==getrt(v)` 输出 `Yes.`，否则输出 `No.`，每行一个。
5. 结束。

### 复杂度

- 时间复杂度：$O\bigl((N+M+K)\log N\bigr)$（并查集按大小合并 + 路径压缩；哈希查找期望 $O(1)$）。
- 空间复杂度：$O(N)$（并查集、名字表）。

### 验证状态

- 使用 `/d/mingw64/bin/g++.exe -std=c++20 -O2` 编译通过，无错误。
- 本地题面无样例，手造并跑通 3 组：
  - 4 人、`Alice-Bob`、`Bob-Carol`、`Dave-Dave`，询问 `Alice Carol` / `Alice Dave` / `Carol Bob` → `Yes.` / `No.` / `Yes.`；
  - 2 人、`x-y`，询问 `x y` / `y x` → `Yes.` / `Yes.`；
  - 2 人、`x-x`，询问 `x y` → `No.`。
- 与“每次询问重建图并 BFS”的暴力对拍 300 组随机数据（$N\le 10$，含自环、重边），输出完全一致。

## 五、示例代码（C++，Louis Li 风格）

```cpp
// 题目：P2256 一中校运会之百米跑
// 思路：同组 = 无向图连通；边读边用并查集合并
//       名字用 unordered_map 映射为 0..n-1
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{20005};

int n,m,k,f[mxn],sz[mxn];
unordered_map<string,int> id;

int getrt(int x)
{
	if(f[x]==x)
		return x;
	return f[x]=getrt(f[x]);
}

void unite(int u,int v)
{
	int ru=getrt(u),rv=getrt(v);
	if(ru==rv)
		return;
	if(sz[ru]<sz[rv])
		swap(ru,rv);
	f[rv]=ru;
	sz[ru]+=sz[rv];
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>m;
	id.reserve(n*2);
	for(int i=0;i<n;++i)
	{
		string s;
		cin>>s;
		id[s]=i;
		f[i]=i;
		sz[i]=1;
	}
	for(int i=0,u,v;i<m;++i)
	{
		string a,b;
		cin>>a>>b;
		u=id[a];v=id[b];
		unite(u,v);
	}
	cin>>k;
	for(int i=0;i<k;++i)
	{
		string a,b;
		cin>>a>>b;
		cout<<(getrt(id[a])==getrt(id[b])?"Yes.\n":"No.\n");
	}
	return 0;
}
```

### 代码说明

- `getrt` 递归 + 路径压缩；`unite` 先求根，相同则直接返回，否则按 `sz` 把小树挂到大树下。
- 字符串只在读入时查一次哈希表；同组语句和询问各自做两次查找。
- `id.reserve(n*2)` 预留桶数，避免 $2\times 10^6$ 次查找中反复 rehash。
- 输出直接使用三目表达式，注意字符串是 `"Yes.\n"` 与 `"No.\n"`，带句号。
- 单组数据，不需要 `memset`；`f` 与 `sz` 在读到名字时逐个初始化。
