# P1032 字串变换 题解

---

## 一、发现叙事

打开题目，映入眼帘的是一个字串变换问题。给定起始串 $A$ 和目标串 $B$，以及至多 6 条变换规则 $A_i\to B_i$，每次将当前串中 **任意一处** 匹配的 $A_i$ 替换为 $B_i$，问最少几步能在 10 步以内将 $A$ 变成 $B$。

数据范围极小：串长 $\le 20$，规则 $\le 6$，步数上限 $10$。直觉告诉我们——这就是一个搜索问题。

第一反应是朴素的 BFS：从 $A$ 出发，每一步枚举所有规则、所有匹配位置，生成新串，入队。步数上限只有 10，状态空间似乎可控。但仔细一想，每次变换后串长可能增加（例如样例中 `abc→xu` 从 3 变 2，`y→yz` 从 1 变 2），扩散速度可能指数级增长。最坏情况下每一步都可能产生大量新串，10 层 BFS 可能炸掉内存。

那 DFS 加迭代加深（IDDFS）呢？每次限制深度，逐层加深，避免了 BFS 的队列膨胀，但有大量重复搜索。10 层尚可接受，但字符串替换每次都要扫描匹配，常数不小。

再想——步数上限是 10，如果我们从起点搜 5 步，从终点搜 5 步（反向搜索），然后在中间相遇，就能把复杂度从 $O(b^{10})$ 降到 $O(b^5 + b^5)$，这是一个巨大的优化。这就是 **双向 BFS（meet in the middle）**。

问题在于反向搜索怎么做？正规则是 $A_i\to B_i$，反向规则就是 $B_i\to A_i$：在串中找到 $B_i$ 并替换回 $A_i$。注意反向替换可能有歧义——同一个 $B_i$ 可能在串中出现多次，和正向一样要枚举所有出现位置。

现在方案清晰了：

1. 读入 $A,B$ 和所有规则 $(a_i,b_i)$。
2. 正向队列从 $A$ 出发，步数上限 5，记录每个可达状态及其步数。
3. 反向队列从 $B$ 出发，步数上限 5，记录每个可达状态及其步数。
4. 一旦某个状态在正反向都被访问到，答案 = 正向步数 + 反向步数，输出并结束。
5. 若双向均搜索完仍未相遇，输出 `NO ANSWER!`。

这就是本题的标准解法。下面我们深入讨论正确性和细节。

## 二、思维链与完整证明

### 2.1 问题建模

**定义 1（状态）**。一个状态是一个字符串 $s$，表示当前变换得到的中间串。

**定义 2（转移）**。对于规则 $a_i\to b_i$，若 $s$ 中存在子串等于 $a_i$，设 $s = p + a_i + q$，则一步转移得到 $s' = p + b_i + q$。一个规则在一次转移中只作用于 **一个匹配位置**（最左匹配或全部匹配？题目说"在 A 中的子串 $A_1$ 可以变换为 $B_1$"，没有指定位置策略，所以我们需要枚举所有出现位置）。

**定义 3（步数）**。从 $A$ 到 $B$ 所需的最少转移次数，记作 $\text{dist}(A,B)$。若无法在 10 步内到达，输出 `NO ANSWER!`。

### 2.2 BFS 正确性

BFS 在无权图上按层扩展，首次访问目标时一定得到最短路径。本题的状态图是一个隐式图（状态由字符串隐式定义，边由规则生成），BFS 的正确性由图的广度优先遍历性质保证。

**引理 1**。若存在从 $A$ 到 $B$ 的变换路径，BFS 一定找到最短的那一条。

> **证明**。BFS 按距离源点的层数逐层扩展，设 $d(s)$ 为 BFS 首次访问 $s$ 时的步数，则 $d(s)$ 就是 $A$ 到 $s$ 的最短步数。这是因为队列中所有距离为 $k$ 的状态一定在距离为 $k+1$ 的状态之前被取出扩展。当 $B$ 被首次出队时，$d(B)$ 即为最短步数。$\square$

### 2.3 双向 BFS 正确性

**定义 4（正向搜索）**。从 $A$ 出发，应用正规则 $a_i\to b_i$，搜索深度 $\le 5$。记 $F(s)$ 为正向搜索到达 $s$ 的最少步数。

**定义 5（反向搜索）**。从 $B$ 出发，应用逆规则 $b_i\to a_i$，搜索深度 $\le 5$。记 $G(s)$ 为反向搜索到达 $s$ 的最少步数。

**定理 1**。若存在某个状态 $s$ 使得 $F(s)$ 和 $G(s)$ 均有定义，则存在一条从 $A$ 到 $B$ 的变换路径，长度为 $F(s)+G(s)$，且该长度不超过 10。

> **证明**。由正向搜索可知，存在路径 $A \xrightarrow{F(s)} s$；由反向搜索可知，存在路径 $s \xrightarrow{G(s)} B$（反向路径反转后即得到 $s\to B$ 的路径）。拼接得到 $A\to s\to B$，长度为 $F(s)+G(s)$。两条路径各自的步数均在 $\le 5$ 的约束下找到，因此总长 $\le 10$。$\square$

**定理 2（双向 BFS 的最优性）**。若 $A$ 到 $B$ 的最短路径长度 $L \le 10$，则双向 BFS 一定能找到某个相遇状态 $s$，且 $F(s)+G(s) = L$。

> **证明**。设最短路径为 $A = s_0 \to s_1 \to \cdots \to s_L = B$。取 $k = \lfloor L/2 \rfloor$，考虑状态 $s_k$。正向搜索深度 5 $\ge k$（因为 $k \le 5$），所以 $F(s_k)$ 有定义且等于 $k$（BFS 的最短路径性质）。反向搜索深度 5 $\ge L-k$（因为 $L-k \le 5$），所以 $G(s_k)$ 有定义且等于 $L-k$。因此 $s_k$ 是一个相遇点，且 $F(s_k)+G(s_k) = k + (L-k) = L$。$\square$

**推论**。双向 BFS 的搜索空间上界为 $O(b^5)$，其中 $b$ 为分支因子（每次转移可能生成的状态数），而朴素 BFS 为 $O(b^{10})$。

### 2.4 反向规则的一致性

反向搜索时需要逆用规则：对每个 $(a_i,b_i)$，定义逆规则为 $b_i \to a_i$。但这里有一个潜在陷阱：

设正向规则 $abc \to xu$，则逆规则为 $xu \to abc$。如果 $B$ 中同时出现了 $xu$ 和 $abc$，反向搜索时只关心 $xu$ 的出现位置，将其替换回 $abc$。这完全模拟了正向过程的逆操作，是正确的。

但需要注意的是：多个规则可能映射到相同的 $b_i$，即存在 $a_1\to c$ 和 $a_2\to c$。此时反向搜索遇到 $c$ 时，需要同时尝试替换回 $a_1$ 和 $a_2$，两者都是可能的。我们的算法在枚举规则时自然会处理这一点。

### 2.5 剪枝与优化

**剪枝 1（深度限制）**。正向 $\le 5$，反向 $\le 5$，这是算法的核心。

**剪枝 2（字符串长度剪枝）**。若当前串长度已经超过 $|B|$ 且所有正向规则都使长度增加（或所有反向规则都使长度减少），可以剪枝。但数据范围小，这个非必需。

**剪枝 3（去重）**。使用 `unordered_map<string,int>` 或 `map<string,int>` 记录已访问状态，避免重复扩展。这是 BFS 的标准剪枝。

**优化 1（双向扩展的调度）**。每次选择队列较小的方向进行扩展，减少总状态数。

**优化 2（字符串处理）**。使用 `string::find` 的第二个参数（起始位置）枚举所有匹配位置，简洁高效。

## 三、模式总结

本题展示了以下重要的算法模式：

### 模式 1：双向 BFS（Meet in the Middle）

当搜索深度固定且较小时（本题 $\le 10$），将搜索一分为二，从起点和终点同时搜索，在中点相遇，将指数复杂度开方。

**适用条件**：
- 搜索深度有明确上限
- 状态空间随深度指数增长
- 已知目标状态
- 变换可逆（或可定义逆变换）

### 模式 2：字符串替换的状态搜索

在字符串上应用规则进行变换的搜索问题，关键操作是：
- 枚举所有规则
- 对每条规则，枚举所有匹配位置
- 使用 `find(pos+1)` 或 `find` + 循环来遍历所有出现

### 模式 3：反向搜索

当规则可逆时（将规则左右互换），从目标状态反向搜索可以同时获得正向和反向的路径。注意逆规则可能不是唯一的（多个正向规则映射到同一个右部）。

## 四、解法与符号表

### 符号表

| 符号 | 含义 |
|------|------|
| $A$ | 起始字符串 |
| $B$ | 目标字符串 |
| $n$ | 变换规则的数量 |
| $a_i$, $b_i$ | 第 $i$ 条规则：$a_i\to b_i$ |
| $F(s)$ | 正向 BFS 中 $A$ 到 $s$ 的最短步数 |
| $G(s)$ | 反向 BFS 中 $B$ 到 $s$ 的最短步数 |
| $Q_f$ | 正向 BFS 队列 |
| $Q_b$ | 反向 BFS 队列 |
| $M_f$ | 正向访问记录（状态 → 步数） |
| $M_b$ | 反向访问记录（状态 → 步数） |

### 算法步骤

```
输入 A, B
读入规则序列 (a_i, b_i) 直到 EOF
n = 规则数

初始化:
  Q_f = {A}, M_f[A] = 0
  Q_b = {B}, M_b[B] = 0

for step = 1 to 5:
    // 扩展正向一层
    for each s in Q_f (当前层的所有状态):
        for each 规则 i:
            for each 匹配位置 p of a_i in s:
                t = s 中替换 a_i 为 b_i
                if t not in M_f:
                    M_f[t] = step
                    将 t 加入下一层队列
                if t in M_b:
                    return step + M_b[t]
    
    // 扩展反向一层
    for each s in Q_b (当前层的所有状态):
        for each 规则 i:
            for each 匹配位置 p of b_i in s:
                t = s 中替换 b_i 为 a_i
                if t not in M_b:
                    M_b[t] = step
                    将 t 加入下一层队列
                if t in M_f:
                    return step + M_f[t]

return "NO ANSWER!"
```

### 时间复杂度

- 每个状态扩展时，枚举 $n\le 6$ 条规则，每条规则在串长 $\le 20$ 内找匹配，$O(n\cdot |s|)$。
- 状态数受限于 $b^5$，$b$ 为平均分支因子（实践中远小于理论值）。
- 总复杂度 $O(2 \cdot b^5 \cdot n \cdot L)$，其中 $L\le 20$ 为串长。
- 在最坏数据下也能在毫秒级完成。

### 空间复杂度

- 存储访问过的状态数和队列，每个状态为一个字符串和整数步数。
- 上界约 $O(b^5)$，实际最多几千到几万个状态，完全可接受。

## 五、C++ 代码

```cpp
#include<bits/stdc++.h>
using namespace std;

string A,B,a[10],b[10];
int n;

int bfs()
{
	queue<string>qf,qb;
	unordered_map<string,int>mf,mb;
	qf.push(A);mf[A]=0;
	qb.push(B);mb[B]=0;
	while(!qf.empty()&&!qb.empty())
	{
		// extend forward
		{
			int sz=qf.size();
			while(sz--)
			{
				string s=qf.front();qf.pop();
				int d=mf[s];
				if(d>=5)
					break;
				for(int i=0;i<n;++i)
				{
					int p=0;
					while((p=(int)s.find(a[i],p))!=-1)
					{
						string t=s;
						t.replace(p,a[i].size(),b[i]);
						if(mb.count(t))
							return d+1+mb[t];
						if(!mf.count(t))
						{
							mf[t]=d+1;
							qf.push(t);
						}
						++p;
					}
				}
			}
		}
		// extend backward
		{
			int sz=qb.size();
			while(sz--)
			{
				string s=qb.front();qb.pop();
				int d=mb[s];
				if(d>=5)
					break;
				for(int i=0;i<n;++i)
				{
					int p=0;
					while((p=(int)s.find(b[i],p))!=-1)
					{
						string t=s;
						t.replace(p,b[i].size(),a[i]);
						if(mf.count(t))
							return d+1+mf[t];
						if(!mb.count(t))
						{
							mb[t]=d+1;
							qb.push(t);
						}
						++p;
					}
				}
			}
		}
	}
	return -114514;
}

int main()
{
	cin.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>A>>B;
	string x,y;
	while(cin>>x>>y)
	{
		a[n]=x;b[n]=y;
		++n;
	}
	int ans=bfs();
	if(ans==-114514||ans>10)
		cout<<"NO ANSWER!\n";
	else
		cout<<ans<<'\n';
	return 0;
}
```

### 关键细节说明

- **`find` 的起始终止**：`(int)s.find(a[i],p)` 的返回值强制转为 `int`，因为 `string::npos` 在比较时若 `p` 为 `-1` 会出问题。`string::npos` 的值是 `size_t(-1)`，与 `(int)-1` 相等，比较 `!= -1` 即可。

- **`++p` 的技巧**：找到匹配后从 `p+1` 继续搜索，防止死循环。这确保同一位置不会被重复匹配，也允许重叠匹配（如 `"aaa"` 中匹配 `"aa"` 会找到位置 0 和 1）。

- **深度限制**：`if(d>=5) break;`——当前层全部处理完后队列中剩余的当前层状态不再扩展（这些状态的 BFS 距离也是 5，已经达到边界）。注意这里 `d` 是出队状态的距离，如果 `d==5`，这一步扩展出的新状态距离为 6，超出了 5 的上限。

- **边界情况**：`A` 和 `B` 初始相等时，正向 BFS 初始化 `mf[A]=0`，反向 BFS 初始化 `mb[B]=0`，两轮扩展前不会相遇。但我们可以在 BFS 前单独判断 `if(A==B)` 直接输出 `0`。不过题目从样例看至少需要 1 步的变换才计数，且 `A\neq B$` 为一般情况，可以不加这个特判。更稳妥的是在 BFS 开始时检查队列是否包含对方记录。实际上本实现中若 $A=B$，第一次正向扩展前检查 `mb.count(A)` 会发现 $A$ 在反向记录中，返回 `0+0=0$`。但在循环结构里，第一次 while 迭代的正向扩展中 `mb.count(t)` 检查的 `t` 是扩展后的新状态，不会检查初始状态。**因此需要特判 `A==B` 输出 `0`**。我们可以在 BFS 函数开头加入：

    ```cpp
    if(A==B)return 0;
    ```

- **反向替换的正确性**：反向搜索时，我们在当前串 $s$ 中寻找 $b_i$ 出现的位置，将其替换为 $a_i$。这恰好是正向操作的逆过程。

- **队列调度**：本实现简单地轮流扩展正向和反向各一层，没有采用"优先扩展小队列"的优化。对于本题数据规模，这完全足够。

---

*本题是双向 BFS 的经典入门题。虽然 10 步的限制让单向 BFS 在弱数据下也能通过，但双向 BFS 的思想具有普遍意义——当你能同时从起点和终点搜索时，永远不要只从一个方向搜到底。*
