# P1555 尴尬的数字 Awkward Digits B

> 标签：模拟 · 数学 · 枚举 · 进制 · 2011 · USACO · 难度：普及/提高-
> 本地题面：`statement/P1000-P1999/P1555.md`（$N\le10^9$；两行输入——各错一位的二进制、三进制表示；保证解存在且唯一）。
> 验证：`appendix/P1555/` 官方样例 `1010`/`212` → `14` 通过；3800 组随机数据 + 30 组 20 位抽查，标程与「按定义枚举」暴力逐字节一致；8 个手工核验边界用例（含 $N=0$、前导零输入、两组假配对陷阱）；最坏规模 $N=10^9$（二进制 30 位 / 三进制 19 位）实测 **0.65~0.85 ms**（含进程启动）。

## 1. 重新读题

**问题重述（人话版）**

Bessie 把整数 $N$ 分别转成二进制和三进制，但每次都会恰好写错一位数字，而且不会多写或少写任何一位。给出这两个写错的串，还原 $N$（十进制输出）。

> 一句话版本：**两个各错一位、位数不变的串，交给出唯一的公共真值。**

**题面里容易漏掉的条款**

1. 「总会写错**一位**数字」——是**恰好**一位，不是"至多一位"。两个串各自恰好错一位，不存在"某一侧其实全对"的情况。
2. 「从不会意外地增加或删减数字」——**位数锁定**！真值的二进制表示长度 = 第一行长度 $l_b$，三进制表示长度 = 第二行长度 $l_t$。这是整道题最重要的杠杆：它把无界的还原问题变成"每位只有几种改法"的枚举。
3. 「可能会写出以 `0` 开头的错误数字」——**输入可以有前导零**（错位恰在首位时，如 $14=$ `1110` 被写成 `0110`）。所以既不能把输入当成标准表示，也不能顺手 strip 掉前导零（见 §2.5）。
4. 「$N$ 可能会达到 $10^9$」——$2^{30}=1073741824>10^9$，故 $l_b\le30$；$3^{19}=1162261467>10^9\ge3^{18}$，故 $l_t\le19$。两侧候选总数 $\le l_b+2l_t\le30+38=68$，双重循环求交足够——这就是题面「枚举」标签的由来，不需要任何高级数据结构。
5. 「输入数据保证解的存在**唯一性**」——存在性：答案一定找得到，代码不需要写"无解"分支；唯一性：**找到的第一个公共值就是答案**，不需要比较多解、不需要判重。
6. 单组数据、无多测，输出一行。题面只给了 $N$ 的上界、未明说下界；$N=0$ 在构造上可以出现（输入 `1`/`1`），本解不依赖 $N\ge1$（见 §2.4、§4.5）。

**数据范围与规模感受**

$$N\le10^9,\qquad l_b\le30,\qquad l_t\le19.$$

二进制每位只有 1 种"写错"方式（翻成另一个数字），三进制每位有 2 种。两侧候选都是小集合，求交即可。这是一个"位数极小、枚举可行"的普及/提高- 模拟题；唯一的技术含量在**别被前导零骗了**（§2.4）。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：把"写错一位"翻译成数学语言

设输入二进制串为 $b$、三进制串为 $t$，长度分别记 $l_b,l_t$。

**引理 1（真值表示 = 输入串改回一位）**

设真值为 $N$。则 $\mathrm{bin}(N)$ 与 $b$ **长度相同**且恰好有一个位置上的数字不同；$\mathrm{ter}(N)$ 与 $t$ 同理。

**证明**：「总会写错一位数字」$\Rightarrow$ 写出的串与正确表示恰好一位不同（既不会全对，也不会错两位）；「不会意外地增加或删减数字」$\Rightarrow$ 位数不变。$\blacksquare$

> 引理 1 把"恢复 $N$"翻译成一个纯组合问题：找一串 $c$，与 $b$ 等长、恰好一位不同，且 $c$ 是合法二进制表示；再找一串 $d$，与 $t$ 等长、恰好一位不同，且 $d$ 是合法三进制表示；然后要求 $\mathrm{val}(c)=\mathrm{val}(d)=N$。

### 2.2 简化版：只给二进制，能定出 $N$ 吗？

先砍掉三进制，只留 $b$。二进制只有 $\{0,1\}$ 两种数字，某位写错 $\Rightarrow$ 写出的必是另一个数字，所以每位恰好一种改法。

**引理 2（单侧候选数的上界）**

二进制侧至多 $l_b$ 个候选串，三进制侧至多 $2l_t$ 个候选串。

**证明**：二进制数字集大小为 2，每个位置只有 1 种"改成别的数字"的方式；三进制数字集大小为 3，每个位置有 2 种。候选串由（改哪个位置，改成什么）唯一确定，故计数即位置数 × 每位改法数。$\blacksquare$

**例子**：$b=$ `1010`。翻第 0 位得 `0010` $=2$，翻第 1 位得 `1110` $=14$，翻第 2 位得 `1000` $=8$，翻第 3 位得 `1011` $=11$。四个候选，单看二进制**没有任何理由**选哪个——样例的真值 14 只是碰巧藏在里面。

> 下一个想法就这样冒出来：**一侧只能把 $N$ 框进一个小集合，要定出 $N$ 必须两侧联合**。三进制那边同样生成候选，答案自然就是"两侧候选的公共值"。问题被归约成了经典的**集合求交**。

### 2.3 归约：两侧候选求交，以及"合法表示"这道暗坎

先把存在性钉死：

**引理 3（存在性：真值必在两侧候选里）**

$N$ 既是二进制侧的候选值，也是三进制侧的候选值。

**证明**：由引理 1，$\mathrm{bin}(N)$ 正是"把 $b$ 的那个错位改回去"得到的串，故 $\mathrm{val}(\mathrm{bin}(N))=N$ 落在二进制候选值集合中；$\mathrm{ter}(N)$ 同理。$\blacksquare$

再看"匹配即解"——这一步有道暗坎，必须先补两个关于进制表示的标准事实。

**引理 4（标准表示唯一）**

每个非负整数在固定 base 下有且只有一个无前导零表示（$0$ 的表示就是 `0`，其余首位非零）。

**证明**：存在性来自反复除 $base$ 取余的构造。唯一性：设两个无前导零串 $s_1\ne s_2$ 同值。若长度不同，长者数值 $\ge base^{|长者|-1}$，短者数值 $\le base^{|短的|-1}-1$，矛盾，故等长，记 $L$。取两串第一个不同的位置 $i$，高位部分相同，于是

$$\mathrm{val}(s_1)-\mathrm{val}(s_2)=(s_1[i]-s_2[i])\,base^{L-1-i}+\sum_{k>i}(s_1[k]-s_2[k])\,base^{L-1-k}.$$

第一项绝对值 $\ge base^{L-1-i}$（两位数字至少差 1），第二项绝对值 $\le\sum_{k>i}(base-1)base^{L-1-k}=base^{L-1-i}-1$，合起来不可能为 $0$。矛盾。$\blacksquare$

**引理 5（合法表示的判定）**

数字都在 $[0,base)$ 内的串 $c$ 是某个非负整数的合法 $base$ 进制表示 $\iff$ $c=$ `0` 或 $c[0]\ne$ `0`。

**证明**：

- ($\Rightarrow$) 若 $c\ne$ `0` 且 $c[0]=$ `0`，则 $|c|\ge2$ 且 $\mathrm{val}(c)\le(base-1)\sum_{k=0}^{|c|-2}base^k=base^{|c|-1}-1<base^{|c|-1}$；而任何 $|c|$ 位标准写法的值 $\ge base^{|c|-1}$（首位非零）。由引理 4，标准表示唯一，所以 $c$ 不可能是它的值的 $|c|$ 位表示，即不合法。
- ($\Leftarrow$) $c=$ `0` 是 $0$ 的合法表示；$c[0]\ne$ `0` 时 $c$ 本身就是 $\mathrm{val}(c)$ 的标准写法（引理 4 保证这就是唯一写法）。$\blacksquare$

**引理 6（两侧合法候选的公共值就是解）**

若值 $x$ 满足：(a) 存在二进制改写串 $c_b$（与 $b$ 恰好一位不同）是 $x$ 的**合法**二进制表示；(b) 存在三进制改写串 $c_t$ 是 $x$ 的合法三进制表示；则 $x$ 是本题的解。

**证明**：(a) 中 $c_b$ 与 $b$ 只差一位，故 $|c_b|=l_b$；又 $c_b$ 是 $x$ 的合法二进制表示，由引理 4 得 $\mathrm{bin}(x)=c_b$，于是 $|\mathrm{bin}(x)|=l_b$ 且 $\mathrm{bin}(x)$ 与 $b$ 恰好一位不同。(b) 同理给出 $|\mathrm{ter}(x)|=l_t$ 且与 $t$ 恰好一位不同。合起来 $x$ 满足解的定义。$\blacksquare$

由引理 3，真值 $N$ 一定在交集里；由引理 6，交集里每个元素都是解；题面又说解唯一——**交集恰好一个元素，找到的第一个匹配就是答案**。到这里算法已经完整：生成两侧候选（只留合法改写串），求交，输出。

### 2.4 失败思路 1（本题最大的坑）：不过滤前导零，直接按值相交

"把 $b$ 每位翻一下算值、把 $t$ 每位改一下算值，两边相等就输出"——这是最先想到、也最容易写错的版本。它漏掉了引理 5 这道暗坎。

**反例（输入 $b=$ `11`，$t=$ `0`）**：真解是 $N=2$——$\mathrm{bin}(2)=$ `10` 与 `11` 恰好一位不同，$\mathrm{ter}(2)=$ `2` 与 `0` 恰好一位不同。但不过滤前导零时：二进制侧翻第 0 位得 `01`，值 $1$；三进制侧把 `0` 改成 `1`，值也是 $1$——**按值匹配到 1，错**。

错因：`01` 的值虽然是 1，但 1 的合法二进制表示是 `1`（长度 1），不是 `01`（长度 2）。把"改写串的值"直接当候选，等于偷偷允许了"真值表示比输入短一位"，而题面明文禁止增删位数。**我用一个去掉过滤的版本实测过：这个输入输出 `1`（应 2），输入 `111`/`00` 输出 `3`（应 6），而官方样例 `1010`/`212` 照样输出 14**——陷阱能骗过样例，极具迷惑性。

修正很小：生成候选时，若改写串长度 $\ge2$ 且首位是 `0`，跳过（引理 5）。修正后看反例：二进制侧只剩 `10` $=2$，三进制侧是 $\{1,2\}$，交集 $\{2\}$ ✓。

**附带发现**：若输入首位是 `0` 且 $l_b\ge2$，由引理 1 真值表示首位必为 `1`，那个唯一的错位就在首位——此时二进制侧其他位置的改写全都会带上前导零被跳过，只剩"把首位改成 `1`"一个候选，恰好与推断吻合。前导零输入不是脏数据，是合法数据，代码天然兼容。

### 2.5 失败思路 2：把输入的前导零 strip 掉

看到 `0110` 就想"先去掉前导零变成 `110`"是错的：位数被改小，真值（14，二进制 `1110`，4 位）根本不会出现在候选里。以 `0110`/`212` 为例，strip 后二进制侧只能凑出 $\{4,7\}$，与三进制侧 $\{14,20,21,22,26\}$ 无交，直接无解。**输入的每一位（哪怕它是错的）都携带"位数"信息，动不得。**

### 2.6 失败思路 3（一条弯路）：从两侧的值差反推错位

记输入二进制的值为 $V_b$、三进制的值为 $V_t$。由引理 1 的位权视角，$V_b=N\pm2^k$、$V_t=N\pm\delta\cdot3^m$（$\delta\in\{\pm1,\pm2\}$），于是 $V_b-V_t=\pm2^k\mp\delta\cdot3^m$——看起来可以枚举 $k,m$ 和符号解方程，少生成一半候选。但枚举量和候选生成一样大，符号组合反而更容易漏（尤其是三进制一侧），并不更简单。**候选生成 + 求交把两个约束对称处理，更稳。** 这条弯路的价值是确认了"枚举量本来就很小"，放心暴力即可。

### 2.7 等价变形：只枚举一侧，按定义校验另一侧

也可以只翻二进制的每一位得到候选值 $v$，再算 $v$ 的标准二进制/三进制，检查"等长 + 恰好一位不同"。这与两侧求交**完全等价**（任何解的二进制都是 $b$ 翻一位所得，枚举不漏），且那里的"等长"检查恰好起着和前导零过滤相同的作用——`01` 翻出来的值 1，标准二进制是 `1`，长度 $1\ne2$，同样被拦下。本解采用两侧求交，因为代码更短、两侧对称。

### 2.8 位权引理：复杂度与正确性的算术依据

**引理 7（改一位的数值增量）**

$\mathrm{val}(s)=\sum_{j}s[j]\cdot base^{L-1-j}$；把第 $i$ 位（从左数，0-based）从 $c$ 改成 $d$，数值变化 $(d-c)\cdot base^{L-1-i}$。

**证明**：求和式中只有第 $i$ 项改变，其余项不变。$\blacksquare$

由引理 7，每个候选的求值就是 $O(L)$ 的位权扫描；两侧候选数 $\le l_b+2l_t\le68$；求交是 $O(l_b\cdot l_t)\le1140$ 次比较。总计算量几千次字符操作，微秒级。

### 2.9 暴力基准：按定义枚举，专抓"假配对"

为了对"前导零过滤"这类掩蔽性错误有独立裁判，另写一个结构完全不同的暴力（见 §5.2）：枚举所有二进制位数可行的 $N\in[0,2^{l_b})$，对每个 $N$ **按题面定义**判定——$\mathrm{bin}(N)$ 与 $b$ 等长且恰好一位不同，$\mathrm{ter}(N)$ 与 $t$ 等长且恰好一位不同。它不使用"翻改一位"的任何技巧，因此标程漏掉的条件（如前导零）在它面前会立刻现形。

对拍时还发现一类**数据侧**的坑：小规模随机输入经常是**多解**的（题面只保证测试数据唯一，不保证随便造的输入唯一），例如 $b=$ `101`、$t=$ `01` 的解集是 $\{4,7\}$（$\mathrm{bin}(4)=$ `100`、$\mathrm{bin}(7)=$ `111` 都与 `101` 差一位，三进制侧 `11`/`21` 都与 `01` 差一位）。所以对拍生成器必须先验证唯一性再造数据——这正是题面"解的存在唯一性"条款在对拍里的镜像。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 「恰好错一位 + 不增删位数」⇒ 真值表示就是输入串改回一位，且位数被输入串长锁定。
- **explore its property（位权）** — 改第 $i$ 位只动该位权重，数值增量 $=(新-旧)\cdot base^{L-1-i}$；据此得出候选规模：二进制 $\le l_b$、三进制 $\le 2l_t$。
- **consider easier version** — 先只给二进制：候选 $\le l_b$ 个，单侧无法定解（`1010` 有 4 个候选），必须两侧联合。
- **reduce to easier problem** — 答案 = 两侧合法候选值集合的交；存在性由构造保证（引理 3），唯一性由题面保证。
- **classic problem solution（集合求交）** — 候选总数 $\le68$，$O(l_b\cdot l_t)$ 双重循环直接求交，数据量小到不需要哈希 / 排序归并。
- **explore its property（合法表示）** — 改写串带前导零就不是合法表示，按值相交会产生假配对；先按引理 5 过滤再求交（反例 `11`/`0`，已实证）。
- **verify against a definition brute** — 另写「按定义枚举 $N$」的独立暴力；并发现随机小输入常多解，生成器必须先验唯一性。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 |
|---|---|---|---|---|
| `b` | `string`（全局） | Bessie 写出的二进制串（恰有一位错） | 读入第一行 | 题面 |
| `t` | `string`（全局） | Bessie 写出的三进制串（恰有一位错） | 读入第二行 | 题面 |
| `lb` | `int`（main 局部） | $l_b$：`b` 的长度 = 真值二进制位数 | `b.size()` | 引理 1：位数不变 |
| `lt` | `int`（main 局部） | $l_t$：`t` 的长度 = 真值三进制位数 | `t.size()` | 同上 |
| `vb[]` | `i64[mxn]` | 二进制侧候选值（合法改写串的值） | 生成时写入，`nb` 计数 | v=value，b=binary |
| `vt[]` | `i64[mxn]` | 三进制侧候选值（合法改写串的值） | 同上，`nt` 计数 | v=value，t=ternary |
| `nb`/`nt` | `int`（全局） | 两侧候选个数 | `0`（全局零初始化） | 计数器 |
| `val(s,base)` | 函数 | 按位权把串算成数值（允许前导零） | — | 引理 7 的代码化 |
| `ans` | `i64` | 答案 | `-114514`（114514 家族哨兵） | 题面保证存在唯一，必被覆盖 |

### 4.2 编号步骤

1. `cin>>b>>t`；`lb=b.size()`，`lt=t.size()`（引理 1：真值表示的位数就是这两个数）。
2. 二进制侧：对 $i=0,\dots,l_b-1$，复制 `b` 并把第 $i$ 位翻转（`c[i]^=1`，二进制写错 = 翻成另一个数字）；若 `c` 长度 $\ge2$ 且 `c[0]=='0'` 则 `continue`（引理 5：不是合法表示）；否则 `vb[nb++]=val(c,2)`。
3. 三进制侧：对每个位置 $j$ 和每个不等于 `t[j]` 的数字 `d`，改写出 `c`；同样跳过前导零串；`vt[nt++]=val(c,3)`。
4. 双重循环找 `vb[i]==vt[j]`，首个匹配即答案（引理 6 + 题面唯一性），`goto hit` 跳出嵌套循环。
5. 输出 `ans`。

### 4.3 复杂度

- 时间：候选生成 $O(l_b^2+2l_t^2)\le900+722$，求交 $O(l_b\cdot2l_t)\le1140$，合计约 $2.8\times10^3$ 次字符级操作。
- 空间：两个 `i64[45]` 加两个串，约 1 KB。
- 实测（§4.5）：最坏规模 $N=10^9$ 单次 0.65~0.85 ms（多次运行，含进程启动），算法本身微秒级。

### 4.4 关键不变量（值得写 `assert` 的地方）

1. `vb`/`vt` 中每个值都对应一个**合法**改写串——前导零串在入表前已被 `continue` 掉（引理 5）。
2. 匹配到的 `vb[i]==vt[j]` 同时满足两侧「等长 + 恰好一位不同」（引理 6），由题面唯一性，首个匹配就是 $N$。
3. `nb,nt≥1` 恒成立：二进制侧至少有一个合法改法（$l_b=1$ 时唯一改法合法；$l_b\ge2$ 且 `b[0]=='0'` 时把首位改成 `1` 合法），三进制侧同理——不会空集打空。

| 随机对拍 | **通过**：3800 组（极小 $N\le10$ 500 组 + 小规模 $N\le300$ 3000 组 + 中规模 $N\le10^5$ 300 组，生成时均验证解唯一）+ 20 位二进制抽查 30 组；全部 std==brute==真值 |

| 最坏规模计时 | $N=10^9$（二进制 30 位、三进制 19 位）→ 多次运行 **0.65~0.85 ms**（含进程启动） |
| 编译检查 | `g++ -O2 -std=c++17 -Wall -Wextra` 零警告 |
| 残余风险 | 输入串长若超出约束（二进制 >30 位或三进制 >19 位），`mxn{45}` 将越界；按题面 $N\le10^9$ 不会发生 |

## 5. 示例代码

> 与 `appendix/P1555/P1555.cpp` **逐字节一致**。

```cpp
//
// 题目：P1555 尴尬的数字 Awkward Digits B
// https://www.luogu.com.cn/problem/P1555
// 本地验证:样例 1010/212 -> 14;3800 组随机数据 std==brute==真值
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{45};    // 候选值个数上界:二进制<=30,三进制<=2*19=38 (+5 松弛)

i64 vb[mxn];              // vb[i]=二进制串第 i 位写错时凑出的值
i64 vt[mxn];              // vt[j]=三进制某位写错时凑出的值
int nb,nt;
string b,t;

// base 进制串 s 的数值(题面允许前导零,按位权从左往右展开)
i64 val(const string&s,int base)
{
	i64 v=0;
	for(char c:s)
		v=v*base+(c-'0');
	return v;
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>b>>t;
	int lb=b.size(),lt=t.size();
	for(int i=0;i<lb;++i)
	{
		string c=b;
		c[i]^=1;                   // 二进制只有 0/1 两种数字,写错一位=翻成另一个
		if(c.size()>1&&c[0]=='0')  // 前导零串不是合法表示,不可能是真值的写法
			continue;
		vb[nb++]=val(c,2);
	}
	for(int j=0;j<lt;++j)
		for(char d='0';d<='2';++d)
			if(d!=t[j])
			{
				string c=t;
				c[j]=d;            // 三进制每位有两种写错方式
				if(c.size()>1&&c[0]=='0')
					continue;
				vt[nt++]=val(c,3);
			}
	i64 ans{-114514};             // 哨兵:题面保证解存在且唯一,必被覆盖
	for(int i=0;i<nb;++i)
		for(int j=0;j<nt;++j)
			if(vb[i]==vt[j])       // 两侧候选的唯一公共值即 N
			{
				ans=vb[i];
				goto hit;
			}
hit:;
	cout<<ans<<'\n';
	return 0;
}
```

### 5.2 对照实现：按定义枚举的暴力基准

见 `appendix/P1555/P1555_brute.cpp`：枚举 $N\in[0,2^{l_b})$，对每个 $N$ 按题面定义判定（等长 + 恰好一位不同，两侧都要），首命即中。结构上与标程完全独立——不翻改任何一位，只使用定义，因此能抓住"前导零假配对"这类标程特有的错误。复杂度 $O(2^{l_b}\cdot(l_b+l_t))$，仅小规模可用。

### 5.3 易错点清单

- **不过滤前导零** ⇒ 假配对：`11`/`0` 输出 1（应 2）、`111`/`00` 输出 3（应 6）；官方样例却能蒙对，极具迷惑性（已用去过滤版实证）。
- **strip 输入的前导零** ⇒ 位数被改小，真值（如 14）根本不在候选里，`0110`/`212` 直接无解。
- **只查一侧合法** ⇒ 必须两侧改写串都合法才算公共值（引理 6）。
- **以为 $N\ge1$** ⇒ $N=0$ 可构造（`1`/`1`、`1`/`2`）；代码靠"长度 $\ge2$ 才查前导零"天然兼容，哨兵 `-114514` 只在非法输入时出现。
- **生成随机数据不验唯一性** ⇒ 歧义输入（如 `101`/`01`，解集 $\{4,7\}$）会让对拍双方各说各话。
- **`cout<<...<<endl;`** ⇒ 违反本项目风格指南，一律用 `'\n'`。
