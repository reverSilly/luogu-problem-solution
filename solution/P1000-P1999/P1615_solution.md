# P1615 西游记公司

## Part 1 — 题目理解 (Problem Comprehension)

### 题意简述

猪八戒从某个时刻 $T_1$ 开始，以每秒 $n$ 台的速度抢沙和尚的笔记本；孙悟空会在更晚的时刻 $T_2$ 来偷猪八戒的平底锅，届时猪八戒必须停手。问这段时间里猪八戒一共能抢到多少台笔记本。

剥离包装后，这题只有一个数学内核：求两个"时:分:秒"时刻之间相差多少秒，再乘以速率 $n$。

### 输入输出格式

- **输入格式**：第一行一个时刻（时:分:秒）；第二行一个更晚的时刻（时:分:秒）；第三行一个整数 $n$。时刻的时/分/秒都可能带前导零，也可能不带。
- **输出格式**：一行一个整数，表示抢到的笔记本总数。
- **数据规模**：两个时刻均合法（一天之内），$n<32768$。

### 关键约束分析

1. 输入是带冒号的字符串，`cin>>int` 无法直接吃掉冒号，需要按字符解析；用 `scanf("%d:%d:%d")` 或手工扫一遍都行。
2. 前导零意味着**不能用固定宽度**去截取子串（`00:00:01` 与 `0:0:1` 都要能读），按分隔符解析才安全。
3. 结果上界：最大时间差 $24\times3600-1=86399$ 秒，乘 $32767$ 得 $2831036033$，已经超过 `int` 上限 $2147483647$，**必须开 64 位**。这是本题唯一的真正陷阱。
4. 题面保证第一行早于第二行，因此差值恒为正，不需要处理借位为负的情况。

## Part 2 — 思路推导 (Idea Discovery)

### 第一步：先把"时间"变成"数"

既然速率是"每秒 $n$ 台"，那么只要知道总秒数就能一步算出答案。时刻本身是六十进制混合写法的字符串，直接做减法要处理"秒不够向分借、分不够向时借"的三层借位，非常容易写错。

反过来想：**六十进制的每一次借位，在统一折算成秒之后都会自动消失**。于是把 $h$ 时 $m$ 分 $s$ 秒折算为

$$S(h,m,s)=3600h+60m+s,$$

两个时刻相减就退化成一次普通整数减法。

**引理 1（折算的唯一性）**：对任意合法时刻 $(h,m,s)$（$0\le h\le 23$，$0\le m,s\le 59$），$S(h,m,s)$ 是 $[0,86399]$ 内的整数，且不同时刻折算结果不同。

*证明*：先证值域。$h\le 23$ 给出 $3600h\le 82800$，$m\le 59$ 给出 $60m\le 3540$，$s\le 59$，三者相加不超过 $82800+3540+59=86399$，且各项非负，故 $S\in[0,86399]$。再证单射：设 $S(h_1,m_1,s_1)=S(h_2,m_2,s_2)$，两边对 $60$ 取模得 $s_1\equiv s_2\pmod{60}$，而 $s_1,s_2\in[0,59]$，故 $s_1=s_2$；约去后同法对 $60$ 取模得 $m_1=m_2$；最后剩下 $3600h_1=3600h_2$，得 $h_1=h_2$。$\square$

### 第二步：差值与速率相乘

**引理 2（时间差即秒数差）**：若 $T_1$ 早于 $T_2$，则二者相隔的秒数恰为 $S_2-S_1$。

*证明*：把一天的时间轴按秒离散成 $0,1,\dots,86399$ 这些整点，时刻 $T$ 就落在第 $S(T)$ 个整点上（引理 1 保证这个对应是双射）。从第 $S_1$ 个整点走到第 $S_2$ 个整点，每走一步恰好一秒，共 $S_2-S_1$ 步。$\square$

于是答案 $=(S_2-S_1)\,n$。因为每秒恒定抢 $n$ 台，题目没有"中途速率变化"的设定，所以不需要分段。

### 第三步：为什么必须用 64 位

很多人第一反应是 `int`——毕竟 $n<32768$ 看起来很小。但被乘数可以接近 $86400$：

$$86399\times 32767=2\,831\,036\,033>2^{31}-1=2\,147\,483\,647.$$

也就是说，只要 $n$ 取到上界且时间跨度接近一整天，`int` 就会溢出成负数。因此保存 $n$ 和最终答案都必须用 `long long`。

**引理 3（64 位足够）**：答案不超过 $86399\cdot32767<2^{32}<2^{63}-1$。

*证明*：由引理 1，$S_2-S_1\le 86399$；由题面 $n\le 32767$，故乘积小于 $2.84\times10^9$，远小于 `long long` 上界 $9.22\times10^{18}$。$\square$

## Part 3 — 模式总结 (Pattern Summary)

- `explore its property` — 单位时间收益恒定，所以整个问题只依赖"总秒数"这一个量。
- `reduce to easier problem` — 把六十进制时刻折算成秒，把带借位的时刻减法降成整数减法。
- `classic problem solution` — 用 `sscanf("%d:%d:%d")` 按分隔符吃数，天然兼容前导零与不定宽。
- `discuss by category` — 单独讨论乘法上界，据此把 `int` 换成 `i64`。
- `explore its property` — 题面保证先后顺序，省掉"差值为负要取绝对值"的分支。

## Part 4 — 真正的解法 (The Real Solution)

### 符号表 (Notation Glossary)

| 数学符号 | 代码变量 | 含义说明 |
| :--- | :--- | :--- |
| $T_1$ | `s1` | 猪八戒开始抢的时刻串，形如 `hh:mm:ss`，可能带前导零 |
| $T_2$ | `s2` | 孙悟空到来的时刻串，保证晚于 $T_1$ |
| $n$ | `n` | 每秒抢到的笔记本数，读入后即以 `i64` 存放 |
| $h$ | `h` | `parse()` 内的"时"分量，初值 0 |
| $m$ | `mi` | `parse()` 内的"分"分量，初值 0（避开与题意中的 $m$ 混淆，命名 `mi`） |
| $s$ | `se` | `parse()` 内的"秒"分量，初值 0 |
| $S$ | `parse()` 返回值 | 该时刻在当天时间轴上的秒数，$3600h+60mi+se$ |

### 算法步骤

1. 读入 `s1`、`s2` 与 `n`。
2. 对 `s1` 调用 `parse()`：用 `sscanf` 按 `%d:%d:%d` 提取三段，返回 `h*3600+mi*60+se`，记为 $S_1$。
3. 对 `s2` 同样处理，得到 $S_2$。
4. 输出 `(i64)(S2-S1)*n`。两个整数先相减（此时 $S_2>S_1$，不会下溢），再提升为 64 位后与 `n` 相乘。

### 复杂度分析

- **时间复杂度**：$\mathcal{O}(|s_1|+|s_2|)$，只扫过两行输入的字符，常数极小。
- **空间复杂度**：$\mathcal{O}(1)$，只有两个字符串与三个整型分量。

### 正确性验证

引理 1 保证折算是一一对应，引理 2 保证秒数差就是真实间隔，引理 3 保证 64 位乘法不会溢出，三条合起来即答案 $=(S_2-S_1)n$ 正确。代码中 `parse()` 的三个局部变量都显式初始化为 0，即使某个分量缺失（题面保证不会）也不会读到未定义值。

## Part 5 — 示例代码 (Example Code)

```cpp
//
// 题目：P1615 西游记公司
// https://www.luogu.com.cn/problem/P1615
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

string s1,s2;
i64 n;

int parse(const string&s)          // "hh:mm:ss" -> 当天第几秒
{
	int h=0,mi=0,se=0;
	sscanf(s.c_str(),"%d:%d:%d",&h,&mi,&se);
	return h*3600+mi*60+se;
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>s1>>s2>>n;
	cout<<(i64)(parse(s2)-parse(s1))*n<<'\n';
	return 0;
}
```

### 易错点

1. **答案溢出**：`(S2-S1)*n` 最大 $2.83\times10^9$，`int` 会溢出，必须先转 `i64`。
2. **前导零**：不要用定长下表截取字符串，`0:0:15` 与 `00:00:15` 都要能读。
3. **符号优先级**：`(i64)(parse(s2)-parse(s1))*n` 里的强制转换写在减法之后、乘法之前——若写成 `(i64)parse(s2)-parse(s1)*n` 就完全不同了。
4. **输出换行**：本题只输出一个整数，末尾按仓库惯例补 `'\n'`。
