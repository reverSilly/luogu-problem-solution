# P1834 速算游戏

> 难度：省选/NOI- · 标签：枚举、搜索

## 1. 重新读题

### 1.1 问题重述（人话版）

给定 $4$ 个 $1\sim 9$ 的整数（保证有解），用加、减、乘、除和括号把它们算成 $24$。限制是**每一步运算的中间结果都必须是整数**，例如 $(2\times2)/4$ 允许，而 $2\times(2/4)$ 不允许（因为 $2/4$ 不是整数）。

输出一行表达式。要求：

1. 每一个「非最外层」的二元运算都要用一对括号括起来，形如 `(3+5)+6`、`3*(5+6)`；最外层不再套括号。
2. 若有多种解法，输出**字典序最小**的字符串。
3. 运算符用 `+ - * /`，数字用输入的那 $4$ 个数字字符。

### 1.2 关键约束与规模暗示

- 只有 $4$ 个数，所有可能的表达式数量是一个与输入无关的常数——大约 $9\times10^3$ 量级。这明确指向**暴力枚举所有表达式**，而不是找什么巧妙的构造。
- 「中间结果必须是整数」不是一句可以事后检查的话，它必须在**每一种括号结构的每一步**上成立，所以要边搜边判。
- 「字典序最小」说明不能找到一个解就停，必须把所有解都生成出来取最小；也不能用 DP 只保留最优值，因为字典序是一个全局字符串性质。

## 2. 思维链（Chain-of-thought）

### 2.1 先确定「一个表达式」到底长什么样

四个数用三次运算连起来，本质上是一棵**二叉树**：三个内部结点各放一个运算符，四个叶子各放一个数字。任意加括号的方式，恰好对应所有把 $4$ 个叶子分成两两组合再合并的形态。

题面要求「每一步的运算括号补齐」，例子 `(3+5)+6` 说明：

- 根结点（最后一次运算）**不**被括号包住；
- 每个非根内部结点整体被一对括号包住。

于是字符串可以递归地定义：

$$
\text{str}(\text{叶子})=\text{数字字符},\qquad
\text{str}(\text{内部})=\begin{cases}
\text{str}(L)\ \circ\ \text{str}(R), & \text{该结点是根},\\
\bigl(\ \text{str}(L)\ \circ\ \text{str}(R)\ \bigr), & \text{否则},
\end{cases}
$$

其中 $\circ$ 是运算符字符。

### 2.2 枚举的对象是什么

一个完整的候选表达式由三部分组成：

1. 四个数字的**排列**（因为 $a-b$ 与 $b-a$、$a/b$ 与 $b/a$ 不同，甚至 $a+b$ 与 $b+a$ 的字符串也不同，所以必须把顺序也当作枚举对象）；
2. 三个位置上的**运算符**，各 $4$ 种；
3. 二叉树的**形态**（四个叶子的组合方式）。

如果分别枚举这三样，规模是 $4!\times4^3\times5=7680$，已经很小。但「边枚举边维护中间结果是否为整数」在按「形态」展开时写起来容易出错。

更自然的写法是**递归合并**：当前有一堆「值 + 对应字符串」的项，每次任选**两个不同**的项 $A,B$（有序），选一个运算符合并成一个新项，直到只剩一项。这样：

- 每一步的运算就是树的一个内部结点；
- 中间结果是否整数可以在这一步立刻检查；
- 五种树形、所有排列、所有运算符都被自然地覆盖。

### 2.3 引理：递归合并恰好生成所有合法表达式

**引理 1**：设当前有 $k$ 个项，每个项对应一棵已构造好的子树。任取两个不同的项 $A,B$（有先后顺序），用任一运算符合并，得到一棵新的合法子树；所有 $4$ 个叶子的带括号表达式都可以通过这种方式从 $4$ 个叶子出发、经 $3$ 次合并得到。

**证明**：
- 任意一棵以 $4$ 个叶子为叶结点的满二叉树，其根把叶子集合分成两个非空部分，分别对应左右子树。按后序遍历，先递归构造左、右子树（各对应一次或多次合并），最后把这两个子树的根合并即可。归纳即得「可以生成」。
- 反过来，每次合并都是把两棵子树的根用运算符连接，得到的仍是一棵合法的二叉树表达式，所以生成的字符串都是合法表达式。$\blacksquare$

因为合并时对 $(A,B)$ 取了**有序对**，所以 $A+B$ 与 $B+A$、$A-B$ 与 $B-A$ 都会被分别尝试；又因为每一层都尝试所有运算符，所有表达式都被覆盖。

### 2.4 整数的处理

所有项的值始终是整数（初始是输入整数，每次只在结果为整数时才保留）。对除法：

$$
A/B\text{ 合法}\iff B\ne0\ \text{且}\ A\bmod B=0 .
$$

C++ 中 `a % b == 0` 对负数同样正确（例如 $-6\bmod3=0$、$6\bmod(-3)=0$），所以不需要额外讨论符号。

> **失败尝试的极简反例**：如果只在最后检查最终结果是否为 $24$，那么 $2\times(2/4)=1$ 这种「用到了非整数中间结果」的表达式会被误判为合法。例如对 $2,2,2,4$，最终式 $(2+4)\times(2+2)=24$ 合法，但若不限制中间结果，会多出一些用分数绕路的表达式，可能得到字典序更小的错误答案。所以整数检查必须**每合并一次就做一次**。

### 2.5 字典序比较

把所有终态（只剩一项且值等于 $24$）的字符串与当前最优答案比较，取较小者。字符串比较用 C++ 的 `std::string::operator<`，它的顺序就是字符的 ASCII 序：

$$
\texttt{'('}<\texttt{')'}<\texttt{'*'}<\texttt{'+'}<\texttt{'-'}<\texttt{'/'}<\texttt{'0'}<\cdots<\texttt{'9'} .
$$

题面所说的「字典顺序」正是这个逐字符比较的顺序。

### 2.6 规模与正确性收尾

第一层：$4\times3\times4=48$ 种合并；第二层：$3\times2\times4=24$；第三层：$2\times1\times4=8$。总共至多

$$
48\times24\times8=9216
$$

条搜索路径。每条路径的字符串长度不超过 $4$ 个数字、$3$ 个运算符、$2$ 对括号（根结点不套括号），共 $11$ 个字符，所以整个搜索是常数级。

由于：

1. 所有合法表达式都被生成（引理 1），
2. 每个生成的表达式都满足整数中间结果（每步都检查），
3. 对所有值为 $24$ 的终态取了字符串最小值，

所以输出的就是字典序最小的合法解。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 把表达式看成二叉树，非根内部结点整体加括号、根不加括号，得到递归的字符串构造方式。
- **consider easier version** — 先想「枚举排列 × 运算符 × 五种树形」的 $7680$ 种方案，确认暴力可行。
- **classic problem solution** — 用「任取两个项合并」的递归搜索统一枚举所有树形与顺序，并在合并时立即检查整除与中间结果。
- **explore its property** — 每一层都尝试有序对，保证 $A-B$、$B-A$、$A/B$、$B/A$ 都被覆盖。
- **classic problem solution** — 所有终态中取 `std::string` 最小值，即字典序最小解。

## 4. 解法说明（The Real Solution）

### 4.1 符号表

| 符号 | 类型尺寸 | 含义 | 初值 / 来源 | 助记 |
| :--- | :--- | :--- | :--- | :--- |
| `item` | `struct` | 一项：`i64 v`（当前值）、`string s`（对应表达式） | — | value + string |
| `best` | `string` | 目前找到的字典序最小合法表达式 | 空串 | 答案 |
| `found` | `bool` | 是否已找到过解 | `false` | 标记 |
| `v` | `vector<item>` | 当前层待合并的项集合 | 初始为 4 个输入数字 | 递归参数 |
| `op` | `int` | 运算符编号 $0..3$ 对应 `+ - * /` | 循环 | operator |

### 4.2 算法步骤

1. 读入 4 个数字，构造成 4 个 `item{x, to_string(x)}`。
2. 调用 `dfs(v)`：
   1. 若 `v.size()==1`：如果 `v[0].v==24`，用 `v[0].s` 更新 `best`（更小则更新），返回。
   2. 否则枚举有序对 `(i,j)`（$i\ne j$）：设 $A=v[i],B=v[j]$，把除 $i,j$ 外的项放进 `nxt`。
   3. 枚举四种运算：
      - `+`：$r=A.v+B.v$；
      - `-`：$r=A.v-B.v$；
      - `*`：$r=A.v\times B.v$；
      - `/`：若 $B.v\ne0$ 且 $A.v\bmod B.v=0$，$r=A.v/B.v$，否则跳过。
   4. 生成字符串：若合并后只剩一项（即当前 `v.size()==2`），不加外层括号；否则加一对括号。
   5. 把新项压入 `nxt`，递归 `dfs(nxt)`，再弹出。
3. 输出 `best`。

### 4.3 复杂度

- 搜索路径至多 $48\times24\times8=9216$ 条，每条做常数次整数运算与长度 $\le11$ 的字符串拼接/比较。
- 时间与空间均为 $O(1)$（相对于输入规模是常数）。

## 5. 示例代码

```cpp
//
// 题目：P1834 速算游戏
// https://www.luogu.com.cn/problem/P1834
// AC
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

struct item
{
	i64 v;
	string s;
};

string best;
bool found{false};

void dfs(const vector<item>&v)
{
	int k=(int)v.size();
	if(k==1)
	{
		if(v[0].v==24&&(!found||v[0].s<best))
		{
			best=v[0].s;
			found=true;
		}
		return;
	}
	for(int i=0;i<k;++i)
		for(int j=0;j<k;++j)
		{
			if(i==j)
				continue;
			vector<item>nxt;
			for(int t=0;t<k;++t)
				if(t!=i&&t!=j)
					nxt.push_back(v[t]);
			i64 a=v[i].v,b=v[j].v;
			for(int op=0;op<4;++op)
			{
				i64 r{0};
				char ch{'+'};
				if(op==0)
					r=a+b,ch='+';
				else if(op==1)
					r=a-b,ch='-';
				else if(op==2)
					r=a*b,ch='*';
				else
				{
					if(b==0||a%b!=0)
						continue;
					r=a/b,ch='/';
				}
				string s;
				if(k==2)
					s=v[i].s+ch+v[j].s;
				else
					s="("+v[i].s+ch+v[j].s+")";
				nxt.push_back({r,s});
				dfs(nxt);
				nxt.pop_back();
			}
		}
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	vector<item>init;
	for(int i=0;i<4;++i)
	{
		int x;
		cin>>x;
		init.push_back({x,string(1,char('0'+x))});
	}
	dfs(init);
	cout<<best<<'\n';
	return 0;
}
```
