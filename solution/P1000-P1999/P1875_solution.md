# P1875 佳佳的魔法药水

## 1. 重新读题

### 1.1 问题重述（人话版）

有 $n$ 种药水，编号 $0..n-1$，$0$ 号是目标药水。得到一种药水有两种方式：

1. 直接到商店买一份，价格 $p_i$；
2. 按魔法书配方，用 $1$ 份 $A$ 药水加 $1$ 份 $B$ 药水合成 $1$ 份 $C$ 药水。

初始手里没有任何药水（所以每一次"用料"都要自己先花钱买/配）。求得到一份 $0$ 号药水的最小总花费，以及花费最小的方案数（方案按"步骤"区分，任何一个步骤不同就算不同方案）。

$n\le1000$，每种药水价格在 $[1,2.8\times10^4]$，答案方案数 $\le2^{63}-1$。输入以空行结束。

题面背景里还有一句提醒：实际数据中存在 $A,B$ 相同但 $C$ 不同的行（与正文保证矛盾）。这句话决定了实现细节（见 2.6）。

### 1.2 关键约束与规模暗示

- $n\le1000$，价格上界 $2.8\times10^4$。最便宜方案的花费一定 $\le$ 直接买 $0$ 号的价格 $\le2.8\times10^4$，所以花费可以 32 位存，但方案数要 64 位（题目直接给了 $\le2^{63}-1$ 的提示）。
- 配方条数没有单独给上界，只能读到 EOF。
- $n=1000$ 排除任何指数/背包式枚举；每条配方形如"两份药水合成一份"，这是**最短路**的形态，而不是线性 DP。

## 2. 思维链（Chain-of-thought）

### 2.1 建模：把"买"和"配方"都看成路

把每种药水看成一个顶点。"直接买 $v$"看成从源点出发、代价 $p_v$ 到达 $v$ 的一条边。配方 $A+B\to C$ 不是普通的有向边，因为它的"边权"是 $dis[A]+dis[B]$——要依赖两个已有答案。这类结构叫**超边**：一次操作消耗两个点、产出一个点。

但"消耗两个点"并没有让问题变难，因为每个子方案的代价是可以独立分解的，而分解出来的正是"各自的最小花费"：

**引理 1（最优子结构）**：若某个最优方案在最后一步用配方 $A+B\to C$ 得到 $C$，则该方案中"得到一份 $A$"和"得到一份 $B$"的子方案，分别都是各自花费最小的方案。

**证明**：设该方案中为得到 $A$ 花了 $c_A$，而 $A$ 的最小花费是 $dis[A]$。若 $c_A>dis[A]$，把方案里那段得到 $A$ 的过程整体换成花费 $dis[A]$ 的最优方案：由于初始手中没有任何药水，两段子过程之间不存在共享或复用（每个中间产物都是独立购买/合成的），替换不会影响其它部分，总花费严格下降，与"该方案最优"矛盾。所以 $c_A=dis[A]$。对 $B$ 同理。$\square$

由引理 1，得到

$$\boxed{dis[C]=\min\Bigl\{p_C,\ \min_{A+B\to C}\bigl(dis[A]+dis[B]\bigr)\Bigr\}}$$

其中 $dis[v]$ 是得到一份 $v$ 的最小花费。

**引理 2（方程是充要的）**：上式给出的 $dis$ 恰好是真实最小花费。

**证明**：

- 任何方案的最后一步只有两种可能：买 $C$（花费 $p_C$），或用某条配方 $A+B\to C$（花费 $=$ 得到 $A$、$B$ 的花费之和，由引理 1 取最小即 $dis[A]+dis[B]$）。所以真实最优值 $\ge$ 右端。
- 右端两种候选都能真正构造：买 $C$ 可行；对配方取 $A$、$B$ 的最优方案再合成，也可行，花费恰为 $dis[A]+dis[B]$。所以真实最优值 $\le$ 右端。

两边夹得等号。$\square$

### 2.2 为什么这仍然能跑 Dijkstra

这是一个"最短路 + 两条最短路合成"的方程，看起来像要迭代到不动点（Bellman–Ford 式）。关键观察是：

**所有 $dis\ge1$**（价格是正整数，配方只是把两份的花费相加，不会变小）。于是对任一配方 $A+B\to C$，

$$dis[A]+dis[B]\ge dis[A]+1>dis[A],\qquad dis[A]+dis[B]>dis[B].$$

也就是说：**产生 $C$ 的最优配方的两个原料，距离都严格小于 $C$ 的最优距离**。

**引理 3（按距离从小到大定稿）**：当某个顶点 $u$ 以当前最小距离从优先队列弹出时，$dis[u]$ 已经不会再被改小，并且所有以 $u$ 为产物、能取到最优值的配方都已在之前被处理完。

**证明**：设弹出 $u$ 时距离为 $d$。若存在另一条更优路径使 $dis[u]<d$，其最后一步要么是买 $u$（$p_u<d$，则 $u$ 会以更小距离入队），要么是配方 $A+B\to u$，其中 $dis[A],dis[B]<dis[u]<d$。由归纳假设（所有距离 $<d$ 的顶点都已定稿），$A,B$ 都已处理，该配方在较晚定稿的那个原料被弹出时已经被考虑过，会把 $u$ 的距离更新到 $\le dis[A]+dis[B]<d$ 并入队。矛盾。故 $dis[u]$ 已正确。同理，任何以 $u$ 为产物且能取到最优的配方，其原料距离 $<dis[u]$，都已定稿，贡献也已经加进 `cnt[u]`。$\square$

这正是 Dijkstra 的定稿顺序，所以可以把"买"作为初始距离、把配方当作"只有当两个原料都定稿时才可用的超边"，用优先队列模拟。

### 2.3 计数：什么时候重置、什么时候累加

设 `cnt[v]` 为"以最小花费得到一份 $v$ 的方案数"。初值 `cnt[v]=1`：直接买是一种方案（注意：即使后面发现更便宜的配方，重置时也会覆盖掉这个 $1$，这是正确的，因为买不再是最优）。

处理配方 $A+B\to C$ 时令 $nd=dis[A]+dis[B]$、$w=cnt[A]\cdot cnt[B]$：

- $nd<dis[C]$：更优，`dis[C]=nd`，旧的方案全部作废，`cnt[C]=w`；
- $nd=dis[C]$：同样优，`cnt[C]+=w`。

为什么是**乘法**：得到 $A$ 与得到 $B$ 是两段相互独立的子过程（初始无药水，互不复用），把它们的方案任意拼接都得到不同的完整方案；再接上固定的"合成"这一步仍不同。由乘法原理得 $cnt[A]\cdot cnt[B]$。若配方要求 $A=B$，需要两份 $A$，方案数是 $cnt[A]^2$——注意这条配方在邻接表里只能挂一次，否则会在弹出 $A$ 时被重复处理一次，把方案数算成两倍。

### 2.4 实现细节：超边挂在哪

把每条配方存成 `rec[id]={a,b,c}`，并同时挂到 `adj[a]` 和 `adj[b]`（若 $a=b$ 只挂一次）。当顶点 $u$ 定稿时，遍历 `adj[u]` 里的每条配方，看"另一个原料"是否已定稿：

- 另一个原料未定稿 → 这条配方还不能用，跳过；
- 另一个原料已定稿、且产物 $C$ 也已定稿 → 跳过（$C$ 的值不会再变，等值贡献按引理 3 已经统计完；若不跳过，会把"产物是 $u$ 自己的配方"在 $u$ 弹出时错误地再累加一次）。

每条配方只会在"两个原料中较晚定稿的那个"弹出时被真正处理一次。

### 2.5 输入与数据坑

- 题目说"输入以一个空行结束"，直接用 `while(cin>>a>>b>>c)` 读到 EOF 即可，`>>` 会自动跳过空行。
- 背景提示数据里存在同一对 $(A,B)$ 对应不同 $C$ 的行。按"每条配方独立"处理（每条都挂进邻接表、各自参与松弛）即可：它们产出不同药水，本来就不冲突，不需要额外合并。
- 若同一对 $(A,B)$ 恰好重复成同一三元组（题面保证不会有），按当前实现会被算作两种不同方案；这是题面保证之外的情况，不影响正确性讨论。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 买是初始最短路，配方是消耗两条最短路、产出一条新路的超边。
- **optimal substructure** — 最优配方的两个原料必各自取最小花费（否则替换后更优）。
- **classic problem solution** — 因为原料距离严格小于产物距离（所有距离 $\ge1$），可以按 Dijkstra 的定稿顺序处理超边。
- **counting by relaxation** — 更优则重置方案数、相等则累加，乘法原理合并两个原料。

## 4. 解法说明（The Real Solution）

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 |
| :--- | :--- | :--- | :--- | :--- |
| $n$ | `int` | 药水种数 | 读入 | $\le1000$ |
| `dis[v]` | `i64 [1005]` | 得到一份 $v$ 的最小花费 | 读入的价格 | distance |
| `cnt[v]` | `i64 [1005]` | 最小花费的方案数 | $1$ | count |
| `vis[v]` | `bool [1005]` | $v$ 是否已定稿 | `false` | — |
| `adj[u]` | `vector<int> [1005]` | 以 $u$ 为原料的配方编号 | — | adjacency |
| `rec[id]` | `array<int,3> [2000005]` | 第 $id$ 条配方 $(a,b,c)$ | — | recipe |

### 4.2 算法步骤

1. 读入 $n$；读入 $n$ 个价格作为 `dis[0..n-1]`，令 `cnt[v]=1`，全部压入小根堆。
2. 读入全部配方 $(a,b,c)$，存进 `rec`，并挂到 `adj[a]`（若 $a\ne b$ 也挂到 `adj[b]`）。
3. 不断弹出堆顶 $(d,u)$：若 `vis[u]` 或 $d\ne dis[u]$（惰性删除）则跳过；否则 `vis[u]=true`。
4. 遍历 `adj[u]` 中每条配方，取另一原料 $v$、产物 $c$：
   - 若 `!vis[v]` 或 `vis[c]`，跳过；
   - 令 $nd=dis[u]+dis[v]$、$w=cnt[u]\cdot cnt[v]$；
   - 若 $nd<dis[c]$：`dis[c]=nd`、`cnt[c]=w`、入堆；若 $nd=dis[c]$：`cnt[c]+=w`。
5. 输出 `dis[0]` 与 `cnt[0]`。

### 4.3 复杂度

- 时间 $O((n+E)\log n)$，$E$ 为配方条数（每条配方最多被处理一次，堆操作 $O(\log n)$）。
- 空间 $O(n+E)$：配方数组约 $2\times10^6\times12$ 字节 $=24$ MB，邻接表 $O(E)$。

## 5. 示例代码

```cpp
//
// 题目：P1875 佳佳的魔法药水
// https://www.luogu.com.cn/problem/P1875
// 自测：手造小数据与手算一致（含等距方案数累加）
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{1005};

int n;
i64 dis[mxn],cnt[mxn];
bool vis[mxn];
vector<int> adj[mxn];
array<int,3> rec[2000005];
int rn{0};

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	priority_queue<pair<i64,int>,vector<pair<i64,int>>,greater<>>Q;
	for(int i=0;i<n;++i)
	{
		cin>>dis[i];
		cnt[i]=1;                   // 直接买是一种方案
		Q.push({dis[i],i});
	}
	for(int a,b,c;cin>>a>>b>>c;)
	{
		rec[rn]={a,b,c};
		adj[a].push_back(rn);
		if(b!=a)
			adj[b].push_back(rn);   // a==b 只挂一次，避免重复计数
		++rn;
	}
	while(!Q.empty())
	{
		auto[d,u]=Q.top();Q.pop();
		if(vis[u]||d!=dis[u])
			continue;
		vis[u]=true;
		for(int id:adj[u])
		{
			int a=rec[id][0],b=rec[id][1],c=rec[id][2];
			int v=(a==u?b:a);
			if(!vis[v]||vis[c])     // 另一原料未定稿 / 产物已定稿
				continue;
			i64 nd=dis[u]+dis[v],ways=cnt[u]*cnt[v];
			if(nd<dis[c])
			{
				dis[c]=nd;
				cnt[c]=ways;
				Q.push({nd,c});
			}
			else if(nd==dis[c])
				cnt[c]+=ways;
		}
	}
	cout<<dis[0]<<' '<<cnt[0]<<'\n';
	return 0;
}
```
