# P1540 [NOIP 2010 提高组] 机器翻译

> 标签：模拟 · 队列 · 难度：普及-
> 本地题面：`P1540.md`（$1\le M\le 100$，$1\le N\le 1000$，单词编号 $0\le v\le 1000$）。
> 验证：官方样例 `3 7 / 1 2 1 5 4 4 1 -> 5`；400 组随机对拍 std==brute；最坏规模 $M=100,N=1000$（全互异，答案 $1000$）耗时 $0.0054$ s。

## 1. 重新读题

**问题重述（人话版）**

有一个容量为 $M$ 的「内存」（页框），初始为空。按顺序读入长度 $N$ 的单词序列（每个单词用 $\le 1000$ 的非负整数编号），对每个单词 $w$：

- 若 $w$ 已在内存中 $\Rightarrow$ 直接命中，**什么都不做**；
- 若 $w$ 不在内存中 $\Rightarrow$ 去外存词典查一次（**查词典次数 $+1$**），然后把它放进内存；放之前若内存已满（已存 $M$ 个），**先清掉"最早进入内存"的那个单词**腾出单元，再放入 $w$。

求整个过程中「去外存查词典」的总次数。

> 一句话版本：**维护一个容量 $M$ 的先进先出队列，统计入队（未命中）次数**。

**题面里容易漏掉的条款**

1. 「每单元能存放一个单词和译义」$\Rightarrow$ 同一时刻内存中同一个单词至多占一个单元（不会重复占用）。
2. 「若当前内存中已存入的单词数**不超过** $M-1$，软件会将新单词存入一个未使用的内存单元」$\Rightarrow$ 未满时**直接新增单元，不淘汰任何旧词**。只有"已存 $M$ 个"时才淘汰。
3. 「清空**最早进入内存的那个单词**」$\Rightarrow$ 淘汰的是**进入时间最早**的，不是"最久没用过的"。命中**不刷新**这个顺序（见 §2.3 的关键辨析）——这就是"先进先出"（FIFO）而非"最近最少使用"（LRU）。
4. 「假设在翻译开始前，内存中没有任何单词」$\Rightarrow$ 计数器从 $0$ 开始，内存从空开始。
5. 单词编号是**非负整数**，可以取 $0$；代码里不能用 $-1$ 之类的哨兵去表示"空单元"来混淆编号。

**数据范围与规模感受**

$$1\le M\le 100,\qquad 1\le N\le 1000,\qquad \text{单词编号}\le 1000 .$$

三个上界都在 $10^3$ 以内：$O(NM)$ 的线性查找暴力（$10^5$）都绰绰有余，正解 $O(N)$ 更不在话下。值域只有 $1001$，因此可以用一个大小 $1000+5$ 的布尔数组直接做「是否在内存」的 $O(1)$ 判定。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：这个"内存"到底是一台什么机器

把描述抽象一下：每个单词到来时，只发生两种事情之一——**命中**（内存已有）或**未命中**（内存没有）。未命中时所作的全部动作是「查外存一次 + 插入内存」，而插入内存的唯一副作用是当内存已满时挤掉"最早进入的那个"。因此整个系统可以由两个量完全刻画：**当前内存中有哪些单词**，以及**这些单词进入内存的先后顺序**。

先解决"要统计什么"这个最基础的问题：

**引理 1（查词典次数 = 未命中次数）**

设序列中"内存里没有该单词"的位置共有 $U$ 个，则最终需要去外存查词典的次数恰为 $U$。

**证明**：逐词考察题面规定的动作。

- 若某词 $w$ 命中（在内存中）：题面写"如果内存中有，软件就会用它进行翻译"——只有一次**内存内**查找，**不**去外存，也不插入。
- 若某词 $w$ 未命中：题面写"软件就会在外存中的词典内查找，查出……然后翻译，并将这个单词和译义放入内存"——恰好一次**外存**查找，随后一次插入。

于是每一次未命中贡献且仅贡献一次外存查找，每一次命中贡献 $0$ 次。按加法求和，总数恰为 $U$。$\blacksquare$

> 这条引理把问题从"统计一类动作的累计量"简化成了"统计序列中有多少位置满足一个谓词"，为后面的队列化铺平道路：我们只需要能 $O(1)$ 地判断"$w$ 是否在内存"。

### 2.2 一次归约：内存 $\equiv$ 一条先进先出队列

**引理 2（内存状态 = 未命中序列的"最近 $M$ 个"）**

设把序列中所有**未命中**的单词依次记为 $w_1,w_2,w_3,\dots$（$w_t$ 表示第 $t$ 次插入内存的单词）。那么在处理完整个序列后的任意时刻，内存中的单词集合恰为

$$\{w_t:\ t>\max(0,\,T-M)\},$$

其中 $T$ 是当前已发生的插入总次数；并且当内存满时被淘汰的顺序依次是 $w_1,w_2,\dots$（先进先出）。

**证明**（对插入次数 $T$ 归纳）：

- **基例** $T=0$：内存为空，"最近 $M$ 个插入"也是空集，成立。
- **归纳步**：设处理完 $T-1$ 次插入后内存恰为最近 $M$ 个插入 $w_{\max(1,T-M)},\dots,w_{T-1}$。现在发生第 $T$ 次插入 $w_T$：
  - 若当前内存大小 $\le M-1$：题面规定存入一个**未使用**单元，不淘汰任何词。新集合 = 旧集合 $\cup\{w_T\}$ = 最近 $M$ 个插入（因为旧集合本就只有 $T-1\le M-1$ 个元素，加一个仍不超过 $M$，且 $w_T$ 是最新的）。✓
  - 若当前内存大小 $=M$：题面规定清掉"最早进入内存的那个单词"。旧集合恰为 $\{w_{T-M},\dots,w_{T-1}\}$（最近的 $M$ 个），其中"最早进入内存的"就是 $w_{T-M}$（下标最小者即进入时间最早者）。清掉它再放入 $w_T$，新集合 $=\{w_{T-M+1},\dots,w_{T-1},w_T\}$ = 最近的 $M$ 个插入。✓
  - **命中**（插入 $w$ 的编号已在内存、无需再插）不发生插入，$T$ 不变，集合与顺序都保持，不影响结论。✓

归纳成立。同时可见淘汰总是从"下标最小"即最早插入者开始，退出的顺序正是 $w_1,w_2,\dots$，即先进先出。$\blacksquare$

> **为什么这条引理值得写**：它一次性把"清空最早进入的单词"这句自然语言翻译成了严格的数据结构语义——**队列**。「最新插入的在队尾，最老的插入在队头，满了就弹队头」。于是插入 = 入队、淘汰 = 出队，全部 $O(1)$。也顺带确认了：**命中不改变内存顺序**（这正是 FIFO 与 LRU 的分界，见 §2.3）。

### 2.3 关键辨析：为什么是 FIFO 而不是 LRU（附反例）

直觉很容易把"淘汰最老"误读成"淘汰最不常用"，从而在命中时把该词"刷新"到最新（贴到队尾）。请回头逐字确认题面：命中时的描述只有"用它进行翻译"，**没有**任何"更新该单词位置/时间"的动作；只有未命中插入时才谈顺序。"最早进入内存"锚定的是**首次插入时刻**，而不是最近一次使用时刻。因此命中**不**刷新。

这两套规则在多数数据上会得到相同的答案，但存在尖锐的对拍反例：

> **反例**：$M=2$，序列 `1 2 1 3 2`。
> - **FIFO（正确）**：`1` 未命中入 `[1]`；`2` 未命中入 `[1,2]`；`1` 命中；`3` 未命中，满则弹最早的 `1`，入 `[2,3]`；`2` 命中。查词典 **3** 次。
> - **LRU（错误）**：前三步同上；`1` 命中后把 `1` 贴到队尾 $\Rightarrow[2,1]$；`3` 未命中弹 `2` 入 `[1,3]`；`2` 此时**不在**内存，未命中，弹 `1` 入 `[3,2]`。查词典 **4** 次。

规则只差"命中时贴不贴队尾"，答案就差了 $1$。**判定依据只能是题面原文**：命中不产生插入动作，队列顺序不被改写 $\Rightarrow$ 严格执行 FIFO。

### 2.4 剖析另一个失败思路：淘汰时不撤标记

**失败：出队时忘了把被淘汰单词的"在内存"标记清掉。**

维护一个布尔数组 `inmem[]` 记录每个编号是否在内存。若入队时置 `true`，出队时却**忘记**置 `false`，那么一个早已被淘汰的单词仍会被判为"在内存"，导致后续真正的未命中被误判成命中，答案偏小。

> **反例**：$M=1$，序列 `1 2 1`。
> - 正确：`1` 未命中（查 $1$）；`2` 未命中，弹 `1` 入 `[2]`（查 $2$）；`1` 未命中，弹 `2` 入 `[1]`（查 $3$）。总 **3** 次。
> - 漏撤标记：`1` 入队置 `inmem[1]=true`；`2` 未命中、弹 `1` 但没清标记，`inmem[1]` 仍为 `true`；`1` 到来时被判命中（实际内存里只有 `2`）。总 **2** 次。少算了 $1$ 次。

$\Rightarrow$ **淘汰与置标记必须原子配对**：弹出队头 $q[\text{head}]$ 的同一条语句里就必须 `inmem[q[head]]=false`，再 `++head`。

### 2.5 越界与状态体检

| 量 | 范围 | 上界 | 数组尺寸 |
|---|---|---|---|
| 单词编号 $v$ | 题面给定 | $1000$ | `mxv{1005}`（含 $0$） |
| 队列长度（= 内存中单词数） | $\le M$ | $100$ | `q[mxn]`，但插入总数 $\le N$ |
| 插入总数（队尾下标 `tail`） | $\le N$ | $1000$ | `mxn{1005}` |

结论：全程 `int`/`bool` 足够。真正要防的是两类**静默错误**：

1. **队尾下标越界**：`tail` 最多推进到 $N$（每个单词至多入队一次），故数组开到 $N+5=1005$ 即可；不采用环形回绕也不越界。
2. **`inmem` 标记不撤**（§2.4），以及**读入顺序反了**（题面是"$M,N$"，即先内存容量后文章长度；样例 `3 7` 中 $M=3,N=7$），把两者读反会导致容量与长度互换，答案天差地别。

## 3. 模式总结（Pattern Summary）

**模式名：状态机模拟 —— 「容量 $M$ 的 FIFO 队列 + 布尔占用标记」。**

按真实思考顺序排列的可迁移标签：

- **explore its property** — 先把"内存"这台机器逐字拆解成"命中/未命中两种动作 + 满则挤掉最早进入者"，确认它只由「内容」和「进入顺序」两个量刻画。
- **reduce to easier problem** — 用引理 1 把"统计外存查找次数"这一个累计量，等价替换成"统计序列里有多少次未命中"，把问题降为一个谓词计数问题。
- **explore its property（第二次）** — 用引理 2 把"清空最早进入的单词"翻译成严格的数据结构语义：**先进先出队列**（入队 = 插入、出队 = 淘汰），顺带确认命中**不**改写顺序。
- **disambiguate by counterexample** — 用 `M=2` 的 `1 2 1 3 2` 反例把 FIFO 与 LRU 区分开，锁定"命中不刷新"。
- **classic problem solution** — 「队列 + 布尔占用数组」实现 $O(1)$ 判定与 $O(1)$ 淘汰，整体 $O(N)$。
- **atomic bookkeeping** — 出队与 `inmem` 清标记必须同一处完成，用 `M=1` 的 `1 2 1` 反例说明漏撤标记的危害。

**同族题 / 同源题**：

- **缓存替换策略族**：LRU（LeetCode 146 用哈希表 + 双向链表）、LFU、FIFO 的对比题，本质都是本题的"维护内容 + 顺序"结构，只是刷新规则不同。
- **前者把命中当成"使用一次"、后者把命中当成"无事发生"**——凡是题目里出现"最近使用/最早进入"这类措辞，第一件事就是确认命中是否刷新。

**一句话记忆**：**内存 = 容量 $M$ 的队列；统计入队次数即可；命中不刷新、淘汰要撤标记。**

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $M$ | `int`（全局 `m`） | 内存容量（单元数） | 读入 | 题面第一行第一个数 |
| $N$ | `int`（全局 `n`） | 文章单词数 | 读入 | 题面第一行第二个数 |
| $w_i$ | `int`（局部 `x`） | 当前单词的编号 | 逐词读入 | 值域 $[0,1000]$ |
| `q` | `int[mxn]` | **队列**：按插入先后存单词编号，仅使用 $[\text{head},\text{tail})$ 段 | 空 | 引理 2 的 FIFO 内存 |
| `head`,`tail` | `int` | 队头（下次被淘汰的下标）/ 队尾（下次插入的下标），`tail-head` = 当前内存中单词数 | 均 $0$ | 只增不回绕，故无环形取模 |
| `inmem` | `bool[mxv]` | `inmem[v]=true` $\iff$ 编号 $v$ 当前在内存中 | 全 `false`（全局默认） | $O(1)$ 命中判定 |
| `ans` | `int` | 已发生的未命中次数，即外存查词典次数 | $0$ | 引理 1 |

### 4.2 编号步骤

1. 读入 $M$、$N$（顺序：先容量后长度）；`head=tail=0`；`ans=0`。
2. 对 $i=0..N-1$ 读入单词 $x$：
   - 2.1 若 `inmem[x]` 为真 $\Rightarrow$ 命中，`continue`（引理 1：不计数）。
   - 2.2 否则 `++ans`（引理 1：未命中恰一次外存查找）。
   - 2.3 若 `tail-head==M`（满）$\Rightarrow$ **先** `inmem[q[head]]=false;` **再** `++head;`（§2.4 原子撤标记），弹出最早进入的词。
   - 2.4 `q[tail++]=x;`（入队）并 `inmem[x]=true;`。
3. 输出 `ans`。

### 4.3 复杂度

- 时间：每个单词 $O(1)$，总计 $O(N)\le 1000$ 步。
- 空间：`q` 约 $4$ KB、`inmem` 约 $1$ KB，远低于限制。
- 实测（见 §4.5）：最坏 $M=100,N=1000$（单词全互异）$0.0054$ s。

### 4.4 关键不变量

1. `tail-head` 恒等于当前内存中的单词数，且 $\le M$。
2. `q[head..tail)` 就是当前内存的单词，且按"进入时间"升序（队头最老）。
3. `inmem[v]==true` $\iff$ $v$ 出现在 `q[head..tail)` 中（原子维护保证）。
4. `ans` 恒等于目前已出现的未命中次数。

### 4.5 验证状态小结

| 官方样例回归 | **通过**：`3 7 / 1 2 1 5 4 4 1` $\to 5$ |

| 残余风险 | 若把 $M,N$ 读反，或出队时漏撤 `inmem` 标记，会静默给出错误答案（§2.4 §2.5 已说明） |

## 5. 示例代码

### 5.1 主解：FIFO 队列 + 布尔占用标记

```cpp
//
// 题目：P1540 [NOIP 2010 提高组] 机器翻译
// https://www.luogu.com.cn/problem/P1540
// AC
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{1005};          // N<=1000 (+5 松弛)
constexpr int mxv{1005};          // 单词编号 <=1000 (+5 松弛)

int m,n;
int q[mxn];                       // 内存队列:按进入顺序存单词编号(仅用 [head,tail))
int head=0,tail=0;                // 队头/队尾:tail-head 即当前内存中的单词数
bool inmem[mxv];                  // inmem[v]=单词 v 是否仍在内存中

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>m>>n;
	int ans=0;
	for(int i=0,x;i<n;++i)
	{
		cin>>x;
		if(inmem[x])              // 命中:内存中已有,不查词典
			continue;
		++ans;                    // 未命中:查一次外存词典
		if(tail-head==m)          // 内存已满:清空最早进入的那个单词
		{
			inmem[q[head]]=false;
			++head;
		}
		q[tail++]=x;              // 新词入内存
		inmem[x]=true;
	}
	cout<<ans<<'\n';
	return 0;
}
```

**代码结构对照**：`q/head/tail` 是引理 2 的 FIFO 队列（`tail++` 入队、`head++` 淘汰），`inmem` 是 $O(1)$ 命中判定，`ans` 是引理 1 的未命中计数。出队的 `inmem[q[head]]=false` 与 `++head` 必须成对出现（§2.4），这是全题唯一容易写错的静默陷阱。

### 5.2 对照实现：线性扫描内存（仅用于对拍）

```cpp
// 朴素暴力:用 vector 直接线性扫描内存,内存满则删除最早进入的元素
#include<bits/stdc++.h>
using namespace std;

int m,n;

int main()
{
	if(!(cin>>m>>n))
		return 0;
	vector<int> mem;                 // 按进入顺序存放内存中的单词
	int ans=0;
	for(int i=0;i<n;++i)
	{
		int x;
		cin>>x;
		bool found=false;
		for(int v:mem)
			if(v==x)
				found=true;
		if(found)
			continue;
		++ans;
		if((int)mem.size()==m)
			mem.erase(mem.begin());   // 移出最早进入的单词
		mem.push_back(x);
	}
	cout<<ans<<'\n';
	return 0;
}
```

两版**输出必须逐字节相同**（已用 $400$ 组随机数据确认）。这一版完全绕过队列下标与 `inmem` 数组，直接用 `vector` 按定义维护内存并按定义线性查找，因此可作为队列写法的独立交叉验证——若队列回绕、标记维护、淘汰顺序有 bug，这里会立刻暴露。代价是 $O(NM)$，在本数据范围内仍绰绰有余，但不能作为最优解法提交。

### 5.3 易错点清单

- **把 $M,N$ 读反**：题面顺序是"内存容量 $M$、文章长度 $N$"。
- **误当 LRU**：命中时把单词贴到队尾（§2.3 反例给出 $3$ vs $4$）。
- **出队漏撤 `inmem` 标记**：被淘汰的词仍被判为在内存（§2.4 反例给出 $3$ 变 $2$）。
- **满的条件写成 `tail-head>m` 或 `>=m`**：应为"已存 $M$ 个"即 `tail-head==m`。
- **`cout<<ans<<endl;`**：违反本项目风格指南，一律用 `'\n'`。
