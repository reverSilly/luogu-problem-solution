# P1572 计算分数

> 标签：模拟 · 字符串 · 洛谷原创 · 难度：普及-
> 本地题面：`P1572.md`（输入计算式长度 $\le100$，分子、分母 $\le1000$；Hint 保证逐步通分并立即约分时中间结果不超 `int`，答案各数在 $32$ 位带符号整数范围内）。验证：`appendix/P1572/` 对拍 $3600$ 组随机（标程 vs `__int128` 暴力 vs Python `Fraction` 神谕）$+900$ 组满规模（标程 vs `Fraction` 神谕）全部一致；官方样例 `2/1+1/3-1/4` → `25/12` 通过；最坏规模 $98$ 字符满值表达式单次 $0.73\text{ ms}$（含进程创建）。

## 1. 重新读题

**问题重述（人话版）**

输入一行分数计算式，只包含数字、`+`、`-`、`/`。它就是**若干个带符号的分数项排成一条水平线相加**：第一项前面可以有一个前缀 `-`（为正时连 `+` 都没有），项与项之间用 `+`/`-` 连接；每一项都是 `a/b` 的样子，`/` 是分数线，左边分子、右边分母。要求输出最终结果：是整数就按整数输出，否则按**最简分数**输出。

> 一句话版本：**把一条"带符号分数项的水平之和"精确算出来，约分到最简，按整数/分数两种格式输出。**

**题面里容易漏掉的条款**

1. 「计算式中只包含数字、`+`、`-`、`/`。其中 `/` 为分数线」$\Rightarrow$ 没有括号、没有乘除、没有空格、没有优先级。表达式就是一串项的**水平和**，而有理数加法满足结合律，所以**从左到右一项一项加**完全合法。
2. 「输入数据保证不会出现繁分数」$\Rightarrow$ 分数线两边必定是单纯整数，不会出现 `1/(2/3)` 这种嵌套。解析器可以放心假定：**每个项必定是 `数字/数字`**。
3. 「所有整数均以分数形式出现」$\Rightarrow$ 不存在裸整数（如 `1+1/2`），每个数都带 `/`。官方样例里的 `2/1` 就是整数 $2$ 的写法——这是本条的直接证据。
4. 「如果输入计算式的第一项为正，不会有前缀 `+` 号；若为负，会有前缀 `-` 号」$\Rightarrow$ 字符串只可能以 `-` 或数字开头；`+`/`-` 只出现在两项之间。**解析器不需要处理前导 `+`。**
5. 「保证答案内出现的所有数（如果答案是分数即为分子和分母）均在 $32$ 位带符号整数的表示范围之内」$\Rightarrow$ 最终输出的整数/分子/分母都在 `int` 范围内。
6. Hint 里藏的第三条数据范围：「直接从前往后直接计算分数的和或者差，然后立刻化简，这么做的中间结果不会超过 int 的范围」$\Rightarrow$ 这句话**只对"每步立即约分"成立**，它把测试数据卡在了这个性质上，是整道题最关键的一句话（见 §2.3 的反例：不立即约分就会爆）。
7. 「注意输入的分数不一定是最简分数」$\Rightarrow$ 不能假设 `a/b` 已约分；但只要累加器每步约分，非最简输入会被自动消化。
8. 「输入计算式长度在 $100$ 以内」$\Rightarrow$ 项数上界由此确定：最短的项是 `1/1`（$3$ 字符），$25$ 项加 $24$ 个运算符 $=99$ 字符，故**最多 $25$ 项**。

**数据范围与规模感受**

$$\text{长度}\le100\ (\Rightarrow\text{项数}\le25),\qquad a_i,b_i\le1000 .$$

总工作量就是 $O(\text{长度})$ 的线性扫描，数组都不用开。这道题真正的难点不在复杂度，而在三处：**(a)** 把藏在角落的格式条款（条款 2/3/4/6）翻译成正确的解析与算术策略；**(b)** 全链路保持精确，不能走浮点；**(c)** 用"每步立即约分"把中间量压在安全范围内。下面按真实思考顺序展开。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：这串字符到底在说什么

先把题面翻译成形式语言。综合条款 1–4，输入必然匹配

```
-?[0-9]+/[0-9]+([+-][0-9]+/[0-9]+)*
```

**引理 1（表达式结构）**

输入 $s$ 可唯一分解为 $t_0\ \mathrm{op}_1\ t_1\ \mathrm{op}_2\ t_2\ \cdots\ \mathrm{op}_{k-1}\ t_{k-1}$，其中每个 $t_i=a_i/b_i$ 都是「数字/数字」，$\mathrm{op}_i\in\{+,-\}$，且 $t_0$ 为正时前面没有符号、为负时前面恰有一个 `-`。

**证明**：$s$ 只含数字与 `+`、`-`、`/`。

- 无繁分数 $\Rightarrow$ 每个 `/` 的左右都是单纯数字串；「所有整数均以分数形式出现」$\Rightarrow$ 不存在不带 `/` 的裸数字串。于是每个极大数字串都被某个 `/` 收纳进某一项，项的形状必为 `数字/数字`。
- `+`/`-` 不可能出现在数字串内部：否则一个数字串会被切成两段，其中至少有一段不带 `/`（与上一条矛盾），或者出现 `/` 旁边直接跟符号（分数线右边就不是「单纯整数」了，违背「右边为分母」）。
- `+`/`-` 也不可能出现在串尾：其后若不跟任何字符，则最后一个「项」是空串，不含 `/`，矛盾。
- 所以 `+`/`-` 只能出现在两项之间；串首的 `-` 是首项的前缀符号（条款 4 保证为正时没有 `+`，故首部符号至多一个且只能是 `-`）。

按运算符切分即得上述唯一分解。$\blacksquare$

> 这条引理的价值：**解析器可以写到最简**——从头扫描，遇数字累乘，遇 `/` 切换分子/分母，遇 `+`/`-` 记录下一项符号。不需要词法分析器，不需要处理括号、优先级、一元减号。

### 2.2 考虑简化版：一项、两项、然后多项

先剥掉大部分项，看子任务：

- **子任务 A（只有一项 `a/b`）**：答案就是约分后的 $a/b$；若 $b\mid a$ 则输出整数。
- **子任务 B（两项 `a/b±c/d`）**：通分，$(ad\pm bc)/(bd)$，再约分。
- **一般情形（多项水平和）**：能不能"一项一项慢慢加"？这需要两样东西：一个累加公式，和"加法顺序无关"的许可。

**引理 2（累加公式）**

设累加器当前值为 $p/q$，新项为 $\mathrm{sg}\cdot a/b$（$\mathrm{sg}=\pm1$），则

$$\frac{p}{q}+\mathrm{sg}\cdot\frac{a}{b}=\frac{p\cdot b+\mathrm{sg}\cdot a\cdot q}{q\cdot b}.$$

**证明**：分数加法的定义就是把两个分数化为同分母 $qb$（$q>0,b>0$，故 $qb\neq0$）：$p/q=(p\cdot b)/(q\cdot b)$，$\mathrm{sg}\cdot a/b=(\mathrm{sg}\cdot a\cdot q)/(q\cdot b)$，分母相同，分子相加即得右端。等式成立，且全程只有整数乘与整数加，无精度损失。$\blacksquare$

**引理 2'（顺序无关）**

按任意结合顺序累加，结果相同。

**证明**：只需证有理数加法满足结合律。任取 $x=m/n,\ y=p/q,\ z=r/t$（分母均为正）：

$$(x+y)+z=\frac{mp+nq}{nq}+\frac{r}{t}=\frac{(mp+nq)t+r\cdot nq}{nqt},$$

$$x+(y+z)=\frac{m}{n}+\frac{pt+rq}{qt}=\frac{m\cdot qt+n(pt+rq)}{nqt}=\frac{mqt+npt+nrq}{nqt}.$$

两者分子都是 $mpt+nqt+nrq$，分母都是 $nqt$，故相等。由数学归纳法，任意结合顺序结果相同。$\blacksquare$

> 引理 2' 是「从左到右逐个处理项」的许可证：表达式的值不依赖于结合顺序，于是维护一个累加器、来一项加一项即可。

**引理 3（立即约分保值）**

设 $g=\gcd(\mathrm{num},\mathrm{den})$，$\mathrm{den}>0$，则 $(\mathrm{num}/g)/(\mathrm{den}/g)=\mathrm{num}/\mathrm{den}$。

**证明**：写 $\mathrm{num}=g\cdot u,\ \mathrm{den}=g\cdot v$（$g$ 整除二者），则 $\mathrm{num}/\mathrm{den}=(g u)/(g v)=u/v=(\mathrm{num}/g)/(\mathrm{den}/g)$。分子分母同除一个正因子，值不变。$\blacksquare$

**引理 4（约分后确为最简）**

$g=\gcd(\mathrm{num},\mathrm{den})$ 时，$\gcd(\mathrm{num}/g,\ \mathrm{den}/g)=1$。

**证明**（反证）：设 $d\ge2$ 整除以 $\mathrm{num}/g$ 与 $\mathrm{den}/g$，则 $dg\mid\mathrm{num}$ 且 $dg\mid\mathrm{den}$，于是 $dg\mid\gcd(\mathrm{num},\mathrm{den})=g$，从而 $d\mid1$，与 $d\ge2$ 矛盾。$\blacksquare$

> 引理 3+4 合起来说明：**每加一项就约分，不仅保值，还保证累加器始终最简**。于是终值天然就是最简分数，不需要最后再约一次；而且 $ \mathrm{num}=0 $ 时 $\gcd(0,\mathrm{den})=\mathrm{den}$，自动得到 $0/1$——这悄悄解决了「零的输出格式」（见 §2.5）。

### 2.3 失败思路 1：先通分到「公共分母 = 各分母之积」，最后统一约分

这是比"逐项累加"更诱人的批量想法：$D=b_1b_2\cdots b_k$，答案就是 $\big(\sum_i \mathrm{sg}_i a_i D/b_i\big)/D$，最后约一次分。算术路径简单直白。

**具体反例**：$14$ 个 `1/1000` 相加，即

```
1/1000+1/1000+…+1/1000     （14 项，97 字符，完全合法）
```

- 合法性：每步立即约分的中间量都不超过 $10^6$（累加值第 $i$ 步为 $i/1000$ 约分后，$|p|\le14$、$q\le1000$，未化简的 $|p\cdot b+\mathrm{sg}\cdot a\cdot q|\le 14\cdot1000+1000$、$q\cdot b\le10^6$），远在 `int` 内，是标准测试数据。
- 但按批量思路，$D=1000^{14}=10^{42}$——`int` 不用说，连 `__int128`（上限约 $1.7\times10^{38}$）都装不下，而真正的答案 $14/1000=7/500$ 只是个小小的分数。

**教训**：题面 Hint 的保证**只对"每步立即约分"成立**，不对"最后统一约分"成立。分母之积随项数指数爆炸，而约分后的中间量被数据范围死死压住。$\Rightarrow$ 必须每步约分。（自嘲式备注：我的 C++ 暴力基准用的恰恰就是这个会爆的思路，靠 `__int128` 只能撑到 $12$ 个 `1/1000`，$14$ 个就爆——所以 `check.py` 里另请了一位 Python `Fraction` 神谕来覆盖满规模，见 §5.2。）

### 2.4 失败思路 2：用 `double` 存分数，最后靠「连分数/容差」还原最简分数

心想：分数不就是小数吗，用 `double` 加完再还原成最简分数不就行了？

**具体反例**：单项 `1/3`。`double` 根本存不下 $1/3$，输出会变成 `0.3333333333333333` 一类的东西。就算对 `1/3+1/3+1/3` 这种碰巧凑回 $1.0$ 的特例靠 rounding 蒙混过关，`1/7+1/7=2/49` 也无法可靠还原——容差取多少？分母上界是多少？全是拍脑袋。

**教训**：答案要求的是「最简分数」这种**精确对象**，整条链路就必须走整数/精确有理数运算。引理 2 的交叉相乘公式全是整数乘加，没有任何精度损失——这是唯一安全的路。

### 2.5 失败思路 3：约分只做一半，或漏掉输出格式的两种特判

想着"输入的分数不一定最简，那我约分一下就行了"，于是只对输入项动手，不维护累加器的最简性。

**具体反例**：

- `1/2+1/2`：正确输出 `1`。不维护最简性会得到未约分的 $4/4$，输出 `4/4`。
- `4/2`：正确输出整数 `2`。若忘了 `q==1` 分支，会输出 `2/1`。
- `1/2-1/2`：结果是零，正确输出 `0`。未约分的累加器是 $0/4$；若约分实现没有考虑 $\gcd(0,q)=q$，就会残留 `0/4` 而不是 `0`。

**教训**：输出规则「整数用整数表示」靠 `q==1` 判定；零能自动落进这个分支，靠的正是引理 3 对 $\mathrm{num}=0$ 也成立（$0/\mathrm{den}\to0/1$）。约分不是可选的润色，而是正确性的一部分。

### 2.6 失败思路 4：符号处理想当然

**具体反例**：`-1/2-1/3`，正确答案 $-5/6$。两种典型翻车：把开头的 `-` 当成"项间运算符"去配一个空气左项；或者让每个 `-` 都触发"减去后面整个数"，而累加器本身已经为负，出现二次取反，得到 $+5/6$ 或 $-1/6$ 之类。

**教训**：符号只有两个来源——首项前缀（仅 `-`，条款 4）与项间运算符。标程的做法：**进循环前先把首项符号从 `s[0]` 取好**，之后每读一个运算符就更新 `sg`；累加公式 $p=p\cdot b+\mathrm{sg}\cdot a\cdot q$ 对两种符号一视同仁，符号永远只以乘数身份出现**一次**。

### 2.7 中间量真的有界吗？——把题面保证变成一条引理

标程用 `i64`。即使数据满足 Hint 保证，也要白纸黑字说清为什么绝不溢出。

**引理 5（中间量上界）**

若数据满足 Hint 保证（每步立即约分后的 $|p|$、$q\le M:=2^{31}-1$）且 $b\le1000$，则未化简的中间量满足

$$|p\cdot b+\mathrm{sg}\cdot a\cdot q|\le M\cdot1000+1000\cdot M=2\cdot10^{3}M<2^{43},\qquad q\cdot b\le10^{3}M<2^{42},$$

均远小于 `i64` 上限 $2^{63}-1\approx9.22\times10^{18}$（余量超过 $2^{20}$ 倍）。

**证明**：$|p\cdot b|\le M\cdot1000$（因子各自上界），$|\mathrm{sg}\cdot a\cdot q|\le1\cdot1000\cdot M$（$|\mathrm{sg}|=1$、$a\le1000$、$|q|\le M$），由三角不等式 $|p\cdot b+\mathrm{sg}\cdot a\cdot q|\le|p\cdot b|+|\mathrm{sg}\cdot a\cdot q|\le2\cdot10^3M$；$q\cdot b\le M\cdot1000$（$q>0$、$b\le1000$）。数值校验：$2\cdot10^3(2^{31}-1)\approx4.30\times10^{12}<2^{43}\approx8.80\times10^{12}$，$10^3(2^{31}-1)\approx2.15\times10^{12}<2^{42}\approx4.40\times10^{12}$，而 $9.22\times10^{18}/4.30\times10^{12}\approx2.1\times10^6>2^{20}$。$\blacksquare$

**引理 6（分母恒正）**

$q$ 的初值为 $1$，每步 $q\leftarrow q\cdot b$，而 $b\ge1$（分母是正整数），故 $q>0$ 恒成立；分数的符号完全由 $p$ 承载。

**证明**：归纳。第 $0$ 步 $q=1>0$；若某步之前 $q>0$ 且 $b\ge1$，则 $q\cdot b\ge q>0$。$\blacksquare$

> 引理 6 让输出规则极简：`q==1` 时输出整数 $p$（自动覆盖 $0$ 与负数），否则输出 `p/q`，分母天然为正、无需再搬符号。

### 2.8 收拢：算法全貌

读入一行 $\to$ 按引理 1 逐项解析 $\to$ 按引理 2 累加、引理 3/4 每步约分 $\to$ 按 `q==1` 分支输出。时间 $O(\text{长度})$，空间 $O(\text{长度})$（就一个字符串）。没有任何数据结构，全部难度都在"把条款读细 + 每条引理站得住"。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 把「只含数字与 `+-/`、无繁分数、整数必为 `a/b`、首项符号规则」四条格式条款合成一条正则，证明输入必为带符号分数项的唯一水平和分解（引理 1），解析因此不需要词法/优先级。
- **consider easier version** — 先解单项（约分后输出）与两项（交叉相乘通分）子任务，再借有理数加法结合律（引理 2'）把多项归结为同一个累加动作（引理 2）。
- **classic problem solution** — 分数加法 = 交叉相乘；「最简分数」的精确性要求把浮点还原思路直接判死（§2.4 失败 2），全程整数运算。
- **reduce to easier problem** — 每步立即约分（引理 3/4）把中间量压回 `int` 范围，把「批量通分」的分母积指数爆炸（§2.3 失败 1）消于无形。
- **incremental reduction** — 约分不是最后做而是每步做：保值、保最简，且让零自动变成 `0/1`、让终值免再约一次。
- **sign normalization** — 符号只以乘数 `sg` 出现一次（首项前缀 vs 项间运算符两个来源分清，§2.6 失败 4），配合 $q$ 恒正（引理 6），输出分支只需判 `q==1`。
- **bounds analysis** — 把 Hint 里「中间结果不超 int」形式成引理 5，证明 `i64` 全程无溢出、余量 $2^{20}$ 倍以上；并用反例说明该保证仅对逐步约分成立。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| `s` | `string`（全局） | 整个计算式（一行、无空格） | 读入 | `cin>>s` 一次吞掉整行 |
| `p`,`q` | `i64` | 累加器的分子 / 分母，当前值 $=p/q$ | `0`,`1` | accumulator；不变量 $q>0$（引理 6）、每步最简（引理 4） |
| `sg` | `int` | 当前项符号 $\pm1$ | `1`；`s[0]=='-'` 时为 `-1` | sign，来自首项前缀或项间运算符 |
| `i` | `int` | 扫描指针 | `0`；`s[0]=='-'` 时为 `1` | index |
| `len` | `int` | `s.size()` | — | 循环边界 |
| `a`,`b` | `i64`（循环内） | 当前项的分子 / 分母 | `0`,`0` | 每项重建：遇数字 `x=x*10+d` |
| `g` | `i64`（循环内） | $\gcd(|p|,q)$，每步重算 | — | 约分公因子（引理 3/4） |

### 4.2 编号步骤

1. `cin>>s` 读入整行；`i=0, sg=1`；若 `s[0]=='-'` 则 `sg=-1, i=1`（条款 4：首项为负才有前缀 `-`）。
2. 循环直至 `i==len`：
   1. 扫描连续数字得 `a`（分子）；`++i` 跳过 `/`（条款 2/3 保证它必在且右边是单纯数字）；扫描连续数字得 `b`（分母）。
   2. `p=p*b+sg*a*q; q=q*b;`（引理 2 的交叉相乘）。
   3. `g=gcd(p,q); p/=g; q/=g;`（引理 3 保值、引理 4 保最简；`p==0` 时自动得 `0/1`）。
   4. 若 `i<len`：读运算符 `s[i]` 更新 `sg`（`'-'` → `-1`，否则 `+1`），`++i`。
3. 输出：`q==1` 时输出整数 `p`（自动覆盖 `0` 与负数），否则输出 `p/q`（引理 6：分母恒正，符号全在 `p`，无需搬动）。

### 4.3 复杂度

- **时间**：$O(\text{len})$，$\text{len}\le100$；每个字符 $O(1)$ 次处理，外加每项一次 $O(\log\min(p,q))$ 的 `gcd`。
- **空间**：$O(\text{len})$，只有一个输入字符串，无数组。
- **实测**（§4.5）：最坏规模 $98$ 字符满值表达式单次 $0.726\text{ ms}$（含进程创建；算法本身远小于此）。

### 4.4 关键不变量（值得写 `assert` 的地方）

1. 每轮循环开始时，`p/q` 是已处理前缀的最简值，且 $q>0$（引理 4、6）。
2. `sg` 恰为下一项的符号，且只以乘数身份进入公式一次（§2.6 失败 4 的防护）。
3. 中间量 $|p\cdot b+\mathrm{sg}\cdot a\cdot q|<2^{43}$、$q\cdot b<2^{42}$（引理 5），`i64` 无溢出。
4. 循环结束时 `p/q` 即整个表达式的值且已最简（引理 2' 的顺序无关 + 引理 4）。

## 5. 示例代码

> 与 `appendix/P1572/P1572.cpp` **逐字节一致**。

```cpp
//
// 题目：P1572 计算分数
// https://www.luogu.com.cn/problem/P1572
// AC
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

string s;

i64 gcd(i64 a,i64 b)
{
	a=a<0?-a:a;
	b=b<0?-b:b;
	while(b)
	{
		i64 t=a%b;
		a=b;
		b=t;
	}
	return a;
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>s;
	int i=0,len=s.size();
	i64 p=0,q=1;              // 累加器:当前值=p/q;不变量 q>0,符号全在 p 上
	int sg=1;                 // 当前项符号
	if(s[0]=='-')             // 题面:首项为负才有前缀 '-',为正时连 '+' 都没有
	{
		sg=-1;
		i=1;
	}
	while(i<len)
	{
		i64 a=0,b=0;
		while(i<len&&s[i]>='0'&&s[i]<='9')
			a=a*10+(s[i++]-'0');
		++i;                  // 跳过 '/':题面保证所有整数都以 a/b 形式出现
		while(i<len&&s[i]>='0'&&s[i]<='9')
			b=b*10+(s[i++]-'0');
		p=p*b+sg*a*q;         // p/q+sg*a/b=(p*b+sg*a*q)/(q*b)
		q=q*b;
		i64 g=gcd(p,q);       // 每步立即约分:既保最简,又把中间量压回题面保证的范围内
		p/=g;
		q/=g;
		if(i<len)             // 还有下一项:读运算符
		{
			sg=(s[i]=='-')?-1:1;
			++i;
		}
	}
	if(q==1)
		cout<<p<<'\n';        // 整数(含 0)直接输出整数
	else
		cout<<p<<'/'<<q<<'\n';
	return 0;
}
```

**代码结构对照**：`p/q` 是引理 2 的累加器（初值 $0/1$ 即"空和"），`sg` 承载引理 1 分解出的符号，`gcd` 一步落实引理 3/4 的"立即约分"，`s[0]=='-'` 与 `i<len` 处的运算符读取分别吃掉条款 4 的首项前缀与项间运算符。`while(i<len&&...)` 的双边界（指针与长度）是逐字符扫描唯一需要小心的地方——少一个 `i<len` 就会在串尾越界（`check.py` 的神谕解析器第一版就犯了这个错，被样例直接抓出）。

### 5.2 对照实现：`__int128` 暴力基准（仅用于小规模对拍）

见 `appendix/P1572/P1572_brute.cpp`：按 `+`/`-` 边界把字符串切成若干项（与标程的逐字符扫描是不同的解析路径），再用**公共分母 = 各分母之积**一次性求和、最后统一约分（与标程的每步约分是不同的算术路径），全程 `__int128` 精确运算。两条路径都独立，可作为交叉验证基准；但公共分母随项数指数增长（§2.3 的反例：$14$ 个 `1/1000` 即达 $10^{42}$，超出 `__int128`），故只能覆盖小规模（项数少、分母之积 $\le10^{37}$）。满规模由 `appendix/P1572/P1572_check.py` 内置的 Python `Fraction` 神谕（独立解析 + 任意精度精确求和）覆盖。三方在 $3600$ 组小规模数据上逐字节一致，标程与神谕在另 $900$ 组满规模数据上一致。

### 5.3 易错点清单

- **想批量通分、最后统一约分** $\Rightarrow$ $14$ 个 `1/1000` 公分母 $10^{42}$ 直接爆（§2.3 失败 1）；必须每步立即约分。
- **用 `double` + 容差还原最简分数** $\Rightarrow$ 单项 `1/3` 就无法精确表示（§2.4 失败 2）；全程整数交叉相乘。
- **忘掉 `q==1` 的整数分支** $\Rightarrow$ `4/2` 输出 `2/1` 而非 `2`（§2.5）。
- **零结果** $\Rightarrow$ 靠 $\gcd(0,q)=q$ 自动得到 `0/1`、输出 `0`；约分实现不处理 `num==0` 会残留 `0/4`。
- **首项 `-` 被当成项间运算符** $\Rightarrow$ 符号二次取反（§2.6 失败 4）；进循环前先取首项符号，之后只读项间运算符。
- **试图解析前导 `+`/裸整数/括号/空格** $\Rightarrow$ 题面明文不存在这些形态；按条款 2/3/4 把解析器写到最简才是正解。
- **逐字符扫描漏掉 `i<len` 边界** $\Rightarrow$ 串尾越界；数字扫描循环的两个 `while` 都必须带长度条件。
- **用 `int` 存中间量** $\Rightarrow$ 满足 Hint 保证时确实安全（这正是 Hint 的意义所在）；标程用 `i64` 把余量再放大 $2^{20}$ 倍以上（引理 5）。
- **`cout<<...<<endl;`** $\Rightarrow$ 违反本项目风格指南，一律用 `'\n'`。
