# P1413 坚果保龄球

> 标签：贪心 · 难度：普及- · 来源：kkksc03 改编 · **本地题面无样例**

## 1. 重新读题

**问题重述（把机制翻译成大白话）**

- 地图 $6$ 行 $\times\;60$ 列。zombie 在时刻 $t$ 出现在它那一行的第 $60$ 列，之后每秒左移一格。
- 玩家可以在**任意时刻**选定**某一行**滚出坚果保龄球，该时刻**这一行**上还在场的所有 zombie 被瞬间碾死。
- zombie 走到第 $1$ 列后再往左走，大脑就被吃掉 ⇒ 每只 zombie 必须在"它还站在盘上"的这段时间里，被本行的某一颗坚果覆盖。
- 求消灭全部 $n$ 只 zombie 所需的最少坚果数。

**目标**：最小化"滚坚果"这个动作的**次数**（不是时间、不是存活时长）。

**数据范围**：$n\le 2000$，$t\le 10^5$，$1\le P\le 6$，输入不保证按行或按时间有序。
范围很小（$2000$），说明 $O(n\log n)$ 甚至 $O(n^2)$ 都够用；真正考的是**建模是否正确**，而不是优化。

**陷阱与边界**

1. **字段顺序**：输入每行是 `P t`（行号在前、时刻在后）。读成 `t P` 会把 $t\le10^5$ 塞进行号里，直接越界或答案全错。
2. **重复出现**：题面明说"可能会同时出现同一位置的僵尸"，即同一 $(P,t)$ 可有多只。它们区间完全相同，贪心会把它们并进同一组，**不能**去重后当作"少一只"（去重不影响答案，但不能漏计数逻辑），更不能因为"已经杀过一次"就跳过。
3. **空行**：只有 $1\sim 6$ 中出现过的行才贡献坚果数，没 zombie 的行贡献 $0$，不能无脑 `ans+=6`。
4. **时刻从 1 开始**（"$t$ 为正整数"），但算法不依赖下界，任何平移都不影响结果。
5. **端点约定之争（$t+59$ 还是 $t+60$）**：zombie 在 $t$ 秒位于第 $60$ 列，$t+59$ 秒位于第 $1$ 列，$t+60$ 秒就走出棋盘。所以"离散时刻"模型里它可被 $[t,t+59]$ 这 $60$ 个整数时刻中的坚果杀死；"连续时间"模型里可被 $[t,t+60)$ 内的任意实数时刻杀死。**两种模型给出的答案相同**，因为所有出现时刻都是整数：
   - 离散：$[a,a+59]\cap[b,b+59]\ne\varnothing\iff|a-b|\le 59$；
   - 连续：$[a,a+60)\cap[b,b+60)\ne\varnothing\iff|a-b|<60\iff|a-b|\le 59$（$a,b\in\mathbb Z$）。
     多个区间的公共交同样都等价于"极差 $\le 59$"（区间族的交非空 $\iff\max l\le\min r$，两个模型都化为 $\max t-\min t\le 59$）。
     于是任何"选点打穿区间族"的方案数在两个模型下一致，代码里写 `a[i].t+59` 或 `a[i].t+60` 配合对应的比较符号，只要前后一致就得到同一答案。本文统一取**闭区间 $[t,t+59]$**。
6. **贪心判据陷阱**：判断"两只能不能共用一颗坚果"看的是**组内极差**而不是**相邻差**，反例见 §2.2。

## 2. 思维链（Chain-of-thought）

### 2.1 探索特殊机制 —— 一颗坚果到底杀了谁

先不管"最少"，先把一次操作到底发生了什么写清楚。

**引理 1（可杀时刻区间）**
在第 $P$ 行、时刻 $t$ 出现的 zombie，被"在时刻 $T$ 于第 $Q$ 行滚出的坚果"杀死，当且仅当 $Q=P$ 且 $t\le T\le t+59$。

**证明**：分四支。

- *行必须相同*：题面说坚果是"在某一行第一列"滚出、"这一行的 zombie 瞬间全被滚过去的坚果碾死"。坚果沿着一行滚动，不会跳到别的行。故 $Q\ne P$ 时该 zombie 不受影响（$Q=P$ 是必要的一支）。
- *$T\ge t$ 是必要的*：$T<t$ 时这只 zombie 还没出现，盘上没有它，滚坚果自然杀不到它。
- *$t\le T\le t+59$ 时一定杀到*：zombie 每秒左移一格，$T$ 秒时位于第 $60-(T-t)$ 列。$T-t\in[0,59]$ 时该列号 $\in[1,60]$，即它此刻**仍在棋盘上且尚未走出第 $1$ 列**；而坚果在时刻 $T$ 扫过该行所有列，故被碾死。
- *$T\ge t+60$ 时不可能再杀*：$T=t+60$ 时它已经走出棋盘（题面：走到第 $1$ 列后再向左走则大脑被吃），也就是说任何合法方案都不允许把坚果拖到这个时刻，$T>t+59$ 属于非法情形。

把上面合成："这只 zombie 能被杀的时刻集合"恰为闭区间 $I=[t,\,t+59]$（按 §1 第 5 点，换成 $[t,t+60)$ 结论不变）。$\blacksquare$

> 记号：**把每只 zombie 变成一个区间 $I_i=[t_i,\,t_i+59]$，把一次滚坚果变成一个"时刻点 $T$"，且这个点还带着"行号"这个标签。**

**引理 2（行独立）**
设 $R_p$ 为第 $p$ 行 zombie 集合对应的区间族，$g(\cdot)$ 为打穿一个区间族所需的最少点数，则全局答案 $=\sum_{p=1}^{6}g(R_p)$。

**证明**：
- "$\ge$"：任一全局方案里，每个时刻点只作用在一行上，把方案按行拆开，第 $p$ 行用到的点数记 $k_p$，则 $\{k_p\}$ 打穿了 $R_p$，故 $k_p\ge g(R_p)$，求和得总点数 $\ge\sum_p g(R_p)$。
- "$\le$"：对每行各取一个达到 $g(R_p)$ 的最优点集，把 $6$ 套方案的时间表并起来执行。不同行的操作互不干扰（引理 1 中"行必须相同"），因此这就是一个合法的全局方案，点数 $=\sum_p g(R_p)$。
  两者合并即得等号。$\blacksquare$

> **机制小结**：本题 = **$6$ 个互不相干的"区间选点"（minimum stabbing points）子问题之和**。行号这个维度已经被彻底剥离，剩下的只有"时间轴上的区间"。

**顺带的有用推论**：既然行之间无关，实现时"先按行分桶（或排序）再各行独立贪心"即可，行间不需要任何协调——这一点后面在 §4 变成代码结构。

### 2.2 简化版 —— 只剩一行时题目长什么样

**先剥掉"6 行"这个维度**：假设所有 zombie 都在第 $1$ 行，出现时刻为 $t_1,\dots,t_m$。问题变成：选尽量少的整数时刻 $T_1,\dots,T_k$，使每个 $[t_i,t_i+59]$ 都包含某个 $T_j$。

**引理 3（共组判据）**
设 $S$ 是同一行的若干只 zombie，它们能被**同一颗**坚果全部杀死 $\iff$ $\max_{i\in S}t_i-\min_{i\in S}t_i\le 59$。

**证明**：记 $a=\min_{i\in S}t_i$、$b=\max_{i\in S}t_i$。所有区间的交为
$$\bigcap_{i\in S}[t_i,t_i+59]=[\max_i t_i,\ \min_i(t_i+59)]=[b,\ a+59]$$
（因为 $\min_i(t_i+59)=a+59$）。存在一颗坚果杀光 $S$ $\iff$ 这个交非空 $\iff b\le a+59\iff b-a\le 59$。逐条核实：
- **非空 $\Rightarrow$ 可行**：若 $b\le a+59$，取 $T=b$。对任意 $i\in S$：$t_i\le b=T$ 满足下界；$t_i\ge a\Rightarrow t_i+59\ge a+59\ge b=T$ 满足上界。故 $T\in[t_i,t_i+59]$ 对全体成立，在 $T$ 时刻滚一颗即可。
  （注意：取 $T=b+59$ 是**不行**的，它超出最早那只的右端点 $a+59$；交里的任何点都行，最省事的就是取左端点 $b$。）
- **可行 $\Rightarrow$ 非空**（反证）：若 $b-a\ge 60$ 却存在 $T$ 杀光 $S$。由引理 1 需 $T\in[a,a+59]$ 故 $T\le a+59$；又需 $T\in[b,b+59]$ 故 $T\ge b\ge a+60>a+59$，矛盾。$\blacksquare$

> **推论（本题最重要的一个"等价说法"）**：一行所需的最少坚果数 = **把该行的时刻集合划分成尽量少的组，使每组的极差 $\le 59$**。

**贪心失败剖析：为什么"相邻差 $\le 59$ 就并组"是错的**

初学时的直觉版本：把时刻排序，只要 $t_{i+1}-t_i\le 59$ 就把 $i+1$ 并进 $i$ 所在的组，只有出现"断层"（差 $\ge 60$）才新开一颗坚果。它错在把**局部性质当成全局性质**——极差是"累积"的量，相邻差小不代表跨度小。

具体小反例（单行 $3$ 只）：$t=1,\;51,\;101$。
- 相邻差：$51-1=50\le 59$，$101-51=50\le 59$ ⇒ 错误贪心给出 **1 颗**。
- 真实情况：三者的区间是 $[1,60],\,[51,110],\,[101,160]$，公共交 $=[\max(1,51,101),\,\min(60,110,160)]=[101,60]=\varnothing$，一颗坚果杀不完（引理 3 的极差 $101-1=100>59$ 也直接判死）。
- 正确答案 **2 颗**：在 $T=60$ 滚一颗（杀 $t=1$ 于第 $1$ 列、杀 $t=51$ 于第 $51$ 列），再在 $T=120$ 滚一颗（杀 $t=101$）。手算核对：$60\in[1,60]$ ✓、$60\in[51,110]$ ✓、$120\in[101,160]$ ✓。
- 而且 2 是下界：$[1,60]$ 与 $[101,160]$ 不相交，一颗坚果最多带走其中一只。

失败的模式可以一般化：**"并查集式"地按相邻差合并会造出极差任意大的组**（把 $1,51,101,151,\dots$ 串成一条链）。正确的判据必须锚定在"组的第一只"上：只要当前时刻还满足 $t_i\le t_{\text{组首}}+59$ 才允许进组，否则立刻新起一颗坚果。这个"以组首的右端点为闸门"的写法，恰好就是经典解法。

### 2.3 经典解法 —— 区间选点：按右端点排序，贪心打点

"每个区间必须含一个点，求最少点数"是**经典·区间选点**（与"雷达覆盖""活动安排"同源）。标准做法：

> 按**右端点**从小到大排序；维护上一个已打的点 $last$（初始 $-\infty$）；扫到区间 $[l,r]$ 时，若 $last<l$ 就**新增一个点 $p\leftarrow r$**。

为什么打在最靠右的位置（右端点）而不是最靠左？直觉：右端点尽量"往后伸手"，能顺便覆盖更多后面来的区间。下面把它写成严格证明。

**引理 4（贪心安全性 / 交换论证）**
设剩余区间中右端点最小的是 $I^*=[l^*,r^*]$。则存在一个最优解，它包含点 $r^*$。

**证明**：取任意最优解 $O$（点数最少的点集）。$O$ 必须打穿 $I^*$，故存在 $x\in O\cap I^*$。构造 $O'=(O\setminus\{x\})\cup\{r^*\}$，$|O'|=|O|$（若 $r^*$ 已在 $O$ 中则结论已成立，以下设 $x\ne r^*$）。只需证 $O'$ 仍打穿所有区间。
任取 $O$ 中被 $x$ 覆盖的区间 $J=[l_J,r_J]$，即 $l_J\le x\le r_J$。要证 $r^*\in J$：
- 由 $x\in I^*$ 知 $x\le r^*$，于是 $l_J\le x\le r^*$，即 $r^*\ge l_J$ ✓（不越过左端点）。
- 由 $r^*$ 是**全体剩余区间中最小的右端点**知 $r^*\le r_J$ ✓（不越过右端点）。
故 $r^*\in J$，$J$ 在 $O'$ 下仍被覆盖；$O$ 里其他点没被移动，所以它们覆盖的区间照旧。于是 $O'$ 也是最优解且含 $r^*$。$\blacksquare$

**引理 5（贪心解 = 下界，故最优）**
贪心依次选出的点 $p_1<p_2<\dots<p_k$ 所对应的"触发区间" $I^{*}_1,\dots,I^{*}_k$ 两两不相交；而任意合法方案的点数 $\ge k$。

**证明**：分三支。

- *可行性（贪心自己一定合法）*：扫描指针按右端点升序经过每个区间 $[l,r]$。轮到它时只有两种情况：① $last\ge l$，它已被上一个点打穿；② $last<l$，于是在它自己的右端点打新点 $p=r$，而 $r\in[l,r]$ 恒成立，它被这个新点打穿。两种情况都不需要"回头"，指针单调前进，故结束时**每个区间都被打穿**，贪心给出一个含 $k$ 个点的合法方案。
- *两两不相交*：设第 $j$ 次打点 $p_j=r_j$（触发区间 $I^{*}_j=[l_j,r_j]$）。第 $j+1$ 次的触发区间 $I^{*}_{j+1}=[l_{j+1},r_{j+1}]$ 是排序后第一个满足 $l_{j+1}>p_j$ 的区间（否则它会被 $p_j$ 或更早的点打穿，不触发新点）。于是 $r_j=p_j<l_{j+1}$，即相邻两个触发区间一左一右不重叠。对不相邻的 $u<v$，把相邻关系串起来：
$$r_u<l_{u+1}\le r_{u+1}<l_{u+2}\le\cdots\le r_{v-1}<l_v$$
（用到每个区间自身 $l_j\le r_j$），故 $r_u<l_v$，$k$ 个触发区间两两不相交。注意这段论证**没有**用到"$l$ 随排序单调"，所以对一般（非等长）区间也成立。
- *下界*：$k$ 个两两不相交的区间，一个点最多落在其中一个里，故任何合法方案至少要用 $k$ 个点。
  上界（可行性）= 下界（$k$）$\Rightarrow$ 贪心方案点数最少。$\blacksquare$

对本题，所有区间长度都是 $60$，所以"按右端点排序"和"按左端点排序"给出的顺序**完全一致**（$r_i=t_i+59$ 与 $t_i$ 同序），代码里只要对时刻排序即可，不用真的算出 $r$ 再排。贪心的"打点 $r$"翻译成游戏语言就是：**发现某只 zombie 救不了的瞬间，立刻在它到达第 $1$ 列的那一刻（$t+59$）滚坚果**——这颗球顺带把该行"在它之后出现、且此刻还没走出棋盘"的所有 zombie 一起带走。

### 2.4 归约到更简单的问题 —— 排序后切成尽量少的"极差 $\le 59$"连续段

引理 3 把问题写成"划分成最少的组，组内极差 $\le 59$"。**组可以要求是连续段吗？** 直觉上"随便分组"比"必须切成连续段"更宽松，所以连续段版本的答案可能更大，必须证明两者相等。

**引理 6（分组可取连续段）**
把一行时刻排序为 $t_1\le\dots\ t_m$。则"任意分组（每组极差 $\le59$）的最少组数" $=$ "把该序列切成连续段（每段极差 $\le59$）的最少段数"。

**证明**：记 $A=$ 任意分组的最少组数，$B=$ 连续段切分的最少段数。显然 $A\le B$（连续段切分是分组的一种特例，放宽"必须连续"不会使答案变差）。下面证反向 $A\ge B$。
- 设存在 $k$ 组（可交叉）的合法分组 $\mathcal{G}$，$k\ge A$。取 §2.3 引理 5 中贪心产生的 $k'$ 个**两两不相交**的区间 $I_1,\dots,I_{k'}$。断言：它们属于 $\mathcal{G}$ 中**互不相同**的组。反设 $I_u,I_v$（$u\ne v$）同在某组 $G$ 中，则 $G$ 极差 $\le59$，由引理 3 证明中的交式 $[\max t,\ \min t+59]$（非空）知 $G$ 内所有区间两两有公共点，从而 $I_u\cap I_v\ne\varnothing$，与两两不相交矛盾。故 $k\ge k'$，即 $A\ge k'$。
- 贪心的 $k'$ 个点恰好把排序序列切成 $k'$ 个**连续段**（每颗坚果带走的是"当前未覆盖前缀"的一段），所以 $B\le k'$。
- 合并：$A\ge k'\ge B$，与 $A\le B$ 夹出 $A=B=k'$。$\blacksquare$

> **归约结果**：一行 = 排序后从左往右扫描，"当前段首 $s$ 固定，只要 $t_i\le s+59$ 就继续加人，否则就地封口、新开一段"。段数即答案。这正是 §2.3 的经典贪心在"等长区间"上的退化形态——所以两套论证可以互相印证。

**再用 DP 校一遍贪心（也给出 `fill_n` 的坑）**

对一行排序后的时刻，记
$$j_i=\min\{j\le i:\ t_i-t_j\le 59\},\qquad f[i]=\text{前 }i\text{ 只的最少组数},\ f[0]=0$$
最后一段一定是 $[m..i]$ 的形式且 $m\ge j_i$，故
$$f[i]=1+\min_{m\in[j_i,i]}f[m-1]$$
**断言 $f$ 单调不减**：取前 $i+1$ 只的最优划分（$f[i+1]$ 组），删掉第 $i+1$ 只（若它独占一组就顺手删掉这个空组），得到前 $i$ 只的一个**合法**划分，组数 $\le f[i+1]$；而 $f[i]$ 是前 $i$ 只组数的最小值，故 $f[i]\le f[i+1]$。
于是 $\min$ 在最小的下标 $m=j_i$ 处取到（$f[m-1]$ 随 $m$ 不减），
$$f[i]=f[j_i-1]+1\tag{$\ast$}$$
**引理 7（贪心数 $=$ DP 数）**：记 $c_i=$ 贪心在前 $i$ 个元素里已经开启的段数（即"段首下标 $\le i$"的段数），则 $f[i]=c_i$ 对所有 $i$ 成立，特别地 $f[m]=c_m$ 就是贪心答案。

**证明**：约定 $c_0=0$。对 $i$ 归纳，设贪心的段首依次为 $s_1<s_2<\dots$。归纳假设"$f[\cdot]=c_\cdot$ 对下标 $<i$ 成立"；因 $j_i\ge1$，有 $j_i-1<i$，故 $f[j_i-1]=c_{j_i-1}$，代入 $(\ast)$ 得 $f[i]=c_{j_i-1}+1$。于是只剩一件事要证：
$$c_{j_i-1}+1=c_i\iff\text{下标区间}[j_i,i]\text{ 内恰好有一个贪心段首}.$$
- **至少一个**：设 $s_k$ 是 $\le i$ 的最后一段的段首。贪心保证该段极差 $\le59$，故 $t_i-t_{s_k}\le 59$，按 $j_i$ 的定义（最小的满足 $t_i-t_j\le59$ 的下标）得 $s_k\ge j_i$；又 $s_k\le i$。所以 $s_k\in[j_i,i]$ ✓
- **至多一个**（反证）：若还有下一段段首 $s_{k+1}\le i$，则贪心之所以在 $s_{k+1}$ 断开，是因为 $t_{s_{k+1}}>t_{s_k}+59$。由排序与 $s_{k+1}\le i$ 得 $t_i\ge t_{s_{k+1}}>t_{s_k}+59$，即 $t_i-t_{s_k}>59$，于是 $s_k<j_i$，与上一条的 $s_k\ge j_i$ 矛盾 ✓
- 基例 $i=1$：$j_1=1$，$f[1]=f[0]+1=1=c_1$ ✓。$\blacksquare$

> 注意"恰好一个段首"这件事**并不**意味着 DP 的切法和贪心的切法一模一样（例：$t=1,50,61$，$j_3=2$，$(\ast)$ 给 $f[3]=f[1]+1=2$，DP 眼中最后一段是 $\{50,61\}$，贪心的最后一段却是 $\{61\}$）——两者**数量**恒等，方案可不唯一。这也顺带说明"最少坚果数"可能有多种摆法。
（实现提示：$j_i$ 随 $i$ 单调不减（$t_i$ 不减 $\Rightarrow$ 门槛 $t_i-59$ 不减），可双指针 $O(m)$ 求出，或 `lower_bound(t+1,t+i+1,t_i-59)` 二分 $O(m\log m)$。）

坑：全局 `int f[mxn]` 默认值是 **0**，而 DP 里"未定义/不可达"要的是 $+\infty$。若把转移写成"对所有 $m$ 取 $\min$"而不加 $m\ge j_i$ 的下界限制，就**必须**先 `fill_n(f,mxn,inf)`（或 `fill_n(&f[0][0],mxn*mxn,inf)` 处理二维），否则 0 会被当成一个合法的 0 组方案，答案恒为 $1$ 之类的怪值。本文的正解只用 $f[0]=0$ 递推，不依赖 INF，所以 §5 代码里不需要 `fill_n`；DP 版若要写，就得老老实实填。

**另一种实现路线（值域扫描，$O(6\max t)$）**：$t\le10^5$ 很小，可给每行开一个 `bool have[mxt]` 记录"该行在这一秒有 zombie 出现"（重复时刻压成 `true` 是安全的：完全相同的区间对选点数的贡献是 1，多几只不会多要一颗坚果）。然后对每行 $p$ 从 $0$ 扫到 $\max t$：遇到 `have[x]` 为真就 $\mathtt{++}ans$，并把指针跳到 $x+60$。这与"段首 + 59 封口"一模一样，只是把"排序"换成了"值域枚举"。$n$ 小、$\max t$ 也小，两种都不卡常。

### 2.5 复杂度与溢出防护

逐项核对量级，确认 `int`（$\approx 2.1\times10^9$）够不够：

| 量 | 上界 | 是否溢出 | 说明 |
|---|---|---|---|
| $t_i$ | $10^5$ | 否 | 输入本身 |
| $t_i+59$ | $100059$ | 否 | 打点时刻 $r$；离 `int` 上限还差 4 个数量级 |
| 组内极差判定 $t_i\le r$ | 同数量级 | 否 | 只做比较，**没有乘法** |
| $ans$ | $\le n\le 2000$ | 否 | 每颗坚果至少带走一只，故 $ans\le n$ |
| 数组下标 | $n\le2000$ | 否 | `mxn{2005}`（+5 松弛）够用 |

结论：本题**全程 `int` 安全**，不需要 `i64`。真正需要留意的"数值型陷阱"是**比较方向/边界**而不是溢出：

- 写成 `a[i].t<=r`（含等号）而不是 `<`：$t=r$ 时该 zombie 此刻刚出现在第 $60$ 列，坚果同时在滚，能杀到。若用 `<`，$t=1,60$ 两只会被判成 2 颗（错，应为 1 颗）。
- $r$ 必须取**段首**的 $t+59$，不能取"上一只的 $t+59$"再累加，否则又会退化成 §2.2 的相邻差错误。
- 如果哪天把题面改成 $t\le10^{18}$ 或加上"每颗坚果有伤害值/多列判定"出现乘积，就要用 `i64`（本项目惯用 `using i64=long long;`）；`int` 的 $10^9$ 附近做加法（如 `mid=(l+r)/2`）也要提防，习惯上写 `(l+r)>>1` 之前先确认 $l+r$ 不爆。

**复杂度**：排序 $O(n\log n)$；扫描一遍 $O(n)$；总共 $O(n\log n)$ 时间、$O(n)$ 空间（值域扫描版为 $O(\max t\cdot 6+n)$ 时间、$O(\max t\cdot 6)$ 空间）。$n=2000$ 时两者都远远不到限制，写法以不易出错为准。

## 3. 模式总结（Pattern Summary）

按**真实思考顺序**逐条列出（同一步骤出现两次就写两条，不合并）：

- 探索特殊机制 — 把"滚坚果"这个动作翻成"在时刻轴上打一个带行标签的点"，于是每只 zombie 变成可杀时刻区间 $[t,t+59]$。
- 降维 / 按独立维度分治 — 一次操作只影响一行 ⇒ 行与行无关，答案 = 各行子问题之和（先按 $P$ 排序分桶）。
- 考虑简化版 — 剥掉"6 行"，只在单行上想清楚"什么是一组"，得到"组 $\iff$ 极差 $\le 59$"（引理 3）。
- 剖析贪心失败 — "相邻差 $\le 59$ 就并组"把局部性质当全局，被 $t=1,51,101$（答案 2 而非 1）推翻，暴露出判据必须锚在**段首右端点**。
- 经典问题解法 — **区间选点**：按右端点升序，遇到没被打穿的区间就在其右端点打点；交换论证（引理 4）证明"打右端点"永远能替换进某个最优解。
- 下界证明（匹配即最优）— 贪心打出的 $k$ 个点对应 $k$ 个两两不相交区间，任何方案至少要 $k$ 个点，上界 = 下界（引理 5）。等长区间还额外让"按右端点排"退化成"按出现时刻排"。
- 归约到更简单问题 — 再等价改写成"排序后切成最少数量的极差 $\le 59$ 连续段"，并用两侧夹逼证明"允许交叉分组"不会更优（引理 6）；这一步让贪心的实现形态（双条件 while）一眼可见。
- 经典问题解法（第二次）— **线性 DP + 单调性**：$f[i]=1+\min_{m\in[j_i,i]}f[m-1]$，由 $f$ 单调不减化简为 $f[i]=f[j_i-1]+1$，与贪心逐步一致，作为独立校验；顺带引出"全局数组默认 0，不可达状态必须 `fill_n(...,inf)`"的移植坑。
- 值域枚举替代排序 — 因 $\max t\le10^5$，可开 `bool have[]` 按秒扫描，同一段贪心换一种实现（$O(6\max t)$）。
- 溢出防护与边界核对 — 逐项检查 $t+59\le100020$、$ans\le n\le2000$，确认全程 `int`；真正的坑是**比较符号含不含等号**而不是溢出。

## 4. 真实解法

**符号表**（每个符号：存什么 / 怎么初始化 / 一句话记忆）

| 符号 | 类型与定义 | 含义 | 记忆 |
|---|---|---|---|
| `mxn{2005}` | `constexpr int` | 数组尺寸，$n\le2000$ 加 5 松弛 | "上界 +5，宁虚高不越界" |
| `dly{59}` | `constexpr int` | 从第 $60$ 列走到第 $1$ 列所需的秒数 $=$ 区间长度 $60$ 减 $1$ | $r=t+dly$ |
| `struct zombie{int p,t;}` | 纯聚合结构体 | 一只 zombie：所在行 $p$（$1\!\sim\!6$）、出现时刻 $t$ | 区间就是 $[t,\,t+dly]$ |
| `a[mxn]` | 全局静态数组 | 全部 $n$ 只，读入后**就地**按 $(p,t)$ 升序排 | 行优先、时刻次之 |
| `n` | `int` | zombie 总数，循环一律 `i<n`（**0-based**，故不做 `--p`，行号只用于比较大小） | — |
| `ans` | `int`，初值 $0$ | 已使用的坚果数 | 每开一段 $+1$ |
| `p` | `int`（段首行号） | 当前段所属行，用于"只在本行内合并" | 段首锁行 |
| `r` | `int`（段首 $t+dly$） | 本行这一段坚果的**打点时刻**，也是这段的覆盖闸门 | "段首的右端点" |
| `i` | `int` | 排序数组的游标；外层 `for(int i=0;i<n;)` **不带自增**，靠内层 `while` 推进 | 谁消费谁推进 |

**步骤**

1. 读入 $n$，把 $n$ 条 $(P,t)$ 原样存进 `a[0..n-1]`（**注意字段顺序**，先 $P$ 后 $t$）。
2. 用 lambda 比较器 `sort(a,a+n,...)`：行号不同按行号升序，行号相同按时刻升序。行号维度的排序 = 引理 2 的"按行分桶"；时刻维度的排序 = §2.3 的"按右端点排序"（区间等长，故按左端点同序，引理 3 之后的说明）。
3. 外层 `for(int i=0;i<n;)`（无 `++i`）：
   1. `++ans` —— 为 `a[i]` 这只"当前最靠左端点的最小右端点区间"新打一颗坚果（引理 4 的贪心选择）。
   2. 记住段首的 `p=a[i].p` 与闸门 `r=a[i].t+dly`（**段首**，不是上一只；见 §2.5 第二条）。
   3. 内层 `while(i<n&&a[i].p==p&&a[i].t<=r) ++i;` —— 把同一行、且满足 $t\le r$（等价于 $r\in[t,t+dly]$，因为段首时刻 $\le t$）的 zombie 全部划进这一段。三个条件缺一不可：`i<n` 防越界、`p` 相同防跨行、`t<=r` 是引理 3 的极差判据（含等号，见 §2.5 第一条）。
   4. 由于段首自己一定满足三条件，`while` 至少消费 $1$ 个元素 ⇒ 循环必然终止（每轮 $i$ 严格增大）。
4. 输出 `ans<<'\n'`。

**复杂度**：$O(n\log n)$ 时间、$O(n)$ 空间（$n\le2000$）。

**验证状态**（**本地题面 `P1413.md` 无样例，无法与官方答案对标**；按任务约束**未编译、未运行**任何代码，全部为纸面手算）

- **用例 1（混合行 + 重复 + 空行）**：$n=7$，$(1,1),(1,51),(1,101),(3,7),(3,7),(5,200),(6,1)$。
  排序后 `ans` 逐步：段首 $(1,1),r=60$ 吃掉 $1,51$ ⇒ $ans=1$；段首 $(1,101),r=160$ ⇒ $ans=2$；段首 $(3,7),r=66$ 吃掉两只 $t=7$ ⇒ $ans=3$；$(5,200),r=259$ ⇒ $ans=4$；$(6,1),r=60$ ⇒ $ans=5$。**输出 5**。

- **用例 2（$59/60$ 边界）**：$n=3$，$(1,1),(1,60),(1,61)$ ⇒ $r=60$ 覆盖 $t=1,60$，$t=61$ 另起一段，**输出 2**。
  物理核对：$60$ 时刻第一只正好站在第 $1$ 列（最后一秒）、第二只刚出现在第 $60$ 列，一颗扫全行；第三只 $61$ 才出现，$60$ 的球打不到它，必须再一颗。若把 `<=` 误写成 `<`，本例会输出 3，说明"含等号"这条边界确实被抓到了 ✓
- **用例 3（全重复 / 极差恰好 59）**：$n=4$，$(2,10)$ 四次 ⇒ 一段吃完，**输出 1**；再加一只 $(2,69)$（$69-10=59$）仍 $r=69\ge69$ ⇒ **1**；改成 $(2,70)$（差 60）⇒ **2**。手工验证交 $[70,69]=\varnothing$，一颗确实不行 ✓
- **用例 4（§2.2 反例）**：$n=3$，$(1,1),(1,51),(1,101)$ ⇒ 正解 **2**（段首 $r=60$ 吃 $1,51$，再一段吃 $101$），而"相邻差"错误贪心给 1，本用例可区分两种实现 ✓
- **用例 5（单行最坏链）**：第 1 行 $n=1667$ 只，$t_i=1+60(i-1)$（末项 $99961\le10^5$ 合法），相邻差恰好 $60>59$ ⇒ 每只独占一段，**输出 1667**；最大的 $r=99961+59=100020$，验证 $r$ 与 $ans$ 都远在 `int` 之内 ✓
- **用例 5b（答案上界可达）**：$n=2000$，第 1 行放上面那 $1667$ 只，第 2 行放 $333$ 只 $t=1+60(i-1)\ (i=1..333)$，末项 $19921$，两段链互不干扰 ⇒ **输出 2000**，说明 $ans\le n$ 这个上界是紧的（同时再次验证 `a[i].p==p` 让跨行的同刻 zombie 无法共用坚果）✓
- **用例 6（行独立）**：$n=6$，行号 $1\sim6$ 各一只、时刻全为 $100$ ⇒ **输出 6**（时刻相同但不同行绝不共用坚果），验证 `a[i].p==p` 这个条件的作用 ✓
- **交叉校验（非对拍）**：§2.4 的 DP $f[i]=f[j_i-1]+1$（引理 7 保证它与贪心同值）在上述用例上逐步复核：用例 4（$t=1,51,101$）$j=(1,1,2)$ ⇒ $f=[1,1,2]$，与贪心的"段首 $1$（闸门 $60$）、段首 $101$"同为 $2$ ✓；用例 2（$t=1,60,61$）$j=(1,1,2)$ ⇒ $f=[1,1,2]$ ✓；用例 1 第 1 行同用例 4，第 3 行（$t=7,7$）$j=(1,1)$ ⇒ $f=[1,1]$，两行合计与手工分组的 $5$ 一致 ✓。**未做随机对拍、未运行程序**，因此不声明任何"对拍通过 / 耗时"结论。

## 5. 示例代码

```cpp
// https://www.luogu.com.cn/problem/P1413
// 每只 zombie = 区间 [t,t+59]；按 (行,时刻) 排序后做"区间选点"贪心，行内一段一颗
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{2005};            // n<=2000，+5 松弛
constexpr int dly{59};              // 第 60 列走到第 1 列耗时 59 秒

struct zombie{int p,t;}a[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	int n;
	cin>>n;
	for(int i=0;i<n;++i)
		cin>>a[i].p>>a[i].t;			// 注意先 P 后 t
	sort(a,a+n,[](const zombie&x,const zombie&y){return x.p!=y.p?x.p<y.p:x.t<y.t;});

	int ans=0;
	for(int i=0;i<n;)
	{
		++ans;
		int p=a[i].p,r=a[i].t+dly;	// 段首的右端点当闸门，跨行/超时都停
		while(i<n&&a[i].p==p&&a[i].t<=r)
			++i;
	}
	cout<<ans<<'\n';
	return 0;
}
// 手算用例 1（输出应为 5）：
// 7
// 1 1
// 1 51
// 1 101
// 3 7
// 3 7
// 5 200
// 6 1
```

**另一种实现（值域 DP 版，仅示意，含 `fill_n` 的正确姿势）**：把贪心换成 §2.4 的 $f[i]=f[j_i-1]+1$，或者更朴素地写成"枚举上一段的结束位置取 $\min$"，此时**未定义状态是 $+\infty$，而全局 `int` 数组默认 $0$**，必须显式填满：

```cpp
constexpr int mxt{100005};          // max t + 5 松弛
constexpr int inf{1145141919};      // 114514 家族哨兵
int f[mxn],lst[mxn],ans=0;          // lst[p]=该行上一颗坚果的打点时刻
// 若把 f 写成"对所有 m 取 min"的形式：
// fill_n(f,mxn,inf); f[0]=0;       // 不填就会把 0 当成合法的 0 组方案
for(int i=0;i<n;++i)
{
	if(lst[a[i].p]<a[i].t)			// 上一颗打不穿 [t,t+59]
		++ans,lst[a[i].p]=a[i].t+dly;
}
```

（这段"逐只扫描 + 记录各行上一颗坚果时刻 `lst[p]`"与 §5 主写法等价：因为排序后同段内 $t$ 递增、$r$ 固定，`lst[p]<a[i].t` 与"越出段首闸门"同一条件；`lst` 初值 $0$ 在这里**恰好安全**，因为 $t\ge1>0$，不存在"0 被误当成可达状态"的问题——但换成时刻可以为 $0$ 的变体题就得 `fill_n(lst,mxn,-1)` 或干脆用 $-1$ 哨兵。）
