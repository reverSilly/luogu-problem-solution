# P1509 找啊找啊找朋友

> 标签：动态规划 DP / 背包 DP · 难度：普及/提高-
> 本地题面：`P1509.md`（$1\le n,m,r\le100$，$1\le rmb_i,rp_i\le100$，$1\le time_i\le1000$）。验证：官方样例 `13`；400 组随机对拍全过；最坏 $n=m=r=100$ 约 $0.007$ s。

## 1. 重新读题

**问题重述（人话版）**

有 $n$ 个任务。完成第 $i$ 个任务要花 $rmb_i$ 预算、$rp_i$ 点人品、$time_i$ 时间。你手头有 $m$ 预算、$r$ 人品，两者**是总量上限、不能透支**。请选出一个任务子集，使得所选任务的预算总和 $\le m$、人品总和 $\le r$；先让**完成的（不同）任务数量最多**，在数量相同的情况下再让**总时间最少**。输出那个最小总时间；如果一个任务也完不成，输出 $0$。

> 一句话版本：二维费用（预算、人品）的 $0/1$ 背包，目标函数是"先最大化物品数，再最小化总价值（时间）"的字典序双目标。

**题面里容易漏掉的条款**

1. 「sqybi 在一个时刻只能去泡一个 MM」$\Rightarrow$ 这是对"任务逐个顺次完成"的文学解释，与选择子集、求总时间无关（总时间就是所选任务的时间之和；同时进行并不会使总时间变短）。**它不构成任何额外约束。**
2. 「保证搞到 MM 数量最多的情况下花费的总时间最少」$\Rightarrow$ 目标是**字典序双目标** $(−数量,\ +时间)$，即先按数量取大，再按时间取小；不是"先时间后数量"，也不是"数量×时间"之类的加权。
3. 「如果他没能力泡到任何一个 MM……消耗的时间为 0」$\Rightarrow$ 空集恒可行，答案下界是 $0$；数量为 $0$ 时输出 $0$。**不存在无解分支。**
4. 预算与人品是**两个互相独立**的上限（不能把两者合并成一个"总代价"）。见 §2.5 失败 3/4 的反例。

**数据范围与规模感受**

$$1\le n,m,r\le100,\qquad 1\le rmb_i,rp_i\le100,\qquad 1\le time_i\le1000 .$$

状态数 $(m+1)(r+1)\le 101^2\approx10^4$，每件物品对每个状态做一次转移，总开销 $O(nmr)=100\times100\times100=10^6$——**三维皆 $10^2$ 的宽裕规模**。任何 $2^n$ 的子集枚举在 $n=100$ 时必挂，提示正解是背包 DP。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：把问题翻译成"受两条资源约束的子集选择"

记第 $i$ 个任务的资源三元组 $p_i=(rmb_i,rp_i,time_i)$。一次方案就是把任务编号分成"做/不做"两部分，即选一个下标子集 $S\subseteq\{1,\dots,n\}$。方案 $(S)$ 的
$$\text{预算}(S)=\sum_{i\in S}rmb_i,\quad \text{人品}(S)=\sum_{i\in S}rp_i,\quad \text{数量}(S)=\lvert S\rvert,\quad \text{时间}(S)=\sum_{i\in S}time_i .$$

**引理 1（问题模型）**

题目要求：在满足 $\text{预算}(S)\le m$ 且 $\text{人品}(S)\le r$ 的所有 $S$ 中，先取 $\lvert S\rvert$ 最大者、再在其中取 $\text{时间}(S)$ 最小者。$\blacksquare$（直接翻译题面，无需证明。）

> 这一步把"泡 MM"彻底翻译成"在两条独立资源线上选子集、目标为字典序双目标"。总时间只是被选任务时间之和，与顺序无关——题面那句"一个时刻只能泡一个"并不改变总和。

### 2.2 考虑简化版：砍掉一条资源

**单资源版**：若只有预算 $m$ 一条上限，目标为"最大化数量、其次最小化时间"，这就是经典的 $0/1$ 背包（价值取"数量"、再加一层时间做 tie-break）。

**引理 2（单资源 DP 的形态）**

单资源版状态 $g[j]$ 表示"预算 $\le j$ 时的最优 $(\text{数量},\text{时间})$"，转移自 $g[j-rmb_i]$ 加一个任务。$\blacksquare$

单资源版给我们的启示是：**多一条资源，就给状态多一维**——把 $g[j]$ 升成二维 $dp[j][k]$（预算维 $\times$ 人品维），转移同时扣两条资源即可。于是问题归约成标准的**二维费用 $0/1$ 背包**。

### 2.3 核心难点：目标是一对值，不是标量

普通背包的"价值"是一个数，取 $\max$ 天经地义。本题目标却是字典序对：先比数量、再比时间，且两个方向相反（数量要大、时间要小）。必须先用一个**全序**把它变成"可以取 $\max$ 的标量式对象"。

**定义 1（字典序 $\preceq$）** 对两个状态 $x=(cnt_x,tm_x)$、$y=(cnt_y,tm_y)$，规定
$$x\succeq y\iff cnt_x>cnt_y\ \text{或}\ \big( cnt_x=cnt_y\ \text{且}\ tm_x\le tm_y\big).$$
即"数量大者胜；数量相同则时间小者胜"。

**定义 2（合并算子 $\oplus$）** 往状态里加入任务 $i$：$x\oplus i:=(cnt_x+1,\ tm_x+time_i)$。空状态用恒等元 $\varnothing=(0,0)$。

**引理 3（$\oplus$ 对 $\succeq$ 单调）**

若 $x\succeq y$，则 $x\oplus i\succeq y\oplus i$。

**证明**：分两种情形。

- 若 $cnt_x>cnt_y$：则 $cnt_x+1>cnt_y+1$，按定义 1 立刻有 $x\oplus i\succeq y\oplus i$。
- 若 $cnt_x=cnt_y$ 且 $tm_x\le tm_y$：则 $cnt_x+1=cnt_y+1$，且 $tm_x+time_i\le tm_y+time_i$，按定义 1 仍有 $x\oplus i\succeq y\oplus i$。$\blacksquare$

**引理 4（$\succeq$ 是全序且 $\varnothing$ 最小）**

$\succeq$ 是状态集上的全序（任意两状态可比），且对任意 $x$ 有 $x\succeq\varnothing$。

**证明**：任意两状态 $x,y$，先比 $cnt$——若不等则大者胜、若相等则比 $tm$——$tm$ 也有大小，故一定分出胜负（相等则两者等价），全序成立。$\varnothing=(0,0)$ 的 $cnt=0$ 是最小可能数量，故 $x\succeq\varnothing$。$\blacksquare$

> 引理 3、4 是"能不能对一堆状态安心取 $\max$"的全部依据：$\oplus$ 保序（引理 3）保证"用更优的前缀能得到更优的拼接"；$\succeq$ 是全序（引理 4）保证任意两候选一定可比、不会出现"互相不占优"的僵局。

### 2.4 一次归约：二维费用 $0/1$ 背包

**定义 3（DP 状态）** 设 $dp[j][k]$ 表示"只用已经考虑过的那批任务、预算总用量 $\le j$ 且人品总用量 $\le k$ 时的最优状态（$\succeq$ 意义下）"。

**引理 5（DP 正确性）**

按"逐任务考虑、对每个任务做 `dp[j][k]=better(dp[j][k],\ dp[j-rmb_i][k-rp_i]\oplus i)`"更新，处理完全部任务后 $dp[j][k]$ 恰为"在所有 $\le j,\le k$ 约束下能达到的最优状态"。

**证明**（对已考虑任务数 $t$ 归纳）：

- **基例** $t=0$：只有一个空子集，状态 $\varnothing$。$dp[j][k]$ 初值是 $(0,0)=\varnothing$，与"$\le j,\le k$"相容（空集资源用量 $0\le j,k$），成立。
- **归纳步**：设处理完前 $t-1$ 个任务后 $dp$ 正确，记作 $dp_{0}$。引入第 $t$ 个任务后，任一子集 $S$ 分两类：
  - $t\notin S$：其状态由 $dp_0[j][k]$ 给出；
  - $t\in S$：令 $S'=S\setminus\{t\}$，则 $S'$ 是前 $t-1$ 个任务的子集，且预算 $\le j-rmb_t$、人品 $\le k-rp_t$（因 $rmb_t,rp_t\ge0$）；设 $S'$ 的最优状态为 $dp_0[j-rmb_t][k-rp_t]$，由引理 3 单调知 $S$ 的状态 $\preceq dp_0[j-rmb_t][k-rp_t]\oplus t$，且取 $S'$ 为最优子集时等号可达。
  - 两类候选的 $\max$（由引理 4 全序保证可比）即 $dp_{\text{new}}[j][k]$，等于"引入第 $t$ 个任务后的最优状态"。$\blacksquare$

> 注意这里 $dp$ 的语义是"**用量 $\le$ 容量**"（不是"恰好等于"）：初值处处 $\varnothing$（空集），凡是"$\le$"的容量都容纳空集，正是这种写法。它使得最后**只需读 $dp[m][r]$**，无需在其他容量上再取一遍 $\max$。

**引理 6（倒序枚举 $\Rightarrow$ 每件物品至多用一次）**

把容量维的循环写成 $j$ 从 $m$ 递减、$k$ 从 $r$ 递减，则转移读到的是**本轮未被改写的** $dp[j-rmb_i][k-rp_i]$，即"没选第 $i$ 件"的旧状态；每件物品至多用一次。

**证明**：处理第 $i$ 件时，转移只读下标 $(j-rmb_i,\ k-rp_i)$，其中 $j-rmb_i<j$、$k-rp_i<k$ 且 $rmb_i,rp_i\ge1$。在两重倒序下，所有"下标不更大"的格子都**尚未**在本轮被改写，故读到的是旧值（引理 5 归纳步所需的 $dp_0$）。若改成正序，则会读到本轮已更新的 $dp[j-rmb_i][k-rp_i]$，等价于允许第 $i$ 件被反复取用（完全背包），与"每件只有一个"矛盾。$\blacksquare$

### 2.5 剖析几个失败思路（都给出具体反例）

**失败 1：把目标当成"先时间后数量"。**
反例：$m=r=2$，两个任务 $(1,1,1000)$、$(1,1,1)$。先最小化时间只会取第 $2$ 个：数量 $1$、时间 $1$；而题目要数量优先，正解是两者都取：数量 $2$、时间 $1001$。数量不同，直接判失败。

**失败 2：$dp$ 只优化时间、不记录数量。**
反例：$m=r=3$，三个任务 $A=(1,1,1000)$、$B=(1,1,1)$、$C=(1,1,1)$。"最小时间"会只取 $B$，输出 $1$；但三者预算/人品各为 $3\le3$，可全取，数量 $3$ 才是主目标，正解是时间 $1002$。只存时间会把主序丢掉。$\Rightarrow$ 状态必须同时携带数量与时间。

**失败 3：把两条资源合并成一条（如用 $rmb+rp$ 当总代价）。**
反例：$m=2,r=2$，单个任务 $A=(3,1,\cdot)$。真实约束要求预算 $\le2$，故 $A$ 不可选，答案 $0$；但若按合并容量 $m+r=4$ 做一维背包，会认为 $3+1=4\le4$ 可行而选中 $A$，输出非零。**根因**：可行域是矩形 $[0,m]\times[0,r]$，不是三角形 $rmb+rp\le m+r$。$\Rightarrow$ 必须开二维状态。

**失败 4：把容量语义写成"恰好装满"。**
反例：$m=r=3$，单个任务 $A=(1,1,5)$。若 $dp$ 是"恰好用满 $j,k$"语义，则 $dp[3][3]$ 对应"恰好用掉 $3$ 预算、$3$ 人品"，而 $A$ 只用了 $1,1$，于是 $dp[3][3]$ 反而为空，输出 $0$；真答案 $5$。**根因**：题目约束是"$\le$ 容量"，故 $dp$ 必须用"容量 $\le$"语义（初值处处空集），最后只读 $dp[m][r]$。

### 2.6 答案与边界

**引理 7（答案 $=dp[m][r]$ 的时间分量）**

答案 $=dp[m][r].tm$；当 $dp[m][r].cnt=0$（泡不到任何人）时该值为 $0$。

**证明**：由引理 5，$dp[m][r]$ 是全部可行子集里 $\succeq$ 最优者，其 $cnt$ 最大、在最大 $cnt$ 下 $tm$ 最小，正是题目所求，取其时间分量即答案。若最优 $cnt=0$，说明只有空集可行，按题面消耗时间 $0$。$\blacksquare$

### 2.7 越界与状态体检

| 量 | 范围 | 上界 | `int` 够？ |
|---|---|---|---|
| $n,m,r$ | 题面 | $100$ | 是 |
| $rmb_i,rp_i$ | 题面 | $100$ | 是 |
| $time_i$ | 题面 | $1000$ | 是 |
| 总时间（最多 $100$ 个任务） | $n\cdot\max time$ | $10^5$ | 是 |

结论：**全程 `int` 足够**（最大和 $10^5$，远未溢出）。要防的是：

1. **状态用一个数而不是一对**：必须同时存 `cnt` 与 `tim`（失败 4）。
2. **内层两重循环都必须倒序**（引理 6），否则退化为"每件可重复取"。
3. **`dp` 初值处处是 $(0,0)$**（空集），这正是"$\le$ 容量"语义；不要改成"恰好装满"的 $-\infty$ 初值，那样还得对 $m,r$ 以外容量再扫一遍。

## 3. 模式总结（Pattern Summary）

按真实思考顺序排列，每条一行：

- explore its property — 把"泡 MM"翻译成"在预算、人品两条独立资源线上选子集 + 字典序双目标"（引理 1）。
- consider easier version — 砍掉一条资源得到单资源 $0/1$ 背包，确认"多一条资源 = 状态多一维"（引理 2）。
- reduce to easier problem — 二维费用 $0/1$ 背包：状态 $dp[j][k]$（引理 5）。
- lexicographic encoding — 把"先数量后时间"这一对目标编码成全序状态 $(cnt,tm)$（定义 1），使其可被 $\max$ 处理。
- monotonicity lemma — 证明合并算子 $\oplus$ 对全序单调（引理 3），这是"对状态取 $\max$"合法性的根据。
- classic problem solution — 二维费用背包用倒序两重循环实现"每件至多一次"（引理 6，与 P1504 的倒序一维同源）。
- tie-break inside DP — 在转移处直接以字典序比较，而不是先算最优数量再第二遍算时间（失败 4）。
- answer reading — 语义是"容量 $\le$"，故只读 $dp[m][r]$（引理 7）。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $n$ | `int` | 任务数 | 读入 | 题面 |
| $m$ | `int` | 预算上限 | 读入 | 题面 |
| $r$ | `int` | 人品上限 | 读入 | 题面 |
| `rmb[i]` | `int [105]` | 第 $i$ 个任务的花费 | 读入 | 题面 |
| `rp[i]` | `int [105]` | 第 $i$ 个任务的人品 | 读入 | 题面 |
| `ti[i]` | `int [105]` | 第 $i$ 个任务的时间 | 读入 | 题面（**不可命名 `tm`，与 `<time.h>` 的 `struct tm` 冲突**） |
| `cnt[j][k]` | `int [105][105]` | 预算 $\le j$、人品 $\le k$ 时的最大任务数 | 全 $0$ | 状态主序 |
| `tim[j][k]` | `int [105][105]` | 对应最大任务数下的最小总时间 | 全 $0$ | 状态次序 |
| `c2` | `int`（局部） | 候选状态的数量 | — | `cnt[j-rmb][k-rp]+1` |
| `t2` | `int`（局部） | 候选状态的时间 | — | `tim[j-rmb][k-rp]+ti[i]` |

> 助记：`cnt`=count（主序），`tim`=time（次序）；`ti[i]` 是第 $i$ 件的时间。

### 4.2 编号步骤

1. 读入 $n$，再读 $n$ 组 `rmb[i],rp[i],ti[i]`，最后读 `m`、`r`。
2. `cnt[*][*]`、`tim[*][*]` 保持全局零初始化（即处处空状态 $(0,0)$）。
3. 对每个任务 $i=0..n-1$：对 $j=m$ 递减到 `rmb[i]`、$k=r$ 递减到 `rp[i]`：
   3.1 `c2=cnt[j-rmb[i]][k-rp[i]]+1`，`t2=tim[j-rmb[i]][k-rp[i]]+ti[i]`；
   3.2 若 `c2>cnt[j][k]` 或（`c2==cnt[j][k]` 且 `t2<tim[j][k]`），则把 `cnt[j][k]=c2`、`tim[j][k]=t2`。
4. 输出 `tim[m][r]`。

### 4.3 复杂度

- 时间：$O(nmr)\le100\times100\times100=10^6$ 次转移。
- 空间：两张 $105\times105$ 的 `int` 表，约 $0.09$ MB，远低于 $125$ MB。
- 实测（见 §4.5）：$n=m=r=100$ 约 $0.007$ s（含进程启动）。

### 4.4 关键不变量（值得写 `assert` 的地方）

1. 处理完前 $t$ 件后，`cnt[j][k]`、`tim[j][k]` 是"$\le j,\le k$ 约束下 $\succeq$ 最优状态"（引理 5）。
2. 任意时刻 `cnt[j][k]` 单调不减于 $j,k$（容量越大可选子集越多）。
3. 倒序循环保证每件至多一次（引理 6）。
4. `cnt[j][k]==0` 时恒有 `tim[j][k]==0`。

### 4.5 验证状态小结

| 项目 | 状态 |
|---|---|
| 官方样例回归 | **通过**：样例 `4 / (1,2,5)(2,1,6)(2,2,2)(2,2,3) / 5 5` $\to$ `13`（标程与暴力一致） |
| 随机数据对拍 | **通过**：$400$ 组随机小规模（$n\le12$、$m,r\le12$，资源与容量随机，含超容量件），DP 与 $2^n$ 子集枚举**逐字节一致** |
| 边界用例 | **通过**：泡不到 $\to0$；恰好装下 $4$ 个 $\to4$；人数优先于时间 $\to1001$；只有一件可泡 $\to999$；两件单独可行取时间小 $\to5$；资源差一点泡不到 $\to0$ |
| 最坏规模计时 | $n=m=r=100$、全 $(1,1,1000)$：输出 `100000`，最快约 **$0.007$ s**（含进程启动） |
| 残余风险 | 状态语义是"容量 $\le$"，若误改成"恰好装满"（初值 $-\infty$）会漏掉"未用满容量"的最优方案 |

## 5. 示例代码

### 5.1 主解：二维费用 $0/1$ 背包 + 字典序 tie-break（与 `appendix/P1509/P1509.cpp` 逐字节一致）

```cpp
//
// 题目：P1509 找啊找啊找GF
// https://www.luogu.com.cn/problem/P1509
// AC
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{105};   // n<=100 (+5 松弛)
constexpr int mxr{105};   // m,r<=100 (+5 松弛)

int n,m,r;
int rmb[mxn],rp[mxn],ti[mxn];
int cnt[mxr][mxr];        // cnt[j][k]=预算<=j 且点数<=k 时能泡到的最大人数
int tim[mxr][mxr];        // tim[j][k]=在最大人数前提下的最小总时间

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
		cin>>rmb[i]>>rp[i]>>ti[i];
	cin>>m>>r;

	for(int i=0;i<n;++i)
		for(int j=m;j>=rmb[i];--j)
			for(int k=r;k>=rp[i];--k)
			{
				int c2=cnt[j-rmb[i]][k-rp[i]]+1;
				int t2=tim[j-rmb[i]][k-rp[i]]+ti[i];
				if(c2>cnt[j][k]||(c2==cnt[j][k]&&t2<tim[j][k]))
				{
					cnt[j][k]=c2;
					tim[j][k]=t2;
				}
			}

	cout<<tim[m][r]<<'\n';
	return 0;
}
```

**代码结构对照**：`cnt[j][k]` 与 `tim[j][k]` 一起构成状态 $(cnt,tm)$；`if(c2>cnt...||(c2==cnt...&&t2<tim...))` 就是定义 1 的字典序比较；两重倒序是引理 6；输出 `tim[m][r]` 是引理 7。

### 5.2 对照实现：$2^n$ 子集枚举（仅用于小规模对拍）

```cpp
//
// 题目：P1509 找啊找啊找GF (暴力基准)
// https://www.luogu.com.cn/problem/P1509
// 仅用于小规模对拍: 枚举全部子集, 先取人数最大再取时间最小
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{25};

int n,m,r;
int rmb[mxn],rp[mxn],ti[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
		cin>>rmb[i]>>rp[i]>>ti[i];
	cin>>m>>r;

	int bc=0,bt=0;            // 最多人数 及 该人数下的最小总时间
	for(int mask=0;mask<(1<<n);++mask)
	{
		int sr=0,sp=0,st=0,c=0;
		for(int i=0;i<n;++i)
			if(mask>>i&1)
			{
				sr+=rmb[i];sp+=rp[i];st+=ti[i];++c;
			}
		if(sr<=m&&sp<=r&&(c>bc||(c==bc&&st<bt)))
		{
			bc=c;
			bt=st;
		}
	}
	cout<<bt<<'\n';
	return 0;
}
```

两版输出**逐字节相同**（$400$ 组随机数据确认）。暴力按定义穷举每个任务做/不做，独立于背包转移，可交叉验证引理 5/6；代价 $O(2^n n)$，不能提交。

### 5.3 易错点清单

- **把目标反成"先时间后数量"** $\Rightarrow$ 数量优先是硬要求（失败 1 反例）。
- **把数量与时间加权成一个标量** $\Rightarrow$ 字典序无法用固定权重实现（失败 2）。
- **把预算与人品合并成一维代价** $\Rightarrow$ 可行域是矩形而非三角形（失败 3）。
- **状态只存时间不存数量** $\Rightarrow$ 丢掉了主序（失败 4）。
- **内层正序** $\Rightarrow$ 每件可重复取，答案偏大（应为倒序，引理 6）。
- **`ti` 误写成 `tm`** $\Rightarrow$ 与 `<time.h>` 的 `struct tm` 名字冲突，编译期报 ambiguous（本项目实测踩过）。
- **`cout<<...<<endl;`** 违反项目风格，一律 `'\n'`。
