# P1550 [USACO08OCT] Watering Hole G

> 标签：图论 / 贪心 / 生成树 / 超级源点 / 并查集 · 难度：普及/提高-
> 本地题面：`P1550.md`（$1\le n\le 300$，$1\le W_i\le 10^5$，$0\le P_{i,j}\le 10^5$）。验证：300 组随机对拍（枚举候选边子集暴力验证）+ 2 组手工用例全部通过，最坏规模 $n=300$ 耗时 约 0.010 s。

## 1. 重新读题

**问题重述（人话版）**

有 $n$ 块田地。使所有田地都能供上水，有两种花钱方式：

- 在第 $i$ 块田里**挖一口井**，花费 $W_i$（该田**自己**得到水源）；
- 在田 $i$ 与田 $j$ 之间**修一条水道**，花费 $P_{i,j}$（两田互通，水可以在有水的田与它之间流动）。

要求：**每块田要么自己有井，要么通过若干条水道（可中转）连到某块有井的田**——这就是题面"与有水的田地相连或拥有水井"的含义。问使所有田都满足这一条件所需的最小总花费。

> 一句话版本：**给每条"挖井"和"修水道"选项定价，求一个最省钱的方案，让每块田都能（直接或间接地）通到水源。**

**题面里容易漏掉的条款**

1. 「$P_{j,i}=P_{i,j}$」$\Rightarrow$ 水道花费**对称**，是无向边；对角元 $P_{i,i}$ 对答案无意义（不需要"从 $i$ 连到 $i$"），代码里只取 $i<j$ 的项即可。
2. 「所有田地都与有水的田地相连**或**拥有水井」$\Rightarrow$ 关键词是"或"，所以允许**多块田各自挖井**、也允许**一块田挖井 + 大量水道**、更允许**部分挖井 + 部分水道**的混合方案；水的传递是**可中转**的（"相连"指连通，不是只连到水源本体）。
3. 「$0\le P_{i,j}$」$\Rightarrow$ 水道花费**可以为零**，零花费边能白送连通性；代码不能因为边权为 $0$ 就特判跳过（Kruskal 天然接受 $0$ 权边）。
4. 「为使所有田地都与有水的田地相连或拥有水井所需要的最少钱数」$\Rightarrow$ 目标是最小化总花费，是**求和**（不是最短路、不是最大边），与 P1547 那种"求最大边"完全不同。
5. 题面未附样例数据，一切以数据范围与描述为准。

**数据范围与规模感受**

$$1\le n\le 300,\qquad 1\le W_i\le 10^5,\qquad 0\le P_{i,j}\le 10^5 .$$

$n$ 很小（$300$）。可能的边数是 $n$（井）$+\binom{n}{2}$（水道）$\le300+44850=45150$ 条，这是典型的**稠密小图最小生成树**规模，$O(E\log E)$ 的 Kruskal 或 $O(n^2)$ 的 Prim 都轻松胜任。答案上界约 $n\cdot10^5=3\times10^7$，`int` 内。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：把"供水方案"精确化

先厘清"合法方案"到底是什么。一个方案 $=$ 选定"哪些田挖井" $+$ "修哪些水道"。判定标准是一个**关于连通性的断言**：从任意一块田出发，若沿水道走，一定能走进一块有井的田。

**引理 1（合法方案的等价刻画：连通到"水源集合"）**

记 $W\subseteq\{1,\dots,n\}$ 为挖井的田集合。方案合法 $\iff$ 对每块田 $i$，在"由所选水道构成的图"里，$i$ 与 $W$ 中**至少一个点**处于同一连通块。

**证明**：

- （$\Rightarrow$）若方案合法，则每块田 $i$ 或有井（即 $i\in W$，自己与 $W$ 同块，$W$ 含自身）或通过一串水道连到某块有井的田 $j\in W$。"连到"即 $i,j$ 在同一连通块，故 $i$ 与 $W$ 同块。
- （$\Leftarrow$）若每块田 $i$ 与 $W$ 中某点 $j$ 同块，则 $i,j$ 之间存在一条由所选水道组成的路径，于是 $i$ 通过这条通路连到有井的 $j$，满足"与有水的田地相连"。$\blacksquare$

> 这一步的价值：它把"水会流动"这个物理直觉，翻译成了纯图论的"与一个指定点集连通"。

### 2.2 经典归约：加一个超级源点

现在引入一个**虚拟的"水源节点"**，编号 $s$，把"挖井"也纳入图：在 $s$ 与田 $i$ 之间连一条权为 $W_i$ 的边——"选这条边"就代表"在田 $i$ 打井"。

**引理 2（原问题的图论等价形式）**

构造增广图 $G'$：点集为 $\{s\}\cup\{1,\dots,n\}$（共 $n+1$ 个点），边集为

- 对每个 $i\in\{1,\dots,n\}$，一条边 $(s,i)$，权 $W_i$（挖井）；
- 对每对 $1\le i<j\le n$，一条边 $(i,j)$，权 $P_{i,j}$（水道）。

则：原问题的"合法方案"$\iff$ 在 $G'$ 中，**每块田 $i$ 都与 $s$ 连通**（$s$ 到 $i$ 有通路）。

**证明**：直接用引理 1 对照。

- 方案对应的边集 $S$ = 所挖井对应的 $s$-$i$ 边 加上 所选水道对应的 $i$-$j$ 边。
- "$i$ 与 $W$ 中某点同块（仅用水道）" $\iff$ 在边集 $S$ 中，"$i$ 经若干 $i$-$j$ 边到达某个 $j\in W$，而 $j$ 又与 $s$ 由边 $s$-$j$ 相连" $\iff$ "$i$ 与 $s$ 在边集 $S$ 中同属一个连通块"。

两方向逐字对应（有井 $\Rightarrow$ 选了边 $s$-$j$；水道路径 $\Rightarrow$ $i$-$j$ 边路径），故等价成立。$\blacksquare$

> **这是本题的核心一步**：挖井（点上的操作）被成功改写成了一条"从虚拟源点出发的边"。这样"井 + 水道"两种异质花费就被统一成同一种对象——**$G'$ 上的边**。

### 2.3 再归约：最小连通子图 = 最小生成树

要求每块田（其实还有 $s$）都连通，最省钱，即：在 $G'$ 中选一个边集 $S$，使（含 $s$ 在内的）所有 $n+1$ 个点连通，并让 $\sum_{e\in S}w_e$ 最小。

**引理 3（最小连通生成子图 = 最小生成树）**

设 $G'$ 的边权非负。所有"能连通全部 $n+1$ 个点的边集"中，总权最小者恰为 $G'$ 的最小生成树，其权值记 $\text{MST}(G')$。

**证明**：

- **MST 可行**：最小生成树本身就是连通的生成子图（连通全部 $n+1$ 点、恰 $n$ 条边、无环），故存在可行边集其总权 $=\text{MST}(G')$，从而最小可行值 $\le\text{MST}(G')$。
- **任何可行边集不优于 MST**：设 $S$ 是任一可行边集（连通全部 $n+1$ 点）。则子图 $(\{s\}\cup F,\ S)$ 连通，因而**含有一棵生成树** $T\subseteq S$（连通图必含生成树：反复删去环上的边即可保留连通性，最终必得无环连通子图）。由边权非负，$\sum_{e\in S}w_e\ge\sum_{e\in T}w_e$。而 $T$ 是生成树，故 $\sum_{e\in T}w_e\ge\text{MST}(G')$。于是任一可行边集的总权 $\ge\text{MST}(G')$。
- 两式夹逼得最小可行值 $=\text{MST}(G')$。$\blacksquare$

> 注意这里的"连通子图含生成树"这一步用到了**子图 $(\{s\}\cup F,S)$ 连通**这一前提：我们不是要求 $s$ 也"供水"，而是 $n+1$ 个点整体连通等价于每块田都连到 $s$。MST 恰好覆盖全部 $n+1$ 点，包含 $s$ 与所有田，故两头对上。

于是问题彻底变成：**在 $G'$ 上求一棵最小生成树，输出其总权。** 用 Kruskal：把 $n+\binom{n}{2}$ 条边按权升序排好，依次并查集合并，直到 $n+1$ 个点连通（即合并 $n$ 条边），累加被选边权。

### 2.4 剖析几个失败思路

**失败 1：只挖一口最便宜的井，其余全靠水道连过去（单源最短路思维）。**
反例：$n=2$，$W=(1,1)$，$P_{1,2}=100$。单源想法：挖便宜井（$1$）再修一条水道（$100$），总 $101$。正确：两块田各挖一口井，总 $1+1=2$。$\Rightarrow$ 供水方案**不要求只有一个水源**；多水源反而可能更省。这正是"最小生成树"而非"最短路"的根源。

**失败 2：把答案拆成"对 $n$ 块田求 MST，再加一口最便宜的井"。**
这种"两步走"是错的，因为它**强制先连通所有田**才允许打井，忽略了"多块田各自打井"这条更省的路。反例：$n=3$，$W=(1,1,1000)$，三条水道全为 $1000$。
- 正确（增广图 MST）：给 $1,2$ 各打一口井（$1+1$）再给 $3$ 打一口（$1000$），或等价选井边 $s\text-1,s\text-2,s\text-3$，总花费 $=1+1+1000=\mathbf{1002}$。
- 错误拆解：先对田 $\{1,2,3\}$ 求 MST（水道全 $1000$，需两条 $=2000$），再加最便宜的井（$1$），得 $2001$。

差了近一倍。$\Rightarrow$ **不能把"打井"当成 MST 之外的附加项**；打井必须作为边进入同一张图，由 MST 统一权衡（引理 2）。

**失败 3：忘了加虚拟源点，直接对 $n$ 块田求 MST。**
反例：$n=3$，$W=(1,1,1)$，三条水道全 $100$。若只对田求 MST：需要把三块田连成一串，两条水道共 $100+100=200$——错！正确：三块田各挖一口井，$1+1+1=3$。$\Rightarrow$ **虚拟源点是必须的**，它承载了"挖井"这一自由度（引理 2）；没有它，"全部挖井"这种解在图上根本无处表达。

**失败 4：把"井边"建成无向双向边算了两次或漏建。**
- 漏建：完全没有 $s$-$i$ 边，退化为失败 3；
- 重复：把 $s$-$i$ 当成两条边各算 $W_i$，若程序里真的把两条都选中会重复计费。$\Rightarrow$ **$s$-$i$ 只需一条无向边**；水源作为点只建 $n$ 条井边（每个 $i$ 一条），不建往返。

### 2.5 越界与状态体检

| 量 | 范围 | 上界 | `int` 够？ |
|---|---|---|---|
| $n$ | 题面 | $300$ | 是 |
| $W_i$ / $P_{i,j}$ | 题面 | $10^5$ | 是 |
| 边数 $n+\binom{n}{2}$ | — | $45150$ | 是 |
| 答案 $\le n\cdot\max W$ | — | $3\times10^7$ | 是（用 `i64` 更稳） |
| 数组尺寸 | $n+5$ / 边数 $+5$ | `mxn{305}`、`mxm{50005}` | — |

结论：答案在 `int` 内，累计用 `i64` 保险。要防的静默错误：

1. **并查集要开到 $n+1$ 个点**（含虚拟源点 $s$，编号 $n$）：`iota(f,f+n+1,0)`；Kruskal 的停止条件是"合并 $n$ 条边"（$n+1$ 个点连通需 $n$ 条边），写成 `<n-1` 会漏一条边。
2. **`E[m++]` 时 `m` 的初值必须是 $0$**，且边表容量不能小于 $n+\binom{n}{2}$。
3. **对角元 $P_{i,i}$ 不建边**：只取 $i<j$，避免自环与重复。
4. **边权为 $0$ 的水道**要正常参与（Kruskal 不跳过）。

## 3. 模式总结（Pattern Summary）

**模式名：「超级源点 + 最小生成树」处理"点权与边权混合"的连通问题。**

**识别信号**：

- 目标是让**所有对象**通过某种方式"都连到一个共同的资源"，并最小化总花费。
- 花费有两种形态：**在点上"开通/建造"**（如挖井、建厂、通电）与**在之间"连接"**（如修路、铺管），二者可混用。
- 强调"或"（可各自开通，也可互连），且传递**可中转**。

**可复用的思维轨迹（按实际思考顺序）**：

- explore its property — 把"供水"物理描述翻译为**"每块田与水源集合 $W$ 连通"**（引理 1）。
- reduce to easier problem（第一次）— 引入**虚拟源点 $s$**，把"点上的挖井花费"改写为"从 $s$ 出发的边"，让两类花费统一为同一张图上的边（引理 2）。
- reduce to easier problem（第二次）— 把"任选边集使全连通并最小化总权"归约为**最小生成树**，用"连通子图必含生成树 + 边权非负"证双向夹逼（引理 3）。
- classic problem solution — Kruskal（边权升序 + 并查集）求 MST 总权；$n+1$ 个点连通需 $n$ 条边。
- discard harder model — 明确**拒绝**"单源最短路 / 只挖一口井"的模型，因为多水源可混用。
- overflow guard — 累加用 `i64`，并查集开到 $n+1$。

**同族题 / 同源题**：

- **P1197 / 电网、通电类题目**：加超级源点把"建电站"变成边权，是同一套路。
- **POJ 2421 / 修路最小花费**：直接裸 MST。
- **P1661 扩散**、**"村庄通电"类**：点权转边权的超级源点技巧反复出现。
- **P3366 最小生成树模板**：本做法在增广图上即其直接应用。

**一句话记忆**：遇到"开通点"与"连接边"混合的连通花费题，就造一个**超级源点**把点上的花费变成边，然后求整张图的**最小生成树**。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $n$ | `int` | 田块数 | 读入 | 题面 |
| `W[i]` | `int [305]` | 在田 $i$ 挖井的花费 | 读入 | well |
| `P[i][j]` | `int [305][305]` | 连接田 $i,j$ 的水道花费（对称） | 读入 | pipe |
| `E[k]` | 结构体 `{u,v,w}` `[50005]` | 增广图边表（含井边与水管边） | 构造 | edge |
| `f[x]` | `int [305]` | 并查集父指针，共 $n+1$ 个点（$s$ 编号 $n$） | `iota(f,f+n+1,0)` | father |
| `ans` | `i64` | 最小总花费 = MST 总权 | `0` | answer |
| `cnt` | `int` | 已选入生成树的边数，达 $n$ 即连通 | `0` | count |

### 4.2 编号步骤

1. 读入 $n$、各 $W_i$、$P$ 矩阵。
2. 建边（`m` 从 $0$ 起）：
   2.1 对 $i=0..n-1$：`E[m++]={i,n,W[i]}`（井边，虚拟源点编号 $n$）。
   2.2 对 $i=0..n-1$、$j=i+1..n-1$：`E[m++]={i,j,P[i][j]}`（水道边，仅 $i<j$）。
3. `sort(E,E+m,[](auto a,auto b){return a.w<b.w;})` 边权升序。
4. `iota(f,f+n+1,0)` 初始化 $n+1$ 个点的并查集。
5. Kruskal：扫边，若 `ru!=rv` 则合并、`ans+=E[i].w`、`++cnt`；当 `cnt==n` 即可停（$n+1$ 点连通）。
6. 输出 `ans`（引理 3：它是最小总花费）。

### 4.3 复杂度

- 时间：建边 $O(n^2)$；排序 $O(E\log E)$，$E\le45150$；Kruskal $O(E\alpha)$。合计 $O(n^2\log n)$，$n=300$ 时数 $10^6$ 级。
- 空间：`P[mxn][mxn]` 约 $305^2\times4\approx372$ KB，边表约 $45150\times12\approx540$ KB，合计 $<1$ MB，远低于限制。
- 实测（见 §4.5）：$n=300$、权值取满时 **约 0.010 s**。

### 4.4 关键不变量（值得写 `assert` 的地方）

1. 并查集点数恒为 $n+1$；Kruskal 结束时 `cnt == n`（$G'$ 必连通，因每个 $i$ 都有井边 $s$-$i$）。
2. `ans` = 当前已选边权之和；由于升序 + 逐条累加，最终即 MST 总权。
3. 边数 `m == n + n*(n-1)/2`（构造完毕后），不超过 `mxm`。
4. 井边恰 $n$ 条、水道边恰 $\binom{n}{2}$ 条，无自环、无重复。

## 5. 示例代码

### 5.1 主解：超级源点 + Kruskal 最小生成树

```cpp
// 题目：P1550 [USACO08OCT] Watering Hole G
// https://www.luogu.com.cn/problem/P1550
// AC
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{305};           // n<=300 (+5 松弛)
constexpr int mxm{50005};         // n + n(n-1)/2 <= 45150 (+5 松弛)

int n;
int W[mxn];                       // W[i]=在 i 号田挖井的花费
int P[mxn][mxn];                  // P[i][j]=连接 i,j 的花费
struct{int u,v,w;}E[mxm];         // 边表;源点编号 n
int f[mxn];                       // 并查集父指针

int getrt(int x)
{
	if(f[x]==x)
		return x;
	return f[x]=getrt(f[x]);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
		cin>>W[i];
	for(int i=0;i<n;++i)
		for(int j=0;j<n;++j)
			cin>>P[i][j];

	int m=0;
	for(int i=0;i<n;++i)
		E[m++]={i,n,W[i]};                        // 挖井: 虚源点 n <-> 田 i,权 W[i]
	for(int i=0;i<n;++i)
		for(int j=i+1;j<n;++j)
			E[m++]={i,j,P[i][j]};                 // 修水道: 田 i <-> 田 j

	sort(E,E+m,[](auto a,auto b){return a.w<b.w;});
	iota(f,f+n+1,0);                              // n+1 个节点(含源点)
	i64 ans=0;
	int cnt=0;
	for(int i=0;i<m&&cnt<n;++i)                   // n+1 个点连通需 n 条边
	{
		int ru=getrt(E[i].u),rv=getrt(E[i].v);
		if(ru!=rv)
		{
			f[ru]=rv;
			ans+=E[i].w;
			++cnt;
		}
	}
	cout<<ans<<'\n';
	return 0;
}
```

**代码结构对照**：`E` 把两类花费（井、水道）统一成边；`f` 开到 $n+1$（含虚拟源点 $n$）；Kruskal 直到 `cnt==n` 即全连通，`ans` 累加即引理 3 的 MST 总权。`W`、`P` 读入后分别为引理 2 的两个边来源。

### 5.2 对照实现：枚举候选边子集（仅用于小规模对拍）

```cpp
// 题目：P1550 [USACO08OCT] Watering Hole G
// 暴力基准：枚举候选边(井边 + 水管边)的所有子集,找使所有田都与源点连通的方案最小花费
// 仅用于小规模对拍,不能提交
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{12};
constexpr int inf{1145141919};

int n;
int W[mxn],P[mxn][mxn];
int eu[mxn*mxn],ev[mxn*mxn],ew[mxn*mxn];
int f[mxn];

int getrt(int x)
{
	if(f[x]==x)
		return x;
	return f[x]=getrt(f[x]);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
		cin>>W[i];
	for(int i=0;i<n;++i)
		for(int j=0;j<n;++j)
			cin>>P[i][j];

	int me=0;
	for(int i=0;i<n;++i)                          // 井: 源点 n <-> i
	{
		eu[me]=n;ev[me]=i;ew[me]=W[i];++me;
	}
	for(int i=0;i<n;++i)                          // 水管: i <-> j
		for(int j=i+1;j<n;++j)
		{
			eu[me]=i;ev[me]=j;ew[me]=P[i][j];++me;
		}

	int best=inf;
	for(int mask=0;mask<(1<<me);++mask)
	{
		for(int i=0;i<=n;++i)
			f[i]=i;
		int cost=0;
		for(int i=0;i<me;++i)
			if(mask>>i&1)
			{
				int a=getrt(eu[i]),b=getrt(ev[i]);
				if(a!=b)
					f[a]=b;
				cost+=ew[i];
			}
		bool ok=true;
		for(int i=0;i<n&&ok;++i)                  // 每块田都必须与源点连通
			if(getrt(i)!=getrt(n))
				ok=false;
		if(ok)
			best=min(best,cost);
	}
	cout<<best<<'\n';
	return 0;
}
```

两版**输出必须逐字节相同**（已用 300 组随机数据确认）。暴力版按引理 2 的**定义**穷举"选哪些边"，直接检查连通性，完全绕开排序与 MST 逻辑，因此作为引理 3 的独立交叉验证基准。代价是 $2^{(n+\binom n2)}$，仅适合 $n\le5$。

### 5.3 易错点清单

- **不加虚拟源点** $\Rightarrow$ 退化成"对田求 MST"，多水源方案被漏掉（§2.4 失败 3，$n=2,W=(1,1),P=100$ 会给出 $100$ 而非 $2$）。
- **并查集只开到 $n$ 个点 / 停止条件写成 `cnt<n-1`** $\Rightarrow$ 源点 $n$ 越界或漏掉最后一条边，答案错误。
- **$s$-$i$ 建了双向两条边并都选入** $\Rightarrow$ 重复计费；井边只需一条无向边。
- **对角线 $P_{i,i}$ 也建边** $\Rightarrow$ 无意义自环（Kruskal 会跳过，无害但不干净）。
- **边权为 $0$ 的水道被特判跳过** $\Rightarrow$ 漏水，答案偏大。
- **累计用 `int` 以外忘了开大**：答案 $\le3\times10^7$，`int` 内，但用 `i64` 更保险。
- **`endl`** $\Rightarrow$ 用 `'\n'`。
