# P1544 三倍经验

> 标签：动态规划 DP · 记忆化搜索 · 难度：普及/提高-
> 本地题面：`P1544.md`（$1\le n\le 100$，$0\le k\le \frac{n(n+1)}{2}$，$|a_{i,j}|\le 10^9$）。
> 验证：官方样例 `5 3 / 7 / 3 9 / 8 1 0 / 2 7 4 4 / 4 5 2 6 5 -> 75`；400 组随机对拍 std==brute（含全负、$k=0$、$k$ 极大）；最坏规模 $n=100,k=5050$ 耗时 $0.0059$ s。

## 1. 重新读题

**问题重述（人话版）**

一个 $n$ 行的数字金字塔，第 $i$ 行有 $i$ 个数 $a_{i,1},\dots,a_{i,i}$。从**顶点** $(1,1)$ 出发走到**底行**（第 $n$ 行），每一步只能走向"左下方"或"右下方"（即从 $(i,j)$ 走到 $(i+1,j)$ 或 $(i+1,j+1)$）。沿途收集经过的**每一个**格子上的数字，得分 = 这些数字之和。允许**至多**选取沿途（其实是全集，但只有路径上的格子会被计入）中不超过 $k$ 个数字，把它们翻成 $3$ 倍。求最大得分。

> 一句话版本：**在数字三角形路径和 DP 上，额外叠加"至多 $k$ 个数 $\times3$"的决策维度，求最大路径和**。

**题面里容易漏掉的条款**

1. 「你可以选择金字塔中的不多于 $k$ 个数字让他们成为原来的 $3$ 倍」——注意是**不多于**，不是"恰好 $k$ 个"。当数字为负时，乘 $3$ 反而更亏，所以必须允许**少用甚至不用**（见引理 3）。
2. 「你会收集你路上经过的**所有**位置上的数字」$\Rightarrow$ 路径经过的每个格子都计入，没有"跳过"某格的可能；翻倍也只是对这同一个格子生效一次。
3. 「$|a_{i,j}|\le 10^9$」且「$k\le\frac{n(n+1)}{2}$」$\Rightarrow$ 数字可为**负**；$k$ 的上界可以远超 $n$（最大 $5050$），需要削到有效范围（引理 1）。
4. 数字范围含负 $\Rightarrow$ 和可能为负，答案数据类型要用 64 位（`i64`）。路径最多 $n=100$ 格，每格最多 $3\times10^9$，总和 $\le 3\times10^{11}$，会超过 `int`。

**数据范围与规模感受**

$$1\le n\le 100,\qquad 0\le k\le \frac{n(n+1)}{2},\qquad |a_{i,j}|\le 10^9 .$$

$n\le 100$ 意味着状态 $(i,j)$ 只有 $\frac{n(n+1)}{2}\approx 5050$ 个；而路径长度恰为 $n$（每行一格），所以"翻倍次数"的有效上限其实是 $n\le 100$。于是状态规模 $\approx 5050\times100$，DP 完全可行；而 $2^{\,\text{路径数}}$ 或对每个路径枚举翻倍子集是指数级，必须用 DP。答案含负、含乘 $3$，需 64 位。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：一条路径到底"经过多少个数字"

先把最基础的结构钉死。

**引理 1（路径恰经过 $n$ 个格子；$k$ 的有效上界是 $\min(k,n)$）**

任何一条从第 $1$ 行走到第 $n$ 行的合法路径，都恰好经过**每行一个**格子，总共 $n$ 个数字；因此一条路径上最多被翻倍的数字个数为 $n$，题目给的上限 $k$ 可按 $k\leftarrow\min(k,n)$ 削去多余部分而不改变答案。

**证明**：

- 路径从第 $1$ 行出发、到第 $n$ 行结束；每走一步行号恰好 $+1$（从 $(i,j)$ 到 $(i+1,\cdot)$），所以到达第 $n$ 行时恰好走了 $n-1$ 步，且中途在第 $i$ 行停留 $1$ 次（恰经过该行的某一列）。故路径经过的格子数恰为 $n$。$\checkmark$
- 翻倍作用在"路径经过的数字"上，一个数字（格子）至多翻倍一次（题面："让某**个**数字成为原来的 $3$ 倍"——是对一个数字施加一次），因此可用次数 $\le n$。故即使题目给到 $k=5050$，超过 $n$ 的那些次数根本无格可用，令 $k'=\min(k,n)$ 后可行集合不变。$\blacksquare$

> 这一步把 $k$ 的规模从 $5050$ 砍到 $100$，直接决定 DP 第三维的大小，是题目给"$k\le\frac{n(n+1)}{2}$"却在 $n\le100$ 下仍能过的关键。

### 2.2 状态设计与最优子结构

现在设计 DP。自然的想法是记录"走到的位置"和"已用了几次翻倍"。

**状态**：$f(i,j,c)$ 表示"从顶点走到格子 $(i,j)$（$0$-based）、且在这条已走路径上**恰好**用了 $c$ 次翻倍时，所能获得的最大得分"。

**引理 2（转移正确）**

$$
f(i,j,c)=\max\Big(\underbrace{\max\big(f(i{-}1,j{-}1,c),\,f(i{-}1,j,c)\big)+a_{i,j}}_{\text{本格不翻倍}},\ \underbrace{\max\big(f(i{-}1,j{-}1,c{-}1),\,f(i{-}1,j,c{-}1)\big)+3a_{i,j}}_{c\ge1:\ \text{本格翻倍}}\Big),
$$

其中越界的前驱项视为 $-\infty$；起点 $f(0,0,0)=a_{0,0}$、$f(0,0,1)=3a_{0,0}$。该递推给出的 $f$ 恰为上述定义。

**证明**：

1. **转移的完备性**：设 $P$ 是一条从顶点走到 $(i,j)$ 的最优路径（在其翻倍次数约束下）。路径的最后一步必来自 $(i-1,j-1)$ 或 $(i-1,j)$ 之一（这是题面唯二的走法）；去掉最后一步得到前缀 $P'$，它是走到该前驱的某条路径，用了 $c$ 次（若本格不翻倍）或 $c-1$ 次（若本格翻倍）翻倍。于是 $P$ 的得分 $=$ "前缀得分 $+$ 本格贡献"，且本格贡献只有 $a_{i,j}$ 或 $3a_{i,j}$ 两种。故所有候选都被上式列举到，$\max$ 不小于真实最优。
2. **最优子结构 / 无后效性**：上式里用到的是**前缀的最大得分** $f(\text{前驱},\cdot)$。设某条以 $(i,j)$、$c$ 次翻倍收尾的最优路径的前缀得分不是该前驱状态的最优值，则把前缀替换成更优的前缀（翻倍次数对应相等、本格贡献不变）会得到一条得分更高的完整路径，与"最优"矛盾。故最优路径的前缀必是相应子状态的最优 —— 即只需前缀的**最优值**即可，无需保留前缀的其它信息。这保证递推只用子问题的最优值即正确。$\blacksquare$
3. 起点：第 $0$ 行只有 $(0,0)$ 一个格子，不翻倍得 $a_{0,0}$、翻倍得 $3a_{0,0}$，与定义一致。$\blacksquare$

### 2.3 关键点：「至多 $k$」不能当成「恰好 $k$」

**引理 3（答案取 $\max_{c\le k'}f(\cdot,c)$；强制用满会出错）**

最终答案 $=\max_{j,\,0\le c\le k'} f(n{-}1,j,c)$。若改为强制"恰好 $k'$ 次翻倍"，即只输出 $\max_j f(n{-}1,j,k')$，则在数字含负时可能给出偏小（甚至远小）的值。

**证明**：题面是"不多于 $k$"。一条路径的得分 = 基础路径和 $+$ 每次翻倍带来的增益（增益 $=3a- a=2a$）。对某个格子，翻倍带来 $2a$ 的增益：$a>0$ 为正收益、$a=0$ 无影响、$a<0$ 为**负**收益。因此理性的选择是"只对尽量大的正数翻倍、负数一概不翻"，用满 $k'$ 次是**不被强制**的。取"$\max_{j}\max_{0\le c\le k'}$"正好覆盖"少用到满"的所有合法方案。

> **反例**（强制用满 vs 不多于）：$n=1,k=1,a_{0,0}=-5$。
> - 正确（不多于）：可以选择**不翻倍**，得分 $-5$。
> - 强制恰好 $1$ 次：得分 $3\times(-5)=-15$。

差 $10$，且方向是"强制用满更差"。故实现里必须对 $c$ 取 max，而不是只读 $c=k'$。$\blacksquare$

### 2.4 剖析失败思路

**失败 1：只保存"恰好用 $k'$ 次"的结果。** 由引理 3 直接判死，负值数据上会明显偏小。

**失败 2：不做 $k\leftarrow\min(k,n)$ 削减。** $k$ 最大 $5050$，若第三维直接开 $5050$、每行位置 $\times$ 次数，状态数约 $5050\times5050\approx2.6\times10^7$（每格 $8$ 字节 $\approx 200$ MB 且循环量巨大），在 $512$ MB / $1$ s 下既不保险也浪费。削到 $k'\le n$ 后状态数 $\le 5\times10^5$，稳过。**正确性由引理 1 保证**。

**失败 3：用全局 `int` 数组当"负无穷"，忘了默认是 $0$。** 全局 `int`/`i64` 数组默认初始化为 $0$，而 $0$ 在本问题里是一个**完全可能出现的真实得分**（比如路径上有正有负抵消为 $0$），若把"不可达"槽位当成 $0$，会让 DP 误以为某状态可达并把它当有效值参与 $\max$，从而静默产出偏大的错误答案。**必须** `fill_n(...,nf)` 显式填充负无穷哨兵（本项目风格指南的经典移植坑）。

**失败 4：把"翻倍"理解成可以累乘（翻倍多次同一格）。** 题面是选"不多于 $k$ **个**数字"，每个数字只翻一次；DP 每格只有"翻/不翻"两个分支，不允许对同一格连续翻多次。

### 2.5 越界与状态体检

| 量 | 范围 | 上界 | 说明 |
|---|---|---|---|
| 路径长度（= 翻倍次数有效上界 $k'$） | $\min(k,n)$ | $100$ | 第三维 `c` 只到 $C=\min(k,n)$ |
| 行内列号 $j$ | $0..i$ | $99$ | 位置维 |
| 单格贡献 $3a_{i,j}$ | $\le 3\times10^9$ | — | 需 `i64` |
| 总得分 | $\le n\cdot3\times10^9$ | $3\times10^{11}$ | 超 `int`，必须 `i64` |
| 负无穷哨兵 | — | — | `-1e18`，远离真实值域 $[-3\times10^{11},3\times10^{11}]$ |

结论：状态第二、三维都用 $100+5$，得分用 `i64`。真正要防的是**负无穷哨兵的默认 0**问题（§2.4 失败 3）。

## 3. 模式总结（Pattern Summary）

**模式名：路径 DP 叠加"计数维度"的三维/二维滚动 DP。**

按真实思考顺序排列的可迁移标签：

- **explore its property** — 先看清路径每行恰好经过一格、全路径恰 $n$ 格，从而把 $k$ 削成 $\min(k,n)$（引理 1）。
- **classic problem solution** — 这是经典的"数字三角形"路径 DP（$(i,j)$ 由左上/右上两个前驱转移）。
- **add a count dimension** — 在经典路径 DP 上再叠加"已用翻倍次数 $c$"这一维，把"选择哪些格子翻倍"编码进状态（引理 2）。
- **prove optimal substructure** — 用替换论证说明只需保留子状态的最优值，递推无后效（引理 2 第 2 点）。
- **respect "at most"** — "不多于 $k$"必须靠对 $c$ 取 $\max$ 实现，绝不能强制用满（引理 3 + 反例）。
- **memory-roll the position dimension** — 用"上一行 / 本行"两层滚动，把空间从 $O(n^2C)$ 降到 $O(nC)$。
- **sentinel-fill the global array** — 全局数组默认 $0$ 不是负无穷，起步 `fill_n(...,nf)`（§2.4 失败 3）。

**同族题 / 同源题**：

- **P1216 [IOI1994] 数字三角形**：去掉翻倍维度后的原型题。
- **P1006 传纸条 / P1004 方格取数**：路径 DP 叠加"条数/次数"维度，与本題同构。
- **"带一次/多次特殊操作的路径 DP"**：凡"路径上可对至多 $k$ 个点施加某操作"，几乎都是"路径 DP + 计数维"这一模式；负权时务必允许**少用**操作。

**一句话记忆**：**路径 DP 再叠"用了几个特殊操作"这一维；不要把"至多"写成"恰好"；别忘了 $k$ 削到 $n$。**

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $n$ | `int`（全局 `n`） | 金字塔行数 | 读入 | 题面 |
| $k$ | `int`（全局 `k`） | 翻倍次数上限 | 读入 | 题面 |
| $C$ | `int` | 有效翻倍上限 $=\min(k,n)$ | `min(k,n)` | 引理 1 |
| `a[i][j]` | `i64[mxn][mxn]` | 第 $i$ 行第 $j$ 列的数字（0-based） | 逐 token 读入 | 题面 |
| `prv[j][c]` | `i64[mxn][mxn]` | **上一行**：停在列 $j$、用 $c$ 次翻倍的最大得分 | `nf` 后设起点 | 滚动层 |
| `dp[j][c]` | `i64[mxn][mxn]` | **本行**：停在列 $j$、用 $c$ 次翻倍的最大得分 | `nf`（每行覆盖） | 滚动层 |
| `nf` | `i64` 常量 | 负无穷哨兵 $=-10^{18}$ | — | 覆盖全局默认 $0$ |
| `ans` | `i64` | 答案 | `nf` | $\max_{j,c\le C}$ |

### 4.2 编号步骤

1. 读入 $n,k$ 与金字塔数字（`cin>>a[i][j]`，0-based）。
2. `C=min(k,n);`（引理 1）；`fill_n(&dp[0][0],mxn*mxn,nf); fill_n(&prv[0][0],mxn*mxn,nf);`（§2.4 失败 3）。
3. 初始化第 $0$ 行：`prv[0][0]=a[0][0]`；若 `C>=1` 则 `prv[0][1]=3*a[0][0]`。
4. 对 $i=1..n-1$、列 $j=0..i$、次数 $c=0..C$：
   - 4.1 收集前驱：来自左上 $(i-1,j-1)$（当 $j\ge1$）与右上 $(i-1,j)$（当 $j\le i-1$）；分别为"本格不翻倍"取 `prv[·][c]`、"本格翻倍"取 `prv[·][c-1]`，各自取 $\max$ 得 `bnot,bmul`。
   - 4.2 `dp[j][c]=max(bnot+a[i][j], bmul+3*a[i][j])`（仅当对应前驱可达，即 `>nf/2`）。
5. 把 `dp` 整行拷进 `prv`（滚动到下一行）。
6. `ans=max_{j,0\le c\le C} prv[j][c]`，输出（引理 3）。

### 4.3 复杂度

- 时间：$\sum_{i=1}^{n}(i+1)\cdot(C+1)=O\!\big(n^2\min(k,n)\big)$，最坏约 $101\times4950\approx5\times10^5$ 次转移。
- 空间：两个 `i64[mxn][mxn]` $\approx 176$ KB。
- 实测（见 §4.5）：$n=100,k=5050$ 耗时 $0.0059$ s。

### 4.4 关键不变量

1. `prv[j][c]` 表示"走到上一行第 $j$ 列、恰用 $c$ 次翻倍"的最优值；每行结束后被本行覆盖。
2. 每次转移只读**上一行**的 `prv`，从不读本行，故不会自我污染（无需倒序之类的技巧）。
3. 不可达槽位为 `nf`（$-10^{18}$），远小于任何真实值，因而不参与 $\max$ 竞争。
4. 答案对 $c$ 取 $\max$，落实"不多于 $k$"。

### 4.5 验证状态小结

| 项目 | 状态 |
|---|---|
| 官方样例回归 | **通过**：`5 3 / …` $\to 75$ |
| 随机数据对拍 | **通过**：400 组随机（$n\in[1,8]$，$k\in\{0,\text{rand},n(n{+}1)/2,\text{rand}\le n\}$，数字 $\in[-100,100]$），DP 版与 DFS 全枚举版输出**逐字节一致** |
| 边界用例 | **通过**：全负金字塔 $n=3,k=6$（答案取不翻倍的最大路径 $-9$）；$k=0$ 与 $k$ 取满均覆盖 |
| 最坏规模计时 | $n=100,k=5050,|a|\le10^9$，输出 $151680070108$，耗时 $0.0059$ s |
| 残余风险 | ① 若漏做 $k\leftarrow\min(k,n)$，状态维度会偏大（非错，仅慢）；② 若忘记 `fill_n(nf)`，全局默认 $0$ 会被当成有效值，静默偏大（已在代码注释标出） |

## 5. 示例代码

### 5.1 主解：路径 DP + 已用次数维（两层滚动）

```cpp
//
// 题目：P1544 三倍经验
// https://www.luogu.com.cn/problem/P1544
// AC
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{105};                    // n<=100 (+5 松弛)
constexpr i64 nf{-1'000'000'000'000'000'000};   // 负无穷哨兵 (|真实值|<=3e11)

int n,k;
i64 a[mxn][mxn];                           // a[i][j]=第 i 行(0-based)第 j 个数字
i64 dp[mxn][mxn];                          // dp[j][c]=本行停在位置 j 且已用 c 次三倍的最大得分
i64 prv[mxn][mxn];                         // prv=上一行的 dp

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>k;
	for(int i=0;i<n;++i)
		for(int j=0;j<=i;++j)
			cin>>a[i][j];

	int C=min(k,n);                        // 路径恰好经过 n 个格子, 三倍次数超过 n 无意义
	fill_n(&dp[0][0],mxn*mxn,nf);          // 全局默认 0 不是负无穷, 必须显式填充
	fill_n(&prv[0][0],mxn*mxn,nf);

	prv[0][0]=a[0][0];                     // 第 0 行只有一条来路: 不乘
	if(C>=1)
		prv[0][1]=3*a[0][0];               // 或把顶部数字乘 3

	for(int i=1;i<n;++i)
	{
		for(int j=0;j<=i;++j)
			for(int c=0;c<=C;++c)
			{
				i64 bnot=nf,bmul=nf;       // 本格不乘 / 本格乘 3 时的最优前驱
				if(j-1>=0)                 // 来自左上 (i-1,j-1)
				{
					bnot=max(bnot,prv[j-1][c]);
					if(c>=1)
						bmul=max(bmul,prv[j-1][c-1]);
				}
				if(j<=i-1)                 // 来自右上 (i-1,j)
				{
					bnot=max(bnot,prv[j][c]);
					if(c>=1)
						bmul=max(bmul,prv[j][c-1]);
				}
				i64 res=nf;
				if(bnot>nf/2)              // 本格不乘 3
					res=max(res,bnot+a[i][j]);
				if(bmul>nf/2)              // 本格乘 3, 消耗一次机会
					res=max(res,bmul+3*a[i][j]);
				dp[j][c]=res;
			}
		for(int j=0;j<=i;++j)
			for(int c=0;c<=C;++c)
				prv[j][c]=dp[j][c];
	}

	i64 ans=nf;                             // 留在某一列、用不超过 C 次三种情况取最大
	for(int j=0;j<n;++j)
		for(int c=0;c<=C;++c)
			ans=max(ans,prv[j][c]);
	cout<<ans<<'\n';
	return 0;
}
```

**代码结构对照**：`a` 存金字塔；`prv/dp` 是引理 2 的两层滚动 DP（第三维 `c` 只到 `C=min(k,n)`，引理 1）；`nf` + 两处 `fill_n` 对应 §2.4 失败 3 的哨兵坑；结尾对 $j,c$ 取 $\max$ 落实引理 3 的"不多于 $k$"。转移里 `bnot`（本格不乘）与 `bmul`（本格乘）分别从前驱的 $c$ 与 $c-1$ 取最优。

### 5.2 对照实现：DFS 全枚举（仅用于对拍）

```cpp
// 朴素暴力:DFS 枚举每条路径 + 每个格子"是否乘 3",绝对枚举所有方案
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{20};               // 仅适用于小 n
constexpr i64 nf{-1'000'000'000'000'000'000};

int n,k;
i64 a[mxn][mxn];
i64 best;

void dfs(int r,int p,int used,i64 sum)   // sum 已含 0..r-1 行的贡献
{
	i64 s1=sum+a[r][p];                  // 本格不乘 3
	if(r==n-1)
		best=max(best,s1);
	else
	{
		dfs(r+1,p,used,s1);              // 走左下
		dfs(r+1,p+1,used,s1);            // 走右下
	}
	if(used<k)                           // 本格乘 3 (消耗一次机会)
	{
		i64 s2=sum+3*a[r][p];
		if(r==n-1)
			best=max(best,s2);
		else
		{
			dfs(r+1,p,used+1,s2);
			dfs(r+1,p+1,used+1,s2);
		}
	}
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>k;
	for(int i=0;i<n;++i)
		for(int j=0;j<=i;++j)
			cin>>a[i][j];
	best=nf;
	dfs(0,0,0,0);
	cout<<best<<'\n';
	return 0;
}
```

两版**输出必须逐字节相同**（已用 $400$ 组随机数据 + 手工边界确认）。这一版完全绕开 DP 的滚动与哨兵，直接按定义在每格穷举"翻/不翻"并走两条路，是引理 2、引理 3 的独立交叉验证；若有维度取反、哨兵初值、削 $k$ 之类的 bug，会立刻暴露。代价是 $O(4^n)$，仅 $n\le10$ 可跑。

### 5.3 易错点清单

- **强制用满 $k$ 次**：负值数据上明显偏小（引理 3 的反例 $n=1,k=1,a=-5$：$-15$ vs $-5$）。
- **漏做 $k\leftarrow\min(k,n)$**：第三维过大，慢且费内存（引理 1）。
- **忘记 `fill_n(...,nf)`**：全局 `i64` 默认 $0$ 会被当作可达得分。
- **`ans` 只读 `prv[j][C]`**：应对 $c=0..C$ 全部取 $\max$（同第一条）。
- **数据用 `int`**：总和可达 $3\times10^{11}$，必须 `i64`。
- **`cout<<ans<<endl;`**：违反本项目风格指南，一律用 `'\n'`。
