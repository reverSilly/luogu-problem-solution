# P1366 有序表的合并

> 标签：双指针 two-pointer / O2优化 · 难度：普及/提高-

## 1. 重新读题

**问题重述（简化版）**

给两条已排好序的数列：$a$ **严格递增**（题面保证无重复），$b$ **不降**。对每个下标 $i$ 数出 $a_i$ 在 $b$ 中出现的次数 $c_i$，把 $n$ 个次数做**按位异或**，每组数据输出一行一个整数。共 $T$ 组数据。

**约束与暗示**

| 量 | 范围 | 暗示 |
|---|---|---|
| 组数 $T$ | $1\le T\le 10$ | 多组数据，组间状态（指针、计数器）必须重置 |
| 长度 $n,m$ | $1\le n,m\le 10^7$，$\sum(n+m)\le 10^7$ | 输入总长 $10^7$ 个数 $\Rightarrow$ 要 $O(n+m)$；这就是标签 two-pointer |
| 元素值 | $1\le a_i,b_i<2^{64}$ | 必须 **64 位无符号**；只能比较、不能做算术 |
| 有序性 | $a_i<a_{i+1}$，$b_i\le b_{i+1}$ | 归并扫描的入场券；$a$ 的严格递增还是"单个计数器就够"的前提（引理 2、§2.8） |
| 输出量 | $c_1\oplus\cdots\oplus c_n$（$0\le c_i\le m$） | 异或把 $10^7$ 个数压成一行，纯粹是**防输出过大**，不是数学要求 |

**口径（先把"要输出什么"钉死）**

1. **题名"有序表的合并"是手段，不是输出**。题面 Output Format 只要一行整数（各 $c_i$ 的异或和），**不要求输出合并后的序列，也不要求输出每一步合并结果**。合并扫描只是把"数出现次数"做到线性。
2. **$c_i$ 按 $i$ 逐个统计**，不在 $b$ 中出现的 $a_i$ 也有 $c_i=0$，它对异或和无贡献（§2.6 引理 6）。
3. **$b$ 中的相等元素要全部计数，不许去重**：样例解释 1 里 $3$ 出现 $2$ 次就必须记 $2$。这是"相等元素保留规则"的全部内容——保留**重数**。

## 2. 思维链（Chain-of-thought）

### 2.1 先摸清"计数"的结构：$b$ 的相等值挤成一段

两条链都有序，那"某个值出现几次"这件事一定和**连续段**有关。

**引理 1（run 连续性）** 设 $b$ 不降，$v$ 为任意值，则 $I_v=\{j: b_j=v\}$ 是 $\{0,\dots,m-1\}$ 中的一段**连续下标区间**（可以为空）。

**证明**：空集情形即结论成立。设 $I_v$ 非空，取其中最小下标 $p$ 与最大下标 $q$。对任意 $p\le j\le q$，由不降性 $v=b_p\le b_j\le b_q=v$，两端相等夹住中间，故 $b_j=v$，即 $j\in I_v$。所以 $I_v=\{p,p+1,\dots,q\}$。反过来该区间外的下标不可能取值 $v$（否则 $p,q$ 不是最值）。$\blacksquare$

这段区间的长度恰是 $c_i$（当 $v=a_i$）。于是"计数"退化成"认出一段 run、量它的长度"。

**引理 2（匹配下标唯一）** 题面保证 $a_i<a_{i+1}$，故对任意值 $v$，集合 $\{i:a_i=v\}$ 至多一个元素。

**证明**：设 $i<k$。由严格递增逐格传递得 $a_i<a_{i+1}<\cdots<a_k$，故 $a_i<a_k$，两者不可能同时等于 $v$。于是 $\{i:a_i=v\}$ 里至多一个元素（若它非空，其中唯一的下标就是 $v$ 的"归属下标"）。$\blacksquare$

引理 1 + 引理 2 合起来说明：**$b$ 的每一段 run 至多"归属"一个 $a$ 下标**，所以整个扫描只需要**一个**计数器，不需要 $c[]$ 数组。

### 2.2 朴素做法先摸一遍（easier version）

- **值域桶**：开数组 $\mathrm{cnt}[\,]\,$，对每个 $b_j$ 做 `cnt[b_j]++`，再查 $\mathrm{cnt}[a_i]$？值域是 $[1,2^{64})$，桶开不下（$O(\max v)$ 空间），放弃。
- **逐个二分**：对每个 $i$ 用 `lower_bound/upper_bound` 夹出 $c_i=(\mathrm{ub}-\mathrm{lb})$，$O(n\log m)$，$10^7\times\log_2 10^7\approx 2.4\times 10^8$ 次比较，且要同时存下 $a,b$（$160\,\mathrm{MB}$）。**它最大的价值是给出一个"定义级"的暴力基准**，本文所有手算都拿它对照（§4.4 每组的"真值"都由定义直接数出重数）。
- **把两条有序链一起走**：既然都有序，"比大小、推进小的那个"就是**归并**——标签 two-pointer 与题名同时指向它，一次扫描 $O(n+m)$，还只要存 $a$。

### 2.3 归并扫描本身：先证它确实产出有序表（引理 3）

要用它，得先说清它在做什么。经典归并：指针 $i$ 扫 $a$、指针 $j$ 扫 $b$，每步取"两个表头中较小的那个"放入结果，被取者指针前进；一空则把另一个整条接上。

**引理 3（合并结果的有序性）** 设 $a$ 不降、$b$ 不降（本引理不需要 $a$ 严格），按"每次取 $\min(\text{head}_a,\text{head}_b)$，其中一表已空则取另一表表头"的规则输出 $n+m$ 个元素，记输出序列为 $r_0,\dots,r_{n+m-1}$，则 $r$ **不降**；相等时取哪一侧都不影响该结论。

**证明**：先立一个不变式。记第 $t$ 步（即将输出 $r_t$）时两表中尚未输出的元素集合为 $U_t$。
(i) **$U_t$ 中的每个元素都 $\ge$ 本表的表头**：$a$ 侧剩余元素是 $a_i,a_{i+1},\dots$（下标 $i$ 为当前表头位置），由 $a$ 不降，$a_i\le a_{i+1}\le\cdots$；$b$ 侧同理。
(ii) **$r_t=\min U_t$**：若两表都非空，$\min U_t=\min(\min\{a_{i..}\},\min\{b_{j..}\})=\min(\text{head}_a,\text{head}_b)$，这一步用 (i)（每侧最小元就是表头）；若一表空，$U_t$ 只剩一表，最小元也是该表表头。规则取的正是它。
现在证 $r_t\le r_{t+1}$。$U_{t+1}=U_t\setminus\{r_t\}$，故 $U_{t+1}\subseteq U_t$。由 (ii)，$r_t\le u$ 对一切 $u\in U_t$ 成立，于是对一切 $u\in U_{t+1}$ 也成立；而 $r_{t+1}\in U_{t+1}$（它确实还没输出），故 $r_t\le r_{t+1}$。对 $t=0,\dots,n+m-2$ 逐次归纳，得 $r_0\le r_1\le\cdots\le r_{n+m-1}$。
最后看 tie 规则：$\text{head}_a=\text{head}_b=v$ 时取哪侧，取到的值都是 $v=\min U_t$，故 (ii) 仍成立，上述论证一字不改地通过。$\blacksquare$

（至于"一表已空则把另一表整条接上"：此时 $U_t$ 只剩一表的尾段，由 (i)（应用于该表自身的不降性）其最小元就是该表表头，故 (ii) 的推导不依赖"两表都非空"，无需另立情形；接上的尾段自身不降，且尾段每个元素都 $\ge$ 接入时刻的 $\min U_t=r$，故拼接处也不降。）

### 2.4 稳定性：tie 取 $a$ 才叫"稳定"（引理 4）

**引理 4（稳定性）** 若 tie 规则为"相等时取 $a$ 的元素"，则归并输出满足：(i) $a$ 内部相对顺序不变，$b$ 内部相对顺序不变；(ii) 值相同的两个元素，来自 $a$ 的一定排在来自 $b$ 的前面。

**证明**：
*(i)* 每个表的指针只会从表头依次前进，$i$ 严格单调增，故 $i<i'\Rightarrow a_i$ 早于 $a_{i'}$ 输出；$b$ 同理。
*(ii)* 反证。设存在 $a_i=b_j=v$ 而输出中 $b_j$ 在 $a_i$ **之前**。考察输出 $b_j$ 的那一步，此时 $a_i$ 尚未输出，设 $a$ 侧表头为 $a_{i'}$。由 (i) 的单调性，未输出的 $a$ 元素构成一段下标尾段 $\{i',i'+1,\dots\}$，$i$ 在其中，故 $i'\le i$；再由 $a$ 不降得 $a_{i'}\le a_i=v$。此步算法取的是 $\min(\text{head}_a,\text{head}_b)=\min(a_{i'},v)$：
- 若 $a_{i'}<v$，则 $\min=a_{i'}$，应输出 $a_{i'}$，与"输出了 $b_j$"矛盾；
- 若 $a_{i'}=v$，tie 规则"相等取 $a$"应输出 $a_{i'}$，同样矛盾。
故只能 $a_{i'}>v$，与 $a_{i'}\le v$ 矛盾。$\blacksquare$

引理 4 说明"合并后仍有序 + 相等不交换先后"这两件事都成立，也说明**题名所指的经典合并操作**在本题的输入下是良好定义的。

### 2.5 关键分岔：计数要的 tie 规则和稳定合并**相反**（引理 5）

归并扫描顺手就能"量 run 长度"：当 $b$ 侧连续吐出若干 $v$ 时，把它们数进 $v$ 的计数器。可是如果在 $a_i=v$ 与 $\text{head}_b=v$ 相等时**先取 $a$**（稳定规则），$a_i$ 就被结算了，而此时 $b$ 里那些 $v$ 还没被数进来。

**引理 5（结算时机）** 要在 $a_i$ 被"结算"（把它的 $c_i$ 交给异或和）的一刻就已经数完 $b$ 中所有等于 $a_i$ 的元素，必须采用"相等时**先消费 $b$ 的表头**"的规则；稳定规则会漏计。

**证明**：先给漏计的反例：$a=[2]$，$b=[2,2]$（满足全部保证：$a$ 严格递增、$b$ 不降）。按稳定规则，第一步 $a_0=2=\text{head}_b$，取 $a_0$，此刻 $b$ 一个都没消费，$c_0$ 被结算成 $0$；而按定义 $c_0=\#\{j:b_j=2\}=2$，**错了**。一般地：设稳定规则在 $a_i$ 输出的一刻 $b$ 侧表头是 $b_j$。若 $b_j=a_i$，则引理 1 的 run $\{p,\dots,q\}$（值 $a_i$）非空且 $j\le q$，$b_j,\dots,b_q$ 都等于 $a_i$ 且都还没消费，故此刻计数器至多数进该 run 中已被消费的 $j-p$ 个，缺 $q-j+1\ge 1$ 个，结算值 $<c_i$。反之，采用"相等时先消费 $b$ 表头"的规则，$b$ 中每个等于 $a_i$ 的元素 $b_t$（$p\le t\le q$）都在 $a_i$ 结算之前被消费：因为 $b_t=a_i$ 不满足 $a_i<b_t$，$a_i$ 不会因它被跳过；而只有遇到某个 $b_{t'}>a_i$ 时才有 $a_i<b_{t'}$ 触发 $a_i$ 的结算，由 $b$ 不降，$t'>q$，即整个 run 已在更早的步中被数完。$\blacksquare$

**由此定下主循环的骨架**：对读到的每个 $b$ 值 $v$，先把所有 $a_i<v$ 的下标结算并跳过（此时 $a_i$ 的计数彻底封顶），再在 $a_i=v$ 时把 $v$ 数进计数器。

### 2.6 异或在这里只是"累加器"（引理 6）

**引理 6（零元与可乱序）** 按位异或满足：(i) $x\oplus 0=x$，故 $c_i=0$ 的那些 $i$ 不改变答案；(ii) 交换律、结合律成立，故 $c_0,\dots,c_{n-1}$ 可以**按任意顺序**喂进同一个累加器，只要每个恰好喂一次；(iii) 每个元素自逆（$x\oplus x=0$），重复喂同一个数两次会抵消。

**证明**：异或按位独立，只需对单个二进制位验证。把位看作 $\mathbb{Z}/2\mathbb{Z}$，$\oplus$ 就是加法：(i) $x+0=x$；(ii) 加法交换、结合；(iii) $x+x=0$。逐位成立即整体成立。$\blacksquare$

(iii) 的用处是：非零的 $c_i$ **一旦被重喂就会被抹掉**，所以代码必须保证"每个下标至多结算一次"（$i$ 严格单调增 + 只在 $i$ 前进时结算，正好给出这一点）；反过来 (i) 允许我们放心地"喂 $0$"或跳过 $c_i=0$ 的下标。题面提示的 `getXorSum(c+1,c+1+n)` 是"先建 $c[]$ 数组再一次扫完"（那是提示里的 1-based 口径，与本文的 0-based 无关），本文把它换成"结算即异或"，由 (i)(ii) 二者给出同一个值；省掉 $c[]$ 正是内存减半的关键（§4.3）。

顺带一个等价的看法（"run 聚合"）：由引理 1、2、6，答案 $=\bigoplus_{v\in V}\ \#_b(v)$，其中 $V=\{v:\exists i,\ a_i=v\}$ 是 $a$ 的值集（引理 2 保证 $|V|=n$，即 $n$ 个下标对应 $n$ 个互异的值），$\#_b(v)$ 是 $b$ 中值 $v$ 的重数。也就是"只对 $b$ 的每段 run 判定这个值在不在 $a$ 里，在就异或 run 长度"。该实现要先读完一整段 run 才知道长度，得多养一组状态（上一值 + 当前段长），本文主代码沿用 §2.5 定下的骨架，只在 §4.4 用它作为独立口径复核真值。

### 2.7 主循环正确性：结算时机 + 收尾（引理 7）

主循环状态：$i$（$a$ 中尚未结算的最小下标）、$cnt$（当前 $a_i$ 已数到的次数）、$ans$。

**引理 7（不变式与收尾）** 处理完 $b_0,\dots,b_{t-1}$ 后（下称时刻 $t$），
(A) $ans=\bigoplus_{k<i} c_k$，且这些 $c_k$ 已是最终值；
(B) 若 $i<n$，则 $cnt=\#\{j<t:b_j=a_i\}$；
(C) $a$ 中所有能与 $b_t,\dots,b_{m-1}$ 相等的下标都 $\ge i$。
并且主循环结束后 $i$ 之后的所有 $c_k=0$，故收尾循环 `while(i<n){ans^=cnt;cnt=0;++i;}` 恰把剩余项全部异或进去。

**证明**：对 $t$ 归纳。$t=0$（还没读 $b$）：$i=0$，$ans$ 是空异或 $=0$，与 (A) 右端 $\bigoplus_{k<0}c_k=0$ 相符；(B) 右端 $\#\{j<0:\dots\}=\varnothing$ 计数为 $0$，与 $cnt=0$ 相符；(C) 中"$\ge 0$"是下标的最小可能值，故任何能与 $b_0..b_{m-1}$ 相等的下标自动 $\ge i=0$。
设时刻 $t$ 成立，读入 $v=b_t$，看循环体的三种情形。
**① $a_i<v$（while 分支，一次 `++i`）**：分三步证结算合法。
*(a) $c_i$ 已封顶*：$c_i=\#\{j:b_j=a_i\}$ 拆成 $j<t$ 与 $j\ge t$ 两半。对 $j\ge t$，由 $b$ 不降 $b_j\ge b_t=v>a_i$，故这些 $j$ 一个都不是匹配，即"$b_j=a_i\Rightarrow j<t$"。
*(b) $cnt$ 就是完整计数*：时刻 $t$ 的 (B) 说 $cnt=\#\{j<t:b_j=a_i\}$，配上 (a) 右端恰是 $c_i$，故 `ans^=cnt` 喂进去的是最终值，(A) 对推进后的 $i+1$ 成立。
*(c) 清零后 (B) 对新下标成立*：需证 $\#\{j<t:b_j=a_{i+1}\}=0$。反证：设有 $j<t$ 使 $b_j=a_{i+1}$。指针单调不减，故时刻 $j$ 的指针 $i_j\le i_t=i<i+1$。在 $b_j$ 这一次迭代的 while 里，条件 $a_x<b_j=a_{i+1}$ 由引理 2（严格递增）等价于 $x<i+1$，于是循环从 $i_j\le i$ 出发会一路前进、恰停在 $x=i+1$（因为 $a_{i+1}\not<b_j$），即 $i_{j+1}=i+1$。但 $j+1\le t$，单调性给 $i+1=i_{j+1}\le i_t=i$，矛盾。故该集合为空，`cnt=0` 与 (B) 相符。
同一次迭代里 while 若连进多步，就是对上述论证按 $i,i+1,\dots$ 逐个重复套用（每步的前提只涉及"当前 $t$、当前 $v$"，不变）。(C) 的保持：被越过的下标 $x$ 满足 $a_x<v\le b_{t'}\ (\forall t'\ge t)$，故它确实不再可能与未来的 $b$ 相等。
**② $a_i=v$（`++cnt` 分支）**：$i$ 不动，(A) 不变；(B) 左端 $cnt$ 加 $1$，右端 $\#\{j<t+1:b_j=a_i\}$ 因 $b_t=v=a_i$ 也恰加 $1$，同步成立；(C) 不变。
**③ $a_i>v$ 或 $i=n$（忽略分支）**：$i<n$ 时由 $a$ 递增，对一切 $k\ge i$ 有 $a_k\ge a_i>v$，故 $v$ 不等于任何未结算的 $a_k$；$i=n$ 时 $a$ 已全部结算。于是 (A)(B) 都不受影响（(B) 右端加 $0$，因为 $b_t=v\ne a_i$），且 (C) 保持——$v$ 本来就不可能是未来匹配对象。
综上，三种情形都保持 (A)(B)(C)，归纳完成；$t=m$ 时 (A) 给出 $ans=\bigoplus_{k<i_e}c_k$。
**收尾**：$t=m$（$b$ 读完）时记指针为 $i_e$。由 (B)，$cnt=\#\{j<m:b_j=a_{i_e}\}=c_{i_e}$，是完整计数。下证对一切 $k>i_e$ 有 $c_k=0$。反证：设存在 $j$ 使 $b_j=a_k$（$k>i_e$）。取该次迭代开始前的指针 $i_j$，单调性给 $i_j\le i_e<k$。在 $b_j=a_k$ 这一步，while 的条件 $a_x<b_j$ 由引理 2 等价于 $a_x<a_k$ 等价于 $x<k$（$x<k\Rightarrow a_x<a_k$；$x\ge k\Rightarrow a_x\ge a_k$，严格递增给出双向），故循环从 $i_j<k$ 出发会逐步前进并**恰好停在** $x=k$（在 $k$ 处 $a_k\not<b_j$ 而退出），于是 $i_{j+1}=k$；再单调性给 $i_e\ge i_{j+1}=k$，与 $k>i_e$ 矛盾。所以这种 $j$ 不存在，即 $c_k=0$。
由引理 6(i)，$0$ 可以异也可以不异，收尾循环 `while(i<n){ans^=cnt;cnt=0;++i;}` 的效果就是"把 $c_{i_e}$ 喂进去、其余下标喂 $0$"，每个下标恰好一次。结合 (A)（$k<i_e$ 的部分）得 $ans=\bigoplus_{k=0}^{n-1}c_k$，即题面要求的 $c_1\oplus\cdots\oplus c_n$。$\blacksquare$

> **引理 5 与这里的对应**：上面 (a)(b) 两步正是引理 5 的操作性读法——**只有 $a_i<v$ 才结算**，相等时只累加不推进，于是 $b$ 中等于 $a_i$ 的整段 run（引理 1）必然在结算点之前被榨干。若沿用引理 4 的稳定 tie 规则（相等时先出 $a$），(b) 中的 $cnt$ 会少数掉尚未消费的尾部，故**必须反过来**。

### 2.8 保证的边界（题面那句"保证 $a$ 中没有重复"不是废话）

引理 2 是整个"单计数器"设计的地基。若违反保证，例如 $a=[2,2]$（不严格递增）、$b=[2]$：定义给出 $c_0=c_1=1$，答案 $1\oplus1=0$。而本文代码只在 $a_i=v$ 时给 $cnt$ 加一次，指针停在 $i=0$，收尾异或一个 $1$ 后清零、再异或 $0$，输出 $1$——**错**。原因是同一段 run 需要同时计给两个下标，单个 $cnt$ 无法分身。可见"严格递增"是必要前提（不承诺越界输入下的行为）；若要支持重复，得改成"连续相同 $a$ 一起结算"或用 §2.6 的 run 聚合并对每段 run 数 $a$ 中的重合个数，代价是状态翻倍。

### 2.9 类型与 IO 预算（题面两条提示的落点）

- $1\le a_i,b_i<2^{64}$：用 `unsigned long long`（可表示 $[0,2^{64}-1]$，上界恰覆盖）。若用 `long long`，$\ge 2^{63}$ 的值读不进来（`cin` 置 failbit / 手算解析会回绕），比较序也乱。全文对值**只比较不做算术**，所以无回绕风险。
- $n,m\le 10^7$：`int`（上限 $2^{31}-1$）绰绰有余；$cnt\le m<2^{24}$；每个 $c_i<2^{24}\Rightarrow ans<2^{24}$（异或不产生新的 $1$ 位）。
- $10^7$ 个数 $\times$ 最多 $20$ 位十进制 $\approx 2\times10^8$ B 输入：必须快读，`cin`（即使 `sync_with_stdio(false)`）在这个量级上是题面"避免超时"警告的靶子。本文用 $1\,\mathrm{MiB}$ 的 `fread` 缓冲。

## 3. 模式总结（按实际思考顺序）

- **explore its property** — $b$ 的相等值挤成连续 run（引理 1），$a$ 严格递增使 run 至多匹配一个下标（引理 2）：单计数器由此成立。
- **consider easier version** — 值域桶（$2^{64}$，不可行）$\to$ 逐个二分 $O(n\log m)$，它留作"定义级暴力基准"。
- **classic problem solution** — 归并扫描（题名+标签 two-pointer）把总复杂度降到 $O(n+m)$。
- **explore its property（对被借用的运算本身）** — 证合并结果不降（引理 3）与 tie 取 $a$ 的稳定性（引理 4）。
- **discuss by category / 关键分岔** — 计数要的 tie 规则与稳定合并**相反**：相等时先榨 $b$，否则漏计（引理 5 反例 $a=[2],b=[2,2]$）。
- **classic problem solution（第二个不同技巧）** — 异或的代数结构（$0$ 是元、可乱序、自逆，引理 6）把"$c[]$ 数组 + `getXorSum`"换成"边结算边异或"，顺带给出 run 聚合的等价式。
- **reduce to easier problem** — 归约成"带结算时机的单遍双指针"，写出不变式 (A)(B)(C) 并归纳证明（引理 7）。
- **边界审计 + 资源预算** — 违反 $a$ 严格递增会算错（§2.8）；$u64$ 存值、只存 $a$、`fread` 快读（§2.9、§4.3）。

## 4. 真实解法（Real Solution）

### 4.1 符号表

| 符号 | 存什么 | 类型 / 初始化 | 一行记忆点 |
|---|---|---|---|
| `n,m` | 本组 $a,b$ 长度 | `int`，每组重新读入 | $1\le n,m\le10^7$ |
| `a[i]` | $a$ 数列，0-based，严格递增 | `u64 a[mxn]`，只存 $a$（$b$ 流式） | "表头在 $a_i$" |
| `i` | $a$ 中**尚未结算**的最小下标 | `int`，每组 $0$ 起 | 只增不减 |
| `v` | 刚读到的 $b$ 元素 | `u64`，循环内临时量 | 读一个处理一个，不留存 |
| `cnt` | $a_i$ 当前已数到的次数 | `u64`，每组 $0$ 起 | $i$ 前进时清零 |
| `ans` | $\bigoplus_{k<i}c_k$ | `u64`，每组 $0$ 起 | 异或累加器 |
| `rd()` | 无符号十进制快读 | 返回 `u64` | 只处理正数（数据保证 $\ge1$） |

**下标约定**：全文与代码一律 **0-based**（$i=0..n-1$），题面的 $a_1..a_n$ 对应 `a[0..n-1]`。输出只有一行整数，不涉及 $+1$ 换算。

### 4.2 算法步骤

1. 读 $T$；每组依次读 $n,m$，把 $n$ 个 $a_i$ 存进 `a[]`（$b$ 不存）。
2. `i=0; cnt=0; ans=0;`
3. 对 $j=0..m-1$ 逐个读 $v$：
   1. `while(i<n && a[i]<v)`：结算 $a_i$ —— `ans^=cnt; cnt=0; ++i;`（引理 5：此刻 $c_i$ 已封顶）
   2. `if(i<n && a[i]==v) ++cnt;`（run 内继续累加）
   3. 其余（$a_i>v$ 或 $i==n$）忽略该 $v$（引理 7 情形 ③）
4. 收尾：`while(i<n){ans^=cnt;cnt=0;++i;}`（引理 7：只有第一个 $cnt$ 非零，其余是 $0$）
5. `cout<<ans<<'\n';`

### 4.3 复杂度与资源预算

- **时间**：每组 $O(n+m)$。while 循环全体执行次数 $\le n$（$i$ 只增），故 $b$ 侧每元素摊到 $O(1)$；总比较次数 $<3(n+m)$，全数据 $n+m$ 之和 $\le10^7$ ⇒ 约 $3\times10^7$ 次比较 + $10^7$ 次十进制解析。解析成本随数字位数增长（每个数最多 $20$ 位）⇒ 真正的瓶颈是**读入字节数 $\sim2\times10^8$**，这也是选 `fread` 的理由。
- **空间**：`a` = $10000005\times8\,\mathrm{B}=8.0\times10^7\,\mathrm{B}\approx76.3\,\mathrm{MiB}$，读入缓冲 $1\,\mathrm{MiB}$，无其他与 $n$ 相关的数组 ⇒ 峰值约 $78\,\mathrm{MiB}$。若照"存 $a$ 又存 $b$"写，两个 $10^7$ 尺寸的 `u64` 数组静态分配是 $160\,\mathrm{MB}$，比本解高一倍。
- **为什么 $a$ 非存不可**：$a$ 先于 $b$ 进入输入流，而 $c_i$ 要等 $b$ 读到最后才能定；stdin 是管道（不可 `fseek`，也没有第二遍）$\Rightarrow$ 必须原样留下全部 $64$ 位 $\times n$ 的信息，$8n\,\mathrm{B}$ 是固有下界，与算法无关。注意"改存 $b$ 更省"在这里**不成立**：$b$ 在 $a$ 之后才读入，若届时 $a_i$ 已丢失，无论二分还是双指针都无从查询（§2.2 的二分实现同样必须存 $a$，只是它还额外要存 $b$）。本解把 $b$ 改成流式处理，正好省掉那一半。
- **溢出预算**：`u64` 装 $<2^{64}$ 的值 ✓；解析 `x=x*10+(c-'0')` 时前缀值单调递增且不超过终值，终值 $\le2^{64}-1$ ⇒ 不回绕（若真出现 $2^{64}$ 会静默回绕成 $0$，数据保证排除了它）；$n,m,i\le10^7\ll2^{31}-1$；$cnt\le m<2^{24}$；$ans<2^{24}$。

### 4.4 验证状态（全部手工推演，未运行任何代码）

> 本环境不编译、不运行；未做任何对拍，不声称得分或耗时。每组"真值"按定义直接数 $b$ 中的重数得到（等价于 §2.2 的二分暴力）。再用 §2.6 的 run 聚合式 $\bigoplus_{v\in V}\#_b(v)$ 复核一遍，两口径必须同值——例如算例 C 的 $b$ 分成 run $1(1),2(3),5(1),7(2),9(1)$（括号内为重数），其中只有 $2,7$ 属于 $a$ 的值集 $V$，故 $3\oplus2=1$，与逐下数的 $c=[3,2]$ 同值 ✓。

- **算例 A（题面解释 1，官方答案锚点）** $a=[1,3,6]$，$b=[1,3,3]$ ⇒ 真值 $c=[1,2,0]$，题面给出输出 $3$。扫描：$v=1$: $cnt=1$；$v=3$: 结算 $a_0$（$ans=1$）后 $cnt=1$；$v=3$: $cnt=2$；收尾 $ans=1\oplus2=3$，再异或 $0$。✓
- **算例 B（题面解释 2，锚点）** $a=[1,4,5]$，$b=[1,1,4,5]$ ⇒ $c=[2,1,1]$，题面给出输出 $2$。扫描：$ans=2$（结算 $a_0$）$\to\oplus1=3$（结算 $a_1$）→ 收尾 $\oplus1=2$。✓
- **算例 C（相等元素 + 多个 run + 被忽略的 $b$ 值）** $a=[2,7]$，$b=[1,2,2,2,5,7,7,9]$ ⇒ 真值 $c=[3,2]$，$3\oplus2=1$。$v=1$ 忽略（$2>1$）；$v=2$ 三次 $\Rightarrow cnt=3$；$v=5$ 结算 $a_0$（$ans=3$）后忽略（$7>5$）；$v=7$ 两次 $\Rightarrow cnt=2$；$v=9$ 结算 $a_1$（$ans=3\oplus2=1$）后 $i=n$ 忽略。收尾空转。输出 $1$ ✓
- **算例 D（交集为空 / "贡献为空表"）** $a=[5,6,7]$，$b=[1,2]$ ⇒ $c=[0,0,0]$，$ans=0$。两值均忽略；收尾异或三个 $0$。✓
- **算例 D'（$a$ 全部小于 $b$，测 $i==n$ 防越界）** $a=[1,2]$，$b=[5,6]$ ⇒ $c=[0,0]$。$v=5$：while 连结算两个（各异或 $0$），$i=2=n$，`if` 因 $i<n$ 为假而不访问 $a[2]$；$v=6$ 同样不访问。输出 $0$ ✓
- **算例 E（长度 $1$ 的三种关系）** $n=m=1$：$a=[4],b=[4]\Rightarrow c=[1]\Rightarrow ans=1$（走 `++cnt` + 收尾）；$a=[4],b=[3]\Rightarrow c=[0]\Rightarrow ans=0$（忽略 + 收尾异或 $0$）；$a=[4],b=[9]\Rightarrow c=[0]\Rightarrow ans=0$（while 结算 $a_0$ 后 $i=n$）。✓
- **算例 F（值域上界，验类型）** $a=[2^{64}-1]$，$b=[2^{63}-1,\,2^{64}-1,\,2^{64}-1]$ ⇒ $c=[2]$，$ans=2$。$v=2^{63}-1$：$a_0<v$？$2^{64}-1<2^{63}-1$ 为假（无符号比较，不会因符号位翻转），忽略；两个 $2^{64}-1$ 各 `++cnt`；收尾 $\oplus2$。解析 $18446744073709551615$：前缀 $1,18,184,\dots$ 均 $\le$ 终值 $=2^{64}-1$，可表示 ✓
- **算例 G（异或抵消，验"每个 $c_i$ 恰好喂一次"）** $a=[1,2,3]$，$b=[1,1,2,2]$ ⇒ $c=[2,2,0]$，$2\oplus2\oplus0=0$。$ans$：$0\xrightarrow{\oplus2}2\xrightarrow{\oplus2}0$，收尾对 $a_2$ 异或 $0$。输出 $0$ ✓
- **引理 5 的失败例（对照，非本题代码行为）** $a=[2]$，$b=[2,2]$：稳定 tie 规则先出 $a_0$ 会把 $c_0$ 结算成 $0$；本题代码用"相等时 `++cnt`"，得 $cnt=2$、收尾 $\oplus2=2$，与定义一致 ✓
- **§2.8 越界例（如实报告不一致）** $a=[2,2]$（**违反** $a_i<a_{i+1}$），$b=[2]$：定义 $1\oplus1=0$，代码输出 $1$。已定位为引理 2 前提被破坏（§2.8），**不对越界输入承诺正确**。
- **不变式抽查（算例 C 的 $(i,cnt,ans)$ 逐步轨迹）**：$a=[2,7]$，$b=[1,2,2,2,5,7,7,9]$。

  | 读入 $v$ | 分支 | $i$ | $cnt$ | $ans$ |

  | — | 初态 | 0 | 0 | 0 |
  | 1 | ③ 忽略（$a_0=2>1$） | 0 | 0 | 0 |
  | 2 | ② `++cnt` | 0 | 1 | 0 |
  | 2 | ② | 0 | 2 | 0 |
  | 2 | ② | 0 | 3 | 0 |

## 5. 示例代码（C++）

```cpp
// P1366 有序表的合并
// 归并扫描（tie 先榨 b）：结算 a_i 时其匹配数已封顶，边结算边异或
#include<bits/stdc++.h>
using namespace std;
using u64=unsigned long long;

constexpr int mxn{10000005};        // n<=1e7 +5；只存 a，b 流式读

u64 a[mxn];
int n,m;

inline int gc()
{
	static char buf[1<<20],*p=buf,*q=buf;
	return p==q&&(q=(p=buf)+fread(buf,1,1<<20,stdin),p==q)?EOF:*p++;
}
inline u64 rd()
{
	u64 x=0;
	int c=gc();
	while(c<'0'||c>'9')
	{
		if(c==EOF)
			return 0;
		c=gc();
	}
	while(c>='0'&&c<='9')
	{
		x=x*10+(c-'0');
		c=gc();
	}
	return x;
}

void solve()
{
	n=rd();
	m=rd();
	for(int i=0;i<n;++i)
		a[i]=rd();
	u64 ans=0,cnt=0;
	int i=0;
	for(int j=0;j<m;++j)
	{
		u64 v=rd();
		while(i<n&&a[i]<v)
		{
			ans^=cnt;                 //c_i 已封顶
			cnt=0;
			++i;
		}
		if(i<n&&a[i]==v)
			++cnt;                    //相等时先数 b，不推进 i
	}
	while(i<n)
	{
		ans^=cnt;                     //只有当前这个 cnt 可能非 0
		cnt=0;
		++i;
	}
	cout<<ans<<'\n';
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	for(int t=rd();t;--t)
		solve();
	return 0;
}
```

### 代码说明

- **全局静态数组** `u64 a[mxn]` + `constexpr int mxn{10000005}`（上界 $10^7$ 再 +5 松弛）；不存 $b$，也不需要 $c[]$（引理 6 让"边结算边异或"合法）。
- **快读**：`gc()` 用 $1\,\mathrm{MiB}$ `fread` 缓冲，**返回 `int`**（若返回 `char`，在 `char` 默认无符号的平台上调到文件尾时 `EOF` 会被截成 $255$，`c==EOF` 判不出来）；`rd()` 解析无符号十进制，数据保证 $\ge1$ 故不处理负号。这是题面"注意大量数据读入"的落点。输入走 C（`fread`）、输出走 C++（`cout`），两个方向不交叉，`sync_with_stdio(false)` 下没有顺序风险。
- **主循环三叉**即引理 7 的 ①②③；`while` 总支数 $\le n$ 保证 $O(n+m)$。
- **`i<n` 的短路检查**在两处 `a[i]` 访问前都写了，$i=n$ 时绝不越界（算例 D'/F）。
- 每组进入 `solve()` 时 `ans,cnt,i` 都是**局部重新初始化**，多测之间无残留（$T\le10$）。
- `cin.tie/cout.tie/sync_with_stdio` 顺序按规范；换行用 `'\n'`；运算符无空格；Tab 缩进；函数名 `gc/rd/solve` 小写电报式；全文 0-based。
