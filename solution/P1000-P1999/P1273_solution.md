# P1273 有线电视网 — 题解

## 第一部分：重读题目

把有线电视网的树想成"花钱买用户"：

- 根结点 `1` 是转播现场，它是所有信号的唯一源头。
- 用户结点是 `N-M+1` 到 `N`（叶子），其它是内部中转站。
- 每条边 `(u→v)` 有一个**传输费用** `c(u,v)`：要让 `v` 子树里的用户收到信号，这条边必须"开通"一次。
- 每个用户 `u` 愿意付 `pay[u]` 元（`≤10`）。

**不亏本**：所选所有用户愿意付的钱的总和 ≥ 开通信号所花的所有边的费用总和。

**目标**：在不亏本的前提下，让能收到信号的用户**数量**最大（注意：最大化的是"用户数"这个 count，不是总付费额）。

**输入**：
- 第 1 行：`N M`，`2 ≤ N ≤ 3000`，`1 ≤ M ≤ N-1`。
- 接下来 `N-M` 行：第 `i` 行描述转播站 `i`（`i=1..N-M`）下接的 `K` 个儿子，每个儿子是 `A C` 对（儿子编号 `A`、费用 `C`）。
- 最后一行：`M` 个整数，第 `k` 个是用户 `N-M+k` 愿意付的钱。

**输出**：一个整数，最大用户数。

**关键约束**：单次传输成本 ≤ 10，每个用户付费 ≤ 10，`N ≤ 3000`。

样例：`N=5, M=3`，用户 3,4,5 付费 3,4,2；边费用 1→2 费 2、1→5 费 3、2→3 费 2、2→4 费 3。全收 3 个用户花 10 元 > 收 9 元，亏本；只收 3,4 花 7 元 ≤ 收 7 元，可行 → 答案 2。

## 第二部分：思考链（发现过程 + 完整证明）

### Step 1：探索机制 — 连通性强制"前缀付费"

先看这道题的"特殊机制"在干什么：要服务某个用户，从根到他祖先链上**每一段**的边都必须付钱。

**引理 1（连通性）**：若某用户 `x` 收到信号，则对根 `1` 到 `x` 的**每一条边**都必须支付其费用（即这条边被"开通"）。

**证明**：信号只从根出发，沿边逐跳传输。要传到 `x`，信号必须沿着 `1→…→x` 这条唯一路径（树中路径唯一）逐边传输。每传输一跳就产生一次该边的费用，且费用是"每边一次、与经过它的用户数无关"（题目：总费用 = 传输信号的费用总和，每条被使用的边计一次）。因此每条边必须被支付。∎

**推论（前缀结构）**：设 `x` 被选中。则 `x` 的整条祖先链上的边都进入了"已付"集合。反过来，若某条边没被付，它下面所有用户都不可能收到信号。

所以"选中用户集合 S"和"已付边集合 E(S)"是一一对应的：**S 被选中 ⟺ 已付边集合恰好包含"1 到 S 中每个节点路径"的并集**。这给了我们一个干净的刻画：

> 一个可行方案 = 选择一棵**连通含根的连通子树**（从根出发的"前缀闭包"），其叶子/内部中恰好是那些被服务的用户；成本 = 这棵子树所有边的费用和；收入 = 这棵子树中所有**用户叶子**的付费之和。

换句话说，我们选的是"根的一棵连通诱导子树"，代价是边权和，收益是子树里用户叶子的付费。目标：在 (收益 ≥ 代价) 约束下最大化用户叶子数。

### Step 2：考虑简化版本 — 剥离"付费"，先看"成本"的结构

如果暂时不管"付费 ≥ 成本"这个不等式，直接想"给定预算 B，最多能服务多少用户"，会怎样？

- 预算 B = 能花的最大总成本。
- 每服务一个用户 `x`，要付从根到 `x` 的边费用；但多条路径**共享前缀**（一条边只付一次）。
- 收益 = 服务到的用户**数量**（每个用户算 1）。

这正是**树形依赖背包**：在树上选一组节点（用户），代价是"覆盖这些节点所需边权的并集"（共享边只算一次），价值是节点数，容量是预算。标准解法是后序 DFS + 子树 knapsack merge。

但我们的真正目标不是"固定预算下最大用户数"，而是"**付费 ≥ 成本**下最大用户数"——付费随所选用户变化，不是固定预算。所以不能直接套用，需要把"付费"也纳入状态。下一步找办法。

### Step 3：精确刻画目标 — 把不等式改写成可加量

设方案 = 选中用户集合 S（S ⊆ 用户叶子）。
- `cost(S)` = `Σ_{e ∈ 覆盖(S)} c(e)`，覆盖(S) = 根到 S 中每个节点路径的边之并（由引理 1 确定）。
- `rev(S)` = `Σ_{x ∈ S} pay[x]`。
- 约束：`rev(S) ≥ cost(S)`，目标：最大化 `|S|`。

**关键一步**：定义**盈余** `surplus(S) = rev(S) − cost(S)`。约束等价于 `surplus(S) ≥ 0`。

**引理 3（盈余可加性）**：对任意方案 S，`surplus(S) = Σ_{x∈S} pay[x] − Σ_{e∈覆盖(S)} c(e)` 满足**逐元素可加**：每个用户 `x` 贡献 `+pay[x]`，每条被覆盖的边 `e` 贡献 `−c(e)`。

**证明**：直接由定义展开。`rev(S)` 是 S 中用户付费之和（逐用户相加），`cost(S)` 是覆盖(S) 中边权和（逐边相加）。两者都是"对集合元素求和"，故 `surplus = Σ(用户贡献) + Σ(边贡献)` 是逐元素的线性组合，可加性平凡成立。∎

**引理 4（连通子树上的可分解性）**：设 S 对应连通含 u 的子树方案 U（U 是包含 u 的连通子树，S = U 中的用户叶子）。对 u 的某个儿子 v，令 `U_v = U ∩ T(v)`（v 子树内被选中的部分，含 v 当且仅当 v ∈ U）。则：
- 若 `U_v` 非空（选了 v 子树的某些用户）：U 相对 `U \ U_v` 多出的边恰好是 `(u,v)` 加上 `U_v` 内部的边，多出的用户恰好是 `U_v` 内的用户。
- 因此 `surplus(U) = surplus(U \ U_v) + surplus(U_v) − c(u,v)`。

**证明**：把 U 的边集与用户集按"是否属于 U_v"二分。
- 用户集：`S = (S \ S_v) ∪ S_v`，其中 `S_v = U_v` 内的用户（S 与 S_v 不相交，用户是叶子、只属一个子树）。故 `rev(U) = rev(U \ U_v) + rev(U_v)`。
- 边集：覆盖(S) 的边中，"u 到 S 的路径"经过 `(u,v)` 当且仅当 `S_v` 非空。若 `S_v` 非空，`(u,v)` ∈ 覆盖(S)，且 `U_v` 内部的边（v 到 `S_v` 各用户路径的并）也 ∈ 覆盖(S)；其余边属于 `U \ U_v` 的覆盖。若 `S_v` 空，`(u,v)` 与 `U_v` 边都不在覆盖(S) 中。
- 因此 `cost(U) = cost(U \ U_v) + [S_v 非空 ? c(u,v) : 0] + cost(U_v)`。
- 相减即得 `surplus(U) = surplus(U \ U_v) + surplus(U_v) − c(u,v)·[S_v 非空]`。∎

**引理 4 的意义**：盈余在"合并一个儿子子树"时，只需把儿子子树的盈余加上、再扣掉连接边 `c(u,v)`（若该儿子子树非空）。这是把 DP 写成"逐儿子合并"的基础。

### Step 4：经典技术 — 以"盈余"为容量维的树形依赖背包

**为什么用"盈余"而不是"成本"当容量维？**

若用"成本 = j"当状态、存"最大用户数"，转移合并时无法检查"付费 ≥ 成本"——子方案只给了用户数，没给付费，合并后无法算出总付费来验证约束。同理，若存"最大付费"，又丢失了用户数（目标量）。**单维状态无法同时携带"成本、付费、用户数"三者中的两个独立信息。**

**破局**：约束 `付费 ≥ 成本` ⟺ `盈余 = 付费 − 成本 ≥ 0`。**把"盈余"本身作为状态维**，则：
- 目标"最大化用户数"作为状态值（value）。
- 约束"盈余 ≥ 0"作为状态的有效性条件（只保留 `j ≥ 0` 的状态）。
- 转移时盈余可加（引理 3、4），合并儿子 = 盈余相加 + 扣边成本。

这样**单维状态 `f[u][j]`（j = 盈余）同时编码了约束（j ≥ 0）和目标（用户数），绕开了"需要同时存成本和付费"的困境。**

**状态定义**：
`f[u][j]` = 在 u 的子树 `T(u)` 内，**假设 u 已被其父亲接通**（u 到根的路径已付费、u 可用），选一个**连通且包含 u** 的节点子集 U ⊇ {u}（从 u 往下选的连通子树），设 U 含用户叶子 `S_U`、U 内边（不含 u 到父的边）费用和 `cost(U)`、用户付费和 `rev(U)`。
`f[u][j]` = 在所有满足 `surplus(U) = rev(U) − cost(U) = j`（`j ≥ 0`）的连通含 u 子树 U 中，`|S_U|` 的**最大值**；不可达记为负哨兵。

**答案**：`ans = max_{j ≥ 0} f[1][j]`（根处盈余 ≥ 0 的最大用户数）。

### Step 5：转移的正确性证明

**引理 5（最优子结构 + 转移完备性）**：对中转节点 u，儿子 `v_1..v_k`（边权 `c_i`）。处理完前 `i−1` 个儿子后记当前 DP 为 `f[u][·]`。合并第 i 个儿子 `v_i` 时，新 DP 为：

```
new[j] = max( f[u][j],                                  // 不选 v_i 子树
              max_{t ≥ c_i} ( f[u][j - (t - c_i)] + f[v_i][t] )   // 选 v_i，其盈余 = t
            )
```
（`f[u][·]` 取值范围限在"已合并部分的盈余上限"内，`f[v_i][t]` 在 `[0, subpay[v_i]]`，要求 `j - (t - c_i) ≥ 0`。）

**证明（完备性 + 最优性）**：
- **完备性（不漏解）**：任取合法方案 U（连通含 u），看它对 `v_i` 的选择：
  - 若 `v_i` 子树没被选（`S_{v_i}` 空）：U 在 `v_i` 方向无贡献，`surplus(U) = surplus(U \ U_{v_i})`，对应转移第一项 `f[u][j]`（`j = surplus(U \ U_{v_i})`）。
  - 若 `v_i` 子树被选（`S_{v_i}` 非空）：由引理 4，`surplus(U) = surplus(U \ U_{v_i}) + surplus(U_{v_i}) − c_i`。记 `t = surplus(U_{v_i})`，则 `surplus(U \ U_{v_i}) = j − (t − c_i)`。U 的用户数 = `|(U \ U_{v_i}) 的用户| + |U_{v_i} 的用户| ≤ f[u][j-(t-c_i)] + f[v_i][t]`（f 存最大值）。故 U 的用户数 ≤ 转移第二项某取值。
  - 综上，任意合法 U 的用户数都被转移覆盖（≤ 转移结果某项）。
- **最优性（不取非法解）**：
  - 第一项 `f[u][j]`：不选 `v_i`，U 仍连通含 u、盈余 `j ≥ 0`，合法。
  - 第二项要求 `t ≥ c_i`，即 `surplus(U_{v_i}) ≥ c_i`，从而 `t − c_i ≥ 0`，合并后 `surplus(U) = (j-(t-c_i)) + (t-c_i) = j ≥ 0`，合法；`f[v_i][t]` 本身合法（`v_i` 子树连通含 `v_i`、盈余 t ≥ 0）。
  - 故转移产生的每个 `new[j]` 都对应合法 U。
- 由完备性（转移结果 ≥ 任意合法解）+ 最优性（转移结果 ≤ 最优合法解），得 `new[j] = 最优合法解`。∎

**引理 6（基例正确性）**：
- u 是用户叶子：合法 U 只有 `{u}`。`surplus({u}) = pay[u] − 0 = pay[u]`，用户数 1，故 `f[u][pay[u]] = 1`，其余不可达。实现里另置 `f[u][0] = 0`（"u 接通但暂不服务任何用户"的中间占位态，对用户叶子最终无贡献、无害）。
- u 是中转站：初始（未合并儿子）U = {u}，无用户，`surplus = 0`，用户数 0，故 `f[u][0] = 0`。
- 两种基例均满足状态定义。∎

### Step 6：大小截断优化

**引理 7（截断上界）**：对节点 u，`surplus(U) ≤ rev(U) ≤ subpay[u]`（`subpay[u]` = u 子树内所有用户付费之和），因 `cost(U) ≥ 0`。故 `f[u][j]` 对 `j > subpay[u]` 必不可达，可安全截断。

**证明**：`surplus(U) = rev(U) − cost(U) ≤ rev(U) ≤ Σ_{x∈T(u)∩用户} pay[x] = subpay[u]`。∎

合并 u 的第 i 个儿子时，"已合并部分"盈余上限 = 已处理子树付费和（记 `lim`）。枚举 `j1 ∈ [0, lim]`、`t ∈ [c_i, subpay[v_i]]`，合并后 `j = j1 + t − c_i ≤ lim + subpay[v_i]`，再截断到 `[0, subpay[u]]`。

**复杂度**：树形背包合并的经典界 `O(Σ_u subpay[u] · subpay[son])`。利用"儿子子树付费和之和 = subpay[u]"的性质（树形背包标准分析：每对 (用户付费, 节点) 至多在其 LCA 处贡献一次乘法），总复杂度 `O(N · total_pay)` 量级，`total_pay = Σ pay ≤ 10M ≤ 30000`、`N ≤ 3000`，实际约 `1e7 ~ 1e8` 次操作，可接受。

## 第三部分：模式总结

```
- explore its property — 连通性强制"前缀付费"：选用户 ⟹ 根到它路径的边全要付；方案 = 连通含根子树
- consider easier version — 固定预算 B 下"最多服务多少用户" = 树形依赖背包（先剥离付费约束）
- classic problem solution — 树形背包（后序 DFS + 子树 knapsack merge），容量维 = 成本/盈余
- reduce to easier problem — 把"付费 ≥ 成本"整体约束改写为可局部累加的"盈余 = 付费 − 成本 ≥ 0"（边 −c、用户 +pay）
- classic problem solution — 以"盈余"为容量维的依赖背包，价值 = 用户数；合并时扣边成本
- defer reconstruction — 只需答案（最大用户数），不重构方案；大小截断优化复杂度
```

## 第四部分：真实解法（代码做什么）

### 记号表

| 符号 | 含义 | 初始化 | 助记 |
|---|---|---|---|
| `n, m` | 结点总数、用户数 | 输入 | n = N, m = M |
| `pay[u]` | 用户 u 愿意付的钱（`u ∈ [N-M+1, N]`） | 输入最后一行 | pay = 付费 |
| `graph[u]` | u 的儿子列表，每个元素 `{v, c}`：儿子编号 v、边费用 c | 输入前 N−M 行 | 邻接（带权） |
| `isuser[u]` | u 是否用户叶子（`u ≥ N-M+1`） | `u >= n-m+1` | 叶子判定 |
| `subpay[u]` | u 子树内所有用户付费之和（盈余上限） | DFS 后处理计算 | 子树付费和 |
| `f[u][j]` | **u 子树内、u 已接通、盈余（付费−成本）恰为 j（j ≥ 0）时的最大用户数**；`-1` 表示不可达 | `f[u][0] = 0`；若 isuser 则 `f[u][pay[u]] = 1` | f = users, j = surplus |

> **盈余语义**：`surplus = 付费之和 − 成本之和`。要求 `surplus ≥ 0`（不亏本）。边贡献 `−c`，用户贡献 `+pay`。`j = 0` 表示刚好不亏，`j > 0` 表示盈余 j 元。

### 算法步骤

1. **读入**：读 `n, m`。读 `n-m` 行，第 `i` 行（`i = 1..n-m`）为转播站 `i` 的 `K` 个儿子 `{A, C}`，存入 `graph[i]`。读最后一行 `m` 个付费，`pay[N-M+k] = 第 k 个`。

2. **DFS（后序，从根 1 开始）**：对节点 `u`：
   - **初始化**：先把 `f[u][*]` 全置为不可达（负哨兵）。`f[u][0] = 0`（u 已接通但暂不服务任何用户，盈余 0、用户数 0）。若 `isuser[u]`：`f[u][pay[u]] = max(f[u][pay[u]], 1)`（服务 u 本身，盈余 pay[u]、用户数 1）。`subpay[u] = isuser[u] ? pay[u] : 0`。
   - **逐儿子合并**：记 `lim` = 当前已合并部分的盈余上限（初值 `subpay[u]`）。对每个儿子 `v`（边权 `c`）：
     - 递归 `dfs(v)`，得到 `f[v][·]` 与 `subpay[v]`。
     - `newlim = lim + subpay[v]`（合并后盈余上限，再截断到 `subpay[u]`）。
     - 用临时数组 `tmp[*]`（初值不可达）做新状态：
       - 枚举 `j1 ∈ [0, lim]`：若 `f[u][j1]` 不可达则跳过。
       - **不选 v 子树**：`tmp[j1] = max(tmp[j1], f[u][j1])`。
       - **选 v 子树**：枚举 `t ∈ [c, subpay[v]]`（`t ≥ c` 保证扣边后非负）：若 `f[v][t]` 不可达则跳过；`j2 = j1 + t − c`；若 `j2 > newlim` 跳过；`tmp[j2] = max(tmp[j2], f[u][j1] + f[v][t])`。
     - 把 `tmp[0..newlim]` 写回 `f[u]`，更新 `lim = newlim`、`subpay[u] += subpay[v]`。
   - 合并完所有儿子，`f[u]`、`subpay[u]` 就绪，返回。

3. **答案**：`ans = max_{j ≥ 0} f[1][j]`（根处盈余 ≥ 0 的最大用户数）。

### 复杂度

- **时间**：树形背包合并，`O(Σ_u subpay[u] · subpay[son])`，大小截断优化后 `O(N · total_pay)` 量级，`N ≤ 3000`、`total_pay ≤ 10M ≤ 30000`，实际约 `1e7 ~ 1e8` 次操作。
- **空间**：`f[u][0..subpay[u]]`。全局开 `short f[mxn][mxp]`（`mxn = 3005`、`mxp = 30005`）≈ `3005 × 30005 × 2B ≈ 180MB`。用户数 ≤ 3000 < 32767，`short` 不溢出。若 OJ 内存 < 180MB，可改按 `subpay[u]` 动态分配行（`vector<short> f[u](subpay[u]+1)`），实际每节点只访问 `[0, subpay[u]]`，远小于全表。

### 验证状态

- **样例验证**（手工逐步）：`N=5, M=3`，pay[3]=3、pay[4]=4、pay[5]=2，边 1→2(c2)、1→5(c3)、2→3(c2)、2→4(c3)。
  - 用户 3：路径 1→2→3，成本 4，付费 3，盈余 −1 < 0（单用户亏）。
  - 用户 4：路径 1→2→4，成本 5，付费 4，盈余 −1 < 0。
  - 用户 5：路径 1→5，成本 3，付费 2，盈余 −1 < 0。
  - 用户 3+4：成本 (1→2)+(2→3)+(2→4) = 2+2+3 = 7，付费 3+4 = 7，盈余 0 ≥ 0 ✓，用户数 2。
  - 用户 3+5：成本 (1→2)+(2→3)+(1→5) = 2+2+3 = 7，付费 3+2 = 5，盈余 −2 < 0 ✗。
  - 用户 4+5：成本 2+3+3 = 8，付费 4+2 = 6，盈余 −2 < 0 ✗。
  - 用户 3+4+5：成本 2+2+3+3 = 10，付费 9，盈余 −1 < 0 ✗。
  - 最大可行用户数 = 2（方案 {3,4}，盈余 0）✓，与样例一致。
- **随机对拍**：未执行（按指令不编译/运行）。逻辑经上述样例手工逐步验证。

## 第五部分：示例代码（C++）

```cpp
//
// P1273 有线电视网
// https://www.luogu.com.cn/problem/P1273
// 树形背包 DP：盈余(付费-成本)当容量维，最大化用户数
//

#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{3005};      // n <= 3000
constexpr int mxp{30005};     // 总付费 <= 10 * 3000 = 30000
constexpr int neg{-114514};   // 不可达哨兵

int n,m;
int pay[mxn];                 // pay[u]: 用户 u 付费（仅 u >= n-m+1 有效）
vector<pair<int,int>>g[mxn];  // g[u]: 儿子列表 {v, c}
int subpay[mxn];              // subpay[u]: u 子树用户付费之和（盈余上限）
short f[mxn][mxp];            // f[u][j]: u 子树、u 已接通、盈余恰为 j 的最大用户数；neg 不可达
int ans;

void dfs(int u)
{
	// 初始化：u 已接通、暂不服务任何用户 → 盈余 0，用户数 0
	for(int j=0;j<mxp;++j)
		f[u][j]=neg;
	f[u][0]=0;
	// u 是用户 → 可服务 u 本身：盈余 = pay[u]，用户数 1
	if(u>=n-m+1)
	{
		subpay[u]=pay[u];
		f[u][pay[u]]=max((int)f[u][pay[u]],1);
	}
	else
	{
		subpay[u]=0;
	}
	int lim=subpay[u];   // 当前已合并部分的最大盈余（截断用）
	for(auto&[v,c]:g[u])
	{
		dfs(v);
		int newlim=lim+subpay[v];   // 合并后盈余上限
		static short tmp[mxp];
		for(int j=0;j<=newlim;++j)
			tmp[j]=neg;
		for(int j1=0;j1<=lim;++j1)   // 已合并部分盈余
		{
			if(f[u][j1]==neg)
				continue;
			tmp[j1]=max(tmp[j1],f[u][j1]);   // 不选 v 子树
			// 选 v 子树，v 盈余 t，需 t>=c（扣边成本后非负）
			for(int t=c;t<=subpay[v];++t)
			{
				if(f[v][t]==neg)
					continue;
				int j2=j1+t-c;
				if(j2>newlim)
					continue;
				tmp[j2]=max(tmp[j2],(short)(f[u][j1]+f[v][t]));
			}
		}
		lim=newlim;
		subpay[u]+=subpay[v];
		for(int j=0;j<=newlim;++j)
			f[u][j]=tmp[j];
	}
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>m;
	for(int i=1;i<=n-m;++i)
	{
		int k;
		cin>>k;
		for(int j=0;j<k;++j)
		{
			int a,c;
			cin>>a>>c;
			g[i].push_back({a,c});
		}
	}
	for(int i=n-m+1;i<=n;++i)
	{
		cin>>pay[i];
	}

	dfs(1);

	ans=0;
	for(int j=0;j<mxp;++j)
	{
		if(f[1][j]!=neg)
			ans=max(ans,(int)f[1][j]);
	}
	cout<<ans<<'\n';
	return 0;
}
```

**代码要点说明**：

- **盈余语义**：`f[u][j]` 中 `j = 付费 − 成本 = 盈余`，要求 `j ≥ 0`。边贡献 `−c`（合并时 `t − c`），用户贡献 `+pay`（叶子初始化 `f[u][pay[u]] = 1`）。
- **不可达哨兵**：`neg = −114514`（114514 家族），`short` 安全（> −32768）。
- **大小截断**：`lim` 记录当前已合并部分的盈余上限，`newlim = lim + subpay[v]`，避免枚举到 `mxp` 全表。
- **合并正确性**：枚举"已合并盈余 j1"和"v 子树盈余 t"，合并盈余 = `j1 + t − c`（选 v，`t ≥ c`）或 `j1`（不选 v）。取用户数和最大。
- **答案**：根处 `max_j f[1][j]`（盈余 ≥ 0 的最大用户数）。
- **内存**：`short f[mxn][mxp] ≈ 3005 × 30005 × 2B ≈ 180MB`。若 OJ 内存 < 180MB，可改按 `subpay[u]` 动态分配行（`vector<short> f[u](subpay[u]+1)`）或降低 `mxp`（实际 `subpay[u]` 多远小于 30000）。
- **下标**：按题目编号 1-based 处理（树结构 1-based 更自然），未做 0-based 转换。

**已知边界**：
- `subpay[u]` 可能接近 30000（根），`f[u][j]` 访问 `j ∈ [0, subpay[u]]`，`mxp = 30005` 覆盖。
- 用户数 ≤ 3000 < 32767，`short` 不溢出。
- 边权 `c ≤ 10`，`t ≥ c` 的循环从 `c` 开始，正确。
