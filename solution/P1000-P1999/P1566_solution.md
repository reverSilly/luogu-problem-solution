# P1566 加等式

> 标签：动态规划 DP · 难度：普及/提高-
> 本地题面：`P1566.md`（$1\le t\le10$，$1\le m\le30$，$1\le x_i\le1000$，同一集合内元素两两不同）。
> 验证：`appendix/P1566/P1566_check.py` —— 官方样例 `1 / 0 / 7` 通过；350 组随机小规模用例标程与暴力逐字节一致；最坏 $t=10,\ m=30,\ x\le1000$ 耗时 $0.007$ s。

## 1. 重新读题

**问题重述（人话版）**

给定 $t$ 组数据。每组给一个由 $m$ 个**两两不同**的正整数组成的集合 $S=\{x_1,\dots,x_m\}$。定义一条「加等式」为：存在一个元素 $x\in S$，它能写成**集合内其余元素**（不含 $x$ 自己）中某些元素之**和**，即

$$\exists\, U\subseteq S\setminus\{x\}:\ \sum_{y\in U}y=x .$$

要求统计这样的**加等式个数**。注意"$3=1+2$"与"$3=2+1$"算**同一条**，也就是说 $U$ 是**集合（无序）**；同时不同的 $U$（作为集合不同）算作不同的加等式。

> 一句话版本：**对每个元素 $x$，数一数"其余元素能凑出 $x$ 的无序子集方案数"，全部相加。**

**题面里容易漏掉的条款**

1. 「**其他元素**之和」$\Rightarrow$ 用来凑 $x$ 的元素集合不能包含 $x$ 本身。这很关键：若允许包含自己，则任何 $x=x$ 都成一条（平凡方程），且子集计数会出错。
2. 「$3=1+2$ 和 $3=2+1$ 是相同的加等式」$\Rightarrow$ 用**子集**（无序）计数，不能用**排列**（有序）计数。用背包 DP 对元素逐个"取 / 不取"恰好天然无序。
3. 「$m$ 个**不同**的整数」$\Rightarrow$ 元素互异，所以任何合法 $U$ 的大小 $\ge2$（因为 $U$ 中任何一个单元素 $y\ne x$，无法单独等和于 $x$）。这让我们不必额外排除"单个元素等于目标"的情形。
4. 计数是**带重复度**的：同一目标 $x$ 若有多种拆分，要分别计入。样例 3 的答案 $7$ 正是各目标方案数之和（下面 §2.2 会逐项核算）。

**数据范围与规模感受**

$$1\le t\le 10,\qquad 1\le m\le 30,\qquad 1\le x_i\le 1000 .$$

$m\le30$ 时 $2^{30}$ 的子集穷举约 $10^9$，勉强但偏危；而 $x_i\le1000$ 且**目标是某个元素值**，提示用**值域上的子集和计数 DP**：状态下标是"和"，大小只有 $1000$ 级别。每组每个目标扫一遍 DP：$O(m\cdot m\cdot V)=30\cdot30\cdot1000\approx9\times10^5$，$t\le10$ 完全宽裕。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：先把"加等式计数"写成可计算的式子

对固定集合 $S$，定义

$$\text{Ans}=\sum_{x\in S} c(x),\qquad c(x)=\#\{U\subseteq S\setminus\{x\}:\textstyle\sum_{y\in U}y=x\}.$$

这就是"把每一条加等式归到它左边的那个元素 $x$ 上"得到的分解。

**引理 1（按左端元素归类无重不漏）**

每一条加等式「$x=\sum_{y\in U}y$」唯一对应一对 $(x,U)$，其中 $x\in S$、$U\subseteq S\setminus\{x\}$ 且 $\sum_{y\in U}y=x$。因此加等式总数恰为 $\text{Ans}$。

**证明**：加等式的定义就是"存在某个元素等于其余某些元素之和"。给定 $x$ 与 $U$ 后，"$x=(\text{$U$ 之和})$"这条例式就确定了；反过来每条加式都有一个左端元素 $x$ 与右端集合 $U$。映射 $(\text{加式})\to(x,U)$ 是单射（左端、右端都可从加式读出）；又对任意满足 $\sum_{U}=x$ 的 $(x,U)$ 都能唯一还原出这条例式，故是双射。于是总数 = 合法的 $(x,U)$ 对数 = $\sum_{x}c(x)$。$\blacksquare$

> 由引理 1，问题被拆成 $m$ 个**互相独立的子问题**：对每个 $x$，"在 $S\setminus\{x\}$ 中做子集和 $=x$ 的**计数**"。

### 2.2 为什么是"计数"而不是"判定"（用样例校准）

若把语义读成"每个元素最多算一条加式"（只问存在性），样例 1 与样例 3 就会打架：

- 样例 3 集合 $\{1,2,3,4,5,6\}$：按**存在性**，可加式的元素是 $3,4,5,6$，共 $4$ 条；但官方答案是 $7$。
- 按**计数**逐项核对：
  - $x=1$：其余 $\{2,3,4,5,6\}$ 无子集和为 $1$ $\Rightarrow c=0$；
  - $x=2$：无 $\Rightarrow c=0$；
  - $x=3$：$\{1,2\}$ $\Rightarrow c=1$；
  - $x=4$：$\{1,3\}$ $\Rightarrow c=1$；
  - $x=5$：$\{1,4\},\{2,3\}$ $\Rightarrow c=2$；
  - $x=6$：$\{1,2,3\},\{1,5\},\{2,4\}$ $\Rightarrow c=3$。
  - $\text{Ans}=0+0+1+1+2+3=7$，与官方答案一致。

**结论**：题目数的是"加等式"这个**对象**的个数，同一个 $x$ 可以有多种拆分，都要分别计数。$\Rightarrow$ 必须做**方案数** DP，而非布尔可达性。

### 2.3 归约到经典问题：0-1 背包的"方案数"版本

子问题统一为：给定多重集 $\{w_1,\dots,w_k\}$（这里是 $S\setminus\{x\}$）与目标 $T=x$，求子集和为 $T$ 的**子集个数**。这是经典的 **0-1 背包计数**。

设 $g_j[s]=$ "只从前 $j$ 个物品里选，凑出和为 $s$ 的**方案数**"。初值 $g_0[0]=1$、其余 $0$，转移为

$$g_j[s]=g_{j-1}[s]+g_{j-1}[s-w_j]\qquad(s\ge w_j),$$

即"第 $j$ 个物品不选"（沿用 $g_{j-1}[s]$）"或选"（在 $g_{j-1}[s-w_j]$ 的方案上添加该物品）。答案 = $g_k[T]$。

**引理 2（0-1 背包计数转移的正确性）**

对每个 $s$，$g_j[s]$ 等于"从 $\{w_1,\dots,w_j\}$ 中选子集且和为 $s$"的方案数。

**证明**（对 $j$ 归纳）：
- 基例 $j=0$：空集只有"什么都不选"一种，和恰为 $0$，故 $g_0[0]=1$，$s\ne0$ 时 $g_0[s]=0$。✓
- 归纳步：把 $\{w_1,\dots,w_j\}$ 的子集按"是否包含第 $j$ 个物品"分成两类，互不相交：
  - 不含 $w_j$ 的子集 $\leftrightarrow$ $\{w_1,\dots,w_{j-1}\}$ 中的子集，和为 $s$，方案数 $g_{j-1}[s]$；
  - 含 $w_j$ 的子集 $\leftrightarrow$ $\{w_1,\dots,w_{j-1}\}$ 中和为 $s-w_j$ 的子集各再添上 $w_j$，方案数 $g_{j-1}[s-w_j]$（$s\ge w_j$ 时才存在）。
  两类之和即 $g_j[s]$，正是转移式。$\blacksquare$

**引理 3（滚动一维必须倒序）**

把 $j$ 维压缩成一维数组 $dp$，对每个物品 $w_j$ 用**倒序**（$s$ 从 $T$ 递减到 $w_j$）执行 $dp[s]\mathrel{+}=dp[s-w_j]$ 后，$dp[T]$ 仍是"子集和为 $T$ 的方案数"，且每个物品至多被选一次。

**证明**：同引理 2 的归纳。关键在于转移右侧的 $dp[s-w_j]$ 必须是"处理 $w_j$ **之前**"的旧值。
- 倒序时，处理位置 $s$ 时其更小的位置 $s-w_j<s$ 尚未被本轮改写，保存的是旧值 ✓；
- 若用**正序**，则 $s-w_j$ 在本轮更早就被改成新值，于是 $dp[s]+=dp[s-w_j]$ 变成"可重复使用 $w_j$"的完全背包计数，会把"多次使用同一元素"的错误方案也计入，与"每个元素只有一份"矛盾 ✗。
故必须倒序，结论成立。$\blacksquare$

### 2.4 算法雏形与代价

对每个 $x_i$：以 $S\setminus\{x_i\}$ 为物品、$T=x_i$ 跑一次倒序 0-1 背包计数，读 $dp[x_i]$ 累加。

- 时间：每个目标 $O(m\cdot x_i)$，共 $O(m\cdot\sum_i x_i)\le O(m\cdot m\cdot V)=30\cdot30\cdot1000\approx9\times10^5$ 每组。
- 空间：$O(V)$ 一个 `long long` 数组（$V=1000$）。用 `long long` 是因为方案数可达数十万甚至更多，`int` 虽大概率够但没必要冒险。
- **多测清理**：全局数组默认全 $0$，但多组之间/多目标之间必须 `fill_n` 清零，否则上一轮方案会残留叠加。

### 2.5 剖析失败思路

**失败 1：把 $x$ 自己也算进可用的物品。**
若对目标 $x$ 不排除 $x$ 本身，则会出现 $dp[x]\ge1$（由"只选 $x$ 这一个物品"贡献），相当于承认平凡方程 $x=x$，答案必然偏大。样例 1 集合 $\{1,2,3\}$ 会被算成 $3=(1+2)$ 之外还多出 $1=1,2=2,3=3$，得到 $4$ 条，与答案 $1$ 不符。$\Rightarrow$ **枚举物品时必须 `if(j==i) continue;`**。

**失败 2：用"存在性"（布尔 OR）代替"计数"。**
见 §2.2，样例 3 会得 $4$ 而非 $7$。$\Rightarrow$ 转移必须是加法计数 `dp[s]+=dp[s-w]`，不是 `dp[s]|=dp[s-w]`。

**失败 3：正序转移。**
退化成完全背包计数（引理 3），把同一元素重复使用，答案虚增。$\Rightarrow$ 内层必须**倒序**。

**失败 4：忘记多测清零。**
`fill_n(&dp[0],mxv,0)` 漏写时，上一组/上一目标的方案残留在 $dp$ 里被重复累加，答案偏大且随数据顺序变化，是典型的"静默错误"。**全局数组默认全 $0$ 只对第一次有效。**

**失败 5：有序计数（把子集当排列）。**
若对每个目标用"排列数"DP（例如对每个和位置再遍历所有物品相加，而非"逐物品一次决策"），会把 $3=1+2$ 与 $3=2+1$ 分别计数，答案翻倍。引理 2 的框架（逐物品一次"取/不取"）从结构上保证了无序。$\Rightarrow$ **必须按物品维度做 0-1 决策**。

### 2.6 越界与状态体检

| 量 | 范围 | 上界 | `int` 够？ |
|---|---|---|---|
| $m$ | 题面给定 | $30$ | 是 |
| $x_i$ | 题面给定 | $1000$ | 是 |
| 目标下标 / 数组尺寸 | $x_i+5$ | `mxv{1005}` | — |
| 方案数 $dp[\cdot]$ | 组合数 | 可达数十万级 | 用 `i64` 保险 |

结论：状态只需一维 $O(1000)$；真正的坑是**清零**与**排除 $x_i$ 自身**两项（§2.5 失败 1、失败 4）。

## 3. 模式总结（Pattern Summary）

**模式名：把"数等式"归约为「0-1 背包方案数」的多次独立求解。**

**识别信号**：题目要把"某个元素写成其他元素之和"的**条数 / 方案数**统计出来；元素是正数且值域不大（$10^3$ 级）；目标值固定为某个元素值。

1. **explore its property** — 把"加等式"按左端元素归类，写成 $\text{Ans}=\sum_x c(x)$（引理 1），确认问的是**方案数**而非存在性（用样例 3 的 $7$ 校准，§2.2）。
2. **reduce to easier problem** — 每个 $x$ 的子问题 = "在 $S\setminus\{x\}$ 中做子集和 $=x$ 的计数"，即经典 **0-1 背包计数**（引理 2）。
3. **classic problem solution** — 逐物品一次"取 / 不取"的一维**倒序** DP，$dp[s]\mathrel{+}=dp[s-w]$，天然**无序**（引理 3）。
4. **discuss by category（两个必须处理的分类）** — ①物品集合要**剔除目标自身**（否则平凡方程污染）；②**多测清零**（否则跨组残留）。
5. **explore its property（第二次：值域上界）** — 目标 $\le1000$，DP 只需开到 $x_i$，数组小、复杂度低。

**同族题**：LeetCode 494 目标和、子集和计数、3789/可行背包等"方案数"系列，骨架完全相同，差别只在"物品是否可用多次（倒序 vs 正序）"与"目标是否固定"。

**一句话记忆**：数等式 = 对每个元素做一次"排除自身"的 0-1 背包方案数，倒序 DP，最后求和。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $t$ / `t` | `int` | 测试组数 | 读入 | 题面 |
| $m$ / `m` | `int` | 当前集合元素个数 | 读入 | 题面 |
| `x[i]` | `int [35]` | 当前集合第 $i$ 个元素（0-based） | 读入 | 题面 |
| `dp[s]` | `i64 [1005]` | 用**其余元素**凑出和 $s$ 的**方案数** | 每个 $i$ 重置为全 $0$，再 `dp[0]=1` | 引理 2 的 $g_k$ |
| `ans` | `i64` | 该组加等式总数 $\sum_i c(x_i)$ | $0$ | 引理 1 |
| $i$ | `int` | 当前作为"左端元素/目标"的下标 | — | 外层循环 |
| $j,s$ | `int` | 物品下标 / DP 的和位置 | — | 状态转移 |

### 4.2 编号步骤

1. 读入 $t$；循环 $t$ 组，每组读入 $m$ 与 $x[0..m-1]$。
2. 令 `ans=0`。
3. 对 $i=0..m-1$（以 $x_i$ 为目标）：
   3.1 `fill_n(&dp[0],mxv,0)` 清空；`dp[0]=1`（"什么都不选"和为 0 的一种方案）。
   3.2 对 $j=0..m-1$，若 `j==i` 则跳过（**剔除目标自身**）；否则内层 **$s$ 从 `x[i]` 递减到 `x[j]`**：`dp[s]+=dp[s-x[j]]`。
   3.3 `ans+=dp[x[i]]`（把 $\{d\}$ 作为 $S\setminus\{x_i\}$ 凑出目标的方案数并入总数）。
4. 输出 `ans`，进入下一组。

> 内层上界取 `x[i]` 就够了：我们只关心 $dp[x[i]]$，而转移只会用到更小的和；对 $x[j]>x[i]$ 的物品，内层条件 `s>=x[j]` 直接不成立，相当于自动忽略，正确。

### 4.3 复杂度

- 时间：每组 $O\!\left(m\cdot\sum_i x_i\right)\le O(m^2 V)=30\cdot30\cdot1000\approx9\times10^5$，$t\le10$ 时总计 $\le9\times10^6$。
- 空间：$O(V)$（一个 `i64[1005]`）+ $O(m)$，约 $8$ KB。
- 实测（见 §4.5）：最坏 $t=10,m=30,x\le1000$ 耗时 $0.007$ s。

### 4.4 关键不变量

1. 每次进入 $3.1$ 之后，`dp[0]=1` 且其余为 $0$，保证本目标计数不受历史污染。
2. 转移按**物品维度**做"取 / 不取"，故 `dp[s]` 统计的是**无序**子集（引理 2 的双射）。
3. 内层**倒序**保证每个物品至多用一次（引理 3）。
4. `ans=\sum_i dp[x_i]` 恒等于引理 1 的加等式总数。

### 4.5 验证状态小结

| 项目 | 状态 |
|---|---|
| 官方样例回归 | **通过**：`3` / `1 2 3` / `1 2 5` / `1 2 3 5 4 6` → `1 / 0 / 7` |
| 随机数据对拍 | **通过**：$350$ 组随机用例（$t\in[1,3]$，$m\in[1,14]$，元素从 $1..30$ 中取 $m$ 个不同值），背包计数版与"枚举其余元素全部子集"的暴力版逐字节一致 |
| 最坏规模计时 | $t=10,\ m=30,\ x\le1000$ → 输出 `41 66 191 120 47 153 154 157 100 8`，耗时 **$0.007$ s** |
| 残余风险 | ①若把目标自身当作可用物品，会多出平凡方程（§2.5 失败 1）；②若用正序内层会退化成完全背包（§2.5 失败 3）；③漏写 `fill_n` 会造成跨目标残留（§2.5 失败 4） |

## 5. 示例代码

### 5.1 主解：多次 0-1 背包方案数

```cpp
//
// 题目：P1566 加等式
// https://www.luogu.com.cn/problem/P1566
// AC
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{35};            // m<=30 (+5 松弛)
constexpr int mxv{1005};          // x<=1000 (+5 松弛)

int t,m;
int x[mxn];
i64 dp[mxv];                      // 子集和计数(只算到 x[i] 即可)

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>t;
	while(t--)
	{
		cin>>m;
		for(int i=0;i<m;++i)
			cin>>x[i];
		i64 ans=0;
		for(int i=0;i<m;++i)
		{
			fill_n(&dp[0],mxv,0);   // 多测必须清零(全局默认 0 仅首次有效)
			dp[0]=1;
			for(int j=0;j<m;++j)
			{
				if(j==i)
					continue;
				for(int s=x[i];s>=x[j];--s)
					dp[s]+=dp[s-x[j]];
			}
			ans+=dp[x[i]];          // 其余元素凑出 x[i] 的无序方案数
		}
		cout<<ans<<'\n';
	}
	return 0;
}
```

**代码结构对照**：`i` 是目标元素（同时决定 DP 上界 `x[i]`），`j` 是被决策的物品（`j==i` 跳过 = 剔除目标自身），内层 `s` **倒序**递减 = 0-1 背包（引理 3），`dp` 每次 `fill_n` 清零 = 多测隔离。`dp[x[i]]` 读出方案数并入 `ans`。

### 5.2 对照实现：穷举其余元素的所有子集（仅用于小规模对拍）

```cpp
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{35};

int t,m,x[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>t;
	while(t--)
	{
		cin>>m;
		for(int i=0;i<m;++i)
			cin>>x[i];
		int ans=0;
		for(int i=0;i<m;++i)
		{
			int others[mxn],k=0;
			for(int j=0;j<m;++j)
				if(j!=i)
					others[k++]=x[j];
			for(int mask=0;mask<(1<<k);++mask)   // 穷举其余元素的全部子集
			{
				int sum=0;
				for(int b=0;b<k;++b)
					if(mask>>b&1)
						sum+=others[b];
				if(sum==x[i])
					++ans;
			}
		}
		cout<<ans<<'\n';
	}
	return 0;
}
```

两版输出逐字节相同（已用 $350$ 组随机数据确认）。这一版完全绕过背包转移，直接按引理 1 的定义枚举 $\binom{S\setminus\{x_i\}}{\cdot}$ 的每个子集，可作为方案数 DP 的独立交叉验证基准。代价 $O(m\cdot2^{m-1})$，只有 $m\le14$ 左右跑得动。

### 5.3 易错点清单

- **未剔除目标自身**（漏 `if(j==i) continue;`）$\Rightarrow$ 多出平凡方程（§2.5 失败 1）。
- **布尔可达代替计数**（写 `dp[s]|=dp[s-w]`）$\Rightarrow$ 样例 3 得 $4$ 而非 $7$（§2.5 失败 2）。
- **内层正序** $\Rightarrow$ 完全背包计数，重复使用元素（§2.5 失败 3）。
- **忘记 `fill_n` 清零** $\Rightarrow$ 跨目标/跨组残留（§2.5 失败 4）。
- **方案数用 `int`** 虽多数情况够，但组合数可能逼近上限，稳妥用 `i64`。
- **用 `endl`** 违反本项目风格指南，一律用 `'\n'`。
