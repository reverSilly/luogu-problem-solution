# P1220 关路灯 — 解题报告

## 1. 重新读题（用大白话复述）

一条直线上有 `n` 盏路灯，按位置从左到右排好（位置严格递增）。老张住在第 `c` 盏灯旁边。每天早上他先把**自己旁边这盏灯**关掉，然后往左或往右走，一盏一盏关掉剩下的灯。

关键代价模型：
- 一盏灯从"被点亮的时刻"到"被关掉的时刻"之间，一直在耗电，耗电 = 功率 × 时间。
- 老张走路速度 1 m/s，所以走 `|x - y|` 米就花 `|x - y|` 秒。
- 关灯动作本身耗时忽略不计。

目标：安排一个关灯顺序，使得**从开始关灯那一刻起，所有灯累计消耗的总电能最少**。注意，第 `c` 盏灯在 `t = 0` 就被关了，它耗电 0，但它的位置决定了老张的起点。

约束：`n ≤ 50`，`W_i ≤ 100`，位置 ≤ 100，都单调递增。

---

## 2. 思考链（怎么一步步想到区间的）

### 2.1 先把"代价"算清楚 —— 这是最关键的一步

一开始我盯着"安排顺序"，想贪心：先关功率大的那盏？不对，题目自己都说了"先算左边总功率再算右边总功率"这种贪心不成立，因为"关的过程中适当地调头可能更省"。

那我换个角度。每盏灯 `i` 的耗电是 `W_i × (它被关的时刻 T_i)`。老张的起点是 `t = 0` 在第 `c` 盏位置。所以

> **总功耗 = Σ W_i × T_i**，其中 `T_c = 0`，`T_i`（i ≠ c）= 老张从起点走到第 i 盏灯所花的总时间（沿路线、有来回）。

这个式子一写出来，问题就从"排顺序"变成了"给每盏灯定一个到达时刻"。但时刻不是独立选的——它由走法决定，走法又受"必须先关自己位置灯"约束。

### 2.2 看一个性质：关掉之后就不管了，所以"已关的集合"是连续的

老张关灯的过程中，有一件事很特殊：**灯一旦被关就不再耗电，也就再也不会被碰**。这意味着在任意时刻，"已经关掉的灯"构成了一个**关于老张位置连续的区间**——因为老张只能从已关灯区间的某一端往外走（如果中间有没关的灯，他必须先经过它，那它就该先被关）。

更准确地说：设已关的灯是下标区间 `[l, r]`（按位置排序的下标），老张现在**站在** `l` 或 `r` 中某一个上（因为他是从区间内部一路关到边上的）。下一次他只能走到 `l-1` 或 `r+1`，把它关掉，于是区间扩成 `[l-1, r]` 或 `[l, r+1]`，且他站在新端点上。

这个性质把"任意顺序"压缩成了"只由区间端点决定"的结构。这是能上区间 DP 的根本原因。

### 2.3 先解个简单版：固定"最后关的灯"

反过来想。假设所有灯都关了，最后被关的那盏是 `k`。那么在关它**之前**，`[0, k-1]` 和 `[k+1, n-1]` 这两边其实可以独立地、互不干扰地被关掉——因为老张最后才去关 `k`，意味着在他关 `k` 之前，他不可能"跨过" `k` 去关另一侧的灯（`k` 还亮着挡路）。

但这里有个陷阱：老张中途可以在左右两侧之间反复横跳（先关几个左边的，再回头关右边的，再回来……）。所以"先左后右"或"先右后左"的固定顺序**不是**最优的。这正是题目说的"适当地调头更省"。

### 2.4 关键洞察：把"时间 × 功率"按"灯还亮着的时间"重新记

我换一种记法，这对推出 O(1) 转移至关重要。

考虑在某一"时刻"，还亮着的灯是 `[L, R]`（尚未关掉的连续区间），老张站在端点上（`L` 或 `R`）。在这一小段时间 `dt` 内，**所有还亮着的灯都在耗电**，耗电速率 = `Σ_{i=L..R} W_i`（记作 `pw(L, R)`），耗电 = `pw(L, R) · dt`。

也就是说，与其给每盏灯单独算 `W_i × T_i`，不如**按时间轴积分**：每一段老张在路上走的 `dt` 时间内，把"此刻还亮着的所有灯的功率和"乘上去。

形式化：总功耗 = 沿老张从起点走到"全部关完"的整条路径，对每个路段 `|x_cur - x_next|`，加上 `pw(还亮着区间) × |x_cur - x_next|`。

这个积分形式有个巨大好处：**还亮着区间的功率和可以前缀和 O(1) 拿到**，而且它只依赖于当前区间端点 `(L, R)`，不依赖于历史路径。这就把 DP 转移变成了 O(1)。

### 2.5 证明 DP 最优性（完整的归纳证明）

**引理 1（区间不变量）.** 在任意关灯方案执行到一半时，已关掉的灯的下标集合恰为一个连续区间 `[c_left, c_right]`（含 `c`），且老张站在该区间的一端。

*证明.* 对关灯步数做归纳。
- 初始：只关了第 `c` 盏，已关集合 = `{c}`，是连续区间，老张站在 `c`（同时是左端和右端）。成立。
- 归纳步：设某时刻已关集合是连续区间 `[a, b]`，老张站在 `a` 或 `b`。老张下一盏要关的灯，必须是从当前位置 `a` 或 `b` 出发能"第一个遇到"的还没关的灯。若他向左，第一个未关灯是 `a-1`（若 `a-1 ≥ 0`）；若向右，是 `b+1`。因为区间内全已关，区间外紧邻的只有 `a-1` 和 `b+1` 两盏。所以他关的必然是 `a-1` 或 `b+1`，关完后已关集合变为 `[a-1, b]` 或 `[a, b+1]`，仍是连续区间，且他站在新端点上。归纳成立。∎

**引理 2（代价只依赖当前区间与老张位置）.** 设当前已关区间为 `[a, b]`、老张站在端点 `s ∈ {a, b}`、此时时钟为 `t`。则从此刻到全部关完的**最小剩余耗电**只由 `(a, b, s)` 决定（`t` 已被积分形式吸收，不再单独出现）。

*证明.* 由引理 1，下一盏只能关 `a-1` 或 `b+1`。关其中一盏 `x` 需要走路时间 `|pos[x] - pos[s]|`，这 `|pos[x]-pos[s]|` 秒内，**所有**当前还亮着的灯（即下标在 `[a-1, b+1]` 中除去已关的 `a..b` 的灯，也就是 `a-1` 和 `b+1` 两盏）都在耗电，速率 = `pw_alive(a, b)`。注意即使目标是关 `a-1`，在路上 `b+1` 也还亮着，所以整段路的耗电速率是 `pw_alive(a, b)`（含两盏），而不是只算 `a-1` 一盏。到达 `x` 后立刻关掉，状态变为已关区间扩成 `[a-1, b]` 或 `[a, b+1]`、老张站在新端点。

  由于"未来最小耗电"只通过"当前区间端点 + 老张所在端点 + 当前还亮着区间功率和"来影响每一步的瞬时耗电速率，而这些量都由 `(a, b, s)` 唯一确定（功率和 `pw_alive(a,b)` 由端点定），所以剩余耗电是 `(a, b, s)` 的函数。∎

**定理（区间 DP 最优）.** 记 `f[a][b][s]` = 已关区间为 `[a, b]`、老张站在端点 `s`（`s ∈ {a, b}`）时，把剩余灯全部关完所需的**最小额外耗电**（不含已经发生的耗电）。则最优解为 `f[c][c][·]`（`c` 同时当左端和右端，二者同值），转移：

```
f[a][b][s] = min over x in {a-1, b+1}  {  pw_alive(a, b) * |pos[x] - pos[s]|  +  f[new_a][new_b][new_s]  }
```

其中 `x = a-1` 时新状态是 `[a-1, b]`、`new_s = a-1`（新左端，编码 0）；`x = b+1` 时新状态是 `[a, b+1]`、`new_s = b+1`（新右端，编码 1）。`pw_alive(a,b) = preW[a] + (totalW - preW[b+1])`（`[0,a-1]` 与 `[b+1,n-1]` 的功率和）。

*最优子结构证明.* 设最优方案在状态 `(a, b, s)` 下的第一盏关的灯是 `x*`。则该方案 = 先花 `pw_alive(a,b)·|pos[x*]-pos[s]|` 走到并关掉 `x*`，之后从新状态按某顺序关完。由最优性，之后的部分必须是新状态下的最优方案（否则替换成更优的，整体更优，矛盾）。因此 `f[a][b][s]` 取第一盏所有可能 `x` 的 `min`，即得转移。反向，任取一个使转移取等的第一盏 `x` 加上新状态最优方案，就构成 `(a,b,s)` 的一个可行方案，代价恰好等于 `f[a][b][s]`，故 `f` 就是最优值。归纳于"剩余灯数"：剩余 0 盏（`a=0, b=n-1`）时 `f=0` 为基态；剩余 1 盏起逐层向上，每层依赖的"剩余更少的状态"已先算好。∎

**关于"调头"的说明（回应题目）.** 注意转移里第一盏 `x` 可以是 `a-1` 也可以是 `b+1`，与老张当前在左还是右**无关**。也就是说，老张可以"站在左端却先跑去关右边的 `b+1`"（调头），也可以"站在右端先关左边的 `a-1`"。这正是"调头可能更省"被 DP 自然捕捉到的机制——`pw_alive` 乘的是**整段路程**，所以"先横穿去关远端"的代价会被正确计入。∎

## 3. 模式总结（按实际思考顺序）

- **explore its property — 代价积分**：把"每盏灯 `W_i×T_i`"改成"按时间轴积分 `Σ pw_alive(dt)·dt`"，代价只依赖当前还亮着区间功率和 + 步长。
- **explore its property — 已关灯是连续区间**：灯关掉后不再被碰，所以已关集合永远是连续区间，老张永远站在端点。这是状态空间压缩的根据。
- **consider easier version — 反向看"最后关的灯"**：先尝试固定最后一盏，发现左右两侧不能独立（可调头），放弃独立分解，保留"调头"自由度。
- **classic problem solution — 区间 DP**：状态 = 已关区间 `[l, r]` + 老张所在端 `dir`，按"剩余灯数"归纳，转移枚举下一盏关 `l-1` 还是 `r+1`。
- **classic problem solution — 前缀和 O(1) 功率和**：`pw_alive(l, r)` 用功率前缀和 O(1) 求出，使转移 O(1)。
- **reduce to easier problem — 起点与终点**：第 `c` 盏在 `t=0` 关掉（耗电 0），它是**答案状态** `f[c][c][·]`；全关完 `[0,n-1]` 是**递归基** `f=0`。二者方向别搞反。
- **defer reconstruction — 不需还原顺序**：题目只要最小总功耗，不要求输出顺序，省去路径记录。

## 4. 真正的解法（代码做什么）

### 符号表

| 符号 | 含义 | 初始化 / 类型 |
|---|---|---|
| `n` | 路灯总数 | 读入，`int` |
| `c` | 老张所在路灯（1-based 输入） | 读入后 `--c` 变 0-based |
| `pos[i]` | 第 `i` 盏灯位置（0-based） | 读入，`int`，单调递增 |
| `w[i]` | 第 `i` 盏灯功率（0-based） | 读入，`int` |
| `preW[i]` | 功率前缀和：`preW[i] = Σ_{j=0..i-1} w[j]`，`preW[0]=0` | 预处理，`int` |
| `totalW` | `preW[n]`，总功率 | 预处理 |
| `f[l][r][2]` | 已关区间 `[l,r]`、老张在端点（`0`=左端 `l`，`1`=右端 `r`）时，关完剩余灯的最小额外耗电 | 全表填 `INF`，`i64`；**唯一例外** `f[0][n-1][0]=f[0][n-1][1]=0`（基态） |

> 溢出说明：`f` 值最大约 `Σ W × T ≈ 50·100·(来回走完整段) ≈ 5e3·5e3 = 2.5e7` 量级；`pw_alive·|…|` 中间量 `≤ 5e3·1e2 = 5e5`，累加远小于 `2e9`。`int` 其实够，但用 `long long` 存 `f` 保险。

### 算法步骤

1. **读入** `n, c`，`--c`。对 `i = 0..n-1` 读 `pos[i], w[i]`。
2. **前缀和**：`preW[0]=0`；`for i in 0..n-1: preW[i+1] = preW[i] + w[i]`。`totalW = preW[n]`。
3. **辅助** `pw_alive(l, r) = preW[l] + (totalW - preW[r+1])`。
4. **初始化**：`f` 全表填 `INF`；设基态 `f[0][n-1][0] = f[0][n-1][1] = 0`（全关完，无剩余灯）。
5. **填表（倒序，从大区间到小区间）**：`f[l][r][dir]` 依赖 `f[l-1][r][·]` 与 `f[l][r+1][·]`（已关数量更多、区间更大），所以**先算大区间、后算小区间**。
   - `for len = n-2 down to 0`（`len = r - l`，即已关数量 `len+1` 从 `n-1` 盏递减到 `1` 盏）：
     - `for l = 0 .. n-1-len`，`r = l+len`：
       - 若 `l > c || r < c` 跳过（区间必须包含 `c`，否则不可达）。
       - `for dir in {0,1}`：老张在端点 `p = (dir==0 ? pos[l] : pos[r])`，
         - 候选 A（若 `l > 0`）：先关 `l-1`，`costA = pw_alive(l,r) * |pos[l-1] - p| + f[l-1][r][0]`。
         - 候选 B（若 `r < n-1`）：先关 `r+1`，`costB = pw_alive(l,r) * |pos[r+1] - p| + f[l][r+1][1]`。
         - `f[l][r][dir] = min(存在的候选)`。
   - 说明：`len = 0` 这轮算到 `f[c][c][·]`，此时它依赖的 `f[c-1][c][·]`、`f[c][c+1][·]`（`len=1`）已在上一轮算好，故能正确得出。
6. **答案**：`ans = min(f[c][c][0], f[c][c][1])`（只关了起点，把剩余全关完的最小额外耗电 = 总功耗）。
7. **输出** `ans`。

### 复杂度

- 状态数：包含 `c` 的区间 `[l, r]`（`l ≤ c ≤ r`）有 `(c+1)·(n-c)` 个，乘 2 个 `dir`，共 `O(n²)`。
- 每状态 O(1) 转移（两个候选）。
- 总时间 `O(n²)`，空间 `O(n²)`。`n ≤ 50` 时约 `2500` 状态，瞬时完成。

### 验证状态

- 边界 `n = 1`：只有一盏灯，老张在 `c=0`，`t=0` 关掉，功耗 0。DP：基态 `f[0][0][·]=0` 直接就是答案，`ans = f[0][0][·] = 0`。✓
- 边界"老张在最左/最右"：`c = 0` 或 `c = n-1`，区间只能向一侧扩展，DP 仍正确（另一侧候选被 `if(l>0)/if(r<n-1)` 跳过）。
- 样例（题面暗示最优顺序 `3 4 2 1 5`）：用该顺序手算总功耗应与 DP 结果一致（DP 只报最小值，不强制走样例那条路，但若样例那条路最优则值相同）。
- 随机小数据可与 O(n!) 暴力（枚举全部关灯顺序，模拟走路累加 `pw_alive·步长`）对拍验证 DP 值。（此处按要求不执行编译，仅说明验证方法。）

## 5. 示例代码（C++，遵循 Louis Li 风格）

```cpp
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{55};                 // n<=50, +5 松弛
constexpr i64 inf{1e18};

int n,c;
int pos[mxn],w[mxn],preW[mxn];
i64 totalW;
i64 f[mxn][mxn][2];                   // f[l][r][dir]: 已关[l,r], 老张在端点 dir(0=左l,1=右r), 关完剩余灯最小额外耗电

i64 pwAlive(int l,int r)              // 此刻还亮着灯功率和 = [0,l-1] + [r+1,n-1]
{
	return preW[l]+(totalW-preW[r+1]);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>c;--c;
	for(int i=0;i<n;++i)
	{
		cin>>pos[i]>>w[i];
		preW[i+1]=preW[i]+w[i];
	}
	totalW=preW[n];

	// 全局数组默认 0, 但这里要 INF 表示"未算/不可达", 必须显式填
	for(int l=0;l<n;++l)
		for(int r=0;r<n;++r)
			f[l][r][0]=f[l][r][1]=inf;

	// 递归基: 全关完 [0,n-1], 无剩余灯, 额外耗电 0
	f[0][n-1][0]=f[0][n-1][1]=0;

	// 倒序枚举: f[l][r] 依赖更大区间 (l-1,r)/(l,r+1), 须先算大 len 再算小 len
	for(int len=n-2;len>=0;--len)
		for(int l=0;l+len<n;++l)
		{
			int r=l+len;
			if(l>c||r<c) 
				continue;              // 区间必须包含 c (l<=c<=r), 否则不可达
			for(int dir=0;dir<2;++dir)
			{
				int p=(dir==0?pos[l]:pos[r]);
				i64 best=inf;
				if(l>0)                // 先关左端外 l-1
					best=min(best,pwAlive(l,r)*abs(pos[l-1]-p)+f[l-1][r][0]);
				if(r<n-1)              // 先关右端外 r+1
					best=min(best,pwAlive(l,r)*abs(pos[r+1]-p)+f[l][r+1][1]);
				f[l][r][dir]=best;
			}
		}

	i64 ans=min(f[c][c][0],f[c][c][1]);
	cout<<ans;
	return 0;
}
```

**代码要点说明：**

- **方向别搞反**：`f[l][r][·]` 依赖 `f[l-1][r][·]`、`f[l][r+1][·]`（已关数量 `len+1`，更大区间），所以 `len` 必须**从 `n-2` 递减到 `0`**（大区间先算）。基态 `f[0][n-1][·]=0` 在填表前设好，`len=n-2` 这轮引用的 `f[·][·]`（`len=n-1`）只有 `f[0][n-1][·]` 是合法的，其余越界被 `if(l>0)/if(r<n-1)` 挡住。
- **INF 必须显式填**：全局 `long long` 数组默认 0，若不填 `inf`，未算的状态会被当成 0 成本，导致错误转移。这是从 `vector` 迁到全局数组的典型坑。
- **只算包含 `c` 的区间**：`if(l>c||r<c) continue;` 剪掉不可达状态，`f[c][c][·]` 在 `len=0` 这轮由转移正确得出，是最终答案。
- **调头自然成立**：转移里候选 A/B 与 `dir` 无关，所以"站在左端先关右端外"的调头走法会被枚举到。
- 复杂度 `O(n²)` 时间 / `O(n²)` 空间，`n≤50` 瞬时完成。
