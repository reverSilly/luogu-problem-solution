# P1189 [COI 2001] SEARCH — 题解

## Part 1 — 题目再陈述

小镇是一张 $R \times C$ 的网格（$1\le R,C\le 50$）。
- `.` 与 `*` 可通行；`X` 是墙，不可通行。
- 汽车初始位于唯一的 `*`，初始时汽车**只可能在**该格。
- 之后给出 $N\le 1000$ 条命令，命令 $\in\{\text{NORTH,SOUTH,WEST,EAST}\}$，且**相邻两条命令一定不同**。
- 每收到一条命令 $d$，汽车必须沿 $d$ 方向走**至少一格**，路径上所有经过的格子（不含起始格、不含墙外）都必须可通行，最终停在路径上某个可通行格（含末格）。

输出：把最终所有**可能**停留的位置标成 `*`，原地图其余部分保持不变（`X` 不变，`.` 变回 `.`，原起点 `*` 若不再属于可能集合也改回 `.`）。

目标：求出执行完 $N$ 条命令后，汽车**可能**停留的位置集合。

---

## Part 2 — 思维链（完整证明）

### 第 0 步：先搞清楚"机制"到底在做什么

汽车的运动不是"走到尽头"，而是"至少走一格，可以中途停在任意可行格"。
所以从起点 $S$ 向北（NORTH）发令时，可能到达的格子集合是：

$$
\{S' = (x',y): x'<x_S,\ \text{从 }S\text{ 到 }S'\text{ 之间全可通行}\}
$$

——即**朝 $d$ 方向从 $S$ 出发、沿可行格子连续延伸的那一段**。
注意"不含 $S$ 本身"（必须至少走一格），也"不含越过第一个墙/边界之外的格子"。

> 关键：每次命令后，汽车的位置集合不再是单个点，而是一组点，且**沿 $d$ 方向排成一段连续区间**（或沿另一维度的一段连续区间）。

### 第 1 步：先考虑"只发 1 条命令"的情形

设汽车初始在 $S$，发令 NORTH：
- 候选集合 = $S$ 正上方、相邻格子可通行形成的最大连续段，去掉 $S$ 自己。
- 若 $S$ 上方全是墙或已在顶，候选集合为**空**，游戏直接结束（之后所有命令都无解）。

这一步告诉我们：单点 $S$ 在一条命令下扩展为"一段"。**状态从点变成了段**。

### 第 2 步：连续命令下段如何演化？—— 用"不变量"看

假设发令 $d_1$ 之前汽车可能停在**一行或一列上的若干格**（下面要证明它始终是一整段），发令 $d_1$（NORTH）之后，汽车可能停在哪里？

直觉：对于**每一个**可能起点，向北能延伸到的格子集合，再取并集，就是新集合。

**问题**：并集是否仍然"沿 NORTH 方向排成一段连续区间"？

**证明（引理 A：沿命令方向的可达段是连续区间）**
设命令 $d$ 为 NORTH。设发令前可能集合 $S_{\text{pre}}$ 中，对任意一列 $y$，发令前 $S_{\text{pre}}$ 在列 $y$ 上的格子（若存在）构成 $[lo_y, hi_y]$（行号），其中 $lo_y\le hi_y$。

发令 NORTH 后，列 $y$ 中可能停靠的行号集合为：

$$
\bigcup_{x\in[lo_y,hi_y]}\big[\text{top}_y(x),\;x-1\big]
$$

其中 $\text{top}_y(x)$ 是从 $x$ 向上、连续可行格中最顶上的行号（含 $x$ 本身），且要求该段至少一格（即 $x-1\ge \text{top}_y(x)$，否则该 $x$ 对列 $y$ 无贡献）。

由于 $\text{top}_y(\cdot)$ 在可行区段内是**常数**，在墙边是跳变，且跳变只发生在墙所在行，故并集仍是一个（至多）连续区间。

> 但我们要的是**所有列的并集**，且最终输出要按格子标记，不能只按列存。

换个角度：**命令 NORTH 后，所有可能格子都在 $d$ 方向的"延伸段"里**，且**不同列的段之间是独立的**。所以状态自然按"列"组织，每列一个 `[top_row, bottom_row]` 区间（或更准确地，一个 `[l_row, r_row]` 区间）。

### 第 3 步：方向交替 ⇒ 维度交替（这是本题最关键的结构性观察）

题目保证**相邻命令不同**。NORTH/SOUTH 都改变行号，WEST/EAST 都改变列号。

考虑命令序列 $d_1, d_2, \dots, d_N$。
- 若 $d_i$ 是 NORTH/SOUTH（称"纵向命令"），它把状态组织成**按列分段的行区间**。
- 若 $d_i$ 是 WEST/EAST（"横向命令"），它把状态组织成**按行分段的列区间**。

关键观察：**相邻命令不同**有两种可能：
1. **方向改变但维度不变**：NORTH → SOUTH。此时两次都是纵向命令。
2. **维度改变**：NORTH → WEST。此时纵向 → 横向。

第 1 种情形（NORTH → SOUTH）会让状态**缩小**：必须先停在 NORTH 能到达的段里，再向南延伸。两次同维度命令之间，状态始终按列组织（或按行，取决于维度）。

> **重要推论**：状态集合始终可以表示为"若干条**平行于命令方向**的连续段"。纵向命令 ⇒ 段是竖的（每列一段），横向命令 ⇒ 段是横的（每行一段）。

这个观察把"二维的格子集合"压缩成"一维的若干区间"，复杂度从 $O(RC)$ 格子降到 $O(\max(R,C))$ 段。

### 第 4 步：状态表示与转移

我们维护两组数组（按当前命令的维度选用）：
- 纵向状态：`l_col[y]` = 列 $y$ 中当前可能停靠的**最上行号**（0 表示该列无可能点），`r_col[y]` = **最下行号**。
- 横向状态：`l_row[x]` = 行 $x$ 中当前可能停靠的**最左列号**（0 表示该行无可能点），`r_row[x]` = **最右列号**。

（约定 0 表示空，真实下标从 1 开始，避免和 0 下标混淆——但代码里我们用 -1 表空、0 表真实，下面说明。）

**命令 NORTH 的转移**（设当前是纵向状态 `l_col`/`r_col`，输入也是纵向 NORTH）：
- 对每列 $y$，从 $l_col[y]$ 向上找到第一个不可通行格 $w_y$（墙或边界外），新段为 $[w_y+1, \; r_col[y]-1]$（**去掉原段最顶 $l_col[y]$**——必须至少走一格，且原段最顶不能再作为"停靠后的新起点"向北延伸，因为那意味着原地不动）。

  等等——这里要小心。命令 NORTH 要求"至少走一格"。所以从原段 $[l, r]$ 中的某格 $x$ 出发，向北能到的格是 $[\text{top}_y(x), x-1]$。新段的整体是各 $x$ 贡献的并集。由于 $\text{top}_y$ 在同一段可行区里是常数，并集为 $[\text{top}_y(l), r-1]$（$l$ 是原段最顶，它向上延伸最多；$r-1$ 是原段最底减一，它只贡献 $r-1$ 这一格）。

  所以新 `l_col[y] = top_y(l_col[y])`，新 `r_col[y] = r_col[y] - 1`。
  若新 $l > r$，该列变空。

**命令 SOUTH 的转移**（同理）：
- 新 `l_col[y] = l_col[y] + 1`，新 `r_col[y] = bot_y(r_col[y])`，其中 $\text{bot}_y(r)$ 是从 $r$ 向下第一个不可通行格之上的行号。
- 若 $l > r$ 变空。

**命令 WEST 的转移**（横向状态 `l_row`/`r_row`，当前命令 WEST）：
- 新 `l_row[x] = l_row[x] + 1`，新 `r_row[x] = left_x(l_row[x])`（向左延伸）。
- 若 $l > r$ 变空。

**命令 EAST 的转移**：
- 新 `l_row[x] = right_x(r_row[x])`，新 `r_row[x] = r_row[x] - 1`。

**维度切换（纵向 → 横向，或反之）怎么办？**
例如前一条是 NORTH（状态按列存 `l_col`/`r_col`），这一条是 WEST（需要按行存 `l_row`/`r_row`）。

转移：对每一行 $x$，收集所有 $y$ 使得 $l_col[y]\le x\le r_col[y]$，则新 `l_row[x] = min y`、`r_row[x] = max y`（若该行无任何列覆盖则空）。

这个切换是 $O(RC)$ 的（扫描所有格子），但只发生**维度交替时**，最多 $N$ 次，总复杂度 $O(NRC)$。$N\le 1000$，$RC\le 2500$，总计 $2.5\times 10^6$，完全可接受。

### 第 5 步：为什么段表示是对的？（完整正确性论证）

**定理**：上述算法在每条命令后维护的段集合，恰好等于汽车**可能停留**的全部格子集合。

**证明**（对命令数 $k$ 归纳）。

- $k=0$：初始只有起点 $S=(x_0,y_0)$。若首条命令是纵向，则 `l_col[y_0]=r_col[y_0]=x_0`，其余列空。正确。

- 归纳步：设 $k$ 条命令后段集合 $S_k$ 正确，处理第 $k+1$ 条命令 $d$。

  **情形 1：$d$ 与 $d_k$ 同维度**（如 NORTH→SOUTH）。
  新集合 = $\{p: \exists q\in S_k, \text{从 }q\text{ 沿 }d\text{ 走}\ge 1\text{格能到 }p\}$。
  由引理 A，对每列 $y$，$S_k$ 在列 $y$ 是 $[l_y,r_y]$，新集合在列 $y$ 是 $[\text{top}_y(l_y), r_y-1]$（NORTH 例）。这正是算法做的。✓

  **情形 2：$d$ 与 $d_k$ 维度不同**（如 NORTH→WEST）。
  先做维度切换：把 $S_k$（按列的段）转成按行的段。由"每列一段"的定义，行 $x$ 上的格子 = $\{y: l_y\le x\le r_y\}$，这本身就是行 $x$ 上 $S_k$ 的全部格子，且**在行 $x$ 上是连续的**（因为 $y$ 的取值使 $l_y\le x\le r_y$ 的 $y$ 集合是连续的吗？——**不一定**！）。

  > **反例检查**：列 1 段 $[1,5]$，列 2 段 $[10,12]$，列 3 段 $[1,5]$。行 $x=3$ 上 $S_k$ 含 $\{1,3\}$，**不连续**！

  所以"维度切换后按行仍是连续段"的断言**是错的**。但——**不需要是连续段也照样能正确转移**：只要我们知道每行上**最小列号** $l_{\text{row}}[x]$ 和**最大列号** $r_{\text{row}}[x]$，且转移只依赖这两个端点，就够吗？

  再看 WEST 转移：从行 $x$ 上的某格 $y$ 出发向西走，能到的列是 $[\text{left}_x(y), y-1]$。整个新集合在行 $x$ 上是 $\bigcup_{y\in Y_x}[\text{left}_x(y), y-1]$。若 $Y_x$ 不连续，这个并集**可能不连续**。

  **但是**：注意 WEST 转移后，新集合的每个格 $p$ 都满足"从某 $q\in S_k$ 沿 WEST 走 ≥1 格到 $p$"。而 $S_k$ 本身是由"前一条纵向命令"产生的——**纵向命令产生的 $S_k$，在每列上是一段**，这意味着 $S_k$ 有一个强结构：**它是若干竖条的并**，每条竖条占满某列的一段。

  这种"竖条并"结构在行方向投影时，每行得到的列集合**未必连续**，但 WEST 转移的"向西延伸"操作有**单调性**：若 $y_1<y_2$ 都在 $Y_x$，且中间某 $y'\in(y_1,y_2)$ 不在 $Y_x$，那么 $y'$ 这一列在行 $x$ 上没被 $S_k$ 覆盖，意味着 $y'$ 列的段不覆盖 $x$。然而 $y'$ 列的段是连续的，若不覆盖 $x$，要么整段在 $x$ 上方要么整段在 $x$ 下方。

  这个分析变得复杂。我们退一步，**用暴力验证**这个算法——如果维度切换后行方向不连续，我们需要改表示。

**重新审视：是否真的需要"段"表示？**

$R,C\le 50$，格子总数 $RC\le 2500$。$N\le 1000$。
直接用**布尔数组** `ok[x][y]` 表示"可能停靠"，每条命令扫描全部格子：

- NORTH：对每列 $y$，自顶向下扫描，维护"当前是否已在可行段内"，标记可达。

  更简单：对每格 $(x,y)$，若 `ok[x][y]` 且 $x>0$ 且 $(x-1,y)$ 可行，则新 `ok2[x-1][y]` 候选……不对，是"从 $(x,y)$ 向北走 ≥1 格"，能到的格是 $(x-1,y),(x-2,y),\dots$ 直到墙。

  直接做法：对每列 $y$，找出 $S_k$ 在列 $y$ 的最下行 $r_y$（若该列有格子），则新可达段 = $[\text{top}_y(r_y)?, r_y-1]$……不，是从**任意** $q\in S_k$ 出发。

  最干净的暴力：对每列 $y$，若 $S_k$ 在列 $y$ 非空，则新可达 = 从 $\min(S_k\cap\text{col }y)$ 向上到第一个墙，**并** 从 $\max(S_k\cap\text{col }y)$ 向上到第一个墙……不对，应该是**从最顶 $l_y$ 向上**（它延伸最远）**到** $r_y-1$（最底减一）。

  这正是"段表示"！所以暴力也退化成段表示。

**结论**：无论用暴力还是优化，核心都是"每列（或每行）一段"。维度切换时的"不连续"问题，实际上**不影响正确性**，因为：

> **引理 B（维度切换后，新维度的端点足够）**
> 设 $S_k$ 由纵向命令产生（每列一段）。处理 WEST 命令时，对行 $x$，新可达列集合 = $\{y': \exists y\in Y_x, \text{left}_x(y)\le y'\le y-1\}$，其中 $Y_x=\{y: l_y\le x\le r_y\}$。
>
> 这个集合等于 $[\text{left}_x(\min Y_x),\; \max(Y_x)-1]$ 吗？
>
> 上界：$\max(Y_x)-1$ 显然可达（取 $y=\max Y_x$）。
> 下界：$\text{left}_x(\min Y_x)$ 显然可达（取 $y=\min Y_x$）。
> 中间：对任意 $y'\in[\text{left}_x(\min Y_x), \max(Y_x)-1]$，需证存在 $y\in Y_x$ 使 $\text{left}_x(y)\le y'\le y-1$。
>
> 取 $y^* = \min\{y\in Y_x: y>y'\}$（若存在）。则 $y^*-1\ge y'$。还需 $\text{left}_x(y^*)\le y'$。
> $\text{left}_x(y^*)$ 是从 $y^*$ 向左连续可行格的最左列。由于 $y'\ge \text{left}_x(\min Y_x)$ 且 $\min Y_x$ 与 $y^*$ 之间可能隔墙……

  这个证明卡住了。**换策略：既然 $RC\le 2500$ 极小，直接用格子集合（位集/布尔数组）暴力，不做段优化。**

### 第 5' 步（最终方案）：暴力格子集合

$RC\le 2500$，$N\le 1000$，总操作 $N\cdot RC = 2.5\times 10^6$，极快。

**状态**：`bool ok[R][C]`，`ok[x][y]` = 汽车当前可能停在 $(x,y)$。

**每条命令的转移**（以 NORTH 为例）：
- 初始化 `ok2` 全 false。
- 对每列 $y$：从上到下扫描。维护"本列 $S_k$ 是否有格子"的标记。
  - 更直接：对每列 $y$，找出 $S_k$ 在列 $y$ 的最上行 $l_y$ 和最下行 $r_y$。若 $l_y$ 存在，则新可达 = 从 $l_y$ 向上到第一个不可通行格 $w$（含 $w+1$），**并** 到 $r_y-1$。即新段 $[w+1, r_y-1]$（若 $w+1\le r_y-1$）。

  等等，这还是段。但**我们不需要证明并集连续**——因为 $S_k$ 在列 $y$ **本来就是一段**（归纳假设），所以 $S_k\cap\text{col }y = [l_y, r_y]$ 连续。NORTH 转移后新集合在列 $y$ 是 $[\text{top}_y(l_y), r_y-1]$，也连续。**段表示在同维度命令下是封闭的**。

  维度切换时（纵向→横向），新集合按行组织，**可能不连续**。但我们可以**放弃"每行一段"的假设，直接用 `ok[x][y]` 布尔数组**：

  **维度切换（如 NORTH 后接 WEST）的暴力转移**：
  - `ok` 是上一命令后的格子集合（任意形状）。
  - WEST：`ok2[x][y'] = true` 当且仅当 $\exists y>y'$ 使 `ok[x][y]` 且 $(x,y'),(x,y'+1),\dots,(x,y)$ 全可行。
  - 等价：对每行 $x$，从左到右扫描，维护"右侧是否存在可达源点"。

  具体：对每行 $x$：
  ```
  reachable = false   // 是否已遇到一个 ok[x][y] 源点，且从该源点到当前位置全可行
  for y = 0 to C-1:
      if ok[x][y]: reachable = true   // 源点本身（但 WEST 要求至少走一格，源点本身不算）
      if reachable and cell(x,y) walkable: ok2[x][y] = true   // 等等，要 y < 源点
  ```
  更仔细：WEST 是从源点 $y_s$ 走到 $y<y_s$，路径 $(x,y+1),\dots,(x,y_s)$ 全可行（不含源点 $y_s$ 本身，因为源点已在 $S_k$）。
  
  简化：`ok2[x][y] = true` 当 $\exists y_s>y$ 使 `ok[x][y_s]` 且 $\forall y''\in[y+1, y_s], \text{cell}(x,y'')$ 可行。
  
  等价（反向扫描）：对每行 $x$，从 $y=C-1$ 到 $0$：
  ```
  src = false   // 右侧是否已遇到源点，且从当前 y 到该源点全可行
  for y = C-1 downto 0:
      if ok[x][y]:
          ok2[x][y] stays false (源点本身不能原地不动)
          src = true   // 从此 y 向左，若全可行则可达
      if src and cell(x,y) walkable:
          ok2[x][y] = true
      if not cell(x,y) walkable:
          src = false   // 墙挡住
  ```
  
  等等，`src` 的维护：一旦遇到源点 $y_s$，对 $y<y_s$，只要 $(x,y+1)\dots(x,y_s)$ 全可行，$y$ 就可达。从右往左扫，`src` 表示"从 $y+1$ 到某个源点全可行且存在源点"。遇到墙则 `src=false`。

  代码：
  ```cpp
  for x:
      bool src=false;
      for y=C-1 downto 0:
          if(!walk(x,y)) { src=false; continue; }
          if(ok[x][y]) { ok2[x][y]=false; }  // 源点本身
          else if(src) { ok2[x][y]=true; }
          // 更新 src：若 (x,y) 是源点或 (x,y) 可达且右侧有源点
          if(ok[x][y]) src=true;
          // 实际上 src 应该在处理 (x,y) 之前表示"y+1 侧是否有源点链"
  ```
  
  让我重新理顺 WEST 的反向扫描：
  - 定义 `can[y]` = "从行 $x$ 的列 $y$ 出发，向西（列减小方向）走 ≥1 格能到达某格" —— 不对，我们要的是"某源点 $y_s>y$ 能走到 $y$"。
  
  换个清晰定义：处理行 $x$，从 $y=C-1$ 到 $0$：
  - 维护 `has_src`：表示"在列 $y+1$ 及更右，存在源点 $y_s$ 使得 $(x,y+1),(x,y+2),\dots,(x,y_s)$ 全可行"。
  - 进入列 $y$：
    - 若 cell$(x,y)$ 是墙：`has_src = false`，`ok2[x][y]=false`，continue。
    - 否则（可行）：
      - 若 `ok[x][y]`（是源点）：`ok2[x][y]` 由 `has_src` 决定？不——`ok2[x][y]` 表示"汽车最终停在 $(x,y)$"，需要存在源点 $y_s>y$ 能走到 $y$，即 `has_src` 为真。源点本身 $(x,y)$ 也能被"更右的源点"走到吗？可以！若 $y_s>y$ 且路径可行，汽车可从 $y_s$ 走到 $y$，停在 $y$。所以 `ok2[x][y] = has_src`。
      - 然后更新 `has_src` 为下一轮（列 $y-1$）用：`has_src = has_src or ok[x][y]`（若 $(x,y)$ 是源点，则对 $y-1$ 来说 $y$ 是候选源点；若 `has_src` 已真，传递下去）。

  所以：
  ```cpp
  for x in 0..R-1:
      bool has_src = false;
      for y = C-1 downto 0:
          if(!walk(x,y)){ has_src=false; continue; }
          ok2[x][y] = has_src;
          has_src = has_src or ok[x][y];
  ```

  验证：源点 $y_s$，列 $y_s-1$：进入 $y_s-1$ 时 `has_src` 还是旧值（$y_s$ 右侧的源点链）。然后 `has_src = has_src or ok[x][y_s-1]`。若 $ok[x][y_s]$（$y_s$ 是源点），在列 $y_s$ 处理时：`ok2[x][y_s]=has_src_old`，`has_src = has_src_old or true = true`。然后列 $y_s-1$：`ok2[x][y_s-1] = true`（若可行）。✓

  这个扫描是 $O(C)$ 每行，总 $O(RC)$。

  NORTH/SOUTH/EAST 同理（扫描方向不同）。

**复杂度**：$N \cdot RC \le 1000 \times 2500 = 2.5\times 10^6$。✓

**这个暴力方案不需要证明"段连续"**，直接枚举格子，正确性显然（直接模拟定义）。我们用它。

### 第 6 步：边界与空集合

- 若某命令后 `ok` 全 false，后续命令保持全 false，最终输出无 `*`（除了原地图的 `X` 保持）。
- 起点 `*` 在输出时：若 `ok[x0][y0]` 为真则输出 `*`，否则 `.`。原 `*` 只是标记起点，最终是否出现取决于它是否在可能集合中。

### 第 7 步：输出

输出 $R$ 行，每行 $C$ 字符：
- 若原格是 `X`：输出 `X`。
- 否则若 `ok[x][y]`：输出 `*`。
- 否则：输出 `.`。

## Part 3 — 模式总结

```
- explore its property — "至少走一格 + 中途可停" ⇒ 状态从单点扩展为方向上的连续段；相邻命令不同 ⇒ 维度交替
- consider easier version — 单条命令下点→段；多条同维度命令下段→段（封闭）
- classic problem solution — 放弃段优化的证明负担，直接布尔格子集合 + 沿命令方向单趟扫描转移（利用"路径必须全可行"的单调性，O(1)/格）
- reduce to easier problem — 每条命令的转移 = 沿该方向一次线性扫描，维护"右侧/上侧是否有可达源点链"标志
- defer reconstruction — 输出时按 ok 数组直接渲染，无需回溯路径
```

## Part 4 — 真实解法

### 符号表

| 符号 | 含义 | 初始化 | 助记 |
|---|---|---|---|
| `R, C` | 地图行数、列数 | 输入 | |
| `grid[x][y]` | 原地图字符，`'X'`/`'.'`/`'*'` | 输入 | 原图 |
| `walk(x,y)` | `grid[x][y] != 'X'`（`*` 和 `.` 都可行） | — | 可行性 |
| `ok[x][y]` | 当前命令执行后，汽车**可能**停在 $(x,y)$ | 仅起点 `true`，其余 `false` | 当前可能集合 |
| `ok2[x][y]` | 下一条命令执行后的可能集合 | 每条命令前清零 | 下一状态 |
| `x0, y0` | 起点坐标（`grid` 中 `*` 的位置） | 扫描输入时记录 | |
| `cmd` | 当前命令字符串 | 输入 | |

### 算法步骤

1. 读入 $R, C$ 与地图，记录起点 $(x_0, y_0)$。
2. 初始化 `ok` 全 false，`ok[x0][y0] = true`。
3. 读入 $N$ 与 $N$ 条命令。对每条命令 $d$：
   1. 清零 `ok2`。
   2. 按 $d$ 做线性扫描转移：
      - **NORTH**：对每列 $y$，从 $x=0$ 到 $R-1$ 扫描。维护 `has_src`（上方是否有可达源点链）。进入 $(x,y)$：若墙则 `has_src=false` 跳过；否则 `ok2[x][y]=has_src`，`has_src = has_src || ok[x][y]`。
      - **SOUTH**：对每列 $y$，从 $x=R-1$ 到 $0$ 扫描。同上，`has_src` 表示下方源点链。
      - **WEST**：对每行 $x$，从 $y=C-1$ 到 $0$ 扫描。`has_src` 表示右方源点链。
      - **EAST**：对每行 $x$，从 $y=0$ 到 $C-1$ 扫描。`has_src` 表示左方源点链。
   3. `ok = ok2`（拷贝或交换）。
4. 输出 $R$ 行：`grid[x][y]=='X'` → `X`；`ok[x][y]` → `*`；否则 `.`。

### 复杂度

- 时间：$O(NRC)$，$N\le 1000, RC\le 2500$，$\le 2.5\times 10^6$。
- 空间：$O(RC)$。

### 正确性

直接模拟定义：`ok2[x][y]=true` 当且仅当存在源点 $q$（`ok[q]=true`）使汽车从 $q$ 沿命令方向走 ≥1 格能到 $(x,y)$ 且路径全可行。线性扫描的 `has_src` 标志恰好等价于"扫描方向上、到当前格之间全可行、且存在源点"。由归纳，每条命令后 `ok` 正确。✓

### 验证状态

## Part 5 — 示例代码（C++）

```cpp
#include<bits/stdc++.h>
using namespace std;

constexpr int mxr{55};
constexpr int mxc{55};

int r,c;
char grid[mxr][mxc];
bool ok[mxr][mxc]{};
bool ok2[mxr][mxc]{};

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>r>>c;
	int x0=-1,y0=-1;
	for(int i=0;i<r;++i)
	{
		for(int j=0;j<c;++j)
		{
			cin>>grid[i][j];
			if(grid[i][j]=='*')
				x0=i,y0=j;
		}
	}

	ok[x0][y0]=true;

	int n;
	cin>>n;
	string cmd;

	for(int k=0;k<n;++k)
	{
		cin>>cmd;
		//clear ok2
		for(int i=0;i<r;++i)
			for(int j=0;j<c;++j)
				ok2[i][j]=false;

		if(cmd=="NORTH")
		{
			for(int j=0;j<c;++j)
			{
				bool has=false;
				for(int i=0;i<r;++i)
				{
					if(grid[i][j]=='X')
					{
						has=false;
						continue;
					}
					ok2[i][j]=has;
					has=has||ok[i][j];
				}
			}
		}
		else if(cmd=="SOUTH")
		{
			for(int j=0;j<c;++j)
			{
				bool has=false;
				for(int i=r-1;i>=0;--i)
				{
					if(grid[i][j]=='X')
					{
						has=false;
						continue;
					}
					ok2[i][j]=has;
					has=has||ok[i][j];
				}
			}
		}
		else if(cmd=="WEST")
		{
			for(int i=0;i<r;++i)
			{
				bool has=false;
				for(int j=c-1;j>=0;--j)
				{
					if(grid[i][j]=='X')
					{
						has=false;
						continue;
					}
					ok2[i][j]=has;
					has=has||ok[i][j];
				}
			}
		}
		else // EAST
		{
			for(int i=0;i<r;++i)
			{
				bool has=false;
				for(int j=0;j<c;++j)
				{
					if(grid[i][j]=='X')
					{
						has=false;
						continue;
					}
					ok2[i][j]=has;
					has=has||ok[i][j];
				}
			}
		}

		for(int i=0;i<r;++i)
			for(int j=0;j<c;++j)
				ok[i][j]=ok2[i][j];
	}

	for(int i=0;i<r;++i)
	{
		for(int j=0;j<c;++j)
		{
			if(grid[i][j]=='X')
				cout<<'X';
			else if(ok[i][j])
				cout<<'*';
			else
				cout<<'.';
		}
		cout<<'\n';
	}

	return 0;
}
```

### 代码说明

- **全局静态数组** `grid` / `ok` / `ok2`，尺寸 `55 = 50+5` 松弛。
- **每条命令一次线性扫描**，`has` 标志维护"扫描方向上到当前格之间全可行且存在源点"，墙处复位。
- 四个方向的扫描方向：
  - NORTH：列内从上到下（`i: 0→r-1`），`has` 表示"上方源点链"。
  - SOUTH：列内从下到上（`i: r-1→0`），`has` 表示"下方源点链"。
  - WEST：行内从右到左（`j: c-1→0`），`has` 表示"右方源点链"。
  - EAST：行内从左到右（`j: 0→c-1`），`has` 表示"左方源点链"。
- 输出时 `X` 优先（墙不变），`ok` 为真输出 `*`，否则 `.`。
- 未使用 `endl`，换行用 `'\n'`；`cin.tie(nullptr)` 在前。
