# P1614 爱与愁的心痛

## Part 1 — 题目理解 (Problem Comprehension)

### 题意简述

给定长为 $n$ 的正整数序列 $a_1,a_2,\dots,a_n$，求所有**连续 $m$ 个数**之和的最小值，即
$$\min_{0\le i\le n-m}\ \sum_{j=i}^{i+m-1} a_j .$$

### 输入输出格式

- **输入格式**：第一行 $n,m$；随后 $n$ 行，每行一个整数 $a_i$（**注意是每行一个**）。
- **输出格式**：一行一个整数，连续 $m$ 个刺痛值和的最小值。
- **数据规模**：$0\le m\le n\le3\times10^3$，$1\le a_i\le100$。

### 关键约束分析

1. $n\le3000$，$\mathcal{O}(n\cdot m)\le9\times10^6$ 的暴力都能过；但用滑动窗口可以 $\mathcal{O}(n)$，代码同样短。
2. **$m$ 可以等于 $0$**：此时"连续 $0$ 个数之和"按定义为 $0$。很多题解写成 `for(i=0;i+m<=n;...)` 并在循环里取 `ans=min(...)`，当 $m=0$ 时会把答案算成 $0$，恰好也是对的，但 `ans` 初值若取 $0$ 又会掩盖 $m\ge1$ 的错误——要分清楚。
3. $m=n$ 时只有一个候选（整段和）。
4. 输入格式是"每行一个数"，但用 `cin>>` 读整数时空白（含换行）自动跳过，不必特殊处理。
5. 数值范围：$\sum\le3000\times100=3\times10^5$，`int` 足够，不必开 `long long`（开了也无害）。

## Part 2 — 思路推导 (Idea Discovery)

### 第一步：最直白的写法

对每个起点 $i\in[0,n-m]$，用一层循环累加 $m$ 个数，取最小值。复杂度 $\mathcal{O}(n\cdot m)\le9\times10^6$，本题完全能过。

但它有明显的浪费：从窗口 $[i,i+m)$ 移到 $[i+1,i+1+m)$ 时，中间 $m-1$ 个数被**重复加了两遍**。

### 第二步：把重复的部分剥掉

**引理 1（窗口递推）**：记 $S_i=\sum_{j=i}^{i+m-1}a_j$，则
$$S_{i+1}=S_i-a_i+a_{i+m}.$$

*证明*：两个窗口的公共部分是 $[i+1,i+m)$，共 $m-1$ 个数；$S_{i+1}$ 比 $S_i$ 少了 $a_i$、多了 $a_{i+m}$。按定义展开即得。$\square$

于是只要 $\mathcal{O}(m)$ 算出 $S_0$，之后每步 $\mathcal{O}(1)$ 递推，总复杂度 $\mathcal{O}(n)$。

### 第三步：正确性与边界

**引理 2（候选集合完备）**：所有长度恰为 $m$ 的连续段，恰好是 $S_0,S_1,\dots,S_{n-m}$。

*证明*：长度 $m$ 的连续段由起点唯一确定，合法起点是 $0\le i\le n-m$，共 $n-m+1$ 个，与 $S_i$ 一一对应。$\square$

**引理 3（算法正确）**：初始化 $cur=S_0$、$ans=S_0$，然后对 $i=m..n-1$ 做 $cur\mathrel{+}=a_i-a_{i-m}$ 并更新 $ans=\min(ans,cur)$，最终 $ans=\min_i S_i$。

*证明*：由引理 1，第 $t$ 次迭代后 $cur=S_t$（$t=i-m+1$）。迭代覆盖 $t=1..n-m$，加上初值 $S_0$，恰好遍历引理 2 的全部候选并取最小。$\square$

**边界 $m=0$**：此时不存在"窗口"，题面按"连续 $0$ 个数之和 $=0$"理解，输出 $0$。代码在最前面特判，避免出现"初值 $S_0$ 需要读 $0$ 个数"与"循环从 $i=0$ 开始"的下标混乱。

### 第四步：为什么不需要前缀和

前缀和写法 $pre_i=\sum_{j<i}a_j$，$S_i=pre_{i+m}-pre_i$，也是 $\mathcal{O}(n)$ 预处理 + $\mathcal{O}(1)$ 查询。两种写法等价；滑动窗口少一个数组，且不必担心 $m=0$ 时 `pre[i]` 的下标问题（虽然也能处理）。本题两者都可以，这里选滑动窗口。

## Part 3 — 模式总结 (Pattern Summary)

- `explore its property` — 相邻两个定长窗口只差"一头一尾"两个元素。
- `classic problem solution` — 滑动窗口（增量更新）把 $\mathcal{O}(nm)$ 降到 $\mathcal{O}(n)$。
- `reduce to easier problem` — 用差分思想把"求和"换成"加减一个元素"，与"区间和 = 前缀和相减"同源。
- `handle degenerate case` — $m=0$ 是唯一需要特判的退化情形。

## Part 4 — 真正的解法 (The Real Solution)

### 符号表 (Notation Glossary)

| 数学符号 | 代码变量 | 含义说明 |
| :--- | :--- | :--- |
| $n,m$ | `n,m` | 序列长度、窗口长度 |
| $a_i$ | `a[i]` | 刺痛值，$0$ 基存放 |
| $S_i$ | `cur` | 当前窗口 $[i,i+m)$ 的和 |
| 答案 | `ans` | 所有窗口和的最小值，初值为 $S_0$ |
| $i$ | `i` | 滑动窗口的右端点下标（新进入窗口的元素） |

### 算法步骤

1. 读入 $n,m$ 与 $a_0..a_{n-1}$。
2. 若 $m=0$，输出 $0$ 并结束。
3. 计算 $cur=\sum_{j=0}^{m-1}a_j$，令 $ans=cur$。
4. 对 $i=m..n-1$：`cur+=a[i]-a[i-m]`，`ans=min(ans,cur)`。
5. 输出 `ans`。

### 复杂度分析

- **时间复杂度**：$\mathcal{O}(n)$（初始化 $\mathcal{O}(m)$，滑动 $n-m$ 步）。
- **空间复杂度**：$\mathcal{O}(n)$ 存序列。

### 正确性验证

- 引理 1 保证递推式正确，引理 2 保证候选不重不漏，引理 3 给出整体正确性。
- 数值范围：窗口和 $\le3\times10^5$，`int` 安全；`cur` 在递推中不会变成负数（$a_i\ge1$，但即便为负也不会溢出）。
- 边界：$m=0$ 特判输出 $0$；$m=n$ 时初始窗口就是整段，循环不执行，直接输出整段和。

## Part 5 — 示例代码 (Example Code)

```cpp
//
// 题目：P1614 爱与愁的心痛
// https://www.luogu.com.cn/problem/P1614
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{3005};              // n<=3000

int n,m,a[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n>>m;
	for(int i=0;i<n;++i)
		cin>>a[i];
	if(m==0)                          // 长度 0 的区间和为 0
	{
		cout<<0<<'\n';
		return 0;
	}
	i64 cur=0;
	for(int i=0;i<m;++i)
		cur+=a[i];
	i64 ans=cur;
	for(int i=m;i<n;++i)              // 滑动窗口
	{
		cur+=a[i]-a[i-m];
		ans=min(ans,cur);
	}
	cout<<ans<<'\n';
	return 0;
}
```

### 易错点

1. **`ans` 初值取 $0$**：若取 $0$ 且不做特判，$m\ge1$ 时最小值永远是 $0$，答案直接错。
2. **`m=0` 不特判**：写法 `cur` 初始化时循环不执行，`cur=0`、`ans=0`，恰好输出 $0$；但如果 `ans` 初值是 `INF` 又用 `min` 收集，最后要保证能输出 $0$，还是显式特判最清楚。
3. **循环上界写成 `i<=n`**：`a[i-m]` 与 `a[i]` 必须都在 $[0,n)$ 内，`i` 只能到 $n-1$。
4. **窗口右移时写成 `cur+=a[i]`**：忘了减去离开窗口的 `a[i-m]`。
5. **读入格式**：题目是每行一个数，用 `cin>>` 即可，别用 `getline` 逐行再解析（容易踩空行）。
