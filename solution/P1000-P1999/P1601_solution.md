# P1601 高精度加法

## Part 1 — 题目理解 (Problem Comprehension)

### 题意简述

给定两个非负整数 $a,b$（十进制书写，可能长达 $500$ 位），求 $a+b$ 的十进制表示。不需要考虑负数与符号。

### 输入输出格式

- **输入格式**：两行，每行一个非负整数，没有多余字符。
- **输出格式**：一行，一个非负整数，即 $a+b$；不得有前导零（结果为 $0$ 时输出单个 `0`）。
- **数据规模**：$0 \le a,b \le 10^{500}$，即位数 $L \le 501$。另有 $20\%$ 数据 $a,b\le10^9$、$40\%$ 数据 $a,b \le 10^{18}$ 的子任务。

### 关键约束分析

1. **为什么不能用内置类型**：$10^{500}$ 需要约 $1661$ 个二进制位，`long long`（$63$ 位可用）与 `__int128`（$127$ 位）都远远不够。
2. **子任务暗示了递进关系**：$10^9$（`int`）→ $10^{18}$（`long long`）→ $10^{500}$（必须自己实现），这意味着"位数"才是真正的瓶颈，思路应从"整数运算"转向"字符串/数组上的竖式运算"。
3. **前导零**：输入可能带前导零（如 `0007`），输出不允许前导零；两个数都为 $0$ 时必须输出 `0` 而不是空串。
4. **进位方向**：加法从低位向高位传播，而字符串的高位在前，所以要么反转，要么按下标倒序访问。

## Part 2 — 思路推导 (Idea Discovery)

### 第一步：从子任务 1、2 出发

$a,b\le10^9$ 时直接 `cin>>a>>b; cout<<a+b;` 即可；$\le10^{18}$ 时把类型换成 `long long`。
沿着这个方向再往前一步就撞墙了：类型长度是固定的。所以要换一个"容器"——
把整数拆成一位一位的数字存进数组，自己实现"列竖式"。

### 第二步：竖式的每一步在做什么

小学竖式：右对齐、逐位相加、超十进一。

**引理 1（单步进位唯一且不超过 1）**：设第 $i$ 位的两个数字为 $x,y\in[0,9]$，来自低位的进位为 $c\in\{0,1\}$，
则本位结果 $s=(x+y+c)\bmod 10$，向高位的进位 $c'=\lfloor (x+y+c)/10 \rfloor \in\{0,1\}$，且 $s,c'$ 由 $x,y,c$ 唯一确定。

*证明*：$0 \le x+y+c \le 9+9+1 = 19$，所以 $s = (x+y+c)-10c'$ 且 $c' \in \{0,1\}$（$19<20$ 保证不会进 $2$）。
取模与整除在整数上是确定函数，故 $s,c'$ 唯一。$\square$

引理 1 说明"逐位处理 + 一个进位变量"就够了，不需要预先知道高位，也不需要回溯。

**引理 2（按从低位到高位的顺序处理是正确的）**：把两个数分别**反转**（低位在前）后，从下标 $0$ 开始同步扫描，
每一步用引理 1 的规则产生一位结果并把进位带入下一步，则处理完所有位后得到的序列反转即为 $a+b$。

*证明*：对位数归纳。设两数反转后为 $A[0..]$、$B[0..]$，则 $a+b=\sum_i (A_i+B_i)10^i$。记
$T_i=\sum_{j<i}(A_j+B_j)10^j$，不变量取为"处理完前 $i$ 位后，进位 $c_i=\lfloor T_i/10^i\rfloor$，且已输出的 $i$ 位恰为 $a+b$ 的低 $i$ 位"。
$i=0$ 时 $c_0=0$，成立。设 $i$ 时成立，则第 $i$ 步的 $t=A_i+B_i+c_i$，
而 $T_{i+1}=10^i\bigl(c_i+(A_i+B_i)\bigr)+(T_i\bmod 10^i)$，故 $a+b$ 的第 $i$ 位数字为 $(c_i+A_i+B_i)\bmod 10=t\bmod 10$，
且 $c_{i+1}=\lfloor T_{i+1}/10^{i+1}\rfloor=\lfloor t/10\rfloor$，与引理 1 的规则一致，不变量保持。
归纳到底即得每一位都正确；最高位之外若仍有进位 $1$，正好补齐最高位。$\square$

### 第三步：长度与末尾进位

**引理 3（结果长度）**：$a+b$ 的十进制位数不超过 $\max(\text{len}(a),\text{len}(b)) + 1$。

*证明*：$a < 10^{\text{len}(a)}$，$b<10^{\text{len}(b)}$，故 $a+b < 2\cdot 10^{\max}$，当 $\max \ge 1$ 时 $2\cdot10^{m} \le 10^{m+1}$，位数至多 $m+1$。
（$a=b=0$ 时结果为 $0$，位数为 $1$，也满足。）$\square$

引理 3 决定了循环条件：只要"还有位没处理完"或"进位仍为 $1$"就继续，这样末尾进位会被自动补上，不必特判。

### 第四步：前导零

**引理 4（去前导零）**：设结果串为 $R$（高位在前），去掉 $R$ 的所有前导 `0` 后，若剩余为空则输出 `0`，否则输出剩余部分，
得到的正是 $a+b$ 的标准十进制写法。

*证明*：$R$ 是 $a+b$ 的一个"带前导零的十进制表示"，即 $R$ 的数值等于 $a+b$（前导零不改变数值）。
标准写法要求最高位非零（$0$ 本身除外），去掉前导零后要么最高位非零、要么整体为空（此时 $a+b=0$），二者都符合标准写法且数值不变。$\square$

**定理**：算法输出的字符串与 $a+b$ 的标准十进制表示逐字符相同。

*证明*：由引理 2 结果串数值正确，由引理 3 长度足够不丢位，由引理 4 去掉前导零后即为标准写法。$\square$

### 第五步：实现细节

- 用 `string` 存反转后的结果，最后 `reverse` 回来；
- 循环条件写成 `i>=0||j>=0||carry`，越界的位当作 $0$；
- 去前导零用"找第一个非零位置"再 `substr`，避免 `erase` 的 $O(L^2)$。

## Part 3 — 模式总结 (Pattern Summary)

- `explore its property` — 瓶颈是位数而不是数值，必须换"按位存储"的表示。
- `consider easier version` — 从 $10^9$（`int`）、$10^{18}$（`long long`）两个子任务逐步逼近，发现类型长度是死路。
- `classic problem solution` — 高精度竖式：反转成低位在前，逐位相加并维护进位。
- `handle boundary` — 循环条件带上 `carry`，让最高位的进位自然补出，避免特判。
- `normalize output` — 统一去掉前导零，并单独处理结果为 $0$ 的情形。

## Part 4 — 真正的解法 (The Real Solution)

### 符号表 (Notation Glossary)

| 数学符号 | 代码变量 | 含义说明 |
| :--- | :--- | :--- |
| $a,b$ | `a`, `b` | 输入的两个十进制串（高位在前），长度 $\le 501$ |
| $i,j$ | `i`, `j` | 指向 `a`、`b` 当前待处理位的下标，从末尾开始递减，$-1$ 表示该数已处理完 |
| $c_i$ | `carry` | 第 $i$ 步进入本位的进位，取值 $0$ 或 $1$，初值 $0$ |
| $x,y$ | `x`, `y` | 本位取到的两个数字（越界时为 $0$） |
| $t$ | `t` | 本位和 $x+y+carry$，范围 $[0,19]$ |
| $R$ | `sum_` | 结果串，**低位在前**地追加，最后整体反转 |
| $p$ | `p` | 反转后结果串中第一个非零位的下标，用于跳过前导零 |

### 算法步骤

1. 读入 `a`,`b`；令 `i=a.size()-1`，`j=b.size()-1`，`carry=0`。
2. 当 `i>=0 || j>=0 || carry` 时循环：
   - 取 `x=(i>=0? a[i]-'0' : 0)`、`y=(j>=0? b[j]-'0' : 0)`，并各自 `--`；
   - `t=x+y+carry`；`sum_ += '0'+t%10`；`carry = t/10`。
3. `reverse(sum_)`，使其恢复高位在前。
4. 从 `p=0` 开始跳过前导 `0`（保证至少留一位），输出 `sum_.substr(p)`。

### 复杂度分析

- **时间复杂度**：$\mathcal{O}(L)$，$L=\max(\text{len}(a),\text{len}(b))\le501$，每一位常数次操作，反转与 `substr` 各 $\mathcal{O}(L)$。
- **空间复杂度**：$\mathcal{O}(L)$，仅存放两个输入串与一个结果串。

### 正确性验证

引理 1 保证单步进位规则唯一且不会"进 2"，引理 2 保证逐位处理的顺序正确，引理 3 保证循环终止条件不会丢最高位，
引理 4 保证输出格式合法，定理给出整体正确性。
数值范围：单步最大 `19`，`int` 完全够用，不存在溢出；也没有浮点参与，无精度问题。

## Part 5 — 示例代码 (Example Code)

```cpp
//
// 题目：P1601 高精度加法
// https://www.luogu.com.cn/problem/P1601
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;

string a,b,sum_;                 // sum_ 低位在前地存放结果

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>a>>b;

	int i=a.size()-1,j=b.size()-1,carry=0;
	while(i>=0||j>=0||carry)
	{
		int x=i>=0?a[i--]-'0':0;
		int y=j>=0?b[j--]-'0':0;
		int t=x+y+carry;
		sum_+=char('0'+t%10);
		carry=t/10;
	}
	reverse(sum_.begin(),sum_.end());

	int p=0;                     // 去掉结果的前导零, 至少保留一位
	while(p+1<(int)sum_.size()&&sum_[p]=='0')
		++p;
	cout<<sum_.substr(p)<<'\n';
	return 0;
}
```

### 易错点

1. **循环条件漏掉 `carry`**：`a="9", b="1"` 时若只判 `i>=0||j>=0`，会输出 `0` 而不是 `10`。
2. **下标越界**：`i,j` 减到 $-1$ 后仍去访问 `a[i]` 是未定义行为，必须先判 `>=0`。
3. **忘记反转**：结果是低位在前追加的，不反转就整个数位序颠倒。
4. **前导零处理过头**：`while(p<size && s[p]=='0') ++p` 在结果为 `0` 时会把整个串删空，必须保留至少一位。
5. **用 `int`/`long long` 硬算**：$10^{500}$ 远超 64 位，只能按位模拟。
