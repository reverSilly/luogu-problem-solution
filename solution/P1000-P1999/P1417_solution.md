# P1417 烹调方案

> 标签：动态规划 DP / 排序 / 背包 DP · 难度：提高/省选-

## 1. 重新读题

**问题重述（简化版）**

$n$ 件食材，第 $i$ 件有三个属性 $a_i,b_i,c_i$：

- 做第 $i$ 件要**占用** $c_i$ 的时间（耗时，不是时刻）；
- 若第 $i$ 件的**完成时刻**是 $t$，它贡献美味度 $a_i-t\times b_i$（越晚完成越难吃）；
- 多件食材只能**串行**做（题面没有并行的说法，"设计烹调方案"即排一个顺序 + 选一个子集）。

求总耗时 $\le T$ 的方案中，所选食材美味度之和的最大值。

**输入形式**：先一行 $T,n$，之后**三行分别给出整个数组** $a_1..a_n$、$b_1..b_n$、$c_1..c_n$（不是每件食材一行三个数！这是本题最容易写错读入的地方）。

**数据范围**

| 规模 | 约束 |
|---|---|
| $40\%$ | $1\le n\le 10$ |
| $100\%$ | $1\le n\le 50$ |
| 全部 | "所有数字均小于 $10^5$"，即 $T$ 与所有 $a_i,b_i,c_i$ 都 $<10^5$ |

范围给出的暗示：$n$ 只有 $50$，$T$ 有 $10^5$，$n\le10$ 的部分分可以暴力枚举"子集 + 全排列"（$10!\cdot2^{10}\approx3.7\times10^9$ 偏大，实际要枚举"排列"就够，或按子集大小分别枚举），$40\%$ 的暴力恰好能用来验证正解。$n\cdot T=5\times10^6$ 是安全复杂度，说明正解形态是"排序 + 以时间为状态的 DP"。

**外部提示与题面的差异（按题面为准）**：题面标签写"动态规划、排序、背包 DP"，但**没有给出样例**（本地 `P1417.md` 无 Sample 段），因此本文无法与官方答案对标，只能在 §4 末尾用手算的自造用例验证。题面也未明说 $a_i,b_i,c_i$ 的下界（只说"小于 $10^5$"）与"是否必须至少做一件食材"，本文按 $1\le a_i,b_i,c_i<10^5$、且允许"一件都不做"（方案得分 $0$）处理，并在 §2.6 说明哪些结论依赖这两个假设。

**陷阱与边界清单**

1. **$t$ 是完成时刻，不是开始时刻**：第 $i$ 件在 $t=S_{\text{前}}+c_i$ 时刻结算，写成 $a_i-S_{\text{前}}b_i$ 会整体偏大 $c_ib_i$。
2. **顺序影响答案**：同一组食材，不同顺序分数不同（见 §2.2 用例 A），因此不能只做"选或不选"。
3. **贡献可为负**：$a_i-t b_i$ 在 $t$ 很大时为负，DP 中间值必须允许负数，不能按"最大值 $\ge 0$"的直觉把中间状态截断（见 §2.5 关于 $-\infty$ 初始化的讨论）。
4. **总耗时 $\le T$ 而非 $=T$**：答案要对 $\mathrm{dp}[0..T]$ 全部取 $\max$，只输出 $\mathrm{dp}[T]$ 会取到"不可达"或"无意义空转"的状态（用例 B）。
5. **溢出**：$t\times b_i\le 10^5\times10^5=10^{10}$，单个贡献就超出 `int`；排序判据 $b_ic_j$ 同样是 $10^{10}$ 量级。全部要 $64$ 位。
6. **$c_i>T$ 的食材**：内层循环自动不执行，天然被跳过，不需要特判，但要知道它为什么不会越界。

## 2. 思维链（Chain-of-thought）

### 2.1 探索特殊机制：时刻 $t$ 从哪里来

**把"一套方案"翻译成公式**。方案 $=$ 选一个下标集合 $S\subseteq\{1,\dots,n\}$ $+$ 给 $S$ 排一个顺序 $(i_1,i_2,\dots,i_m)$。串行做，所以第 $k$ 件食材的完成时刻就是"前面 $k$ 件的耗时之和"：

$$S_k=c_{i_1}+c_{i_2}+\cdots+c_{i_k},\qquad F=\sum_{k=1}^{m}\bigl(a_{i_k}-S_k b_{i_k}\bigr),\qquad \text{要求 } S_m\le T .$$

（时刻从 $0$ 开始计时：第一件在 $c_{i_1}$ 时刻完成，题面 "$t$ 时刻完成"没有别的起点可解释，也没有别的量可当 $t$。）

**引理 1（$F$ 的两份分离）** 把 $F$ 写成 $F=F_{\text{sel}}+F_{\text{ord}}$，其中

$$F_{\text{sel}}=\sum_{k=1}^m a_{i_k},\qquad F_{\text{ord}}=-\sum_{k=1}^m S_k b_{i_k} .$$

则 $F_{\text{sel}}$ 只依赖集合 $S$，与顺序无关；$F_{\text{ord}}$ 同时依赖 $S$ 与顺序。

**证明**：$a_{i_k}$ 只对 $k$ 求和，每个被选中的下标恰好出现一次，因此 $\sum_k a_{i_k}=\sum_{i\in S}a_i$，是 $S$ 的函数。而 $S_k$ 是"排在我前面（含自己）的 $c$ 之和"，交换两个相邻元素会改变哪些 $c$ 落在哪些 $b$ 的系数里，所以 $F_{\text{ord}}$ 依赖顺序。$\blacksquare$

**引理 2（$b$ 的作用方向）** 若 $b_i=0$，则第 $i$ 件食材的贡献与完成时刻无关，它既不"惩罚自己"也不受顺序影响。

**证明**：$a_i-S_kb_i=a_i-0=a_i$，与 $S_k$ 无关。$\blacksquare$

> **机制小结**：本题 = 「选子集」（背包）$+$ 「排顺序」（排序/交换论证）两个决策耦合在一起，耦合的载体是 $b_i\ge 1$ 的那些食材——它们希望尽早完成。直觉上"$b$ 大的要先做"，但必须先解决一个障碍：**先做要付的时间是 $c$**，所以真正要比较的是"单位耗时的衰减率"。这句话就是下一节的验证目标。

### 2.2 简化版 1：把"取舍"拿掉，只留顺序

先做一件更简单的事：假设**必须把所有 $n$ 件都做完**（且 $\sum c_i\le T$），此时 $F_{\text{sel}}=\sum a_i$ 是常数，只剩"怎样排使 $-\sum S_kb_{i_k}$ 最大"。这就是引理 3 的场景。

**引理 3（相邻交换判据）** 设某方案中相邻两件食材为 $i$（前）$j$（后），它们开始前已累计耗时 $t_0$，其余食材的位置不变。记 $D=(\text{i 在前的总分})-(\text{j 在前的总分})$，则

$$D=c_jb_i-c_ib_j .$$

特别地，$D$ 与 $t_0$、与 $a_i,a_j$、与其余所有食材的属性**都无关**。

**证明（逐项展开）**：$i$ 在前时 $i$ 完成于 $t_0+c_i$，$j$ 完成于 $t_0+c_i+c_j$；$j$ 在前时 $j$ 完成于 $t_0+c_j$，$i$ 完成于 $t_0+c_j+c_i$。其余项相同（见下方"其它位置不变"），故

$$D=\bigl[-(t_0+c_i)b_i-(t_0+c_i+c_j)b_j\bigr]-\bigl[-(t_0+c_j)b_j-(t_0+c_j+c_i)b_i\bigr].$$

$b_i$ 的系数：$-(t_0+c_i)+(t_0+c_j+c_i)=c_j$。$b_j$ 的系数：$-(t_0+c_i+c_j)+(t_0+c_j)=-c_i$。合并得 $D=c_jb_i-c_ib_j$。

其它位置不变：交换的两件相邻，之前食材的完成时刻都不变（前缀和不变），之后食材的完成时刻都等于 $t_0+c_i+c_j$ 再加上各自的后续前缀，两种顺序下这个值相同；$a$ 项按引理 1 与顺序无关。所以全局差确实等于局部差 $D$。$\blacksquare$

**引理 4（排序键）** 若 $c_i,c_j>0$，则 $D>0\iff \dfrac{b_i}{c_i}>\dfrac{b_j}{c_j}$。所以"单位耗时衰减率高"的应先做。

**证明**：$D=c_jb_i-c_ib_j>0$。因 $c_ic_j>0$，两边同除 $c_ic_j$（不等号方向不变）得 $\frac{b_i}{c_i}-\frac{b_j}{c_j}>0$。反向同理，故为等价。$\blacksquare$

> 写成判据时**不要做除法**，用 $b_ic_j$ 与 $b_jc_i$ 交叉相乘比较：既避免实数精度，也覆盖 $c=0$ 的情形（若数据允许）。

**用例 A（顺序确实重要，且方向由引理 4 决定）**：$T=2$，两件食材 $(a,b,c)$ 分别为 ①$(100,1,1)$、②$(100,10,1)$。

- ①前②后：①完成于 $1$，$100-1=99$；②完成于 $2$，$100-20=80$；合计 $179$。
- ②前①后：②完成于 $1$，$100-10=90$；①完成于 $2$，$100-2=98$；合计 $188$。

引理 3 预言的差 $D=c_{②}b_{①}-c_{①}b_{②}=1-10=-9$，即"①在前"比"②在前"差 $9$：$179=188-9$ ✓。键 $b/c$：①$=1$，②$=10$，降序应②在前 ✓。

**引理 5（键相等时顺序无所谓）** 若 $c_ib_j=c_jb_i$，则两种相邻顺序总分相同。

**证明**：此时 $D=c_jb_i-c_ib_j=0$，由引理 3，交换不改变总分。$\blacksquare$

**用例 G（验证引理 5）**：X$(a=100,b=2,c=1)$、Y$(a=100,b=4,c=2)$，键都是 $2$，$T=3$。X 前：$(100-2)+(100-4\times3)=98+88=186$；Y 前：$(100-4\times2)+(100-2\times3)=92+94=186$。相等 ✓，说明平局怎么打破都不影响最优性（这保证排序比较器的平局是安全的）。

### 2.3 简化版 2：把"时间惩罚"拿掉，只留取舍

令所有 $b_i=0$（引理 2 说此时顺序完全无关），问题变成

$$\max\sum_{i\in S}a_i\ \ \text{s.t.}\ \ \sum_{i\in S}c_i\le T,$$

就是**最裸的 $0/1$ 背包**：以"用时 $j$"为状态，$\mathrm{dp}[j]=\max(\mathrm{dp}[j],\mathrm{dp}[j-c_i]+a_i)$，复杂度 $O(nT)$，$50\times10^5=5\times10^6$，完全够。

> **两个简化版的启示**：顺序问题（§2.2）给出一个**与选择无关的两两比较判据**，取舍问题（本节）给出一个**以时间为状态的背包**。若"最优顺序可以由一次全局排序事先确定"，那么两者可以叠加：先排序，再在固定顺序上做背包。下面先验证这个前提，再检验贪心能不能顶替背包。

### 2.4 贪心的诱惑与失败（剖析三种）

排好序之后，最省事的做法是"按序一直做到装不下为止"。三种贪心都会错：

**贪心 1：按 $b$ 从大到小排。** 反例（用例 B1）：$T=11$，P$(a=100,b=10,c=10)$、Q$(a=100,b=9,c=1)$。

- P 前：P 完成于 $10$，$100-100=0$；Q 完成于 $11$，$100-99=1$；合计 $1$。
- Q 前：Q 完成于 $1$，$100-9=91$；P 完成于 $11$，$100-110=-10$；合计 $81$。

按 $b$ 排选了错的顺序（$1$ vs $81$）。原因：把 $b$ 大但 $c$ 也大的东西放前面，它自己只承担 $c_Pb_P$ 的惩罚，却让后面所有件多等 $c_P$ 的时间。真正该比的是"每单位耗时造成的衰减"，即 $b/c$（引理 4 已经证明了这一点，用例 B1 的键：P$=1$、Q$=9$，Q 在前 ✓）。

**贪心 2：按 $a$ 从大到小排。** 反例（用例 B2）：$T=2$，①$(a=100,b=1,c=1)$、②$(a=90,b=50,c=1)$。按 $a$ 排（①②）得 $(100-1)+(90-100)=89$；按 $b/c$ 排（②①）得 $(90-50)+(100-2)=138$。注意引理 3 的 $D$ 里根本没有 $a$ ——**排序键绝不该出现 $a_i$**，$a$ 只在"要不要选"里起作用。

**贪心 3：键排好序后顺序贪心装填。** 反例（用例 C）：$T=3$，三件食材

| 食材 | $a$ | $b$ | $c$ | 键 $b/c$ |
|---|---|---|---|---|
| ① | $100$ | $90$ | $3$ | $30$ |
| ② | $100$ | $3$ | $1$ | $3$ |
| ③ | $100$ | $3$ | $1$ | $3$ |

排序后顺序为 ①②③。贪心装填：①耗时 $3$ 恰好用满 $T$，得到 $100-3\times90=-170$，②③没时间了 → 答案 $-170$。而正确做法是**放弃①**，只做②③：$(100-3)+(100-6)=97+94=191$。全枚举校验：任何含①的合法子集只有 $\{①\}$（$-170$），不含①的有 $\varnothing(0)$、$\{②\}(97)$、$\{③\}(97)$、$\{②,③\}(191)$，最优 $191$ ✓。

> **失败模式归纳**：排序只解决"谁在前"，不解决"要不要"。要不要某件食材会占用容量 $c_i$，这正是背包决策；而且**一件食材的价值还取决于它排在第几个完成**（同一个 ①，独自完成是 $-170$，若前面还有别的会更差），所以价值不能事先写成常数——这是"带顺序依赖的背包"，不是普通背包。

### 2.5 经典解法：一次全局排序 + $0/1$ 背包

**引理 6（顺序可以事先固定）** 存在一个最优方案，其被选中的食材按键 $b_i/c_i$ 非增排列（$c_i>0$；键相等视为任意顺序）。

**证明**：取任意最优方案，把它按选中顺序写成序列。若序列中存在相邻一对"左边键 $<$ 右边键"（即一个逆序对 $(L,R)$，$\frac{b_L}{c_L}<\frac{b_R}{c_R}$），由引理 3 与引理 4，交换它们带来的总分改变量 $D=c_Rb_L-c_Lb_R<0$，即"$L$ 在前"比"$R$ 在前"差，于是交换后总分**不降**。且交换不改变总耗时 $\sum c_i$（只是换了顺序），可行性保持；不影响其它食材的完成时刻（引理 3 已证）。

重复此操作：每次交换使逆序对数严格减少 $1$（相邻交换最多消除这一对，其它逆序关系不变——这是冒排的标准结论），故至多 $\binom m2$ 步后终止，得到键非增的序列，其总分 $\ge$ 原最优方案，因此也是最优的。$\blacksquare$

**归约**：把 $n$ 件食材按键降序重排为 $1,2,\dots,n$（下文编号指排序后的位置）。由引理 6，只需决策"每个位置选还是不选"，一旦子集定了，顺序与每件食材的完成时刻就唯一确定：被选中的第 $k$ 件在"所选前缀 $c$ 之和"时刻完成。

**引理 7（DP 的正确性）** 定义 $\mathrm{dp}_k[j]\ (0\le j\le T)$ 为"只考虑排序后的前 $k$ 件、所选子集总耗时**恰好**为 $j$"的合法方案中的最大美味度；不可达记为 $-\infty$。则

$$\mathrm{dp}_0[0]=0,\quad \mathrm{dp}_0[j>0]=-\infty,$$
$$\mathrm{dp}_k[j]=\max\bigl(\mathrm{dp}_{k-1}[j],\ \mathrm{dp}_{k-1}[j-c_k]+a_k-j\,b_k\bigr),$$

且答案 $=\max_{0\le j\le T}\mathrm{dp}_n[j]$。

**证明**：对 $k$ 归纳。$k=0$ 时唯一方案是空集，耗时 $0$、得分 $0$，故 $\mathrm{dp}_0$ 如上。设结论对 $k-1$ 成立。考虑前 $k$ 件、总耗时恰为 $j$ 的任一合法子集 $S$，分两类：

- $k\notin S$：$S\subseteq\{1..k-1\}$ 且总耗时 $j$，按归纳假设其最好成绩是 $\mathrm{dp}_{k-1}[j]$。
- $k\in S$：按键降序 $k$ 是 $S$ 中排最后的一件（$k$ 是 $S$ 里下标最大的），因此 $k$ 的完成时刻恰为总耗时 $j$，其贡献为 $a_k-j b_k$；而 $S\setminus\{k\}$ 是前 $k-1$ 件、总耗时 $j-c_k$ 的子集，且在把 $k$ 追加到末尾时，**前面各件的完成时刻一个都没变**（它们的前缀和不含 $c_k$），所以这部分的最好成绩是 $\mathrm{dp}_{k-1}[j-c_k]$。反过来，任意一个 $\mathrm{dp}_{k-1}[j-c_k]$ 的方案追加 $k$ 都得到合法方案，故两个量可以互相取到。

两类取 $\max$ 即得递推式，$\mathrm{dp}_k$ 定义成立，归纳完成。最后，合法方案的要求是"总耗时 $\le T$"，而 $\mathrm{dp}_n[j]$ 只对恰好 $j$ 的最优，故全局最优是 $\max_{j\le T}\mathrm{dp}_n[j]$。$\blacksquare$

> **关键的一句**：转移里用的是 $j$（完成时刻）而不是 $j-c_k$（开始时刻）——这正是"末尾追加"视角带来的好处：$k$ 的完成时刻就是状态 $j$ 本身，不需要再算前缀。

**用例 F（与全排列暴力对标）**：$T=4$，三件食材 ①$(50,2,1)$、②$(50,6,2)$、③$(50,1,1)$，键分别 $2,3,1$，排序后顺序 $②,①,③$。

六种排列（全选，总耗时 $1+2+1=4\le T$）的总分：$(①,②,③)=48+32+46=126$；$(①,③,②)=48+48+26=122$；$(②,①,③)=38+44+46=\mathbf{128}$；$(②,③,①)=38+47+42=127$；$(③,①,②)=49+46+26=121$；$(③,②,①)=49+32+42=123$。排序序 $(②,①,③)$ 取得最大 $128$ ✓（引理 6 的方向没错）。

再手算 DP 逐层值（$-\infty$ 记作 $-$）：

- $k=0$：$[0,-,-,-,-]$
- 加入②$(a=50,b=6,c=2)$：$j=2$：$0+50-12=38$ → $[0,-,38,-,-]$
- 加入①$(50,2,1)$：$j=3$：$38+50-6=82$；$j=1$：$0+50-2=48$ → $[0,48,38,82,-]$
- 加入③$(50,1,1)$：$j=4$：$82+50-4=128$；$j=3$：$\max(82,38+50-3{=}85)=85$；$j=2$：$\max(38,48+50-2{=}96)=96$；$j=1$：$\max(48,0+50-1{=}49)=49$ → $[0,49,96,85,128]$

$\max=128$ ✓ 与暴力一致。子集最优也核对过：$\{①,③\}$ 在 $j=2$ 处 $96$、$\{②,①\}$ 在 $j=3$ 处 $82$（后被子集 $\{②,③\}$ 的 $85$ 取代），单件最大值 $49$（③ 独做），均 $\le128$。

**用例 D（$c_i>T$ 的边界）**：$T=2$，①$(5,1,3)$、②$(5,1,2)$。①的 $c=3>T$，内层循环 `j=T;j>=3` 一次都不执行，①自动被跳过；②在 $j=2$ 处 $5-2=3$ → 答案 $3$。

**用例 E（全负 $\to$ 空方案）**：$T=1$，①$(1,5,1)$：$\mathrm{dp}_1[1]=1-5=-4$，$\max(\mathrm{dp}[0]=0,-4)=0$，输出 $0$（一件都不做）。题面未强制"至少做一件"，本文按允许空方案处理；若判定要求非空，只需把 $\mathrm{dp}[0]=0$ 改成"不参与答案"（即答案从 $\mathrm{dp}[c_i]$ 层取）。

### 2.6 实现细节的三条引理与假设检查

**引理 8（倒序循环 $=$ 二维分层）** 用一维数组 $\mathrm{dp}[\cdot]$ 就地转移时，若内层 $j$ 从 $T$ **递减**到 $c_k$，则计算 $\mathrm{dp}[j]$ 时读到的 $\mathrm{dp}[j-c_k]$ 仍是第 $k-1$ 层的值，于是得到与引理 7 完全相同的结果。

**证明**：本层循环按 $j=T,T-1,\dots,c_k$ 的顺序写格子。对固定的 $k$，当处理到 $j$ 时，被写过的格子是 $j+1,j+2,\dots,T$；而读取的两个格子 $j$ 与 $j-c_k$ 都 $\le j$，其中 $j-c_k<j$ 尚未在本层被写（它要到之后才被访问），$j$ 本身此刻仍是上一层的值。故 $\mathrm{dp}[j]$（跳过分支）与 $\mathrm{dp}[j-c_k]$（选取分支）都来自第 $k-1$ 层，与二维写法一致。$\blacksquare$

**反例（为什么不能升序）**：$T=2$，只有一件食材 $(a=10,b=1,c=1)$，它只能用一次。升序写会得 $\mathrm{dp}[1]=0+10-1=9$，接着 $\mathrm{dp}[2]=\mathrm{dp}[1]+10-2=17$，等于把同一件食材做了两遍（真实答案应是 $\max(0,9)=9$，$\mathrm{dp}[2]$ 根本不可达）。升序对应完全背包，本题是 $0/1$。

**引理 9（空转无益，故状态只需"恰好 $j$"）** 若 $b_i\ge 0$，任何含有"故意等待"的方案都不比去掉等待的方案差。

**证明**：设方案中在某处空转了 $\delta>0$，把该空转之后的所有食材整体提前 $\delta$，则这些食材的完成时刻各减 $\delta$，总分变化 $=\delta\sum_{\text{被提前的 }i}b_i\ge0$；若其中有 $b_i>0$ 则严格变好。总耗时仍 $\le T$，可行性不变。$\blacksquare$

**推论（$-\infty$ 与 $0$ 初始化的关系）** 由引理 9，最优解一定在"恰好等于某个子集耗时和"的格子上取到，所以 $\mathrm{dp}$ 必须把不可达格记为 $-\infty$（`fill_n` 预置），否则"不可达 $+\,\mathrm{dp}[j-c]=0$ 当作已知值"会伪造状态。同时，把不可达格记为 $0$ **不会让答案变大**：由引理 9，从 $0$ 出发得到的每个值都对应"做了若干件再空转到 $j$"，其值 $\le$ 同一子集在不空转时的真实值，而真实值一定会在对应格子被取到；因此两种写法输出的 $\max$ 相同，但只有 $-\infty$ 写法让每个 $\mathrm{dp}[j]$ 具有"恰好用时 $j$"的真实含义（调试时更有用，也避免误用 $\mathrm{dp}[T]$）。

**用例 B（必须对 $j$ 取 $\max$）**：$T=10$，一件食材 $(100,5,1)$。真实答案 $\mathrm{dp}[1]=100-5=95$；$\mathrm{dp}[10]$ 在 $-\infty$ 写法下不可达（输出它会给出哨兵值），在 $0$ 初始化下是 $100-50=50$（空转版本）。两种都不等于 $95$，所以**必须** $\max_{0\le j\le T}$。

**引理 10（数值范围）** 在 $|a_i|,|b_i|,c_i,T<10^5$、$n\le50$ 下，

- 单项贡献 $a_i-j b_i\in(-10^{10},10^5)$；总分 $\mathrm{dp}$ 值 $\in(-5\times10^{11},\,5\times10^{6})$；
- 比较器乘积 $b_ic_j<10^{10}$。

两者都超出 $32$ 位（$\pm2.1\times10^9$），故 $\mathrm{dp}$ 用 `i64`、$a,b,c$ 存 `i64`、循环变量 $j$ 用 `i64`；哨兵取 $\approx-1.1\times10^{18}$，加上 $-10^{10}$ 量级的转移项仍远大于 `i64` 下界 $-9.2\times10^{18}$，不会回绕。

**假设依赖检查（题面没写死的部分）**

1. $c_i>0$：只用于把判据写成分数形式 $b_i/c_i$（引理 4）。代码用交叉相乘 $x.b\cdot y.c>y.b\cdot x.c$，$c_i=0$ 时也给出正确方向（$b_i>0$ 的零耗时食材键视为 $+\infty$，排最前，与引理 3 一致）。
2. $b_i\ge0$：用于引理 9（空转无益）与"$0$ 初始化不会高估"。若允许 $b_i<0$，则应当故意拖延，本题模型会退化成另一种问题；按题面与食材语义（"越晚越难吃"）默认 $b_i\ge0$。
3. 平局：引理 5 保证键相等时任意顺序等价，所以比较器的 `==` 分支怎么打破都不影响最优性，`std::sort` 的严格弱序要求也满足（$b/c$ 是实数键，$>$ 本身传递）。
4. 允许空方案：影响用例 E 的输出（$0$ vs 必做的最大值）。

## 3. 模式总结（Pattern Summary）

按真实思考顺序，一条一技巧，重复出现的步骤拆开列：

- **explore its property** — 把"$t$ 时刻完成"翻译成"前缀耗时和 $S_k$"，于是 $F=\sum a-\sum S_kb$，立刻看出"$a$ 管选择、$b$ 管顺序"（引理 1）。
- **consider easier version 1** — 强制全选，只剩顺序问题，才能安心用相邻交换（§2.2）。
- **classic problem solution：相邻交换论证** — 计算相邻两件的差 $D=c_jb_i-c_ib_j$，发现 $t_0$ 与 $a$ 全部抵消，这是"排序键与位置无关"的核心信号（引理 3）。
- **classic problem solution：交叉相乘比较** — 用 $b_ic_j$ 比 $b_jc_i$ 代替除法，避开浮点与 $c=0$（引理 4 的落地写法）。
- **consider easier version 2** — 令 $b\equiv0$，问题塌成裸 $0/1$ 背包，确认答案骨架是 $O(nT)$ 的时间维 DP（§2.3）。
- **dissect greedy failure（三次，各自独立）** — 按 $b$ 排错在用例 B1、按 $a$ 排错在引理 3 的 $D$ 里没有 $a$、"排序后贪心装填"错在取舍（用例 C 的 $-170$ vs $191$）。
- **necessary-and-sufficient flavor** — 不止说"贪心会错"，还用引理 5 给出"键相等时任意顺序等价"，即判据的完备一侧。
- **classic problem solution：交换论证升级为整体排序** — 逆序对相邻交换不降总分且减少逆序数，冒排终止 $\Rightarrow$ 存在按键降序的最优解（引理 6）。
- **reduce to easier problem** — 顺序被排序钉死后，本题退化为"按固定次序选子集"的 $0/1$ 背包，只是第 $k$ 件的价值从常数 $a_k$ 变成依赖状态的 $a_k-j b_k$（引理 7）。
- **classic problem solution：状态定义技巧** — 令状态 $j$ 就是"最后一件的完成时刻"，转移时直接写 $a_k-j b_k$，免去额外记录前缀和。
- **classic problem solution：二维压一维** — 倒序循环保证读的是上一层（引理 8），并用升序反例说明它与完全背包的区别。
- **boundary discipline：不可达 $-\infty$** — `fill_n` 预置哨兵而不是依赖全局数组的 $0$；再证明 $0$ 初始化为何"恰好也不影响最终 $\max$"（引理 9 空转无益）。
- **answer-scan-all-states** — 约束是"$\le T$"而非"$=T$"，答案必须扫 $\mathrm{dp}[0..T]$（用例 B）。
- **overflow defense** — $t b_i$ 与 $b_ic_j$ 都是 $10^{10}$ 量级，DP 值到 $-5\times10^{11}$，一律 `i64`，哨兵留足余量（引理 10）。
- **hand-brute-force validation** — 无官方样例时，用 $n\le3$ 的全排列/全子集枚举对标 DP 逐层值（用例 F）。

## 4. 真实解法

**符号表**

| 符号 | 含义 | 初始化 | 记忆提示 |
|---|---|---|---|
| `T` | 允许的总耗时上界（`i64`，$<10^5$） | 读入 | Time |
| `n` | 食材件数（`int`，$\le50$） | 读入 | number |
| `s[i].a` | 第 $i$ 件（排序后）的基础美味度 | 读入第 1 行 | additive |
| `s[i].b` | 第 $i$ 件的单位时间衰减率 | 读入第 2 行 | burn |
| `s[i].c` | 第 $i$ 件的耗时 | 读入第 3 行 | cost |
| 键 $b_i/c_i$ | 排序依据，降序；代码里用 $x.b\cdot y.c>y.b\cdot x.c$ 判定 | `sort` 时 | "衰减率" |
| `dp[j]` | 只考虑已处理前缀、所选子集**总耗时恰好** $j$ 时的最大美味度 | `fill_n(dp,T+1,ninf)`，`dp[0]=0` | "用掉 $j$ 时间能到多好" |
| `ninf` | 不可达标记 $\approx-1.1\times10^{18}$ | constexpr | 负无穷 |
| `ans` | $\max_{0\le j\le T}\mathrm{dp}[j]$ | $0$（允许空方案） | answer |

**步骤**

1. 按输入格式分三行读入 $a$、$b$、$c$ 三个数组，装入 `s[0..n-1]`（$0$-based）。
2. 以 `[](const node&x,const node&y){return x.b*y.c>y.b*x.c;}` 排序 —— 键 $b/c$ 降序（引理 3、4、6）。乘法两侧是 `i64`，因为积可达 $10^{10}$。
3. `fill_n(dp,T+1,ninf); dp[0]=0;` —— 不可达必须显式置哨兵（引理 9），长度只到 $T$，$T<10^5$ 在 `mxT` 之内。
4. 对每件食材 $i$（已按序），内层 `for(i64 j=T;j>=s[i].c;--j)`：**倒序**保证读到的 `dp[j-c]` 属于上一层（引理 8）。
5. 转移前判 `dp[j-s[i].c]!=ninf`，不可达则跳过，避免"哨兵 $+$ 负贡献"污染；可达时 `dp[j]=max(dp[j], dp[j-c]+a-i*b)`，其中 $j$ 是 $i$ 的完成时刻（引理 7 的"末尾追加"）。
6. 全部处理完后扫一遍 `dp[0..T]` 取最大值到 `ans`（约束是 $\le T$，不是 $=T$）。
7. 输出 `ans`。

**复杂度**：排序 $O(n\log n)$，DP $O(nT)\le50\times10^5=5\times10^6$ 次常数次运算，空间 $O(T+55)$（`dp` 约 $800\,\mathrm{KB}$）。$40\%$ 的 $n\le10$ 部分是同一套代码的子集，不需要单独分支。

## 5. 示例代码

```cpp
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{55},mxT{100005};
constexpr i64 ninf{-1145141919314LL*1000000};	// 约 -1.1e18，远小于任何真实答案

struct node
{
	i64 a,b,c;
}s[mxn];
i64 dp[mxT];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	i64 T;
	int n;
	cin>>T>>n;
	for(int i=0;i<n;++i)
		cin>>s[i].a;
	for(int i=0;i<n;++i)
		cin>>s[i].b;
	for(int i=0;i<n;++i)
		cin>>s[i].c;
	//b/c 降序：x 排在 y 前 <=> x.b*y.c > y.b*x.c
	sort(s,s+n,[](const node&x,const node&y)
	{
		return x.b*y.c>y.b*x.c;
	});
	fill_n(dp,T+1,ninf);
	dp[0]=0;
	for(int i=0;i<n;++i)
	{
		for(i64 j=T;j>=s[i].c;--j)
			if(dp[j-s[i].c]!=ninf)
				dp[j]=max(dp[j],dp[j-s[i].c]+s[i].a-j*s[i].b);
	}
	i64 ans=0;
	for(i64 j=0;j<=T;++j)
		ans=max(ans,dp[j]);
	// cerr<<ans<<'\n';
	cout<<ans<<'\n';
	return 0;
}
```

**风格对照说明**：`#include<bits/stdc++.h>`、`using i64=long long;`、全局静态数组、`constexpr int mxn{55},mxT{100005};`（$+$ 松弛）、Tab 缩进、运算符两侧无空格、`'\n'` 不用 `endl`、`cin.tie(nullptr);cout.tie(nullptr);ios::sync_with_stdio(false);` 固定顺序、内部 $0$-based、保留注释掉的 `cerr` 调试行，均符合风格指南。`INF` 型数组（这里是负无穷哨兵 `dp`）按要求用 `fill_n` 预置，未依赖全局数组的默认 $0$。本题没有图，故链式前向星与 `E[i^1]` 反边技巧无处可用（同库网络流/二分图模板不适用）。

**三个典型错写法（对照本代码）**

1. `for(i64 j=s[i].c;j<=T;++j)` 升序：变成完全背包，同一件食材可重复使用（§2.6 反例）。
2. `dp[j]=max(dp[j],dp[j-c]+a-(j-c)*b)`：把"开始时刻"当成了 $t$，整体偏大 $\sum c_ib_i$（陷阱 1）。
3. `sort` 用 `x.a>y.a` 或 `x.b>y.b`：见用例 B1、B2，直接给错顺序；比较器里写 `1e10` 量级的乘积若用 `int` 还会溢出成错序。
4. `fill_n(dp,mxT,ninf)` 后仍对 `j` 扫到 `mxT-1`：会把哨兵当成候选值参与 $\max$；本代码只在 $[0,T]$ 内扫，且 `ans` 初值 $0$ 保证不被哨兵拉低。
