# P1949 [NOI2001] 聪明的打字员

## 1. 重新读题

### 1.1 问题重述（人话版）

录入区固定有 $6$ 个位置（从左到右编号 $1\sim6$），每个位置上是一个数字 $0\sim9$，另外有一个**光标**，初始时一定在第 $1$ 个位置。允许六种操作，每按一次算一次击键：

| 键 | 作用 |
| :--- | :--- |
| `swap0` | 把光标处的数字与位置 $1$ 的数字交换；光标在位置 $1$ 时不变 |
| `swap1` | 把光标处的数字与位置 $6$ 的数字交换；光标在位置 $6$ 时不变 |
| `up` | 光标处数字 $+1$；若已是 $9$ 则不变 |
| `down` | 光标处数字 $-1$；若已是 $0$ 则不变 |
| `left` | 光标左移一格；已在位置 $1$ 则不动 |
| `right` | 光标右移一格；已在位置 $6$ 则不动 |

给定初始串和目标串（都是长度 $6$），求从初始串（光标在位置 $1$）变成目标串（**光标位置不限**）的最少击键次数。

### 1.2 关键约束与规模暗示

- 长度固定为 $6$，每位 $10$ 种取值，光标 $6$ 个位置。
- 操作全部是「一步改变一个局部」的等代价操作，没有权重。
- 位数固定且很小，状态空间是可枚举的：大约 $10^6\times6=6\times10^6$ 个状态。
- 这类「等代价、可逆、状态有限」的最短操作序列问题，标准工具就是 **BFS（状态空间最短路）**。

---

## 2. 思维链（Chain-of-thought）

### 2.1 第一步：到底什么是「状态」

一个自然的想法：状态就是「当前录入区的 $6$ 个数字」。但马上会发现它不够：

- 同一个数字串，光标在位置 $1$ 和在位置 $4$，按 `up` 改的是不同的位、按 `left/right` 能去的方向也不同。
- 所以历史信息里唯一**会影响未来**的，就是「当前 6 个数字 + 光标位置」。

**引理 1（状态充分性）**：设当前录入区为 $d=(d_1,\dots,d_6)$、光标在 $c$。则以后每种按键序列的效果（以及是否合法地改变状态），只由 $(d,c)$ 决定，与之前怎么到达的无关。

**证明**：六个操作的定义都是「读取 $(d,c)$，输出新的 $(d',c')$」的纯函数：

- `swap0`/`swap1` 只依赖 $d_1,d_c$（或 $d_6,d_c$）与 $c$；
- `up`/`down` 只依赖 $d_c$；
- `left`/`right` 只依赖 $c$。

没有任何操作读取「历史」。因此对任意按键串，从相同 $(d,c)$ 出发得到相同轨迹。这正是 BFS 所需要的马尔可夫性。$\square$

**引理 2（必要性）**：$(d,c)$ 中两部分缺一不可；任何更粗的划分都会把「可用操作集合不同」的状态混在一起，从而无法正确求出最短步数。

**证明**：

- 只看数字串 $d$（丢掉光标）：状态 $(d,1)$ 与 $(d,6)$ 会被合并。但在 $(d,1)$ 上按 `right` 会把光标移到 $2$（状态改变），在 $(d,6)$ 上按 `right` 却什么也不发生。同一个合并状态出现了不同的后继集合，合并会丢失信息。
- 只看光标（丢掉数字）：显然 `up`/`down`/`swap` 的结果都依赖具体数字。

因此 $(d,c)$ 是最细的必要信息。$\square$

初始状态是 $(s,1)$；目标集合是所有满足 $d=t$ 的状态 $(t,c)$，$c$ 任意。

### 2.2 第二步：状态编码与去重

**引理 3（编码单射）**：令

$$
\mathrm{code}(d)=\sum_{i=1}^{6}d_i\cdot10^{\,6-i}\in[0,10^6),
$$

再令状态编号

$$
\mathrm{id}(d,c)=6\cdot\mathrm{code}(d)+c\in[0,\,6\times10^6).
$$

则 $\mathrm{id}$ 是单射；由 `code=id/6, c=id%6` 可以唯一还原状态。

**证明**：`code` 就是六位十进制数，与数字串一一对应（前导零也算数位，长度固定为 6）。$\mathrm{id}$ 是把 $(code,c)\in[0,10^6)\times[0,6)$ 按「$code$ 为高位、$c$ 为低位」打包，打包与解包互逆（整数除法与取余），故单射。$\square$

有了单射，就能用一个长度为 $6\times10^6$ 的 `dis` 数组做「访问标记 + 距离」，**不需要哈希表**，也不会把不同状态误判为同一个。

### 2.3 第三步：BFS 为什么给出最少击键数

把每个状态看成点，一次按键看成一条**权为 1** 的有向边。问题就是：从初始点出发，到目标集合的最短路长度。

**引理 4（BFS 正确性）**：在边权全为 1 的图上，BFS 第 $k$ 层恰好是「距离为 $k$」的所有点；因此某个点第一次被访问时的层数就是它的最短路长度。

**证明**（对层数归纳）：

- 第 $0$ 层只有起点，距离 $0$，成立。
- 设第 $0..k$ 层都正确。任何距离 $k+1$ 的点 $v$ 存在一条长度 $k+1$ 的最短路，其前驱 $u$ 距离为 $k$；$u$ 在第 $k$ 层，扩展时会把 $v$ 放入第 $k+1$ 层，故 $v$ 层数 $\le k+1$。另一方面，若 $v$ 在第 $\le k$ 层，则它已被更短的路径到达，矛盾于距离为 $k+1$。所以 $v$ 恰在第 $k+1$ 层。

另外每个点第一次被记录时一定处于最小层：BFS 按层扩展，先到的一定不大于后到的。$\square$

由于目标集合是「所有数字串等于 $t$ 的状态」，BFS **第一次弹出**数字串等于 $t$ 的状态时，它的距离就是答案（同层内哪个光标先弹出都一样，距离相同）。

### 2.4 第四步：无意义操作可以安全删掉

有些按键在当前状态是「空操作」：`up` 遇到 $9$、`down` 遇到 $0$、`left` 在位置 $1$、`right` 在位置 $6$、`swap0` 在位置 $1$、`swap1` 在位置 $6$。它们不改变状态，只会让步数 $+1$。

**引理 5（最短序列不含空操作）**：任何最优（最短）击键序列中都不会出现上述空操作。

**证明**：反设某最短序列第 $j$ 步是空操作。删掉这一步，剩下的序列仍然合法（因为每一步的合法性只依赖当时的状态，而空操作不改变状态，后续步骤的前提完全不变），并且仍从初始状态到达目标状态，但长度少了 $1$，与「最短」矛盾。$\square$

因此实现时可以直接不生成这些自环边。这既省时间，又不影响答案（BFS 本来也不会靠自环变短，但省掉能减小常数）。

### 2.5 第五步：状态空间与距离上界（为什么 `short` 够用）

**引理 6（距离上界）**：任意初始串到任意目标串，答案不超过 $59$。

**证明**：构造一个不用交换键的合法方案：光标初始在位置 $1$。对 $i=1,\dots,6$：此时光标在位置 $i$，用 `up`/`down` 把第 $i$ 位调到目标值（最多 $9$ 次）；然后（除最后一位外）按一次 `right`。总击键数 $\le 6\times9+5=59$。这是个可行方案，所以最短距离 $\le59$。$\square$

于是 `dis` 可以用 16 位有符号整数 `short`（$-1$ 表示未访问，距离 $\le59$），内存 $12$ MB；队列存状态编号，`int`，最多 $6\times10^6$ 个，$24$ MB。总内存约 $36$ MB。

### 2.6 第六步：复杂度

状态数 $S=6\times10^6$，每个状态最多 $6$ 条出边。BFS 时间 $O(6S)=O(3.6\times10^7)$，空间 $O(S)$。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 状态必须是「6 位数字 + 光标」；操作是纯函数，故状态充分（马尔可夫性）。
- **consider easier version** — 只看数字串不够（光标影响操作），反向确认光标必须在状态里。
- **classic problem solution** — 等权图最短路 = BFS；层数即击键数。
- **reduce to easier problem** — 用进制打包把状态压成整数，用数组而不是哈希去重。
- **explore its property** — 空操作可删（否则可构造更短序列），距离上界 $59$ 允许 `short` 存距离。
- **classic problem solution** — 目标是一个集合（光标任意），第一次弹出目标数字串即为答案。

## 4. 真实解法（The Real Solution）

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 |
| :--- | :--- | :--- | :--- | :--- |
| `a,b` | `string` | 初始串、目标串 | 读入 | 六位数字 |
| `s,t` | `int` | 初始/目标数字串的十进制编码 | 读入转换 | code |
| `w[6]` | `int [6]` | `w[i]=10^(5-i)`，第 $i$ 位的权 | 常量 | weight |
| `dis[id]` | `short [6000005]` | 到状态 `id` 的最少击键数，$-1$ 未访问 | $-1$ | distance |
| `Q[]` | `int [6000005]` | BFS 队列，存状态编号 | 空 | queue |
| `head,tail` | `int` | 队尾（下一个写入）、队头 | $0$ | 队列指针 |
| `code` | `int` | 当前状态的数字串编码 | 出队时算 | $u/6$ |
| `cur` | `int` | 当前光标位置（0-based） | 出队时算 | $u\%6$ |
| `d` | `int` | 光标处的数字 | 出队时算 | digit |

### 4.2 算法步骤

1. 读入两个六位串，转成整数 $s,t$（按十进制拼接，前导零自动保留在数值里，因为固定读 6 位）。
2. `memset(dis,-1,sizeof(dis))`；起点状态 `st=s*6+0`（光标在位置 $1$，0-based 的 $0$）；`dis[st]=0`，入队。
3. 当队列非空：
   1. 弹出 $u$，解包 `code=u/6, cur=u%6`。
   2. 若 `code==t`，输出 `dis[u]` 并结束（第一次弹出即最优）。
   3. 取 `d=(code/w[cur])%10`，依次尝试六种不产生自环的操作，新状态为 `nc*6+cur`（数字变化）或 `code*6+cur±1`（光标移动）：
      - `up`：`d<9` 时 `nc=code+w[cur]`；
      - `down`：`d>0` 时 `nc=code-w[cur]`；
      - `left`：`cur>0` 时编号减 $1$；
      - `right`：`cur<5` 时编号加 $1$；
      - `swap0`：`cur!=0` 时 `nc=code+(d0-d)*w[cur]+(d-d0)*w[0]`；
      - `swap1`：`cur!=5` 时 `nc=code+(d5-d)*w[cur]+(d-d5)*w[5]`。
   4. 若新状态未访问，置 `dis=dis[u]+1` 并入队。
4. （理论上不会走到）若队列空还没到达，说明状态图不连通；本题一定可达，程序在到达时已返回。

### 4.3 复杂度

- 时间：$O(6\times 10^6\times6)=O(3.6\times10^7)$。
- 空间：`short dis` $12$ MB + `int Q` $24$ MB $\approx36$ MB。

## 5. 示例代码

```cpp
//
// 题目：P1949 [NOI2001] 聪明的打字员
// https://www.luogu.com.cn/problem/P1949
#include<bits/stdc++.h>
using namespace std;

constexpr int mxstate{6000005};

short dis[mxstate];		// -1 未访问，距离 <=59
int Q[mxstate];
int w[6]={100000,10000,1000,100,10,1};

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	string a,b;
	cin>>a>>b;
	int s{0},t{0};
	for(int i=0;i<6;++i)
	{
		s=s*10+(a[i]-'0');
		t=t*10+(b[i]-'0');
	}

	memset(dis,-1,sizeof(dis));
	int head{0},tail{0};
	int st=s*6;		// 光标固定在 1 号位（0-based 0）
	dis[st]=0;
	Q[head++]=st;
	while(tail<head)
	{
		int u=Q[tail++];
		int code=u/6,cur=u%6;
		if(code==t)		// 第一次弹出目标数字串即最优，光标不限
		{
			cout<<dis[u]<<'\n';
			return 0;
		}
		int d=(code/w[cur])%10;
		auto relax=[&](int nc)	// 数字串改变，光标不动
		{
			int v=nc*6+cur;
			if(dis[v]<0)
			{
				dis[v]=dis[u]+1;
				Q[head++]=v;
			}
		};
		if(d<9)
			relax(code+w[cur]);
		if(d>0)
			relax(code-w[cur]);
		if(cur>0)	// left
		{
			int v=code*6+cur-1;
			if(dis[v]<0)
			{
				dis[v]=dis[u]+1;
				Q[head++]=v;
			}
		}
		if(cur<5)	// right
		{
			int v=code*6+cur+1;
			if(dis[v]<0)
			{
				dis[v]=dis[u]+1;
				Q[head++]=v;
			}
		}
		if(cur!=0)	// swap0
		{
			int d0=(code/w[0])%10;
			relax(code+(d0-d)*w[cur]+(d-d0)*w[0]);
		}
		if(cur!=5)	// swap1
		{
			int d5=(code/w[5])%10;
			relax(code+(d5-d)*w[cur]+(d-d5)*w[5]);
		}
	}
	return 0;
}
```
