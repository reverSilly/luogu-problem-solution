# P1618 三连击（升级版）

## Part 1 — 题目理解 (Problem Comprehension)

### 题意简述

把 $1,2,\dots,9$ 这九个数字各用一次，拼成三个三位数 $x,y,z$，要求 $x:y:z=A:B:C$。输出所有满足条件的三元组，每行一个，按 $x$ 升序；无解则输出 `No!!!`。

### 输入输出格式

- **输入格式**：一行三个整数 $A,B,C$。
- **输出格式**：若干行，每行三个整数，按每行第一个数升序；若无解输出 `No!!!`。
- **数据规模**：$0\le A<B<C\le999$。

### 关键约束分析

1. 三个数都是三位数且九个数字互不相同、均非零——这等价于"$x,y,z\in[100,999]$ 且九个数字恰好是 $1..9$"。
2. 暴力枚举三个三位数是 $900^3\approx7.3\times10^8$，再乘上判重开销必然超时；必须利用比例关系把自由度压到一维。
3. $A$ 可以等于 $0$，此时第一个数按比例只能是 $0$，不可能是三位数，答案必然无解；同时要避免"除以 $0$"。
4. 比例可能不互质（如 $2:4:6$），**必须先约分**，否则会漏掉不以 $A$ 为步长的那批解。
5. 输出顺序：按 $x$ 升序。若枚举量本身按 $x$ 递增，就不需要排序。

## Part 2 — 思路推导 (Idea Discovery)

### 第一步：暴力枚举的三个变量太多

最直接的想法是三重循环枚举 $x,y,z\in[100,999]$，再检查九个数字。状态数 $900^3$ 太大。

注意到三个数并不独立：比例给定后，只要确定其中一个，另外两个就被"钉死"了。于是问题从"枚举三个数"变成"枚举一个参数"。

### 第二步：把比例写成整数参数

设 $x:y:z=A:B:C$，即存在正有理数 $\lambda$ 使 $x=\lambda A,\ y=\lambda B,\ z=\lambda C$。

**引理 1（比例的三数参数化）**：设 $A,B,C$ 为正整数，$g=\gcd(A,B,C)$，$A'=A/g,\ B'=B/g,\ C'=C/g$。若正整数 $x,y,z$ 满足 $x:y:z=A:B:C$，则存在正整数 $k$ 使
$$x=kA',\qquad y=kB',\qquad z=kC'.$$

*证明*：由比例存在正有理数 $\lambda=x/A=y/B=z/C$。把 $\lambda$ 写成最简分数 $u/v$（$u,v$ 互质，$v>0$），则 $x=uA/v$ 是整数，故 $v\mid A$（因 $\gcd(u,v)=1$）；同理 $v\mid B$、$v\mid C$，于是 $v$ 是 $A,B,C$ 的公因数，$v\mid g$。取 $k=u\cdot(g/v)$，则 $k$ 为正整数，且
$$kA'=u\frac{g}{v}\cdot\frac{A}{g}=\frac{uA}{v}=x,$$
对 $y,z$ 同理。$\square$

引理 1 说明：**枚举 $k$ 就够了**，而且步长必须用约分后的 $A',B',C'$。举个真实的例子：$A:B:C=2:4:6$ 约分后是 $1:2:3$，解 $219,438,657$ 中 $x=219$ 不是 $2$ 的倍数——若直接用 $x=kA$ 枚举就会漏掉它。

### 第三步：$k$ 枚举到哪

**引理 2（$k$ 的上界）**：$k$ 的取值范围恰为 $1\le k\le\lfloor999/C'\rfloor$。

*证明*：约分不改变大小关系，故 $A'<B'<C'$，$C'$ 最大。必要性：$z=kC'\le999$ 给出 $k\le\lfloor999/C'\rfloor$。充分性：任取该范围内的 $k$，$z=kC'\le999$ 且 $y=kB'<kC'\le999$、$x=kA'<999$；再配合第四步的数字检查即可筛出合法解。$\square$

### 第四步：九个数位的判定

**引理 3（数位判定的等价形式）**：三个数 $x,y,z$ 恰好把 $1..9$ 各用一次，当且仅当 $x,y,z\in[100,999]$ 且九个数字中没有 $0$、没有重复。

*证明*：必要性：三位数保证九个数位存在；用到的数字都在 $1..9$ 内且互不相同，共九个，故恰为 $1..9$ 的一个排列。充分性：九个数字互不相同且都取自 $1..9$ 这九个值，由抽屉原理正好把 $1..9$ 取遍一次。$\square$

实现上用一个 `vis[10]` 布尔数组：拆每个数的三位，遇到 $0$ 或已标记的数字立即判假，否则标记。三个数都拆完，`vis[1..9]` 全为真。

### 第五步：$A=0$ 与输出顺序

**引理 4（$A=0$ 时无解）**：若 $A=0$，则不存在合法三元组。

*证明*：$x:y:z=0:B:C$ 迫使 $x\cdot B=y\cdot0=0$，而 $B>0$，故 $x=0$。但合法三元组的每个数都在 $[100,999]$，矛盾。$\square$

**引理 5（输出天然有序）**：按 $k$ 递增枚举时，$x=kA'$ 严格递增，故输出顺序已满足"按第一个数升序"。

*证明*：$A'\ge1$，故 $k_1<k_2$ 时 $x_1=k_1A'<k_2A'=x_2$。$\square$

## Part 3 — 模式总结 (Pattern Summary)

- `explore its property` — 三个数由比例锁定，自由度只有一维。
- `reduce to easier problem` — 把"比例"条件换成整数参数 $k$，枚举对象从三元组降为单个整数。
- `classic problem solution` — 辗转相除求出 $\gcd(A,B,C)$ 并约分，得到正确步长。
- `explore its property` — 九个数字恰为 $1..9$ 的排列，可用"非零且互异"的布尔数组一次性判定。
- `discuss by category` — 单独处理 $A=0$ 与"无解"两种情形。
- `defer reconstruction` — 不排序，让枚举顺序直接等于输出顺序。

## Part 4 — 真正的解法 (The Real Solution)

### 符号表 (Notation Glossary)

| 数学符号 | 代码变量 | 含义说明 |
| :--- | :--- | :--- |
| $A,B,C$ | `A`,`B`,`C` | 读入的比例，读入后原地除以 $g$ 变成 $A',B',C'$ |
| $g$ | `g` | $\gcd(A,B,C)$，用 `__gcd` 两次求得 |
| $k$ | `k` | 比例参数，从 $1$ 枚举到 $\lfloor999/C\rfloor$ |
| $x,y,z$ | `x`,`y`,`z` | 候选三元组，$x=kA,\ y=kB,\ z=kC$（约分后的 $A,B,C$） |
| 数位标记 | `vis[10]` | `vis[d]=true` 表示数字 $d$ 已被用过，每次判定前清零 |
| 单数判定 | `ok(x)` | 把 $x$ 逐位拆开打标记，返回是否出现 $0$ 或重复 |
| 三数判定 | `chk(x,y,z)` | 先查三个数是否都在 $[100,999]$，再依次调用 `ok()` |
| 有无解标志 | `found` | 初值 `false`，每输出一行置 `true`，用于最后决定是否打印 `No!!!` |

### 算法步骤

1. 读入 $A,B,C$。若 $A=0$，直接输出 `No!!!` 并结束（引理 4）。
2. 计算 $g=\gcd(\gcd(A,B),C)$，令 $A\gets A/g,\ B\gets B/g,\ C\gets C/g$。
3. 令 $k$ 从 $1$ 递增到 $\lfloor999/C\rfloor$，每次算出 $x=kA,\ y=kB,\ z=kC$。
4. 调用 `chk(x,y,z)`：区间检查 + 数位检查（引理 3）。通过则输出一行并把 `found` 置真。
5. 循环结束后若 `found` 仍为假，输出 `No!!!`。

### 复杂度分析

- **时间复杂度**：$\mathcal{O}(999/C'\times 9)$，最坏（$A'=1$）约 $999$ 次迭代、每次常数次取位，总计万级运算。
- **空间复杂度**：$\mathcal{O}(1)$，只有一个长度 $10$ 的布尔数组。

### 正确性验证

引理 1 与引理 2 保证枚举范围既不漏（每个合法解都对应某个 $k$）也不越界（超出范围的 $k$ 不可能满足 $z\le999$）；引理 3 保证数位判定与题意等价；引理 5 保证输出顺序正确；引理 4 保证 $A=0$ 时不会误判或除零。四者合起来即得正确性。全部运算都在 `int` 范围内（最大 $999\times999<10^6$）。

## Part 5 — 示例代码 (Example Code)

```cpp
//
// 题目：P1618 三连击（升级版）
// https://www.luogu.com.cn/problem/P1618
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;

int A,B,C;
bool vis[10];

bool ok(int x)                     // 拆出三个数字，要求恰好用完 1..9 各一次
{
	while(x)
	{
		int d=x%10;
		if(d==0||vis[d])
			return false;
		vis[d]=true;
		x/=10;
	}
	return true;
}

bool chk(int x,int y,int z)
{
	if(x<100||y<100||z<100||x>999||y>999||z>999)
		return false;
	memset(vis,0,sizeof vis);
	return ok(x)&&ok(y)&&ok(z);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>A>>B>>C;
	if(A==0)                       // 比例含 0 时第一个数必为 0，不可能是三位数
	{
		cout<<"No!!!"<<'\n';
		return 0;
	}
	int g=__gcd(__gcd(A,B),C);     // 约分，否则 2:4:6 这类比例会漏解
	A/=g;B/=g;C/=g;
	bool found=false;
	for(int k=1;k*C<=999;++k)
	{
		int x=k*A,y=k*B,z=k*C;
		if(chk(x,y,z))
		{
			cout<<x<<' '<<y<<' '<<z<<'\n';
			found=true;
		}
	}
	if(!found)
		cout<<"No!!!"<<'\n';
	return 0;
}
```

### 易错点

1. **不约分**：直接以 $A,B,C$ 为步长枚举，遇 $2:4:6$ 这类比例会漏掉一半以上的解。
2. **$A=0$ 未特判**：会除以 $0$ 或输出错误的 `No!!!`（虽然答案也是 `No!!!`，但程序会崩）。
3. **`No!!!` 的感叹号个数**：是三个 `!`，且不是 `No`。
4. **`vis` 忘记清零**：每判定一个三元组前必须 `memset`。
5. **区间检查**：约分后 $x=kA$ 在 $k$ 较小时可能只有两位数（如 $A'=1,k=5$），必须显式要求 $\ge100$。
6. **输出分隔符**：三个数之间是空格，不是逗号。
