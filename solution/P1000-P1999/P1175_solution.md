# P1175 表达式的转换 题解

## 1. 重新读题（问题重述）

输入一行中缀表达式，长度不超过 $100$。表达式中只有以下字符：

- 数字 `0` ~ `9`（保证每一位数字都是一位的，即不存在多位数）；
- 二元运算符 `+`、`-`、`*`、`/`、`^`；
- 括号 `(`、`)`。

保证：

- 不会出现负数及类似 `2*-3` 的格式（即 `-` 只作为二元运算符出现）；
- 不会出现乘方时幂次为负数的情况；
- 运算的中间结果和最终结果绝对值不超过 $2^{31}$；
- `^` 为乘方运算，**从右向左结合**；其余运算符**从左向右结合**。运算优先级：`^` 最高，`*`、`/` 次之，`+`、`-` 最低。
- `/` 为整除运算（对正数而言就是直接截断小数部分）。

要求：将中缀表达式转换为后缀表达式，并模拟整个计算过程。输出若干行：

- 第 $1$ 行：完整的后缀表达式；
- 之后每一行：某一步二元运算完成后的状态；
- 最后一行只含一个数字，即最终结果。

因此总行数 $=$ 运算符个数 $+1$。输出的每一行中，所有数据（数字和运算符）之间用**一个空格**分隔。

## 2. 思维链（发现过程与完整证明）

### 2.1 问题本质：这是两道经典题的组合

1. **中缀表达式 → 后缀表达式**（逆波兰式 RPN）的转换；
2. 对后缀表达式进行**逐步求值**，并且要输出每一步的中间状态。

第一问直接用经典的**调度场算法**即可；第二问只需要在 RPN 求值的每一步输出"已求值部分 + 未处理部分"。

### 2.2 调度场算法（Shunting-yard）做了什么

用两个结构：

- `post`：输出序列，存放后缀表达式的 token；
- `ops`：运算符栈。

从左到右扫描中缀表达式，对每个字符 $c$：

1. **数字**：直接放入 `post`。
2. **``(` ``**：压入 `ops`。
3. **`)`**：反复把 `ops` 栈顶弹出放入 `post`，直到弹出的是 `(`，将 `(` 丢弃。
4. **运算符**：当 `ops` 非空、栈顶不是 `(`，并且满足
   $$ \mathrm{prec}(\mathrm{top})>\mathrm{prec}(c) \quad\text{或}\quad \big(\mathrm{prec}(\mathrm{top})=\mathrm{prec}(c)\ \text{且}\ c\ \text{是左结合}\big) $$
   时，弹出栈顶放入 `post`；最后把 $c$ 压入 `ops$。

扫描结束后，把 `ops` 中剩余的运算符全部弹出放入 `post`。

优先级表：

| 运算符 | 优先级 | 结合性 |
| ------ | ------ | ------ |
| `^` | 3 | 右结合 |
| `*` `/` | 2 | 左结合 |
| `+` `-` | 1 | 左结合 |

### 2.3 为什么 `^` 要特殊处理（右结合）

考虑 `2 ^ 3 ^ 2`，题目要求它是右结合的，即 $2^{3^2} = 2^9 = 512$，对应后缀式 `2 3 2 ^ ^`。

如果 `^` 也按左结合处理，遇到第二个 `^` 时会把栈里的第一个 `^` 弹出，得到后缀式 `2 3 ^ 2 ^`，也就是 $(2^3)^2 = 8^2 = 64$，**结果错误**。

所以对右结合的 `^`，遇到**同优先级**的运算时不能弹出栈顶（必须让先入栈的 `^` 后输出）。这就是算法第 4 步中加"且 $c$ 是左结合"的原因。

### 2.4 逐步求值

得到后缀表达式后，用它模拟一遍求值：

- 用一个**值栈** `val`；
- 从左到右扫描后缀 token：
  - 数字 → 压入 `val`；
  - 运算符 → 弹出栈顶两个数 $b, a$，计算 $a \ \mathrm{op}\ b$，结果压回 `val`，**然后输出一行**：`val` 从底到顶的内容 + 位置在 $i$ 之后的所有尚未处理的后缀 token。

> 注意：对 `/` 用整除，对 `^` 用乘方。所有中间结果在题目保证下不会超过 $2^{31}$，但建议直接用 `long long` 存储以防万一。

### 2.5 完整证明

**引理 1（后缀表达式求值等价于中缀求值）**：设一棵表达式树的后序遍历为 $T$，则对 $T$ 使用标准 RPN 求值（数字入栈，运算符弹出两个操作数、计算、压回）得到的栈顶结果等于该表达式树代表的运算结果。

*证明*：对表达式树的高度做归纳。
- 高度为 $0$：叶子是数字，直接入栈，栈顶就是该数字本身，结论成立。
- 归纳步：设内部节点 $u$ 的左右子树后序遍历分别为 $L,R$，由归纳假设，依次求值 $L$ 与 $R$ 后，栈顶为 $\mathrm{val}(R)$，其下为 $\mathrm{val}(L)$。遇到运算符 `op` 时弹出并计算 $\mathrm{val}(L)\ \mathrm{op}\ \mathrm{val}(R)$，这正是 $u$ 的值，压回栈顶，结论成立。

> 注：这个引理与后续引理 2 结合，保证最终结果正确；同时它也保证了求值过程中每一步"弹出两个数"都是合法的（RPN 的良定义性）。

**引理 2（调度场算法的输出是表达式树的后序遍历）**：调度场算法输出的 `post` 序列就是中缀表达式对应表达式树的后序遍历序列。

*证明思路（归纳于表达式树的结构）*：

- 数字按原顺序出现，对应叶子在左、中、右遍历中的同一位置。
- 考虑任意一个子树 $S$，其左边界以 `(` 或表达式开头为标志，右边界以 `)` 或更低优先级运算符为标志。扫描进入 $S$ 之后，$S$ 内部的运算符会先按递归规则处理（括号内同样处理），只有等到 $S$ 完全扫描完毕（遇到 `$\verb|)|$`）或者遇到一个优先级更低/同级的运算符时，$S$ 的根运算符才会被弹出。因此 $S$ 的根运算符必然排在 $S$ 左右子树所有 token **之后**输出。
- 这说明每个节点都在其子树之后输出，即输出是"左右根"的后序顺序，也就是后序遍历。

**引理 3（每一步输出即"部分求值后的后缀状态"）**：设值栈 `val` 从底到顶为 $v_0,\dots,v_k$，尚未处理的 token 从 $i$ 向后为 $p_i,\dots,p_{n-1}$，则任何时刻的完整表达式状态为
$$ v_0 \ v_1 \ \cdots \ v_k \ \ p_i \ \cdots \ p_{n-1} $$
每完成一次归约（一个运算符的处理），操作数个数减 $1$、运算符个数减 $1$。

*证明*：这是 RPN 语义的直接推论——值栈就是"已经用过的数/结果"，未处理部分是"还剩下的运算符和被 初始 token 顺序压入的数"。归约一次就把三个 token（两个操作数、一个运算符）合并为一个数字，故操作数与运算符各减少一个。

## 3. 模式总结（可复用的套路）

```text
中缀 -> 后缀(右结合^不弹同优先级) -> 模拟RPN求值并输出每一步
```

- 表达式转换类题目的核心：**优先级表 + 结合性判定 + 运算符栈**。
- 后来想"输出所有中间过程"时，最省事的办法是**不递归、不复原表达式**，而是在求值阶段利用"值栈 + 剩余 token"重新拼出完整行。
- 涉及负数的处理（本题已保证不出现）需要额外小心一元负号；本题直接用 `isdigit` 判断即可。

## 4. 正解（记号与算法步骤）

### 记号表

| 记号 | 含义 |
| --- | --- |
| `post` | 后缀表达式 token 序列，用 `vector<string>` 存储 |
| `ops` | 中缀转后缀时用的运算符栈（`stack<char>`） |
| `val` | RPN 求值时的数字栈（`vector<string>`，方便随时打印） |
| `prec(c)` | 运算符 `c` 的优先级：`^`=3, `*`/`/`=2, `+`/`-`=1 |
| `isop(c)` | 判断字符是否是运算符 |
| `calc(a, b, op)` | 计算 $a\ \mathrm{op}\ b$（注意除法与乘方的顺序） |

### 算法步骤

1. **读入并清理**：读入整行，去掉所有空格。
2. **中缀转后缀**：
   - 数字 → `post`；
   - ``(` `` → 压栈；
   - `)` → 弹出到 `(`；
   - 运算符 → 按 2.2 节的规则弹栈后压入。
   - 结束时弹空栈。
3. **输出第一行**：`post` 全体。
4. **RPN 求值与逐步输出**：
   - 扫描 `post`：
     - 数字 → 压入 `val`；
     - 运算符 → 弹出 `b`、`a`，计算 $a \ \mathrm{op}\ b$，结果转字符串压回 `val`；
     - 构造一行 = `val`（底到顶）+ `post[i+1..]`，输出。
   - 最后一行自然只剩一个数（最终答案）。

### 复杂度

- 记 $L$ 为表达式长度，$L\le 100$。
- 转换阶段：$O(L)$。
- 求值阶段：每个运算符归约一次；每次输出一行的长度不超过 $O(L)$；最多 $O(L)$ 行，故总输出与打印时间为 $O(L^2)$。
- 空间：$O(L)$。
- 该复杂度对 $L\le 100$ 绰绰有余。

## 5. 参考代码（C++）

```cpp
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

int prec(char c){
	if(c=='^')return 3;
	if(c=='*'||c=='/')return 2;
	if(c=='+'||c=='-')return 1;
	return 0;
}

bool isop(char c){
	return c=='+'||c=='-'||c=='*'||c=='/'||c=='^';
}

i64 ipow(i64 a,i64 b){
	i64 r=1;
	while(b){
		if(b&1)r*=a;
		a*=a;
		b>>=1;
	}
	return r;
}

void outp(const vector<string>&v){
	for(size_t i=0;i<v.size();++i){
		if(i)cout<<' ';
		cout<<v[i];
	}
	cout<<'\n';
}

int main()
{
	cin.tie(nullptr);
	ios::sync_with_stdio(false);

	string t;
	getline(cin,t);

	vector<string>post;
	stack<char>op;
	for(char c:t){
		if(c==' ')continue;
		if(isdigit(c)){
			post.push_back(string(1,c));
		}else if(c=='('){
			op.push(c);
		}else if(c==')'){
			while(op.top()!='('){
				post.push_back(string(1,op.top()));
				op.pop();
			}
			op.pop();
		}else{
			while(!op.empty()&&op.top()!='('){
				if(prec(op.top())>prec(c)||(prec(op.top())==prec(c)&&c!='^')){
					post.push_back(string(1,op.top()));
					op.pop();
				}else break;
			}
			op.push(c);
		}
	}
	while(!op.empty()){
		post.push_back(string(1,op.top()));
		op.pop();
	}

	outp(post);

	vector<string>val;
	for(size_t i=0;i<post.size();++i){
		if(isdigit(post[i][0])){
			val.push_back(post[i]);
		}else{
			i64 b=stoll(val.back());val.pop_back();
			i64 a=stoll(val.back());val.pop_back();
			i64 r;
			if(post[i]=="+")r=a+b;
			else if(post[i]=="-")r=a-b;
			else if(post[i]=="*")r=a*b;
			else if(post[i]=="/")r=a/b;
			else r=ipow(a,b);
			val.push_back(to_string(r));

			vector<string>line=val;
			for(size_t j=i+1;j<post.size();++j)line.push_back(post[j]);
			outp(line);
		}
	}

	return 0;
}
```

### 对样例的走查

输入：`8-(3+2*6)/5+4`

1. 转后缀得：`8 3 2 6 * + 5 / - 4 +`，第一行输出它；
2. `2*6=12`，栈 `8 3 12`，剩余 `+ 5 / - 4 +` → 输出 `8 3 12 + 5 / - 4 +`；
3. `3+12=15`，栈 `8 15`，剩余 `5 / - 4 +` → 输出 `8 15 5 / - 4 +`；
4. 入栈 `5`；`15/5=3`，栈 `8 3`，剩余 `- 4 +` → 输出 `8 3 - 4 +`；
5. `8-3=5`，栈 `5`，剩余 `4 +` → 输出 `5 4 +`；
6. 入栈 `4`；`5+4=9`，栈 `9`，剩余空 → 输出 `9`。

与题目样例输出完全一致。
