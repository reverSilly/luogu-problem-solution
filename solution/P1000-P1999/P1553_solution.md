# P1553 数字反转（升级版）

> 标签：模拟 · 字符串 · 洛谷原创 · 难度：普及-
> 本地题面：`P1553.md`（整数/小数/分数/百分数四大形态，单个数位段位数 ≤ 20）。验证：14 组手工边界 + 900 组随机用例，标程 / 暴力 / Python 参考三路输出逐字节一致；最坏规模（20 位整数、10+10 位小数、10+10 位分数、19 位百分数）反复运行单次约 5 ms（绝大部分是进程启动开销）。

## 1. 重新读题

**问题重述（人话版）**

输入一个**字符串** $s$，它必然是下面四种形态之一：

1. 整数：形如 `digits`。
2. 小数：形如 `intpart.digits`（`.` 前是整数部分，`.` 后是小数部分）。
3. 分数：形如 `num/den`（`/` 前是分子，`/` 后是分母）。
4. 百分数：形如 `digits%`。

要求输出 $s$ 的"反转数"，**规则完全由题面逐字规定**：

- 整数：把所有数位对调，且结果要满足整数常见形式——除原数是 `0` 外，**最高位不为 `0`**。
- 小数：整数部分反转、小数部分反转，**两段位置不交换**；小数新数的**末尾不为 `0`**（若小数部分只有 `0`，则只保留一个 `0`；反转后若末尾出现 `0`，省掉多余的 `0`）。
- 分数：分子、分母各自反转（各自满足整数规则），**不交换分子分母**；输入保证分母非 `0`。
- 百分数：只把 `%` 前的数字部分按整数规则反转。
- 无负数。

**题面里最容易踩的条款**

1. 「**反转**」在这里是**纯语法操作**：把某一段的字符序列倒过来，再按照去零规则修剪。它**不是**算术意义的"求相反数/取倒序数值"。关键推论见 §2.1——所以**任何"去零不改变数值"的论证都是错的**（`0.05` 反转后是 `0.5`，数值从 `0.05 ≠ 0.5` 就被改了）。
2. 「末尾不为 `0`」「最高位不为 `0`」是**两把方向相反的刀**：整数型段去掉反转串的**前导零**，小数型段去掉反转串的**末尾零**。
3. 「至少保留一位」：任何一段去零后若被去空，都要输出单个 `0`（对应"原数为零"/"小数部分只有 0"）。
4. 分隔符 `.`、`/`、`%` 的位置在反转后**不变**，四类形态彼此互斥。

**数据范围与规模感受**

四类数据各自规定：整数 ≤ 20 位；小数的整数部分、小数部分各 ≤ 10 位；分数的分子分母各 ≤ 10 位；百分数的分子 ≤ 19 位。**位数都在 20 以内，用字符串逐段处理即可，无需大整数运算**；这也提示本题是纯模拟+字符串题，重点是"规则落地别写错"，而非算法设计。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：操作发生在"数字段"上，且分隔符原地不动

把输入看成"若干个数字段 + 0或1个分隔符"。题面对三类带分隔符的形态都用了同一句话：**"不交换整数部分与小数部分" / "不交换分子与分母" / "百分数只改变数字部分"**。这说明反转只是**在每段内部做字符倒序**，段与分隔符的排列次序原封不动。

**引理 1（分隔符与分段不动）**

设输入被分隔符切成数字段 $P_1,P_2,\dots$（整数、百分数只有一段；小数、分数有两段）。反转后的结果，其第 $i$ 段是 $P_i$ 的某种身份变换（见 §2.3），且分隔符、段序与原串完全一致。

**证明**：题面三类描述均明言"不交换部分/只改变数字部分"，即只允许改动段的**内容**、不允许改动段的**排列与分隔符**。故输出恰是把每个 $P_i$ 原地替换为反转处理后的 $Q_i$，其余（分隔符与其位置）不变。$\blacksquare$

> **这一步的收益**：题目从"处理一个整体字符串"退化为"对每个数字段独立做同一套原子操作"，四种形态的差别被压缩成"切几段、每段用哪把去零刀"两件事。

### 2.2 讨论分类：四种形态就是要切的段数与分隔符

由引理 1，只需按分隔符把输入分批：

| 形态 | 分隔符 | 段数 | 各段类型 |
|---|---|---|---|
| 整数 | 无 | 1 | 整数型 |
| 小数 | `.` | 2 | 前段整数型、后段小数型 |
| 分数 | `/` | 2 | 前段整数型、后段整数型 |
| 百分数 | `%` | 1 | 前段整数型（`%` 原样保留） |

四类形态互斥（不会同时出现两种分隔符），因此判定顺序不敏感；实现上任选其一分支即可。

### 2.3 每段的去零口径：两把方向相反的刀

这是本题**唯一真正会写错**的地方。先把"反转"定义清楚。

**定义（段反转）**：对一个数字段 $P$（字符序列），$\operatorname{rev}(P)$ 是把 $P$ 的字符顺序完全颠倒得到的串。

反转后要按形态修剪零。有两种"刀"：

- **整数型刀** $\mathrm{revInt}(P)$：反向字符串 $\operatorname{rev}(P)$ 去掉**所有前导零**，若全被去掉则保留单个 `0`。
- **小数型刀** $\mathrm{revDec}(P)$：反向字符串 $\operatorname{rev}(P)$ 去掉**所有末尾零**，若全被去掉则保留单个 `0`。

**引理 2（整数型段的正确修剪是"去前导零"）**

对整数型段 $P$，其反转结果必须且只能是 $\mathrm{revInt}(P)$。

**证明**：
- **必要性（必须去前导零）**：题面规定整数新数"除非给定的原数为零，否则最高位数字不应为零"。$\operatorname{rev}(P)$ 的前导零，来源正是 $P$ 末尾的零（如 `100` → `001`）。若不去掉，新数最高位即为 `0`，且原数 $P\neq$ 全零，直接违反规则。
- **充分性（去掉即可，且不影响其余位）**：去掉的恰是位于最高位连续的 `0`；删除后新的最高位是第一个非零数字，满足"最高位不为零"；而"整数常见形式"正是"没有多余前导零"的写法，删到只剩一位非零（或原数为全零时只剩 `0`）即为所求。
- **"至少保留一位"**：若 $P$ 全为 `0`，题面"除非给定的原数为零"允许结果为 `0`，故保留单个 `0`。$\blacksquare$

**引理 3（小数型段的正确修剪是"去末尾零"）**

对小数型段（小数部分）$P$，其反转结果必须且只能是 $\mathrm{revDec}(P)$。

**证明**：
- **必要性**：题面规定"小数新数的末尾不为 `0`……若反转之后末尾数字出现 `0`，请省略多余的 `0`"。$\operatorname{rev}(P)$ 的末尾零来自 $P$ 的开头零（如 `05` → `50`）。不去掉则小数部分末尾为 `0`，违反规则。
- **充分性**：删去末尾连续的 `0` 后，小数部分末位非零，满足"末尾不为 `0`"。
- **边界**："小数部分除了 `0` 没有别的数，那么只保留 1 个 `0`"：$P$ 全为 `0` 时 $\operatorname{rev}(P)$ 全为 `0`，删空后回退为单个 `0`，与题面一致。$\blacksquare$

**⚠️ 关键区分（也是失败 1 的根源）**：**小数部分的时间顺序是"先翻转、再去末尾零"**；等价地说，是把原小数部分的**前导零**去掉。它**绝不能**沿用整数型刀的"去前导零"，否则会把 `1.05` 变成 `1.50`（反转串 `50` 的前导零是 `无`，整数刀不会动它，于是 `50` 被原样留下）。

### 2.4 归约：整道题 = 切段 + 两把刀 + 原位拼回

**引理 4（算法骨架）**

设由分隔符切出的段依次为 $P_1,\dots,P_k$，各段使用引理 2/3 规定的刀。则把切分出的每段替换为其修剪结果、并按原分隔符拼回，即得正确答案。

**证明**：由引理 1，输出是各段原地替换；由引理 2、3，每个整数型段/小数型段的替换结果唯一确定。故整体结果唯一确定，拼接即得。$\blacksquare$

于是实现归结为：

$$\boxed{\;\text{按分隔符切分}\ \longrightarrow\ \text{逐段套刀}\ \longrightarrow\ \text{原位拼回}\;}$$

分数段两把都是整数型刀（引理 2）；小数前段用整数型刀、后段用小数型刀；百分数仅前段用整数型刀、`%` 原样保留。

### 2.5 剖析几个失败思路（都给出具体反例）

**失败 1：小数部分沿用"整数型刀"（去前导零）。**
输入 `1.05`：正确做法小数部分 `05` 反转得 `50`，去**末尾零**得 `5`，答案 `1.5`；错误做法对 `50` 去**前导零**（`50` 无前导零，原样），答案 `1.50`——末尾带零，一眼可见违反"小数新数末尾不为 0"。

**失败 2：忘记"至少保留一位"，把全零段去空。**
输入 `0.0`：小数部分 `0` 反转仍 `0`，去末尾零得空串。若不兜底成 `0` 就会输出 `0.`（缺小数部分）。正确输出 `0.0`。

**失败 3：把小数/分数整体当一个串反转，不按分隔符切分。**
输入 `12.34`：整体反转得 `43.21`；正确做法是两段各转——整数 `12→21`、小数 `34→43`，答案 `21.43`。二者不同，说明必须按分隔符切段。

**失败 4：分数输出时把分子分母写反。**
输入 `7/30`：正确 `7/3`（分子 `7` 转得 `7`，分母 `30` 转得 `3`）；若按"先转分母再转分子"误把顺序颠倒会得到 `3/7`，与题面"不交换分子与分母"直接冲突。

**失败 5：把整数段的反转写成"去末尾零"。**
输入 `100`：正确反转 `001→1`（去前导零）；若去末尾零则 `001` 末位是 `1`、是个非零数，刀不动它，得 `001`——最高位为 `0`，违反整数规则。

> 总结：**五把失败恰好对应"两把刀用错段 / 忘兜底 / 不切段 / 颠倒顺序"**，都是规则细节而非算法问题。

### 2.6 边界体检

| 量 | 范围 | 处理方式 |
|---|---|---|
| 单段位数 | ≤ 20 | 字符串操作，无溢出风险 |
| 全零段 | `0` | 去零后兜底为单个 `0` |
| 小数部分 = `0` | `0` | 同上，输出形如 `x.0` |
| 无分隔符 | 整数 | 单段走整数型刀 |

复杂度：每段线性扫描一次，整体 $O(|s|)$；空间 $O(|s|)$。本题是"规则落地"题，**没有算法难点，难点全在去零的两把刀上**。

## 3. 模式总结（Pattern Summary）

**模式名：分隔符切段的「分段规范化」模拟。**

按真实思考顺序排列：

- explore its property — 认清"反转"是**纯语法**重排、分隔符与段序不动，因此去零规则只能照抄题面、不能用数值守恒推导。
- discuss by category — 按分隔符 `.` `/` `%` 把输入分成四类，分别决定"切几段、哪段用哪把刀"。
- reduce to easier problem — 把四种形态统一归约为"对每个数字段套同一原子操作"：整数型刀 = 反转+去前导零，小数型刀 = 反转+去末尾零。
- classic problem solution — 字符串切分 + 原位拼接（模拟题的工程化标准写法：全程 string、`find`/`substr`，不碰数值）。
- watch the trimming direction — 同一动作在整数段与小数段上是**方向相反**的两把刀，用反必错（失败 1）。
- guard the all-zero segment — 任何一段去零后都要"至少保留一位"，全零段输出单个 `0`（失败 2）。
- keep segments, not the whole — 必须先按分隔符切段再各自处理，不能整体反转（失败 3）。

**一句话记忆**：*先切段，整数段反过去砍前导零、小数段反过去砍末尾零，段各自都别砍空。*

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| `s` | `string` | 输入串 | 读入 | 题面 |
| `dot` | `size_t` | `.` 的下标；`string::npos` 表示无 | `s.find('.')` | digital 的段界 |
| `slash` | `size_t` | `/` 的下标；同上 | `s.find('/')` | fraction 的段界 |
| `pct` | `size_t` | `%` 的下标；同上 | `s.find('%')` | percent 的段界 |
| `revInt(t)` | `string → string` | 整数型刀：反转 `t` 后去**前导**零（≥1 位） | — | Integer 段用 |
| `revDec(t)` | `string → string` | 小数型刀：反转 `t` 后去**末尾**零（≥1 位） | — | Decimal 小数段用 |

### 4.2 编号步骤

1. 读入 `s`，用 `find` 得到三个分隔符下标（缺者为 `npos`）。
2. **百分数分支**（`pct != npos`）：输出 `revInt(s.substr(0, s.size()-1))` 拼上 `%`。
3. **小数分支**（`dot != npos`）：输出 `revInt(前段)` + `.` + `revDec(后段)`。
4. **分数分支**（`slash != npos`）：输出 `revInt(前段)` + `/` + `revInt(后段)`（两段都是整数型刀）。
5. **整数分支**（以上皆非）：输出 `revInt(s)`。
6. `revInt`：`reverse` 后从前往后跳过 `'0'`，但**至少留一位**（`i+1 < size`），再 `substr(i)`；`revDec` 对称地从句尾跳过 `'0'` 至少留一位。

### 4.3 复杂度

- 时间：$O(|s|)$（每段只 `reverse` + 一次线性扫描）。
- 空间：$O(|s|)$。
- 实测（见 §4.5）：最坏规模反复运行，单次约 5 ms（且绝大部分是进程启动，算法本身在微秒级）。

### 4.4 关键不变量

1. 输出中原分隔符的位置、个数与输入完全一致（引理 1）。
2. 每个输出数字段，除全零情况外，整数型段最高位非零、小数型段末位非零（引理 2、3）。
3. 任何数字段长度 ≥ 1（"至少保留一位"）。

### 4.5 验证状态小结

| 项目 | 状态 |
|---|---|
| 手工/官方边界 | **通过**：`1234567→7654321`、`100→1`、`0→0`、`100.0→1.0`、`0.0→0.0`、`0.05→0.5`、`7/30→7/3`、`50%→5%`、`100%→1%` 等 14 组 |
| 随机对拍 | **通过**：900 组随机（四类形态 + 偶发前导零），标程 == 暴力 == Python 参考三路一致 |
| 最坏规模计时 | 20 位整数 / 10+10 位小数 / 10+10 位分数 / 19 位百分数：200×4 次运行合计 4.10 s（单次 ≈ 5 ms，含进程启动） |
| 残余风险 | 若输入段长度远超题面（>20 位）本解法仍正确（纯字符串），无越界风险 |

## 5. 示例代码

### 5.1 主解：分段 + 两把去零刀

```cpp
//
// 题目：P1553 数字反转（升级版）
// https://www.luogu.com.cn/problem/P1553
// AC
#include<bits/stdc++.h>
using namespace std;

string revInt(string t)          // 整数型片段: 反转后去前导 0(至少留一位)
{
	reverse(t.begin(),t.end());
	int i=0;
	while(i+1<(int)t.size()&&t[i]=='0')
		++i;
	return t.substr(i);
}
string revDec(string t)          // 小数型片段: 反转后去末尾 0(至少留一位)
{
	reverse(t.begin(),t.end());
	int i=(int)t.size()-1;
	while(i>0&&t[i]=='0')
		--i;
	return t.substr(0,i+1);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	string s;
	cin>>s;
	size_t dot=s.find('.');
	size_t slash=s.find('/');
	size_t pct=s.find('%');
	if(pct!=string::npos)                          // 百分数: 只反转数字部分
		cout<<revInt(s.substr(0,s.size()-1))<<"%\n";
	else if(dot!=string::npos)                     // 小数: 两段各自反转, 不交换
		cout<<revInt(s.substr(0,dot))<<'.'<<revDec(s.substr(dot+1))<<'\n';
	else if(slash!=string::npos)                   // 分数: 分子分母各自反转, 不交换
		cout<<revInt(s.substr(0,slash))<<'/'<<revInt(s.substr(slash+1))<<'\n';
	else                                           // 整数
		cout<<revInt(s)<<'\n';
	return 0;
}
```

**代码结构对照**：`revInt`/`revDec` 是 §2.3 的两把刀；主程序只做"切段 + 原位拼回"（引理 4）。全程 `string`，不涉及任何整数运算，因此对 20 位位数毫无压力。

### 5.2 对照实现：结构独立的暴力基准（仅用于对拍）

```cpp
//
// 题目：P1553 数字反转（升级版）——朴素暴力基准
// https://www.luogu.com.cn/problem/P1553
// 结构独立于标程: 先按分隔符切分, 再分别用 find_first_not_of / find_last_not_of 去零
#include<bits/stdc++.h>
using namespace std;

string stripLead(string s)   // 去前导 0, 全 0 则返回 "0"
{
	size_t p=s.find_first_not_of('0');
	return p==string::npos?"0":s.substr(p);
}
string stripTail(string s)   // 去末尾 0, 全 0 则返回 "0"
{
	size_t p=s.find_last_not_of('0');
	return p==string::npos?"0":s.substr(0,p+1);
}
string revInt(string s)      // 整数型片段
{
	reverse(s.begin(),s.end());
	return stripLead(s);
}
string revDec(string s)      // 小数型片段
{
	reverse(s.begin(),s.end());
	return stripTail(s);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	string s;
	cin>>s;
	if(s.back()=='%')                       // 百分数
		cout<<revInt(s.substr(0,s.size()-1))<<"%\n";
	else if(s.find('.')!=string::npos)      // 小数
	{
		size_t p=s.find('.');
		cout<<revInt(s.substr(0,p))<<'.'<<revDec(s.substr(p+1))<<'\n';
	}
	else if(s.find('/')!=string::npos)      // 分数
	{
		size_t p=s.find('/');
		cout<<revInt(s.substr(0,p))<<'/'<<revInt(s.substr(p+1))<<'\n';
	}
	else                                     // 整数
		cout<<revInt(s)<<'\n';
	return 0;
}
```

两版**输出必须逐字节相同**（已用 900 组随机数据确认）。暴力版把去零改写成 `find_first_not_of` / `find_last_not_of`，并用 `s.back()=='%'` 判百分数，与主解的 `find` + 下标跳零是**两套独立实现**，可交叉暴露去零方向写反之类的隐性 bug。

### 5.3 易错点清单

- **小数段误用整数型刀**（去前导零）⇒ `1.05` 输出 `1.50`（失败 1）。
- **去零不留兜底**⇒ `0.0` 输出 `0.`（失败 2）。
- **整体反转不切段**⇒ `12.34` 输出 `43.21`（失败 3）。
- **分数分子分母颠倒**⇒ `7/30` 输出 `3/7`（失败 4）。
- **整数段误去末尾零**⇒ `100` 输出 `001`（失败 5）。
- **`cout<<...<<endl`** 违反本仓库风格，一律 `'\n'`。
