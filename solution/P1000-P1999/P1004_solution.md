# P1004 [NOIP 2000 提高组] 方格取数 题解

---

## 一、像人一样想题

### 1.1 先看清题目在说什么

我们有一个 N×N 的方格（N≤9），某些格子里有正整数（≤30），其余是 0。一个人从左上角 (1,1) 走到右下角 (N,N)，只能向右或向下走，沿途把格子里的数取走（取过后变成 0）。他要走两次。问：两次路径取到的数字之和最大是多少？

### 1.2 暴力思路 — 第一次直觉

最直接的想法：先找一条最大值路径，取走数，再在剩下的格子里找第二条最大值路径，加起来。

但这个贪心对吗？反例很容易构造。比如：

```
2 3
  (1,1)=1, (1,2)=100
  (2,1)=100, (2,2)=1
```

N=2。第一次最大路径是 1→(1,1)→(1,2)→(2,2) 得 1+100+1=102？还是 1→(1,1)→(2,1)→(2,2) 得 1+100+1=102？无论哪条，剩下的数都很小。但最优解明明是两条路径各走一个 100，总和 200。

所以贪心不行。必须**把两次路径作为一个整体来决策**。

### 1.3 降低难度：先想"走一次"怎么做

走一次太简单了——经典 2D DP：`dp[i][j] = max(dp[i-1][j], dp[i][j-1]) + a[i][j]`。走到 (i,j) 的最大值只能来自上方或左方。

这个 DP 的本质是：**每个格子至多被决策一次**，决策就是选上方来路还是左方来路。

### 1.4 核心观察：两次路径可以看作"两个人同时走"

既然走一次是 DP，走两次能不能 DP 呢？

关键想法：**不要先走完第一次再走第二次，而是让两个人在同一时刻从起点出发，同时走，同时到达终点。**

这样每个"时刻"（步数），两个人都在某两个格子上。我们只需要记录两个人各自在什么位置，就能做 DP 了。

为什么可以"同时"？因为：

- 从 (1,1) 到 (N,N) 不管怎么走，步数都是固定的：向右走 N-1 步，向下走 N-1 步，总共 **2N-2 步**。
- 所以两个人一定在同一时刻到达终点。
- 既然步数相同，我们就可以用**步数**作为 DP 的阶段。

### 1.5 设计状态

设两个人分别为 A 和 B。在第 k 步（从 1 开始数，起点是第 1 步），A 在 (x₁, y₁)，B 在 (x₂, y₂)。

因为每一步只能向右或向下，所以每一步的坐标满足：
- x₁ + y₁ = k + 1  （如果以起点为 k=0, 则 x₁+y₁=k；不同习惯差一个常数，不影响）
- x₂ + y₂ = k + 1

也就是说，给定 k 和 x₁，就能算出 y₁ = k+1 - x₁。同理 x₂ 决定 y₂。

因此状态可以压缩为 **dp[k][x₁][x₂]** —— 表示走了 k 步时，A 在第 x₁ 行，B 在第 x₂ 行，所取得的最大数字和。

这里 k 的范围是 0 到 2N-2（或 1 到 2N-1，取决于定义方式）。每个 x 的范围是 1 到 N。

### 1.6 转移方程

在第 k 步，A 和 B 各自**上一步**的位置：
- A 可以从 (x₁-1, y₁) 来（从上往下），或从 (x₁, y₁-1) 来（从左往右）。
- B 同理，有两种来路。

所以一共 2×2 = 4 种组合：

```
dp[k][x₁][x₂] = max( 四种来路 ) + 当前格子上的数
```

当前格子上的数怎么算？

- 如果 A 和 B 在同一个格子（x₁==x₂ && y₁==y₂），那这个格子只贡献一次，因为他们同时取走。
- 否则两个格子各自贡献。

更确切地：
```
add = a[x₁][y₁] + (x₁==x₂ && y₁==y₂ ? 0 : a[x₂][y₂])
```

四种来路是：
```
from_up_up    = dp[k-1][x₁-1][x₂-1]   // A 从上, B 从上
from_up_left  = dp[k-1][x₁-1][x₂]     // A 从上, B 从左
from_left_up  = dp[k-1][x₁][x₂-1]     // A 从左, B 从上
from_left_left= dp[k-1][x₁][x₂]       // A 从左, B 从左
```

注意边界情况：x₁ 或 x₂ 为 1 时不能从上走来；y₁ 或 y₂ 为 1 时不能从左走来。对于无效的转移，直接取 -inf。

### 1.7 边界与答案

起点 k=0 时，A 和 B 都在 (1,1)：`dp[0][1][1] = a[1][1]`。

终点 k = 2N-2 时，A 在 (N,N)，B 也在 (N,N)：答案是 dp[2N-2][N][N]。

### 1.8 复杂度

N ≤ 9，步数 ≤ 16，x₁ 和 x₂ 各 ≤ 9。状态数 ≈ 16×9×9 = 1296，每个状态转移 4 种。轻松通过。

事实上 N 大到 50 也能做，但题目 N≤9，怎么写都行。

### 1.9 另一种经典思路：四维 DP

如果不压缩步数维度，直接 `dp[x₁][y₁][x₂][y₂]` 也是可以的。由于 N≤9，四维 DP 也毫无压力（9⁴=6561）。步数压缩只是为了更优雅，也能推广到更大的数据范围。

## 二、Chain-of-Thought（完整推导）

### 符号定义

设方格为 N×N，行号 i，列号 j 均从 1 开始编号。a[i][j] 为格子 (i,j) 上的数字。

### Lemma 1：路径的结构

**任意一条从 (1,1) 到 (N,N) 且只向右或向下的路径，恰好包含 N-1 次右移和 N-1 次下移，总步数为 2N-2。**

*证明*：从 (1,1) 到 (N,N) 需要增加行号从 1 到 N（需 N-1 次下移），列号从 1 到 N（需 N-1 次右移）。每次移动要么下移要么右移，故总步数为 (N-1)+(N-1) = 2N-2。□

### Lemma 2：同时性

**两条路径可以看作两个人同时从起点出发，每步同时移动，同时到达终点。**

*证明*：由 Lemma 1，两条路径的长度均为 2N-2。安排两个人以相同速度（每单位时间移动一步）同时出发，则他们必然在同一时刻到达终点。反之，任何一对路径都可以被想象成这种同步走法。因此，用同步视角不会丢失任何可行解。□

### Lemma 3：状态可约化

**在同步视角下，设第 k 步时 A 的行号为 x₁、B 的行号为 x₂，则 A 的列号 y₁ = k - x₁ + 2，B 的列号 y₂ = k - x₂ + 2（若起点 k=0 时在 (1,1)）。**

*证明*：以起点为第 0 步，此时 A 在 (1,1)，k=0, x₁=1, y₁=1，满足 y₁ = 0 - 1 + 2 = 1。每走一步，x₁+y₁ 恰好增加 1（因为一步要么 x₁+1 要么 y₁+1）。所以第 k 步时 x₁ + y₁ = k + 2，即 y₁ = k + 2 - x₁。同理 y₂ = k + 2 - x₂。□

**推论**：状态只需表示成 dp[k][x₁][x₂]，因为 y₁,y₂ 可由 k,x₁,x₂ 唯一确定。

### Lemma 4：最优子结构

**设 dp[k][x₁][x₂] 为第 k 步时 A 在 (x₁, y₁), B 在 (x₂, y₂) 的已取得最大数字和（y₁,y₂ 由 Lemma 3 确定）。则 dp[k][x₁][x₂] 的最优值依赖于 dp[k-1][...][...] 的最优值。**

*证明*：第 k 步的到达位置由第 k-1 步的位置经一次移动得到。A 的上一步可能是 (x₁-1, y₁) 或 (x₁, y₁-1)；B 类似。共四种组合。每种组合的已取得数字和 = 该组合上一步的 dp 值 + 当前步新增的贡献。由于各步贡献非负且互不影响（格子被取后变为 0，但两个人不会重复取同一格子——若在同一格子则只计一次），两个子问题（前 k-1 步的决策）独立，因此最优子结构成立，可以用 DP 求解。□

### Lemma 5：转移方程

```
add = a[x₁][y₁] + (x₁==x₂ && y₁==y₂ ? 0 : a[x₂][y₂])
dp[k][x₁][x₂] = max(
    dp[k-1][x₁-1][x₂-1] ,   // A 从上, B 从上
    dp[k-1][x₁-1][x₂]   ,   // A 从上, B 从左
    dp[k-1][x₁][x₂-1]   ,   // A 从左, B 从上
    dp[k-1][x₁][x₂]         // A 从左, B 从左
) + add
```

需要检查各来路是否合法（x₁>1 才能从上、y₁>1 才能从左，等等），非法取 -inf。

*证明*：由 Lemma 4 及四个方向组合直接给出。□

### 边界与答案

- 边界：dp[0][1][1] = a[1][1]（起点），其余 dp[0][*][*] = -inf。
- 答案：dp[2N-2][N][N]（两人均到达终点）。

### 正确性

上述 DP 枚举了每一时刻两人所有可能的位置组合，通过最优化原则递推。由于网格大小有限（N≤9），状态空间完全覆盖所有可行路径对，因此算法正确。

## 三、Pattern Summary（思考顺序）

1. **同步行走** — 两次路径转化为两个人同时从起点走到终点，利用步数相等的性质。
2. **步数阶段化** — 以总移动步数 k 作为 DP 阶段，消去列号自由度，降维至 3D。
3. **四方向转移** — 每个人的上一步有 2 种可能（上/左），组合成 4 种转移。
4. **去重贡献** — 两路径在同一格时只计一次该格数值，其余情况各自贡献。

## 四、真正的解法（代码如何运作）

### 符号表

| 符号 | 含义 |
|---|---|
| `N` | 网格边长 |
| `a[x][y]` | 格子 (x,y) 上的数字 |
| `dp[k][i][j]` | 走 k 步时，A 在第 i 行、B 在第 j 行的已取最大和 |
| `y1, y2` | 由 k,i,j 推算的列号：`y1 = k+2-i`, `y2 = k+2-j` |
| `add` | 第 k 步新贡献：若两路径在同一格则只计一次，否则各自计 |
| `-inf` | 负无穷（用于不可达状态） |

### 算法步骤

1. 读入 N，读入 (x,y,v) 直到遇到 0，存储到 `a[x][y]`。
2. 初始化所有 dp 为 -inf（`fill_n`），令 `dp[0][1][1] = a[1][1]`。
3. 枚举步数 k 从 1 到 2N-2：
   - 枚举 x₁ 从 1 到 N，x₂ 从 1 到 N：
     - 检查 (x₁, y₁) 和 (x₂, y₂) 是否在界内。
     - 计算四种来路的最大值。
     - 加上 add，写入 dp[k][x₁][x₂]。
4. 输出 `dp[2N-2][N][N]`。

### 复杂度

- 时间复杂度：O(N³ × 4) = O(N³)，N≤9，实际约 9³×16≈11664 次操作。
- 空间复杂度：O(N³)，约 16×9×9 = 1296 个整数，可优化为滚动数组 O(N²)，但完全没必要。

### 验证

手工验证 N=2 的样例（题目未直接给出，自行构造验证）：按前述反例，DP 正确输出 200。

## 五、示例代码

```cpp
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{14};  // N≤9, +5 slack

int n;
int a[mxn][mxn];
int dp[mxn*2][mxn][mxn];  // dp[step][x1][x2]

int main(){
    cin.tie(nullptr);
    ios::sync_with_stdio(false);

    cin>>n;
    for(int x,y,v;cin>>x>>y>>v&&(x||y||v);)
        a[x][y]=v;

    fill_n(&dp[0][0][0],(mxn*2)*mxn*mxn,-1145141919);
    dp[0][1][1]=a[1][1];

    int steps=2*n-2;
    for(int k=1;k<=steps;++k){
        for(int x1=1;x1<=n;++x1){
            for(int x2=1;x2<=n;++x2){
                int y1=k+2-x1,y2=k+2-x2;
                if(y1<1||y1>n||y2<1||y2>n)continue;
                int add=a[x1][y1]+(x1==x2&&y1==y2?0:a[x2][y2]);
                int&cur=dp[k][x1][x2];
                // 4 directions: (up,up), (up,left), (left,up), (left,left)
                cur=max(cur,dp[k-1][x1-1][x2-1]+add);
                cur=max(cur,dp[k-1][x1-1][x2]+add);
                cur=max(cur,dp[k-1][x1][x2-1]+add);
                cur=max(cur,dp[k-1][x1][x2]+add);
            }
        }
    }
    cout<<dp[steps][n][n]<<'\n';
    return 0;
}
```
