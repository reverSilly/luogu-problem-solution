# P1628 合并序列

## Part 1 — 题目理解 (Problem Comprehension)

### 题意简述

给出 $N$ 个由小写字母组成的单词和一个字符串 $T$，要求按**字典序升序**输出所有以 $T$ 为前缀的单词。没有符合条件的单词时什么都不输出。

### 输入输出格式

- **输入格式**：第一行 $N$；随后 $N$ 行每行一个单词（长度 $\le100$）；最后一行是 $T$。
- **输出格式**：每行一个单词，按字典序升序。
- **数据规模**：$60\%$ 数据 $N\le1000$；$100\%$ 数据 $N\le10^5$，字符均为小写字母。

### 关键约束分析

1. $N$ 最大 $10^5$，总字符量约 $10^7$，$\mathcal{O}(N\log N\cdot L)$ 的"排序 + 逐词判前缀"完全可行（$L\le100$）。
2. 单词长度不统一，判前缀时必须先保证"单词长度 $\ge$ 前缀长度"，否则会越界读。
3. 输出顺序是字典序，不是输入顺序——必须先排序或按有序结构遍历。
4. 边界：$T$ 比所有单词都长时答案为空（一行都不输出）；单词可以重复，重复的每一次出现都要输出；$T$ 本身等于某个单词时，该单词也算（前缀可以是自身）。

## Part 2 — 思路推导 (Idea Discovery)

### 第一步：问题拆成两件事

题目要求同时满足"是前缀"和"按字典序输出"。最直接的想法是做两遍：先筛出所有以 $T$ 开头的单词，再把这些单词排序。或者先全部排序，再顺序扫一遍筛出前缀。两种写法复杂度相同，后者更短，因为排序后的数组只要线性扫一次。

### 第二步：怎样判断"以 $T$ 为前缀"

**引理 1（前缀判定）**：对字符串 $w$ 与 $T$，若 $|w|\ge|T|$，则"$T$ 是 $w$ 的前缀"等价于 $w$ 的前 $|T|$ 个字符与 $T$ 逐字相等，即 `w.compare(0,|T|,T)==0`。

*证明*：`compare(pos,count,str)` 取出 $w$ 从 $pos$ 开始、长度 $\min(count,|w|-pos)$ 的子串与 `str` 做字典序比较，返回 $0$ 当且仅当两者完全相同。取 $pos=0,count=|T|$，在 $|w|\ge|T|$ 时取出的正是前 $|T|$ 个字符；它们与 $T$ 相同当且仅当 $T$ 是前缀。$\square$

顺带说明：当 $|w|<|T|$ 时，取出的子串比 $T$ 短，比较结果必然非 $0$，所以 `compare` 自身已经处理了长度不足的情况；代码里额外的长度判断只是提前短路，不影响正确性。

### 第三步：排序后过滤，输出仍然有序

**引理 2（子序列保序）**：若 $s_1\le s_2\le\cdots\le s_N$（字典序），且 $i_1<i_2<\cdots<i_m$，则 $s_{i_1}\le s_{i_2}\le\cdots\le s_{i_m}$。

*证明*：对任意 $k$，由 $i_k<i_{k+1}$ 与整体的有序性得 $s_{i_k}\le s_{i_{k+1}}$；有限个两两相邻的不等关系传递即得整个子序列有序。$\square$

于是"先 `sort` 全部单词，再顺序扫描并输出满足前缀条件的词"得到的输出天然按字典序升序，无需第二次排序。

### 第四步：不重不漏

**引理 3（筛选的完备性）**：扫描输出集合恰为 $\{w_i: T \text{ 是 } w_i \text{ 的前缀}\}$，且每个下标恰好被输出一次。

*证明*：循环对每个 $i$ 判断一次条件，条件成立才输出，故输出的每个元素都属于该集合（无多余）；集合中的每个元素在其下标被访问时条件成立，故都会被输出（无遗漏）；下标互不相同，循环只走一遍，故不重复。$\square$

**引理 4（字典序与 ASCII 一致）**：所有字符限定为小写字母时，`std::string` 的 `<` 比较（按字符编码逐位比较）与题目所说的字典序一致。

*证明*：小写字母的 ASCII 编码 $97\sim122$ 是递增的，与字母表顺序 $a<b<\cdots<z$ 一致；字典序的定义正是"从左到右找第一个不同位置，比较该位置字符的大小，若一方是另一方前缀则短者更小"，而逐字符编码比较恰好实现这一规则（前缀情形下短串先结束，判为更小）。$\square$

### 第五步：为什么不用 Trie

也可以把所有单词插入 Trie，定位到 $T$ 的终止结点后做一次先序遍历输出所有词尾，复杂度 $\mathcal{O}(\text{总字符数})$，比排序更优。但本题 $N\le10^5$、$L\le100$，排序的 $1.7\times10^8$ 次字符比较实测仅 $0.03$ s，Trie 的代码量与内存都更大，属于"不必要的优化"。因此选择排序方案。

另一种写法是"先筛选、再对筛出的结果排序"：最坏情况（全部单词都以 $T$ 开头）代价与先排序完全相同，最好情况（几乎无匹配）更省。本实现选择"先排序 + 线性筛选"，因为只需一次 `sort` 调用、代码最短，且"无匹配"时不会构造任何中间数组。

**定理**：算法输出恰为全部以 $T$ 为前缀的单词，且按字典序升序。

*证明*：引理 1 保证筛选条件正确，引理 3 保证不重不漏，引理 2 保证输出有序，引理 4 保证所用比较与题目定义的字典序一致。$\square$

## Part 3 — 模式总结 (Pattern Summary)

- `reduce to easier problem` — 把"筛前缀 + 排序"拆成"全部排序 + 线性筛选"。
- `explore its property` — 有序序列的任意子序列仍有序，因此只需一次排序。
- `classic problem solution` — 用 `compare(0,len,T)` 做 $O(L)$ 的前缀判定。
- `consider easier version` — 若只要"是否包含"而不要求顺序，连排序都可以省掉；顺序要求才是排序的理由。

## Part 4 — 真正的解法 (The Real Solution)

### 符号表 (Notation Glossary)

| 数学符号 | 代码变量 | 含义说明 |
| :--- | :--- | :--- |
| $N$ | `n` | 单词个数 |
| $w_i$ | `s[i]` | 第 $i$ 个单词（0-based，`string` 数组） |
| $T$ | `t` | 前缀串 |
| $|T|$ | `len` | `t.size()`，判定时作为比较长度 |
| — | `i` | 扫描下标 |
| — | `mxn` | 数组上界 $10^5+5$ |

### 算法步骤

1. 读入 $n$ 与 $n$ 个单词存入 `s`，最后读入 `t`。
2. `sort(s,s+n)`：按字典序升序（引理 4 保证与题意一致）。
3. 令 `len=t.size()`，顺序扫描 $i=0..n-1$：若 `s[i].size()>=len` 且 `s[i].compare(0,len,t)==0`，输出 `s[i]` 并换行。
4. 结束（无匹配时自然不输出任何内容）。

### 复杂度分析

- **时间复杂度**：排序 $\mathcal{O}(N\log N\cdot L)$（每次比较最坏 $L$ 个字符），扫描 $\mathcal{O}(NL)$，合计 $\mathcal{O}(NL\log N)$。$N=10^5,L=100$ 实测约 $0.03$ s。
- **空间复杂度**：$\mathcal{O}(NL)$ 存储所有单词，约 $10^7$ 字节。

### 正确性验证

引理 1 保证前缀判定正确，引理 3 保证不重不漏，引理 2 保证输出顺序，引理 4 保证排序规则符合题意。`sort` 对 `string` 使用 `operator<`，不会修改内容；数组大小 `mxn=100005` 覆盖 $N\le10^5$。无整数运算，不存在溢出问题。

输出格式上，每个单词后跟一个 `'\n'`，最后一行也带换行，符合多数 OJ 的"行末可有换行"约定；无匹配时循环体一次都不进入，程序不产生任何输出。

## Part 5 — 示例代码 (Example Code)

```cpp
//
// 题目：P1628 合并序列
// https://www.luogu.com.cn/problem/P1628
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{100005};

int n;
string s[mxn],t;

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>n;
	for(int i=0;i<n;++i)
		cin>>s[i];
	cin>>t;
	sort(s,s+n);
	int len=t.size();
	for(int i=0;i<n;++i)
		if((int)s[i].size()>=len&&s[i].compare(0,len,t)==0)
			cout<<s[i]<<'\n';
	return 0;
}
```

### 易错点

1. **按输入顺序输出**：题目要求字典序，必须先 `sort`；直接扫描原数组会错。
2. **忘记长度判断**：本题的 `compare(0,len,t)` 在短串上返回非零，恰好安全；但若改用 `s[i].substr(0,len)==t` 之外的下标访问（如 `s[i][len-1]`）就会越界，养成"先比长度"的习惯更稳妥。
3. **用 `find(t)==0` 代替 `compare`**：`find` 是子串查找，语义不同且更慢，`t` 出现在中间时 `find` 返回非 $0$ 会被误判。
4. **`T` 为空**：题面保证是字符串，但若读入失败 `len=0`，`compare(0,0,t)` 恒为 $0$，会输出全部单词——读入要用 `cin>>t` 保证至少读到内容。
5. **输出用 `endl`**：$10^5$ 行会反复刷新缓冲区，必须用 `'\n'`。
6. **数组开小**：$N$ 上界 $10^5$，`mxn` 必须按此设置，不能按 $60\%$ 的 $1000$ 开。
