# P1801 黑匣子

> 难度：普及/提高- · 标签：堆、平衡树、线段树

## 1. 重新读题
### 1.1 问题重述（人话版）

黑匣子一开始是空的，计数器 \(i=0\)。只有两种操作：`ADD(x)` 把整数 \(x\) 放进去；`GET` 先把 \(i\) 加 1，再输出匣子里**第 \(i\) 小**的数（相等的数按重数算，从小到大排好后的第 \(i\) 个）。

输入不是逐条命令，而是压成两段：

- \(a_1,\ldots,a_m\)：按时间顺序将要被 ADD 的数；
- \(u_1,\ldots,u_n\)：第 \(j\) 个 GET 发生在**恰好放进了前 \(u_j\) 个数之后**。\(u\) 单调不降，所以同一次插入之后可以连着 GET 好几次（样例里 \(u_3=u_4=6\)）。

因此输出一共 \(n\) 行，第 \(j\) 行是多重集 \(\{a_1,\ldots,a_{u_j}\}\) 的第 \(j\) 小。

### 1.2 关键约束与规模暗示

- \(1\le n,m\le 2\times 10^5\)，\(|a_i|\le 2\times 10^9\)。\(a_i\) 放得进 32 位 `int`，但每次 GET 都重新排序前缀是 \(O(m^2\log m)\)，过不了满数据。
- \(u\) 单调不降，而且第 \(j\) 小必须存在，所以数据满足 \(u_j\ge j\)（否则匣子里根本没有 \(j\) 个数）。题面写「输入不用判错」，标程按这个前提写，不特判空堆。
- 询问的下标 \(j\) 只增不减，而且只增 1。这允许我们用一个「恰好装着当前最小的 \(j\) 个」的结构，每次查询只把规模加 1，而不是从头做选择。

## 2. 思维链（Chain-of-thought）

**引理 1（输出就是前缀的第 \(j\) 小）**

第 \(j\) 行输出等于 \(\{a_1,\ldots,a_{u_j}\}\) 里第 \(j\) 小的元素。

**证明**：对命令条数归纳。匣子只进不出。处理到第 \(j\) 个 GET 时，之前发生过的 ADD 恰好是前 \(u_j\) 个（\(u_j\) 的定义），所以匣子里的多重集就是这个前缀。GET 的定义是「\(i\) 加 1 再输出第 \(i\) 小」，而每个 GET 都把 \(i\) 加 1、初始 \(i=0\)，所以第 \(j\) 个 GET 时 \(i=j\)。两句话合起来就是引理。\(\square\)

于是问题变成：按 \(u_j\) 给定的前缀长度，在线维护「当前前缀的第 \(j\) 小」，且 \(j\) 从 1 增到 \(n\)。

**引理 2（分界堆的堆顶就是第 \(k\) 小）**

设当前多重集被分成两部分 \(L\) 和 \(H\)，满足：

1. \(L\) 与 \(H\) 的并就是当前多重集，且不交；
2. \(L\) 中每个元素 \(\le\) \(H\) 中每个元素。

则 \(L\) 恰好是全体里最小的 \(|L|\) 个，\(\max L\) 就是第 \(|L|\) 小。

**证明**：把全体从小到大排。假设 \(L\) 里混进了一个「不该在最小 \(|L|\) 个里」的元素 \(x\)，则最小的 \(|L|\) 个里至少有一个 \(y\) 落在 \(H\)。于是 \(y\le x\)（\(y\) 属于最小的 \(|L|\) 个而 \(x\) 不属于）。但条件 2 要求 \(x\in L\)、\(y\in H\) 时 \(x\le y\)，故 \(x=y\)，把 \(x\) 和 \(y\) 对调后 \(L\) 仍然是某一组最小的 \(|L|\) 个（重数相同）。因此 \(\max L\) 等于第 \(|L|\) 小：它 \(\ge L\) 中其余元素，又 \(\le H\) 中一切元素，排起来正好卡在第 \(|L|\) 位。\(\square\)

实现时 \(L\) 用大根堆（堆顶即 \(\max L\)），\(H\) 用小根堆（堆顶即 \(\min H\)，重平衡时要用）。

**引理 3（只往分界的一侧插，分界不被破坏）**

假设插入前引理 2 的条件 2 成立，且插入过程中不从堆里弹出。规则：若 \(L\) 空或 \(x\le \max L\)，把 \(x\) 放进 \(L\)，否则放进 \(H\)。则插入后条件 2 仍成立。并且在「从一次查询结束、到下一次重平衡之前」的一整段连续插入里，\(\max L\) 保持不变。

**证明**：插入前 \(\max L\le \min H\)（\(H\) 空则右侧不存在，条件 2 真空为真）。

- 若 \(x\le \max L\)：\(x\) 进 \(L\)。新的 \(\max L\) 仍是原来的 \(\max L\)（\(x\) 没有更大）。新 \(L\) 的每个元素仍 \(\le\) 原 \(\max L\le\) 每个 \(H\) 的元素。
- 若 \(x>\max L\)：\(x\) 进 \(H\)。\(x\) 大于原 \(\max L\)，而原 \(\max L\) 又 \(\ge L\) 的每个元素，所以 \(x\) 大于等于每个 \(L\) 的元素；原来的 \(H\) 本来就大于等于每个 \(L\) 的元素。

连续插入时，凡是进 \(L\) 的都 \(\le\) 当前 \(\max L\)，所以 \(\max L\) 不会变大；又没有弹出，它也不会变小。因此这一段里比较基准是常数，上面的论证可以逐个用上去。

起始时两堆都空，第一个数按「\(L\) 空」放进 \(L\)，条件 2 成立。每次查询结束时我们会把 \(|L|\) 调成当前的正整数 \(i\ge 1\)，而 \(i\) 只增不减，所以下一段插入开始时 \(L\) 非空，规则里的 \(\max L\) 有定义。\(\square\)

**引理 4（把 \(|L|\) 调成 \(i\) 之后，堆顶就是第 \(i\) 小）**

在引理 3 的分界之上做：

- 当 \(|L|>i\)：把 \(\max L\) 弹出并塞进 \(H\)；
- 当 \(|L|<i\)：把 \(\min H\) 弹出并塞进 \(L\)。

直到 \(|L|=i\)。之后条件 2 仍成立，故 \(\max L\) 就是第 \(i\) 小。

**证明**：先看把 \(\max L\) 移入 \(H\)。被移走的数 \(t=\max L\) 满足 \(t\le\) 每个 \(H\) 的元素（条件 2）。剩下的 \(L\) 全部 \(\le t\)。新 \(H\) 里最小的那个只可能更小到 \(t\)，所以新 \(H\) 的每个元素 \(\ge t\ge\) 剩下的每个 \(L\)。条件 2 保留，且 \(|L|\) 减 1。

再看把 \(\min H\) 移入 \(L\)。设 \(s=\min H\)。条件 2 给出 \(s\ge\) 每个 \(L\) 的元素。新 \(\max L=\max(\text{旧}\max L,\,s)=s\)。剩下的 \(H\) 全部 \(\ge s\)，所以新 \(L\) 全部 \(\le s\le\) 新 \(H\)。条件 2 保留，且 \(|L|\) 加 1。

最后说明 \(H\) 不会在 \(|L|<i\) 时被抽空。当前元素总数等于已经 ADD 的个数 \(u_i\)。由第 \(i\) 小存在，\(u_i\ge i\)。故 \(|L|+|H|=u_i\ge i\)，\(|L|<i\) 时 \(|H|\ge 1\)。\(\square\)

把引理 1 到 4 串起来：第 \(i\) 个 GET 之前，先把 \(a\) 补插到下标 \(u_i\)，再把 \(|L|\) 调成 \(i\)，输出 \(\max L\)。\(i\) 从 1 走到 \(n\)，每行一次。

## 3. 模式总结（Pattern Summary）

- **explore its property** — \(u\) 单调、\(i\) 每次只加 1，所以第 \(j\) 行只跟前缀多重集的第 \(j\) 小有关。
- **maintain an invariant** — 大根堆 \(L\) 装最小的若干个，小根堆 \(H\) 装剩下的，并且 \(L\) 全体 \(\le H\) 全体。
- **rebalance** — 插入阶段只维护分界，查询前把 \(|L|\) 拧到恰好等于当前的 \(i\)，堆顶即答案。

## 4. 真实解法
### 4.1 符号表（表格：符号 / 类型尺寸 / 含义 / 初值 / 助记）

| 符号 | 类型尺寸 | 含义 | 初值 | 助记 |
| :--- | :--- | :--- | :--- | :--- |
| \(m,n\) | `int` | ADD 个数、GET 个数 | 读入 | 行数就是 \(n\) |
| `a[0..m)` | `int[200005]` | 插入序列 | 读入 | 下标从 0 |
| `u[0..n)` | `int[200005]` | 第 \(i+1\) 次 GET 时已插入的个数 | 读入 | 单调不降 |
| `lo` | `priority_queue<int>` 大根堆 | 集合 \(L\) | 空 | 顶 = 第 \(i\) 小 |
| `hi` | 小根堆 | 集合 \(H\) | 空 | 顶 = \(L\) 之外最小 |
| `ptr` | `int` | 下一个待插入的下标 | 0 | 走到 \(u_{i-1}\) 为止 |
| \(i\) | `int`，1…\(n\) | 当前要的是第 \(i\) 小 | — | 也是 `lo` 的目标大小 |

### 4.2 算法步骤

1. 读入 \(m,n,a,u\)。
2. 对 \(i=1\) 到 \(n\)：
   - 当 `ptr < u[i-1]` 时取出 `x=a[ptr++]`。`lo` 空或 `x<=lo.top()` 则进 `lo`，否则进 `hi`。
   - `while (lo.size()>i)` 把 `lo.top()` 拨到 `hi`。
   - `while (lo.size()<i)` 把 `hi.top()` 拨到 `lo`。
   - 输出 `lo.top()`。
3. 每个答案单独一行。

### 4.3 复杂度与验证状态（只写你真实跑出来的数字）

- 时间：每次插入和每次重平衡都是堆操作，总次数 \(O(m+n)\)，复杂度 \(O((m+n)\log m)\)。
- 空间：两个数组 \(O(m+n)\)，堆里元素总数 \(\le m\)。
- 编译：`g++ -O2 -std=c++17 -Wall -Wextra`，标准输出为空，warn=0。
- 对拍：样例 `7 4 / 3 1 -4 2 8 -1000 2 / 1 2 6 6` 输出 `3 3 1 2`；另 5 组边界（单元素、全相等、负数下界、重复的 \(u\)）与 200 组随机（\(m\le 500\)，\(|a_i|\le 2\times 10^9\)，\(u\) 合法单调）标程对 `nth_element` 暴力，共 206 组，随机段耗时 4.986s。
- 满数据计时：\(m=n=2\times 10^5\)、\(u_i=i\)，标程 0.209s，输出 200000 行。

## 5. 示例代码
### 5.1 标程（`P1801.cpp`）

```cpp
//
// 题目：P1801 黑匣子
// https://www.luogu.com.cn/problem/P1801
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{200005};

int m,n;
int a[mxn],u[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>m>>n;
	for(int i=0;i<m;++i)
		cin>>a[i];
	for(int i=0;i<n;++i)
		cin>>u[i];

	priority_queue<int> lo;
	priority_queue<int,vector<int>,greater<int>> hi;
	int ptr{0};
	for(int i=1;i<=n;++i)
	{
		while(ptr<u[i-1])
		{
			int x{a[ptr++]};
			if(lo.empty()||x<=lo.top())
				lo.push(x);
			else
				hi.push(x);
		}
		while((int)lo.size()>i)
		{
			hi.push(lo.top());
			lo.pop();
		}
		while((int)lo.size()<i)
		{
			lo.push(hi.top());
			hi.pop();
		}
		cout<<lo.top()<<'\n';
	}
	return 0;
}
```
