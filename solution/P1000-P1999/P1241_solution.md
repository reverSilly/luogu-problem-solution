# P1241 括号序列 · 题解

## Part 1 — 重新读题

**输入**：一行，仅由 `(、)、[、]` 四种字符构成的字符串 $s$（长度 $n \le 100$）。

**配对规则**（题目给定，按从左到右扫描）：
1. 逐个看每个字符。
2. 遇到一个**右括号**，去它的**左边**找**离它最近**的、**还没被配对的**左括号：
   - 如果这个左括号与它"对应"（`(` 配 `)`、`[` 配 `]`），就把它俩配成一对；
   - 如果左边的未匹配左括号**不存在**，或者**类型不对应**，那么**这一个右括号**配对失败（注意：被考察的那个左括号**仍然保持未匹配状态**，后面别的右括号还能再找它）。
3. 遇到一个**左括号**，它本身不触发任何动作，只是"登记"成一个候选未匹配左括号，等待将来的某个右括号来配。

**补全规则**：配对结束后，对**每一个**没有配对的括号，在它的**旁边**（左边或右边）各加一个字符，使得它和这个新字符正好构成一对匹配括号。

**输出**：补全后的完整字符串（必须是平衡括号序列）。

**约束**：$n \le 100$。这意味着算法复杂度几乎不受限，$O(n^2)$ 甚至 $O(n^3)$ 都绰绰有余；但更关键的是**补全方式不唯一时，判题怎么判**——这道题是**特殊判题（SPJ）**，任何合法的平衡括号序列补全都算对。所以我们的目标不是"凑出某种特定答案"，而是"凑出**任意一个**合法答案"，并且**构造过程本身必须保证结果合法**。

## Part 2 — 思路推导（像人一样思考）

### 第 1 步：先把"配对规则"这个特殊机制搞清楚

读题时最容易踩的坑是**第 2 条规则的"类型不对应"分支到底会发生什么**。我把规则逐字翻译一下，并立刻问"它和标准括号匹配有什么不同"。

> 标准括号匹配（比如 `(` 和 `[` 混在一起）：遇到右括号，弹出栈顶左括号，类型不符就判非法。

> **本题**：遇到右括号，只看"离它**最近**的**未匹配**左括号"。类型不符时，**这个右括号放弃**（配对失败），但**那个左括号不被弹出**——它还在栈里，继续等下一个右括号。

这两条规则的区别非常关键。举个小例子看差异：

- 字符串 `([)]`。
  - 扫到 `(`：入栈，未匹配。
  - 扫到 `[`：入栈，未匹配。
  - 扫到 `)`：离它最近的未匹配左括号是 `[`，**类型不对应** → `)` 配对失败，但 `[` **仍在栈里**。
  - 扫到 `]`：离它最近的未匹配左括号是 `[`，**类型对应** → `[` 和 `]` 配对成功。
  - 最终：只有 `)` 未匹配。

如果按"标准匹配"来想，`([)]` 早就被判非法、`[` 被弹出了，结果就错了。**所以本题的配对过程不是"贪心弹出"，而是"扫描+跳过"，一个右括号可能跨过多个未匹配左括号去找自己真正对应的那个。** 这是第一个必须刻在脑中的性质。

### 第 2 步：想清楚"配对结束后的状态长什么样"

既然右括号会"跨过"不匹配的左括号，那配对结束后，"未匹配的括号"分布在什么位置？我先在纸上画几个例子，归纳一下。

- 例子 A：`([)]`（见上）。未匹配的只有位置 2 的 `)`。
- 例子 B：`[(`。扫 `[` 入栈；扫 `(` 入栈。结束。两个左括号都未匹配。
- 例子 C：`)`。扫 `)`，左边没有未匹配左括号，失败。未匹配的是这个 `)`。
- 例子 D：`[]`。`]` 配 `[`，全匹配，无未匹配。

观察规律：

**观察 1：未匹配的括号，要么是"孤立的左括号"，要么是"孤立的右括号"。** 一个左括号未匹配，当且仅当从它出发向右找不到一个"类型对应、且中间没有任何已配对括号挡路"的右括号；一个右括号未匹配，当且仅当从它出发向左找不到这样的左括号。这个性质由规则 2 直接保证：右括号只会和"最近的未匹配左括号"配对，所以一旦配上了，中间的左括号一定已经被别的右括号配走了（否则那个"最近的"才会是它）。

**观察 2（核心）：配对过程结束后，整个字符串可以被看成一串"片段"的拼接，其中：**
- **已配对的片段**：形如 `X ... Y`，其中 `X` 是左括号、`Y` 是它对应的右括号，中间是任意内容（已配对的或别的片段）。
- **未配对的片段**：单个孤立括号。

这个观察把问题从"一堆零散括号"提升成了"片段结构"，下一步我就靠它。

### 第 3 步：先解一个简化版——"如果全是同一种括号呢？"

为了让大脑放松，先假设字符串里**只有 `(` 和 `)`**。这时规则 2 退化成"遇到 `)` 就配最近的未匹配 `(`"，就是经典匹配。配对结束后的未匹配括号是什么形态？

- 任何未匹配的 `(` 都**在右边**（因为它右边没有 `)` 来配，说明它后面全是左括号或者已经配完的，否则会被配）。
- 任何未匹配的 `)` 都**在左边**（同理，它左边没有未匹配 `(` 可配）。

更精确地说：**未匹配的右括号一定出现在未匹配的左括号左边**（在"位置序"意义上）。也就是说，未匹配括号从左到右看，一定是"一段右括号 + 一段左括号"的形状。

**给简化版补全**：
- 未匹配的 `)`：在它**左边**加一个 `(`。
- 未匹配的 `(`：在它**右边**加一个 `)`。

这样每个孤立括号都被包成一对，结果一定是平衡的。简化版到此打通。

### 第 4 步：加回"两种括号"的增量，找经典技巧

现在回到两种括号。难点是：未匹配的 `)` 旁边要加的左括号是 `(` 还是 `[`？未匹配的 `[` 旁边要加的右括号是 `]` 还是 `)`？**类型必须和它自己对应**（`(` 配 `)`、`[` 配 `]`），这个没悬念。

真正的难点藏在**"加在左边还是加在右边"**。我一开始的直觉是：

> 右括号 → 加在左边；左括号 → 加在右边。（和简化版一致）

但这个直觉在两种括号下**会出错**。我构造一个反例验证。

**反例**：`([)]`（见 Part 2 第 1 步）。未匹配的只有位置 2 的 `)`（类型 `)`）。按"右括号加在左边"：

```
原串：  ( [ ) ]
         0 1 2 3
未匹配：   ·  ) ·
加在左边： ( ( [ ) ]   ← 在位置 2 的 ) 左边插一个 (
```

结果是 `(([])` 吗？让我仔细写：原串字符 `(、[、)、]`，在位置 2 的 `)` **左边**插一个 `(`，得到 `(、[、(、)、]`，即 `([() ]` → 写成连续字符串是 `([() ]`，去掉空格 = `([() ]`……

我把它按位置排出来：位置 0=`(`，位置 1=`[`，然后插入的 `(`，然后位置 2=`)`，位置 3=`]`。连起来是 **`([() ]`** = `([() ]`，即 `(` `[` `(` `)` `]` = **`([() ]`**。

等一下，我要仔细写：`(` + `[` + `(` + `)` + `]` = **`([() ]`**，去掉我手抖加的空格，就是 **`([() ]`**……

直接写出来：**`([() ]`** 这个串里字符依次是 `(`, `[`, `(`, `)`, `]`。

现在判断它是否平衡。用栈验证：
- `(` → 栈 `[(`
- `[` → 栈 `[(`, `[`
- `(` → 栈 `[(`, `[`, `(`
- `)` → 弹 `(`，匹配。栈 `[(`, `[`
- `]` → 弹 `[`，匹配。栈 `[(`
- 结束，栈非空（还剩 `(`）→ **不是平衡括号序列！**

**直觉失败了。** 问题出在哪？

### 第 5 步：解剖失败，归纳失败模式

`([() ]`（即 `([()]`，少了一个右括号）不平衡，是因为**最外面的那个 `(`（位置 0）永远等不到它的 `)`**。我本来只给位置 2 的 `)` 配了左括号，却忘了位置 0 的 `(` 其实……

等等，让我重新核对配对结果。`([)]` 的配对：
- `(` 位置 0：入栈。
- `[` 位置 1：入栈。
- `)` 位置 2：最近未匹配左括号是 `[`（位置 1），类型不对应 → `)` 失败，`[` 保留。
- `]` 位置 3：最近未匹配左括号是 `[`（位置 1），类型对应 → 配对。

所以位置 0 的 `(` **从未被配对**！我前面说"未匹配的只有位置 2 的 `)`"是**错的**。重新数：未匹配的是 **位置 0 的 `(`** 和 **位置 2 的 `)`**，共两个。

修正后按"左加右、右加左"补全：
- 位置 0 的 `(`（左括号）→ 右边加 `)`。
- 位置 2 的 `)`（右括号）→ 左边加 `(`。

原串位置：`(`, `[`, `)`, `]`。
- 在位置 0 的 `(` **右边**插 `)`：变成 `(`, `)`, `[`, `)`, `]`。
- 在位置 2 的 `)`（现在的第 3 个字符）**左边**插 `(`：变成 `(`, `)`, `[`, `(`, `)`, `]`。

连起来：**`()[()]`**。

验证平衡：`(` `)` 一对；`[` `(` `)` `]` 一层嵌套，合法。**`()[()]` 是平衡括号序列！** 反例被修正了。

**教训**：我第一遍漏数了未匹配的左括号，导致补全不完整。这说明**正确性不依赖"加在左边还是右边"的微妙选择，而依赖"每一个未匹配括号都必须被处理到"**。那"加在左/加在右"到底能不能乱选？

### 第 6 步：证明"补全方向可以随意选，只要每对孤立括号各自成对"

**命题（关键引理）**：设配对过程结束后，未匹配的括号集合为 $U$。对 $U$ 中**任意**一个未匹配的左括号 $L$，在 $L$ 的**紧右侧**插入与它对应的右括号 $L'$；对 $U$ 中**任意**一个未匹配的右括号 $R$，在 $R$ 的**紧左侧**插入与它对应的左括号 $R'$。这样得到的新串一定是平衡括号序列。

**证明**：

我把"插入"这件事和"原来的配对结构"分开看。原串 $s$ 在配对过程结束后，它的字符分成两类：
- **已配对的括号**：参与某一对 $(X_i, Y_i)$（$X_i$ 左、$Y_i$ 右，类型对应，且 $X_i$ 在 $Y_i$ 左边）。
- **未配对的括号**：集合 $U$，每个都是孤立的。

关键观察：**已配对的括号集合本身，已经构成了一组合法的嵌套/并列结构。** 这一点需要证明。

**子引理 1**：配对过程结束后，把所有已配对的括号按位置排好，它们构成一个**合法的括号序列骨架**（即存在一种方式使已配对括号自身平衡）。

**证明子引理 1**：我用"配对过程构造出的配对对"本身来论证。配对过程产生的每一对 $(X_i, Y_i)$ 满足：
- $X_i$ 在 $Y_i$ 左边；
- $X_i, Y_i$ 类型对应；
- 在 $X_i$ 和 $Y_i$ 之间，**任何括号要么是已被配对的（且它们的配对对完全落在 $X_i$ 与 $Y_i$ 之间，或完全在 $X_i$ 左边或 $Y_i$ 右边），要么是未配对的孤立括号**。

后一点（"配对对的区间不会交叉"）是括号匹配的经典性质：如果 $(X_a, Y_a)$ 和 $(X_b, Y_b)$ 满足 $X_a < X_b < Y_a < Y_b$（区间交叉），那么配对过程不可能同时产生这两对。证明：假设 $X_a < X_b$。当配对过程处理 $Y_a$ 时，$X_a$ 是未匹配的（否则它已配对，矛盾），且 $X_b$ 在它右边。处理 $Y_a$ 时，算法找的是"$Y_a$ 左边最近的未匹配左括号"。$X_a$ 在它左边且未匹配，但**$X_b$ 更近**。如果 $X_b$ 与 $Y_a$ 类型对应，算法会配 $(X_b, Y_a)$ 而不是 $(X_a, Y_a)$，矛盾；如果类型不对应，算法**跳过 $X_b$**，继续向左找，仍可能配到 $X_a$。所以"最近"的规则保证了：**$Y_a$ 配到的左括号，是 $Y_a$ 左边第一个"类型对应且未匹配"的左括号**。

这个"跳过不匹配"的细节让"区间不交叉"的证明需要更仔细。我换一个更直接的角度。

**换角度证明子引理 1（用"栈的不变量"）**：

我重新定义配对过程，把它显式地用栈写出来（这其实是题目规则的等价实现）：

```
维护一个栈 stk，里面是"未匹配的左括号"的位置（从底到顶位置递增）。
从左到右扫 s 的每个位置 i：
  若 s[i] 是左括号：把 i 压入 stk。
  若 s[i] 是右括号：
     从 stk 顶往下找，第一个"类型与 s[i] 对应"的位置 j：
        若找到：把 j 弹出（配对成功），并记下 pair(j)=i, pair(i)=j。
        若找不到（栈里没有类型对应的）：s[i] 配对失败，stk 不动。
```

**等等，这个"从顶往下找第一个类型对应的"对吗？** 题目说"离它**最近**的**未匹配**左括号"，如果类型不对应就失败——**不是跳过继续找更远的**，是**直接失败**！

我重读题目：

> 对于当前的字符，如果它是一个右括号，考察它与它左侧离它**最近**的**未匹配**的的左括号。如果该括号与之对应……则将二者配对。**如果左侧未匹配的左括号不存在或与之不对应，则其配对失败。**

**是"只看最近的一个"，不对应就直接失败，不继续往更远的找！** 我前面的栈模拟写错了。

这改变了整个分析。我重新来。

**修正后的配对过程（严格忠实题目）**：

```
维护一个栈 stk，存"未匹配的左括号"的位置（从底到顶位置递增，栈顶=最近）。
从左到右扫 s 的每个位置 i：
  若 s[i] 是左括号：把 i 压入 stk。
  若 s[i] 是右括号：
     若 stk 非空 且 stk 顶的位置 j 处的 s[j] 与 s[i] 类型对应：
        弹出 j，pair(j)=i, pair(i)=j（配对成功）。
     否则（栈空，或栈顶类型不对应）：
        s[i] 配对失败，stk 不动（栈顶左括号仍然未匹配，继续等）。
```

这个实现才是题目规则的忠实翻译。它和"标准匹配"的区别在于：**类型不对应时，右括号失败但不弹栈**，所以栈顶那个"类型不对应的左括号"会一直待在栈顶，挡住后面所有右括号（直到……它永远等不到对应类型的右括号了，因为它被自己挡住了）。

**这个性质极其重要**：一旦某个左括号 X 入栈，且它上面又压了一个"类型不同"的左括号 Y，那么 Y 在栈顶，任何来配 Y 的右括号如果类型不对，Y 就永远留在栈顶；而如果来的右括号类型对 Y 对应，Y 被弹出，X 又露出来。所以**栈顶始终"垄断"匹配权**，下面的左括号只有在栈顶被弹出后才轮到。

这其实回到了**标准括号匹配的栈行为**，只是"类型不对应不报错、右括号直接失败"。也就是说：**未匹配的左括号 = 配对过程结束时栈里剩下的所有左括号**；**未匹配的右括号 = 配对过程中"失败"的那些右括号**。

好，现在子引理 1 要在这个**正确的**配对过程下重新证明。

**重新证明子引理 1**：配对过程结束后，已配对的括号构成合法括号序列骨架。

我用"栈的进出顺序"论证。配对过程里，每次成功配对都是"弹出栈顶 j，配上当前 i"。这保证了：

**性质 P（不交叉）**：任意两对 $(X_a,Y_a)$、$(X_b,Y_b)$，要么 $Y_a < X_b$（$a$ 对完全在 $b$ 对左边，并列），要么 $X_a < X_b < Y_b < Y_a$（$b$ 对完全嵌在 $a$ 对里，嵌套）。不可能出现 $X_a < X_b < Y_a < Y_b$（交叉）。

**证明性质 P（用反证法）**：

反设存在交叉，即 $X_a < X_b < Y_a < Y_b$。考虑配对过程处理 $Y_a$ 的时刻。

- 此刻 $X_a$ 已入栈（因为 $X_a < Y_a$）。
- 此刻 $X_b$ 也已入栈（因为 $X_b < Y_a$）。
- 谁在栈顶？栈里从底到顶位置递增。$X_a < X_b$，所以 $X_a$ 先入栈，$X_b$ 后入栈，$X_b$ 在 $X_a$ 上面（更靠近栈顶），除非 $X_b$ 在此之前已被弹出。
- $X_b$ 是否可能在 $Y_a$ 之前被弹出？$X_b$ 被弹出当且仅当某个 $Y_b' < Y_a$ 与它配对。但配对是"栈顶匹配"，$X_b$ 要成为栈顶才能被弹。在 $X_a < X_b$ 且 $X_a$ 未弹出之前，$X_b$ 压在 $X_a$ 上，$X_b$ 是栈顶候选。若 $Y_b' < Y_a$ 与 $X_b$ 配对成功，则 $X_b$ 弹出，配对对是 $(X_b, Y_b')$，其中 $Y_b' < Y_a < Y_b$，这与"$(X_b,Y_b)$ 是 $X_b$ 的配对对"矛盾（一个左括号只能配一个右括号）。所以 $X_b$ 在 $Y_a$ 之前**没有被弹出**。
- 因此处理 $Y_a$ 时，$X_b$ 在栈顶（或栈顶之上只有比 $X_b$ 更晚入栈的、位置在 $X_b$ 和 $Y_a$ 之间的左括号，但那些左括号若还在，它们的位置 $> X_b$，更靠近 $Y_a$，才是真正栈顶）。

这里我需要更严谨：栈顶是"位置最大的未匹配左括号"。设处理 $Y_a$ 时栈顶位置为 $t$。$t \ge X_b$（因为 $X_b$ 未弹出，位置在栈里）。若 $t > X_b$，则存在位置 $t \in (X_b, Y_a)$ 的左括号在栈顶，$Y_a$ 考察的是 $t$ 而非 $X_b$。若 $s[t]$ 与 $Y_a$ 对应，则 $(t, Y_a)$ 配对，$Y_a$ 被 $t$ 配走——但我们要的是 $Y_a$ 被 $X_a$ 配走（因为 $(X_a,Y_a)$ 是配对对）。矛盾，除非 $t = X_a$。

所以为了让 $(X_a, Y_a)$ 成为配对对，必须：处理 $Y_a$ 时，**栈顶恰好是 $X_a$**，且 $s[X_a]$ 与 $Y_a$ 对应。这意味着 $X_a$ 之上（位置更大）的左括号**都已被弹出**。但 $X_b$ 满足 $X_a < X_b < Y_a$，若 $X_b$ 在 $Y_a$ 之前已被弹出，则它配了一个 $Y_b' < Y_a$，与 $X_b$ 最终配 $Y_b > Y_a$ 矛盾。所以 $X_b$ 没被弹出，$X_b$ 仍在栈里且 $X_b > X_a$，$X_b$ 在 $X_a$ 上面，栈顶 $\ge X_b > X_a$。**栈顶不可能是 $X_a$**。矛盾！

**故交叉不可能，性质 P 成立。** ∎

性质 P 说明已配对的括号形成合法的嵌套/并列结构（这是 Catalan 结构的刻画：不交叉的配对 = 合法括号骨架）。

**继续证明主命题**：

现在，未匹配的括号 $U$ 分两类：
- $U_L$：结束时栈里剩下的左括号（位置集合）。
- $U_R$：过程中失败的右括号（位置集合）。

我对 $U_L$ 中每个 $L$，在 $L$ 紧右插入 $L'$（对应右括号）；对 $U_R$ 中每个 $R$，在 $R$ 紧左插入 $R'$（对应左括号）。

**断言**：新串是平衡括号序列。

**证明**：我用"把新串看作对原配对骨架的'打补丁'"来论证。

考虑原串 $s$ 加上所有已配对括号构成的骨架 $K$。由性质 P，$K$ 的已配对括号本身合法（不交叉嵌套）。现在 $U$ 里的孤立括号"穿插"在 $K$ 的骨架之间。

关键：我要证明插入的 $L'$ 和 $R'$ 不会破坏合法性，且最终所有括号都被配平。

**换一种更直接的论证（逐括号配对验证）**：

我直接构造新串的一个合法配对方案，证明它平衡。

新串 $s'$ 的字符 = 原串 $s$ 的字符 + 插入的 $L'$ 们 + 插入的 $R'$ 们。

我定义 $s'$ 的一个配对方案 $\pi$：
1. 对每个**已配对对** $(X_i, Y_i)$（原串中），在 $s'$ 中让 $X_i$ 与 $Y_i$ 配对（它们的相对位置不变，类型对应，合法）。
2. 对每个 $L \in U_L$，让 $L$ 与刚插入的 $L'$ 配对（$L'$ 紧挨在 $L$ 右边，类型对应，合法）。
3. 对每个 $R \in U_R$，让 $R$ 与刚插入的 $R'$ 配对（$R'$ 紧挨在 $R$ 左边，类型对应，合法）。

这个方案 $\pi$ 给 $s'$ 的**每个**字符都分配了恰好一个配对对象（原串字符：已配对的走 1，未配对的走 2/3；插入字符：走 2/3）。

**剩下只需证明 $\pi$ 是"不交叉"的**，则 $s'$ 是合法括号序列（不交叉的完全配对 = 平衡括号序列，这是标准事实）。

证明 $\pi$ 不交叉：

$\pi$ 里的配对对分三种来源，我检查所有可能的交叉。

**(a) 两个已配对对之间**：由性质 P，不交叉。✓

**(b) 一个已配对对 $(X_i,Y_i)$ 与一个"补丁对"**：

补丁对分两种：$L$-$L'$（$L \in U_L$）和 $R'$-$R$（$R \in U_R$）。

- **$(X_i,Y_i)$ 与 $L$-$L'$**：$L'$ 紧挨在 $L$ 右边，$L'$ 的位置 $= L$ 的位置 $+1$（在原串位置意义下，插入后 $L'$ 在 $L$ 下一格）。$L$-$L'$ 是一个"紧邻对"，占据原串中 $L$ 的位置和其右邻。
  - 若 $L$ 在 $[X_i, Y_i]$ 区间外（$L < X_i$ 或 $L > Y_i$）：$L$-$L'$ 与 $(X_i,Y_i)$ 位置不相交，不交叉。
  - 若 $L$ 在 $(X_i, Y_i)$ 之间（$X_i < L < Y_i$）：$L$-$L'$ 完全落在 $(X_i,Y_i)$ 内部，是**嵌套**（$X_i < L < L' < Y_i$），合法，不交叉。
  - $L$ 不可能等于 $X_i$ 或 $Y_i$（$L$ 是左括号且未配对，$X_i$ 已配对；$Y_i$ 是右括号）。

- **$(X_i,Y_i)$ 与 $R'$-$R$**：$R'$ 紧挨在 $R$ 左边，$R'$ 的位置在 $R$ 的左邻。
  - 类似地，$R$ 若在 $(X_i,Y_i)$ 之间，则 $R'$-$R$ 完全落在内部（$X_i < R' < R < Y_i$），嵌套，合法。
  - $R$ 若在区间外，不相交。

**(c) 两个补丁对之间**：

- $L_1$-$L_1'$ 与 $L_2$-$L_2'$（$L_1, L_2 \in U_L$）：都是紧邻左括号对。设 $L_1 < L_2$。则 $L_1 < L_1' < L_2 < L_2'$（因为 $L_1'$ 在 $L_1$ 右邻，且 $L_1' < L_2$，因为 $L_2 > L_1$ 且 $L_1'$ 只占 $L_1$ 右边一格，$L_1'$ 的位置 $< L_2$ 的位置，除非 $L_2 = L_1+1$，但即使如此 $L_1'$ 在 $L_1$ 和 $L_2$ 之间，$L_1' < L_2$）。所以 $L_1$-$L_1'$ 与 $L_2$-$L_2'$ 是**并列**（$L_1' < L_2$），不交叉。
- $R_1'$-$R_1$ 与 $R_2'$-$R_2$（$R_1, R_2 \in U_R$）：设 $R_1 < R_2$。$R_1'$ 在 $R_1$ 左邻，$R_2'$ 在 $R_2$ 左邻。$R_1' < R_1 < R_2' < R_2$？需要 $R_1 < R_2'$，即 $R_2$ 的左邻 $> R_1$，即 $R_2 \ge R_1+1$，成立（$R_2 > R_1$）。所以并列，不交叉。
- $L$-$L'$ 与 $R'$-$R$（$L \in U_L$，$R \in U_R$）：这是最需要小心的。
  - 若 $L < R$：$L$-$L'$ 在左，$R'$-$R$ 在右。要交叉需 $L < R' < L' < R$ 或 $R' < L < R < L'$。
    - $L'$ 在 $L$ 右邻，$R'$ 在 $R$ 左邻。$L < R$。
    - 若 $L' < R'$：即 $L$ 的右邻 $< R$ 的左邻，即 $L+1 < R-1$，即 $R \ge L+2$，中间至少隔一格。此时 $L < L' < R' < R$，**嵌套**（$L$-$L'$ 嵌在 $R'$-$R$ 里），合法。
    - 若 $L' = R'$：即 $L+1 = R-1$，$R = L+2$，$L'$ 和 $R'$ 在同一位置？不可能，$L'$ 在 $L$ 右（位置 $L+1$ 的新格），$R'$ 在 $R$ 左（位置 $R-1=L+1$ 的新格）——它们会**冲突在同一格**。但实际上插入是"在各自旁边各加一个"，$L$ 右边加一个、$R$ 左边加一个，若 $L$ 和 $R$ 中间只隔一个位置（$R=L+2$，中间是位置 $L+1$ 的某个字符），那 $L'$ 和 $R'$ 都要插到"位置 $L+1$ 附近"。
      - 等等，这里"旁边"到底怎么定义？题目说"在其旁边添加一个字符"。如果 $L$ 右边紧邻的是 $R$（$R=L+1$），那 $L$ 的"右边"就是 $R$ 的位置，$L'$ 插到 $L$ 和 $R$ 之间。而 $R$ 的"左边"也是 $L$ 的位置，$R'$ 插到 $L$ 和 $R$ 之间。两个都插到 $L$、$R$ 之间的同一个缝隙！
      - 这时 $L$ 和 $R$ 是**相邻的未匹配括号**，$L$ 在左、$R$ 在右，类型：$L$ 是左括号、$R$ 是右括号。它们相邻且都未匹配。$L'$ 插到 $L$ 右、$R'$ 插到 $R$ 左，都在 $L$、$R$ 之间。新串这段变成 $L, L', R', R$ 或 $L, R', L', R$？
      - 插入顺序：我按位置从左到右插入。$L$ 在原位置 $p$，$R$ 在原位置 $p+1$。$L'$ 插到 $p$ 和 $p+1$ 之间（即 $L$ 右），$R'$ 插到 $p$ 和 $p+1$ 之间（即 $R$ 左）。两者都插在同一个缝隙 $p|p+1$。
      - 最终这段 = $L$（位置 $p$）+ [插入的 $L'$ 和 $R'$] + $R$（位置 $p+1$）。缝隙里有两个字符，顺序取决于我插入的次序。
      - 若 $L'$ 在前、$R'$ 在后：$L, L', R', R$。配对：$L$-$L'$（紧邻对），$R'$-$R$（紧邻对）。$L < L' < R' < R$，嵌套，合法。✓
      - 若 $R'$ 在前、$L'$ 在后：$L, R', L', R$。配对：$L$-$L'$，$R'$-$R$。位置序 $L < R' < L' < R$。**交叉！** $L < R' < L' < R$ 意味着 $(L,L')$ 和 $(R',R)$ 交叉。
      
      **所以插入次序影响合法性！** 当 $L$ 和 $R$ 相邻且 $L$ 在左 $R$ 在右时，必须 $L'$ 在前、$R'$ 在后（即 $L, L', R', R$），不能 $R'$ 在前。

      但我之前说"补丁对之间不交叉"时，$L$-$L'$ 与 $R'$-$R$ 在 $L < R$ 且 $L' < R'$ 时是嵌套（$L < L' < R' < R$），这正对应 $L'$ 在前 $R'$ 在后的情形。如果实现时按"从左到右扫描原串，遇到未匹配左括号就在它右边记一个插入、遇到未匹配右括号就在它左边记一个插入"，那么对于相邻的 $L$（左）$R$（右），$L$ 先被扫描到（位置 $p < p+1$），$L'$ 的插入点（$L$ 右 = 缝隙 $p|p+1$）先记录，$R$ 后扫描到，$R'$ 的插入点（$R$ 左 = 缝隙 $p|p+1$）后记录。同一缝隙里，$L'$ 先、$R'$ 后 → $L, L', R', R$，嵌套，合法。✓

      所以**只要插入时按位置从左到右处理、同一缝隙内保持"先左括号的右插、后右括号的左插"的顺序**，就不会交叉。

  - 若 $L > R$（$R$ 在左、$L$ 在右）：对称。$R' < R < L < L'$？$R'$ 在 $R$ 左邻，$L'$ 在 $L$ 右邻，$R < L$。若 $R' < L$（显然，$R' < R < L$），则 $R' < R < L < L'$，$R'$-$R$ 与 $L$-$L'$ 并列，不交叉。✓

综上，**只要插入顺序处理得当（同一缝隙内左括号的右插优先），$\pi$ 不交叉，$s'$ 是平衡括号序列。** ∎

**证明结束。** 结论：对每个未匹配左括号在**紧右**插对应右括号、对每个未匹配右括号在**紧左**插对应左括号，且按位置从左到右处理插入，得到的串一定是平衡括号序列。

### 第 7 步：把证明落回实现——双栈收集插入位置

现在我有了正确的补全方向（左括号→右插、右括号→左插），但实现时还要解决"**插入位置**"的整理。直接在原串上插字符会很乱（尤其同一缝隙多个插入）。更干净的做法是：**先收集"哪些位置要插左括号、哪些位置要插右括号"，最后统一重排输出。**

我定义两个集合：
- $A$：**需要插入左括号的"缝隙"位置集合**。缝隙定义为"在原串第 $i$ 个字符之前"（$i \in [0, n]$，$i=0$ 表示串首，$i=n$ 表示串尾）。对每个未匹配的**右括号** $R$（原位置 $pos_R$），它在 $R$ 左边插左括号 → 缝隙 $pos_R$（即"第 $pos_R$ 个字符之前"）。所以 $A$ = $\{ pos_R : R \in U_R \}$。
- $B$：**需要插入右括号的缝隙集合**。对每个未匹配的**左括号** $L$（原位置 $pos_L$），它在 $L$ 右边插右括号 → 缝隙 $pos_L + 1$（"第 $pos_L+1$ 个字符之前"，即 $L$ 之后）。所以 $B$ = $\{ pos_L + 1 : L \in U_L \}$。

然后输出时，我按缝隙 $i = 0, 1, \dots, n$ 顺序走：
- 在缝隙 $i$，先输出 $A$ 里等于 $i$ 的左括号（全部），再输出原串第 $i$ 个字符（若 $i < n$），再输出 $B$ 里等于 $i$ 的右括号（全部）。

**等等，这个输出顺序对吗？** 让我用 `([)]`（位置 0=`(`,1=`[`,2=`)`,3=`]`）验证。未匹配：位置 0 的 `(`（$U_L$）、位置 2 的 `)`（$U_R$）。

- $A = \{pos_R\} = \{2\}$（位置 2 的 `)` 要在缝隙 2 插左括号）。
- $B = \{pos_L+1\} = \{0+1\} = \{1\}$（位置 0 的 `(` 要在缝隙 1 插右括号）。

输出按缝隙 0..4：
- 缝隙 0：$A$ 里有 0 吗？无。输出原串第 0 字符 `(`。$B$ 里有 0 吗？无。→ 输出 `(`。
- 缝隙 1：$A$ 里有 1 吗？无。输出原串第 1 字符 `[`。$B$ 里有 1 吗？有 → 输出 `)`。→ 输出 `[])`…… 等一下，`[` 然后 `)`，是 `[)`。

- 缝隙 3：$A$ 里有 3 吗？无。输出原串第 3 字符 `]`。$B$ 里有 3 吗？无。→ 输出 `]`。
- 缝隙 4：$A$ 里有 4 吗？无。原串无第 4 字符。$B$ 里有 4 吗？无。→ 空。

连起来：`(` + `[)` + `()` + `]` = **`([() ]`** = `([() ]`，字符 `(`,`[`,`)`,`(`,`)`,`]` = **`([() ]`**……

让我把字符一个个列：缝隙 0 给 `(`；缝隙 1 给 `[`、`)`；缝隙 2 给 `(`、`)`；缝隙 3 给 `]`。
全部连起来：`(` `[` `)` `(` `)` `]` = **`([() ]`** → 写成串：**`([() ]`** 去掉空格 = **`([() ]`**。

直接写：**`(` + `[` + `)` + `(` + `)` + `]` = `([() ]`**…… 我把它老老实实拼：

最终串 = **`([() ]`**，即 **`([() ]`**，6 个字符：`(`, `[`, `)`, `(`, `)`, `]`。

**这不对！** 我前面手算"左加右、右加左"得到的是 `()[()]`（合法），现在按缝隙输出得到 `([)()]`（非法）。**问题出在输出顺序！**

我的缝隙输出规则是"A 里等于 $i$ 的左括号 → 原串第 $i$ 字符 → B 里等于 $i$ 的右括号"。但 `([)]` 的正确合法补全 `()[()]` 的字符是 `(`,`(`,`)`,`[`,`)`,`]`…… 不对，`()[()]` 是 `(`,`)`,`(`,`[`,`)`,`]`？让我写 `()[()]`：`(` `)` `[` `(` `)` `]`？不，`()[()]` = `()` + `[()]` = `(`,`)`,`[`,`(`,`)`,`]`。6 字符：`(`,`)`,`[`,`(`,`)`,`]`。

`([)()]` 验证：`(` 入栈；`[` 入栈；`)` → 栈顶 `[` 不对应，失败…… 但这是补全后的串，它本身要合法。用标准栈验证 `([)()]`：`(`→[`(`；`[`→[`(`,`[`；`)`→ 栈顶 `[` 与 `)` 不匹配 → **非法**。

**所以我的缝隙输出顺序是错的。** 问题在哪？

回到第 6 步的证明。我在证明里说"同一缝隙内左括号的右插优先"，但更根本的问题是：**$A$（插左括号的缝隙）和 $B$（插右括号的缝隙）的相对顺序，以及它们与"原串字符"的相对顺序，必须满足不交叉。**

我重新审视。正确的合法补全 `()[()]`（= `(`,`)`,`[`,`(`,`)`,`]`）是怎么来的？

原串 `([)]` = 位置 0=`(`, 1=`[`, 2=`)`, 3=`]`。
- 位置 0 的 `(` 未匹配（$U_L$）→ 在它**右**插 `)`。

- 缝隙 0（原 0 之前）：空。

所以：
- $B$（插右括号的缝隙）= $\{1\}$（缝隙 1 插 `)`）。✓ 与 $B = \{pos_L+1\} = \{1\}$ 一致。
- $A$（插左括号的缝隙）= $\{2\}$（缝隙 2 插 `(`）。✓ 与 $A = \{pos_R\} = \{2\}$ 一致。

**集合 $A, B$ 是对的！** 错的是**输出顺序**。我之前的输出规则是"缝隙 $i$：先 $A$ 的左括号，再原串第 $i$ 字符，再 $B$ 的右括号"。

对缝隙 1：$A$ 里有 1 吗？无（$A=\{2\}$）。原串第 1 字符 `[`。$B$ 里有 1 吗？有 → `)`。输出 `[`、`)`。
对缝隙 2：$A$ 里有 2 吗？有 → `(`。原串第 2 字符 `)`。$B$ 里有 2 吗？无。输出 `(`、`)`。

所以缝隙 1 输出 `[)`，缝隙 2 输出 `()`。全串：缝隙 0 `(` + 缝隙 1 `[)` + 缝隙 2 `()` + 缝隙 3 `]` = `([)()]`。

但正确的是缝隙 1 应该只输出 `)`（`[` 是原串字符，在缝隙 1 之前还是之后？）。

**啊，我搞混了缝隙和字符的归属！** 缝隙 $i$ 是"第 $i$ 个字符之前"。原串第 $i$ 个字符应该在**缝隙 $i$ 之后、缝隙 $i+1$ 之前**输出。我的输出规则把"原串第 $i$ 字符"放在了"缝隙 $i$"里，导致错位。

正确的输出应该是：

```
对 i = 0 到 n:
   输出 A 里等于 i 的所有左括号       // 缝隙 i 的左括号（在字符 i 之前）
   输出 B 里等于 i 的所有右括号       // 缝隙 i 的右括号（在字符 i 之前）
   若 i < n: 输出原串第 i 个字符      // 字符 i 本身
```

但这样 $A$ 和 $B$ 在**同一缝隙**内的顺序呢？缝隙 $i$ 里既有 $A$ 的左括号又有 $B$ 的右括号时，谁先？

对 `([)]`：$A=\{2\}$，$B=\{1\}$，没有同一缝隙同时含 $A$ 和 $B$ 的情况。所以用"先 $A$ 后 $B$"或"先 $B$ 后 $A$"都无所谓，但字符归属要对。

重算（修正字符归属）：
- $i=0$：$A$ 含 0？无。$B$ 含 0？无。输出原 0 = `(`。→ `(`
- $i=1$：$A$ 含 1？无。$B$ 含 1？有 → `)`。输出原 1 = `[`。→ `)[`
- $i=2$：$A$ 含 2？有 → `(`。$B$ 含 2？无。输出原 2 = `)`。→ `()`
- $i=3$：$A$ 含 3？无。$B$ 含 3？无。输出原 3 = `]`。→ `]`
- $i=4$：$A$ 含 4？无。$B$ 含 4？无。无字符。→ 空

连起来：`(` + `)[` + `()` + `]` = **`() [()]`** → 字符 `(`,`)`,`[`,`(`,`)`,`]` = **`()[()]`** ✓✓✓

**正确！** 是字符归属搞错了。修正后的输出规则：

```
对 i = 0 到 n:
   输出 A 里 == i 的左括号（全部）
   输出 B 里 == i 的右括号（全部）
   若 i < n: 输出 s[i]
```

**同一缝隙内 $A$ 和 $B$ 的顺序**：当缝隙 $i$ 同时含 $A$ 的左括号和 $B$ 的右括号时，按第 6 步证明的结论（相邻 $L$ 左 $R$ 右需 $L'$ 在前 $R'$ 在后），应该是**先 $A$（左括号）后 $B$（右括号）**。我上面 `i=1` 时只有 $B$、`i=2` 时只有 $A$，没触发同缝隙冲突。但为保险，统一"先 $A$ 后 $B$"。

**再验证一个同缝隙冲突的例子**：原串 `()` 去掉配对…… 我构造 `([` 不行（没右括号失败）。构造 `)` 单个：$U_R=\{0\}$，$A=\{0\}$，$B=\emptyset$。
- $i=0$：$A$ 含 0 → `(`。$B$ 含 0？无。输出原 0 = `)`。→ `()`。
- $i=1$：空。
结果 `()` ✓。

构造 `([` 全左括号：$U_L=\{0,1\}$，$B=\{1,2\}$，$A=\emptyset$。
- $i=0$：$A$ 无。$B$ 含 0？无。输出原 0 `(`。→ `(`
- $i=1$：$A$ 无。$B$ 含 1？有 → `)`。输出原 1 `[`。→ `)[`
- $i=2$：$A$ 无。$B$ 含 2？有 → `]`。无字符。→ `]`
连起来 `(` + `)[` + `]` = 字符序列 `(`,`)`,`[`,`]`，即 `()` 紧跟 `[]`，整体为四个字符无间隔拼接（先 `(` 再 `)` 再 `[` 再 `]`）。

用栈验证该串：`(` 入栈 → `)` 弹 `(` 匹配 → `[` 入栈 → `]` 弹 `[` 匹配 → 栈空。**平衡** ✓。

（这个例子同时覆盖了"缝隙 1 只插右括号、缝隙 2 只插右括号"的情形，与 `([)]` 的"缝隙 2 插左括号"形成对照，说明 `insL`/`insR` 两个容器各司其职、互不干扰。）

好，算法彻底验证。现在我要用**代码里的双栈**来实现"收集 $A$ 和 $B$"，而不是"模拟配对过程再回溯"。

### 第 8 步：用双栈直接收集 $A, B$（实现落地）

我重新组织实现。配对过程用栈 `stk` 存未匹配左括号位置。我同时维护：
- `stk`：未匹配左括号的位置栈（栈顶=最近）。
- 配对过程结束后，`stk` 里剩下的 = $U_L$（未匹配左括号）。
- 过程中失败的右括号 = $U_R$。

为了在输出时知道每个缝隙插什么，我用两个**按缝隙位置存**的容器。但更简单：我直接记录"哪些缝隙要插左括号、哪些缝隙要插右括号"，用两个 `vector` 或布尔数组。

由于 $n \le 100$，缝隙数 $n+1 \le 101$，我可以开两个布尔/计数数组 `insL[n+1]`、`insR[n+1]`，标记缝隙 $i$ 是否要插左/右括号（实际上每个缝隙至多插一个，但用计数更稳）。

**配对过程**：
```
栈 stk（存位置）
对 i = 0..n-1:
   若 s[i] 是左括号: stk.push(i)
   若 s[i] 是右括号:
      若 stk 非空 且 s[stk.top()] 与 s[i] 类型对应: stk.pop()   // 配对成功
      否则: insR[i]++                                          // 失败，缝隙 i 插左括号
```

**等等，`insR[i]` 表示"缝隙 i 插左括号"吗？** $A$ = 插左括号的缝隙 = $\{pos_R\}$。$U_R$ 中位置 $pos_R$ 的右括号，要在缝隙 $pos_R$ 插左括号。所以失败时（位置 $i$ 的右括号失败），`insL[i]++`（缝隙 $i$ 插左括号）。我命名搞反了，重命名：
- `insL[i]`：缝隙 $i$ 需要插入的**左括号**数（来自 $U_R$ 中位置 $i$ 的失败右括号）。
- `insR[i]`：缝隙 $i$ 需要插入的**右括号**数（来自 $U_L$ 中位置 $i-1$ 的未匹配左括号，即 $B$ 中 $i = pos_L+1$）。

配对过程结束后：
- $U_L$ = `stk` 里剩下的位置。对每个 $L \in stk$：`insR[L+1]++`。

**输出**：
```
对 i = 0..n:
   输出 insL[i] 个 '('或'['  —— 等等，插入的左括号类型要和配对的右括号对应！
```

**啊，又一个大问题：插入的左括号类型！** $U_R$ 中位置 $i$ 的失败右括号，类型可能是 `)` 或 `]`。要配它，插入的左括号类型必须对应：右括号是 `)` → 插 `(`；右括号是 `]` → 插 `[`。所以 `insL[i]` 不能只存个数，要存**具体类型**。同理 `insR` 存的右括号类型要和配对的左括号对应。

所以改用 `string` 记录每个缝隙要插入的字符：
- `insL[i]`：缝隙 $i$ 要插入的左括号字符串（每个失败右括号贡献一个对应左括号）。
- `insR[i]`：缝隙 $i$ 要插入的右括号字符串。

**重新整理实现**：

```
string insL[n+1], insR[n+1];   // 每个缝隙要插的左/右括号
栈 stk
对 i = 0..n-1:
   若 s[i] 是左括号: stk.push(i)
   若 s[i] 是右括号:
      若 stk 非空 且 match(s[stk.top()], s[i]): stk.pop()
      否则: insL[i] += 与 s[i] 对应的左括号
对 stk 里每个剩下的 L: insR[L+1] += 与 s[L] 对应的右括号
输出: 对 i=0..n: cout << insL[i] << insR[i]; if(i<n) cout << s[i];
```

**但这里 `insL` 和 `insR` 在同一缝隙的顺序**：输出时 `insL[i]` 在前、`insR[i]` 在后。`insL[i]` 可能含多个字符（若同一缝隙多个失败右括号？不可能，缝隙 $i$ 只对应位置 $i$ 那一个右括号，所以 `insL[i]` 长度 $\le 1$）。`insR[i]` 同理长度 $\le 1$（缝隙 $i$ 只对应位置 $i-1$ 那一个左括号）。所以每个缝隙至多各一个字符，顺序"先 $insL$ 后 $insR$"即可。

**验证 `([)]`**：
- $i=0$ `(` 左括号 → stk=[0]。
- $i=1$ `[` 左括号 → stk=[0,1]。
- $i=2$ `)` 右括号 → stk.top()=1，s[1]=`[` 与 `)` 不匹配 → 失败，`insL[2] += "("`。stk 不变 [0,1]。
- $i=3$ `]` 右括号 → stk.top()=1，s[1]=`[` 与 `]` 匹配 → pop，stk=[0]。
- 结束，stk=[0]，$U_L=\{0\}$。`insR[0+1] += ")"` → `insR[1] += ")"`。
- 输出 i=0..4:
  - i=0: insL[0]=空, insR[0]=空, s[0]=`(` → `(`
  - i=1: insL[1]=空, insR[1]=`)`, s[1]=`[` → `)[`
  - i=2: insL[2]=`(`, insR[2]=空, s[2]=`)` → `()`
  - i=3: insL[3]=空, insR[3]=空, s[3]=`]` → `]`
  - i=4: insL[4]=空, insR[4]=空, 无字符 → 空
  - 连起来: `(` + `)[` + `()` + `]` = `()[()]` ✓✓✓

**完美匹配之前的合法答案 `()[()]`！**

**再验证 `)` 单个**：
- i=0 `)` 右括号 → stk 空 → 失败，`insL[0] += "("`。
- 结束 stk 空，$U_L=\emptyset$。
- 输出 i=0: insL[0]=`(`, insR[0]=空, s[0]=`)` → `()`。i=1: 空。
- 结果 `()` ✓

**验证 `[(`**：
- i=0 `[` 左括号 → stk=[0]。
- i=1 `(` 左括号 → stk=[0,1]。
- 结束 stk=[0,1]，$U_L=\{0,1\}$。`insR[1] += "]"`（配 `[`），`insR[2] += ")"`（配 `(`）。
- 输出:
  - i=0: insL[0]空, insR[0]空, s[0]=`[` → `[`
  - i=1: insL[1]空, insR[1]=`]`, s[1]=`(` → `](`
  - i=2: insL[2]空, insR[2]=`)`, 无字符 → `)`
  - 连起来: `[` + `](` + `)` = `[]()` ✓（`[]` 接 `()`，平衡）

**验证 `]` 单个**：
- i=0 `]` 右括号 → stk 空 → 失败，`insL[0] += "["`。
- 输出 i=0: insL[0]=`[`, s[0]=`]` → `[]`。✓

**验证 `([`**：
- i=0 `(` → stk=[0]。
- i=1 `[` → stk=[0,1]。
- 结束 $U_L=\{0,1\}$。`insR[1]+=`)``, `insR[2]+=`]``。
- 输出: i=0 `(`; i=1 `)`+`[` = `)[`; i=2 `]` → 连起来 `(` + `)[` + `]` = 字符序列 `(`,`)`,`[`,`]`（`()` 紧跟 `[]`，合法）✓。

**算法彻底验证，多个样例全部通过。**

## Part 3 — 模式总结

按实际思考顺序提炼可复用的标签：

- **探索机制** — 本题配对规则是"只看最近的未匹配左括号，不对应即失败且不弹栈"，等价于标准括号栈匹配但"类型不符不报错、右括号直接失败"；未匹配左括号=栈剩余，未匹配右括号=过程失败者。
- **考虑简化版** — 先假设只有一种括号，确认"右括号失败在左、左括号剩余在右"的分布，补全方向"右括号左插、左括号右插"在简化版下合法。
- **构造反例** — 用 `([)]` 暴露"漏数未匹配括号"和"插入次序"两个坑，逼出严格证明。
- **证明补全合法性** — 引理：已配对括号不交叉（反证法+栈顶垄断匹配权）；主命题：每孤立左括号右插、孤立右括号左插、按位置序处理同一缝隙（左插优先），则新串不交叉 → 平衡。
- **落地实现（双容器收集插入缝隙）** — 配对过程用位置栈；失败右括号记 `insL[pos]`，栈剩余左括号记 `insR[pos+1]`；输出按缝隙 `i=0..n` 依次打印 `insL[i]`、`insR[i]`、`s[i]`。
- **类型对应** — 插入的括号类型必须与所配括号对应（`(`/`)`、`[`/`]`），故插入容器存字符而非计数。

## Part 4 — 正式解法

### 符号表（Notation Glossary）

| 符号 | 含义 | 初始化 | 助记 |
|---|---|---|---|
| `s` | 输入字符串，长度 `n` | 读入 | 原串 |
| `n` | `s` 的长度 | `s.size()` | 串长 |
| `stk` | 栈，存**未匹配左括号**在原串中的**位置**（0-based），栈顶=位置最大（最近） | 空栈 | L=left，存下标 |
| `pos` | 栈顶元素，即最近未匹配左括号的位置 | — | top |
| `insL[i]` | 缝隙 `i` 需要插入的**左括号**字符串（`i∈[0,n]`，缝隙 `i`="第 `i` 个字符之前"）；由位置 `i` 的**失败右括号**贡献一个对应左括号 | 每个 `insL[i]` 初始空串 `""` | L=左括号插入 |
| `insR[i]` | 缝隙 `i` 需要插入的**右括号**字符串；由位置 `i-1` 的**未匹配左括号**（配对结束后栈剩余）贡献一个对应右括号 | 每个 `insR[i]` 初始空串 `""` | R=右括号插入 |
| `match(a,b)` | 判定左括号 `a` 与右括号 `b` 类型对应（`(`↔`)`、`[`↔`]`） | — | 对应关系 |
| `pairOf(c)` | 给定括号字符 `c`，返回与它匹配的那个括号字符（`(`→`)`，`)`→`(`，`[`→`]`，`]`→`[`） | — | 取对应 |

**缝隙语义**：缝隙 `i` 表示"在原串第 `i` 个字符**之前**的位置"，`i=0` 是串首之前，`i=n` 是串尾之后。原串第 `i` 个字符（`i<n`）位于缝隙 `i` 与缝隙 `i+1` 之间。

### 算法步骤

1. **读入** `s`，令 `n = s.size()`。
2. **配对扫描**（左→右）：维护位置栈 `stk`。对每个位置 `i∈[0,n)`：
   - 若 `s[i]` 是左括号（`(` 或 `[`）：`stk.push(i)`。
   - 若 `s[i]` 是右括号（`)` 或 `]`）：
     - 若 `stk` 非空 且 `match(s[stk.top()], s[i])` 为真：`stk.pop()`（配对成功）。
     - 否则（`stk` 空，或栈顶类型不对应）：`s[i]` 配对失败，令 `insL[i] += pairOf(s[i])`（在缝隙 `i` 记录一个与 `s[i]` 对应的左括号）。
3. **处理栈剩余**：配对扫描结束后，`stk` 中每个位置 `L` 都是未匹配左括号，令 `insR[L+1] += pairOf(s[L])`（在缝隙 `L+1` 记录一个与 `s[L]` 对应的右括号）。
4. **按缝隙输出**：对 `i = 0, 1, …, n` 依次：
   - 打印 `insL[i]`（缝隙 `i` 的左括号，若有）；
   - 打印 `insR[i]`（缝隙 `i` 的右括号，若有）；
   - 若 `i < n`：打印 `s[i]`。
5. 末尾输出换行。

**正确性**：由 Part 2 第 6 步的主命题保证——每个孤立左括号右插对应右括号、每个孤立右括号左插对应左括号、同一缝隙内左插优先，所得新串的配对方案不交叉，故为平衡括号序列。

**复杂度**：
- 时间：配对扫描 $O(n)$（每位置入栈/出栈各一次，栈操作摊还 $O(1)$）；处理栈剩余 $O(n)$；输出 $O(n + |insL|+|insR|) = O(n)$。总计 $O(n)$。
- 空间：栈 $O(n)$，`insL`/`insR` 共 $O(n)$。总计 $O(n)$。
- 约束 $n \le 100$，复杂度绰绰有余。

**验证状态**：手动验证了 6 个代表性样例——`([)]`→`()[()]`、`)`→`()`、`[`→`[]`、`[`+`(`→`[]()`、`]`→`[]`、`([`→`(`,`)`,`[`,`]` 四字符拼接（`()` 紧跟 `[]`）——全部输出合法平衡括号序列。算法为题目规则的忠实实现+已证明的合法补全，未做暴力对拍（$n\le100$ 且逻辑已严格证明）。

## Part 5 — 示例代码

```cpp
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{105};

char s[mxn];
string insL[mxn],insR[mxn];

bool isL(char c){return c=='('||c=='[';}
bool match(char l,char r){return (l=='('&&r==')')||(l=='['&&r==']');}
char pairOf(char c)
{
	if(c=='(')
		return ')';
	if(c==')')
		return '(';
	if(c=='[')
		return ']';
	return '[';
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	string t;
	cin>>t;
	int n=t.size();
	for(int i=0;i<n;++i) 
		s[i]=t[i];

	vector<int>stk;
	for(int i=0;i<n;++i)
	{
		if(isL(s[i]))
			stk.push_back(i);
		else
		{
			if(!stk.empty()&&match(s[stk.back()],s[i]))
				stk.pop_back();
			else
			{
				char c=pairOf(s[i]);
				insL[i]+=c;
			}
		}
	}
	for(int L:stk)
	{
		char c=pairOf(s[L]);
		insR[L+1]+=c;
	}

	for(int i=0;i<=n;++i)
	{
		cout<<insL[i]<<insR[i];
		if(i<n) 
			cout<<s[i];
	}
	cout<<'\n';
	return 0;
}
```

**实现要点**：
- `stk` 用 `vector<int>` 当栈（`push_back`/`pop_back`/`back()`），存位置下标。
- `insL`/`insR` 是 `string` 数组，每个缝隙至多追加一个字符，故直接 `+=` 字符即可（`string += char`）。
- 输出严格按"缝隙 `i`：先 `insL[i]`、再 `insR[i]`、最后 `s[i]`（若 `i<n`）"，保证同一缝隙内左插优先，避免交叉。
- 复杂度 $O(n)$，$n\le100$ 下瞬间完成。
