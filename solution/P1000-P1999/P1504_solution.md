# P1504 积木城堡

> 标签：动态规划 DP / 枚举 / 背包 DP · 难度：普及/提高-
> 本地题面：`P1504.md`（$n\le 100$，单座城堡积木 $\le 100$ 块，单块棱长 $\le 100$）。

## 1. 重新读题

**问题重述（人话版）**

有 $n$ 座已经垒好的城堡。第 $i$ 座自下而上有若干块立方体积木，第 $j$ 块的**棱长**是 $a_{i,j}$，这座城堡的原始高度是 $S_i=\sum_j a_{i,j}$。

允许的操作只有一种：从一座城堡里**挪去若干块积木**（剩下的块保持原来的上下相对顺序、不新增、不重排）。要求操作之后 $n$ 座城堡**一样高**，并且这个共同高度要**尽量大**。输出这个最大高度；若不存在正数方案则输出 $0$。

> 一句话版本：**从每座城堡的棱长序列里各挑一个子集（保持原有顺序），使得 $n$ 个子集的和相等且尽量大**。

**题面里容易漏掉的条款**

1. 「一座城堡的高度，是组成它的所有积木的**棱长之和**」$\Rightarrow$ 高度只与"留下了哪些块"有关，与留下几块、块排在哪儿、块是否挨着全都无关。
2. 「下面的积木比上面的积木大或者一样大」这句背景描述 $\Rightarrow$ 它只是解释输入为什么是**从下往上非递增**的一段文学铺垫；并且"抽走中间若干块"后剩下的序列仍然自动满足这个形状规则，所以它**不是**额外约束，代码里没有任何需要检验它的地方。
3. 「用 `-1` 结束」$\Rightarrow$ 每座城堡一行，行长不定，必须以哨兵读法消费掉这个 `-1`，否则会错位读到下一座城堡的数据上。
4. 「如果找不到合适的方案，则输出 $0$」$\Rightarrow$ $0$ 永远合法（全挪空），所以这句真正想说的是"答案为 $0$ 时也要正常输出 $0$，而不是输出 $-1$ 或什么都不做"。**答案恒存在，不存在无解的情况。**
5. 棱长是"非负整数"，明文允许 $0$。棱长为 $0$ 的块是合法输入，代码不能假设 $a_{i,j}\ge 1$。

**数据范围与规模感受**

$$1\le n\le 100,\qquad \text{单座积木数}\le 100,\qquad \text{单块棱长}\le 100 .$$

于是单座城堡的棱长总和 $S_i\le 100\times 100=10^4$，全部城堡的总和也不超过 $10^6$。三个上界都是 $10^2$ 级别，提示的是 $O(n\cdot m\cdot S)$ 这种"三维不大"的做法：$100\times100\times10^4=10^7$，非常宽裕；而任何 $2^{\text{积木数}}$ 的指数做法在 $m=100$ 时必挂。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：一次"挪去"到底改变了什么

先把操作翻译成数学语言。设第 $i$ 座城堡的积木按自下而上编号为 $1,\dots,m_i$（棱长 $a_{i,1},\dots,a_{i,m_i}$）。一次改造相当于选出一个**保留下标集合** $T_i\subseteq\{1,\dots,m_i\}$，被挪走的正是补集。**注意这里 $T_i$ 是原序列的一个子序列的下标集合**，因为剩下的块必须维持原有上下顺序。

**引理 1（高度 = 保留集合的元素和）**

改造后第 $i$ 座城堡的高度为

$$H_i(T_i)=\sum\nolimits_{j\in T_i}a_{i,j}.$$

**证明**：题面明文定义"一座城堡的高度，是组成它的所有积木的棱长之和"，而改造后这座城堡由且仅由 $\{a_{i,j}:j\in T_i\}$ 这些积木组成，故其高度就是这些棱长相加。$\blacksquare$

> 这一步把"挪走若干块"这个动作彻底翻译掉了：题目里唯一剩下的自由度就是每个 $T_i$ 的选择，唯一的输出量就是这些和。

### 2.2 一次归约：从"子序列"降到"子集"

这是本题最关键的简化，也是最容易被人忽略、或者反过来过度纠结的地方。

$a_{i,j}$ 被选中时必须**维持原有上下顺序**——这看起来像一个硬约束（很容易让人联想到最长公共子序列）。但它对我们真正关心的那个量（和）毫无影响：

**引理 2（子序列可达和集合 = 子集和集合）**

记第 $i$ 座城堡的
- 子序列可达集合 $\mathcal R_i=\{\sum_{j\in T}a_{i,j}:\ T$ 是 $\{1..m_i\}$ 的某个子序列下标集$\}$；
- 子集和集合 $\mathcal P_i=\{\sum_{j\in U}a_{i,j}:\ U\subseteq\{1,\dots,m_i\}$ 为任意子集$\}$。

则 $\mathcal R_i=\mathcal P_i$。

**证明**：
- $\mathcal R_i\subseteq\mathcal P_i$：任何子序列下标集 $T$ 本身就是一个子集（"按下标升序排好的子集"），故它是 $\mathcal P_i$ 定义中的一个合法 $U$，两边各自的求和对象相同，值相同。
- $\mathcal P_i\subseteq\mathcal R_i$：任取子集 $U\subseteq\{1,\dots,m_i\}$，把 $U$ 中的元素**按下标从小到大排序**得到有序列表 $j_1<j_2<\dots<j_k$。这个列表天然是原序列的一个子序列（下标严格递增），故 $U$ 是一个合法的子序列下标集 $T$；而加法满足交换律，
  $$\sum_{t=1}^{k}a_{i,j_t}=\sum_{j\in U}a_{i,j},$$
  同一个 $U$ 无论按什么顺序相加，值都一样，故这个值也属于 $\mathcal R_i$。$\blacksquare$

> **为什么这一步值得单独写成引理**：它一次性消掉了"保持顺序"这个约束。很多人看到"只能抽走、不能重排"就去写 LCS（最长公共子序列），那是把题目读错了——见 §2.5 失败 1，那样做出来的答案会明显偏小。**顺序约束只在被询问对象是"序列"时才起作用；一旦问的是"和"，顺序就自动失效了。**

于是问题被改写成一句干净的话：

> 求最大的 $H$，使得每个子集和集合 $\mathcal P_i$ 都包含 $H$。

### 2.3 多城堡：这一步是完全可分离的

**引理 3（全局可行 $\iff$ 每座城堡各自可行）**

高度 $H$ 可以被达成 $\iff$ 对所有 $i\in\{1,\dots,n\}$ 都有 $H\in\mathcal P_i$。因此

$$\text{Ans}=\max\Big(\bigcap_{i=1}^{n}\mathcal P_i\Big).$$

**证明**：
- （$\Rightarrow$）若 $H$ 被达成，则存在一组选择 $T_1,\dots,T_n$ 使得所有城堡的高度都等于 $H$，即 $H=H_i(T_i)=\sum_{j\in T_i}a_{i,j}$ 对每个 $i$ 成立，由 $\mathcal P_i$ 的定义（引理 2 保证 $T_i$ 对应的和落在 $\mathcal P_i$ 里）得 $H\in\mathcal P_i$。
- （$\Leftarrow$）若对每个 $i$ 都有 $H\in\mathcal P_i$，则对每个 $i$ 存在某个子集 $U_i$ 使 $\sum_{j\in U_i}a_{i,j}=H$。关键观察：**这些选择互不干扰**——第 $i$ 座城堡挪走哪些块，既不影响第 $i'$ 座城堡有哪些块可用，也不影响第 $i'$ 座城堡能凑出什么高度，$n$ 座城堡是完全独立的物理对象，唯一把它们绑在一起的只有"最终高度必须相等"这一条全局等式，而这条等式已经被我们吸收成了"同一个 $H$"。于是把 $n$ 个选择 $(U_1,\dots,U_n)$ 拼在一起就是一个合法的整体方案，高度为 $H$。
- 两条合起来说明可行高度集合恰为 $\bigcap_i\mathcal P_i$，取其中最大者即为答案。$\blacksquare$

> **这是整道题的第二个转折点**：原本"让 $n$ 个东西互相迁就、看起来要联合搜索"的问题，被降维成了"$n$ 次彼此独立的计算，最后取一次集合交"。这也是为什么后面能只用一个滚动数组 $f$ 顺序扫一遍就完事——**因为不需要同时保存 $n$ 份可达信息，只需要维护"到目前为止的交集"**。

### 2.4 答案的上界：搜索区间先卡死

**引理 4（答案落在 $[0,\Lambda]$，且必定存在）**

令 $\Lambda=\min_{i}S_i$（$S_i$ 为第 $i$ 座的原始高度），则 $0\le\text{Ans}\le\Lambda$，且 $\text{Ans}$ 一定存在（$H=0$ 恒可行）。

**证明**：
- 上界：任一方案中第 $i$ 座的高度 $H_i=\sum_{j\in T_i}a_{i,j}\le\sum_{j=1}^{m_i}a_{i,j}=S_i$（棱长非负，子集和不超过全集和）。这对每个 $i$ 都成立，故共同高度 $H\le\min_i S_i=\Lambda$。
- 存在性：取 $T_i=\varnothing$ 对所有 $i$，则所有城堡高度都是 $0$，合法。故 $\mathcal P_i$ 都含 $0$，$0\in\bigcap_i\mathcal P_i$，交集非空，最大值存在。$\blacksquare$

由引理 4，最后只需把 $h$ 从 $\Lambda$ 往下枚举，第一个满足 "$h\in\bigcap_i\mathcal P_i$" 的就是答案；若一路降到 $0$ 才命中，就输出 $0$，正好对应题面第 4 条。**这也意味着代码里不需要任何"无解"分支，向下枚举必然在 $h=0$ 处终止。**

### 2.5 剖析几个失败思路（都给出具体反例）

**失败 1：把"一样高"读成"形状一样"，去写最长公共子序列（LCS）。**
这是本题最典型的误读。反例（$n=2$）：第一座 `5 3 -1`，第二座 `4 4 -1`（两座都满足"自下而上非递增"）。
- 按 **LCS（要求最终形状完全相同）**：第一座能剩下的序列只有 $()$、$(5)$、$(3)$、$(5,3)$，第二座只有 $()$、$(4)$、$(4,4)$，两者公共的非空形状**一个都没有**，答案为 $0$。
- 按 **题面（只要求总高度相等）**：第一座可达和 $\{0,3,5,8\}$，第二座可达和 $\{0,4,8\}$，交集 $\{0,8\}$，答案为 $\mathbf{8}$。

两者差了整整 $8$。**判定依据只能是题面原文**：题面说的是"移去一些积木，使得最终每座城堡**都一样高**"，并且专门用黑体注"一座城堡的高度，是组成它的所有积木的棱长之和"——它从头到尾只谈高度这一个标量，从未要求每层的棱长序列一致。$\Rightarrow$ 见引理 2，顺序约束对"和"无效。

**失败 2：先让每座城堡"各自尽量高"，再取 min 或强行对齐。**
反例（$n=2$）：第一座 `3 3 3 -1`（原始高度 $9$，可达 $\{0,3,6,9\}$），第二座 `4 4 -1`（原始高度 $8$，可达 $\{0,4,8\}$）。$\Lambda=8$。
若按"每座在不超过自身高度的前提下尽量高"，第一座取 $9\to$ 退到 $6$，第二座取 $8$，取 $\min$ 得 $6$ —— 但 $6$ **不在**第二座的可达集合里（第二座只能凑 $0,4,8$），这个方案根本不存在。正确答案：交集 $\{0,8\}\cap\{0,3,6,9\}=\{0\}$，输出 $\mathbf{0}$。
$\Rightarrow$ **教训：可达性不是一个可以取 max/min 的标量，必须保留整个布尔集合。**任何"先各自求最优再合并"的贪心都会坠机，因为合并操作（取交集）不保持各自的最优性。

**失败 3：0-1 背包的正序一维写法（把每块积木用了无限多次）。**
这是背包最经典的坑。若把内层写成

```cpp
for(int h=a[j];h<=sum;++h) f[h]=(f[h]||f[h-a[j]]);   // 错:正序 = 完全背包
```

以城堡 `1 3 -1` 为例（真实可达和应为 $\{0,1,3,4\}$）：处理 $a=1$ 时，$h=1$ 置真后，紧接着 $h=2$ 会读到**刚刚被本轮置真的** $f[1]$ 于是把 $2$ 也置真，$h=3$ 又读到刚置真的 $f[2]$，滚下去整个 $[0,4]$ 全真 —— 相当于那块 $1$ 被重复使用了 $4$ 次。

把它放进整题看后果：取 $n=2$，第一座 `1 3 -1`，第二座 `2 -1`。
- 真实：$\mathcal P_1=\{0,1,3,4\}$，$\mathcal P_2=\{0,2\}$，交集 $\{0\}$，答案 $\mathbf 0$。
- 正序错版：$\mathcal P_1$ 被算成 $\{0,1,2,3,4\}$，与 $\{0,2\}$ 的交集为 $\{0,2\}$，答案 $\mathbf 2$ —— 显然 $2$ 是无论如何也凑不出的（第一座只有 $1$ 和 $3$ 两块）。$\Rightarrow$ **内层必须倒序**，证明见引理 5。

**失败 4：把"可达信息"误当作"最优值"。**
与失败 2 同源，但表现形式是编码上的：想用 `int best[i]` 存"第 $i$ 座能达到的最接近 $\Lambda$ 的高度"，最后取 $\min_i best[i]$。§2.5 失败 2 的反例直接判它死刑：$\text{best}_1=6$、$\text{best}_2=8$，$\min=6$，而 $6$ 在第二座不可达。$\Rightarrow$ 必须存**布尔可达数组**并逐座求交。

### 2.6 经典技术：0-1 背包可达性（倒序一维 DP）

现在只需解决一个子问题：给定多重集 $\{a_1,\dots,a_m\}$（$a_j\ge 0$）与上界 $S=\sum_j a_j$，求它能凑出的所有和。这是标准的 **0-1 背包可达性**。

记 $f_j[h]=$ "只用前 $j$ 块，能否凑出高度 $h$"，初值 $f_0[0]=\text{true}$、其余 false，转移为

$$f_j[h]=f_{j-1}[h]\ \ \text{or}\ \ f_{j-1}[h-a_j]\qquad(h\ge a_j).$$

用一维数组滚动压缩时,$j$ 这一维被省略,于是必须**倒序**枚举 $h$。

**引理 5（倒序一维 DP 的正确性）**

上述倒序写法结束后，$f[h]=\text{true}\iff$ 存在子集 $U\subseteq\{1,\dots,m\}$ 使 $\sum_{j\in U}a_j=h$（即 $h\in\mathcal P$），且每块至多被选用一次。

**证明**（对块数 $j$ 归纳，兼证倒序的必要性）：

- **归纳假设**：进入第 $j$ 轮（处理 $a_j$）之前，数组状态恰好等于 $f_{j-1}$。
- **基例**：初始 $f[0]=$ true、其余 false，正是 $f_0$。
- **归纳步**：第 $j$ 轮要把 $f_{j-1}$ 原地改成 $f_j$。由定义 $f_j[h]=f_{j-1}[h]\lor f_{j-1}[h-a_j]$，这是一个"读旧值、写新值"的过程，**右边两个值都必须是尚未被本轮修改过的 $f_{j-1}$**。
  - 倒序（$h$ 从 $S$ 递减到 $a_j$）：处理位置 $h$ 时，所有**更小的位置** $h-a_j<h$ 都还没轮到，故它们存的仍是 $f_{j-1}$；所有**更大的位置** $h'>h$ 虽然已被改写为 $f_j$，但本轮永远不会去读它们（转移只读 $h$ 与 $h-a_j$，两者都不大于 $h$）。因此读到的确实是 $f_{j-1}$。✓
  - 反过来，若正序递增（$h$ 从 $a_j$ 升到 $S$）：处理位置 $h$ 时会读到 $h-a_j<h$，而该位置**在本轮更早的时候已经被改写为 $f_j$** 了，于是转移实际上变成了 $f_j[h]=f_j[h]\lor f_j[h-a_j]$ —— 这正是"第 $j$ 块可以被反复取用"的完全背包转移，等价于允许同一块的棱长累加任意多次，与"每块只有一块"矛盾（反例见 §2.5 失败 3）。✗
- **归纳结论**：$m$ 轮后 $f=f_m$，而 $f_m[h]$ 为真 $\iff$ 存在子集的选择使其和为 $h$（转移的语义就是"第 $j$ 块不选 / 选"的二分支）。$\blacksquare$

**复杂度**：单座 $O(m\cdot S)$ 次布尔或运算；全部城堡 $O\!\left(\sum_i m_i S_i\right)\le O(n\cdot 100\cdot 10^4)=10^7$。空间 $O(S)$ 一个滚动数组 + $O(S)$ 一个交集数组。

### 2.7 越界与状态体检（写代码前的最后一次停顿）

| 量 | 范围 | 上界 | `int` 够？ |
|---|---|---|---|
| $n$、$m_i$、$a_{i,j}$ | 题面给定 | $100$ / $100$ / $100$ | 是 |
| $S_i=\sum a_{i,j}$ | $m_i\cdot\max a$ | $10^4$ | 是 |
| 共同高度 $H\in[0,\Lambda]$ | $[0,\min_i S_i]$ | $10^4$ | 是 |
| 数组尺寸 | $S+5$ 松弛 | `mxh{10005}`、`mxn{105}` | — |

结论：**全程 `int` 足够，无乘法项、无溢出风险**。真正要防的是下面四类**状态污染**（它们都不会崩溃，只会静默给出偏大的错误答案，是最难查的一类）：

1. **交集数组 `ok[]` 的初值必须是全集 `true`**（`fill_n(&ok[0],mxh,true)`）。全局 `bool` 数组默认零初始化为 `false`；若忘了这行，交集恒为空，答案永远输出 $0$。
   > 与本项目风格指南里的移植坑同源：**全局数组默认 0，而不是"全集/无穷"。**凡是语义为"全集/无穷"的数组，一律显式 `fill_n`。
2. **每换一座城堡必须 `fill_n(&f[0],mxh,false)` 重置**。`f` 是滚动复用的；若不重置，上一座的可达高度会残留下来被误当作本座也能达到，答案偏大。
3. **内层必须倒序**（引理 5），否则退化为完全背包。
4. **`-1` 哨兵必须被消费掉**。用 `while(cin>>x&&x!=-1)` 的写法时，`-1` 已被读入并消耗，下一轮循环自然从下一座城堡的第一个数开始。

## 3. 模式总结（Pattern Summary）

**模式名：多集合可行性的「可达性 DP + 逐集合求交」。**

**识别信号**（下次见到这几条就该想到本模式）：

- 要求"多个对象最后**某个标量相等/达到某个共同值**，并且要最大化这个值"。
- 每个对象的操作是"**从中挑选一部分**"（子集 / 子序列 / 删点），并且被优化的标量是**可加的**（和、代价、重量、长度）。
- 各对象的选择**互不干扰**（没有共享资源），唯一的耦合是那一条全局等式。
- 上界 $10^2\sim10^3$ 级别、且总和 $S_i$ 可算 $\Rightarrow$ 可以开布尔数组而不是哈希表。

**可复用套路（三步）**：

1. **explore its property** — 把"挪去/保留"翻译成"选一个下标子集"，确认被问的那个量（高度）只依赖于子集的**和**。
2. **reduce to easier problem** — 利用"加法可交换"把**子序列**约束退化成**子集**约束（引理 2）；再利用"对象间独立"把 $n$ 元联合决策退化成 $n$ 次独立计算 + 一次求交（引理 3）。
3. **classic problem solution** — 子集和的存在性判定 = **0-1 背包可达性**，倒序一维布尔 DP，$O(mS)$；答案的上界用"各自总和的最小值"卡死（引理 4），从大到小扫第一个命中。
4. **maintain the set, not the optimum** — 全程携带布尔集合，绝不压缩成一个标量最优值（§2.5 失败 2、失败 4）。

**同族题 / 同源题**：

- **P1049 [NOIP 2001 普及组] 装箱问题**：一模一样的倒序 0-1 背包可达性，只是对象是单个箱子，问"剩的最小体积"。
- **子集和 / 划分相等的经典题**（LeetCode 416 分割等和子集、POJ 1014 Dividing）：判定"能否把总和均分成两半"，本质上也是这个可达数组。
- **真正的 LCS 家族**：如果本题改一个字——"使得最终每座城堡**形状完全相同**"——那才是 LCS / 最长公共子序列的地盘，此时"加法可交换"不再适用，引理 2 失效，复杂度也完全不同。**判定用哪个的关键提问是：被询问的量对顺序敏感吗？**

**一句话记忆**：多个对象要"凑成同一个值"，就把每个对象的可达值算成一个布尔集合，取交集后从大到小找第一个。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $n$ | `int` | 城堡座数 | 读入 | 题面 |
| `a[j]` | `int [105]` | **当前**这座城堡自下而上第 $j$ 块的棱长（0-based） | 每座读入时覆盖 | 滚动复用，无需二维数组 |
| `m` | `int`（局部） | 当前城堡的积木块数 | $0$ | 读到一个数就 $+1$ |
| `sum` | `int`（局部） | 当前城堡的原始高度 $S_i$ | $0$ | 即 DP 的上界，也是 $\Lambda$ 的候选 |
| `f[h]` | `bool [10005]` | **当前城堡**能否凑出高度 $h$ | 每座重置为全 false，再置 `f[0]=true` | 0-1 背包滚动数组（引理 5） |
| `ok[h]` | `bool [10005]` | **已处理的所有城堡**都能凑出高度 $h$，即 $\bigcap_{i'\le i}\mathcal P_{i'}$ 的特征函数 | **全 true**（必须是全集） | 可达性交集（引理 3） |
| `lim` | `int` | $\Lambda=\min_i S_i$，答案上界 | `inf=1145141919` | 引理 4 |

### 4.2 编号步骤

1. 读入 $n$；`fill_n(&ok[0],mxh,true)` 把交集初始化为全集；`lim=inf`。
2. 对第 $i$ 座城堡（$i=0..n-1$）：
   2.1 令 `m=0, sum=0`；反复 `cin>>x`，只要 $x\ne -1$ 就 `a[m++]=x; sum+=x;`（`-1` 被消耗掉，见 §2.7 第 4 条）。
   2.2 `lim=min(lim,sum)` 更新答案上界。
   2.3 `fill_n(&f[0],mxh,false)` 重置滚动数组，再 `f[0]=true`（一块不留）。
   2.4 对 $j=0..m-1$，内层 **$h$ 从 `sum` 递减到 `a[j]`**：`f[h]=(f[h]||f[h-a[j]]);`。结束后 $f$ 就是 $\mathcal P_i$（引理 5）。注意 $a_j=0$ 时 `f[h]|=f[h]` 是恒等变换，多跑一趟但无害。
   2.5 对 $h=0..\text{sum}$：`ok[h]=(ok[h]&&f[h]);`，把本座的可达集合并入交集。
3. 从 $h=\text{lim}$ 递减到 $0$，第一个满足 `ok[h]` 的就是答案，输出并 `return 0;`。
4. 循环必然在 $h=0$ 命中（`ok[0]` 恒真，引理 4），兜底写 `cout<<0<<'\n';` 即可收尾。

> 第 2.5 步只对 $h\le\text{sum}$ 求交即可：$h>\text{sum}$ 的部分本座必然凑不出（子集和不超过全集和），把 `ok` 在那里残留的 `true` 留着也无所谓——因为最终只在 $[0,\text{lim}]$ 里找答案，而 $\text{lim}\le$ 每一座的 `sum`，这部分区间在每一轮都被真正求交过。

### 4.3 复杂度

- 时间：第 $i$ 座耗 $O(m_i S_i)$，求和得
  $$O\!\left(\sum_{i=1}^{n}m_iS_i\right)\le n\cdot 100\cdot 10^4=10^{7}\ \text{次布尔运算}.$$
- 空间：两个 `bool[10005]` 加一个 `int[105]`，约 $20$ KB，远低于 125 MB 限制。
- 实测（见 §4.5）：最坏规模 $n=100$、$m=100$、棱长全 $100$ 时 $0.035$ 秒。

### 4.4 关键不变量（值得写 `assert` 的地方）

1. `ok[h]` 为真 $\iff$ 对**所有已处理**的城堡 $i'\le i$ 都有 $h\in\mathcal P_{i'}$。
2. `f[h]` 为真 $\iff$ 对**当前**城堡有 $h\in\mathcal P_i$；每轮开头被重置，故不含历史残留。
3. `lim = min(已处理的 S_i) >= 0`，且答案 $\in[0,\text{lim}]$。
4. `ok[0]` 恒为真（空集和恒为 $0$）$\Rightarrow$ 第 3 步的向下枚举必定终止，无需"无解"分支。

### 4.5 验证状态小结

| 项目 | 状态 |
|---|---|
| 官方样例回归 | **通过**：`2 / 2 1 -1 / 3 2 1 -1` $\to$ `3` |
| 随机数据对拍 | **通过**：$3000$ 组随机用例，DP 版与 $2^m$ 子集穷举版输出**逐字节一致**（$n\in[1,6]$，单座 $m\in[0,14]$，棱长 $\in[0,20]$，每座先把随机棱长排序成非递增序列再输出） |
| 边界用例 | **通过**：单座空城堡 $\to 0$；三座全同 `5` $\to 5$；`8` 与 `5 1 1` $\to 0$；`3 3 3` 与 `4 4` $\to 0$（§2.5 失败 2 的反例） |

## 5. 示例代码

### 5.1 主解：0-1 背包可达性 + 逐座求交

```cpp
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{105};           // 单座城堡积木数 <=100 (+5 松弛)
constexpr int mxh{10005};         // 高度上界 100*100 (+5 松弛)
constexpr int inf{1145141919};    // 114514 家族哨兵

int n;
int a[mxn];                       // a[j]=当前城堡自下而上第 j 块的棱长(读入即 0-based)
bool f[mxh];                      // f[h]=当前城堡能否抽出高度 h
bool ok[mxh];                     // ok[h]=此前所有城堡都能抽出 h(可达性交集)

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>n;
	int lim{inf};                 // 答案上界:各城堡原高度的最小值
	fill_n(&ok[0],mxh,true);      // 交集初值为全集;bool 全局默认 false,必须显式填充
	for(int i=0,x,m,sum;i<n;++i)
	{
		m=0;sum=0;
		while(cin>>x&&x!=-1){a[m++]=x;sum+=x;}
		lim=min(lim,sum);         // 共同高度不可能超过任何一座城堡的原高
		fill_n(&f[0],mxh,false);  // 换城堡必须重置,否则残留上一座的可达状态
		f[0]=true;                // 一块不留/全删,高度 0 必可达
		for(int j=0;j<m;++j)
			for(int h=sum;h>=a[j];--h)
				f[h]=(f[h]||f[h-a[j]]);   // 倒序:保证第 j 块至多用一次
		for(int h=0;h<=sum;++h)
			ok[h]=(ok[h]&&f[h]);
	}
	for(int h=lim;h>=0;--h)
		if(ok[h])
		{
			cout<<h<<'\n';
			return 0;
		}
	cout<<0<<'\n';
	return 0;
}
```

**代码结构对照**：`f` 是引理 5 的滚动可达数组（内层倒序），`ok` 是引理 3 的可达性交集，`lim` 是引理 4 的上界，`a/m/sum` 三者每座城堡滚动复用故不必开二维。读入采用 `while(cin>>x&&x!=-1)` 消费掉行尾哨兵，天然支持 `< 100` 块的变长行。`ok[]` 的 `fill_n(true)` 与 `f[]` 的每座 `fill_n(false)` 是 §2.7 里最容易被省掉、代价又最安静的两行。

### 5.2 对照实现：$2^m$ 子集穷举（仅用于小规模对拍）

```cpp
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{105};
constexpr int mxh{10005};
constexpr int inf{1145141919};

int n;
int a[mxn];
bool can[mxh];                    // 当前城堡的子集和可达集合(穷举得到)
bool ok[mxh];                     // 所有城堡可达集合的交集

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>n;
	int lim{inf};
	fill_n(&ok[0],mxh,true);
	for(int i=0,x,m,sum;i<n;++i)
	{
		m=0;sum=0;
		while(cin>>x&&x!=-1){a[m++]=x;sum+=x;}
		lim=min(lim,sum);
		fill_n(&can[0],mxh,false);
		for(int mask=0;mask<(1<<m);++mask)   // 穷举每一块留/删,单座 m<=20
		{
			int h=0;
			for(int j=0;j<m;++j)
				if(mask>>j&1)
					h+=a[j];
			can[h]=true;
		}
		for(int h=0;h<=sum;++h)
			ok[h]=(ok[h]&&can[h]);
	}
	for(int h=lim;h>=0;--h)
		if(ok[h])
		{
			cout<<h<<'\n';
			return 0;
		}
	cout<<0<<'\n';
	return 0;
}
```

两版**输出必须逐字节相同**（已用 $3000$ 组随机数据确认）。这一版的意义在于：它完全绕过了背包转移，直接按定义枚举"每块留还是删"，因此可作为§2.6 引理 5 的独立交叉验证基准 —— 若 DP 版有方向写反、初值写错之类的掩蔽性 bug，这里会立刻暴露。代价是 $O(2^m\cdot m)$，单座 $m\le 20$ 才跑得动，不能提交。

### 5.3 易错点清单

- **忘记 `fill_n(&ok[0],mxh,true)`** $\Rightarrow$ 全局默认 false，交集恒空，答案永远是 $0$。
- **忘记每座 `fill_n(&f[0],mxh,false)`** $\Rightarrow$ 上一座的可达高度残留，答案偏大。
- **内层写成正序** $\Rightarrow$ 完全背包，单块棱长可被累加多次（§2.5 失败 3 的 `1 3` / `2` 反例）。
- **先把棱长累加出 `sum` 再去 DP** 是对的，但若把上界误写成全局 $10^4$ 而不用本座的 `sum`，只是常数浪费，不会错；反过来若上界取得太小则会漏解。
- **把 `-1` 当成数据读进去**（例如先整行读入再手动解析但忘了丢弃结尾） $\Rightarrow$ 高度被减 $1$，答案偏小甚至变负。
- **误读成"形状相同"去写 LCS** $\Rightarrow$ 答案明显偏小（§2.5 失败 1 的 `5 3` / `4 4` 反例给出 $0$ vs $\mathbf 8$）。
- **`cout<<...<<endl;`** 违反本项目风格指南，一律用 `'\n'`。
