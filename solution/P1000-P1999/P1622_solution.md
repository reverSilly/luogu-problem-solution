# P1622 释放囚犯

## Part 1 — 题目理解 (Problem Comprehension)

### 题意简述

$P$ 个牢房一字排开，初始全部满员。名单上有 $Q$ 个牢房编号（升序给出），每天释放其中**一个**（顺序由我们决定，不必按名单顺序）。相邻牢房中的人可以互相传话：某人被释放后，与他在同一段"连续未被释放"的牢房里的人都会知道消息，并于当天集体大吼，需要给每个大吼的人送一份肉。求一个释放顺序，使总送肉人次最少。

### 输入输出格式

- **输入格式**：第一行 $P,Q$；第二行 $Q$ 个升序整数，表示名单。
- **输出格式**：一行一个整数，最少送肉人次。
- **数据规模**：$1\le P\le10^3$，$1\le Q\le100$，$Q\le P$。

### 关键约束分析

1. $Q\le100$，$Q!$ 完全不可行，但 $Q^3=10^6$ 非常宽裕——这几乎是区间 DP 的标准信号。
2. 释放顺序自由，所以"按名单顺序模拟"是错的（样例就是逆序释放的）。真正要决策的是顺序。
3. 一次释放的发火人数取决于"当前仍连成一片的牢房块"，块的大小随释放不断被切断，具有典型的"切分 → 两段独立"结构。
4. 边界：$Q=1$ 时答案可能为 $0$（只关着一个人，释放他时没有别人可传话）；名单可能包含两端（$1$ 或 $P$）。
5. 答案上界 $\le P\cdot Q\le10^5$，`int` 足够。

## Part 2 — 思路推导 (Idea Discovery)

### 第一步：先弄清"发火人数"到底是多少

假设当前还没被释放的牢房里，某人 $k$ 左右两侧一直延伸到最近的"已释放牢房"（或墙）为止都是满的，那么他所在的块就是这段连续满员区间，块内所有人都能收到消息，除他自己外都要吃肉。

于是关键事实是：**一次释放的代价 = 他所在块的大小 $-1$**。块越大，代价越大；这意味着我们应当尽早释放"能把块切小"的人，也就是靠近中间的人。这正是"先切中间"的直觉，但具体最优切法要交给 DP。

### 第二步：用哨兵把"墙"和"名单"统一

在名单两端各加一个哨兵：$a_0=0$（左墙外）、$a_{Q+1}=P+1$（右墙外），中间的 $a_1<\dots<a_Q$ 就是名单。这样每个"尚未释放的连续块"都能写成"夹在两个已释放位置（或哨兵）之间的部分"。

记 $D(i,j)$ 表示"只考虑 $a_i,a_j$ 之间（不含端点）的囚犯，且 $a_i,a_j$ 已被释放（或为哨兵）"这个子问题，$dp[i][j]$ 为它的最小总代价。

### 第三步：一次释放的代价与选择无关

**引理 1（区间内释放的代价恒定）**：在子问题 $D(i,j)$（$j\ge i+2$）中，第一次释放区间内任意一人 $a_k$（$i<k<j$）时，他所在的连续满员块恰为 $[a_i+1,\;a_j-1]$，因此发火人数为
$$w(i,j)=a_j-a_i-2 .$$

*证明*：$a_i$ 与 $a_j$ 都已被释放（哨兵视为已释放），所以块不可能越过它们；而 $D(i,j)$ 的递归定义保证区间内**还没有任何人被释放**（这是该子问题的第一次操作），故 $[a_i+1,a_j-1]$ 全部满员。于是块就是 $[a_i+1,a_j-1]$，大小 $a_j-a_i-1$，去掉被释放的 $a_k$ 本人，发火人数为 $a_j-a_i-2$。注意这个值只与端点有关，与 $k$ 无关。$\square$

这解释了样例：第一刀在 $14$ 号，$w(0,4)=21-0-2=19$；接着在区间 $(0,3)$ 砍 $6$ 号，$w(0,3)=14-0-2=12$；最后在 $(0,2)$ 砍 $3$ 号，$w(0,2)=6-0-2=4$；合计 $19+12+4=35$。

### 第四步：切一刀后左右独立

**引理 2（最优子结构）**：设 $j\ge i+2$，则
$$dp[i][j]=\min_{i<k<j}\bigl(dp[i][k]+dp[k][j]\bigr)+w(i,j).$$

*证明*：任取一个最优释放顺序，它的第一次操作必是某个 $a_k$（$i<k<j$），由引理 1 这一步固定花费 $w(i,j)$。此后 $a_k$ 已空，剩余操作分成两组：一组落在 $(a_i,a_k)$ 内，一组落在 $(a_k,a_j)$ 内。任一时刻，落在左组的释放只受 $a_i,a_k$ 两个空位约束，与右组互不影响——因为 $a_k$ 已被释放，左右两段在物理上已经断开，消息传不过去。故两组的代价分别不少于 $dp[i][k]$ 与 $dp[k][j]$，总代价不少于 $dp[i][k]+dp[k][j]+w(i,j)$。反之，取左组的最优顺序与右组的最优顺序任意交错执行，每个操作的代价与各自子问题中完全相同（引理 1 的块边界不变），故可达该值。两边夹逼即得等号。$\square$

当 $j=i+1$ 时区间内没有人，$dp[i][i+1]=0$。

### 第五步：按区间长度递推

**引理 3（递推顺序正确）**：按 $len=j-i$ 从小到大计算 $dp[i][j]$，则计算到 $dp[i][j]$ 时其依赖的 $dp[i][k]$、$dp[k][j]$ 都已有终值。

*证明*：$k\in(i,j)$ 给出 $k-i<len$ 与 $j-k<len$，两个子区间的长度都严格更小，故在更早的轮次已算完。$\square$

最终答案是 $dp[0][Q+1]$，因为整个监狱就是"哨兵 $0$ 与哨兵 $P+1$ 之间"的子问题，且由引理 1，$w(0,Q+1)=(P+1)-0-2=P-1$：第一个被释放的人，其余 $P-1$ 人全部发火，与样例一致。

## Part 3 — 模式总结 (Pattern Summary)

- `explore its property` — 代价只取决于"当前连续满员块的大小"，与具体是哪一号无关。
- `consider easier version` — 若顺序固定，直接模拟即可；顺序自由才需要决策。
- `explore its property` — 释放一人等于把区间切成两半，且两半此后完全独立（消息传不过去）。
- `classic problem solution` — 加两个哨兵把"墙"与"名单"统一，写出区间 DP $dp[i][j]=\min_k(dp[i][k]+dp[k][j])+w(i,j)$。
- `classic problem solution` — 按区间长度从小到大枚举，保证依赖先算（与石子合并同构）。
- `discuss by category` — $j=i+1$ 的退化区间取 0，作为递推基态。

## Part 4 — 真正的解法 (The Real Solution)

### 符号表 (Notation Glossary)

| 数学符号 | 代码变量 | 含义说明 |
| :--- | :--- | :--- |
| $P$ | `P` | 牢房总数，右哨兵取值 $P+1$ |
| $Q$ | `Q` | 名单人数 |
| $a_i$ | `a[i]` | $a_0=0$，$a_{1..Q}$ 为名单（升序），$a_{Q+1}=P+1$ |
| $dp[i][j]$ | `dp[i][j]` | 释放 $(a_i,a_j)$ 之间所有囚犯的最小代价；$j=i+1$ 时为 0 |
| $w(i,j)$ | `w` | 一次释放的固定代价 $a_j-a_i-2$ |
| $i,j$ | `i`,`j` | 区间左右哨兵下标 |
| $k$ | `k` | 区间内第一个被释放的人的下标 |
| $len$ | `len` | 区间跨度 $j-i$，作为递推的阶段 |
| 无穷 | `inf` | 哨兵值 `1145141919`，仅用于初始化"未计算"状态 |

### 算法步骤

1. 读入 $P,Q$；置 `a[0]=0`、`a[Q+1]=P+1`，读入 `a[1..Q]`。
2. 初始化：所有 $j\le i+1$ 的 `dp[i][j]=0`，其余置 `inf`。
3. 令 `len` 从 $2$ 到 $Q+1$，对每个 $i$（满足 $i+len\le Q+1$）令 $j=i+len$，计算 `w=a[j]-a[i]-2`，并枚举 $k\in(i,j)$ 取 `dp[i][j]=min(dp[i][j],dp[i][k]+dp[k][j]+w)`。
4. 输出 `dp[0][Q+1]`。

### 复杂度分析

- **时间复杂度**：$\mathcal{O}(Q^3)$，$Q\le100$ 时约 $1.7\times10^5$ 次加法取小（含常数），瞬间完成。
- **空间复杂度**：$\mathcal{O}(Q^2)$，即 $101\times102$ 的 `int` 表，约 $40$ KB。

### 正确性验证

引理 1 确定单步代价，引理 2 给出最优子结构（含"两个子问题可任意交错"的可行性），引理 3 保证递推顺序合法，三者合起来即 $dp[0][Q+1]$ 为最小总代价。数值上单步代价 $\le P-1\le999$，总代价 $\le P\cdot Q\le10^5$，`int` 不会溢出；`inf` 只出现在会被覆盖的初值上，不参与加法（$k$ 至少取 $i+1$，两侧子区间长度均小于当前长度，已有有限值）。

## Part 5 — 示例代码 (Example Code)

```cpp
//
// 题目：P1622 释放囚犯
// https://www.luogu.com.cn/problem/P1622
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;

constexpr int mxq{105};
constexpr int inf{1145141919};

int P,Q;
int a[mxq];                        // a[0]=0, a[1..Q]=名单, a[Q+1]=P+1
int dp[mxq][mxq];                  // dp[i][j]：只释放 (i,j) 之间的囚犯的最小代价

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>P>>Q;
	a[0]=0;
	a[Q+1]=P+1;
	for(int i=1;i<=Q;++i)
		cin>>a[i];
	for(int i=0;i<=Q;++i)
		for(int j=0;j<=Q+1;++j)
			dp[i][j]=(j>i+1?inf:0);
	for(int len=2;len<=Q+1;++len)
		for(int i=0;i+len<=Q+1;++i)
		{
			int j=i+len;
			// 区间内还有 a[j]-a[i]-1 人，被放走的那人不喊，故为人数减一
			int w=a[j]-a[i]-2;
			for(int k=i+1;k<j;++k)
				dp[i][j]=min(dp[i][j],dp[i][k]+dp[k][j]+w);
		}
	cout<<dp[0][Q+1]<<'\n';
	return 0;
}
```

### 易错点

1. **代价写成 $a_j-a_i-1$**：那会把被释放的人自己也数进去，答案整体偏大（样例会输出 $38$ 而非 $35$）。
2. **按名单顺序模拟**：题面只说名单是"要释放哪些人"，顺序可自选，模拟固定顺序是错的。
3. **哨兵缺失**：没有 $0$ 与 $P+1$ 就无法表示"贴着墙的那一段"。
4. **递推方向**：必须按区间长度递增，按 $i$ 递增而内层用未算完的状态会得到错值。
5. **初始化**：$j\le i+1$ 必须置 0（区间内无人，代价为 0），其余置 `inf`。
6. **数组下标**：`a` 与 `dp` 都要开到 $Q+2\ge102$，代码用 $105$ 留松弛。
