# P1882 [USACO10OPEN] 接力赛跑 B

> 难度：普及/提高- · 标签：最短路 / 事件模拟

## 1. 重新读题

### 1.1 问题重述（人话版）

$N$ 头牛，时刻 $0$ 只有 $1$ 号牛起跑。牛 $i$ 跑一圈要用 $L_i$ 秒，跑完的瞬间通知名单 $A_{i1},\ldots,A_{i,M_i}$ 里的牛立刻起跑。每头牛最多跑一圈：已经被叫起来过，再被叫就当没听见。比赛结束时间是最后一头真正跑完的牛越过终点的时刻。没被通知到的牛不跑，也不影响答案。

### 1.2 关键约束与规模暗示

- $N\le 1000$，$1\le L_i\le 1000$，$0\le M_i\le N$。边数最多 $N^2=10^6$。
- 通知时刻等于通知者的完成时刻，完成时刻等于它的起跑时刻加 $L_i$，全是正数。
- 同一头牛可能被很多人通知，取最早的那一次。
- 样例五头牛的结束时间是 $14$：牛 $3$ 在时刻 $7$ 被牛 $2$ 叫起，再跑 $7$ 秒。

## 2. 思维链（Chain-of-thought）

### 2.1 把它写成最短路

内部把牛编号改成 $0$ 起。若 $u$ 的名单里有 $v$，就连一条边 $u\to v$。

**引理 1（起跑时刻是最短路）**。令 $st[0]=0$，对 $u\to v$ 定义边权 $w(u,v)=L_u$。则牛 $v$ 的起跑时刻等于从 $0$ 到 $v$ 的最短路长度；不可达的牛从未起跑。牛 $v$ 的完成时刻是 $st[v]+L_v$。答案是所有可达牛的完成时刻的最大值。

**证明**。一条从 $0$ 到 $v$ 的路径 $0=u_0\to u_1\to\cdots\to u_k=v$ 对应一串真实的通知：牛 $u_i$ 在自己跑完时叫醒 $u_{i+1}$。路径长度是 $\sum_{i<k} L_{u_i}$，这正是这串通知把 $v$ 叫起来的时刻。最早的通知就是这些路径里最短的一条。反过来，任何实际发生的叫醒链都是图上的一条路径。不可达意味着不存在从牛 $1$ 传过来的通知链，这头牛不会起跑，题面也不把它算进比赛。$\square$

边权是正的（$L_i\ge 1$），Dijkstra 适用。第一次从堆里弹出 $u$ 时，$st[u]$ 已经是最短路，之后标记 `vis`，忽略更晚的通知，这和「每头牛只跑一圈」一致。自己通知自己时 `vis[u]` 已经是真，不会再入队。

### 2.2 为什么答案不是某条路的长度，而是最大完成时刻

最短路给出的是起跑时刻。牛还要把自己的那一圈跑完才越过终点，所以要加 $L_v$。最后一头完成的牛不一定是起跑最晚的牛：起跑晚但 $L$ 很小，可能先结束。样例里牛 $5$ 在时刻 $8$ 起跑、$9$ 结束，牛 $3$ 在时刻 $7$ 起跑、$14$ 才结束。

### 2.3 对照：按完成顺序扫事件

暴力不建堆。每一轮在「已经起跑、还没发过通知」的牛里，找完成时刻最小的那头，让它发通知。

**引理 2（第一次写上的起跑时刻就是最早的）**。按完成时刻从早到晚发通知时，牛 $v$ 第一次被写上的时刻就是它的最早起跑时刻。

**证明**。通知时刻等于发通知者的完成时刻。算法每次选的都是当前最早的未发通知者，所以通知按时间递增发出。设 $v$ 的最早通知来自 $u$，时刻 $T$。所有完成时刻 $<T$ 的牛都已经发过通知，它们都没有把 $v$ 叫得更早，否则与 $T$ 的最小性矛盾。此后的通知时刻 $\ge T$，不能再改进。$\square$

这是 $O(N^2+N\cdot E)$ 的扫描，和 Dijkstra 不同。$N\le 200$ 的稠密图以及 $N=1000$、每头牛最多通知 $30$ 头的数据都拿它对过。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 叫醒时刻 $=$ 叫醒者的完成时刻 $=$ 起跑时刻 $+L_u$，且只取最早的一次。
- **model as graph** — 边权取源点的 $L_u$，起跑时刻是从牛 $1$ 出发的最短路。
- **consider easier version** — 反复线性寻找下一头跑完的牛来发通知，用来对拍。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 |
| :--- | :--- | :--- | :--- | :--- |
| `g[u]` | `vector<int> [1005]` | $u$ 会通知的牛（$0$ 起） | 读入时 `--v` | graph |
| `len[u]` | `int [1005]` | 跑一圈的时间 | 读入 | length |
| `stt[u]` | `int [1005]` | 最早起跑时刻 | `1145141919`，牛 $0$ 为 $0$ | start |
| `vis[u]` | `bool [1005]` | 是否已经起跑并处理过 | `false` | visited |
| `ans` | `int` | 最大完成时刻 | $0$ | answer |

### 4.2 算法步骤

1. 读入每头牛的 $L_i$、$M_i$ 和名单，名单编号减一后存进邻接表。
2. `stt` 全部填成无穷大，再令 $0$ 号牛的起跑时刻为 $0$，压入小根堆。
3. Dijkstra：弹出时若已访问或时间不是当前最优就跳过；否则用完成时刻 $t+L_u$ 更新答案，并尝试用它去松弛后继的起跑时刻。
4. 输出 `ans`。牛 $1$ 一定跑，答案至少是 $L_1$。

### 4.3 复杂度与验证状态

- **时间**：堆优化 Dijkstra，$O((N+E)\log N)$。$E\le N^2$ 时也可接受。
- **空间**：$O(N+E)$。
- **沙箱对拍**：`g++ -O2 -std=c++17 -Wall -Wextra` 零警告。样例输出 `14`，单牛 `5 0` 输出 `5`。另 $80$ 组 $N\le 200$ 的随机图（含自环和重复通知）与事件扫描一致，共 $82$ 组。$N=1000$、每头牛最多 $30$ 条出边的数据标程耗时 $0.0194\text{ s}$，并与暴力相同。

## 5. 示例代码

### 5.1 标程（`P1882.cpp`）

```cpp
//
// 题目：P1882 [USACO10OPEN] 接力赛跑 B
// https://www.luogu.com.cn/problem/P1882
// 本地对拍验证通过
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{1005};
constexpr int inf{1145141919};

vector<int> g[mxn];
int len[mxn],stt[mxn];
bool vis[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	int n;
	cin>>n;
	for(int i=0;i<n;++i)
	{
		int m;
		cin>>len[i]>>m;
		g[i].clear();
		while(m--)
		{
			int v;
			cin>>v;
			--v;
			g[i].push_back(v);
		}
		stt[i]=inf;
	}
	stt[0]=0;
	priority_queue<pair<int,int>,vector<pair<int,int>>,greater<pair<int,int>>> pq;
	pq.push({0,0});
	int ans=0;
	while(!pq.empty())
	{
		auto [t,u]=pq.top();
		pq.pop();
		if(vis[u]||t!=stt[u])
			continue;
		vis[u]=true;
		int ft=t+len[u];
		ans=max(ans,ft);
		for(int v:g[u])
		{
			if(vis[v])
				continue;
			if(ft<stt[v])
			{
				stt[v]=ft;
				pq.push({ft,v});
			}
		}
	}
	cout<<ans<<'\n';
	return 0;
}
```
