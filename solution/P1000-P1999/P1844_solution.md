# P1844 阅览室

## 1. 重新读题

### 1.1 问题重述（人话版）

阅览室从时刻 $0$ 开到时刻 $T$。共有 $n$ 个读者，按到达时间先后给出。第 $i$ 个读者在 $t_i$ 到达，有 $k_i\le 5$ 本"想看的刊物"，按喜好从高到低排列，每本附带一个"读完所需时间"。

读者的行为规则可以拆成五条：

1. 到达后，从自己**没看过**的最想看的那本开始，依次尝试；当前这本被别人占着，就试下一本。
2. 如果一本都拿不到，他就**开始等待**，并去服务台**登记一次**。登记时刻就是"开始等待的时刻"。
3. 等待期间，一旦有他想要的刊物被还回来（哪怕同时回来好几本），他立刻在其中取自己**最想看**的一本。
4. 看完一本就放回，然后继续找"没看过的最想看的一本"；若又没有，就回到第 2 条（这一段等待的登记时刻不变）。
5. 两人同一时刻想要同一本：**登记早者得**；登记时刻相同，**到达早者得**。

到 $T$ 关门时所有人被请走，不允许再开始阅读。只要**开始**读一本，该刊物的阅读次数就 $+1$，无论最后有没有读完。

求所有刊物被阅读的总次数。

### 1.2 关键约束与规模暗示

- $n\le 100$，$k_i\le 5$：每个读者最多读 $5$ 本，全局"开始阅读"次数不超过 $500$。这提示答案很小，模拟的复杂度可以放开手脚。
- $T$ **没有给出上界**（只知 $t_i<T$）。若按"每一时刻做一步"的写法，$T$ 可能是 $10^9$，必然超时。因此只能用**事件驱动**：状态发生变化的时刻只有"某人到达"与"某人读完一本"两类，总数为 $O(nk)$。
- 到达时间互不相同，因此"到达早"这个第二关键字在全序中是唯一的，不会出现三方平局。
- 刊物编号 $0\le s<1000$，只需开一个 $1000$ 的桶表示"当前空闲份数"。

## 2. 思维链（Chain-of-thought）

### 2.1 先把"人"和"书"的状态机写清楚

这一步是本模拟题的全部难点：规则文字很多，但状态其实很少。

- 一本书只有两种状态：**空闲**，或被**某一个**读者拿在手里。
- 一个读者只有四种状态：
  - `reading`：手里有书，正在读，并且已知"读完时刻"；
  - `waiting`：没书，已登记，记住"登记时刻"；
  - `arriving`：刚到、还没来得及参与分配（转瞬即逝）；
  - `done`：想看的都看完了，走人。
- 每个读者还有一个**只增不减**的"已读集合"，以及由此决定的"当前最想看的未读刊物"。

于是整个系统是确定性的：只要规定了同一时刻的处理顺序，之后完全由输入决定。

### 2.2 为什么不能按到达顺序处理所有人

一个很自然的偷懒想法是：读者是输入按到达时间给的，那就按到达顺序依次让他去抢书。这个想法是错的。

**反例**：$T=13$，三个读者：

- $X$：$t=0$，想看 $(0,10)$、$(1,8)$；
- $Z$：$t=1$，想看 $(1,10)$；
- $Y$：$t=5$，想看 $(1,1)$。

时间线：$X$ 在 $[0,10)$ 读 $0$；$Z$ 在 $[1,11)$ 读 $1$；$Y$ 在 $5$ 到达，书 $1$ 被占，登记 $5$ 后等待；$X$ 在 $10$ 读完书 $0$，想读书 $1$ 但被占，登记 $10$ 后等待。

到 $11$ 时 $Z$ 还书，$X$（登记 $10$）与 $Y$（登记 $5$）同时想要书 $1$。按题面规则，**$Y$ 先登记，$Y$ 得**。$Y$ 在 $[11,12)$ 读完，$12$ 时把书让出，$X$ 又能在 $[12,13)$ 开始读。总次数为 $1+1+1+1=4$。

如果按"到达早者优先"，$X$ 会在 $11$ 抢到书 $1$ 一直占到 $19$，$Y$ 一无所获，总次数只有 $3$。

**结论**：优先级的关键字必须是 $(\text{登记时刻},\ \text{到达时刻})$，而不是单纯的到达时刻。登记时刻可能远晚于到达时刻（$X$ 就是先读了 $10$ 个单位才登记），这正是两者会"交叉"的原因。

### 2.3 登记时刻在整个等待期内不变

题目说"读者**每次在开始等待时**先去服务台做一次登记"。

一个读者已经处于等待状态、只是这一轮没抢到书，他并没有"开始"新的等待，所以登记时刻保持不变。否则会推出荒谬结论：每次还书后，所有没抢到书的人都在同一时刻重新登记，第一关键字全部相等，规则退化成"只看到达时间"——这与题面专门区分"先登记"和"同时登记"的写法矛盾。因此：**登记时刻 = 本次等待开始的那一刻，直到他拿到书为止都不更新**。

### 2.4 同一时刻到底该怎么处理

设当前事件时刻为 $cur$。这一刻可能同时发生很多事：若干人读完并还书、若干人到达。我们的处理顺序是：

1. **还书**：所有 `finish == cur` 的读者把手里的书放回桶里（空闲数 $+1$），自己转入等待，登记时刻 $cur$；
2. **到达**：所有 $t_i==cur$ 的读者进入等待，登记时刻 $cur$；
3. **统一分配**：把所有等待者按 $(\text{登记时刻},\text{到达时刻})$ 排序，依次让每个人取走"他当前最想看的、且空闲的"一本；拿不到的人继续等待。

**引理 1（一次顺序分配即可完成该时刻的全部匹配）**

在时刻 $cur$ 的第 3 步中，按优先级从高到低**只扫一遍**，每人取自己当前最想看的空闲书，得到的分配结果恰好等于题面的规则。

**证明**：

(i) *该时刻可用的书集合在分配开始时已经确定*。第 1 步的还书全部发生在分配之前，而第 3 步内部只会"取走"书、不会"还回"书，所以空闲集合只会变小，不会新增。因此没有"后处理的人反而拿到刚被释放的书"这种情况，扫一遍就够。

(ii) *冲突的判定与题面一致*。考虑一本被多个等待者列入愿望清单的书 $B$。$B$ 的归属只会发生在"某人轮到时把 $B$ 当作自己**当前最想看的空闲书**"的那一刻。设这一时刻轮到的第一个这样的人是 $P$。由于 $P$ 之前没有人拿走 $B$（否则那个人更早就把 $B$ 当作当前目标，与 $P$ 是第一个矛盾），$B$ 在 $P$ 轮到时仍空闲；而 $P$ 在所有"把 $B$ 当作当前目标的人"中排序最靠前。于是拿到 $B$ 的正是这批人里登记最早（同登记则到达最早）的那个，与题面一致。若某人在 $P$ 之前拿走了一本比 $B$ 更想看的书，他本来就没有把 $B$ 当作当前目标，不属于这次冲突。

(iii) *没有冲突的人不受影响*。如果一个人想要的空闲书没有别人竞争，他轮到时书仍在，直接拿走，与题面一致。

(iv) *每个人都取的是最想看的那本*。轮到某人时，他前面的人已按各自最优取走，剩下的空闲集合正是他此刻面对的真实集合，取其中最想看的一本即为题面行为。

综合 (i)~(iv)，一遍顺序分配与题面规则逐本一致。$\blacksquare$

### 2.5 关门时刻的边界

- **不能在 $t\ge T$ 开始新的阅读**：$T$ 时所有人被请走。所以事件循环只处理 $cur<T$ 的时刻；若下一个事件时刻 $\ge T$，直接结束。
- **开始于 $T$ 之前、结束于 $T$ 之后的书仍然计数**：计数发生在"开始阅读"的瞬间。因此允许 `finish` 超过 $T$，只是这类完成事件永远不会被处理（也没必要处理，因为读者已被请走，书还不还都无所谓）。
- 若某人恰在 $T$ 读完，等同于 $T$ 时刻关门，此时也不该再让他借下一本；我们的循环在 $cur\ge T$ 时终止，正好覆盖。

### 2.6 事件驱动的实现

维护一个候选"下一事件时刻"：

$$\text{nxt}=\min\Big(\text{下一位未处理读者的到达时刻},\ \min_{\text{正在阅读且 finish}<T}\text{finish}\Big).$$

若 $nxt\ge T$ 或不存在，结束。否则令 $cur=nxt$，按 2.4 执行。

由于每处理一次至少消费一个"到达"或一个"读完"事件，而这两类事件总数不超过 $n+nk\le 600$，循环次数是 $O(nk)$。

**为什么不会漏掉"等待者突然能拿书"的时刻？** 因为等待者能拿书，只可能是因为某本书被还回来了；还书必然对应某个 `finish` 事件。所以只需要在这些事件时刻重新分配。$\blacksquare$

### 2.7 一个容易写错的细节：读完最后一本的人

某读者在 $cur$ 读完手里的书后，如果还有未读刊物，他要在 $cur$ **立刻**参与本轮分配（他可能马上拿到一本刚被同一时刻别人还回来的书）；如果全部读完，他直接离开，不进入等待队列。代码里用 `any` 判断。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 把读者/刊物抽象成有限状态机；只有"到达"和"读完"两种时刻会改变状态。
- **explore its property** — 登记时刻在整段等待期内固定，它是与到达时刻独立的第一优先级。
- **consider easier version** — 先假设不冲突（每本书同一时刻只被一人想要），模拟退化成单纯的还书/借书；加入冲突后只需要一个全序。
- **exchange argument / priority ordering** — 按 $(\text{登记时刻},\text{到达时刻})$ 的顺序分配，等价于题面的两两冲突规则。
- **classic problem solution** — 离散事件模拟：每次跳到下一个事件时刻，还书 → 到达 → 一次顺序分配。

## 4. 解法说明（The Real Solution）

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 / 来源 | 助记 |
| :--- | :--- | :--- | :--- | :--- |
| `T` | `i64` | 关门时刻 | 读入 | 上界，不参与数组 |
| `n` | `int` | 读者数 | 读入 | $\le 100$ |
| `arr_[i]` | `i64 [105]` | 第 $i$ 人到达时刻（输入已按此升序） | 读入 | arrival |
| `k[i]` | `int [105]` | 第 $i$ 人想看的本数 | 读入 | $\le 5$ |
| `bid[i][j]` | `int [105][5]` | 第 $i$ 人第 $j$ 想看的刊物编号 | 读入 | book id |
| `rt[i][j]` | `int [105][5]` | 读完该书所需时间 | 读入 | read time |
| `rd[i][j]` | `bool [105][5]` | 第 $i$ 人是否已读过自己的第 $j$ 项 | `false` | read |
| `reading[i]` | `bool [105]` | 是否正在阅读 | `false` | — |
| `fin[i]` | `i64 [105]` | 若在阅读，读完时刻 | 分配时写入 | finish |
| `reg[i]` | `i64 [105]` | 本段等待的登记时刻 | 转入等待时写入 | registration |
| `curbook[i]` | `int [105]` | 正在读的刊物编号 | 分配时写入 | — |
| `waiting[i]` | `bool [105]` | 是否在等待队列中 | `false` | — |
| `freecnt[s]` | `int [1005]` | 刊物 $s$ 当前空闲份数 | 全 $1$ | 每本只有一本 |
| `ans` | `i64` | 阅读总次数 | $0$ | 输出它 |

### 4.2 算法步骤

1. 读入 $T,n$ 与全部读者描述（令牌式读入，忽略换行）。
2. 初始化：`freecnt` 全 $1$，所有 `rd/reading/waiting` 置 `false`，`ans=0`，到达游标 `ai=0`，等待表 `wl` 清空。
3. 循环：
   1. 求下一事件时刻 `nxt`：未处理的最小到达时刻，以及所有 `reading` 且 `fin<T` 的最小 `fin`；
   2. 若 `nxt>=T` 或不存在，跳出；
   3. `cur=nxt`；
   4. 处理还书：对所有 `reading && fin==cur` 的人，归还 `curbook`（`freecnt++`），若仍有未读则 `reg=cur`、`waiting=true` 并压入 `wl`；
   5. 处理到达：所有 `arr_==cur` 的人 `reg=cur`、`waiting=true` 并压入 `wl`，`ai` 后移；
   6. 将 `wl` 按 `(reg, arr_)` 升序排序；
   7. 顺序分配：对 `wl` 中每人，找到第一个满足 `!rd` 且 `freecnt[bid]>0` 的偏好 $j$；找到就标记已读、占用该书、置 `reading`、`fin=cur+rt`、`ans++`；找不到就留在新等待表 `nwl`；
   8. `wl=nwl`。
4. 输出 `ans`（每个测试数据一行）。

### 4.3 复杂度

- 事件数 $E\le n+nk=O(nk)$。
- 每个事件：排序等待表 $O(n\log n)$，扫描每人至多 $k$ 项 $O(nk)$。
- 总时间 $O\big(nk\,(n\log n+nk)\big)$；$n\le100,k\le5$ 时不足 $10^6$，可忽略。
- 空间 $O(nk+1000)$。

## 5. 示例代码

```cpp
//
// 题目：P1844 阅览室
// https://www.luogu.com.cn/problem/P1844
// 本地自测通过
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{105};
constexpr i64 inf{1145141919810LL};

i64 T;
int n;
i64 arr_[mxn];
int k[mxn];
int bid[mxn][5],rt[mxn][5];
bool rd[mxn][5];
bool reading[mxn];
i64 fin[mxn];
i64 reg[mxn];
int curbook[mxn];
bool waiting[mxn];
int freecnt[1005];

void solve()
{
	for(int i=0;i<n;++i)
	{
		i64 t;
		int kk;
		cin>>t>>kk;
		arr_[i]=t;
		k[i]=kk;
		for(int j=0;j<kk;++j)
			cin>>bid[i][j]>>rt[i][j];
	}
	fill_n(freecnt,1005,1);
	for(int i=0;i<n;++i)
	{
		for(int j=0;j<k[i];++j)
			rd[i][j]=false;
		reading[i]=false;
		waiting[i]=false;
	}
	i64 ans=0;
	int ai=0;
	vector<int>wl;
	while(true)
	{
		i64 nxt=inf;
		if(ai<n&&arr_[ai]<nxt)
			nxt=arr_[ai];
		for(int i=0;i<n;++i)
			if(reading[i]&&fin[i]<T&&fin[i]<nxt)
				nxt=fin[i];
		if(nxt>=T||nxt==inf)
			break;
		i64 cur=nxt;
		for(int i=0;i<n;++i)
			if(reading[i]&&fin[i]==cur)
			{
				reading[i]=false;
				++freecnt[curbook[i]];
				bool any=false;
				for(int j=0;j<k[i];++j)
					if(!rd[i][j])
						any=true;
				if(any)
				{
					reg[i]=cur;
					waiting[i]=true;
					wl.push_back(i);
				}
			}
		while(ai<n&&arr_[ai]==cur)
		{
			reg[ai]=cur;
			waiting[ai]=true;
			wl.push_back(ai);
			++ai;
		}
		sort(wl.begin(),wl.end(),[](int x,int y){
			if(reg[x]!=reg[y])
				return reg[x]<reg[y];
			return arr_[x]<arr_[y];
		});
		vector<int>nwl;
		for(int id:wl)
		{
			if(!waiting[id])
				continue;
			int best=-1;
			for(int j=0;j<k[id];++j)
				if(!rd[id][j]&&freecnt[bid[id][j]]>0)
				{
					best=j;
					break;
				}
			if(best==-1)
			{
				nwl.push_back(id);
				continue;
			}
			rd[id][best]=true;
			--freecnt[bid[id][best]];
			reading[id]=true;
			curbook[id]=bid[id][best];
			fin[id]=cur+rt[id][best];
			waiting[id]=false;
			++ans;
		}
		wl.swap(nwl);
	}
	cout<<ans<<'\n';
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	while(cin>>T>>n)
		solve();
	return 0;
}
```
