## 1. 重新读题

一句话：**维护一个可重集（员工工资），支持全局加、全局减后删除所有低于下界的元素、以及查询第 k 大**。语义上有四个必须钉死的细节（严格小于、被拒不计数、`F` 越界报 `-1`、最后多一行离职总数），它们会在下面的表格之后逐条展开。

**把故事翻译成一个数据结构问题。** 设当前公司里的员工工资构成一个**可重集** $S$（可重是因为两个人完全可以拿同样的工资，而"第 $k$ 多"要按人头数）。四条命令对应的抽象操作：

| 命令 | 抽象操作 | 朴素实现的代价 |
|---|---|---|
| `I k` | $S\leftarrow S\cup\{k\}$，但若 $k<\text{low}$ 直接丢弃 | $O(1)$ |
| `A k` | $\forall x\in S,\ x\leftarrow x+k$ | $O(|S|)$，**致命** |
| `S k` | $\forall x\in S,\ x\leftarrow x-k$；然后删掉所有 $x<\text{low}$ 的元素 | $O(\lvert S\rvert)$，**致命** |
| `F k` | 求 $S$ 中第 $k$ 大的数（按重数计），$k>\lvert S\rvert$ 时报 $-1$ | 排序 $O(\lvert S\rvert\log)$，**致命** |

**规模数字告诉我们的三件事**（读题时必须把范围和"操作"对上号）：

1. `I` 至多 $10^5$ 条 ⇒ $|S|\le 10^5$；`F` 至多 $10^5$ 条 ⇒ 单次查询必须远快于 $O(|S|)$，"每次排序"这条路一开始就被判了死刑（题面里"对数万个员工进行一次漫长的排序"正是在暗示这一点）。
2. `A` + `S` 合计**只有 100 条**，而且调整量 $\le 10^3$ ⇒ 全局偏移的总变化量被压到 $|\Delta|\le 10^5$；同时"至多 100 次遍历全表"是 $100\times 10^5=10^7$，**居然**可行 —— 这给了 §2.6 那条"不上平衡树"的退路。另外新员工工资 $\le 10^5$ 而 $\text{low}\le 10^9$ ⇒ 只要 $\text{low}>10^5$，所有 `I` 都会被拒；边界 $k=\text{low}$ 必须留下。

**语义上必须钉死的四个细节**（都是历年踩坑点）：

- "低于合同规定的工资下界"= **严格小于**。工资恰好等于下界的人**不离职**；`I k` 的拒绝条件同样是严格 $k<\text{low}$。
- 被拒的新人**不算离职员工**。题面原文："如果某个员工的初始工资低于最低工资标准，那么将不计入最后的答案内。" 他压根没进过档案系统。
- `F` 的 $k$ 超过当前人数输出 $-1$；$F$ 本身不修改集合。
- 输出**行数** = `F` 命令条数 + 1（最后那行离职总数），别漏掉最后一行。

**本地题面没有样例。** `P1486.md` 只有描述 / 输入输出格式 / 数据范围，没有任何 输入-输出 样例对，因此本文的所有验证都用**自造小数据手算**完成（见 §4 验证状态），无法与官方样例对标，也不会假装对拍过。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：全局加减里"共同的部分"能不能剥掉

先看最刺眼的问题：`A`/`S` 要改**所有人**的工资。能不能不改？

观察：所有人被加的是**同一个数**。那么把"大家共同的那部分"抽出来单独记一个数，每个人只记"自己比共同部分多/少多少"，不就行了？

形式化。设一个全局变量

$$\delta\ (\text{代码里叫 `delta`}),\qquad \text{真实工资}(p)=\underbrace{s(p)}_{\text{档案里存的相对值}}+\delta$$

初始 $\delta=0$。三条命令改写为：

- `A k`：$\delta\leftarrow\delta+k$（$s$ 一个都不动）；
- `S k`：$\delta\leftarrow\delta-k$（$s$ 一个都不动）；
- `I k`：新员工真实工资是 $k$，于是给他登记 $s=k-\delta$。

**引理 1（偏移不变量）。** 按上面的规则维护 $\delta$ 与 $s$，则从入职到离职（或到最后）的整个过程中，恒有 $\text{真实工资}=s+\delta$。

**证明**（对命令条数做归纳）。
归纳命题 $P(t)$：执行完前 $t$ 条命令后，对每个在司员工 $p$，其真实工资等于 $s(p)+\delta_t$，其中 $\delta_t$ 是 $\delta$ 在前 $t$ 条命令后的值。

- 基础：$t=0$，公司空，命题空真。
- `A k`：真实工资全体 $+k$，即每人新真实值 $=(s+\delta_t)+k$；命令后 $\delta_{t+1}=\delta_t+k$，$s$ 不变，故 $s+\delta_{t+1}=(s+\delta_t)+k$，逐人成立。
- `S k`：与上同理（$\delta_{t+1}=\delta_t-k$，真实值 $-k$），并且离职判定只影响**集合成员**，不影响留下的人的等式。
- `I k`：新人真实工资为 $k$，登记 $s=k-\delta_t$，则 $s+\delta_t=k$ ✓；其后每一步与上面两条同构。
- `F k`：不改任何量，平凡保持。

由归纳，$P(t)$ 对所有 $t$ 成立。$\blacksquare$ **收益**：`A` 从 $O(|S|)$ 降到 $O(1)$，且**存值 $s$ 一旦登记就永远不再改变**（这句话后面 §2.6 的离线做法全靠它）。代价是"下界"也跟着挪了位置 —— 这是 §2.3 的主题。

> 这一步是**读题后唯一必须立刻做出来的转化**：全局同加同减 + 只比较大小 = 可以整体平移。它是"延迟标记 / 差分数组"思想在集合上的体现，不是本题独有的技巧。

### 2.2 简化版：先假装没有离职机制

把 $\text{low}=-\infty$（或想象老板从不发火、员工从不走），题目退化成：

> 可重集 $S$，操作只有 ①插入一个数；②查第 $k$ 小（第 $k$ 大等价转换）。**在线**、只有 $10^5$ 次操作。

这就是教科书上的**秩序统计（order statistics）**问题，可选的实现只有四类：

| 方案 | 插入 | 查第 k 小 | 备注 |
|---|---|---|---|
| 排序数组 / `multiset`+`advance` | $O(n)$ 搬动 / $O(\log n)$ | $O(1)$ / $O(n)$ | 前者插入太贵；后者**没有**第 k 小，走迭代器是线性的 |
| 树状数组 + 离线离散化 | $O(\log n)$ | $O(\log n)$（倍增） | 需要预先知道所有会出现的值 |
| 平衡树（FHQ/Splay/PBDS） | $O(\log n)$ | $O(\log n)$ | 在线，无需离线 |

"值域线段树"也算第三种的特例（新员工工资 $\le 10^5$，但**相对值** $s=k-\delta$ 可以是负的，值域会因 $\delta$ 而漂移，所以要么整体平移、要么离散化，别直接用 $[0,10^5]$ 当值域 —— 这是一个隐蔽的坑）。

先记住结论：**这道题的骨架是"秩序统计 + 一个全局偏移"**，剩下的麻烦全部来自离职机制。

### 2.3 把离职条件搬到"相对坐标"上

`S k` 之后要走的人满足：真实工资 $<\text{low}$。用引理 1 替换真实工资：

$$s+\delta<\text{low}\iff s<\underbrace{\text{low}-\delta}_{\text{记作 }T}$$

**引理 2（离职判定的相对形式）。** 在任意时刻，在司员工 $p$ 离职当且仅当其存值 $s(p)<T$，其中 $T=\text{low}-\delta$ 只依赖全局量，不依赖 $p$。

**证明**：由引理 1，真实工资 $=s(p)+\delta$。题面条件"真实工资 $<\text{low}$"即 $s(p)+\delta<\text{low}$，两边同减 $\delta$（整数减法，保序且等价）得 $s(p)<\text{low}-\delta=T$。$\blacksquare$

于是 `S k` 变成一个纯数据结构操作：**删掉所有存值 $<T$ 的元素**。但 `A k` 之后**不需要**做任何删除吗？需要检查——见下面的引理。

**引理 3（只有扣款会赶人）。** 执行 `A k`（$k\ge 0$）之后，集合中不存在存值 $<T$ 的元素，前提是执行前不存在。

**证明**：`A k` 只令 $\delta\leftarrow\delta+k$，$k\ge0$，故 $T=\text{low}-\delta$ 变为 $T'=T-k\le T$。执行前所有存值 $s\ge T$（题设前提），故 $s\ge T\ge T'$，即执行后仍无人满足 $s<T'$。$\blacksquare$

注意这里用的是 $k\ge0$。题面说"每次工资调整的调整量不超过 $10^3$"，但没有明文保证 `A k` 的 $k$ 非负；若出现负的 `A`，它本质是扣款，**也必须做一次删除**。本文代码只在 `S` 之后删除，这在"调整量 $\ge0$"的自然语义下由引理 3 保证无副作用（`A` 后必切不出任何人）。加固写法：把删除逻辑抽成一个小函数，在 `A`、`S` 两个分支都调用一次 —— 多出来的那次 `split` 只是切出空片，成本 $O(\log n)$，且 `A`+`S` 总共才 $100$ 条。

**引理 4（离职者构成存值序的前缀）。** 固定时刻，令 $S$ 中元素按存值升序排成序列。则 $\{p:s(p)<T\}$ 恰是该序列的一个**前缀**。

**证明**：设序列第 $i$ 项存值为 $s_i$，$s_1\le s_2\le\cdots\le s_m$。若第 $j$ 项满足 $s_j<T$，则对任意 $i\le j$ 有 $s_i\le s_j<T$，故第 $i$ 项也满足 —— "满足条件"对下标向左侧封闭，这正是前缀的定义。$\blacksquare$

这个"前缀"视角直接决定了实现：**批量删除一段前缀**在平衡树里是一次 `split`，在树状数组里是"把若干个连续排名清零"，都不需要逐人遍历。

### 2.4 剖析一个看似省事的错误做法

有了引理 4，很自然会想："那我干脆**不真删**，只记一个阈值，最后统计有多少人的存值小于阈值就行。" 最常见的具体形态是：

> 错误猜测：令 $M=\max_{\text{所有时刻}}T$（历史上出现过的最大阈值），则离职者集合 $=\{p:s(p)<M\}$，离职总数 $=\# \{p:s(p)<M\}$，`F` 查询时把存值 $<M$ 的人当不存在即可。

直觉来源：$T$ 变大才赶人，"最狠的那一次"应该覆盖了所有被赶的人。**这个猜测是错的**，而且错得很隐蔽，因为它的反例需要"先狠后松再招人"。

**反例（$\text{low}=10$，即本文验证用例 B 的前 5 条命令）**：

| # | 命令 | $\delta$ | $T=\text{low}-\delta$ | 存值集合 | 真实工资 | 该猜测认为 |
|---|---|---|---|---|---|---|
| 1 | `S 10` | $-10$ | $20$ | $\varnothing$ | — | 历史最大 $M=20$ |
| 2 | `A 15` | $5$ | $5$ | $\varnothing$ | — | 阈值回落到 5，但 $M$ 仍是 20 |
| 3 | `I 11` | $5$ | $5$ | $\{6\}$ | $11$ | 该人存值 $6<20$ ⇒ **被判为已离职** |
| 4 | `F 1` | $5$ | $5$ | $\{6\}$ | $11$ | 该猜测输出 $-1$（集合为空） |
| 5 | `S 2` | $3$ | $7$ | $\varnothing$ | — | 此人才真正离职 |

第 4 步的正确答案是 $11$（他在司，工资 $6+5=11\ge10$），而按 $M=20$ 的猜测他"已经走了"。**矛盾来自第 2~3 步**：$\delta$ 上升使阈值 $T$ **回降**，此后招进来的人存值可以小于历史上限 $M$，却因为 $s\ge T_{\text{当前}}$ 而合法在岗。

**引理 5（离职时刻的刻画）。** 对每个被**接受**的员工 $p$（入职时刻 $t_0$，存值 $s$ 从此不再改变），令
$$\tau(p)=\min\{t\ge t_0:\ s<T_t\},\qquad \text{集合为空时 }\tau(p)=\infty .$$
则 $p$ 在时刻 $t$ 在司 $\iff t<\tau(p)$。特别地，$p$ 最终离职 $\iff\tau(p)<\infty$。

**证明**：$\tau(p)$ 按定义就是"第一次使真实工资 $s+\delta_t<\text{low}$ 的时刻"（等价性由引理 2）。题面规定"一旦……低于……就**立刻**离开，并且**再也不会回来**"，即离职是不可逆的一次性事件。分三种情形：
- 若 $t<\tau(p)$：由最小性，对所有 $t'\in[t_0,t]$ 有 $s\ge T_{t'}$，即每一步他的真实工资都 $\ge\text{low}$，从未触发离职条件，故仍在司。
- 若 $t\ge\tau(p)$：他在 $\tau(p)$ 那一步已被删除且不再返回，故不在司。
- 若 $\tau(p)=\infty$：从不触发，永远在司（可视为 $t<\infty$ 恒成立）。
三分支互斥且穷尽，故"$t$ 时刻在司"与"$t<\tau(p)$"完全等价。$\blacksquare$

**推论（把阈值压成一个数必然失败）。** $\tau(p)$ 只看 $p$ **入职之后**的阈值后缀 $\langle T_t\rangle_{t\ge t_0}$，与入职之前的历史无关。上表第 3 步的员工 $s=6$：全历史 $\max_tT_t=20>6$，但他的后缀里 $T$ 只取过 $5$，故 $\tau=\infty$，他在司。反过来，"存值大于等于全历史最大阈值"的人确实绝不可能离职（$s\ge\max_tT_t\ge T_t$ 对所有 $t$ 成立），所以 $\{s<\max T\}$ 是离职者集合的**超集**而非相等 —— 用超集计人数就会**多数**，用例 B 第 4 步把它误判成空集就是这个多数的体现。$\blacksquare$

（这段推导的收获：必须**显式删除**，或者显式记住每个人入职之后的阈值后缀。前者只要一次 split，后者要存时间戳，复杂度还更高 —— 显然选前者。）

顺带排除另外三个更初级的错误：

1. **"插入时判一次就行"**：反例即本文用例 A —— `I 15` 合格，`A 5` 后 $15\to 20$，`S 10` 后回到 $10$（仍留），再 `S 1` 变 $9<10$ 才走。一个人可以在司很久之后才离职，离职判定必须**每次扣款都重做**。
2. **"离职人数在每次删除时累加 $\text{sz}[a]$，等于把 split 切下的大小加起来"** —— 这个其实是对的（每人最多被切走一次），但更容易写错的是"用 `I` 的总条数减去现存人数"：`I` 总条数包含了被拒的人，而题面明确他们不算离职。必须用**被接受**的入职数（用例 A 第 7 步 `I 9` 正是这一格的陷阱）。
3. **"第 $k$ 大就是去重后第 $k$ 个不同值"**：题面问"第 $k$ 多的**员工**拿多少工资"，按人头计。用例 C 的多重集 $\{5,5,8\}$ 中第 2 大与第 3 大都是 $5$；若按去重集合 $\{8,5\}$ 处理，`F 2` 侥幸输出 $5$（对），`F 3` 就会错报 $-1$（应为 $5$），末行人数也会跟着错。

### 2.5 经典解法：一次 split 删掉前缀

**选型。** 需要同时支持三件事：①插入任意存值；②"删掉所有 $<T$"；③查第 $k$ 小。三件事都是 $O(\log n)$ 的经典组合是 **FHQ Treap（无旋平衡树）**：它天然带子树大小 `sz`，`split` 按键值切一刀正好实现②，`kth` 沿 `sz` 走实现③。Splay 也能做（区间翻转那套），但代码更长；PBDS 不支持批量删除前缀（只能逐个 `erase`，见 §2.6 的摊还分析）；线段树需要离线或动态开点。故主线用 FHQ。

**数据结构。** 每个节点存 `(v, w, sz, ls, rs)`：$v$ = 存值（相对工资，可重复），$w$ = 随机堆权（满足堆性质：父 $w<$ 子 $w$），$sz$ = 子树节点总数。二叉搜索性质定为

$$\text{ inorder 升序：} \quad v[\text{左子树}]\le v[x]\le v[\text{右子树}]$$

即"等于"允许出现在左子树或自身，**可重集**由此自然表示。

**引理 6（split 正确性）。** `split(x, key, a, b)` 结束后，$a$ 是 $x$ 中所有 $v\le key$ 的节点组成的树，$b$ 是其余节点组成的树；两棵树的 inorder 相对顺序与原树一致；且 `sz` 全部被正确维护。

**证明**（对 $x$ 的子树大小归纳）。
- 基：$x=0$（空树），$a=b=0$，命题空真。
- 设 $v[x]\le key$：按算法，$a\leftarrow x$，并对 $x$ 的右子树递归切分 `split(rs[x],key,rs[x],b)`。由归纳假设，递归后 $rs[x]$ 是"原右子树中 $\le key$"的部分，$b$ 是"原右子树中 $>key$"的部分。左子树所有值 $\le v[x]\le key$，故全部属于 $a$，算法没有动它 —— 因此 $a$ 恰含 $x$ 的左子树 $+x+$ 右子树中 $\le key$ 者 $=$ 原树中所有 $\le key$ 的节点；$b$ 恰含其余。相对顺序：$a$ 的中序 = 左中序, $x$, 新右中序，与原树中序中这些元素的出现顺序相同 ✓。最后 `pushup(a)` 用两个新子树的 `sz` 重算 $a$ 的根，正确（其余节点的 `sz` 在递归里已按归纳假设修正）。
- 设 $v[x]>key$：对称地 $b\leftarrow x$，递归 `split(ls[x],key,a,ls[x])`；右子树所有值 $\ge v[x]>key$，整片留在 $b$，故 $a$ 恰为"原左子树中 $\le key$"者 $=$ 原树中所有 $\le key$ 者。顺序与 `sz` 同上（`pushup(b)`）。$\blacksquare$

**引理 7（merge 正确性）。** 若 $x$ 的所有键 $\le$ $y$ 的所有键，则 `merge(x,y)` 返回包含两者全部节点的合法 treap，中序为 $x$ 的中序接 $y$ 的中序，`sz` 正确。

**证明**：若一方为空显然。否则 $w[x]<w[y]$ 时把 $y$ 合并进 $x$ 的右子树：因为 $x$ 的右子树所有键 $\le v[x]\le$（$x$ 中所有键）$\le$（$y$ 中所有键），所以 $rs[x]$ 与 $y$ 仍满足"左全 $\le$ 右全"的前提，递归合法；又 $y$ 的堆权全部 $>w[y]>w[x]$，故 $x$ 仍是堆顶，BST 性在 $x$ 处也成立。$w[x]\ge w[y]$ 时把 $x$ 合并进 $y$ 的左子树，对称论证。两种情形都只沿一条根到叶路径下行，路径长度即 treap 期望高度 $O(\log n)$。`pushup` 在回溯时修正 `sz`，故所有被访问过的祖先 `sz` 正确，未访问者未改动仍正确。$\blacksquare$

**引理 8（`kth` 正确性）。** 设 `sz` 维护正确。`kth(rt,k)` 返回中序第 $k$ 个（$1$ 起）节点。

**证明**：在中序（"左、根、右"）视角下，节点 $x$ 的左子树恰含 $x$ 之前的 $\text{sz}[\text{ls}[x]]$ 个元素，故 $x$ 自身的名次是 $\text{sz}[\text{ls}[x]]+1$。三种走法覆盖所有情形：目标名次 $\le\text{sz}[\text{ls}[x]]$ ⇒ 在左子树，名次不变；等于 $\text{sz}[\text{ls}[x]]+1$ ⇒ 就是 $x$；更大 ⇒ 在右子树，名次减去 $\text{sz}[\text{ls}[x]]+1$。每次调用 $x$ 变为严格更深的后代或立即返回，故有限步终止；终止的返回点由上述分解必为目标节点。$\blacksquare$

**第 $k$ 大 → 第 $k$ 小的换算**：存值升序共 $m=\text{sz}[rt]$ 个，降序第 $k$ 大即升序第 $m-k+1$ 小。输出时**必须加回 $\delta$**（引理 1），这是最容易忘的一行。

**引理 9（离职总数 $=$ accepted $-$ 现存）。** 记 `accepted` 为 `I` 命令中"初始工资 $\ge\text{low}$"的条数，`sz[rt]` 为全部命令处理完时的现存人数，则离职员工总数 $=$ `accepted` $-\text{sz}[rt]$。

**证明**：把"曾真正入职"的员工构成集合 $A$，$|A|=$ `accepted`（每个被接受的 `I` 恰好建立一个档案，且每个档案对应唯一员工）。引理 5 说明离职是不可逆一次性事件，且引理 4 保证每次 `S` 的删除把当时所有 $s<T$ 者**一次性**移出树；一个员工一旦被 `split` 切进被丢弃的那一片，就不再出现在任何后续树中，也不会被重复计入（我们根本没有逐个计数）。于是 $A$ 中每个元素在终止时刻恰处于两种状态之一：仍在树中（$\tau=\infty$），或已在某次 `S` 中被切走（$\tau<\infty$，且切走的时刻唯一）。二者不交且并集为 $A$，故"曾离职者数" $=|A|-|\text{仍在树中者}|=$ `accepted` $-\text{sz}[rt]$。$\blacksquare$

> 这条引理是**"差值计数"优于"累加计数"**的原因：累加版本 $\sum\text{sz}[a]$ 也正确，但一旦在 `I` 分支里忘了过滤被拒者、或在 `A` 分支误加一次删除，就会与 `accepted` 的定义打架；用差值只需守住 `accepted` 一个入口。

**插入的重复键处理**：`split(rt, s, a, b)` 按 $v\le s$ 切，会把所有**等于** $s$ 的旧节点留在左片 $a$，新节点插在中间，因此相等键在 inorder 中相邻，第 $k$ 大的名次计算不受影响（用例 C 的第 2、3 大都是 $5$ 即验证）。

### 2.6 归约：不用平衡树也能做（离线 + 树状数组）

再读一遍数据范围里的"$A$ 和 $S$ 的总条数不超过 $100$"——这是一条**极其反常**的提示：`I`/`F` 是 $10^5$ 级，而全局调整只有 $10^2$ 级。命题人（2004 年）显然预设了两种解法：当年标答是平衡树；但今天我们可以利用"调整次数极少 + 存值永不改变"给出更短的码。

**引理 10（存值静态性）。** 每个员工的存值 $s=k-\delta_{\text{入职时刻}}$ 从登记那一步起就不再随任何命令改变。

**证明**：由引理 1 的构造，`A`/`S` 只修改 $\delta$，代码里从不触碰任何 $s$；`F` 不修改任何量；`I` 只新增节点。故 $s$ 在其生命周期内是常量。$\blacksquare$

于是 $\delta$ 的取值序列在**读完输入前就能算出来**（它只依赖 `A`/`S` 与 `I k` 的 $k$ 吗？不依赖 $k$ —— $\delta$ 只被 `A`/`S` 改变，`I` 不改 $\delta$）。这意味着可以**两趟扫描**：

- 第一趟：按顺序模拟 $\delta$，对每条"会被接受"的 `I k` 记录 $s=k-\delta$。被接受的条件是 $k\ge\text{low}$，只涉及输入的 $k$ 与 $\text{low}$，与 $\delta$ 无关，所以第一趟就能判定接受与否。把所有 $s$ 收集起来排序去重，得到离散化数组 $\text{val}_1<\text{val}_2<\cdots<\text{val}_{tot}$。
- 第二趟：用树状数组 $\text{bit}$ 维护"每个排名上当前在司的人数"，$\delta$ 重新从 $0$ 模拟一遍，即可回答 `F`（倍增求第 $k$ 小）与删除。

**关键简化**：同一个存值 $s$ 上的所有人**同生同死**吗？不完全 —— 入职时刻不同，可能一个被某次 `S` 删了，另一个之后才入职。但删除条件只看 $s$ 与当时的 $T$，而**所有存值相同的在司员工必然同时满足 $s<T$**，所以一次删除会把该排名上"当时已在司"的人**全部清零**，之后入职的人再重新累积计数。也就是说：我们只需要"把某个排名的计数清零"这个操作，而**不需要**区分同排名的人各自是谁。

**引理 11（前缀清零的摊还代价）。** 第二趟中，"清零所有满足 $\text{val}_r<T$ 的排名"这一步的**总**执行次数（对所有 `S` 命令求和）不超过 `accepted`。

**证明**：每一次清零动作都作用在一个**当前计数 $>0$** 的排名上（计数为 $0$ 的排名不在这个"活排名"集合里，被循环条件直接跳过）。清零会消灭 $c[r]\ge1$ 个在司员工，而由引理 5，每个员工一生只被消灭一次，故被消灭的员工总数 $\le$ `accepted`。每次清零动作至少消灭一个员工，且消灭后立刻从活排名集合中移除，故动作次数 $\le$ 被消灭的员工总数 $\le$ `accepted` $\le 10^5$。$\blacksquare$

（这里"每个员工一生只被消灭一次"用到了显式删除：若沿用 §2.4 的错误猜测，同一个人会被反复计入，摊还界就不成立了。两条推导互相咬合。）

**复杂度**：第一趟 $O(n+I\log I)$，第二趟 $O(n\log tot)$，空间 $O(n)$。比平衡树好在"零随机化、无递归深度风险"；代价是必须**先把输入全部读进内存**并额外存下每条命令。因为 `A`/`S` 只有 $100$ 条，还存在一个更懒的写法：`S` 之后把整个数组重排一次、`F` 直接下标取，$O(100\cdot I\log I)$ 可行，但 $O(I)$ 的搬动常数在 $10^5$ 规模下并不稳妥，只适合当作校验用的暴力（见 §4.4）。

### 2.7 溢出防护与边界清单

**数值范围要逐项推，不能靠感觉。** 记 $\text{low}$ 为下界，$\delta$ 为全局偏移，$s$ 为存值，$T=\text{low}-\delta$。

| 量 | 由题面得到的界 | 推导 |
|---|---|---|
| $\text{low}$ | $0\le\text{low}\le 10^9$ | 直接给出（本地题面） |
| $\delta$ | $\lvert\delta\rvert\le 10^2\cdot10^3=10^5$ | `A`+`S` 合计 $\le100$ 条，每条调整量 $\le10^3$，$\delta$ 是它们的带符号和 |
| $s=k-\delta$ | $\lvert s\rvert\le 10^5+10^5=2\times10^5$（正常输入） | $k\le10^5$ 且 $\lvert\delta\rvert\le10^5$ |
| $T=\text{low}-\delta$ | $\le 10^9+10^5\approx1.0001\times10^9$ | 仍 $<2^{31}-1\approx2.147\times10^9$ |
| 输出的真实工资 | $\le 10^5+10^5=2\times10^5$；下限可负 | 存值 $+\ \delta$ |

结论：**按本地题面的显式界，$32$ 位 `int` 刚好够用**（最危险的 $T$ 只到 $10^9$ 量级，离 $2\times10^9$ 还有倍数空间）。但有三条理由必须换 `long long`：① 题面还写着"输入的所有数字均在 $32$ 位带符号整形范围内"，这是**兜底承诺**，与"新员工工资 $\le10^5$"是两个层次的约束 —— 若某条 `I k` 的 $k$ 真取到 $-2^{31}$，`int` 版的 $k-\delta$ **直接溢出**；② 上表第 3 行的界只对**被接受**的 `I` 成立（接受要求 $k\ge\text{low}\ge0$），被拒的 $k$ 虽不入树，表达式却仍可能被求值；③ `low-delta-1` 这类"再减一"的写法离 `int` 上界只剩一位数量级的余量，一旦题目把 `low` 上限提到 $2\times10^9$ 就越界，换 `i64` 后这些都不用想。顺序上也应**先判 `k<low` 再算 `k-delta`**，并用 `i64` 存 `k`。

**边界清单**（每条都在 §4 的用例里出现）：

- $k=\text{low}$ 恰好等于下界：`I` 接受、`S` 后不离职（严格小于才走）。→ 用例 A 第 3 步、用例 C 第 1~2 步。
- `F k` 且 $k>\lvert S\rvert$：输出 $-1$。$k=0$ 或负：题面未定义，代码统一按"越界"处理输出 $-1$（更贴近出题人意图，且不改变合法数据的输出）。
- $n=0$：没有任何命令，只输出最后一行 `0`。代码的 `for` 循环自然为空，`accepted=0`、`sz[0]=0`，输出 $0$。✓
- 树为空时的 `S`：`split(0,...)` 返回 $a=b=0$，`rt=0`，安全；全员清空后再 `F`：`sz[rt]=0`，任何 $k\ge1$ 都越界 → $-1$（用例 A 第 6 步）。
- 重复工资：见 §2.5 末尾与用例 C。
- **命名**：题面变量叫 `min`，C++ 里 `min` 是 `std` 的函数名，在有 `using namespace std;` 时声明 `int min` 会冲突（或至少把 `std::min` 遮蔽掉）。本文统一用 `low`。
- `A` 分支是否也要执行删除：见引理 3 的说明；若担心 `A` 带负数，最稳的写法是把删除逻辑抽成一个小函数，在 `A`、`S` 两个分支都调用一次。

## 3. 模式总结（Pattern Summary）

四条可迁移的结论：**①全局偏移 + 相对值存储**（延迟标记）；**②可重集秩序统计的容器选型**；**③"删除所有 $<$ 阈值" = 按 key 切一次前缀**；**④离职人数走"入池 − 现存"的差值**。逐条展开：

**模式 1：全局偏移 / 相对坐标（延迟标记）** —— 识别特征：题面出现"对**所有**元素同时 $+k$ / $-k$"，而查询/删除条件都是"元素之间比较"或"元素与常数比较"。标准动作：设 $\delta$ 为累积调整量，元素只存"自身减去共同部分"的相对值；所有常数阈值都要换算到相对坐标（本题 $T=\text{low}-\delta$），所有输出都要换算回真实坐标（$+\delta$）。同一思想的其它身影：线段树懒标记、差分数组、"前缀和相减"里的基准平移。最容易漏两处：**阈值没跟着平移**（写成 `s<low` 而非 `s<low-delta`）、**输出忘了加回 $\delta$**。

**模式 2：可重集的秩序统计选型表**

| 需求 | 首选 |
|---|---|
| 在线 + 第 k 小 + 批量删前缀 | FHQ Treap（`split` 一刀切） |
| 在线 + 第 k 小 + 单点删 | Splay / PBDS `tree_order_statistics_node_update` |
| 可离线（所有值先能算出来） | 排序去重 + 树状数组 + 倍增找第 k 小 |
| 值域小且固定 | 值域线段树 / 直接桶（本题存值可负，别直接用 $[0,10^5]$） |

本题的**存值静态性**（引理 10）是"可以离线"的根据：一旦 $\delta$ 序列可预计算，所有 $s$ 就都提前已知，于是平衡树可以被离散化替掉。

**模式 3："删除所有 $<T$" = 一次切前缀** —— 引理 4（前缀封闭性）是把 $\lvert S\rvert$ 次删除压缩成 $O(\log)$ 一次的关键。凡是"批量删除满足单调条件的元素"都应先问：**满足条件者是否构成某个序下的前缀？** 是 → 找切点、整片丢弃；否 → 只能逐个删，此时必须补一个摊还界（见引理 11）。

**模式 4：计数走差值** —— "总共走了多少人" = "总共来过多少人" $-$ "现在还有多少人"。前提：个体不可重生（离职不返回）、状态二分裂（在/不在）、入口计数准确（被拒的不算）。它把"在多处累加"的易错代码压成一行减法。

**与"排队 / 升序插入数更高者"类的区别**（本文不属于那一类，说明清楚以免套错模型）：
那一类题目（如"每个人统计排在他前面且比他高的人数"）的解法是**按身高升序插入序列 + 树状数组统计已插入者的位置分布**，其正确性来自"升序插入保证后插入的人都不比先插入的人矮，因此位置编号的相对次序即身高次序"。本题**没有**"位置"概念，也**没有**"统计比自己高的人数"，只有"第 $k$ 大"与"全局加减后批量删除"，因此用的是秩序统计容器 + 偏移，而不是升序插入。两类题目的共同点仅在于"都需要一个能按名次访问的可重集"。
本题也**不涉及任何取模**，题面上没有 MOD 口径，因此不存在"前缀积 / 阶乘逆元"之类的处理；$\text{low}$ 是常数下界，与模数无关。凡看到"记得开 long long 防溢出"的提示，那说的是数值界（§2.7），不是模运算。

**提交前检查清单（按踩坑频率排序）**

1. `F` 的输出有没有 `+delta`？2. 删除阈值是不是 `low-delta` 而不是 `low`？3. 被拒的 `I` 有没有污染"入职总数"？4. 最后那一行离职总数有没有输出？5. `k>|S|`（及 `k<=0`）有没有特判 `-1`？6. 变量名有没有占用 `min`？7. `split` 用的键是 `T-1` 还是 `T`（差一，等号的人该留下）？8. 递归 `split` 之后有没有 `pushup`？

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 | 含义 | 界 / 初值 |
|---|---|---|---|
| `n` | `int` | 命令条数 | $0\le n\le 3\times10^5$ |
| `low` | `i64` | 工资下界（题面写作 `min`，C++ 里冲突，改名） | $0\le \text{low}\le10^9$ |
| `delta` | `i64` | 全局偏移 $\delta$，真实工资 $=$ 存值 $+\ \delta$ | 初 $0$，$\lvert\delta\rvert\le10^5$ |
| `v[i]` | `i64` | treap 第 $i$ 个节点的存值 $s$ | $\lvert s\rvert\le 2\times10^5$（正常输入） |
| `w[i]` | `int` | treap 随机堆权 | `mt19937` 生成 |
| `sz[i]` | `int` | 以 $i$ 为根的子树节点数（= 在司人数的一部分） | `sz[0]=0` |
| `ls[i],rs[i]` | `int` | 左 / 右孩子，$0$ 表示空 | 全局数组零初始化 |
| `rt` | `int` | 树根，空树时 $=0$ | 初 $0$ |
| `cnt` | `int` | 已分配的节点数 $=$ `accepted` | $\le 10^5$，数组 `mxn{100005}` 足够 |
| `accepted` | `int` | 曾**被接受**的入职次数（拒绝的不计） | $\le 10^5$ |
| `T` | `i64` | 相对坐标下的删除阈值 $=\text{low}-\delta$ | $\le 1.0001\times10^9$ |
| `tot` | `int` | （实现 B）离散化后不同存值个数 | $\le$ `accepted` |
| `val[]`,`bit[]`,`c[]` | — | （实现 B）值域、树状数组、每排名当前人数 | — |

### 4.2 编号步骤（实现 A：在线 FHQ Treap）

1. 读 `n`、`low`；置 `delta=0`、`accepted=0`、`rt=cnt=0`。
2. 重复 `n` 次，读一条命令 `op k`：
   1. `op=='I'`：若 `k<low`，**跳过本条**（不建树节点、不增加 `accepted`）；否则 `++accepted`，算 `s=k-delta`，`x=newnode(s)`，`split(rt,s,a,b)`，`rt=merge(merge(a,x),b)`。
   2. `op=='A'`：`delta+=k`。（若担心 $k<0$，此处也执行第 2.3 步的删除；引理 3 说明 $k\ge0$ 时删除必为空，加与不加不影响结果。）
   3. `op=='S'`：`delta-=k`；算阈值 `T=low-delta`；`split(rt,T-1,a,b)`（整数存值使 $v\le T-1\iff v<T$）；`rt=b`，被切下的 `a` 整片丢弃。
   4. `op=='F'`：令 `m=sz[rt]`；若 `k<1 || k>m` 输出 `-1`；否则输出 `v[kth(rt,m-k+1)]+delta`。
3. 全部命令结束后输出 `accepted-sz[rt]`（引理 9）。

不变量（每步之后都成立，供检查）：
- $I_1$：树中节点 $\leftrightarrow$ 在司员工，一一对应，且节点 $v$ 恒等于该员工的存值；
- $I_2$：`accepted` $=|$ 树中节点 $|+$ 已切走人数；
- $I_3$：对树中每个节点 $v\ge \text{low}-\delta$（等价地：真实工资 $\ge\text{low}$）；
- $I_4$：`sz` 在每次 `split`/`merge` 回溯时被 `pushup` 修正。

### 4.3 编号步骤（实现 B：离线两趟 + 树状数组）

1. 一趟读入所有命令到数组 `op[]/kk[]`；同时模拟 `delta`，对每条满足 `kk>=low` 的 `I` 把 `kk-delta` 压进 `xs`。
2. `sort` + `unique` 得到 `val[1..tot]`（升序、1 起编号）。
3. 二趟重置 `delta=0`、`accepted=0`、`livecnt=0`、`live=∅`（活排名集合），逐条执行：
   1. `I k`：`k<low` 跳过；否则 `++accepted`；`r=lower_bound(val+1,val+tot+1,k-delta)-val`（1 起，因为 $k\ge\text{low}$ 保证该值必在 `xs` 中，见引理 10 与步骤 1 的对应性）；若 `c[r]==0` 则 `live.insert(r)`；`++c[r]`、`++livecnt`、`add(r,1)`。
   2. `A k`：`delta+=k`。
   3. `S k`：`delta-=k`；`T=low-delta`；当 `live` 非空且 `val[*live.begin()]<T` 时循环：取 `r=*live.begin()`、`live.erase(begin)`、`livecnt-=c[r]`、`add(r,-c[r])`、`c[r]=0`。
   4. `F k`：`k<1||k>livecnt` 输出 `-1`；否则 `r=kthBIT(livecnt-k+1)`，输出 `val[r]+delta`。
4. 输出 `accepted-livecnt`。

`kthBIT` 用树状数组倍增：`for(st=最高位;st;st>>=1) if(p+st<=tot && bit[p+st]<k) k-=bit[p+st],p+=st;` 返回 `p+1`。
**正确性**：树状数组的 `bit[p]` 覆盖区间 $(p-\text{lowbit}(p),\,p]$，倍增时按二进制位从高位到低位试探"跳到 $p+st$ 后累计人数仍 $<k$"，保持不变量"已累加的人数 $<$ 原始 $k$，且这覆盖的是最靠左的可能位置"；循环结束 $p+1$ 即为第一个前缀和 $\ge k$ 的排名，也就是第 $k$ 小。$\blacksquare$

**摊还**：引理 11 保证步骤 3.3 的循环总计 $\le$ `accepted` 次；其余每步 $O(\log tot)$。

### 4.4 复杂度

| | 时间 | 空间 |
|---|---|---|
| 实现 A（FHQ） | $O(n+I\log I)$，期望；$I\le10^5$、$n\le3\times10^5$ → 约 $2\times10^6$ 次基本操作 | $O(I)$ 数组，$8\times10^5$ 字节量级 |
| 实现 B（BIT 离线） | $O(n+I\log I)$，最坏界（无随机化） | $O(n+I)$（要存命令） |
| 朴素（每次排序 / 遍历全表） | $O(n\cdot I)\sim10^{10}$，**不可接受** | — |

`A`/`S` 只有 $100$ 条这件事，让"每次 `S` 扫全表"（$100\times10^5=10^7$）成为一种**可写的**验证暴力；但 $10^5$ 次 `F` 若各排序一次就是 $10^{10}$，所以暴力版只在"每次 `S` 后重排一次、`F` 直接下标取"的前提下才够用。

**用例 E —— $\text{low}=10$，$n=7$**：`I 12 / S 5 / A 10 / I 17 / F 1 / S 8 / F 1`
考点（专为实现 B 设计）：**同一离散化排名被清零后又被重新使用**，检验 `live` 集合的重新插入与 `c[r]` 的重建。
轨迹：① $s=12$ 入树，accepted$=1$；② $\delta=-5,T=15$，$12<15$ ⇒ 被切走，现存 $0$；③ `A 10`：$\delta=5,T=5$；④ `I 17` ⇒ $s=17-5=12$，**与第 ① 步同排名**，accepted$=2$，现存 $1$；⑤ `F 1` $=12+5=\mathbf{17}$；⑥ `S 8`：$\delta=-3,T=13$，$12<13$ ⇒ 再次被切走，现存 $0$；⑦ `F 1` ⇒ $-\mathbf{1}$。末行 $=2-0=\mathbf{2}$，期望输出 `17 / -1 / 2`。
实现 B 里 `val=[12]`、$tot=1$：第 ② 步把排名 $1$ 清零并从 `live` 移除，第 ④ 步必须靠 `if(!c[r])live.insert(r)` 重新登记，否则第 ⑥ 步的循环看不见这个排名、末行错算成 $1$（B 独有的可复现错法；实现 A 用 split 天然无此问题）。

## 5. 示例代码

### 实现 A（主线）：全局偏移 + FHQ Treap

```cpp
// https://www.luogu.com.cn/problem/P1486
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{100005};

i64 v[mxn];                                   // 相对工资（真实值 = v + delta）
int w[mxn],sz[mxn],ls[mxn],rs[mxn],rt,cnt;    // 堆权/子树大小/左右孩子/根/节点数
mt19937 rn(20040618);

int newnode(i64 key){v[++cnt]=key;w[cnt]=rn();sz[cnt]=1;return cnt;}
void pushup(int x){sz[x]=sz[ls[x]]+sz[rs[x]]+1;}

// split：a 收 v<=key 的部分，b 收 v>key 的部分
void split(int x,i64 key,int&a,int&b)   // a: v<=key, b: v>key（引理 6）
{
	if(!x){a=b=0;return;}
	if(v[x]<=key){a=x;split(rs[x],key,rs[x],b);pushup(a);}
	else{b=x;split(ls[x],key,a,ls[x]);pushup(b);}
}
int merge(int x,int y)                  // 前提：x 的最大键 <= y 的最小键（引理 7）
{
	if(!x||!y)return x+y;
	if(w[x]<w[y]){rs[x]=merge(rs[x],y);pushup(x);return x;}
	ls[y]=merge(x,ls[y]);pushup(y);return y;
}
int kth(int x,int k)                    // 中序第 k 小（1 起），要求 1<=k<=sz[rt]（引理 8）
{
	while(true)
	{
		if(sz[ls[x]]>=k){x=ls[x];continue;}
		if(sz[ls[x]]+1>=k)return x;
		k-=sz[ls[x]]+1;x=rs[x];
	}
}

int main()
{
	cin.tie(nullptr);
	ios::sync_with_stdio(false);
	int n;
	i64 low;                        // 题面把这个量叫 min，但 min 是 std 的名字，改名 low
	cin>>n>>low;
	i64 delta=0;                    // 全局偏移：真实工资 = 存值 + delta（引理 1）
	int accepted=0;                 // 真正入职过的人数（初始就低于下界的没入职）
	for(int i=0;i<n;++i)
	{
		char op;
		i64 k;
		cin>>op>>k;
		if(op=='I')
		{
			if(k<low)continue;      // 立刻离开，但不计入离职总数
			++accepted;
			int a,b,x=newnode(k-delta);
			split(rt,k-delta,a,b);
			rt=merge(merge(a,x),b);
		}
		else if(op=='A')delta+=k;
		else if(op=='S')
		{
			delta-=k;
			int a,b;
			split(rt,low-delta-1,a,b);   // 真实值<low <=> 存值<low-delta（整数故取 -1）
			rt=b;                        // 被切下的 a 整片丢弃，即所有离职者
			// cerr<<'S'<<' '<<low-delta<<' '<<sz[a]<<'\n';
		}
		else if(k<1||k>sz[rt])cout<<-1<<'\n';              // 'F' 越界
		else cout<<v[kth(rt,sz[rt]-(int)k+1)]+delta<<'\n'; // 第 k 大 = 第 m-k+1 小，记得加回 delta
	}
	cout<<accepted-sz[rt]<<'\n';     // 引理 9：入池数 - 现存数
	return 0;
}
```

### 实现 B（离线两趟 + 树状数组，无随机化）：与 §2.6 / §4.3 的推导一一对应

```cpp
// https://www.luogu.com.cn/problem/P1486
// 存值静态性（引理 10）=> 可离线；删除是前缀（引理 4）=> 活排名集合整体清零
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{300005};          // n<=3e5，命令数组按 n 开
int n,tot,accepted,livecnt;
i64 low,val[mxn],kk[mxn];
char op[mxn];
int bit[mxn],c[mxn];                // c[r]=排名 r 上当前在司人数
set<int>live;                       // c[..]>0 的排名，升序
vector<i64>xs;

int lowbit(int x){return x&-x;}
void add(int i,int d){for(;i<=tot;i+=lowbit(i))bit[i]+=d;}
int kth(int k){int p=0;for(int st=1<<20;st;st>>=1)if(p+st<=tot&&bit[p+st]<k)k-=bit[p+st],p+=st;return p+1;}

int main()
{
	cin.tie(nullptr);
	ios::sync_with_stdio(false);
	i64 delta=0;
	cin>>n>>low;
	for(int i=0;i<n;++i)cin>>op[i]>>kk[i];
	for(int i=0;i<n;++i)              // 第一趟：delta 只被 A/S 改动，与 I 无关
	{
		if(op[i]=='I'){if(kk[i]>=low)xs.push_back(kk[i]-delta);}
		else if(op[i]=='A')delta+=kk[i];
		else if(op[i]=='S')delta-=kk[i];
	}
	sort(xs.begin(),xs.end());
	xs.erase(unique(xs.begin(),xs.end()),xs.end());
	tot=(int)xs.size();
	for(int i=0;i<tot;++i)val[i+1]=xs[i];

	delta=0;                          // 第二趟：真正的模拟
	for(int i=0;i<n;++i)
	{
		if(op[i]=='I')
		{
			if(kk[i]<low)continue;    // 被拒：既不建树也不计数
			++accepted;
			int r=lower_bound(val+1,val+tot+1,kk[i]-delta)-val;
			if(!c[r])live.insert(r);  // 该排名可能曾被清零（用例 E）
			++c[r];++livecnt;add(r,1);
		}
		else if(op[i]=='A')delta+=kk[i];
		else if(op[i]=='S')
		{
			delta-=kk[i];
			while(!live.empty()&&val[*live.begin()]<low-delta)
			{
				int r=*live.begin();
				live.erase(live.begin());
				livecnt-=c[r];add(r,-c[r]);c[r]=0;
			}
		}
		else // 'F'
		{
			if(kk[i]<1||kk[i]>livecnt)cout<<-1<<'\n';
			else cout<<val[kth(livecnt-(int)kk[i]+1)]+delta<<'\n';
		}
	}
	cout<<accepted-livecnt<<'\n';
	return 0;
}
```

**实现 C（`__gnu_pbds` 一行选型，思路说明，不另附整份代码）**：用 `tree<i64,int,less<i64>,rb_tree_tag,tree_order_statistics_node_update>` 存**多重集**（把 $(s,\text{序号})$ 作为键以保证可重），`F k` 用 `find_by_order(m-k)`，`I` 用 `insert`；但 PBDS **没有**"删除所有 $<T$"的原语，只能 `for(it=T0;it!=end()&&*it<T;erase(it++))` 逐个删 —— 正确性没问题，摊还界靠引理 11（每人至多被删一次）。写法上要小心 PBDS 的 `erase(it++)` 惯用法。总复杂度同为期望 $O(n\log n)$，但常数与码长都不如实现 A，故不推荐作为主线。
