## 1. 重新读题

**问题重述（简化版）**

给定长度为 $n$ 的整数序列 $a_1,\dots,a_n$（下标从 $1$ 开始），$m$ 次操作，只有两种：

- `1 x y`：把所有下标为 $x$ 的**正整数倍**的位置 $a_{x},a_{2x},a_{3x},\dots,a_{\lfloor n/x\rfloor x}$ 都加上 $y$。
- `2 j`：输出 $a_j$ 的当前值；**特别地 $j=0$ 时直接输出 $0$**。

**约束**

| 量 | 上界 |
|---|---|
| $n$ | $10^6$ |
| $m$ | $10^5$ |
| 操作 $2$ 的条数 $Q$ | $10^4$ |
| $\vert a_i\vert,\vert y\vert$ | $10^6$ |
| $x$ | $1\le x\le n$ |
| $j$ | $0\le j\le n$ |

**逐字拆解操作 1**

题面写的是“把所有 $a_{kx}$（$k$ 为正整数，$kx\le n$）都加上 $y$”。三个细节必须钉死：

- $k$ 的取值是 $1,2,\dots,\lfloor n/x\rfloor$，**不含 $k=0$**。所以被影响的下标集合是
  $$M(x)=\{kx:1\le k\le \lfloor n/x\rfloor\}=\{p\in[1,n]:x\mid p\}.$$
  若误写成 $k\ge 0$，就会去动 $a_0$：在“直接模拟”版本里是越界/改到哨兵位，在“懒标记”版本里则会把 $y$ 记到 $x=0$ 这个不存在的桶上——两种写法都是 bug。
- 影响的是**位置**（下标是 $x$ 的倍数），不是**值**。也就是说 $x$ 是“下标空间的量”，不是“数值空间的量”。这一句是整个题目的钥匙。
- $\vert M(x)\vert=\lfloor n/x\rfloor$：$x$ 越大被改的位置越少，$x=1$ 时改全部 $n$ 个，$x=n$ 时只改 $1$ 个。这个“反比”形状是根号分治的信号。

**逐字拆解操作 2**

“输出 $a_j$”——是**单点**查询，不要求和、不要求最值、不要求区间信息。
“当 $j=0$ 时输出 $0$”：注意 $0$ 不是合法下标（$a_0$ 不存在），所以这条是**硬性规定输出常量 $0$**，而**不是**“输出 $a_0$ 的当前值”。差别在于：如果按位置 $0$ 去累加，任何 $x$ 都整除 $0$（$0=kx$ 取 $k=0$，但题面已排除 $k=0$），会得到完全错误的答案。正确实现要在进入求和循环**之前**短路返回 $0$。

**读题要点（先记下来，后面会用到）**

1. 只有“加”，没有“赋值”，也没有“询问区间和/最值”——询问是**单点**。
2. 写操作数量（$10^5$）远大于读操作数量（$10^4$），而且读的是**单点**。这是“批量写 + 稀疏读”的典型形状。
3. 值域会爆 `int`，必须 `i64`（证明见 §2.1）。
4. 本地题面无样例输入/输出，因此无法与官方答案对标，只能用自造小数据手算验证。

**题面依据声明**：本文一切数据以本地 `P1483.md` 为准，**特别是 Hint 里的“操作 $2$ 不超过 $10^4$ 条”**——它决定了本解法的取舍（见 §2.5 与引理 8）。文件头给的标签是“模拟 / 数学 / 根号分治”，而本文最终写法里“根号”出现在**约数配对枚举**而不是**分块阈值**上：这是同一技巧的退化形态，不算与题面冲突，但确实和多数人对“根号分治”的直觉（小 $x$ 懒、大 $x$ 暴力）不同，已在 §2.5 末尾与 §3 第 6~7 条显式说明。未查阅任何外部题解，也没有联网取样例。

## 2. 思维链（Chain-of-thought）

### 2.1 朴素做法与它的失败

最直接的翻译：“$x$ 的倍数加 $y$”就写一个 `for(int k=x;k<=n;k+=x) a[k]+=y;`，查询直接 `cout<<a[j]`。

**引理 1（朴素复杂度）** 朴素做法的总步数为
$$T_{\text{naive}}=\sum_{t\in\text{类型1}}\Big\lfloor\frac{n}{x_t}\Big\rfloor+Q.$$
最坏情形取全部 $m$ 条操作都是 `1 1 y`（即 $x=1$），得
$$T_{\text{naive}}\le m\cdot n=10^5\cdot10^6=10^{11}.$$

**证明**：单次操作 1 的循环次数恰为 $\lfloor n/x\rfloor$（循环体是 $k=x,2x,\dots\le n$），而 $x\ge1$ 时 $\lfloor n/x\rfloor\le n$；把 $m$ 次相加即得上界，取 $x_t\equiv1$ 时等号成立。操作 2 每次 $O(1)$，共 $Q$ 次。$\blacksquare$

代入现实常数：$10^{11}$ 次加法远超 $10^8$/秒量级的评测机预算，必然 TLE。**但注意 $40\%$ 的分项 $n\le100$ 时 $mn=10^7$ 可以过**——这题的部分分正是给“直接模拟”留的，说明出题人预期我们“减少每次写的步数”，而不是换数据结构。

**引理 2（必须用 64 位）** 某个位置最终的值的绝对值可达
$$|a_j|_{\max}=10^6+10^5\cdot10^6=100\,001\,000\,000\approx10^{11}>2^{31}-1=2\,147\,483\,647.$$

**证明**：下界构造——令 $a_1=10^6$，并让全部 $m=10^5$ 条操作都是 `1 1 1000000`，则 $1$ 是任何 $x=1$ 的倍数，$a_1$ 累加 $10^5$ 次，得 $10^6+10^5\cdot10^6=100001000000$。该数 $>2.1\times10^9$，故 `int` 溢出；$<9.2\times10^{18}=2^{63}-1$，故 `long long` 足够。取 $y=-10^6$ 同理得到负号方向的界。$\blacksquare$

所以代码里 `a`、`add` 一律 `i64`，只有下标（$n,m,x,j,d$）保持 `int`。

### 2.2 把操作翻译成集合语言：倍数 ↔ 约数

先不急着优化，先把“某个位置最终长什么样”这件事**精确刻画**出来——这是 explore its property 的第一步。

设前 $t$ 次操作里，所有类型 1 的操作为 $(x_1,y_1),\dots,(x_t,y_t)$（按时间顺序，$x_s\in[1,n]$）。

**引理 3（位置值的闭式表达）** 第 $t$ 次操作之后，任意位置 $j\in[1,n]$ 的当前值为
$$A_j=a_j+\sum_{\substack{1\le s\le t\\ x_s\mid j}}y_s.$$

**证明**：对 $t$ 归纳。
- $t=0$：右边只剩 $a_j$，与初始状态一致。
- 归纳步：设 $t$ 时命题成立。考虑第 $t+1$ 次操作。
  - 若是类型 2，不改变任何 $A_j$，也不新增求和项，命题保持。
  - 若是类型 1，参数 $(x,y)$。按题面定义 $A'_p=A_p+y$ 当且仅当 $p\in M(x)=\{p:x\mid p\}$，否则 $A'_p=A_p$。于是
    $$A'_j=a_j+\sum_{\substack{s\le t\\x_s\mid j}}y_s+\mathbb{1}[x\mid j]\cdot y=a_j+\sum_{\substack{s\le t+1\\x_s\mid j}}y_s,$$
    最后一步正是把新项 $y_{t+1}=y$、$x_{t+1}=x$ 并入求和条件。$\blacksquare$

**推论 4（对偶性：写侧“倍数”= 读侧“约数”）** 位置 $j$ 与参数 $x$ 之间的影响关系是一个**二元关系**
$$j\ \text{受影响于}\ x\iff x\mid j .$$
所以：
- 从 $x$ 看（写侧）：它影响 $\{j:x\mid j\}$，规模 $\lfloor n/x\rfloor$，是“**倍数方向**”。
- 从 $j$ 看（读侧）：它被 $\{x:x\mid j\}$ 影响，规模 $\tau(j)$（约数个数），是“**约数方向**”。

同一张关联矩阵（行是 $x\in[1,n]$、列是 $j\in[1,n]$、格 $(x,j)$ 非零当且仅当 $x\mid j$），按行展开是 $\lfloor n/x\rfloor$ 个格子，按列展开是 $\tau(j)$ 个格子。
$$\text{写侧代价}=\lfloor n/x\rfloor\text{（按行）},\qquad \text{读侧代价}=\tau(j)\text{（按列）}.$$

> **这一步的发现价值**：我们不需要“把 $y$ 推到 $j$”，也可以“把 $j$ 拉回来问哪些 $x$ 命中我”。两种方向代价差得很悬殊时，就该选便宜的那一侧记账。题面 $Q\ll m$ 且读的是单点，恰好暗示：把每笔写按 $x$ 归档，读时再沿约数把账本翻出来。

**引理 5（按 $x$ 归档的正确性）** 定义桶数组 $\text{add}[x]=\sum_{\text{已发生的、参数为 }x\text{ 的类型1操作}}y$。则第 $t$ 步后
$$A_j=a_j+\sum_{x\mid j}\text{add}[x].$$

**证明**：把引理 3 的右端按 $x_s$ 的取值分组：
$$\sum_{\substack{s\le t\\x_s\mid j}}y_s=\sum_{x\mid j}\ \sum_{\substack{s\le t\\x_s=x}}y_s=\sum_{x\mid j}\text{add}[x],$$
其中内层求和正是 $\text{add}[x]$ 的定义（$x\nmid j$ 的组整体不出现）。分组的合法性来自 $x\mid j$ 只依赖 $x$ 的值而不依赖 $s$。$\blacksquare$

这一步还顺带解释了为什么**必须只有加法**：分组重排（把 $\sum_s$ 换成 $\sum_x\sum_{s:x_s=x}$）要求贡献可交换可结合，加法满足；若存在“赋值/覆盖”型操作，后一次赋值会作废前一次，$\text{add}[x]$ 就不再是充分统计量。

### 2.3 顺着标签想：根号分治（先把“标准解”走一遍）

标签写着“根号分治”，那就按标准套路走：设阈值 $B$，把类型 1 按 $x$ 大小分两类。

- **$x>B$（大 $x$，写得慢）**：$\lfloor n/x\rfloor< n/B$，直接沿倍数暴力改 $a[\cdot]$ 本身，每次至多 $\lfloor n/(B+1)\rfloor$ 步。
- **$x\le B$（小 $x$，写得勤）**：不动 $a$，只记 $\text{add}[x]\mathrel{+}=y$，每次 $1$ 步。

读的时候，位置 $j$ 的“暴力部分”已经在 $a[j]$ 里了，只需补上小 $x$ 的懒账。最省事的写法是**扫一遍所有小桶**：

$$\text{query}(j)=a[j]+\sum_{\substack{1\le x\le B\\x\mid j}}\text{add}[x],$$
代价 $O(B)$（对每个 $x$ 做一次 $j\bmod x$）。

**引理 6（根号分治的总代价与最优阈值）** 设类型 1 共 $U$ 条、类型 2 共 $Q$ 条，则本方案
$$T(B)=\underbrace{U\cdot\Big\lfloor\frac{n}{B+1}\Big\rfloor}_{\text{大 }x\text{ 暴力}}+\underbrace{Q\cdot B}_{\text{查询扫小桶}}\le \frac{Un}{B}+QB,$$
在 $B^{*}=\sqrt{Un/Q}$ 处取到最小值 $2\sqrt{UnQ}$（把 $B$ 当连续变量、忽略取整）。

**证明**：$T$ 对 $B$ 的第一项单调减（$\lfloor n/(B+1)\rfloor$ 随 $B$ 增而不增），第二项单调增（线性）。把 $f(B)=Un/B+QB$ 求导：$f'(B)=-Un/B^2+Q$ 令其为零得 $B^2=Un/Q$，$f''=2Un/B^3>0$，故 $B^*$ 是极小点，代回
$$f(B^*)=\frac{Un}{\sqrt{Un/Q}}+Q\sqrt{Un/Q}=\sqrt{UnQ}+\sqrt{UnQ}=2\sqrt{UnQ}.\qquad\blacksquare$$

**代入本题数字**（$U\le m=10^5$，$Q\le10^4$，$n=10^6$）：
$$B^{*}=\sqrt{\frac{10^5\cdot10^6}{10^4}}=\sqrt{10^7}\approx3162,\qquad T\approx2\sqrt{10^{15}}\approx6.3\times10^7 .$$
桶规模也要一并核算清楚，别只看时间：

| 对象 | 规模 | 说明 |
|---|---|---|
| 小桶个数（懒标记数组） | $B\approx3162$ | 只有 $x\le B$ 才需要桶 |
| 被暴力维护的位置数组 | $n=10^6$ | $a[\cdot]$ 本身 |
| 单笔写的实际步数 | $x\le B$：$1$；$x>B$：$\le\lfloor n/(B+1)\rfloor=316$ | $10^6/3163=316.1\dots$ |
| 单笔读的步数 | $B\approx3162$ 次取模 | 与 $j$ 无关的最坏值 |

$6.3\times10^7$ 已经能过，但读侧那 $3\times10^7$ 次**取模**是纯浪费：$j$ 的约数只有 $\tau(j)$ 个（$j\le10^6$ 时 $\tau$ 的最大值是 $240$，在 $j=720720=2^4\cdot3^2\cdot5\cdot7\cdot11\cdot13$ 处取到，$\tau=(4+1)(2+1)\cdot2^4=240$；这是查表/枚举值，**本文不依赖它的精确性**——由引理 7，每次循环至多做 2 次累加，所以 $2\lfloor\sqrt j\rfloor\le2000$ 就是无条件上界，记错了也只动常数不动渐近），我们却扫了 $3162$ 个 $x$。**能不能让读侧只走约数？**——这就把思路推进到下一步。

### 2.4 质疑查询端的成本：约数配对枚举

**引理 7（配对枚举定理）** 设 $j\ge1$。记
$$\mathcal{S}=\{d\in\mathbb{Z}_{\ge1}:d^{2}\le j,\ d\mid j\},\qquad \mathcal{L}=\{j/d:d\in\mathcal{S},\ d^{2}\ne j\}.$$
则 $\mathcal{S}\cup\mathcal{L}$ **恰好**等于 $j$ 的全部正约数集合，且 $\mathcal{S}\cap\mathcal{L}=\varnothing$、两组内部各无重复。因此“枚举 $j$ 的所有约数”可以在
$$\lfloor\sqrt{j}\rfloor\ \text{次取模}$$
之内完成。

**证明**：分三步。

1. **完备性（每个约数都被抓到）**：设 $e\mid j$，写 $j=e\cdot f$。若 $e\le f$，则 $e^2\le ef=j$，故 $e\in\mathcal{S}$；若 $e>f$，则 $f^2<fe=j$，故 $f\in\mathcal{S}$ 且 $f^2\ne j$，于是 $e=j/f\in\mathcal{L}$。两种情形都覆盖。
2. **无重复**：$\mathcal{S}$ 的元素全部 $\le\sqrt j$；$\mathcal{L}$ 的元素形如 $j/d$，其中 $d\in\mathcal{S}$ 且 $d^2\ne j$，即 $d^2<j\Rightarrow d<\sqrt j\Rightarrow j/d>\sqrt j$，故 $\mathcal{L}$ 的元素全部 $>\sqrt j$，与 $\mathcal{S}$ 不交。$\mathcal{L}$ 内部映射 $d\mapsto j/d$ 是单射（$j/d_1=j/d_2\Rightarrow d_1=d_2$），所以整体每个约数恰好出现一次。$\mathcal{S}\cup\mathcal{L}$ 里也全是约数（$\mathcal{S}$ 定义要求 $d\mid j$；$j/d$ 整除 $j$），故并集**等于**约数集。
3. **循环次数**：外层 `for(int d=1;(i64)d*d<=j;++d)` 的迭代次数就是满足 $d^2\le j$ 的正整数 $d$ 的个数，即 $\lfloor\sqrt j\rfloor$。$\blacksquare$

**代码化**（$j$ 在文中用变量 `x` 承接，见 §5）：

```cpp
i64 res=a[j];
for(int d=1;(i64)d*d<=j;++d)
	if(j%d==0)
	{
		res+=add[d];
		if(d*d!=j)
			res+=add[j/d];   // 大约数走这条路
	}
```

**为什么必须写 `d*d!=j` 这个去重**：$j$ 为完全平方数时 $d=\sqrt j$ 满足 $d^{2}=j$，此时 $j/d=d$，若不判重就会把 $\text{add}[d]$ **加两遍**。具体反例见 §2.6 的**坑 A**。

**为什么不能只枚举 $d\le\sqrt j$（漏大约数）**：例如 $n=10^6$，一条 `1 1000000 7` 只影响位置 $10^6$。查询 $j=10^6$ 时，$10^6$ 是 $j$ 的约数但 $10^6>\sqrt j=1000$，只有 $j/d$ 那一支（$d=1$）能抓到它。反例数据见 §2.6 的**坑 B**（用小版 $n=6$ 复现同一结构）。

**注意溢出细节**：循环条件写 `(i64)d*d<=j`。本题 $j\le10^6$、$d\le1000$，`int` 其实也够；但按“把边界钉死”的习惯，凡是 $d^2$ 与 $n$ 比较都先升宽度，防止日后 $n$ 上到 $10^9$ 时静默炸掉。

### 2.5 关键发现：读侧代价在 $B=\sqrt n$ 处**饱和**，于是本题最优点被推到 $B=n$

回到引理 6 的代价式 $T(B)=Un/B+QB$。这里的 $QB$ 项来自“**遍历整个小桶数组、逐个试除**”这一实现方式。用引理 7 换成配对枚举后，读侧代价变成

$$Q(j)=\min\big(B,\ \lfloor\sqrt j\rfloor\big),$$

**解释这个 $\min$**：桶只开到 $B$，所以 $x>B$ 的写必须已经暴力改进 $a$（否则丢账）。当 $B\le\sqrt j$ 时，需要查的桶全在 $[1,B]$ 内、用小半支就能扫完，$\lfloor\sqrt j\rfloor$ 那一支是浪费，于是读侧 $=B$；当 $B>\sqrt j$ 时，大约数 $x\in(\sqrt j,B]$ 只能靠 $j/d$ 支找到，循环必须走满 $\lfloor\sqrt j\rfloor$，此后**再增大 $B$ 也不会让循环变长**——读侧饱和在 $\lfloor\sqrt j\rfloor$。

所以在 $B\ge\sqrt n$ 这一段里，代价式变成

$$T(B)=\sum_{x_s>B}\Big\lfloor\frac{n}{x_s}\Big\rfloor+Q\sqrt{n},$$

第二项是常数、第一项随 $B$ 单调不增：**在该段内阈值越大越划算**，右端点就是 $B=n$：此时“大 $x$ 类”为空集，所有类型 1 都只写一个桶，代价 $U$；查询仍是 $\sqrt n$。跨段（$B<\sqrt n$ vs $B\ge\sqrt n$）谁优谁劣不是显然的，必须实打实比一次——见下面的引理 8。

**引理 8（阈值取 $B=n$ 的真正理由）** 记 $T(B)$ 为“阈值 $B$ + 最优读法”在最坏输入下的步数上界。在题面范围 $(n,m,Q)\le(10^6,10^5,10^4)$ 内，$B=n$ 的全懒方案给出的上界 $T(n)=U+Q\lfloor\sqrt n\rfloor\le1.01\times10^7$ **严格小于**任何 $B<n$ 方案的最坏上界。

**先把“读侧与 $B$ 无关”这句错话修正**——它其实**有关**，而且关系是分段的：

- 若 $B\le\sqrt n$：读侧可以走“扫 $[1,B]$ 逐个试除”（桶只开到 $B$，这样就能命中全部桶），代价 $\le B$，对小 $j$ 还能压到 $\min(B,\lfloor\sqrt j\rfloor)$；这就是 §2.3 的“扫小桶”。于是本段读侧最坏 $=QB$。
- 若 $B>\sqrt n$：试除扫到 $B$ 太亏，改用配对枚举，循环走满 $\lfloor\sqrt j\rfloor$ 即可拿到**全部**约数（其中落在 $(\sqrt j,B]$ 的桶只能靠 $j/d$ 支发现），代价 $\le\sqrt n$，**与 $B$ 无关**。

所以读侧代价是 $Q\min(B,\sqrt n)$：先随 $B$ 线性增，到 $B=\sqrt n$ 饱和。写侧代价 $\sum_{x_s>B}\lfloor n/x_s\rfloor$ 随 $B$ 单调不增。两者是真的在权衡，不能张口就说“$B$ 越大越好”。

**证明（分三段比较，全部用上题面给的最坏值 $U\le10^5,Q\le10^4,n=10^6,\sqrt n=1000$）**：

1. **$B\le\sqrt n$ 段**（读侧用扫小桶）：$T(B)\le U\cdot\lfloor n/(B+1)\rfloor+QB$。本段内 $B\le1000\Rightarrow\lfloor n/(B+1)\rfloor\ge999$。把 $f(B)=Un/B+QB$ 看成连续函数，它的极小点在 $B^{*}=\sqrt{Un/Q}=3162$，**落在本段右边**，所以 $f$ 在 $[1,\sqrt n]$ 上单调下降，本段最好的点是 $B=\sqrt n=1000$：
 $$T(1000)=10^5\cdot999+10^4\cdot1000\approx1.1\times10^8 .$$
2. **$\sqrt n<B<n$ 段**（读侧改用配对枚举，饱和为 $Q\sqrt n=10^7$）：写侧 $U\cdot\lfloor n/(B+1)\rfloor$ 随 $B$ 单调不增，所以本段最小点在右端 $B\to n$。取中间值看量级：$B=10^5$ 时写侧 $10^5\cdot\lfloor10^6/100001\rfloor=10^5\cdot9=9\times10^5$，$T\approx1.09\times10^7$；$B=3162$（已在饱和段内）写侧 $10^5\cdot316=3.16\times10^7$，$T\approx4.2\times10^7$。
3. **$B=n$ 点**：写侧 $U=10^5$（每笔 $1$ 步），读侧 $Q\sqrt n=10^7$，$T(n)=1.01\times10^7$。

比较三段的最小值：$1.1\times10^8$（第 1 段）$>4.2\times10^7$（第 2 段内代表点）$>\dots>1.09\times10^7$（$B=10^5$）$>1.01\times10^7$（$B=n$）。第 2 段的单调性已经说明其下确界就在 $B=n$，故 $B=n$ 全局最优。$\blacksquare$

**为什么这个比较对本数据范围成立、对外不成立**：胜负手是 $Q\ll U$。若 $Q$ 与 $U$ 同量级甚至更大（例如 $Q=9\times10^4$、$U=10^4$、全部写都是 $x=n$ 这种“暴力只要 $1$ 步”的极端分布），第 1 段的 $QB$ 就能远小于 $Q\sqrt n$：$B=100$ 时 $T=10^4\cdot1+9\cdot10^4\cdot100=9.1\times10^6$，而全懒是 $10^4+9\cdot10^4\cdot1000=9.01\times10^7$，**小 $B$ 反胜 10 倍**。所以正确的心态是：**不是“全懒最好”，而是“题面 $Q\le10^4$ 把 $B=n$ 推成了最优”**，前提写在结论里，变了就要换方案（§4.6）。

**于是本题的“根号”落在读侧，而不是分桶上**：$\sqrt{\ }$ 是**约数配对枚举**的 $\sqrt j$，不是把 $[1,n]$ 切成 $\sqrt n$ 段的阈值。这就是标签“根号分治”在本解法中的真实形态（也说明题面给的 $Q\le10^4$ 是这套做法能过的关键前提）。

**双向映射与桶规模核算（这题的“账本”）**

| 方向 | 索引空间 | 一次操作的触达量 | 累计 |
|---|---|---|---|
| 写（原始视角） | $x\in[1,n]$，触达 $M(x)=\{j:x\mid j\}$ | $\lfloor n/x\rfloor$（最坏 $n$，$x=1$） | 若真去触达则 $Un$ |
| 写（懒视角） | 同一个 $x$，只写 $\text{add}[x]$ | $1$ | $U$ |
| 读（懒视角） | $j$，读 $\{x:x\mid j\}=\tau(j)$ 个桶 | 发现它们要 $\lfloor\sqrt j\rfloor$ 次取模 | $Q\sqrt n$ |

- **桶总数** $=n$（$x$ 的值域就是 $[1,n]$，题面保证 $1\le x\le n$，不需要离散化）。规模 $n$ 个 `i64` $=8\text{MB}$；`a` 同规模再 $8\text{MB}$，合计约 $16\text{MB}$。本地题面**未给内存限制**，$16\text{MB}$ 属常规额度内。
- **非零桶数量** $\le U\le10^5$：绝大多数桶是空的，但**空桶不影响读侧代价**——我们从不遍历桶，只按约数定点访问，所以“桶开满 $n$ 个”不带来任何时间损失，只带来 $8\text{MB}$ 空间。这是本方案与“扫小桶”方案的本质区别（后者遍历桶，代价正比于桶数 $B$）。
- **一次读实际做的加法** $=\tau(j)\le240$（$j\le10^6$），但取模次数固定为 $\lfloor\sqrt j\rfloor\le1000$，故时间上限按后者取。
- **变换后值的还原**：$\hat a_j=a_j+\sum_{x\mid j}\text{add}[x]$ 在**任何时刻**都成立（引理 5 对“当前前缀”成立），因此完全在线，不需要离线。

### 2.6 反例驱动的检查（每个坑都配一组能打挂的具体数据）

**坑 A：平方数重复加。** 数据 $n=9$，$a\equiv0$，操作 `1 3 4`、`1 9 2`、`2 9`。
期望：$3,6,9$ 各 $+4$，$9$ 再 $+2$ ⇒ $a_9=6$。
错误实现（去掉 `if(d*d!=x)`）：$9$ 的配对枚举 $d=1(9/1=9)$、$d=2$ 不行、$d=3(9/3=3)$。$d=3$ 时会加 $\text{add}[3]$ 两次，得 $2+4+4=10\ne6$。**判重必要。**

**坑 B：只枚举 $d\le\sqrt j$，漏掉大约数。** 数据 $n=6$，$a\equiv0$，操作 `1 6 5`、`2 6`。
期望 $a_6=5$。若读侧写成 `for(int d=1;d*d<=j;++d) res+=add[d]`（只有小半支），$\sqrt6\approx2.4$，只访问 $\text{add}[1],\text{add}[2]$，得 $0\ne5$。**$j/d$ 那一支不可省。**

**坑 C：把 $j=0$ 当成下标 $0$。** 数据 $n=5$，$a\equiv0$，操作 `1 1 3`、`2 0`。题面规定输出 $0$。两种错误实现各给出什么，算清楚：
- 若写侧是暴力版且循环从 $k=0$ 起（见坑 D），则 $a_0\mathrel{+}=3$，查询若输出 `a[0]` 就得 $3\ne0$。
- 若写侧是懒标记版、读侧写成“遍历所有桶试除”：`for(int x=1;x<=B;++x) if(0%x==0) res+=add[x];`，则 $0\bmod x==0$ **恒真**，$res=a_0+\text{add}[1]=0+3=3\ne0$。
- 反过来，本代码的配对循环 `(i64)d*d<=0` 一条都不进，输出 $a_0=0$——**碰巧**对，因为它读的是从未被写的 $a[0]$。这种“靠未定义行为/巧合活着”的写法不能留。
**结论：显式短路 `if(j==0){cout<<0<<'\\n';continue;}`，并且绝不写 $a[0]$。**

**坑 D：$k$ 从 $0$ 开始。** 若把类型 1 写成 `for(int k=0;k*x<=n;++k) a[k*x]+=y;`：第一次迭代 $k=0$ 访问 `a[0]`，把 $y$ 记到了“下标 $0$”上；随后 `2 0` 若输出 `a[0]` 就成了 $y$，与题面要求的常量 $0$ 冲突。这是坑 C 的“制造者”，两个坑合起来说明：**下标 $0$ 在本问题里既不存在也不该被写。**

**坑 E：32 位溢出。** 极端自造：$n=1$，$a_1=10^6$，$10^5$ 条 `1 1 1000000`，最后 `2 1`。真值 $=10^6+10^5\cdot10^6=100\,001\,000\,000$。若用 `int` 存储：逐次回绕等价于“对 $2^{32}$ 取模后落到 $[-2^{31},2^{31})$”（因为整数加法在 $\mathbb{Z}/2^{32}\mathbb{Z}$ 上是同余的，回绕发生在哪一步不影响最终余数）。
$$100\,001\,000\,000=23\times4\,294\,967\,296+1\,216\,752\,192,\qquad 1\,216\,752\,192<2^{31},$$
故 `int` 版本输出 $1\,216\,752\,192$，与真值相差 $98\,784\,247\,808$。**引理 2 的实验版。**

**坑 F：负 $y$ 的取整/判空。** $y$ 可为 $-10^6$，桶值可能为负；判“桶非空”时不能用 `if(add[x])` 之外的绝对值假设。本实现根本不判空，逐约数相加，所以不受影响——顺手记下这个“因为不遍历桶所以少一个坑”的好处。

### 2.7 在线性与“前缀”这件事：为什么可以边读边答

上面所有推导都在“第 $t$ 次操作之后”这个时间点做，但代码里 $\text{add}$ 是**增量维护**的，必须确认这两件事等价。

**引理 9（前缀充分性）** 设第 $t$ 步后 $\text{add}_t[x]=\sum_{s\le t,\ x_s=x}y_s$（只统计已发生的操作）。则在线算法在第 $t$ 步对查询 $j$ 给出的答案等于引理 3 的真实值。

**证明**：类型 1 操作只把 $\text{add}[x]$ 变成 $\text{add}[x]+y$，其它桶不变，故不变式“$\text{add}[x]$ 恰为截至当前时刻、参数为 $x$ 的所有类型 1 的 $y$ 之和”由归纳保持（初始全 $0$ 成立；每笔写恰好把自己那一笔加进对应的 $x$；类型 2 不改任何桶）。查询时用该时刻的 $\text{add}$ 代入引理 5 的求和式，得到 $\hat a_j$，与引理 3 的表达式逐项相同。$\blacksquare$

**引理 10（可交换性——为何不用记录顺序）** 对固定 $j$，映射 $(x,y)\mapsto \mathbb{1}[x\mid j]\,y$ 的贡献只参与 $(\mathbb{R},+,0)$ 这个交换幺半群。因此同一批写操作不论以何顺序到达，对 $a_j$ 的净效应相同；$\text{add}[\cdot]$ 只是把“按时间累加”重排为“按 $x$ 分桶累加”，不改变结果。

**证明**：$(\mathbb{R},+,0)$ 满足结合律、单位元与交换律。任意两次贡献 $c_1,c_2$ 之和 $c_1+c_2=c_2+c_1$，故对相邻交换不敏感，而任意排列都由相邻交换生成，所以求和值与顺序无关。分桶写法 $\sum_{x\mid j}\sum_{s:x_s=x}y_s$ 与原式 $\sum_{s:x_s\mid j}y_s$ 是同一个有限多重集的元素和（每个 $s$ 恰好被归到 $x_s$ 组一次），故相等。$\blacksquare$

**反面确认（何时这套懒维护会崩）**：
- 若操作含“把 $a_{kx}$ **赋值**为 $y$”，后写覆盖前写，$\text{add}[x]$ 不再是充分统计量（需要按时间戳或倒序处理）。
- 若查询是“区间和/区间最值”，则需要的是聚合量而非常数加法，$\sum_{x\mid j}$ 的对偶不再给出 $O(\sqrt n)$ 的还原。
- 若 $Q$ 与 $m$ 同量级（$10^5$），$Q\sqrt n=10^8$ 就顶到边界；此时应回到 §2.3 的显式分桶并配合预计算约数表（见 §4 末“退化与备用方案”）。**题面明写 $Q\le10^4$，我们按题面执行。**

## 3. 模式总结（Pattern Summary）

按真实思考顺序，一条一个标签，不合并：

1. **explore its property** —— 操作 1 是“在下标的整除格上批量加”：一次写覆盖 $M(x)=\{p:x\mid p\}$，规模 $\lfloor n/x\rfloor$（$x$ 越大越便宜）；一次读只看单个位置 $j$，规模 $1$。形状是 **写宽读窄**，而 $Q\le10^4\ll U\le10^5$ 更放大了这个不平衡。
2. **consider easier version** —— 先不优化，固定单个位置 $j$ 写出它当前值的闭式 $A_j=a_j+\sum_{s:x_s\mid j}y_s$（引理 3）。结论很反常识：**根本不需要维护任何位置的值**，只需要维护“按写参数归档的账本”。
3. **反演 / 对偶换向（倍数 ↔ 约数）** —— 同一张关联矩阵（$(x,j)$ 非零 $\iff x\mid j$），按行展开花 $\lfloor n/x\rfloor$、按列展开花 $\tau(j)$。写侧改成记账 $\text{add}[x]\mathrel{+}=y$（$O(1)$），将成本转移到读侧的 $O(\tau(j))$。
4. **桶规模 ↔ 变换后值的双向核算** —— 桶的个数 $=$ 写参数 $x$ 的值域大小（$\le n$，$8\text{MB}$）；一次读触达的桶数 $=\tau(j)\le240$；发现这些桶要 $\min(B,\lfloor\sqrt j\rfloor)$ 次取模。**注意本题不是“连续段取最值 + 反演”那一类**：写侧作用在离散的倍数集上（无连通性、无叠加顺序），查询是单点，所以双向映射是 $x$（倍数）$\leftrightarrow$ $j$（约数）而不是“区间 $\leftrightarrow$ 端点”；相应地，桶规模按 $x$ 的值域算，还原式是纯求和而非前缀/最值合并。
5. **classic problem solution（第一个）** —— 根号分治：小 $x$ 懒、大 $x$ 沿倍数暴力，读侧扫小桶 $O(B)$，$B^{*}=\sqrt{Un/Q}\approx3162$，$T\approx6.3\times10^7$。可行，但读侧 $3\times10^7$ 次试除是纯浪费。
6. **classic problem solution（第二个，独立技巧）** —— 约数配对枚举 $(d,\ j/d)$：$\lfloor\sqrt j\rfloor$ 次取模拿到**全部**约数（引理 7 的完备 + 无重）。这一步让读侧代价从“必扫 $B$ 个桶”降到 $\min(B,\lfloor\sqrt j\rfloor)$，于是 $B>\sqrt n$ 之后读侧**饱和**、不再随 $B$ 变贵。
7. **阈值反推（分段单调 + 实数比大小）** —— 写侧随 $B$ 单调不增、读侧在 $\sqrt n$ 处饱和：逐段算完 $1.1\times10^8\,(B{=}1000)\;>\;4.2\times10^7\,(B{=}3162)\;>\;1.09\times10^7\,(B{=}10^5)\;>\;1.01\times10^7\,(B{=}n)$，故本题取 $B=n$ 全懒。教训：**“$B$ 越大越好”只在 $B\ge\sqrt n$ 段成立**，跨段必须比数字，不能靠口号（引理 8 的第一版草稿就栽在“读侧与 $B$ 无关”这句错话上）。
8. **值域核算与模拟坑** —— 引理 2 强制 `i64`（桶值本身也溢出，不只 $a_j$）；$j=0$ 必须常量分支；完全平方用 `d*d!=j` 去重；$k\ge1$ 保证不碰 $a_0$。
9. **反面确认** —— 只有加法（交换幺半群）才能分桶重排（引理 10）；出现覆盖型操作、聚合型查询、或 $Q$ 与 $U$ 同量级时本方案退化，需预筛约数表或回到显式分桶（§4.6）。

## 4. 真实解法

**一句话**：把每笔“$x$ 的倍数加 $y$”压缩成桶 $\text{add}[x]\mathrel{+}=y$；查询 $j$ 时输出 $a_j+\sum_{x\mid j}\text{add}[x]$，其中约数用 $(d,\,j/d)$ 配对枚举在 $O(\sqrt j)$ 内取全。

### 4.1 符号表（每个符号都定义）

| 符号 | 类型 / 尺寸 | 存什么 | 初始化 | 一句话记忆 |
|---|---|---|---|---|
| $n$ | `int` | 序列长度，$1\le n\le10^6$ | 读入 | 位置数 |
| $m$ | `int` | 操作条数，$1\le m\le10^5$ | 读入 | 操作数 |
| $U,Q$ | 计数（文中推导用，代码不存） | 类型 1 / 类型 2 的条数，$U+Q=m$，$Q\le10^4$ | — | 写数 / 读数 |
| $a[p]$ | `i64 a[1000005]` | **原始值**（下标 $1..n$），读入后不再修改 | 读入；$a[0]$ 弃用恒为 $0$ | “底子” |
| $\text{add}[x]$ | `i64 add[1000005]` | 截至当前，所有参数为 $x$ 的类型 1 的 $y$ 之和（**懒标记**） | 全局数组自动清零 | “按写参数归档” |
| $M(x)$ | 数学记号 | $\{p\in[1,n]:x\mid p\}$，$\vert M(x)\vert=\lfloor n/x\rfloor$ | — | 倍数集 |
| $\tau(j)$ | 数学记号 | $j$ 的正约数个数，$j\le10^6$ 时 $\le240$ | — | 列宽 |
| $j$ | `int`（代码里复用变量 `x` 承接） | 查询位置，$0\le j\le n$ | 读入 | 列下标 |
| $d$ | `int` | 配对枚举的小半约数，$1\le d\le\lfloor\sqrt j\rfloor$ | 循环内 | 试除指针 |
| $\hat a_j$ | `i64 res` | **变换后值**（当前答案） | 每次查询现算 | 还原结果 |

**下标约定**：本题**保持 1-based**。风格指南默认内部 0-based，但这里“下标整除关系”就是题意本身，$0$ 不是合法位置且题面额外规定 $j=0$ 输出常量 $0$；改成 0-based 会让“倍数”变成“$p+1$ 的倍数”，凭空加一层偏移、把引理 3 的 $x\mid j$ 改成 $x\mid(j+1)$，属于纯亏损。这是本文件唯一偏离 0-based 的地方，理由如上。

**没有 INF 数组**：本题无“不可达/未定义”语义，全局 `a`/`add` 的默认 $0$ 正是需要的单位元，因此**不需要** `fill_n`；若后续把 $\text{add}$ 换成“最值型”懒标记（求 max），才必须 `fill_n(add,n+1,-inf)`，否则 $0$ 会被当成合法标记。

### 4.2 算法步骤（编号）

1. **读入** $n,m$；把 $a_1..a_n$ 读进全局 `i64 a[]`（`a[0]` 保留但不使用）。`add[]` 依赖全局零初始化。
2. **循环 $m$ 次读入操作**，先读 `op`。
3. **$op==1$（写）**：读 $x,y$；执行 $\text{add}[x]\mathrel{+}=y$。**不碰 $a$**，$O(1)$。
4. **$op==2$（读）**：读入 $j$（代码里存进 `x`）。
5. **边界短路**：若 $j==0$，输出 `0` 与换行，`continue`；**不进入求和**（引理：题面规定 $j=0$ 恒输出 $0$，见 §1）。
6. **还原**：`res = a[j]`。令 $d=1,2,\dots,\lfloor\sqrt j\rfloor$（循环条件写成 `(i64)d*d<=j`）：若 $j\bmod d==0$，则 $d$ 是约数，累加 $\text{add}[d]$；再由 $d^2\ne j$ 判断 $j/d$ 是否为**不同**的约数，是则累加 $\text{add}[j/d]$。
7. **输出** `res` 加 `'\n'`。
8. **结束**：`return 0;`。

### 4.3 正确性定理

**定理 1（算法输出正确）** 对每条类型 2 的查询 $j$，算法输出的值等于题面操作序列执行到该时刻后的 $a_j$（$j=0$ 时输出 $0$）。

**证明**：分两块。

- $j=0$：算法在步骤 5 直接输出常量 $0$，与题面“当 $j=0$ 时输出 $0$”逐字一致。
- $j\ge1$：设当前时刻为 $t$。由引理 9，此刻不变式“$\text{add}[x]=\sum_{s\le t,\ x_s=x}y_s$”成立；由引理 5，$A_j=a_j+\sum_{x\mid j}\text{add}[x]$。剩下只需说明步骤 6 的循环**恰好**枚举了 $\{x:x\mid j\}$ 一次：这正是引理 7（完备性保证不漏，无重复保证不多，$d^2=j$ 的分支跳过 $j/d$ 保证平方数不被加两遍）。$a_j$ 自始至终未被修改（步骤 3 只动桶，见引理 11），故它就是闭式里的原始值 $a_j$。三者合一，输出 $=A_j$。$\blacksquare$

**引理 11（不变式：$a$ 恒为原始值）** 算法执行期间 $\forall p\in[1,n],\ a[p]$ 等于输入第二行的第 $p$ 个数。

**证明**：全流程只有步骤 1 写入 $a$；步骤 3 只写 `add`，步骤 6 只读 $a[j]$。故 $a$ 在整个运行中不变。$\blacksquare$

（这条不变式很关键：它保证我们**从不**同时用两种方式记账，不会出现“某笔写已经暴力改进 $a$、另一笔写又进桶”的双重计数或漏计。全懒与全暴力只能二选一，混用时必须像 §2.3 那样按 $x$ 的大小把两笔写划给不同的机制、并保证互斥。）

### 4.4 复杂度定理（含常数与规模核算）

**定理 2（时间）** 设 $U$ 条类型 1、$Q$ 条类型 2（$U+Q=m$），则算法总基本步数
$$T=n+m+U+Q\cdot\lfloor\sqrt n\rfloor+\text{（命中约数的累加次数}\le Q\cdot\max_j\tau(j)\text{）}.$$
代入 $n=10^6,\ m=10^5,\ Q\le10^4,\ \sqrt n=10^3,\ \max\tau=240$：
$$T\le 10^6+10^5+10^5+10^4\cdot1000+10^4\cdot240=10^6+2\cdot10^5+10^7+2.4\cdot10^6\approx1.36\times10^7 .$$
即 $O(n+m+Q\sqrt n)$，最坏约 $1.4\times10^{7}$ 步（主导项是 $10^7$ 次取模），在常规 $10^8$ 量级预算内。

**口径注**：真正求和时有 $U+Q=m\le10^5$（两者不能同时取最大值），上面把 $U\le10^5$ 与 $Q\le10^4$ **各自放大**后再相加，是上界的松弛，结果只会偏大（实际最坏约 $9\times10^4+10^7=1.009\times10^7$ 加 I/O），不影响结论。后续引理 8 的分段比较沿用同一松弛口径，因此各组数字可**横向**比较。

**证明**：读入是 $n+m$ 次取数。步骤 3 是 $O(1)$，$U$ 条合计 $U$。步骤 6 的循环：$d$ 从 $1$ 递增到满足 $d^2\le j$ 的最大整数，迭代次数 $=\lfloor\sqrt j\rfloor\le\lfloor\sqrt{10^6}\rfloor=1000$，每次迭代一次取模；取模为 $0$ 时做 $1$ 或 $2$ 次累加，而“取模为 $0$”的次数恰是小半约数个数 $\le\tau(j)/2$，故累加总次数 $\le\tau(j)\le240$（$j\le10^6$ 时 $\tau$ 的最大值 $240$ 在 $j=720720$ 取到，因式分解与验证见 §2.3）。把 $Q$ 条查询相加即得上界。$\blacksquare$

**定理 3（空间）** 两个 `i64` 的 $1000005$ 长数组，合计 $16\,000\,080\ \text{B}\approx15.26\text{MiB}$，即 $O(n)$。

**证明**：静态全局数组按声明尺寸占空间：$1000005\times8=8\,000\,040$ 字节，两个即 $16\,000\,080$ 字节；$16\,000\,080/2^{20}=15.26\dots\text{MiB}$。除栈上若干 `int` 外无随输入增长的容器。$\blacksquare$

**三种实现的同表核算**（同一份账，逐列对齐）：

| 方案 | 写侧单笔 | 读侧单笔 | 最坏总步数 | 桶规模 / 位置规模 |
|---|---|---|---|---|
| 直接模拟（朴素） | $\lfloor n/x\rfloor$，最坏 $10^6$ | $1$ | $10^{11}$ ✗ | 只有位置 $n$ |
| 根号分治 + 扫小桶（$B=3162$） | $1$ 或 $\le\lfloor n/3163\rfloor=316$ | $B\approx3162$ 次取模 | $6.3\times10^7$ ✓ | 桶 $3162$ / 位置 $n$ |
| **本解法（$B=n$ 退化 + 配对枚举）** | $1$ | $\lfloor\sqrt j\rfloor\le1000$ 次取模 | $1.36\times10^7$ ✓ | 桶 $n$（$8\text{MB}$）/ 位置 $n$ |

最后一行的“桶开满 $n$ 个”**不产生额外时间代价**，因为我们从不遍历桶，只按约数定点访问；付出的代价是 $8\text{MB}$ 空间。这正是“读侧在 $\sqrt n$ 处饱和”带来的自由：饱和之后，把桶开满只花空间、不花时间，而空间换写侧 $U\cdot n/B\to U$ 是稳赚的。

**口径说明（避免两处数字打架）**：定理 2 的 $1.36\times10^7$ **含读入** $n+m=1.1\times10^6$；引理 8 里比较各阈值时用的 $T(B)$ 只统计**操作执行**部分（$1.01\times10^7$），两者相差正是 $n+m+Q\cdot(\text{命中加法的零头})$。同一口径下：$1.36\times10^7$（本解法，含 I/O）对 $6.3\times10^7\sim1.1\times10^8$（各种 $B<n$ 的分治，含 I/O 后同量级），结论不变。

### 4.6 退化与备用方案（若题面条件变了怎么办）

| 若条件变成 | 本方案会 | 应换成 |
|---|---|---|
| $Q$ 涨到 $10^5$（与 $m$ 同量级） | $Q\sqrt n=10^8$，取模占主，可能顶到时限 | 预筛：`for(int x=1;x<=n;++x) for(int j=x;j<=n;j+=x)` 记录每个 $j$ 的约数表（总项数 $n\ln n\approx1.4\times10^7$），查询只走真约数 $\le240$ 个；或回到 §2.3 显式分桶 |
| 出现“赋值/覆盖”型操作 | 桶不再是充分统计量 | 桶里存 (时间戳, 值)，查询时按 $x\mid j$ 取最大时间戳者；或离线倒序 + 并查集跳过 |
| 查询变成区间和 / 最值 | $O(\sqrt n)$ 还原不出聚合量 | 需要按倍数分层的树状数组/分块，另一类问题 |
| 内存被压到 $8\text{MB}$ 以下 | 两个 $8\text{MB}$ 数组不够用 | `add` 用 `int`（$|y|$ 累加仍可能到 $10^{11}$，**不安全**）；正解是只给“出现过的 $x$”开桶：$U\le10^5$ 个桶配排序+二分（$O(\log U)$ 换 $O(1)$），或 $\text{unordered\_map}$，代价是常数变大 |

## 5. 示例代码

**主版本（全懒 + 约数配对枚举，对应 §4.2 步骤 1~8）**

```cpp
// https://www.luogu.com.cn/problem/P1483
// 序列变换：写侧按 x 归档，读侧沿约数还原
#include<bits/stdc++.h>
using namespace std;
using i64=long long;

constexpr int mxn{1000005};       // 1e6 + 5 松弛约定

int n,m;
i64 a[mxn],add[mxn];              // a=原始值(全程只读)，add[x]=所有"1 x y"的累计量

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>n>>m;
	for(int i=1;i<=n;++i)
		cin>>a[i];
	for(int i=0,op,x,y;i<m;++i)
	{
		cin>>op;
		if(op==1)
		{
			cin>>x>>y;
			add[x]+=y;             // 写侧只碰一个桶，O(1)
		}
		else
		{
			cin>>x;                // 此处的 x 就是题面里的 j
			if(x==0)
			{
				cout<<0<<'\n';     // 题面规定：j=0 输出 0，与任何 add 无关
				continue;
			}
			i64 res=a[x];
			//配对枚举 (d,x/d) 取全部约数；桶开到 mxn>n，故无需 x<=B 判据
			for(int d=1;(i64)d*d<=x;++d)
				if(x%d==0)
				{
					res+=add[d];
					if(d*d!=x)            // 完全平方时去重，见 §2.6 坑 A
						res+=add[x/d];
				}
			cout<<res<<'\n';
			// cerr<<x<<' '<<res<<'\n';
		}
	}
	return 0;
}
```

题面条件若变成“查询与写入同量级”，就换这一版：阈值 $B$（$1000<B<10^5$ 之间按引理 8 重新比数字），$x\le B$ 记懒标记，$x>B$ 直接沿倍数改 $a$。

```cpp
constexpr int blen{3162};         // = sqrt(U*n/Q) 的取整，见引理 6
// ... 其余声明同上 ...
if(op==1)
{
	cin>>x>>y;
	if(x<=blen)
		add[x]+=y;
	else
		for(int k=x;k<=n;k+=x)    // 大 x：触达 floor(n/x) <= 316 个位置
			a[k]+=y;
}
else
{
	cin>>x;
	if(x==0)
	{
		cout<<0<<'\n';
		continue;
	}
	i64 res=a[x];
	for(int d=1;d<=blen&&d<=x;++d) // 扫小桶：blen 次取模；因 blen>sqrt(n)=1000，

			res+=add[d];
	cout<<res<<'\n';
}
```
