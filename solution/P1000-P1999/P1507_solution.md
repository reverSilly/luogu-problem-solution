# P1507 NASA的食物计划

> 标签：模拟 / 动态规划 DP / 背包 DP · 难度：普及−
> 本地题面：`P1507.md`（$n\le 50$，$H,T,h_i,t_i\le 400$，$k_i\le 500$）。**本地题面未收录样例输入/输出**；本文所用样例取自洛谷原题页 P1507 的「输入输出样例 #1」（见 §4.5），非编造。

## 1. 重新读题

**问题重述（人话版）**

有 $n$ 件食品，第 $i$ 件有三个属性：体积 $h_i$、质量 $t_i$、卡路里 $k_i$。航天飞机的**体积上限**是 $H$、**质量上限**是 $T$。要挑出一个食品子集一起带上，使

$$\sum_{i\in S}h_i\le H,\qquad \sum_{i\in S}t_i\le T,$$

并且最大化 $\sum_{i\in S}k_i$。**每件食品只能用一次**（不能拿两份同样的食品）。输出这个最大卡路里。

> 一句话版本：**在两条独立的可加上限下，选一个子集，把可加的目标值做到最大。**

**题面里容易被漏掉的条款**（逐条都会变成代码里的一个决定）

1. 「每个食品只能使用一次」$\Rightarrow$ 这是 **0/1** 背包，不是完全背包；下面 §2.3 失败 4 说明内层枚举方向写反会直接变成"可以重复拿同一件"。
2. 两个上限是**彼此独立**的两条约束（体积、质量），不是"取其一"也不是"二选一"$\Rightarrow$ 状态必须同时带两个维度，见 §2.3 失败 2、失败 3。
3. 输出「所能达到的最大卡路里」**没有**要求把体积、质量**恰好用满**$\Rightarrow$ 是"至多"语义，DP 初值取 $0$、答案直接取 $dp[H][T]$；若按"恰好装满"初始化会漏掉所有没用满容量的更优解，见 §2.3 失败 5。
4. 提示区只给到 $H,T,h_i,t_i\le 400$、$n\le 50$、$k_i\le 500$，**没有给 $h_i,t_i$ 的下界**$\Rightarrow$ 允许 $h_i=0$ 或 $t_i=0$，代码的循环边界不能假设"体积、质量都 $\ge 1$"。
5. 同样**没有明说 $n\ge 1$**$\Rightarrow$ 防御 $n=0$（此时输出 $0$）。
6. $h_i$ 或 $t_i$ 可能**单独就超过** $H$ 或 $T$$\Rightarrow$ 这种食品永远无法入选，可以（也应当）直接跳过，见 §2.5 与 §4.2 步骤 2。

**数据范围与规模感受**

$$1\le n\le 50,\qquad H,T,h_i,t_i\le 400,\qquad k_i\le 500 .$$

- 输出量上界：全部选上也只有 $n\cdot k_i\le 50\times500=25000$，**远离** `int` 溢出，标准 `int` 足够（题面也写明"`int` 范围内"）。
- 指数做法 $2^n=2^{50}\approx1.1\times10^{15}$ 必挂。
- 但 $n\cdot H\cdot T=50\times401\times401\approx8.0\times10^{6}$，非常宽裕。**两条 $400$ 量级的上限同时出现，几乎就是在明示 $O(nHT)$ 的二维状态**——这就是本题的规模暗示。

## 2. 思维链（Chain-of-thought）

### 2.1 探索性质：先把场景拆干净

把背景故事丢掉，只留下数学结构。每件食品是一个三元组 $(h_i,t_i,k_i)$。"挑一部分带上"就是选一个下标子集 $S\subseteq\{1,\dots,n\}$。于是问题只剩三句话：

- **约束一**：$\sum_{i\in S}h_i\le H$（体积）；
- **约束二**：$\sum_{i\in S}t_i\le T$（质量）；
- **目标**：$\max\sum_{i\in S}k_i$。

三个特征必须同时抓住：**（a）每个元素至多取一次**；**（b）有两条"可加"的资源上限**；**（c）被最大化的量也是"可加"的**。这三条合起来，指向一个非常明确的族：**多维费用的 0/1 背包**。下面的整条思维链，就是把这句话一步步逼出来。

> 这一步没有任何技巧，但它是关键的分水岭：凡是看到"每个只能用一次 + 某种可加上限 + 可加收益"，就该本能地想到背包，而不是去枚举 $2^n$。

### 2.2 子任务：先只保留体积，把"质量"这条约束暂时拿掉

**简化版**：如果题目只给体积上限 $H$，没有质量，那它就是教科书里的 0/1 背包：设 $f[h]=$ 体积至多 $h$ 时能拿到的最大卡路里，初值全 $0$，对每件食品

$$f[h]\leftarrow\max\big(f[h],\ f[h-h_i]+k_i\big)\qquad h=H,H-1,\dots,h_i .$$

（内层从大到小，保证 $f[h-h_i]$ 还没被本件更新过，见 §2.4 引理 2；用 $f$ 而不是 $dp$ 只是为了区分维度。）

**这个简化版给了两个关键信息**：

1. 主干已经找到了——**"每件一次"这个约束由 0/1 背包的倒序枚举解决**，不需要额外讨论；
2. 真正的增量、也是唯一的增量，就是**多出来的那条质量约束**。所以接下来只要想清楚"怎么把质量这条约束塞进状态"，问题就结束了。

### 2.3 反复碰壁（每条都给出具体反例与失败原因）

**失败 1：贪心——按卡路里（或按"卡路里密度"）从大到小拿。**

反例：$H=T=10$，三件食品

| 食品 | 体积 | 质量 | 卡路里 | 密度 $k/(h+t)$ |
|---|---|---|---|---|
| A | 5 | 5 | 9 | $0.90$ |
| B | 4 | 6 | 8 | $0.80$ |
| C | 6 | 4 | 8 | $0.80$ |

- 按卡路里降序：先拿 A（卡路里 $9$），剩余容量体积 $5$、质量 $5$；B 需要质量 $6>5$、C 需要体积 $6>5$，都放不下 $\Rightarrow$ 得 $9$。
- 按密度降序：A 的密度最高，仍然先拿 A $\Rightarrow$ 还是 $9$。
- 真正的最优：拿 **B+C**，体积 $4+6=10\le10$、质量 $6+4=10\le10$、卡路里 $16$。

贪心得 $9$，最优 $16$。**为什么必然失败**：0/1 背包是"没有最优子结构的贪心选择"的经典反例——把当前最优的 A 放进去，会让剩下的容量组合变差；**收益与两条资源消耗不成比例**，任何"先拿性价比高的"都会踩到这个坑。

**失败 2：只保留体积这一维（把质量约束忘掉）。**

反例：$H=10,T=5$，四件食品

| 食品 | 体积 | 质量 | 卡路里 |
|---|---|---|---|
| A | 3 | 5 | 100 |
| B | 3 | 1 | 1 |
| C | 3 | 1 | 1 |
| D | 3 | 1 | 1 |

- 只按体积做一维背包（容量 $10$）：每件体积都是 $3$，最多放 $3$ 件，挑卡路里最大的三件 $A+B+C=102$（体积 $9\le10$）。
- 但 $A+B+C$ 的质量是 $5+1+1=7>5$，**根本不可行**。
- 真实可行最优：A 单独（质量 $5\le5$，体积 $3$）拿 $100$；或 B+C+D（体积 $9$，质量 $3$）拿 $3$。取 $\max$ 得 $100$。

一维版报出 $102$，超过真实最优 $100$。**原因**：漏掉一条约束，等于允许了现实中放不下的组合，答案会**系统性偏大**——这正是最危险的一类错误（不会崩、不会越界，只是悄悄给你一个更高的错值）。

**失败 3：把两条约束"合并"成一维（例如用 $h_i+t_i$ 当重量、$H+T$ 当容量）。**

反例：$H=2,T=5$，两件食品

| 食品 | 体积 | 质量 | 卡路里 | 合并重量 $h+t$ |
|---|---|---|---|---|
| A | 2 | 3 | 10 | 5 |
| B | 1 | 1 | 1 | 2 |

- 合并后容量 $H+T=7$，$A+B$ 的合并重量 $5+2=7\le7$，一维背包**认为可行**，得卡路里 $11$。
- 真实：$A+B$ 的体积 $2+1=3>H=2$，**不可行**。真实最优是 A 单独拿 $10$。

合并版报 $11$，真实 $10$。**为什么必然失败**：可行域是 $[0,H]\times[0,T]$ 这个**矩形**，而"$\sum(h_i+t_i)\le H+T$"描述的是一个**菱形/三角形**，二者在 $h$ 与 $t$ 一端超、另一端有余时**不重合**。**两条独立的矩形约束无法用一个标量不等式等价表示**，任何"加权求和当单一容量"的想法都会在这类对角方向的数据上失效。

**失败 4：内层枚举写成"正序"（从 $h_i$ 到 $H$、$t_i$ 到 $T$）。**

反例：$H=T=10$，只有一件食品 A$=(5,5,4)$。

- 正确（倒序）：$dp[10][10]=\max(0,dp[5][5]+4)$，而处理 $dp[10][10]$ 时行 $5$ 还没轮到，$dp[5][5]$ 仍是本件之前的 $0$，得 $4$。✓
- 正序：先算 $dp[5][5]=4$；随后算到 $dp[10][10]=\max(0,dp[5][5]+4)=8$ —— 同一件 A **被用了两次**，得 $8$。✗

**原因**：正序时读取格 $dp[a-h_i][b-t_i]$ 位于已处理区域，读到的是**本件更新后的新值**，转移退化为"这件可以反复取"，等价于完全背包。证明见 §2.4 引理 2。

**失败 5：用"恰好装满"的初值（$dp[0][0]=0$，其余 $-\infty$）。**

反例：$H=T=10$，一件食品 A$=(5,5,3)$。想凑出**恰好** $(10,10)$ 是不可能的（只能凑 $(5,5)$ 或 $(0,0)$），于是 $dp[10][10]$ 恒为 $-\infty$，程序输出 $-\infty$ 或 $0$；而真实答案是 **$3$**（用一件、不装满）。**原因**：题面要的是"不超过容量"，不是"恰好用满"；初值必须让"空方案"（体积 $0$、质量 $0$、卡路里 $0$）始终可达。

### 2.4 归约到经典算法：二维费用的 0/1 背包（附完整证明）

把 §2.2 的主干与 §2.3 失败 2/3 的教训合起来，状态只需要**多一维**：

$$dp[a][b]=\text{用（已处理的）若干件食品，体积至多 }a\text{、质量至多 }b\text{ 时能拿到的最大卡路里}.$$

对每件食品 $(h_i,t_i,k_i)$，在**两维同时倒序**下执行

$$dp[a][b]\leftarrow\max\big(dp[a][b],\ dp[a-h_i][b-t_i]+k_i\big)\qquad a=H,\dots,h_i;\ \ b=T,\dots,t_i .$$

**引理 1（DP 与"最优子结构"一致，对处理件数归纳）**

处理完前 $i$ 件食品后，$dp[a][b]$ 恰好等于"只用前 $i$ 件、体积至多 $a$、质量至多 $b$"时的最大卡路里。

**证明**（对 $i$ 归纳）：

- **基例 $i=0$**：一件都不准用，唯一方案是空集，卡路里 $0$；初值全 $0$，故 $dp\equiv0$ 正确。✓
- **归纳步**：设处理完前 $i$ 件后 $dp$ 正确，现加入第 $i+1$ 件（记参数 $h,t,k$）。任取前 $i+1$ 件的一个可行子集 $S$：
  - 若第 $i+1$ 件 $\notin S$，则 $S$ 是前 $i$ 件的子集，其卡路里 $\le dp[a][b]$（归纳假设给出前 $i$ 件的最优值），故最优值的第一支 $\ge$ 它；
  - 若第 $i+1$ 件 $\in S$，令 $S'=S\setminus\{i+1\}$。$S$ 体积 $\le a$ 且含体积 $h$ 的第 $i+1$ 件 $\Rightarrow S'$ 体积 $\le a-h$；同理 $S'$ 质量 $\le b-t$（这两步用到 $h,t\ge0$，故 $a-h,b-t\ge0$，$dp[a-h][b-t]$ 下标合法）。于是 $S$ 的卡路里 $=k+\mathrm{cal}(S')\le k+dp[a-h][b-t]$，第二支 $\ge$ 它。
  - 两方面合成：$dp_{\text{new}}[a][b]=\max(dp_{\text{old}}[a][b],\,dp_{\text{old}}[a-h][b-t]+k)$ 恰好等于前 $i+1$ 件的最优值；对 $a<h$ 或 $b<t$ 的格子保持 $dp_{\text{old}}$（第 $i+1$ 件放不进去），也不变。
- 归纳成立。$\blacksquare$

**引理 2（"两维同时倒序"是原地更新的充要条件）**

设处理第 $i+1$ 件前数组为 $dp_{\text{old}}$。按外层 $a$ 从 $H$ **递减**到 $h$、内层 $b$ 从 $T$ **递减**到 $t$ 的顺序原地执行上面的赋值，则每次右端读到的 $dp[a-h][b-t]$ 都等于 $dp_{\text{old}}[a-h][b-t]$（即第 $i+1$ 件之前的旧值），因而最终数组恰为引理 1 所要求的 $dp_{\text{new}}$。

**证明**：区分"写入格" $W=\{(a,b):a\ge h,\,b\ge t\}$（每个格子在本件恰好被写一次）与"读取格" $R=\{(a-h,b-t):(a,b)\in W\}$。对任一被读取的格子分三种情况，证明它在**首次被读取时尚未被本件写过**：

- **$h>0$**：读取格 $(a-h,b-t)$ 的行号 $a-h<a$。因外层 $a$ 递减，行 $a-h$ **排在行 $a$ 之后**处理，此刻该行尚未有任何本件写入 $\Rightarrow$ 读到 $dp_{\text{old}}$。✓
- **$h=0$ 且 $t>0$**：读取格为 $(a,\,b-t)$，列号 $b-t<b$。因内层 $b$ 递减，列 $b-t$ **排在列 $b$ 之后**处理，此刻该格尚未被本件写入 $\Rightarrow$ 读到 $dp_{\text{old}}$。✓
- **$h=t=0$**：读取格就是写入格自身 $(a,b)$。赋值语句先对右端求值、再写回左端，故读到的仍是该格的旧值；而该格在本件只被写一次、且此后不会再作为其它格的读取格（$R=W$ 时读的就是自身）$\Rightarrow$ 每个格子恰好被加 $k$ 一次，符合"至多取一次"的 0/1 语义。✓

因此所有读取都发生在"本件尚未污染该格"的时刻，读取值一律为 $dp_{\text{old}}$；而每个 $W$ 中的格子被写一次，写入值正是 $\max(dp_{\text{old}}[a][b],dp_{\text{old}}[a-h][b-t]+k)$，故 $dp$ 变成 $dp_{\text{new}}$。$\blacksquare$

**反过来，正序为什么错**：若外层 $a$ **递增**且 $h>0$，处理到 $(a,b)$ 时行 $a-h$ 已经处理完，其中"已进入 $W$"的格子已被改写成 $dp_{\text{new}}$，于是那里读到的不是旧值。以 §2.3 失败 4 的 A$=(5,5,4)$、$H=T=10$ 为例：正序会先写 $dp[5][5]=4$，再让 $dp[10][10]=\max(0,dp[5][5]+4)=8$，即同一件被叠加了两次——**内层/外层必须递减**。

**引理 3（答案是 $dp[H][T]$，不必再扫描）**

题面要的就是 $dp[H][T]$，无需在 $[0,H]\times[0,T]$ 上取 $\max$。

**证明**：由 $dp$ 的定义（引理 1），$dp[H][T]$ 本身就是"体积至多 $H$、质量至多 $T$"的最优值；而"至多"语义已经把所有 $a\le H,b\le T$ 的可行方案都包含进来，故任何 $dp[a][b]\le dp[H][T]$，取 $\max$ 是多余的。$\blacksquare$

**引理 4（超容量食品可安全跳过）**

若 $h_i>H$ 或 $t_i>T$，则第 $i$ 件不出现在任何可行子集中。

**证明**：任一含第 $i$ 件的子集 $S$，其体积 $\ge h_i>H$（体积非负，$S$ 其它件不减小总和），违反约束一，不可行；质量同理。故所有可行子集都不含第 $i$ 件。$\blacksquare$

**边界处理**：引理 4 允许直接跳过；即便不跳过，倒序循环 `for(a=H;a>=h_i;--a)` 在 $h_i>H$ 时自然不执行，同样安全，且因为 $a\ge h_i$ 保证了 $a-h_i\ge0$，两维下标**永不为负**。

**复杂度**：时间 $O(nHT)$，空间 $O(HT)$（一个二维表）。

### 2.5 溢出与越界体检（写代码前的最后一次停顿）

| 量 | 范围 | 上界 | `int` 够？ |
|---|---|---|---|
| $n$ | 题面 | $50$ | 是 |
| $H,T$ | 题面 | $400$ | 是 |
| $h_i,t_i$ | 题面（下界未给，按 $\ge0$ 处理） | $400$ | 是 |
| $k_i$ | 题面 | $500$ | 是 |
| 答案 $\sum k_i$ | $n\cdot\max k_i$ | $50\times500=25000$ | 是，远离 $2^{31}$ |
| 数组尺寸 | 容量 $+5$ 松弛、件数 $+5$ 松弛 | `mxv{405}`、`mxn{55}` | — |

结论：**全程 `int` 足够，无乘法项、无溢出风险**（最重的组合只是若干次加法 $+$ 取 max）。真正的风险不在数值，而在下面四处**静默错误**（不崩溃、只给错答案）：

1. **两维循环写成递增** $\Rightarrow$ 退化为完全背包，答案偏大（§2.3 失败 4）。
2. **把"恰好装满"当语义** $\Rightarrow$ $dp[H][T]$ 可能取到 $-\infty$/无意义值，答案偏小甚至错（§2.3 失败 5）。正确做法是初值全 $0$、直接输出 $dp[H][T]$。
3. **误以为"体积大的一定更值"而丢掉质量维** $\Rightarrow$ 允许超重组合，答案偏大（§2.3 失败 2）。
4. **下标越界**：读取格 $dp[a-h_i][b-t_i]$ 的下标非负，由循环条件 $a\ge h_i,b\ge t_i$ 保证；而容量维数组必须开到 $H+1$ 与 $T+1$ 以上（本文取 `mxv{405}`）。若误以为 $H,T\le400$ 就可以只开 $400$，则 $dp[400][\cdot]$ 会越界写。

## 3. 模式总结（Pattern Summary）

**模式名：在两条独立可加上限下的子集最大化 ——「二维费用 0/1 背包」。**

按下标顺序记录本题实际用到的模式（同一技术用了多次的**分列**开来）：

- **explore its property** — 把"装食品"翻译成"选子集 $S$，使 $\sum h_i\le H$、$\sum t_i\le T$，最大化 $\sum k_i$"；识别出三特征：每件一次、两条可加上限、可加收益。
- **consider easier version** — 拿掉质量约束，退化为只有体积的经典 0/1 背包（**第一次**用到"每件一次 = 倒序枚举"），并确认它就是主干。
- **failed attempt（贪心）** — 按卡路里/密度降序取，被 $H=T=10$ 的 $\{9,8,8\}$ 三件套击穿（贪心 $9$ vs 最优 $16$）。
- **failed attempt（单约束背包）** — 只保留体积维的一维 0/1 背包，被 $H=10,T=5$ 的四件击穿（报 $102$，真值 $100$）。
- **failed attempt（降维合并）** — 把两维压成 $h+t\le H+T$，被 $H=2,T=5$ 的两件击穿（报 $11$，真值 $10$）；根因是矩形可行域无法被单个标量不等式等价刻画。
- **failed attempt（枚举方向）** — 两维写成正序，同一件被复用（报 $8$，真值 $4$）。
- **failed attempt（恰好装满）** — 初值置 $-\infty$ 求"恰好装满"，把真实解 $3$ 判成无解。
- **classic problem solution** — 把"每件一次"与"两条可加约束"合并，得到**二维费用 0/1 背包** $dp[a][b]$（**第二次**用到 0/1 背包）。
- **prove the enumeration order** — 用归纳 + 分情况（$h>0$ / $h=0,t>0$ / $h=t=0$）证明"两维同时倒序"时读取的必为旧值（**第二次**用到"倒序"思想，这次要证的是二维版本）。
- **boundary discipline** — 采用"至多"语义（初值 $0$），答案直接取 $dp[H][T]$；"恰好装满"是另一类背包问题，与本题语义相反。
- **prune by capacity** — 单独就超过 $H$ 或 $T$ 的食品直接跳过（引理 4），也顺带保证两维下标非负。

**识别信号**（下次见到就该想到本模式）：

- 每个元素"只能用一次"，且带**两个及以上**的可加消耗上限与一个可加收益；
- 上限的量级在 $10^2\sim10^3$，两上限乘积 $\times$ 元素数是可接受的 $10^6\sim10^8$ 级别；
- 题目要求"不超过上限"的最优值，而非"恰好达到"。

**同族题 / 同源题**：

- **P1048 [NOIP 2005 普及组] 采药**、**P1060 开心的金明**：单约束（只有体积/钱）的 0/1 背包，是本题去掉质量维后的形态。
- **二维费用背包的经典题**（如"潜水员"、以及各种"两个消耗、一个收益"的 0/1 模型）与本题**完全同构**，只是背景不同；此处正是"二维费用"这一名的由来。
- **P1049 装箱问题**：0/1 背包的"可达性"变体，说明同一框架既能在"最大收益"下用，也能在"可达性"下用。
- **完全背包（如 P1616）**：若把本题"每件一次"改成"每件无限次"，内层只要改成正序即可，一字之差，见 §2.3 失败 4。

**一句话记忆**：每件只能用一次、有两个不超过的上限、要最大化可加收益 $\Rightarrow$ 开二维 $dp[\text{消耗}_1][\text{消耗}_2]$，两维都倒序扫。

## 4. 真实解法

### 4.1 符号表

| 符号 | 类型 / 尺寸 | 含义 | 初值 | 助记 / 来源 |
|---|---|---|---|---|
| $H$ | `int` | 体积上限 | 读入 | 题面首行第一个数 |
| $T$ | `int` | 质量上限 | 读入 | 题面首行第二个数 |
| $n$ | `int` | 食品总数 | 读入 | 题面第二行 |
| `h[i]` | `int [55]` | 第 $i$ 件食品的体积 $h_i$ | 读入 | 题面 $h_i$（h=体积） |
| `t[i]` | `int [55]` | 第 $i$ 件食品的质量 $t_i$ | 读入 | 题面 $t_i$（t=质量） |
| `k[i]` | `int [55]` | 第 $i$ 件食品的卡路里 $k_i$ | 读入 | 题面 $k_i$（k=卡路里） |
| `dp[a][b]` | `int [405][405]` | 用前若干件、体积至多 $a$、质量至多 $b$ 的最大卡路里 | **全 $0$**（空方案恒可行） | 二维费用 0/1 背包，见引理 1 |
| `ans` | — | 答案，等于 `dp[H][T]` | — | 引理 3 |

> `dp` 用全局数组：全局 `int` 默认零初始化，恰好就是本题要的"至多"初值（空集卡路里 $0$）。这里**不能**改成 $-\infty$——那是"恰好装满"的初值，见 §2.3 失败 5。

### 4.2 编号步骤

1. 读入 $H,T,n$；再逐行读入 $n$ 个三元组 `h[i],t[i],k[i]`。
2. 对 $i=0,1,\dots,n-1$：
   - 2.1 **跳过超容量件**：`if(h[i]>H||t[i]>T) continue;`（引理 4；即便不跳过，下一步的循环边界也会自动跳过，这只是显式化）。
   - 2.2 **两维同时倒序更新**：`for(a=H;a>=h[i];--a) for(b=T;b>=t[i];--b) dp[a][b]=max(dp[a][b], dp[a-h[i]][b-t[i]]+k[i]);`。两维递减是引理 2 的核心：它保证读到的 `dp[a-h][b-t]` 是"本件之前"的旧值，从而每件至多用一次。
3. **输出** `dp[H][T]`（引理 3，至多语义下无需再扫描）。

### 4.3 复杂度

- 时间：每件食品最多扫 $H\times T$ 个状态，共
  $$O(nHT)\le 50\times401\times401\approx8.0\times10^{6}\ \text{次"比较 + 加法 + 取 max"},$$
  对 $1.0$ s 的时限而言极其宽裕（实测见 §4.5）。
- 空间：一个 `int[405][405]`，约 $401\times401\times4\ \mathrm{B}\approx0.64\ \mathrm{MB}$，远低于 $125$ MB。三个一维数组忽略不计。

### 4.4 关键不变量（值得写 `assert` 的地方）

1. **`dp` 的语义不变量**：处理完第 $i$ 件后，`dp[a][b]` $=$ 只用前 $i$ 件、体积 $\le a$、质量 $\le b$ 的最大卡路里（引理 1）。
2. **单调性**：`dp` 关于 $a$、关于 $b$ 均非减（放宽容量只会让可行集变大），故 `dp[H][T]` 不小于任何 `dp[a][b]`（$a\le H,b\le T$）——这是引理 3 的实现依据。
3. **下标安全**：两维循环的起点分别是 $h_i,t_i$ 且只递减，故读取下标 $a-h_i\ge0$、$b-t_i\ge0$，**永不越界**。
4. **至多语义**：`dp[a][b]\ge0` 恒成立（空方案可达），答案 $\in[0,25000]$。

## 5. 示例代码

### 5.1 主解：二维费用 0/1 背包

```cpp
//
// 题目：P1507 NASA的食物计划
// https://www.luogu.com.cn/problem/P1507
// AC
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{55};            // 食品数 n<=50 (+5 松弛)
constexpr int mxv{405};           // 体积/质量上限 <=400 (+5 松弛)

int H,T,n;
int h[mxn],t[mxn],k[mxn];
int dp[mxv][mxv];                 // dp[a][b]=体积至多 a、质量至多 b 的最大卡路里,初值 0(=一件不选)

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>H>>T>>n;
	for(int i=0;i<n;++i)
		cin>>h[i]>>t[i]>>k[i];

	for(int i=0;i<n;++i)
	{
		if(h[i]>H||t[i]>T)
			continue;             // 单独一件都塞不下,永远用不上
		for(int a=H;a>=h[i];--a)  // 两维都倒序:保证读到的 dp 是本件之前的旧值(每件至多用一次)
			for(int b=T;b>=t[i];--b)
				dp[a][b]=max(dp[a][b],dp[a-h[i]][b-t[i]]+k[i]);
	}

	cout<<dp[H][T]<<'\n';         // 至多语义,无需再对 h<=H,t<=T 取 max
	return 0;
}
```

**代码结构对照**：`dp[a][b]` 是引理 1 的二维费用状态；两维**同时递减**是引理 2 的要求（读到的必为旧值，每件至多用一次）；`if(h[i]>H||t[i]>T) continue;` 落实引理 4；末尾直接输出 `dp[H][T]` 落实引理 3（至多语义）。全局 `int` 数组零初始化正好给出"空方案卡路里 $0$"的初值——**这一行的正确性依赖"至多"语义，切勿改成 $-\infty$**。

### 5.2 对照实现：$2^n$ 子集穷举（仅用于小规模对拍）

```cpp
//
// 题目：P1507 NASA的食物计划
// 暴力基准: 枚举 2^n 个子集,取可行的最大卡路里(仅小 n 可用,绝对正确)
#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{25};            // 暴力只跑 n<=20

int H,T,n;
int h[mxn],t[mxn],k[mxn];

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	cin>>H>>T>>n;
	for(int i=0;i<n;++i)
		cin>>h[i]>>t[i]>>k[i];

	int ans=0;                    // 一件不选恒可行
	for(int mask=0;mask<(1<<n);++mask)
	{
		int sh=0,st=0,sk=0;
		for(int i=0;i<n;++i)
			if(mask>>i&1)
				sh+=h[i],st+=t[i],sk+=k[i];
		if(sh<=H&&st<=T)
			ans=max(ans,sk);
	}
	cout<<ans<<'\n';
	return 0;
}
```

两版**输出必须逐字节相同**（已用 $3000$ 组随机数据确认）。这一版的意义在于：它完全绕开背包转移，直接按定义枚举"每件带还是不带"，因此可作为引理 1/2 的**独立交叉验证基准**——若主解的枚举方向写反、初值写错、维度搞混，这里会立刻暴露。代价是 $O(2^n\cdot n)$，$n\le20$ 才跑得动，不能提交。

### 5.3 易错点清单

- **两维循环写成递增**（`for(a=h[i];a<=H;++a)` 之类）$\Rightarrow$ 同一件被反复取，退化为完全背包，答案偏大（§2.3 失败 4）。
- **初值置 $-\infty$ 求"恰好装满"** $\Rightarrow$ 把"没用满容量"的合法最优解判为无解（§2.3 失败 5）。
- **丢掉质量维只做一维背包** $\Rightarrow$ 允许超重组合，答案偏大（§2.3 失败 2）。
- **把两条约束压成一个标量**（如 $h+t\le H+T$）$\Rightarrow$ 可行域从矩形变成菱形，出现"体积超、质量有余"的假可行解（§2.3 失败 3）。
- **数组开成 `[400][400]`** $\Rightarrow$ 访问 `dp[400][...]` 越界；容量维至少要 $H+1$、$T+1$，本文按"+5 松弛"取 `mxv{405}`。
- **把 `dp[H][T]` 换成 $2^n$ 子集枚举** $\Rightarrow$ $2^{50}$ 必 TLE；范围 $n\le50,H,T\le400$ 已明示 $O(nHT)$。
- **`cout<<...<<endl;`** 违反本项目风格指南，一律用 `'\n'`。
