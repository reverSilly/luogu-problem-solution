# P1305 新二叉树 —— 题解

## Part 1 · 重述题目

给定一棵二叉树的"逐节点"描述，要求输出它的**前序遍历**（先根、再左子树、再右子树）。

输入分两部分：

- 第 1 行：节点数 `n`（`1 ≤ n ≤ 26`）。
- 接下来 `n` 行：每行 3 个字符，依次为 `节点 左儿子 右儿子`。空节点用 `*` 表示。**保证第一行给出的节点就是根**。

输出：前序遍历得到的节点字符序列（无空格、无分隔符）。

---

## Part 2 · 思考过程（Chain of Thought）

> 以"会基础数学/编程、正在学 OI 的学生"的口吻，按真实思考顺序展开。每一步都给出完整证明，不做"显然"式省略。

### Step 0 —— 读懂输入的特殊机制（先刻画它）

先把输入的"奇怪之处"说清楚，再谈算法。

普通教材里描述二叉树，要么给一棵已建好的树让你遍历，要么用括号/数组编码整棵树。本题的输入是：

- **n 个"行"，每行是 `节点 左儿子 右儿子` 的三元组**，且**行的顺序没有规定**——只有"第一行必是根"是额外保证；
- **`*` 占位空儿子**；
- **没有显式 parent 字段**。

我需要回答两个问题：

**Q1.** 任意一棵合法的二叉树，能否由这种"逐节点三元组"的描述唯一确定？

**Q2.** 给定一个节点 X，我要查"它的左儿子是谁 / 右儿子是谁"，该往哪查？

对 Q2：三元组的第一个字符就是"被描述的节点"，第二/第三个字符分别是它的左/右儿子。所以"以 X 为被描述节点的那一行"就是 X 的孩子信息所在。问题变成：**如何快速定位'以 X 为被描述节点的那一行'？** 这正是需要建一张"节点 → 索引"的表，即**建图**（见 Step 3）。

对 Q1：我先证明"输入自洽、无矛盾"，即每个节点恰好被描述一次、每个非空儿子恰好属于它唯一的父。

**Lemma 0.1（父唯一性）。** 在合法输入中，每个节点 `v ≠ 根` 作为某三元组的第二或第三字符（即"儿子"）**恰好出现一次**；根节点作为儿子**出现 0 次**；`*` 不计入节点。

**证明。** 由二叉树的定义：每个节点除根外有且仅有一个父，每个父最多一个左儿子 + 最多一个右儿子。"逐节点描述"把每个节点的 `(节点, 左, 右)` 完整写出，所以"节点 v 作为某节点的左/右儿子"这件事，在描述中**恰好出现一次**（出现在它的父那行）或**出现 0 次**（v 是根）。由于题目保证"数据合法、第一行是根"，上述性质对合法输入成立。∎

**Lemma 0.2（无环、连通）。** 把每条非空"父子边"画出来，得到的图是一棵以第一行节点为根的**二叉树**（连通、无环、n 个节点 n-1 条边）。

**证明。** 边数：n 行三元组，每个儿子位置若非空则贡献一条边。由 Lemma 0.1，非根节点各贡献 1 条入边（它作为某父的儿子），根贡献 0 条入边；故非空儿子总数 = n - 1，边数 = n-1。无环：若存在环，则环上每个节点都有入边，且循环节点最终会指回自己，与"每个节点只有一个父、父的儿子唯一"矛盾（环上两点会互指为对方的父，违反父唯一）。连通：根第一行给出；每个非根节点都有唯一父，反复上溯父必然在有限步内停在根（否则形成环，已被排除），故所有节点与根连通。∎

> 这两个引理说明：**输入是合法二叉树的标准"逐节点"编码，信息无冗余、无矛盾。** 我接下来只要建出这张图，遍历就有明确语义。

### Step 1 —— 先想"最笨"的办法（探索性质）

如果 n 很小（比如 n=5），我根本不想建任何表：

- 找根：第一行第一个字符，已知。
- 要遍历根：递归"找以根为节点的那一行" → 读它的左儿子 L、右儿子 R → 递归处理 L（若 L≠*）→ 递归处理 R（若 R≠*）。

"找以 X 为节点的那一行"= **线性扫描 n 行**，O(n)。整棵树每个节点被访问一次，每次 O(n)，总 O(n²)。

n ≤ 26 时，O(n²) = 最多 676 次比较，**完全可以跑过**。这就是"剥离一切优化、最直接的暴力"。但它有两个痛点：

1. "找那一行"要重扫，重复劳动；
2. 递归深度最坏 O(n)（退化成链），n=26 没问题，但如果换到 n=1e5 的同类题就会栈溢出——本题不需要担心，但记下这一点。

**结论：** 暴力 O(n²) 已经能 AC（n≤26）。但"找那一行"的 O(n) 扫描是明显可以消除的瓶颈 → 引出 Step 3 的建表。

### Step 2 —— 前序遍历的经典递归（经典技巧）

不管输入怎么给，**"在已建好的二叉树上做前序遍历"是同一个经典问题**：

```
preorder(X):
    if X 为空: return
    输出 X
    preorder(左儿子)
    preorder(右儿子)
```

递归正确性：

**Lemma 2.1（前序递归的正确性）。** 对任意二叉树 T、节点 X，`preorder(X)` 输出的序列，恰好是 T 中以 X 为根的子树的"先根、左子树、右子树"深度优先序列。

**证明。** 对 X 子树的大小 m（节点数）做归纳。
- 基例 m=0（X 为空）：不输出，空序列正确。
- 基例 m=1（X 为叶子）：输出 X，不递归，序列 = [X]，正确。
- 归纳步：设 X 的左子树规模 a、右子树规模 b，a+b+1=m。由归纳假设 `preorder(左)` 输出左子树的前序序列 A（长度 a），`preorder(右)` 输出右子树的前序序列 B（长度 b）。`preorder(X)` 的实际输出 = [X] ∘ A ∘ B。而前序的定义正是"先根、左子树前序、右子树前序"，所以 [X]∘A∘B 即 X 子树的前序序列。∎

这告诉我：**只要我能 O(1) 地由节点查左/右儿子，递归遍历就是 O(n)。** 瓶颈只剩"O(1) 查儿子"。

### Step 3 —— 建表：把"找那一行"从 O(n) 降到 O(1)（经典技巧：散列/索引）

"找以 X 为节点的那一行"本质是**按第一个字符做查找**。n≤26、节点是单个大写字母（或 `*`），最自然的索引方式：

- 用一个数组 `son[2][256]`，`son[0][c]` = 节点 c 的左儿子（char，`*` 表示空），`son[1][c]` = 节点 c 的右儿子；
- 读入一行 `u l r` 时，直接 `son[0][u]=l; son[1][u]=r;`。

这样"查 X 的左儿子"就是 `son[0][X]`，O(1)。读入总 O(n)。

> 为什么用 ASCII 下标而不是映射成 0..25？因为字符本身是天然的离散键，直接做数组下标最省事；`*` 的 ASCII 是 42，落在合法下标内，且我们不会以 `*` 为"节点"去查（`*` 只作为儿子出现），所以无需特判初始化。

**复杂度：** 读入 O(n) 建表 + 遍历 O(n)，合计 **O(n)**。对 n≤26 绰绰有余，对 n=1e5 也稳。

### Step 4 —— 把"找根"也定下来

根 = 第一行第一个字符。读入时顺手记下 `root` 即可。也可用 Lemma 0.1（"作为儿子出现 0 次的那个节点"）事后判定，但既然题目直接保证第一行是根，取第一行第一个字符最简洁。

### Step 5 —— 递归深度与 n 的关系（讨论分类）

- n ≤ 26：递归深度 ≤ 26，栈完全安全，直接递归。
- （若 n 很大）：需考虑迭代/显式栈或增大栈，但本题不需要。

**最终算法：建 O(1) 查儿子的表 + 经典前序递归，O(n)。**

## Part 3 · 模式总结

- **探索性质（读特殊机制）** — 输入是"逐节点三元组"编码，信息无冗余无矛盾；"查儿子"=按节点查对应行。
- **先想暴力** — 线性扫描找行 + 递归遍历，O(n²)，n≤26 已能 AC，但暴露"找行 O(n)"瓶颈。
- **经典技巧①（前序递归）** — 在已建树上前序遍历，归纳法证明递归序列正确。
- **经典技巧②（散列/索引建表）** — `son[方向][字符]` 把"查儿子"降到 O(1)，消掉 O(n²) 瓶颈。
- **定根** — 直接取第一行第一个字符（题目保证）。
- **递归深度分类** — n≤26 直接递归安全；无需迭代。

## Part 4 · 真实解法（代码做什么）

### 符号表（Notation Glossary）

| 符号 | 含义 | 初始化 | 助记 |
|---|---|---|---|
| `n` | 节点数 | 读入 | — |
| `root` | 根节点字符（第一行第 1 个字符） | 读入第 1 行时记下 | R=Root |
| `son[2][256]` | 二维字符表：`son[0][c]`=节点 c 的左儿子，`son[1][c]`=右儿子；`*`=空 | 全局 char 数组默认 `'\0'`，读入时覆写实际出现的节点 | L=Left(0), R=Right(1)；`*`=empty |

> 说明：`son` 用 ASCII 下标（0..255）作键，直接以字符下标。只有实际读入过的节点才有合法儿子值，`*` 只作为儿子出现、不会被当作节点去查，因此无需预填充。

### 算法步骤（Numbered Steps）

1. 读入 `n`。
2. 循环 `i = 0..n-1` 读入每行：读入三个字符 `u, l, r`（跳过空格）；若 `i == 0` 则 `root = u`；记录 `son[0][u] = l`、`son[1][u] = r`。
3. 从 `root` 出发调用 `dfs(root)`：
   - `dfs(c)`：先 `cout << c`；若 `son[0][c] != '*'` 则 `dfs(son[0][c])`；若 `son[1][c] != '*'` 则 `dfs(son[1][c])`。
4. 输出末尾补一个 `'\n'`（可选，单答案无尾换行亦可）。

### 复杂度

- 时间：O(n)（建表 O(n) + 遍历 O(n)，每个节点进出各一次）。
- 空间：O(1)（`son[2][256]` 常数大小）+ 递归栈 O(n)。

### 验证状态（Validation Status）

- 手写样例推演（n=2，`A B *` / `B * *`）：前序 = `A B`，与定义一致。
- 链状最坏（n=3，`A B *` / `B C *` / `C * *`）：递归深度 3，输出 `A B C`，正确且栈安全。
- 空儿子（`*`）分支被显式跳过，不会以 `*` 为节点继续递归。
- 未实际编译运行（按要求仅写题解）；逻辑与 O(n) 复杂度对 n≤26 充分。

## Part 5 · 示例代码（C++，按风格规范）

```cpp
#include<bits/stdc++.h>
using namespace std;

char root;
char son[2][256];

void dfs(char c)
{
	cout<<c;
	if(son[0][c]!='*')
		dfs(son[0][c]);
	if(son[1][c]!='*')
		dfs(son[1][c]);
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);

	int n;
	cin>>n;
	for(int i=0;i<n;++i)
	{
		char u,l,r;
		// 三元组之间有空格，>> 按空白分词读入三个字符
		cin>>u>>l>>r;
		if(i==0)
			root=u;
		son[0][u]=l;
		son[1][u]=r;
	}

	dfs(root);
	cout<<'\n';
	return 0;
}
```

> 注：输入每行是 `节点 左儿子 右儿子`，三个字符之间以空格分隔（如 `A B *`）。用 `cin>>a>>b>>c` 按空白分词即可正确读入三个字符，无需手动跳空格。
