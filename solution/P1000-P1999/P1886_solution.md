# P1886 【模板】单调队列 / 滑动窗口

> 难度：普及/提高- · 标签：单调队列, 队列, 模板题

## 1. 重新读题
### 1.1 问题重述（人话版）

给长度为 `n` 的序列和窗口宽度 `k`。窗口从最左边开始，每次向右挪一格，一共有 `n-k+1` 个窗口。按从左到右的顺序，第一行输出每个窗口的最小值，第二行输出每个窗口的最大值。

### 1.2 关键约束与规模暗示

`1 ≤ k ≤ n ≤ 10^6`，`a_i` 落在 `[-2^31, 2^31)`，也就是闭区间上的 32 位有符号整数，包含 `-2147483648`。`O(nk)` 的逐窗口扫描过不了最大数据，需要每个元素进出窗口各常数次，总时间 `O(n)`。

## 2. 思维链（Chain-of-thought）

先看最小值。窗口右端从 `0` 扫到 `n-1`，右端为 `i` 时窗口是 `[i-k+1, i]`（下标从 0 开始；`i < k-1` 时窗口还没满，先不输出）。

朴素做法会在每个窗口里重新找最小。浪费在于：如果 `a[j] ≥ a[i]` 且 `j < i`，那么 `j` 比 `i` 更早离开窗口，并且在两者都还在窗口里的整段时间里，`j` 永远不会比 `i` 更小。这样的 `j` 可以立刻丢掉。

**引理 1（劣元素可删）。** 设 `j < i` 且 `a[j] ≥ a[i]`。则对任意同时包含 `j` 和 `i` 的窗口，最小值不会只在 `j` 上取到而取不到 `i`（至少 `a[i]` 同样小）。并且 `j` 离开窗口不晚于 `i` 之前的任何时刻……更准确地说：`j` 先于 `i` 过期。因此在 `i` 进入之后，`j` 不再可能成为未来任何窗口的唯一最小值来源。

证明：包含 `j` 的窗口左端点 `≤ j`。一旦左端点 `> j`，`j` 已经出窗；此时若 `i` 仍在窗内，则左端点 `≤ i`。未来任何一个还包含 `j` 的窗口必然也包含 `i`（因为 `j < i`，窗口是连续区间，包含两端就包含中间所有下标）。在这种窗口里 `a[i] ≤ a[j]`，所以最小值 `≤ a[i] ≤ a[j]`，删掉 `j` 不会提高最小值，也不会丢掉一个更小的值。

于是维护一个下标队列，从队头到队尾下标递增、对应的值严格递增（相等时也丢掉左边那个，因为右边的活得更久，值又相同）。

**引理 2（队头是当前窗口最小）。** 处理完下标 `i` 并弹出队头所有 `< i-k+1` 的过期下标之后，若 `i ≥ k-1`，队头下标 `q[hd]` 对应的值就是窗口 `[i-k+1, i]` 的最小值。

证明：队列里剩下的下标都 `≥ i-k+1` 且 `≤ i`，都在窗口内。队头是其中下标最小的，由单调性它的值也是队列里最小的。窗口中每个不在队列里的下标，都曾在某次插入时因为「左边值 ≥ 右边值」被删掉；被删时存在一个更靠右、值不更大的元素，而那个元素或者仍在队列里，或者又被一个更右、值更小或相等的元素替换。沿这条替换链走到底，会停在一个仍在当前队列中的下标上（因为 `i` 自己还在），其值 `≤` 被删元素的值。所以窗口最小值等于队列最小值，又等于队头的值。

最大值把比较方向反过来：进队时弹出队尾所有 `≤ a[i]` 的元素，维护值严格递减的队列。证明把引理 1、2 里的不等号全部反向即可，不再重复书写时只改这一处比较。

`a_i` 可以是 `-2147483648`，比较只用 `<` / `>`，不要对元素取相反数（会溢出）。

## 3. 模式总结（Pattern Summary）

- **explore its property** — 窗口里更早出现、又不比新元素优的下标，对当前和未来所有窗口都没有贡献。
- **classic problem solution** — 用双端队列维持下标递增、值单调的候选，队头即窗口最值。
- **classic problem solution** — 最小值和最大值各做一次，只是单调方向相反。

## 4. 真实解法
### 4.1 符号表（表格：符号 / 类型尺寸 / 含义 / 初值 / 助记）

| 符号 | 类型尺寸 | 含义 | 初值 | 助记 |
| --- | --- | --- | --- | --- |
| `a[i]` | `int[1000005]` | 原序列，0-based | 读入 | array |
| `k` | `int` | 窗口宽度 | 读入 | width |
| `w` | `int` | 窗口个数 `n-k+1` | 读入后计算 | windows |
| `q[]` | `int[1000005]` | 单调队列，存下标 | 空，`hd=tl=0` | queue |
| `amin[]` / `amax[]` | `int[1000005]` | 每个窗口的最小 / 最大 | `slide` 写入 | answers |
| `mode` | `int` | `0` 求最小，`1` 求最大 | 调用参数 | which |

### 4.2 算法步骤

1. 读入 `n, k` 和 `a[0..n)`。
2. `slide(amin, 0)`：从左到右，弹出队尾所有值 `≥ a[i]` 的下标，把 `i` 入队；若队头下标已 `< i-k+1` 则弹出；`i ≥ k-1` 时记录队头的值。
3. `slide(amax, 1)`：弹出条件改成队尾值 `≤ a[i]`。
4. 两行用单个空格分隔输出，行末没有多余空格。

队头过期每次只可能有一个，写成一次 `if` 即可；写成 `while` 也对，因为前面的更老。

### 4.3 复杂度与验证状态（只写你真实跑出来的数字）

每个下标最多入队、出队各一次，两趟都是 `O(n)` 时间，`O(n)` 空间。官方样例

`8 3 / 1 3 -1 -3 5 3 6 7` 输出

`-1 -3 -3 -3 3 3` 与 `3 3 5 5 6 7`，与暴力一致。

另有 `k = 1`、`k = n`、全相等、严格升降以及含 `-2147483648` 的边界，再加上 `n ≤ 400` 任意 `k` 的 60 组、`n ≤ 2000` 且 `k ≤ 30` 的 20 组，都与逐窗口扫描暴力逐字节相同。最大数据 `n = 10^6` 另跑了 `k = 1, 3, n`（这三组暴力仍是线性，继续对拍）和 `k = 1000`（只跑标程并检查输出个数）。标程最慢的一组是 `k = 1`（输出量最大），耗时 `0.3364 s`。合计 `94` 组，编译加 `-Wall -Wextra -Werror`，警告数为 0。

## 5. 示例代码
### 5.1 标程（`P1886.cpp`）

```cpp
//
// 题目：P1886 【模板】单调队列 / 滑动窗口
// https://www.luogu.com.cn/problem/P1886
// 本地对拍验证通过

#include<bits/stdc++.h>
using namespace std;

constexpr int mxn{1000005};

int n,k,w;
int a[mxn];
int q[mxn];
int amin[mxn],amax[mxn];

void slide(int *out,int mode)
{
	int hd=0,tl=0,cnt=0;
	for(int i=0;i<n;++i){
		if(mode==0){
			while(hd<tl&&a[q[tl-1]]>=a[i]){
				--tl;
			}
		}else{
			while(hd<tl&&a[q[tl-1]]<=a[i]){
				--tl;
			}
		}
		q[tl++]=i;
		if(q[hd]<=i-k){
			++hd;
		}
		if(i>=k-1){
			out[cnt++]=a[q[hd]];
		}
	}
}

void dump(int *b)
{
	for(int i=0;i<w;++i){
		if(i){
			cout<<' ';
		}
		cout<<b[i];
	}
	cout<<'\n';
}

int main()
{
	cin.tie(nullptr);
	cout.tie(nullptr);
	ios::sync_with_stdio(false);
	cin>>n>>k;
	for(int i=0;i<n;++i){
		cin>>a[i];
	}
	w=n-k+1;
	slide(amin,0);
	slide(amax,1);
	dump(amin);
	dump(amax);
	return 0;
}
```
