# luogu-problem-solution

洛谷主站题库（Luogu Main Problemset）Markdown 题面归档与 AI 驱动的**发现式（Discovery Narrative）OI 题解工程**。

本项目收录了洛谷主站 `P1001`–`P17391` 共 **16,391** 道题目的结构化题面，并按照统一的「人类思考叙事 + 完整引理证明」编写题解报告。

> **核心理念：思维链（Chain-of-Thought）是一篇题解的灵魂，代码没有那么重要。**
> 题解的真正价值在于完整还原「一个具备基础数学与编程能力的学生，如何从读题、试探性质、碰壁反例一步步推导出正解并完成严格证明」的过程；C++ 代码只是思维链收敛后的自然副产品，清晰可读即可，切勿本末倒置去堆砌形式化的对拍报告或冗余代码。

题解按题号顺序持续推进，**完成进度以 `solution/` 目录下的实际文件为准，本文不再单独维护统计数字**。

## 二、四大核心分类详解

### 1. 题面库（`statement/`）

存放从洛谷主站抓取的标准 Markdown 题面文件。每份题面包含难度（`Difficulty`）、标签（`Tags`）、题目描述（`Problem Description`）、输入输出格式、数据范围提示以及洛谷原题链接。

> **关于原始测试数据与样例的说明**：本地 `statement/` 中的部分题面可能未收录样例输入/输出，仓库也**不存放**洛谷原始评测数据（`.in`/`.out`）。在解题与撰写题解时，**切勿耗费精力去外网搜索、抓取或试图还原原题测试数据与官方样例**；如需具体例子辅助理解或推演，直接根据题面规则手造 1～2 组极简小数据即可。

### 2. 题解库（`solution/`）

存放遵循 `reference/SKILL.write-oi-solution.md` 规范生成的 Markdown 题解。题解摒弃教材式的“先抛结论再给公式”，采用**学生视角的发现式叙事（Discovery Narrative）**。

**核心原则：重思维链（Chain-of-Thought），轻代码（Code isn't that important）。**

题解固定包含五个部分，但权重截然不同：

1. **重新读题（Re-read the problem）**：剥离冗余背景，用直白语言重述问题模型、输入输出约束与边界条件。
2. **思维链与完整证明（Chain-of-thought，全篇核心）**：**占全篇 80% 以上的价值权重**。按真实思考顺序列出从性质剖析、子任务简化、直觉试探与碰壁反例，到最终归约为经典算法的完整推导链条。**每一条引理、贪心选择性质或 DP 状态转移均须附完整证明**（拒绝“显然成立”）。
3. **模式总结（Pattern summary）**：按实际思考顺序提炼可迁移的思维标签（如 `explore its property`、`consider easier version`、`reduce to easier problem`）。
4. **解法说明（The real solution）**：给出符号表（每个关键数组/变量的含义与初值），再按编号简述算法步骤与时空复杂度。无需在此堆砌机械的对拍统计表或耗时基准测试报告。
5. **示例代码（Example code，辅助参考）**：代码只是思维链落地的副产品，符合 `reference/coding-style-guide.md`、简洁可读即可。**只放一份最终参考实现**，不要在题解中贴第二份“暴力对照代码”。

### 3. 解题附件与中间文件（`appendix/`）

用于**按需**存放解题、打表探路或复杂题对拍过程中产生的中间脚本，按题目编号建立子目录 `appendix/P{id}/`，保持主目录与题解目录整洁。

#### 标准文件命名约定（仅在确需创建时参考）

| 中间文件类型 | 建议命名格式 | 说明 |
| :--- | :--- | :--- |
| 标准程序（Std Program） | `P{id}.cpp` 或 `std.cpp` | 本地编译自测或参与对拍的 C++ 标程 |
| 暴力基准（Brute-force） | `P{id}_brute.cpp` 或 `brute.cpp` | **仅限复杂题**：小数据范围绝对正确的朴素实现，用于验证非平凡算法 |
| 数据生成器（Generator） | `P{id}_gen.py` 或 `P{id}_gen.cpp` | 随机测试数据与边界数据生成脚本 |
| 对拍/校验器（Checker） | `P{id}_check.py` 或 `P{id}_checker.cpp` | 自动对拍脚本或 Special Judge 校验程序 |
| 模拟/追踪脚本（Trace） | `P{id}_trace.py` | 辅助理解题目机制、打印小规模状态转移或打表找规律的脚本 |

#### 归档原则（按需使用，拒绝形式主义）

- **`appendix/` 是可选草稿箱，绝非必交作业**：只有当题目状态复杂、性质隐蔽、细节极易写挂，确实需要写脚本打表探路或对拍验证时，才在 `appendix/P{id}/` 下保存相关文件。
- **简单题严禁强行写暴力与对拍**：对于入门/普及难度的简单题、直接模拟题、基本公式题或逻辑一目了然的题目，**不要创建 `appendix/P{id}/` 目录**，更不要为了凑齐“标程 + 暴力 + 对拍三件套”而强行编造一个换皮暴力去跑几千组无意义的随机测试。
- **严禁搜寻原始测试数据**：不要在 `appendix/` 中收集或试图从外部抓取原题测试点（`.in`/`.out`）。
- 已归档题目的清单不在此维护，直接浏览 `appendix/` 目录即可。

### 4. 参考规范与题库统计（`reference/`）

存放驱动整个项目的标准文档，以及由脚本自动生成的题库统计文件：

- **`reference/SKILL.write-oi-solution.md`**：定义 AI 撰写算法题解的核心哲学（思维链至上、代码从简、拒绝无效工程劳动）、五段式输出模板、引理证明要求及仓库目录读写约定。
- **`reference/coding-style-guide.md`**：基于对 606 个既有 `.cpp` 源码全量分析提炼出的描述性编码规范，核心特征包括：
  - 仅包含 `#include<bits/stdc++.h>` 与全局 `using namespace std;`，使用 `using i64=long long;`。
  - 全局静态数组优先，尺寸常量采用 `constexpr int mxn{...+5};` 松弛约定，哨兵值优先采用 `114514` 家族（如 `1145141919`）或 `1e9`。
  - 内部统一使用 **0-based** 下标（读入即 `--u;--v;`，输出恢复 `i+1`）。
  - 线段树等递归结构采用标志性的自递归 Lambda **`sth` 模式**（半开区间 `[l, r)`，根下标 `0`）。
  - I/O 加速固定顺序：`cin.tie(nullptr); cout.tie(nullptr); ios::sync_with_stdio(false);`，换行一律使用 `'\n'`。
  - 缩进采用 Tab，运算符紧凑不留空格，保留注释化的 `// cerr<<...` 作为可随时启用的调试层。
- **`reference/problem-statistics.md`**：全库难度分布、标签分布、标签共现、题解覆盖率的统计报告，**由 `scripts/gen_statistics.py` 自动生成，请勿手工编辑**。
- **`reference/problem-data.csv`**：逐题明细（题号、名称、难度、标签、是否有题解/附件/题面失效），供筛选与二次分析。

## 三、日常使用与维护指南（Maintenance Guide）

### 1. 核心维护准则（AI Agent 必读）

在维护本仓库或批量编写题解时，请严格遵守以下三条减负与提质准则，**切勿做无用功**：

1. **思维链（Chain-of-Thought）才是唯一核心，代码没那么重要**：
   - 读者看题解是为了搞懂「为什么会往这个方向想」「直觉怎么来的」「为什么贪心/DP 转移是对的」，而不是看一份冷冰冰的 AC 代码或测试日志。
   - 请把绝大部分精力投入到 **Part 2（思维链与完整引理证明）** 的打磨上：讲清楚每一步动机、为什么前一个直觉会失败（给极简反例）、如何修正并严格证明最终结论。
   - **Part 5（示例代码）只是点缀**：给出一份简洁、符合 `coding-style-guide.md` 的 C++ 参考代码即可。**不要**在题解里塞入第二份暴力代码，**不要**写冗长的对拍统计表或毫秒级耗时基准报告。
2. **禁止为简单题编写暴力程序与对拍脚本**：
   - 遇到逻辑直接、数学推导已严格闭环、或本身就是模拟/基础算法的题目，**直接写题解即可**。
   - **不要**教条地为每道题建立 `appendix/P{id}/`，**不要**为了形式上的“对拍验证”去给简单题硬凑 `P{id}_brute.cpp` 和 `P{id}_check.py`。只有当题目具有高度非平凡的组合性质、极易出错的复杂边界，或者你需要写脚本打表寻找规律时，才按需使用 `appendix/`。
3. **禁止四处搜寻原题测试数据或官方样例**：
   - 本地 `statement/` 题面如果没有包含输入输出样例，或者缺少评测数据，属于完全正常的情况。
   - **严禁**花费时间去全网搜索、爬虫抓取或到处翻找洛谷原题的原始测试数据（`.in`/`.out`）或官方样例。需要验证思路或举例说明时，直接根据题面定义手造 1～2 个极简合法小例子即可。

### 2. 编写新题解的标准流程

当使用 AI 助手或手动攻克新题目（以 `P{id}` 为例）时：

1. **读取题面**：从 `statement/P{xxxx}-P{yyyy}/P{id}.md` 读取题目描述与数据范围（只依赖本地题面，不外网搜寻原题测试数据）。
2. **推演思维链与证明（重中之重）**：从零推导问题性质、子问题简化、失败尝试与关键引理证明。仅当题目复杂且难以纯靠数学推导确信时，才按需在 `appendix/P{id}/` 下编写轻量的辅助验证脚本。
3. **撰写题解**：参照 `reference/SKILL.write-oi-solution.md` 与 `reference/coding-style-guide.md`，将五段式题解保存至 `solution/P{xxxx}-P{yyyy}/P{id}_solution.md`。

### 3. 使用自动化归档脚本（`scripts/reorganize.py`）

如果在解题过程中习惯先在仓库根目录临时创建 `Pxxxx.cpp`、`Pxxxx_trace.py` 或 `Pxxxx_solution.md`，或者需要将本地旧版扁平仓库迁移至新架构，可直接运行 `scripts/reorganize.py`：

```bash
# 预览将要执行的文件移动操作（不实际修改文件）
python3 scripts/reorganize.py --dry-run

# 在普通目录或解压后的仓库中执行架构整理
python3 scripts/reorganize.py

# 在 Git 仓库中执行架构整理（自动检测并使用 git mv 保留历史记录）
python3 scripts/reorganize.py --git
```

### 4. 查看与刷新题库统计（`reference/problem-statistics.md`）

仓库内置了一份由题面元数据自动汇总的统计报告，用于回答「我库里到底有多少题、难度怎么分布、哪些考点最常出现、还差多少题没写」这类问题。**它是脚本产物，任何时候都不要手工编辑**。

**看什么**（打开 `reference/problem-statistics.md`）：

| 想了解的问题 | 看哪一节 |
| :--- | :--- |
| 全库规模：题面数、标签种数、题解数、平均每题几个标签 | 一、总览 |
| 难度分布，以及「入门 / 普及题」与「高难题」各占多少 | 二、难度分布 |
| 最常考的标签是什么，标签分几类（算法 / 出处 / 年份 / 评测标记） | 三、标签分布、3.1 按类别汇总 |
| 难度爬升时考点如何演进（各难度层的高频算法标签） | 3.2 各难度层的高频算法标签 |
| 哪些考点常成套出现，适合做专题训练 | 3.3 标签组合（共现 Top 30） |
| 各难度还差多少题没写，当前完成度如何 | 四、题解覆盖情况 |
| 按题号区间的推进情况 | 五、题号分段分布 |
| 统计口径、已知数据偏差（**引用数字前必看**） | 六、数据质量与口径说明 |

**筛选题目**用同目录下的 `reference/problem-data.csv`（UTF-8 BOM，Excel / WPS 可直接双击打开），字段为：题号、题目名称、难度、标签数、标签、有题解、有附件、题面失效。

```bash
# 查某道题的难度与全部标签
grep '^P1004,' reference/problem-data.csv

# 列出所有带「线段树」标签、但还没写题解的题
awk -F',' '$5 ~ /线段树/ && $6 == "否" {print $1, $2}' reference/problem-data.csv

# 看看各难度的题解完成情况
cut -d',' -f3,6 reference/problem-data.csv | sort | uniq -c
```

**刷新统计**（新增题面 / 题解之后）：

```bash
# 先校验元数据是否齐全（只读，不写文件）
python3 scripts/gen_statistics.py --check

# 重新生成 reference/problem-statistics.md 与 reference/problem-data.csv
python3 scripts/gen_statistics.py
```

> 脚本只读取 `statement/`、`solution/`、`appendix/`，不会修改任何题面或题解，可以放心反复执行。
> 注意：存档里的难度标签存在历史遗留写法（`提高/省选-`、`NOI+`、`Level 8` 等）且高难度段占比偏高，报告第六节对此有说明；**涉及具体某题难度时请以洛谷原题页面为准**。
